Signature

[[nodiscard]] Pointer Allocate(size_t size)

Function description

Defined in Engine/Memory/StackAllocator.cpp as StackAllocator::Allocate(const size_t requested). Round the request, compare it against what is left, then either hand out the head of the buffer or ask the parent. 

size_t size = requested;
{
	constexpr auto AlignUnit = Config::DefaultAlign;
	const auto multiplier = (size + AlignUnit - 1) / AlignUnit;
	size = multiplier * AlignUnit;
}

const auto freeSize = GetAvailable();
if (unlikely(size > freeSize))
{
	auto& mmgr = MemoryManager::GetInstance();

	return mmgr.FallbackAllocate(GetID(), parentID, requested);
}

auto ptr = reinterpret_cast<void*>(buffer + cursor);
cursor += size;

From Engine/Memory/StackAllocator.cpp, StackAllocator::Allocate()

A block is size bytes at buffer + cursor, charged at the rounded size, and the cursor is the only bookkeeping: there is no header, no footer and no per-block record anywhere in the class, which is what makes Deallocate need a byte count.

Exhaustion does not fail — it silently changes which allocator owns the answer. When the rounded request exceeds GetAvailable(), the call becomes mmgr.FallbackAllocate(GetID(), parentID, requested), and the memory arrives from parentID. Three consequences: the pointer is outside this buffer, so IsMine says no and a later release is forwarded to parentID rather than rewinding the cursor; the number the parent was charged is requested, not the rounded size, so that is the number that must come back; and nothing is logged, so an overflow is invisible in a log and invisible in GetUsage, which counts buffer bytes only. The block also does not die with this object — the destructor frees the buffer and nothing else.
The comparison is made against the rounded size, so a nearly-full buffer can refuse a request it could physically satisfy. With 10 bytes left, a request of 10 rounds to 16, 16 is greater than 10, and the request goes to the parent — the last partial Config::DefaultAlign of the buffer is unreachable for anything but a request that already fits in it. A request of 0 is the degenerate case: it rounds to 0, the comparison never favours the fallback path, and the call returns buffer + cursor without moving the cursor — so two zero-sized requests in a row answer with the same address, and neither owns anything.
Alignment is a stride, not a promise. Every charge is a multiple of 16, so consecutive blocks are exactly 16 bytes apart and the class can never return an address that is misaligned relative to its own buffer. What it cannot promise is that the buffer itself is 16-byte aligned: that is inherited from the allocator that answered the constructor, whose default path is SystemAllocator's malloc (Engine/Memory/SystemAllocator.h), and nothing here checks or forces it. There is no aligned-allocation entry point on this class at all. See Coverage.

A null answer means the parent failed, and only a checked build says so before the caller does. MemoryManager::Allocate ends with Assert(ptr != nullptr, "Allocation Failed"): 

auto ptr = allocProxy.allocate(allocProxy.allocator, nBytes);
Assert(ptr != nullptr, "Allocation Failed");

Parameters

ParameterTypeRequirement
sizesize_tBytes wanted. Rounded up to a multiple of Config::DefaultAlign (16) before anything is compared or charged — so pass the size you actually need and keep the number, because Deallocate must be given a count that rounds to the same value.

Return value

TypeWhat you get
PointerUseful bytes, or nullptr if the parent's answer was nullptr. Which allocator owns the block depends on whether the buffer could cover it: inside the buffer, this stack owns it and a rewind frees it; from the fallback path, parentID owns it and only a release can free it. The attribute is [[nodiscard]] — a discarded pointer cannot be recovered, because the stack keeps no record of what it handed out.

Examples

auto allocFunc = [](void* allocatorPtr, size_t n) -> void*
{
	auto allocator = static_cast<StackAllocator*>(allocatorPtr);

	return allocator->Allocate(n);
};

No engine or application source calls Allocate on a stack allocator by name; this lambda, handed to MemoryManager::RegisterAllocator, is the call site. Anything allocating under an AllocatorScope over GetID() reaches the function through the manager's proxy dispatch — which is exactly how the StackAllocatorTest testlets in Engine/Memory/StackAllocator.cpp fill a stack with an HVector<int> and a String without naming the allocator once.
