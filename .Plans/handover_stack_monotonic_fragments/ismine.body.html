bool IsMine(Pointer ptr) const

Function description

Defined in Engine/Memory/StackAllocator.cpp as StackAllocator::IsMine(Pointer ptr) const, declared private. A range test against the backing buffer, and nothing more: it never consults cursor, so it cannot say whether an address was ever handed out. 

if (ptr < static_cast<void*>(buffer))
{
	return false;
}

if (ptr >= static_cast<void*>(buffer + capacity))
{
	return false;
}

return true;

From Engine/Memory/StackAllocator.cpp, StackAllocator::IsMine(Pointer ptr) const

Its one job is routing. Deallocate asks it first and splits on the answer: true means "rewind the cursor if this is the top block", false means "forward the release to parentID". Because that is the only consumer, the question it answers is "should the buffer or the parent be asked", not "is this pointer valid".

True means "inside my buffer", not "a block I handed out". The test is arithmetic on one address range, so it answers true for the middle of a block, for a block already released, for the gap between two blocks, and for the unwritten tail of a block whose charge was rounded up. The class has no record that could tell those apart — no header, no free list, no generation counter — and this is the reason a wrong-order release in Deallocate can pass the ownership test and then fail the top-of-stack test rather than being caught as a foreign pointer.
The range is fixed for the object's whole life, so the answer never changes. buffer and capacity are written once by the constructor and never again, so two calls with the same pointer agree however much allocation happened between them. The interval is half-open: an address exactly one past the end is not yours. The flip side is that Deallocate judges a rewind against cursor, which does move, so this predicate being true says nothing about whether a release will succeed.
A null pointer is answered "not mine", which is a dispatch, not a rejection. nullptr compares below a live buffer, so Deallocate forwards (nullptr, size) to parentID; the manager's release entry then asserts Assert(nBytes == 0) on a null pointer, so releasing null with a non-zero count aborts in Debug and Dev. With a failed construction the buffer is null and the second comparison (ptr >= buffer + capacity) is what rejects every input, including null. See Coverage for the untested construction paths.
It is private, and it is not marked [[nodiscard]]. No caller outside the class can reach it, so the only observable behaviour is Deallocate's choice of destination. Note the inconsistency with the sibling class: MonotonicAllocator::IsMine declares the same private predicate [[nodiscard]]. Both are used in a condition, so the difference changes nothing today.

The whole of the function's use, and the shape every allocator in this module repeats: ownership is decided by address range, and a pointer the range does not claim is sent to the parent rather than rejected. A caller who wants certainty that an address belongs to this stack must compare it against the pointer Allocate returned, because nothing inside this class remembers that pointer.
