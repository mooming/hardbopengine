## 3. Composition: which rules, and what that costs

| Rule | Findings | What it requires |
|---|---|---|
| A10 | 516 | one blank before `return`, unless it is the only statement in its scope |
| A4 | 333 | none immediately after an opening `{`, or between a header line and its `{` |
| A5 | 241 | none immediately before a closing `}` |
| A3 | 189 | exactly two after the preamble — the only legal double blank in a file |
| A11 | 105 | exactly one after the `}` of a nested block |
| A2 | 86 | exactly one between two directive blocks inside the preamble |
| A1, A6, A12-A16 | 31 | the remaining seams |

1279 of 1501 (85%) sit in A10, A4, A5 and A3 — all four rules `blank_lines.py` decides deterministically, so the
reader's judgement is concentrated in the small remainder. **This does not make the sweep scriptable**:
`SKILL.md` refuses `blank_lines.py --fix` because "deleting a blank because a checker disapproved is the failure
this layer exists to prevent". Each file is still read and edited by whoever holds it; the script's role is to
say which seams are the wrong size and to prove afterwards that nothing but blanks moved.

Workload shape (measured, not estimated): 248 files hold findings, median 3, mean 6.1, maximum 125. **The 37
densest files hold 51% of the debt and the remaining 211 hold the other 49%**, so the tail is where the time

## 4. Ordering against the comment ban — measured, and it settles nothing in anyone's favour

`SKILL.md` says run this layer "before the comment sweep"; `Engine/Core`'s own history did the opposite
(`1d28c88` deleted 233 comments, `f10a9c6` grouped by concern and set the seams afterwards). Neither is costly,
because the two debts barely overlap — measured on the two files that have been through both passes:

| File | blank findings before its strip | after | comment findings removed |
|---|---|---|---|
| `Engine/Core/TaskSystem.h` | 9 | 7 | 234 |
| `Engine/Core/TaskSystem.cpp` | 133 | 125 | 201 |

Stripping 234 and 201 comment findings carried away 2 and 8 blank findings. **A blank-line pass therefore costs
the same whether it runs before or after the comment sweep**, so cost is not a reason to re-order any module.
What no count can settle is which order produces better *seam judgements*: `SKILL.md` argues the comment prose
names the concern a seam divides, so deciding seams while the prose is still there reads the file with its
evidence intact. That argument is sound and unmeasured, and it is the only remaining reason to prefer
`SKILL.md`'s order — which the tree's own history did not follow, at a cost the table above puts near zero.

## 6. Procedure per file, and the proof

1. `python3 .pi/skills/hb-standards/scripts/blank_lines.py <file>` — read the findings, then read the file. The
   seam decision is the reader's; the counts are only sizes.
2. Edit. Format first if the file also needs clang-format, then the table, never the reverse
   (`docs/CodingStandards.md`: formatter cleanliness is a pre-process).
3. `python3 .pi/skills/hb-standards/scripts/blank_lines.py <file>` → 0.
4. `python3 .pi/skills/hb-standards/scripts/prove_regroup.py <file> --whitespace-only` → proves only blank lines
   moved. This is mandatory, not optional: the multiset check cannot see two lines trading places.
5. Regenerate the ledger when the module finishes, and commit it with the module.

Per module, the gate is `scripts/gate.sh` (three configurations plus the suite). Expect `check.sh` to keep
exiting 1 on the tree's unrelated backlog — the failure to chase is the one printed for the module just worked.
