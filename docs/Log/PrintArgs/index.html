PrintArgs

Engine/Log/PrintArgs.h unnamed namespace at global scope — not hbe 2 function templates header-only the last-resort print: no queue, no timestamp, no logger, straight to std::cout

Class description

Two function templates that stream their arguments to std::cout and terminate the line after the last one. They are the print you reach for when the logging system is the thing you no longer trust: no Logger, no level, no category, no filter, no memory pool, no task system — just << and std::endl. That is why the assertion family and Exception use it rather than the asynchronous sink: an assert must produce its text even if the drain thread is the thing that hung.

It is not a formatting facility. Arguments are written back to back with no separator, and the only TLogStream-like conveniences (padding, timestamps, level names) are absent. The one real call site that needs separation supplies it as an argument itself: PrintArgs(file, ":", line, forward<Types>(args)...) in Exception.h.

Read the linkage before you include this header for convenience. Both templates are defined in an unnamed namespace at global scope — not inside hbe — and marked static. Every translation unit that includes PrintArgs.h therefore compiles its own copy of both functions: Engine/Core/Debug.h and Engine/Core/Exception.h each carry one today. The copies are well-formed and cannot collide (that is what the unnamed namespace buys), but this is not one shared engine function: it is duplicated code in each includer, it cannot be called from another translation unit, and there is no single definition to breakpoint or to redirect. A caller wanting a shared formatter should use InlineStringBuilder or the logger's callback form.
Output from here and output from the logger interleave freely. This goes to std::cout unbuffered-by-agreement; queued log lines reach the console through PrintStdIO → Engine::ConsoleOutLn later, on the drain thread. An assert printed this way therefore appears before the log lines it was caused by, and the two streams cannot be ordered against each other without LOG_FORCE_PRINT_IMMEDIATELY.

Template parameters

ParameterKindWhat it must satisfy
T typename Type of the first argument. It must be streamable: an operator<<(std::ostream&, …) must exist for it, because the body is std::cout << arg. That includes the awkward cases — a char prints as a character, not a number, and a raw pointer prints as an address
TTypes typename... Types of the remaining arguments, each of which must also be streamable. They are forwarded, so an argument is passed as an rvalue reference and a stream that consumes its argument (a manipulator with state) sees exactly what the caller wrote

Class properties

Not applicable — the header declares no types, no objects and no aliases. Its entire content is the two templates below, plus #include <iostream>. Anything you need from it is a call.

Coverage

GapDetail
No conversion, no formatting %d and friends mean nothing here; the assert call sites in Engine/Log/Logger.cpp that pass printf-style arguments (Assert(false, "Invalid userdata %p", userData)) get the format string and the value printed side by side. Detail on the function page
What the callers add on top The assert family flushes the logger, prints through this, then traps and aborts; Exception prints and does nothing else — it holds no message and is not throwable in any useful sense. Both belong to Core
Destination is fixed std::cout only, with no redirect, no level and no way to route it into the log file. The only related switch is the LOG_FORCE_PRINT_IMMEDIATELY family, which changes where Logger prints — not where this prints
