PrintArgs

Engine/Log/PrintArgs.h 2 overloads noexcept internal linkage, per translation unit stream every argument to std::cout, one line, no separators

Signatures

Verbatim from the header, including the enclosing scope:

namespace                            // unnamed, at global scope
{
template<typename T>
static void PrintArgs(const T& arg) noexcept;          // base case: prints, then std::endl

template<typename T, typename... TTypes>
static void PrintArgs(const T& arg, TTypes&&... args) noexcept;   // prints arg, recurses on the rest

} // namespace

Function description

Both bodies are two lines each:

std::cout << arg << std::endl;                          // one argument

std::cout << arg;                                       // two or more
PrintArgs(std::forward<TTypes>(args)...);

Recursion peels the first argument off on each call, so the arguments appear left to right and the last one ends the line. Nothing is written between them: PrintArgs("a", "b", 3) produces ab3 followed by a newline. Separators are arguments, which is exactly what the one structured call site in the engine does (see the Exception example below).

The constraint on every argument is streamability — an operator<< taking std::ostream& must be findable for the type. That is a looser and different set than the logger's, which accepts anything a lambda can push into InlineStringBuilder: a type streamable to std::ostream but not to the engine's builder works here and not there, and the reverse is equally true.

printf-style arguments are printed literally, side by side with the values they were meant to consume. The assert family forwards its varargs straight here, and this function has no conversion specifications — so the call in Engine/Log/Logger.cpp, Assert(false, "Invalid userdata %p", userData), writes [Assert] Invalid userdata %p0x7ffee4. Every variadic assert in the engine that uses %d, %p or %s reads this way in a crash log. Pass the message pre-built, or accept the literal; there is no printf anywhere in this path.
noexcept on a call into a user-defined operator<<. Both overloads promise not to throw while doing the one thing that can: streaming an arbitrary type, potentially into a stream in a failed state with exceptions enabled. A user stream operator that throws — or a std::cout configured to throw on failure — turns the print of an assertion into std::terminate before the caller reaches its own debugBreak() and std::abort(), so the report you were trying to print is the reason it never appears.
Whether this prints at all depends on the caller's build configuration, not on this header. The assert family is compiled out of Release: in that configuration Assert(cond, args...) is an empty inline function, so its arguments are never evaluated — the header of Core/Debug.h calls this out explicitly, because it means an argument with a side effect happens in Debug and not in Release. The variadic PrintArgs overloads themselves are always compiled; only the callers gate them.

Parameters

ParameterTypeRequirement
arg const T& Streamable to std::ostream. Bound as a const reference, so a temporary lives to the end of the full expression — which is long enough, because the whole print happens inside this call
args TTypes&&... Only on the variadic overload. Each must be streamable; each is forwarded, so a reference argument reaches std::cout as the caller wrote it

Return value

void. The only output is the line on std::cout, and nothing reports failure: a stream that discards, a redirected standard output that is closed, or a truncated write all look identical to success. There is no return value to check and no way to know whether anyone will read it.

Examples

The single-argument form, from the assert that has nothing further to say:

From Engine/Core/Debug.h

inline void Assert(bool shouldBeTrue) noexcept
{
        if (likely(shouldBeTrue))
        {
                return;
        }

        FlushLogs();
        PrintArgs("[Assert] Please check it.");

        debugBreak();
        std::abort();
}

And the variadic form, where the separators are passed as arguments because nothing adds them — the file/line prefix of an exception:

From Engine/Core/Exception.h

template<typename... Types>
inline Exception(const char* file, int line, Types&&... args)
{
        using namespace std;
        PrintArgs(file, ":", line, forward<Types>(args)...);
}

Note what the assert path does first: FlushLogs(), which calls Engine::FlushLog() and thus Logger::Flush (Engine). The ordering that produces is worth internalising — queued lines are pushed out, then this line is printed, so an assertion's own text can appear after older lines it was involved with but before any line still in the queue when it fired.
