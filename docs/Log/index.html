Module Index / Log

Log

namespace hbe Engine/Log 5 headers, 3 sources — asynchronous logging on the task system's IO stream

Module description

Logging is asynchronous and runs on the TaskSystem's IO stream, so a log call formats into a buffer and returns rather than blocking a frame on a console. Lines carry a category and a level, which is how a caller filters without editing call sites. The behaviour — double buffering, category rules, output destinations — is docs/LoggerGuide.md; this page is the surface you call.

Logging keeps working in a process that never constructed an Engine. That is deliberate, and it is why the logger and the clock do not reach the engine through Engine::Get, which asserts that an instance exists.

Non-member helper functions

namespace   // anonymous
{
template<typename T>
static void PrintArgs(const T& arg) noexcept;                    // prints, then endl

template<typename T, typename... TTypes>
static void PrintArgs(const T& arg, TTypes&&... args) noexcept; // recurses
}
Read the linkage before you include this header for convenience. Both overloads are declared in an anonymous namespace in the header, so each translation unit that includes PrintArgs.h gets its own copy rather than one shared function. That is harmless for a print and is not the same as a normal engine API; a caller wanting a shared formatter should not reach for it.

LogUtil (Engine/Log/LogUtil.h, namespace hbe::LogUtil)

Class description

The log's own clock and the small formatting helpers that turn a level and an instant into text.

Template parameters

None — LogUtil is a namespace.

Class properties

The alias TTimePoint = std::chrono::time_point<std::chrono::steady_clock> and, behind GetStartTime(), the instant timestamps are measured against — so a log reads as elapsed time rather than as a wall-clock value.

Moving the zero point after lines have been written shifts every later line against the ones already out, which reads as log lines running backwards. That is the reason the engine sets it in one place and no subsystem calls ResetStartTime on its own.
