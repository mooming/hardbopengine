Out

member of hbe::Logger::SimpleLogger Engine/Log/Logger.h 4 overloads const noexcept emit one line: callback for text that must be built, literal for text that is already there

Signatures

One page for the name because all four forms state one contract — the line is emitted now, on this thread:

void Out(const TLogFunction& logFunc) const noexcept;
void Out(ELogLevel level, const TLogFunction& logFunc) const noexcept;

void Out(const char* text) const noexcept;
void Out(ELogLevel level, const char* text) const noexcept;

Function description

Two real bodies exist, and they differ only in where the level comes from:

if (unlikely(instance == nullptr))
{
        EmergencyLog(category, level, logFunc);
        return;
}

instance->AddLog(category, level, logFunc);

The const char* forms are one-liners that wrap their argument: Out([text](auto& ls) { ls << text; });. They exist so that a constant string does not pay the construction of a std::function, and overload resolution sends a literal here rather than to the callback form — a literal is an exact match for const char*, while the callback form would need a user-defined conversion.

Where the level comes from decides nothing else: with no level argument the bound level is used, and the two-argument forms override it for that call without touching the object, which is const.

The fallback is a different logging system, and it is louder than the real one. When Logger::instance is null — before construction, after destruction — the line goes to the file-local EmergencyLog, which ignores the Log.Level threshold, ignores every category filter, and writes no timestamp. Output from this path is [category][Level] text with no leading time field, sent with fputs plus fflush to standard output, or to standard error at Error and above, and it never reaches the log file. Two things follow: a startup or shutdown sequence prints more than you expect, and a line without a timestamp in its prefix is evidence of this path rather than of corruption.
Your callback runs before this call returns. AddLog invokes it on the calling thread, into a builder on the calling stack, so captures by reference are sound — this is the module where [&] does not dangle. It also means the work is charged to your thread, including the 128 KiB builder, and that a callback which blocks blocks the caller, not the drain. The const char* forms capture the pointer rather than the bytes, which is safe for exactly the same reason: the text has to outlive the call, not the write. A null pointer becomes the text Null rather than a crash, courtesy of the string builder's handling of null.

Parameters

ParameterTypeRequirement
logFunc const TLogFunction& Anything accepting (TLogStream&); called at most once, synchronously. Must not throw out — the whole path is noexcept — and must not assume the line will be kept: the level and filter checks in the sink happen after it is handed over but before it runs
text const char* A NUL-terminated constant, typically a string literal. Truncation follows the line rules: at most 1023 characters are stored inline, and the rendered line is cut at about 2000 characters (see LogLine and the drain)
level ELogLevel Only on the two-argument forms. Overrides the bound level for this one line; it is the argument that selects the threshold, filter, and any of the error-level special paths in the sink

Return value

void, and no failure is reportable. The call succeeding means the line was passed to the sink (or to the emergency path) — not that it cleared the level threshold, not that it passed the category filter, and not that any byte reached the file.

Examples

The literal form, for text that is already a constant:

From Engine/Core/TaskSystem.cpp

auto log = Logger::Get(GetName());
log.Out("# Creating TaskStreams ======================");

The callback form, when the text is made of values — the shape used for every diagnostic in the engine:

From Engine/Core/TaskStream.cpp

auto log = Logger::Get(name);
log.Out([name = name](auto& ls) { ls << name.c_str() << " is created."; });

And overriding the bound level for one line, from the engine's initialisation banner:

From Engine/Engine/Engine.cpp

auto log = Logger::Get(GetClassName());

log.Out("Command Line Arguments");

for (int i = 0; i < argc; ++i)
{
        log.Out([i, argv](auto& ls) { ls << i << " : " << argv[i]; });
}

All three bind no level explicitly, so each line is emitted at Info — and all three are therefore subject to whatever Log.Level says on the day you read the file. For anything you need to see regardless of a chatty default, use OutWarning, OutError, or the two-argument form with a level named.
