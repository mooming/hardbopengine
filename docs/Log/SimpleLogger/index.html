SimpleLogger

Engine/Log/Logger.h, nested in Logger hbe::TLog final 10 member functions a category and a level bound into one value — the face almost every call site actually uses

Class description

Two const fields and ten functions that do nothing but forward. A SimpleLogger answers the question "what category, what level" once, so a call site writes log.OutError([](auto& ls){ ls << …; }) instead of repeating both arguments on every line in the file. It is Logger's nested class, aliased at namespace scope as hbe::TLog, and obtained either from Logger::Get(category, level) or by naming the constructor directly.

It holds no reference to the sink. Each call reads the process-wide Logger::instance pointer and hands off to AddLog; if the pointer is null — before the logger is constructed, after it is destroyed — the line goes to the file-local emergency path instead, which writes to standard output or standard error and never to the log file.

That makes this object's lifetime embarrassingly easy: it is two fields, copyable, and storable in a static const auto at file scope, which is what every engine subsystem does with one. Nothing the logger does can invalidate it.

The fields are const, so a bound logger is bound. Copying works, assignment does not — const members delete the copy-assignment operator implicitly. A subsystem cannot change its category at runtime, and the workaround is to construct a new one, which is also the reason the constructor is explicit: no implicit conversion from a bare category string to a logger.
Shortcuts exist only for the three levels that mean trouble. There is OutWarning, OutError and OutFatalError, and no OutVerbose, OutInfo or OutSignificant. Below the bound level you use Out(level, …) explicitly — which is more than a style point: the bound level defaults to Info, and a call site that writes log.Out(…) for something interesting and forgets the level is writing at Info, where a threshold of Significant or higher discards it.

Template parameters

None — SimpleLogger is not a template. Its functions are templated only in the sense that a lambda passed to Out converts to TLogFunction.

Class properties

Both fields are public and both are const; there are no aliases of its own, since the types it speaks are declared by Logger.

NameDeclarationWhat it means
category const StaticString category; data member The filter key and the bracketed prefix on every line this object produces. Interned, so copying a logger copies a handle — the reason a file-scope logger costs nothing
level const ELogLevel level; data member The level used by Out(logFunc) and by the three shortcuts' implicit argument — except that each shortcut overrides it with its own severity, so a logger bound at Info still reports through OutError at Error

Class methods

Ten functions under four names. Each name exists in a callback form taking a TLogFunction and a literal form taking a const char*, and Out adds two more that name the level explicitly instead of using the bound one. The three shortcuts are one-line bodies in the header that call Out with their own severity.

Non-member helper functions

None. Two namespace-scope aliases in the same header name this class and the stream its callbacks receive — using TLog = Logger::SimpleLogger; and using LogStream = Logger::TLogStream; — documented with Logger's non-member declarations, where they live.
