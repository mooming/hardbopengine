SimpleLogger constructors

member of hbe::Logger::SimpleLogger Engine/Log/Logger.h explicit noexcept two field copies — no logger required, nothing to release

Signature

explicit SimpleLogger(StaticString category,
                      ELogLevel level = ELogLevel::Info) noexcept;

Function description

The body initialises the two members and does nothing else: : category(category), level(level). It never looks at the sink, so construction cannot fail, cannot block, and is legal at any point in a process's life — before Logger exists, during shutdown after it is gone, and in a process that never builds one. There is no destructor to match it, because nothing is owned.

explicit forecloses the implicit conversion that would otherwise be tempting: a bare category string becoming a logger object in an argument position. The one-argument form is still available, and it binds the level to Info — which means it is the form most likely to be used wrongly, because Info is the level a threshold set to Significant throws away.

Prefer Logger::Get(category, level) in new code. It constructs exactly this object, by the same call, and says what the caller means: obtaining a logger for a category. The constructor is worth naming directly where a type spelling is clearer than a function call — as the TLog log(…) in the test collection below does — or where you are already inside Logger's own code.
The copy constructor exists; assignment does not. Both fields are const, so the copy-assignment operator is implicitly deleted. A logger can be returned by value, stored in a static, passed by value and copied freely, but a statement that rebinds an existing one to a new category will not compile. Make a new one instead.

Parameters

ParameterTypeRequirement
category StaticString Any text; a const char* argument is interned at this call, which is why a call site that logs at load time through a local string pays the interning lookup once. It must match the string given to SetFilter for a filter to apply to this logger's lines
level ELogLevel Defaulted to Info. Stored as given and used by the level-less forms of every output function; the shortcuts (OutWarning and friends) ignore it

Return value

A value with two fields set. It is not registered anywhere, holds nothing, and needs no cleanup; the only state it depends on is the process-wide sink pointer, read afresh on each call.

Examples

Naming the type directly, in the test framework's report:

From Engine/Test/TestCollection.cpp

void TestCollection::Report() const
{
        TLog log(GetName(), ELogLevel::Info);

        if (isSuccess)
        {
                log.Out([](auto& ls) { ls << "= Collection Result: [SUCCESS] =================\n"; });
        }
        else
        {
                log.OutError([](auto& ls) { ls << "= Collection Result: [FAIL] ====================\n"; });
        }
}

And the same type cached for the life of the process, which is the usual shape in engine subsystems:

From Engine/Renderer/Vulkan/VulkanRenderer.cpp

static const auto log = Logger::Get("VulkanRenderer", ELogLevel::Error);

Note that the second example binds the level to Error and then calls OutError anyway — a harmless redundancy that reads as intent, but it also shows the binding is not a constraint: any of these objects can emit at any level its functions name.
