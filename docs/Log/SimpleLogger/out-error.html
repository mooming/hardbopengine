OutError

member of hbe::Logger::SimpleLogger Engine/Log/Logger.h 2 overloads const noexcept Error, spelled — the level where the queue starts being bypassed

Signature

void OutError(const TLogFunction& logFunc) const noexcept
{
        Out(ELogLevel::Error, logFunc);
}

void OutError(const char* text) const noexcept
{
        OutError([text](auto& ls) { ls << text; });
}

Function description

Out(ELogLevel::Error, …), written out twice in the header so that both argument shapes are available. It is the most-used output function in the engine: every renderer, allocator, task registry and configuration failure reports through it.

Three downstream behaviours are keyed on reaching Error, none of them visible from this call:

  • Produced by the log thread, the line is not queued. AddLog detects that this_thread == threadID and writes it straight through FlushBuffer from a thread-local buffer allocated from the system allocator — a deadlock avoided (the drain cannot wait for its own queue) at the cost of ordering: such a line appears ahead of lines queued before it.
  • Outside the logger, this is the level that changes streams. The emergency path sends Error and above to standard error rather than standard output (described here), and it is where the file-local ImmediateLog picks stderr too.
  • It is the threshold of LOG_BREAK_IF_ERROR. With that macro set, the line is printed inline, debugBreak() runs, and the function returns — the line never reaches the log file (Config: BuildConfig carries the note that the guard is the macro alone, not the build type).
Engine convention, visible in every call site: the category carries the level. Subsystems that report failures bind their logger at Error and then call OutError — for example Logger::Get("VulkanRenderer", ELogLevel::Error) in VulkanRenderer.cpp. It is redundant, and it is worth keeping: it makes the level legible at the call site, and it survives someone changing the bound level for other lines.

Parameters

ParameterTypeRequirement
logFunc const TLogFunction& Executed on this thread before the call returns, and only if Log.Level permits Error and no category filter rejects it; capturing by reference is safe for that reason
text const char* NUL-terminated literal; the pointer is captured rather than the bytes. A null pointer prints as Null and does not fault

Return value

void. An error line that the configuration suppresses is indistinguishable from one that was written — and because the level threshold defaults to Info, suppressing Error takes a deliberate setting (Log.Level above 4) or a category filter, never an accident of default.

Examples

Callback form, reporting a result code whose value matters:

From Engine/Renderer/Vulkan/VulkanRenderer.cpp

void LogFailure(const char* step, VkResult result) noexcept
{
        static const auto log = Logger::Get("VulkanRenderer", ELogLevel::Error);
        log.OutError([step, result](auto& ls)
        {
                ls << step << " failed (VkResult=" << static_cast<int>(result) << ")";
        });
}

Literal form, for a failure with nothing numeric to add — note that this overload forwards to the callback one in the header:

From Engine/Renderer/Vulkan/VulkanCapabilities.cpp

static const auto log = Logger::Get("VulkanCapabilities", ELogLevel::Error);
...
log.OutError("Error: cannot query capabilities from a null physical device; leaving capabilities unqueried");

The practical argument for the literal overload is that no std::function is constructed, so a constant failure message costs a pointer and a call. The other side of that: the argument is captured as a pointer, so a text that lives in a temporary is only safe because the callback runs before AddLog returns — as both examples show, the intended use is a literal.
