LogLine constructors

member of hbe::LogLine Engine/Log/LogLine.h 3 overloads all noexcept produce a line, move a line, or make an empty one — one of the three allocates

Signatures

/// empty line: level Info, inline variant, both end bytes of the buffer set to '\0'
LogLine() noexcept;

/// steal a line's body — pointer hand-off for the long variant, 1024-byte copy for the short one
LogLine(LogLine&& rhs) noexcept;

/// the form the logger calls: stamps now, copies inText, chooses the variant from size
LogLine(ELogLevel level, StaticString threadName, StaticString category,
       const char* inText, size_t size) noexcept;

There is no copy constructor. Declaring the move constructor implicitly deletes it, so LogLine b = a; is a compile error — which is exactly what you want from a class whose second variant owns a raw pointer.

Function description

Producing a line

The five-argument form is the constructor that does work. It stamps steady_clock::now() into timeStamp, decides isLong from size >= Config::LogLineLength - 1 — 1023, so the threshold and the inline capacity are the same constant — and then takes one of two paths.

Long: it asks Engine::Get().GetMemoryManager() for size + 1 bytes via SysAllocate, and copies size + 1 bytes from inText — one more than you gave it, taking the terminator on trust. Short: it ignores your size entirely, re-measures with StringUtil::StrLen(inText, Config::LogLineLength - 1), copies that many bytes and writes its own terminator. An inline line therefore ends at the first NUL in the input, while a long line is copied by count.

Moving a line

Long: the pointer and size are taken, and the source is reset to an empty short line (isLong = false, longText = nullptr, longTextSize = 0, text[0] = '\0' — all of that written through the union). Short: all 1024 bytes are copied, which is why a queue of short lines is cheap to swap as a buffer (one std::swap of the vector) and expensive to move element by element.

The empty line

The default constructor sets level = Info, isLong = false, zeroes the pointer member, and writes '\0' at both text[0] and text[Config::LogLineLength - 1]. The last of those is belt-and-braces: it guarantees the buffer's final byte is a terminator even if something later scribbles into the tail. It leaves timeStamp uninitialised — a default-constructed line has no moment in time, and the drain would print an arbitrary elapsed value for one.

A null inText with a size of 1023 or more produces a line whose body pointer was never set. The constructor selects the long variant from the size argument alone, then bails out early when inText == nullptr by writing text[0] = '\0' and returning — leaving isLong true and longText uninitialised. GetText then returns an indeterminate pointer, and the destructor tries to free it (after an Assert that only Debug and Dev run). No current caller can reach this — AddLog always passes a builder it just filled, with a matching Size() — but a hand-built line, or any future caller that passes a length and a pointer separately, can.
The two variants draw memory from different places, and the long one is not the logger's. Long bodies come from MemoryManager::SysAllocate rather than from "LoggerInputPool", even though AddLog opens that pool as allocator scope around the enqueue. It is a deliberate asymmetry: SysAllocate takes an explicit size, and the allocator scope only redirects the default allocator that HString and the queues use.

Parameters

ParameterTypeRequirement
level ELogLevel Stored as produced; no filtering happens here — that is already done before a line is built
threadName StaticString Interned handle, copied by value. Pass what TaskSystem::GetCurrentStreamName() gave you; nothing validates it
category StaticString The key the line will be attributable to in output
inText const char* Must be NUL-terminated at or before size: the long path copies size + 1 bytes and the short path re-measures with StrLen. Not null — see the hazard above
size size_t Length of the text excluding the terminator. It alone chooses the variant, and it is ignored on the short path

Return value

A constructed line. Nothing reports whether the body was truncated, whether it went to the heap, or whether an allocation happened; noexcept throughout, so a failed allocation in the long path is not something this constructor can survive as a status either. Read isLong and longTextSize afterwards if you need to know what you got.

Examples

The only construction in the engine — inside the enqueue block, with a builder the caller thread just filled:

From Engine/Log/Logger.cpp

TLogStream ls;
logFunc(ls);
...
{
        std::lock_guard lock(inputLock);
        AllocatorScope inputAllocScope(inputAlloc);
        inputBuffer.emplace_back(level, threadName, category, ls.c_str(), ls.Size());

        bufferSize = inputBuffer.size();
        ...
}

emplace_back here runs the five-argument constructor in place, so the line is built directly inside the queue's storage — and the two StaticString arguments are handles, not copies of text. The corresponding move constructor is what HVector needs to grow that storage; without its noexcept, a reallocation would have to copy, which this class deliberately does not allow.
