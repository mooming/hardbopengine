LogLine

Engine/Log/LogLine.h namespace hbe final 3 constructors one produced entry: a timestamp, the producing thread, a category, a level, and text that is inline or on the heap

Class description

The record AddLog puts in its queue and ProcessBuffer takes out. It is an aggregate in every sense but syntax: five public data members, a union for the body, and no behaviour beyond the constructors, the destructor and GetText. Nothing formats it — the prefix is assembled at drain time from these fields.

The union is the design. A body shorter than Config::LogLineLength − 1 lives in the line's own storage and costs no allocation; a longer one is a pointer plus a length, with the bytes allocated from the system allocator by the producing constructor and returned by the destructor. isLong says which member is live, and it is the flag every reader must consult — GetText exists so that nobody reads the union directly.

timeStamp is captured with steady_clock::now() at construction, which is why a queued line still carries the moment it was produced rather than the moment it was written. The drain formats that stored value into the prefix.

Every line costs about a kilobyte, whatever it says. The union is sized by its inline member — 1024 characters — so a twenty-character message occupies the same space as an empty one. Multiplied by the queue, that is the real cost of the design: at Config::LogForceFlushThreshold (8192) the pending queue is roughly eight megabytes held in "LoggerInputPool". Long lines add their own allocation on top, from a different pool.
Only about the first 2000 characters of a long line ever reach the log file. Storing a large body faithfully is not the same as emitting it: ProcessBuffer concatenates the prefix and the body into InlineStringBuilder<Config::LogLineLength * 2> — 2048 bytes, which truncates silently. The union buys fidelity that the renderer then discards, so a multi-kilobyte dump must be written by other means or split into lines.
A line cannot be copied, and that is not an oversight. The class declares a move constructor, which implicitly deletes the copy constructor — so a shallow copy of the long variant, which would double-free, cannot be written. Lines move between the queue and the drain, which is the only transfer they need; TLogBuffer holds them by value precisely because that move is noexcept.

Template parameters

None — LogLine is not a template.

Every member of LogLine is public: the type is a payload passed between two functions of one module, not an object with an invariant to protect. Badges below therefore name the kind of member; the visibility is uniform.

text char text[Config::LogLineLength]; data member Inline body, 1024 bytes including the terminator: at most 1023 characters survive, and the producing constructor truncates to that rather than failing
longText char* longText; data member Heap body for a line that did not fit — allocated by MemoryManager::SysAllocate, i.e. the system allocator, not the logger's own pool. Uninitialized when a construction with null text still selects the long variant
longTextSize size_t longTextSize; data member Allocation size, stored as including the terminator (size + 1), and passed back to SysDeallocate by the destructor — so the size the allocator received and the size it gets back always match

Non-member helper functions

None. LogLine.h declares nothing at namespace scope. There is no operator<< for a line and no formatter — rendering lives in ProcessBuffer, and a caller that wants a line as text has to assemble the same five fields by hand.
