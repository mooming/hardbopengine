GetText

member of hbe::LogLine Engine/Log/LogLine.h const noexcept [[nodiscard]] the message body, with the union already resolved

Signature

[[nodiscard]] const char* GetText() const noexcept;

Function description

if (unlikely(isLong))
{
        return longText;
}

return text;

One branch on isLong, and that is the whole function. It exists because the anonymous union makes both members nameable at any time — line.longText compiles whether or not it is the live variant — so the alternative to this accessor is a reader that has to remember the flag, and one reader that forgets prints the first eight bytes of an inline message as a pointer.

The returned pointer addresses the line's own storage: the inline buffer inside the object, or the allocation the producing constructor made. No copy is made and no length is returned, so the string is exactly as long as its terminator says, which is why the truncation rules of the constructor are also the rules for what you see here.

Parameters

None.

Return value

TypeWhat you get
const char* The message, NUL-terminated, never null for a line that was constructed correctly. Valid until the line is destroyed or moved from — the inline variant points into the object itself, so a line held in a queue that gets swapped or cleared invalidates it. Empty, not null, for a default-constructed line and for one that was moved from; for a long line, up to Config::LogLineLength bytes of a longer message are lost before it gets here, in the renderer rather than in the line
There is no length and no variant check, so this function cannot tell you it is lying. If isLong and the storage disagree — which only a hand-built line can arrange, via the null-text branch — this returns an indeterminate pointer and the caller's strlen is where the crash appears, far from the construction that caused it. Reading isLong alongside the result costs nothing and localises that bug.

Examples

The one caller in the engine, appending the body after the prefix it just built:

From Engine/Log/Logger.cpp

for (auto& log : swapBuffer)
{
        ...
        InlineStringBuilder<Config::LogLineLength * 2> text;

        text << '[' << timeStampStr.c_str() << "][" << log.threadName << "[";
        text << log.category << "][" << levelStr << "] ";
        text << log.GetText();

        textBuffer.emplace_back(text.c_str());
}

Note that the result is consumed immediately and copied into an HString in the same iteration — the only safe pattern, since the next statement after the loop clears swapBuffer and destroys the line the pointer belongs to. Nothing in the engine keeps a const char* out of a line past its own batch.
