LogUtil

Engine/Log/LogUtil.h namespace hbe::LogUtil 4 functions 1 member type the log's own elapsed-time clock and the two formatters every stored line is built from

Class description

A namespace, not a class. It holds the instant that every LogLine timestamp is measured against, and the two functions that turn an instant and a ELogLevel into text. Nothing here knows about buffers, categories or the queue: LogUtil is the only part of the module that a caller may use with no Logger in existence, and the only part whose implementation touches neither MemoryManager nor Engine::Get().

The clock is deliberately relative. GetStartTime answers with a steady_clock instant captured the first time anybody asks, and ResetStartTime moves that instant to "now". A log therefore reads as time-since-start rather than as a wall-clock value — which is the right unit for a frame-rate or stall report and the wrong one for correlating with another process's log.

Asking for the start time sets it. The epoch is a function-local static inside LogUtil.cpp, initialised on first call, so GetStartTime() is not a pure read: the first call fixes the zero point. Logger's constructor calls it and discards the result precisely to make that happen at logger construction.
The epoch is ordinary mutable storage with no lock and no atomic around it. ResetStartTime writes it while GetTimeStampString reads it, and nothing serialises the two. That is safe only because the engine writes it exactly once, in Engine::Engine(), before any thread that logs exists. A subsystem that calls ResetStartTime at runtime is a data race before it is a confusing log.

Template parameters

None — hbe::LogUtil is a plain namespace, not a template.

Class properties

NameDeclarationWhat it means
TTimePoint using TTimePoint = std::chrono::time_point<std::chrono::steady_clock>; member type The one clock type the module timestamps with, spelled identically in Logger::TTimePoint and LogLine::TTimePoint — three declarations of the same type rather than one alias used by all three. Because it is steady_clock, a timestamp cannot be converted to a date; nothing in this module records wall-clock time

No variables. The epoch is a function-local static inside LogUtil.cpp's anonymous namespace (MutableStartTime()), so there is no object at namespace scope to take the address of, reset by hand, or observe from another translation unit. The only way in or out is the two functions.

Non-member helper functions

None. LogUtil.h declares nothing outside the namespace — the four functions above are the whole file's public surface, and all four are defined once in Engine/Log/LogUtil.cpp with external linkage, so every translation unit shares them. Contrast PrintArgs, whose copies are per translation unit.
