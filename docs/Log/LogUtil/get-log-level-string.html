GetLogLevelString

member of hbe::LogUtil Engine/Log/LogUtil.h noexcept [[nodiscard]] the name of a severity, interned once so printing it costs a pointer copy

Signature

[[nodiscard]] StaticString GetLogLevelString(ELogLevel level) noexcept;

Function description

A switch over the six real levels of ELogLevel, each returning one of six function-local StaticString statics: "Verbose", "Info", "Significant", "Warning", "Error", "FatalError". Because they are interned, the returned value is an identifier-sized handle and repeating the call costs the switch and nothing else.

The statics are initialised on the first call, from whichever thread logs first, and interning a string takes the static-string table's own mutex. After that first call the function takes no lock and touches no shared state, so it is as safe to call from a worker as AddLog assumes — the logger calls it on the producer thread for the inline error path and on the drain thread for every queued line.

An unrecognised level yields an empty string, not a complaint, and the compiler will not tell you when the enum outgrows this function. The default branch returns a default-constructed StaticString, so ELogLevel::MAX or a value cast out of range from a config parameter prints as nothing: [0:0:1:4][Worker 0][Engine][] stalled. The same default swallows a future enumerator — add a seventh level to ELogLevel and this switch still compiles clean while the new level prints blank. The names exist twice in the module, in the enum and here, and nothing but a test links them.
LogUtil.cpp declares a name that is never used. The function opens with static StaticString none("None"); and no branch returns it, while the branch that would want a fallback returns an empty value instead. The interned string "None" is therefore created and never printed — read that as an unfinished decision about what an unknown level should look like, not as a documented behaviour.

Parameters

ParameterTypeRequirement
level ELogLevel Any value of the enum; nothing is rejected. The six real levels have names — MAX and any out-of-range cast come back empty. A level read from a uint8_t config parameter is worth range-testing before it reaches a line, precisely because this function cannot report the problem

Return value

TypeWhat you get
StaticString The interned name, by value — a handle into the static-string table, valid for the rest of the process and cheap to copy. Empty for a level with no name. [[nodiscard]]: there is no other way to learn a level's text, so discarding it is always a mistake

Examples

The drain path, where the stored level becomes part of the line's prefix:

From Engine/Log/Logger.cpp

for (auto& log : swapBuffer)
{
        InlineStringBuilder<64> timeStampStr;
        LogUtil::GetTimeStampString(timeStampStr, log.timeStamp);
        auto levelStr = LogUtil::GetLogLevelString(log.level);

        text << log.category << "][" << levelStr << "] ";
        text << log.GetText();
        ...
}

The same call in the emergency path, which writes to standard output or standard error without ever touching the queue — the reason a level name is available before a Logger exists:

From Engine/Log/Logger.cpp

void EmergencyLog(StaticString category, ELogLevel level, const Logger::TLogFunction& logFunc)
{
        Logger::TLogStream str;
        str << '[' << category << "][" << LogUtil::GetLogLevelString(level) << "] ";
        logFunc(str);

        auto* out = level >= ELogLevel::Error ? stderr : stdout;
        fputs(str.c_str(), out);
        ...
}

The second example is a function in Logger.cpp's anonymous namespace, so it is engine-internal rather than API — it is shown because it is where the level/destination rule lives: Error and above go to standard error, everything below to standard output.
