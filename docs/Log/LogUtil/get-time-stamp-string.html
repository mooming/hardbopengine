GetTimeStampString

member of hbe::LogUtil Engine/Log/LogUtil.h noexcept elapsed time as h:m:s.mmm, written into a fixed inline buffer with no allocation

Signature

void GetTimeStampString(InlineStringBuilder<64>& outStr,
                        const TTimePoint& currentTime = std::chrono::steady_clock::now()) noexcept;

Function description

Subtracts GetStartTime() from currentTime, splits the difference into hours, minutes, seconds and milliseconds, and appends them to outStr separated by :, : and .. Each field is produced with std::to_string on an integer count, so the whole call is a handful of appends into a buffer that already exists: no allocation, no sprintf, no locale.

The default argument is what lets one function serve both jobs. Called with one argument it stamps now — that is what an immediate or inline write wants. Called with an instant it stamps that instant — which is how ProcessBuffer stamps each queued line with the moment it was produced (LogLine::timeStamp) rather than the moment the drain thread got round to it.

The fields are not zero-padded, and the fractional part is therefore not what it looks like. Every field comes from std::to_string on an integer, so 3.05 seconds renders as 0:0:3.50 and 3.5 seconds renders as 0:0:3.500 — the millisecond field carries only as many digits as its value needs. Two consequences that bite: a reader cannot trust the fraction's width, and sort on a log file is not chronological, because 0:0:10.5 sorts before 0:0:9.9. Nothing in the module pads them for you.
Hours accumulate; they do not wrap. The hour field is the total hours of the elapsed span, not hours-of-day, so a long-running server's lines read 72:14:09:220 after three days. Minutes and seconds are reduced modulo 60 and milliseconds modulo 1000, so the four fields always describe the same instant.

Parameters

ParameterTypeRequirement
outStr InlineStringBuilder<64>& The builder to write into. The size is part of the type, so a builder of any other capacity — including Logger::TLogStream, which is 131072 — will not bind; you must construct a 64-byte builder for this call. Text is appended and never cleared first, so pass a fresh builder or one you have called Clear() on. Writes clamp at the bound and truncate silently, so an over-long result is cut rather than corrupting memory
currentTime const TTimePoint& The instant to render, defaulted to std::chrono::steady_clock::now(). It must be a steady_clock time point — LogLine::timeStamp is one, but a system_clock value from outside the engine is a different clock and the subtraction would be meaningless. An instant earlier than the epoch yields a negative span and the fields print negative counts

Return value

void. The result is the text appended to outStr; read it with outStr.c_str() or stream the builder directly, which is what every caller in the module does. The function reports nothing on failure because it has no failure: the builder truncates itself and the caller cannot tell.

Examples

Stamping a stored line with its own production time, from the drain path — the two-argument form, and the reason a queued line does not carry the drain time:

From Engine/Log/Logger.cpp

for (auto& log : swapBuffer)
{
        InlineStringBuilder<64> timeStampStr;
        LogUtil::GetTimeStampString(timeStampStr, log.timeStamp);
        auto levelStr = LogUtil::GetLogLevelString(log.level);

        InlineStringBuilder<Config::LogLineLength * 2> text;

        text << '[' << timeStampStr.c_str() << "][" << log.threadName << "[";
        text << log.category << "][" << levelStr << "] ";
        text << log.GetText();
        ...
}

The one-argument form, which stamps the moment the call runs instead:

From Engine/Log/Logger.cpp

InlineStringBuilder<64> timeStampStr;
LogUtil::GetTimeStampString(timeStampStr);        // defaults to steady_clock::now()
