GetStartTime

member of hbe::LogUtil Engine/Log/LogUtil.h noexcept the instant every log timestamp is measured from — and the first call is what fixes it

Signature

const TTimePoint& GetStartTime() noexcept;

Function description

Returns the module's zero point: std::chrono::time_point<std::chrono::steady_clock>, held as a function-local static inside LogUtil.cpp and created on first call. GetTimeStampString subtracts it from a line's instant, so this is the number that decides what "0:0:0.000" means in your output.

The call is not read-only. The static initialises to steady_clock::now() the first time the function runs, so the first caller in the process — whichever that happens to be — silently establishes the epoch. Logger's constructor exploits exactly this: it calls LogUtil::GetStartTime(); and throws the reference away, purely so the epoch exists before the first line can be timestamped.

A reference, not a snapshot. The same object is returned before and after ResetStartTime, so a reference held across a reset reads the new instant. Copy the value if you need the old zero point — and note that no API hands you a way to put it back.

Parameters

None.

Return value

TypeWhat you get
const TTimePoint& The live epoch object, not a copy of it. Static storage duration, and std::chrono::time_point has no destructor worth sequencing, so the reference stays valid through shutdown — but its value changes if anything calls ResetStartTime. Not [[nodiscard]], which is why the discard inside the Logger constructor compiles without a warning

Examples

The call with no argument and no use of the result, whose whole purpose is to create the epoch at logger construction:

From Engine/Log/Logger.cpp

Logger::Logger(Engine& engine, const char* path, const char* filename) noexcept
        : allocator("LoggerMemoryPool")
        , inputAlloc("LoggerInputPool")
        , ...
{
        Assert(engine.IsMemoryManagerReady());

        instance = this;
        LogUtil::GetStartTime();              // result discarded on purpose
        ...
}

Elapsed time inside a log statement, which is the only reason a caller normally wants the epoch at all:

Illustrative — the repository computes elapsed time inside GetTimeStampString rather than at call sites.

auto elapsed = std::chrono::steady_clock::now() - hbe::LogUtil::GetStartTime();

log.Out([elapsed](auto& ls)
{
        ls << "shader compile took "
           << std::chrono::duration_cast<std::chrono::milliseconds>(elapsed).count()
           << "ms since log start";
});
