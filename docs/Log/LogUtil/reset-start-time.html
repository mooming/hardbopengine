ResetStartTime

member of hbe::LogUtil Engine/Log/LogUtil.h noexcept make "now" the instant every later line measures itself against

Signature

void ResetStartTime() noexcept;

Function description

Assigns std::chrono::steady_clock::now() to the epoch that GetStartTime returns. After the call, a new line's elapsed time starts from zero again; every line already produced keeps the number it was given, so the output contains the old sequence followed by the new one. There is no flag, no log line of its own and no return value to tell you the clock just moved — the only trace is the discontinuity in the file.

It takes no instant as an argument, and the header states the reason: the caller that owns the decision (SystemStatistics) keeps its own start in time::TTime over high_resolution_clock, and that clock is system_clock on some standard libraries. A parameter of the caller's clock type would have to be converted into steady_clock to be stored — a unit error that only appears when the toolchain changes under the code. Reading the log's own clock here instead removes the conversion entirely.

This is an unsynchronised write to a static that every formatted line reads. The epoch is a plain TTimePoint, guarded by no mutex and no atomic (see the namespace note). Calling ResetStartTime while another thread is inside GetTimeStampString — which is every thread that ever logs, on the drain path — is a data race on a 64-bit-or-wider value, not merely a cosmetic renumbering. It is safe for the engine's use because the call happens in Engine::Engine(), before any worker or IO thread exists. If you call it anywhere else, prove to yourself that no other thread can log at that moment.

Parameters

None — deliberately. The new zero point is always "now", never a value the caller supplies.

Return value

void. The previous epoch is not returned, so the old zero point cannot be restored: there is no undo, and no way to measure how far the clock was moved. Read GetStartTime into a local value before resetting if you need to know either.

Examples

The only call site in the repository — the engine constructor, not Initialize:

From Engine/Engine/Engine.cpp

Engine::Engine()
        : preEngineInit(this)
        , ...
        , logger(*this, "./", "hardbop.log")
{
        time::ResetEngineEpoch();
        LogUtil::ResetStartTime();          // log time 0 = engine construction
        std::signal(SIGABRT, SignalHandler);
        ...
}
The order of those two statements is the contract. Resetting the log clock before any thread that logs exists is what keeps this call race-free, and putting it in the constructor rather than in Initialize means the zero point is set even by a process that initialises only part of the engine — a headless context that passes EInitLevel flags without an application still gets log time measured from engine construction.
