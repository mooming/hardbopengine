ELogLevel

Engine/Log/LogLevel.h namespace hbe enum class : unsigned char 7 enumerators severity of one line, where the declaration order is the filtering rule

Class description

Six severities from chatty to fatal, plus MAX as a count. The header says "ordered from least to most severe" and every consumer in the module relies on exactly that: the logger never tests a level for equality, it tests ranges — level < threshold drops a line in AddLog, level >= ELogLevel::Warning decides whether the file gets flushed in ProcessBuffer, and level >= ELogLevel::Error selects the inline-write path in AddLog. Nothing switches on individual levels except GetLogLevelString.

The numeric values are public, not internal. AddLog compares against a TAtomicConfigParam<uint8_t> named Log.Level, and TaskSystem::Initialize does the same for its own category, so a level reaches the logger as a uint8_t that is static_cast against ConfigParam storage. The order is therefore a stored-format contract: inserting a level between Info and Significant silently renumbers every level that a config file or a defaulting parameter already holds — including the two Config::EngineLogLevel constants, which are uint8_t literals written against this enum's numbering.

MAX is a sentinel, not a level you log at. It exists so the count of real levels has a name. It has no text — GetLogLevelString returns a default-constructed StaticString for any value outside the six, so printing MAX yields an empty field, not "MAX".

Class properties

The enumerators, with the ordinal each one has under : unsigned char. The ordinal column is not decoration: it is the number a uint8_t log-level parameter stores.

NameDeclarationWhat it means
Verbose Verbose (0) enumerator Per-line detail. It is dropped at the default setting, because AddLog compares against Log.Level, whose default is Info. It is rejected before the formatting callback runs, so the line is never rendered and no InlineStringBuilder is built for it
Info Info (1) enumerator Ordinary progress, and the default level of both Logger::Get(category, level) and the Log.Level parameter — so it is the level a call site gets when it does not name one
Significant Significant (2) enumerator A milestone worth keeping in a normal build's output. It is the first level that survives the engine's own standard-output threshold (Config::EngineLogLevelPrint, which is 2 unless memory logging is compiled in)
Warning Warning (3) enumerator Degraded but continuing. Reaching it has one mechanical consequence: ProcessBuffer sets its needIOFlush flag and calls outFileStream.flush() after the batch, so a warning is on disk shortly after it is written while a plain Info batch may sit in the stream buffer
Error Error (4) enumerator A failed operation. The threshold for two special behaviours in AddLog: produced on the log thread it is written inline rather than queued, and it is the level EmergencyLog sends to standard error rather than standard output
FatalError FatalError (5) enumerator The process is not continuing. AddLog enqueues it, then calls Flush, debugBreak() and Assert(false) before returning, and skips the step that wakes the IO stream — the flush is this thread's own business by then
MAX MAX (6) enumerator, sentinel One past the last real level. Logging at it is not meaningless — it passes every >= threshold in the module, including the one that flushes the file — but it has no name text, so the line renders with an empty level field: [0:0:1:4][Worker 0][Engine][] texture cache disabled
