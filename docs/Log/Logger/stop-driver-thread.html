StopDriverThread

member of hbe::Logger Engine/Log/Logger.h public end the driver thread, letting it finish the work it holds before it exits

Signature

void StopDriverThread() noexcept;

Function description

Lowers the flag that keeps DriverLoop repeating, then joins. It is reached only when the process is done logging — the destructor calls it before anything else is torn down.

driverRunning.store(false, std::memory_order_release);

if (driverThread.joinable() && driverThread.get_id() != std::this_thread::get_id())
{
    driverThread.join();
}

The join is guarded against the current thread because the driver thread is the one that writes the log file, and a line written during shutdown can reach this call. Joining oneself is undefined; joining nothing is harmless. The joinable() test covers a logger that was destroyed without ever starting a driver.

What makes the stop safe rather than merely final is where the last pass happens. Lowering the flag only ends the loop; the trailing drain lives inside DriverLoop itself, so whatever was still queued at the moment the stop was requested is written by the thread that owns the file, rather than abandoned to whoever happened to ask for shutdown. A caller of this function returns only after that work is done.

Parameters

None.

Return value

None. Returns once the driver thread has finished its final pass and exited.

Notes

  • Call sites. Logger::~Logger is the only caller. It runs construction's teardown in the reverse order: stop the thread, clear instance, then drain and close the file.
  • Not a substitute for StopTask. That stops the periodic drain task on the task system's stream; this stops the logger's own thread. A logger with a task system installed needs both, and they are independent.
  • After this returns nothing may log. instance is cleared immediately afterwards, so a later call reaches a logger that is no longer there.
