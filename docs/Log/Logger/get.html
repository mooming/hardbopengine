Get

member of hbe::Logger Engine/Log/Logger.h 2 overloads static noexcept the same name asks for two different things, and the argument list decides which

Signatures

One page for the name, because both forms answer "give me the logger" and differ in what they hand back:

/// the sink itself
[[nodiscard]] static Logger& Get() noexcept;

/// a category and level bound into one value
[[nodiscard]] static SimpleLogger Get(StaticString category,
                                       ELogLevel level = ELogLevel::Info) noexcept;

Function description

With no argument, Get returns the live singleton: it reads the static instance pointer and FatalAsserts if it is null. That reference is what you need in order to call SetFilter, Flush, AddLog or StartTask directly.

With a category — and optionally a level, defaulting to Info — it returns a SimpleLogger by value: two fields copied out, no reference to the logger held, no allocation, and no check that a logger exists yet. This is the form almost every call site uses, because it lets a subsystem state its category once and then write log.OutError(…).

Overload resolution, not intent, picks the form. Logger::Get("Renderer") cannot be the sink, because StaticString is implicitly constructible from const char* — a caller who meant the singleton and left an argument in gets a SimpleLogger and a compile error only at the point of use, when a method turns out not to exist. Ask for the sink with an empty argument list, always.
A SimpleLogger obtained before a logger exists is not broken — it is a different code path. Nothing here checks instance, and Out tests it on every call: while it is null, the line bypasses the queue entirely and is written straight to standard output or standard error by the file-local emergency path. So logging "works" before the constructor and after the destructor, but it does not reach the log file, is not filtered by the level parameter or by any category filter, and is not ordered against queued lines. The no-argument form, by contrast, stops the process with FatalAssert rather than let you write to nothing.
The first call with a literal interns that literal. StaticString category means a const char* argument is looked up in the static-string table, which takes that table's mutex (String: StaticString). Storing the result in a static const auto, as every engine call site does, moves the interning to the first call and leaves the rest as two field copies.

Parameters

ParameterTypeRequirement
category StaticString Only on the second overload. The filter key and the bracketed prefix on every line this value produces — free-form, interned, and it must match the string passed to SetFilter character for character for a filter to apply
level ELogLevel Defaulted to Info. The level a plain Out logs at; it is stored in the value, so a later Out(ELogLevel::Error, …) on the same object overrides it for that line only

Return value

TypeWhat you get
Logger& The singleton. Valid while the constructor's object is alive; it is an Engine member, so its lifetime is the engine's
SimpleLogger A two-field value (category, level), copyable and storable in a static, and never invalidated by anything the logger does — it looks the logger up by static pointer on each call rather than holding a reference to it

Examples

Both forms in one function, from the task system's initialisation — first the sink to install a filter, then a bound logger for its own lines:

From Engine/Core/TaskSystem.cpp

void TaskSystem::Initialize() noexcept
{
        auto& logger = Logger::Get();
        auto logFilter = [](auto level)
        {
                ...
                return level > static_cast<ELogLevel>(logLevel.Get());
        };

        logger.SetFilter(GetName(), logFilter);

        auto log = Logger::Get(GetName());
        log.Out([this](auto& ls) { ls << "Hardware Concurrency = " << numHardwareThreads; });

The same bound-logger form cached in a static, which is how a file-scope helper avoids repeating the category:

From Engine/Renderer/Vulkan/VulkanRenderer.cpp

void LogFailure(const char* step, VkResult result) noexcept
{
        static const auto log = Logger::Get("VulkanRenderer", ELogLevel::Error);
        log.OutError([step, result](auto& ls)
        {
                ls << step << " failed (VkResult=" << static_cast<int>(result) << ")";
        });
}

Note the asymmetry the two examples demonstrate: the filter has to be installed on the sink, so it goes through the no-argument form, while everything that only emits lines uses the category form and never touches the sink again.
