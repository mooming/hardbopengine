ProcessBuffer

member of hbe::Logger private Engine/Log/Logger.h noexcept one drain pass: claim the buffers, swap the queue, render every line, hand the batch out

Signature

// private:
void ProcessBuffer() noexcept;

Function description

This is where a queue of LogLine becomes text. Order of operations:

  1. Claim. A DrainGuard exchanges true into isDraining; if it did not acquire the claim, the function returns at once — having drained nothing and having touched needFlush. The guard releases the flag only if it acquired it.
  2. Check. If hasInput reads false, needFlush is cleared and the function returns. This is the path a continuously-rescheduled drain takes while nothing is logging (see the runnable's return value).
  3. Swap. With AllocatorScope scope(allocator) open and inputLock held, std::swap(inputBuffer, swapBuffer) and hasInput is cleared. Producers are unblocked again as soon as this block ends; nothing below it holds a lock.
  4. If swapBuffer is empty, clear needFlush and return.
  5. Render. For each line: note level >= Warning into a local needIOFlush, format the line's own timestamp with GetTimeStampString and its name with GetLogLevelString, and build [time][thread][category][level] text into a InlineStringBuilder<Config::LogLineLength * 2> — 2048 bytes — appending the result into textBuffer.
  6. Release the lines. swapBuffer.clear() destroys each LogLine, which returns any heap-allocated long text to the system allocator.
  7. Write. FlushBuffer passes the whole batch to every output function — file then console — and textBuffer is cleared.
  8. If any line in the batch reached Warning, the file stream is flushed; then needFlush is cleared, releasing anyone sitting in WaitForFlush.
A long message is truncated at render time even though it was stored whole. Step 5 builds into 2048 bytes, while LogLine keeps a body longer than 1022 characters in a heap allocation as large as the statement produced — up to 131071 bytes, the ceiling of TLogStream. So a body of roughly 2000 bytes or more survives allocation, survives the queue, survives the move — and is cut off mid-sentence when the prefix and body are concatenated into that 2048-byte builder, which truncates silently. The union in LogLine buys fidelity the drain then throws away; if you need a whole 100 KB dump, do not send it as one log line.
A caller that loses the claim has flushed nothing, and cannot tell. Step 1 returns without draining and without clearing needFlush. That is the safety property that makes an inline drain from a waiting thread legal — two threads must never share swapBuffer — but it means Flush on the log thread, or the inline branch of WaitForFlush, can return having done nothing at all.
needFlush describes the instant the pass ends, not the lines you care about. Lines enqueued after the swap in step 3 are already back in inputBuffer, and step 8 clears the flag regardless — which is precisely the caveat Flush's header records: the handshake guarantees an empty queue at some instant, not the caller's own prefix. Two other asymmetries are worth knowing: clearing needFlush happens whether or not a single line was written, and the file flush in step 7 is keyed on the batch's highest level, so a batch containing one Warning puts every line in it on disk.

Parameters

None. It drains whatever is queued, on the calling thread, into whichever destinations are installed.

Return value

void. No count of lines written, no indication of whether the claim was won, no status from the destinations. The only externally visible effect is the file and console output itself plus the clearing of a private flag.

Examples

Reached three ways, never by name from outside the class. From the drain task's runnable, which calls it on the IO stream's thread:

From Engine/Log/Logger.cpp

auto runnable = [](void* userData, std::size_t startIndex, std::size_t endIndex) -> std::size_t
{
        auto self = static_cast<Logger*>(userData);
        ...
        const bool isRunning = self->isRunning.load(std::memory_order_relaxed);
        if (!isRunning)
        {
                return 1;
        }

        self->ProcessBuffer();

        return 0;
};

And from the two shutdown paths, which call it directly so that a stopped drain cannot lose the last batch:

From Engine/Log/Logger.cpp

Logger::~Logger() noexcept
{
        instance = nullptr;

        ProcessBuffer();

        outFileStream.flush();
        outFileStream.close();
}
