SetIODriver

member of hbe::Logger Engine/Log/Logger.h public install the IO stream this logger's driver thread should drive, or withdraw it — the handover that makes stream destruction safe while another thread is running it

Signature

void SetIODriver(TaskStream* stream) noexcept;

Function description

Installs the IO stream this logger's driver thread should drive, or withdraws it. The whole body is a lock acquisition and an assignment, and the lock is the entire design:

std::lock_guard lock(driverLock);
ioStream = stream;

Logger's IO stream is a service stream — the logger is one of its customers, as asynchronous file access will be — and it is a ride-on-thread stream, so its driver must be named rather than assumed. The task system installs it once its streams exist and withdraws it before it destroys them. That ordering is not politeness: driverThread outlives the task system by design, so a pointer left installed would be read on a pass whose stream had already been freed.

Passing the lock is what makes withdrawal mean something. DriverLoop holds driverLock across stream->Update(), so nullptr cannot land while a pass is in flight: the call blocks until that pass has returned. This is the only mechanism that lets the task system free its streams while another thread is running them.

Withdrawing also withdraws the drain task that lived on the stream, and the flag goes with it:

if (stream == nullptr)
{
    isRunning.store(false, std::memory_order_release);
}

Nothing can run that task any more, so leaving isRunning set would have every later Flush wait its full 1000 ms on an executor that no longer exists, then report the loss and assert. From here on the driver loop writes the queue directly — the same work with one fewer hop.

Parameters

ParameterTypeMeaning
stream TaskStream* The service stream to drive, or nullptr to withdraw it. Not owned: never freed here. The previous value, if any, is replaced without warning — there is one slot, not a stack of customers

Return value

None. The call cannot fail; the only thing it can do is wait for an in-flight pass.

Notes

  • Who calls it. The task system, from its own thread — never the driver thread. TaskSystem installs &GetIOTaskStream() once its streams exist, and passes nullptr while shutting streams down. See TaskSystem.
  • Thread safety. Safe to call from any thread that may install or withdraw the stream, because the pointer is only ever read or written under driverLock. It is not called by AddLog or any logging path.
  • Ordering. Withdrawal must precede stream destruction, and installing must follow stream construction. Both are the task system's obligation, and nothing in the signature enforces either.
