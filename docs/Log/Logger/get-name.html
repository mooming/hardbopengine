GetName

member of hbe::Logger Engine/Log/Logger.h static noexcept [[nodiscard]] the category the logger uses when it logs about itself

Signature

[[nodiscard]] static StaticString GetName() noexcept;

Function description

Returns the enclosing class name, derived once from __PRETTY_FUNCTION__ by StringUtil::ToCompactClassName and cached in a function-local static, so the cost is an interning lookup on the first call and a handle copy afterwards. Because the value comes from this function's own __PRETTY_FUNCTION__, it always answers "Logger"; the neighbouring convention in the engine — passing your own __PRETTY_FUNCTION__ to ToCompactClassName, as SystemStatistics does — derives the caller's name instead. The two look alike and mean different things.

Its purpose is not introspection. It is the category argument of every line the logger emits about its own operation: "Logger started." in StartTask, the drain-task-tracking failure in the same function, "Logger shall be terminated." in StopTask, and the two give-up reports in WaitForFlush. Keeping it a function rather than a literal is what lets those lines be attributed without hard-coding a spelling that has to track the class name.

"Logger" is an ordinary category, so it can be silenced like one. SetFilter(Logger::GetName(), …) filters the logger's own chatter — its start and stop notices and its flush-timeout reports — without touching the level threshold that every other subsystem shares. Note the exception: the give-up reports reach the queue only if a logger and a drain task are both alive, so a filter is a way to lose the report that tells you the drain thread is wedged.

Parameters

None.

Return value

TypeWhat you get
StaticString An interned handle for the class name of the enclosing scope — "Logger" here — valid for the rest of the process. [[nodiscard]], because it exists to be passed somewhere. If the pretty function string ever lacks the :: separators ToCompactClassName searches for, that helper returns an empty StaticString and the logger's own lines lose their category rather than failing loudly

Examples

Used as the category of a self-reporting line, twice in one function:

From Engine/Log/Logger.cpp

void Logger::StartTask(TaskSystem& taskSys)
{
        AddLog(GetName(), ELogLevel::Info, [](auto& logStream) { logStream << "Logger started."; });
        ...
        auto* drainTask = taskSys.FindTask(taskID);
        if (drainTask == nullptr)
        {
                AddLog(GetName(), ELogLevel::Error, [](auto& logStream)
                {
                        logStream << "The task registry could not track the logger's drain task…";
                });
                return;
        }
}

Filtering exactly those lines and nothing else:

Illustrative — no call site filtering the logger's own category exists in the repository.

hbe::Logger::Get().SetFilter(hbe::Logger::GetName(), [](auto level)
{
        return level >= hbe::ELogLevel::Error;   // keep the failure reports, drop start/stop notices
});
