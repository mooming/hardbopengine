SetFilter

member of hbe::Logger Engine/Log/Logger.h noexcept one predicate per category, consulted on the producing thread before anything is formatted

Signature

void SetFilter(StaticString category, TLogFilter&& filter) noexcept;

Function description

Moves a TLogFilter — std::function<bool(ELogLevel)> — into the category map under filterLock. Two statements, a lock guard and an assignment; the work happens later, inside AddLog, which looks the category up on every line and drops the line if the predicate returns false.

Its purpose is per-subsystem thresholds. The module-wide threshold is the Log.Level parameter, identical for every caller; a filter is how one subsystem says "quieter than everyone else" without editing its call sites. It is checked after that global threshold and before the formatting callback, so a rejected line costs a hash lookup and a call, not a rendered string.

Set semantics, not add semantics. The map is keyed by category, so the last call for a category wins and earlier ones are destroyed. There is no removal and no clearing: to switch a category off permanently you install a predicate that always returns false, and there is no way back to "no filter" except a predicate that always returns true. Two subsystems sharing a category string share one filter, deliberately or not.
Your predicate runs on the producer's thread while filterLock is held, and that mutex is not recursive. A filter that calls SetFilter deadlocks the calling thread on its own lock; a filter that logs directly through AddLog does the same, while a log through the normal Out path survives only if the level fails the global threshold first and so never reaches the lookup. Every call site in the engine is a level comparison against a configuration parameter, which is the whole of what a filter should do. It also inherits the producer's thread: a filter that blocks, blocks the frame that was trying to log.

Parameters

ParameterTypeRequirement
category StaticString Must match the category passed to AddLog — usually via Logger::Get(category, level) — exactly, since the key is an interned string and a near-miss silently filters nothing
filter TLogFilter&& Anything convertible to std::function<bool(ELogLevel)>: it receives the line's level and returns true to keep it. It is moved from, so a lambda with captures is transferred rather than copied. A null function is tolerated at install time and skipped at check time — it filters nothing, which is the same as no filter at all

Return value

void. There is no report of whether the category already had a filter, and no way to read the current one back out — filters is private and has no accessor. The only observable effect of a mistake here is missing lines somewhere else.

Examples

The one call site in the engine, installed during task system initialisation:

From Engine/Core/TaskSystem.cpp

void TaskSystem::Initialize() noexcept
{
        auto& logger = Logger::Get();
        auto logFilter = [](auto level)
        {
                static TAtomicConfigParam<uint8_t> logLevel("Log.TaskSystem", "The TaskSystem Log Level",
                                                        static_cast<uint8_t>(ELogLevel::Warning));

                return level > static_cast<ELogLevel>(logLevel.Get());
        };

        logger.SetFilter(GetName(), logFilter);

        auto log = Logger::Get(GetName());
        log.Out([this](auto& ls) { ls << "Hardware Concurrency = " << numHardwareThreads; });
}
Read that filter's comparison before copying the pattern. It returns level > threshold, not level >= threshold, and its default threshold is Warning — so with default settings the TaskSystem category keeps only Error and FatalError, and the "Hardware Concurrency = …" line three statements later is discarded by the filter installed two statements before it. Note too that the filter's own parameter is Log.TaskSystem, an independent threshold from the module-wide Log.Level: a line must satisfy both to be written, and the stricter one wins.
