Resource

namespace hbe Engine/Resource 7 headers, 6 sources — binary buffers and the manager that loads and keeps them

Module description

Two ideas. A Buffer is bytes plus the callback that releases them, so ownership of a blob does not depend on who allocated it. A ResourceManager keys buffers to paths, loads them synchronously or asynchronously, reference-counts them internally, and advances the asynchronous ones from PostUpdate. A Resource is the handle a caller holds back, and it is deliberately empty.

Class description

A handle to a loaded resource managed by ResourceManager.

Template parameters

None — Resource is not a template.

Class properties

None.

Class methods

class Resource final
{
public:
    Resource() noexcept;
    ~Resource() noexcept;
};
The public surface is a constructor and a destructor. There is no accessor to read — no path, no id, no Buffer. So a Resource returned by RequestLoad or Load is currently a lifetime token and nothing more, which means a caller cannot yet ask the handle for the bytes it stands for. If your code needs to, that gap is the work to do; this page records it rather than describing an accessor that does not exist.

Buffer (Engine/Resource/Buffer.h)

Class description

A byte block plus the function that knows how to release it. Move-only, so a buffer cannot be duplicated into two owners of the same memory.

Template parameters

None — Buffer is not a template; type-safe access is per call, see GetDataAs.

Class properties

size, data and releaser; all private, reached through the methods below.

MethodContract a caller depends on
Buffer(genFunc)The generator fills in the size and the pointer by reference; with no releaser the buffer assumes the memory is released another way, so pair a raw allocation with the two-argument constructor
SetReleaserInstall the release path after construction, which is how a buffer built elsewhere learns who owns its bytes
GetDataAs<T>A reinterpret_cast of the raw pointer. The element type is a promise you make, not something checked
TranslateSizeAs<T>Byte size divided by sizeof(T) — element count for the type you promised above. It truncates, so a malformed size shows up as a short count rather than an error

ResourceManager (Engine/Resource/ResourceManager.h)

Class description

Loads buffers by path, keeps them, and hands out Resource handles. One instance belongs to the Engine, which calls PostUpdate each frame.

Template parameters

None — ResourceManager is not a template.

Class properties

The table of loaded items and pending requests; all private. An item is a nested ResourceItem: an id, a referenceCount, the interned path and the Buffer itself.

Class methods

template<typename T>
using TVector = hbe::HVector<T>;

ResourceManager() noexcept;
~ResourceManager() noexcept;

[[nodiscard]] Resource RequestLoad(StaticString path);  // asynchronous
[[nodiscard]] Resource Load(StaticString path);        // synchronous
void PostUpdate(Engine& engine) noexcept;
MethodContract a caller depends on
RequestLoadQueues the load and returns immediately; the work is dispatched to the TaskSystem and completed by later PostUpdate calls. So the handle is valid at once, and what it stands for may not be
LoadBlocks until the buffer is resident — the right call at startup, the wrong one inside a frame
PostUpdateAdvances pending requests and retires items whose references reached zero. Called by the engine; calling it yourself from inside a frame would advance the queue twice
reference countingInternal. Two loads of one path share one Buffer, and an item is released when its count reaches zero rather than when one handle dies
