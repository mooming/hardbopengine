GetData

member of hbe::Buffer Engine/Resource/Buffer.h 2 overloads noexcept [[nodiscard]] the address of byte zero, and the engine's standing test for "was this buffer built"

Signatures

Both are defined in the header as { return data; } — a field read, nothing else:

/// mutable view of the block
[[nodiscard]] uint8_t* GetData() noexcept;

/// read-only view of the block
[[nodiscard]] const uint8_t* GetData() const noexcept;

Function description

Returns the stored TBufferData, which is a uint8_t*, so pointer arithmetic on the result is in units of one byte and no element type is implied. Const-ness of the result follows const-ness of the buffer, not of the memory: a const Buffer& yields const uint8_t*.

Nothing is checked, offset or clamped, and no extent travels with the pointer. It answers a single question — is there a block — and the amount of it you may touch comes from GetSize. Reading it is valid up to the destruction or move-out of the buffer; the address itself never changes during the buffer's life, because nothing here reallocates.

Parameters

None.

Return value

TypeWhat you get
uint8_t* / const uint8_t* The block, or nullptr when the buffer holds nothing: default-constructed, moved-from, or built by a generator that failed and left its out-parameters alone. Both overloads are [[nodiscard]], so calling one and ignoring it is a compile error

This is the shape the API pushes you into: the buffer factories report no status, so a null pointer is the status channel, and the buffer then goes forward by const Buffer& to whatever reads it, still owned by this scope.

A non-null pointer says nothing about how much you may touch. A generator is free to write a pointer and a size that disagree — BufferUtil::GenerateDummyBuffer is the opposite pairing, a gigantic size with a null pointer, and it is used on purpose. Compare against GetSize() before reading, and check this for null before writing: the write path through a null block is a crash this class will not predict for you.
For anything other than bytes, take the typed view instead. GetDataAs<T>() returns the same address already cast, which keeps the element type in the expression that uses it. GetData remains the right call for a null test and for the raw byte ranges a serialiser works in.
