GetClassName

member of hbe::Buffer Engine/Resource/Buffer.h const noexcept [[nodiscard]] the name this class logs under

Signature

[[nodiscard]] StaticString GetClassName() const noexcept;

Function description

Derived from __PRETTY_FUNCTION__ through StringUtil::ToCompactClassName and cached in a function-local static, so the compaction happens once per process and every later call, from any instance and any thread, returns the same interned StaticString. The value does not depend on the object, which is why this const member could have been static.

Its single purpose in the engine is the log line in the destructor: a buffer releasing nothing needs to say which class failed to own its block, and a literal string would drift away from the class the moment the class was renamed.

Parameters

None.

Return value

TypeWhat you get
StaticString The compacted class name for hbe::Buffer, interned, so comparing two of them with == compares pointers rather than characters. [[nodiscard]], so calling it and dropping the result is a compile error

Examples

The one call site in the repository is this class's own destructor, naming the logger for a block that is being abandoned. From Engine/Resource/Buffer.cpp: 

if (unlikely(releaser == nullptr))
{
        auto log = Logger::Get(GetClassName());
        log.OutWarning([this, func = __func__](auto& ls)
        { ls << '[' << func << "] Releaser func is null, in spite of data is " << data; });

        return;
}

The same idiom — a compacted class name used as a logger key — appears across the engine, so a log filter keyed on Buffer picks up exactly these lines and nothing else; see Log: Logger.
