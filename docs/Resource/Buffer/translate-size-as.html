TranslateSizeAs

member of hbe::Buffer Engine/Resource/Buffer.h template<typename T> const noexcept [[nodiscard]] the byte size divided by sizeof(T) — the element count that matches GetDataAs

Signature

template<typename T>
[[nodiscard]] size_t TranslateSizeAs() const noexcept;

Defined in the header as return size / sizeof(T);.

Function description

One unsigned division of the byte count by sizeof(T). It is the counting half of the typed view: the pointer comes from GetDataAs<T>() and the extent it is legal to walk comes from here, and both are expressed in the same T so the pair is at least self-consistent.

The division truncates, which is the whole of its error behaviour. A block whose byte count is not an exact multiple of sizeof(T) — a truncated file, a header prefix nobody stripped, a T picked one field too wide — reports the smaller count and leaves the leftover bytes unreachable rather than reporting anything wrong.

Parameters

ParameterTypeRequirement
T template parameter, typename The element type the count is wanted in. Must be the same T handed to GetDataAs, or the count is measured against a layout the pointer does not use. No function parameter

Return value

TypeWhat you get
size_t GetSize() / sizeof(T), rounded down. 0 for an empty buffer and for a non-empty buffer smaller than one T. [[nodiscard]], so calling it for effect is a compile error

Examples

Illustrative — no call site for this exists in the repository; nothing calls TranslateSizeAs. See GetDataAs, which is unused for the same reason.

auto buffer = BufferUtil::GetReadOnlyFileBuffer(path);

const auto* verts = buffer.GetDataAs<MeshVertex>();
const auto count = buffer.TranslateSizeAs<MeshVertex>();

if (buffer.GetSize() % sizeof(MeshVertex) != 0)
{
        // the only way to learn the block was a partial record: check the remainder yourself
}

MeshVertex is the real vertex layout declared in Engine/Renderer/Vulkan/VulkanRenderer.h; the snippet is illustrative because no code reads a buffer that way today.

A whole-file buffer and a buffer of records look identical here. The function divides and reports; it cannot tell a byte block that was written as an array of T from one that was written as a header, a string and some padding. Where an exact element count matters, either compare the remainder against zero as above or have the producer record the count itself — which is what the streams do by writing the length ahead of the elements they then copy.
The releaser on a typed buffer has to agree about T too. The engine's own typed releaser in BufferUtil::GetMemoryBuffer recomputes size / sizeof(T) before DeleteArray and asserts that multiplying it back out reproduces size exactly — the same division, with the check this function does not perform.
