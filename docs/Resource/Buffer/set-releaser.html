SetReleaser

member of hbe::Buffer Engine/Resource/Buffer.h Engine/Resource/Buffer.cpp tell an existing buffer who owns its bytes

Signature

void SetReleaser(TReleaseBuffer&& releaseFunc);

Function description

Move-assigns the callable into releaser and then assigns nullptr to the argument, so the caller's std::function is left empty and the buffer is the only holder of the closure. The argument is an rvalue reference, so an lvalue std::function has to be moved by hand at the call site.

It exists because a buffer's producer sometimes cannot know the release path when it starts. A file mapping is the case in the repository: the mapping has to succeed before anybody can say that unmapping is the correct release, and the OS handle has to be detached from the local FileHandle before a closure can carry it. So the buffer is created from the generator alone, checked, and given its releaser here.

This overwrites; it does not release. If releaser already held a closure and data pointed at a real block, the previous closure is destroyed without ever being called and those bytes are unreachable from then on. It is sound only on a buffer that has no releaser yet — which is what the single-argument constructor leaves — and it is not a way to change ownership of a block that is already owned.

Parameters

ParameterTypeRequirement
releaseFunc TReleaseBuffer&& Callable as void(TSize, TBufferData), and it will be called with this buffer's size and data at destruction — not with the pair that existed when it was installed, and not with anything the closure itself returns, since the signature hands nothing back. Anything it captures must still be alive at that destruction: an allocator or a pool reached by reference has to outlive the buffer, which is why the file releaser below captures the handle's raw value rather than a reference to a local object

Return value

void. There is no report of what was replaced, and no way to ask afterwards whether a releaser is present — the buffer exposes no accessor for the field. The only observable feedback is whether the destructor warns.

Examples

Build first, install once the mapping proves real. From Engine/Resource/BufferUtil.cpp, the single call site in the engine: 

Buffer buffer(generator);
if (buffer.GetData() == nullptr)
{
        return buffer;
}

auto handleData = fh.data;
fh.Invalidate();

buffer.SetReleaser([handleData](TSize size, TBufferData data) mutable
{
        if (unlikely(data == nullptr))
        {
                return;
        }

        FileHandle fh;
        fh.data = handleData;

        Assert(size > 0);
        auto ptr = static_cast<void*>(data);

        MapSyncMode syncMode;
        syncMode.SetSync();

        MapSync(ptr, size, syncMode);
        UnmapMemory((void*) data, size);

        OS::Close(std::move(fh));
});

return buffer;

From Engine/Resource/BufferUtil.cpp, in BufferUtil::GenerateFileBuffer

Three things are worth copying from it. The early return leaves a buffer with no releaser, deliberately, because a failed mapping has nothing to release. fh.Invalidate() detaches the raw handle from the local object so the destructor of that object cannot close it twice — the closure owns the value now. And the closure rebuilds a FileHandle from that value at release time, flushing the mapping before unmapping and closing, all through the OS layer documented in OSAL: file.
