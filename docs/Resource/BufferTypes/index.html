BufferTypes

Engine/Resource/BufferTypes.h namespace hbe::BufferTypes 6 aliases, 0 functions the size type and the three callback shapes a Buffer is built from

Class description

A namespace, not a class. It holds the vocabulary that Buffer and the buffer factories in BufferUtil share: how many bytes, what a block of bytes is, who produces one, who frees one, and who proposes a new capacity. Nothing here allocates or computes anything — every entry is a using-declaration, and all six compile to a plain integer or a std::function.

Keeping them in one namespace is what makes a callback interchangeable between subsystems. A releaser written against BufferTypes::TReleaseBuffer is the same type as Buffer::TReleaseBuffer, because Buffer names these very aliases rather than declaring its own, so SetReleaser accepts any callable that fits this signature.

Two of these aliases hide that a buffer's data is a pointer, not a block. TBufferData is uint8_t*, so a generator that "writes out the data" writes out an address, and a releaser that "receives the data" receives the address and the byte count and must already know what kind of memory it points at. Nothing in the type records the allocator, the file handle, or the mapping a block came from; that is precisely why a Buffer needs a releaser at all.

Template parameters

None — a namespace is not a template, and none of these aliases are.

Class properties

Verbatim from Engine/Resource/BufferTypes.h, in the order the header declares them. & in a callback's parameter list is part of the contract, not decoration: it says which arguments the callback may hand back.

NameDeclarationWhat it means
TSize using TSize = size_t; alias A byte count, unsigned. Unlike Array::TIndex, which is int — a buffer's size and a container's index are different quantities and are typed differently here; see Container: Array
TIndex using TIndex = TSize; alias The same size_t under a second name, pinned to it by static_assert(std::is_same<TIndex, TSize>::value); so the two cannot drift apart. No code in the repository uses this name
TBufferData using TBufferData = uint8_t*; alias The block, as an address. Byte-typed, so arithmetic on it is in units of one byte and every typed view of it is a reinterpret_cast — see GetDataAs
TGenerateBuffer using TGenerateBuffer = std::function<void(TSize&, TBufferData&)>; alias Produces a block. It returns void and writes its two arguments by reference, so the out-parameters are the return channel: leaving them untouched is how a generator says it failed. See the Buffer constructors for what an untouched pair leaves behind
TReleaseBuffer using TReleaseBuffer = std::function<void(TSize, TBufferData)>; alias Frees a block. Both arguments are by value, so a releaser cannot hand back a resized or re-pointed block; it is told what to free and must capture whatever it needs to free it correctly — an allocator reference, a file handle, a mapping length
TResizeBuffer using TResizeBuffer = std::function<TSize(TSize)>; alias Proposes a capacity: takes the requested byte count, returns the count to actually use, which is where a grower rounds up to a page or a pool block. Declared only — no field, parameter or call site in the repository names it

Class methods

None. Every entry above is a type alias, so there is no method page under this directory: a name that is not a function has nothing to document beyond its declaration, which is the table above.

Non-member helper functions

None. BufferTypes.h declares nothing but these aliases; the functions that build Buffer objects live in the sibling namespace hbe::BufferUtil in Engine/Resource/BufferUtil.h, and BufferUtil.h itself pulls this namespace in with using namespace BufferTypes; so its own signatures can spell TSize and TBufferData unqualified.
