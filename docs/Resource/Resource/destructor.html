~Resource

member of hbe::Resource Engine/Resource/Resource.h noexcept = default drops the handle; releases nothing

Signature

~Resource() noexcept;

Defined in Engine/Resource/Resource.cpp as Resource::~Resource() noexcept = default;.

Function description

Defaulted, and the class holds no member, so destroying a handle performs no operation: no ResourceManager call, no decrement of ResourceItem::referenceCount, no Buffer release. Contrast Buffer's destructor, which really does free — through the releaser the buffer carries.

This is the second half of the same fact stated on the class page: a handle that stores no reference cannot release one when it dies. Reference-counted retirement would need a pointer or an id here plus a manager to notify, and neither is declared.

Parameters

None.

Return value

void. Destructors have no return value and, being noexcept, report no failure.

Examples

Illustrative — no call site for this exists in the repository, since nothing constructs a Resource. See Coverage. 

{
        const auto handle = engine.GetResourceManager().Load(path);
}       // ~Resource runs here and changes nothing about whatever path named
Letting a handle go out of scope is not a release operation, so do not design around it. Code that expects the bytes to be gone once the last handle dies is relying on behaviour that is documented in the manager's summary and implemented nowhere. Nothing in the engine reads referenceCount, so the count cannot reach zero and no item can be retired.
