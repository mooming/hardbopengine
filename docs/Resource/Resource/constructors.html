Resource

member of hbe::Resource Engine/Resource/Resource.h noexcept = default the only constructor, and the only way to make a handle outside a load

Signature

Resource() noexcept;

Defined in Engine/Resource/Resource.cpp as Resource::Resource() noexcept = default;.

Function description

Value-initialises an empty class. There is no argument to bind it to a path, an id or a Buffer, and no field to leave in an invalid state, so the object it produces is exactly as meaningful — which is to say not at all — as one obtained any other way.

The overload set is one. A loader hands a handle back by value from RequestLoad or Load, and neither of those has a definition, so in the repository as it stands this constructor is the only route to a Resource — and a handle built that way could never be traced to a resource even if the loaders worked.

Parameters

None.

Return value

Constructors have no return type. What you get is a default-constructed Resource — an empty object holding nothing, distinguishable from no other Resource.

Examples

Illustrative — no call site for this exists in the repository. No code constructs a Resource; see Coverage. 

// A handle in a member that has not been pointed at anything yet.
hbe::Resource pending;
Do not treat a default-constructed handle as a "null resource" to compare against. Resource declares no operator==, no IsNull and no bool conversion, so there is no way to ask whether a handle was filled in. Guarding on a handle needs an API that the class does not have yet; today the only honest check is whether the loader was implemented, and it is not.
