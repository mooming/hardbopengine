Resource

Engine/Resource/Resource.h namespace hbe final 0 members the handle a resource loader is meant to hand back — declared as one, implemented as nothing

Class description

The header's own summary calls it a "Handle to a loaded resource managed by ResourceManager", and that is the intent the rest of the module is shaped for: a load returns a Resource, the caller stores it, and dropping it is what eventually retires the bytes.

What exists is a final class with one default constructor and one destructor, both noexcept, both defined = default in Resource.cpp. It declares no data member, no accessor, no conversion, no comparison — an empty class, occupying the single byte that is the smallest any object can.

A Resource refers to nothing, so it cannot be used for anything. With no member to hold an id or a path, every instance is indistinguishable from every other; copying it copies nothing, and the destructor is defaulted, so destroying one does not notify ResourceManager and cannot release a reference count. It is not a lifetime token either — a token has to be observed by somebody, and nothing observes this. A page about an accessor would be documenting API that does not exist, so the absence is recorded here and on the module page instead.
The header still includes what a real handle would need. Resource.h includes <cstddef>, <cstdint> and String/StaticString.h, and no declaration in it uses any of the three — the residue of a handle carrying an id or an interned StaticString path. Treat those includes as the design's open question, not as API: nothing here is a size_t or a StaticString yet.

Template parameters

None — Resource is not a template. There is no resource-type parameter to specialise on either; a load takes a path and the returned handle records nothing about what was loaded.

Class properties

None. No member type, no data member, no static member. The class has no state to inspect and no state to compare, so two handles obtained from two loads of two different paths are the same type holding the same nothing.

Class methods

MethodSignatureWhat a caller depends on
constructors Resource() noexcept Default-constructible with no argument, so a handle can sit in a container or a default-initialised member — but nothing can be asked of it afterwards
destructor ~Resource() noexcept Runs, and releases nothing: it owns no handle, no reference and no allocation

No copy, move, comparison, conversion or accessor is declared, so all of those come from the compiler as trivial members of an empty class — a copy is a no-op, == does not exist, and there is no way to test whether a handle stands for a loaded resource or for nothing at all.

Non-member helper functions

None. Resource.h declares only the class. The two functions in the engine whose declared return type is Resource are ResourceManager::RequestLoad and ResourceManager::Load, and neither has a definition in the repository — see their pages.

Coverage

GapDetail
No accessor exists Path, id, Buffer, loaded-ness: none of them can be read from a handle. Deciding which of those a handle should expose is an engine design decision, not a documentation omission, so it is recorded as a gap rather than answered. The module page has carried this absence since before these pages existed, and it is still true
Nothing constructs one from a load Grepping Engine/ and Applications/ finds no call to RequestLoad or Load, and no definition of either, so no Resource object is created anywhere in the repository. There is consequently no real call site to quote on any page here; the examples are labelled illustrative
Reference-count behaviour The count lives in ResourceItem::referenceCount, not here, and nothing reads or writes it. Documented on ResourceManager
Thread-safety Not stated by the header. With no state there is nothing to race on, but that is not the same as a guarantee about the resource it is meant to name
