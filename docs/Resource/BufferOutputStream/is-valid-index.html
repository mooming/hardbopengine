IsValidIndex

member of hbe::BufferOutputStream Engine/Resource/BufferOutputStream.h private const noexcept never called a private helper this class does not use

Signature

[[nodiscard]] bool IsValidIndex(size_t index) const noexcept
{
	return cursor < buffer.GetSize();
}

Function description

Nothing calls it. A search of the header and BufferOutputStream.cpp finds the declaration and no use, so the function is unreachable and its result is unobservable.

Put does the bounds work directly instead, and does it correctly: it compares the end of the proposed write against the buffer size — if (newIndex > size) — which is the test the helper's signature appears to promise and does not perform. Both Put templates carry that check, in the normal path and in the null-pointer probing path.

It is documented rather than deleted because it is why the two stream helpers no longer look alike: the sibling on BufferInputStream is called three times and was corrected to compare its argument, while this one is never called and still compares cursor. One page each keeps that difference visible instead of letting a reader assume the bodies match.

Parameters

ParameterTypeFate
indexsize_t Not read. The body compares cursor against the buffer size and never mentions the parameter

Return value

TypeWhat you get
bool cursor < buffer.GetSize() — whether the current position is inside the block, which is not a statement about index

Notes

Do not adopt this helper. Any caller that writes if (!IsValidIndex(endOfWrite)) gets "the cursor is somewhere inside the buffer" as an answer to "does this write fit". The correct form is what Put does inline — compare the end of the write against GetSize() — and what the reader's guard now does: BufferInputStream: IsValidIndex
