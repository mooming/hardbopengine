The nine fixed-width and three floating overloads are declared in the header and defined one per statement in BufferOutputStream.cpp, each body a single Put<T> call followed by return *this;.

Function description

Every overload is a thin, chainable wrapper over Put, which holds the alignment and bounds behaviour. Nothing here reports failure; a refused write raises the tally that HasError reads.

Strings are length-prefixed, and the terminator is not written. The const char* overload measures the string with StringUtil::StrLen and hands it to Put<char>(str, length), which writes a size_t length first and then exactly length characters. So the byte count is the string length, the NUL is absent, and the reader that consumes this image must be the one on BufferInputStream, which reads a length and then that many characters. A hand-written reader that expects a C string will not agree with a hand-written writer that appends a terminator.

Three string types funnel through that one overload by c_str(): HInlineString<N>, HString and StaticString. Interned identity is therefore not preserved across a stream — the reader gets a fresh StaticString built from the bytes, and re-interns it.

Arrays carry their element count, not their byte count. The T(&array)[N] template deduces the element type and the length from the argument, so float v[8] writes a prefix of 8 and eight elements. That prefix is what lets Get on the input side size a container, and it is why the two templates — the fixed-array form here and the container form there — are the pair that makes arrays round-trip.

Alignment is per value, and the gap is zero-filled. Each write rounds the cursor up to a multiple of sizeof(T) before storing, and writes zeroes into the skipped bytes. A reader rounding the same way lands on the value; a reader walking byte-by-byte walks into the padding, which is why the two stream classes are meant to be used as a pair rather than independently.

A null string pointer writes nothing and is not an error. The const char* overload returns early on nullptr — not errorCount++, not a zero-length record. A stream of records with a nullable name field therefore produces a shorter image than the writer intended, and since nothing was refused, HasError() stays false and the reader desynchronises against the rest of the record. Pass "" if the field is empty; it writes a zero length, which the reader turns into an empty string.
size_t is a separate overload only off Linux. On Linux size_t and unsigned long are the same type, so the the uint64_t overload already binds it; elsewhere they are distinct and the extra overload is needed for Put<size_t> to be reachable. Code that streams a bare size_t therefore resolves to different overloads per platform — same width on LP64, different binding rule.

Examples

The engine's own writer, from MemoryManager::SaveMultiPoolConfigs: the stream is built on a buffer whose pointer is null so the pass measures the image, and the cursor afterwards becomes the file size. Every << in the chain takes the probing path.

Buffer buffer = BufferUtil::GenerateDummyBuffer();
BufferOutputStream bos(buffer);
bos << MultiPoolConfigCache::Version
   << static_cast<size_t>(numConfigs);
// ... one line per pool configuration ...
returnIfBos.HasError();   // the size probe overflowed the dummy
