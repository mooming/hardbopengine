destructor

member of hbe::BufferOutputStream Engine/Resource/BufferOutputStream.h = default noexcept trivial: a stream finalises nothing

Signature

~BufferOutputStream() = default;

Function description

Generated, and correct to be generated: the members are a reference, two counters and a thread id, none of which need anything at teardown. There is no flush, because there is no staging — Put writes each value into the block as it is called, so the bytes are already in the buffer before the stream ends.

Nothing about the block changes at stream destruction. Whether the bytes survive depends only on what the buffer itself does next, which is the subject of Buffer::~Buffer: the buffer runs its own releaser, and a buffer that was given none logs a warning and leaves the block allocated.

The value the caller usually wants before letting the stream go is GetCursor() — how many bytes the serialisation consumed, which is also the technique MemoryManager uses to size a file before writing one.

Parameters

None.

Return value

None.

Notes

Because the destructor is defaulted and the copy and move operations are deleted, this class is neither copyable nor movable in any form. That is what forces the one-scope discipline described on the constructors.
