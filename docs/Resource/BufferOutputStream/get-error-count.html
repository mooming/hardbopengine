GetErrorCount

member of hbe::BufferOutputStream Engine/Resource/BufferOutputStream.h const noexcept [[nodiscard]] how many writes were refused, not which ones

Signature

[[nodiscard]] auto GetErrorCount() const noexcept { return errorCount; }

Function description

A field read over size_t errorCount;, which only Put ever raises. Two conditions reach it: the value would end past GetSize(), and — in probing mode, where the buffer reports a null block — even the reservation did not fit the size the buffer claims.

It is a tally, not a diagnosis. The counter is shared by every overload of operator<<, so a non-zero count says "something was refused" and nothing more: not which value, not at what offset, not by how much it overflowed. The engine is exception-free, so this counter and the unlikely() branches around it are the entire error channel of serialisation.

A rejected write does not advance the cursor. That means the stream does not resynchronise: once one value has been refused, every later value is written at the offset the refused one would have used, so a caller that ignores the count gets a silently mis-aligned image rather than a hole.

Parameters

None.

Return value

TypeWhat you get
size_t Writes refused since the last ClearErrorCount or since construction. 0 means every write landed. [[nodiscard]], so the usual mistake of calling it and discarding the result is a compile error

Notes

Check it once at the end, not after every value. The counter is cumulative, so the check belongs where the serialisation finishes — the same place GetCursor is read for the byte count. Per-value checks would cost a comparison each and still would not say which value failed.
