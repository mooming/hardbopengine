ClearErrorCount

member of hbe::BufferOutputStream Engine/Resource/BufferOutputStream.h noexcept zeroes the tally and changes nothing else

Signature

void ClearErrorCount() noexcept { errorCount = 0; }

Function description

Assignment, nothing more. The cursor stays where it is, the buffer reference is untouched, and the bytes already written stay written — so clearing the count after a failure leaves a stream that looks healthy and is not: the rejected value was not written, and the values after it sit at offsets the rejected one would have occupied.

Its legitimate use is reusing one stream across several independent images, where each image ends with a check and a reset. Note that the cursor is not reset with it, so that pattern needs a buffer of its own per image or an explicit rewind, which this class does not offer — there is no SetCursor and no Rewind.

Parameters

None.

Return value

None.

Notes

There is no way to move the cursor backwards. GetCursor is the only cursor accessor, and it is read-only. Combined with this function clearing only the counter, a stream cannot be rewound and re-run: writing a length placeholder then back-patching it is not expressible, which is why the engine's serialisation writes lengths before payloads rather than filling them in later.
