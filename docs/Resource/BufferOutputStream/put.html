Put

member of hbe::BufferOutputStream Engine/Resource/BufferOutputStream.h private template noexcept the single write path: alignment, padding, probing, refusal

Signature

template <typename T>
void Put(T value) noexcept;

template <typename T>
void Put(const T* value, size_t length) noexcept;

Both are private templates defined in the class body, and every public operator<< reaches the block through one of them. There is no other write path in this class.

Function description

The scalar form. It asserts the calling thread equals the one captured by the constructor, takes the buffer size afresh on every call, and computes two offsets from sizeof(T): startIndex, the cursor rounded up to a multiple of the element size, and newIndex, one element beyond it. It then either writes or refuses:

const size_t startIndex = ((cursor + tSize - 1) / tSize) * tSize;
const auto newIndex = startIndex + tSize;

auto bufferBase = buffer.GetData();
if (bufferBase == nullptr) {
	if (newIndex <= size) { cursor = newIndex; } else { ++errorCount; }
	return;
}

if (newIndex > size) { ++errorCount; return; }
while (cursor < startIndex) { bufferBase[cursor++] = 0; }

From Engine/Resource/BufferOutputStream.h, with the assert elided

The bytes between the old cursor and startIndex are written as zeroes before the value is stored, so padding is deterministic: two runs of the same write sequence produce byte-identical images, which is what makes a saved file comparable and what stops uninitialised block contents reaching disk. The value itself is stored through reinterpret_cast<T*> at startIndex, and the cursor ends at newIndex.

The array form writes a size_t length prefix by calling the scalar form for size_t, then rounds to the element alignment and stores length elements in a counted loop. Padding is zero-filled the same way, once — between the prefix and the first element. The prefix is an element count, matching what Get expects on the reading side.

Probing mode. When GetData() returns null the function does not write, and the buffer's claimed size is the only bound: if the write would fit, the cursor advances as though it had happened; if not, the error count rises. A caller can therefore serialise once against BufferUtil::GenerateDummyBuffer() — size max, pointer null — and read the needed length from GetCursor(). MemoryManager uses exactly this to size the pool-config file before opening it.

Refusal. Both forms raise errorCount and return without touching the cursor or the block. Nothing is partially written, and nothing is undone: an array form that wrote its length prefix and then found the payload did not fit leaves the prefix in the block.

A length prefix that survives a refused payload is not rolled back. The array form commits Put<size_t>(length) before it tests whether the payload fits. On refusal the count is one higher and the block holds a length with no elements behind it, which a reader will follow off the end. Serialise into a probing buffer first, size the real buffer from that, and the refusal path stops being reachable.
The size is re-read from the buffer on every write, the pointer is re-read too. Neither is cached, so a buffer whose generator has not installed its data yet takes the probing path for those calls and the real path afterwards. This is how the file-mapping factories in BufferUtil can hand out a buffer and fill in the mapping a statement later.

Parameters

valueT (scalar form) Stored as its object representation. static_assert(sizeof(T) > 0) rejects empty and non-object types at compile time

Return value

None. Success and failure are both silent; failure increments the tally read by GetErrorCount.

Notes

Thread identity is asserted, not enforced. Both forms begin with Assert(std::this_thread::get_id() == threadID). Assert is a function in Core/Debug.h whose Release form discards the condition, so in a Release build two threads sharing one stream race on cursor with no detection and no diagnostic. One stream, one thread, is a rule the caller keeps.
