GetCursor

member of hbe::BufferOutputStream Engine/Resource/BufferOutputStream.h const noexcept [[nodiscard]] the write position: bytes written, and next byte to write

Signature

[[nodiscard]] auto GetCursor() const noexcept { return cursor; }

Defined in the class body with a deduced return type over size_t cursor;, so the static type is size_t.

Function description

Two readings, both correct and both used. Forward-looking, it is the offset the next write starts at — Put rounds it up to the alignment of the value being written and may zero-fill the gap before it. Backward-looking, it is how many bytes this stream has consumed, which is the number a caller needs after serialising into a block.

The two readings coincide only when the last write ended flush against the next one. Alignment padding and the zero-fill that follows it sit inside the cursor, so the count includes bytes nobody asked to write, and after a write of a double following a uint8_t the cursor is up to seven bytes ahead of the sum of the payload sizes. That is deliberate — the reader rounds the same way — but it means the cursor is an offset, not a payload total.

Parameters

None.

Return value

TypeWhat you get
size_t Offset in bytes from the start of the block. Can exceed GetSize() when writes were rejected — a failed write leaves the cursor where it was, but probing mode advances it past the end deliberately. [[nodiscard]]

Examples

From Engine/Memory/MemoryManager.cpp, where the cursor after a serialisation into a buffer with no bytes behind it becomes the size of the file to create. The buffer reports size = max and a null pointer, so every write takes the probing path and moves the cursor and nothing else:

Buffer buffer = BufferUtil::GenerateDummyBuffer();
BufferOutputStream bos(buffer);
// ... serialise ...
const size_t bytes = bos.GetCursor();

From Engine/Memory/MemoryManager.cpp, abbreviated

Do not read the cursor as the number of bytes you wrote. It counts alignment padding, and in probing mode it can be larger than the block it points into. Use it as an offset into this buffer, which is what a reader needs, not as a size for an unrelated buffer.
