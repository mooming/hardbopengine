ClearErrorCount

member of hbe::BufferInputStream Engine/Resource/BufferInputStream.h noexcept zeroes the tally, leaves the cursor and the refusals in place

Signature

void ClearErrorCount() noexcept { errorCount = 0; }

Function description

Assignment, and nothing else. The cursor stays where it is, so the fields that were refused keep their substituted defaults and the stream stays at the same offset — clearing the counter does not make an image valid again.

Its use is reading several images through one reader-shaped object, or ignoring a known-absent optional field: a caller that expects a trailing field to be missing can take the default, ClearErrorCount(), and continue with a clean flag. That is a deliberate use of the substitution behaviour, not a workaround, but it depends on knowing exactly which read was expected to fail.

Parameters

None.

Return value

None.

Notes

There is no way to seek. The cursor has one read accessor and no setter, so a reader cannot go back to re-read a field, and a stream that has run off the end cannot be restarted — construct a new reader instead, which costs nothing and starts at offset zero.
