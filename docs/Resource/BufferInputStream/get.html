Get

member of hbe::BufferInputStream Engine/Resource/BufferInputStream.h private template noexcept 3 overloads the single read path, and where refusals are born

Signature

using TVector = hbe::HVector<T>   // member template alias

template <typename T>
void Get(T& value, const T& defaultValue) noexcept;
template <typename T>
void Get(T* arrayBuffer, size_t size) noexcept;
template <typename T, class TContainer = TVector<T>>
void Get(TContainer& array) noexcept;

All three are private, defined in the class body, and the whole public surface — every operator>> — goes through one of them.

Function description

Scalar form Get<T>(value, defaultValue). It rounds the cursor up to a multiple of sizeof(T), asks IsValidIndex whether the read may proceed, and on refusal raises the error count, assigns defaultValue into the caller's object, and returns without moving the cursor. On success it reads through reinterpret_cast<const T*> at the rounded offset and leaves the cursor one element past the value. The mirror of Put, in the offset arithmetic and in the silent-failure shape.

Fixed-array form Get<T>(arrayBuffer, size). It first reads a size_t length prefix through the scalar form, then requires that prefix to equal the caller's size. A mismatch raises the count and returns — after the prefix has already been consumed, so the cursor is past it. On a match, the elements are copied with std::copy over length elements starting at the aligned offset.

Container form Get<T, TContainer>(array), the default TContainer being the member alias TVector<T> = HVector<T>. A static_assert ties T to TContainer::value_type, so asking for the wrong element type is a compile error rather than a reinterpretation. Order matters and is worth reading carefully:

array.clear();

size_t length = 0;
const size_t errorCountBefore = errorCount;

size_t length = 0;
Get<size_t>(length, 0);
if (unlikely(errorCount != errorCountBefore))
	return;

if (length == 0)
	{
		array.clear();
		return;
	}

// ... compute startIndex / newIndex, consult IsValidIndex ...

array.clear();
array.reserve(length);
std::copy(dataBegin, dataEnd, std::back_inserter(array));

From Engine/Resource/BufferInputStream.h, abbreviated

The container is cleared only once the read is known to be honoured: the length prefix is read first, a refusal returns immediately with the container untouched, an explicit zero length clears it, and a bound that does not fit clears nothing. Elements then arrive through back_inserter, so the container's own size is never trusted — only its capacity is pre-booked.

A refused read leaves the container alone. This order was not the original one: array.clear() used to run before the length prefix was read, so a refusal emptied the caller's container. Both behaviours are pinned by testlets now — "Refused Read Keeps The Container" asserts that a prefix which cannot be read leaves the contents, and that a zero-length prefix inside the buffer clears them.
The allocation a container read asks for is sized by the image, but it is now bounded. reserve(length) is reached only after IsValidIndex has accepted startIndex + sizeof(T) * length against GetSize(), so length cannot exceed the remaining bytes divided by the element size. That bound is what the guard's previous comparison failed to impose.
The empty-image case is honoured, not refused. A zero length prefix that fits inside the buffer means the image holds an empty array, so the container is cleared and no error is raised. The branch used to read length <= 0 on an unsigned type — a comparison that can only ever mean == 0 — and it is now written as what it does.

The array and container forms are the exact counterpart of the writer's array overload, which writes an element count and then the elements. A fixed array on one side pairs with T(&array)[N] on the other; a container pairs with the same bytes read into an HVector<T>.

Parameters

Return value

None. Every form communicates through the cursor and the tally read by GetErrorCount, and the scalar form additionally through the default value it assigns.

Examples

The container form has no call site in the engine, and cannot be reached by the operator. Its declaration is template <typename T, class TContainer = TVector<T>> This& operator>>(TContainer& container), and T appears only in the default argument — it is not deducible from the parameter, so stream >> someVector; does not bind. The reachable form is the qualified call with the element type named:

HVector<int> values;
bis.operator>><int>(values);        // T named explicitly; TContainer defaults to HVector<int>

The form used by BufferInputStreamTest, which is the only code in the tree that instantiates this template

The fixed-array form has no such problem — T and N both deduce from T(&array)[N] — so stream >> values; works for a C array, and that is the bulk path real code takes. Where an engine loader needs a sequence it reads a count and then loops over scalars: MultiPoolConfigCache::Deserialize in Engine/Memory/MultiPoolConfigCache.cpp does bis >> size; and then reads each field per element, never through a container.

Because nothing instantiated this template, its body was never compiled. An uninstantiated template member is not checked, so the container form could carry a compile error that no build would report. The new testlets instantiate it, which is also how the container-clearing order above became verifiable at all.
