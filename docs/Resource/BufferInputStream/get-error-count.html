GetErrorCount

member of hbe::BufferInputStream Engine/Resource/BufferInputStream.h const noexcept [[nodiscard]] how many reads were refused, each one substituted with a default

Signature

[[nodiscard]] auto GetErrorCount() const noexcept { return errorCount; }

Function description

A field read over size_t errorCount;, raised only inside the private Get templates. The condition is the same in all three: the read was refused because the bounds test failed.

What distinguishes a read failure from a write failure is what lands in the caller anyway. The scalar form assigns the caller-supplied default — 0 for integers, '\0' for characters, 0.0 for floats — so a short image deserialises into a plausible-looking object of zeroes rather than into nothing. That is why this counter and HasError are not optional at the end of a load: the values are always written, and only the count says whether they were read.

On a refusal the cursor does not advance, so subsequent reads ask for the same offsets again and every later field also comes back as a default. The image is not re-synchronised and no offset recovery is offered.

Parameters

None.

Return value

TypeWhat you get
size_t Reads refused since construction or the last ClearErrorCount. [[nodiscard]]

Examples

The engine's own reader-side checks come from the unit tests for this class in Engine/Resource/BufferInputStream.h, where the case named "Empty Buffer" is precisely a test that reading from nothing raises the count instead of crashing.

BufferInputStream is(buffer);
int32_t v = 0;
is >> v;            // refused: v is 0 anyway
returnIfB(is.HasError());   // the only signal that it was not read
