BufferInputStream

Engine/Resource/BufferInputStream.h namespace hbe final copyable no thread affinity a cursor, an error tally, and the only read path out of a borrowed Buffer

Class description

Three members and no ownership: a const Buffer&, a byte cursor starting at zero, and an error count. Deserialising is pushing the image through operator>>; each read either fills its argument from the block or fills it with a type-appropriate default and raises the count. Values are never left uninitialised, which is precisely why HasError carries the whole burden of trust at the end of a chain.

It is the mirror of BufferOutputStream, and the two differences are deliberate. The reader holds const Buffer&, so it cannot mutate the image; it captures no thread id, because reading a block nobody else is writing needs no owner — the writer asserts one because it races on its own cursor; and the reader does not delete its copy operations, so a copy is an independent reader parked at the same offset, which is how one image is walked twice.

A refused read does not move the cursor, so a reader that runs off the end keeps failing at the same offset and every remaining field comes back as a default. There is no seek, no rewind and no peek: to restart, construct another reader, which costs a reference and two integers.

What the reader assumes

The reader assumes the three rules the writer follows, and nothing verifies them at runtime. If the image was produced by BufferOutputStream they hold by construction; for any other producer they are an agreement made elsewhere:

AssumptionWhat the reader does with itWhat happens if it is false
Every value sits at an offset rounded up to sizeof(T), with the gap zero-filled Each Get rounds the cursor up before reading, mirroring Put Packed images (a file written byte-packed by another tool, or a hand-rolled writer) deserialise as garbage from the first value that needed padding. Nothing detects it: the bytes read are valid bytes of T
Strings and arrays carry a size_t prefix; strings carry no terminator; the array prefix counts elements, not bytes The bulk Get forms read the prefix first and consume that many elements A terminator in the image becomes a stray element; a byte count where an element count was expected makes the read run far past the intended end, since the only guard is IsValidIndex
The image is complete and its lengths are honest Nothing in this class validates a length against the remaining size before using it A corrupt length reaches reserve() and std::copy — see the two gaps on the Get page
No magic, no version, no endianness marker is checked, because none is written. A format that needs a version prefix writes one itself, the way MultiPoolConfigCache::Deserialize in Engine/Memory/ reads the Version its writer stored first and compares it before trusting anything after. That check belongs to the caller, immediately after opening the reader.

Template parameters

None on the class. The class declares one member template alias, template <typename T> using TVector = hbe::HVector<T>;, which is what the container overloads default to: template <typename T, class TContainer = TVector<T>> on both operator>> and Get. A caller can therefore read into a container other than HVector by naming it explicitly, as long as its value_type matches the element type — that is a static_assert, not a convention.

Non-member helper functions

None in BufferInputStream.h, beyond the test collection under __UNIT_TEST__ noted below. The buffers it reads are produced by hbe::BufferUtil — GetFileBuffer and GetReadOnlyFileBuffer are the two that hand back a mapped file a reader consumes, and GetMemoryBuffer<T> the one that hands back an allocator-owned block.
