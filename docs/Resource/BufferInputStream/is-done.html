IsDone

member of hbe::BufferInputStream Engine/Resource/BufferInputStream.h const noexcept [[nodiscard]] the cursor has reached the end of the block

Signature

[[nodiscard]] bool IsDone() const noexcept { return cursor >= buffer.GetSize(); }

Function description

Asks whether the read position is at or past the end of the block. It is the loop condition for"read until the image is exhausted" — the shape used when the record count is not stored in the image.

Two limits follow from the comparison itself. It says nothing about whether the next value would fit: at a cursor one byte from the end of a buffer, IsDone() is false and a double read is still refused, because the bounds decision is made separately by IsValidIndex. And alignment means the cursor can pass the end legitimately: a value rounded up past the last byte leaves the cursor beyond GetSize() without any error having been raised.

For a zero-size or null-pointer buffer it reports true immediately, which is the cheap way to test "is there any image here at all" — although GetData() == nullptr is the honest test for whether there are bytes to touch.

Parameters

None.

Return value

TypeWhat you get
bool cursor >= GetSize(). Does not consult errorCount, so a reader can be done and error-free, or not-done and already failing. [[nodiscard]]
