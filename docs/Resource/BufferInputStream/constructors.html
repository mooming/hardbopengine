Function description

Stores the reference and starts at the beginning: buffer(buffer), cursor(0), errorCount(0). Nothing is read, so a reader that is opened and never used has observed nothing about the block.

Unlike BufferOutputStream, this class does not capture a thread id and does not delete its copy operations. Reading does not mutate the block, so a copy is coherent: it duplicates the buffer reference and the current cursor, giving an independent reader positioned at the same offset. Two copies then advance separately, which is the natural way to re-read a header or to walk one image twice. The explicit on the constructor is what stops BufferInputStream in = buffer; from silently opening a reader.

The buffer is borrowed, not owned: the stream keeps no reference count and no weak handle, so the caller must keep the buffer alive — see the note below, and Buffer::~Buffer for when the block actually goes away.

No thread pinning here, which is a difference from the writer rather than an oversight. Put asserts thread identity because it mutates a cursor that another thread could be mutating. Every member of this class mutates only its own cursor and errorCount, so two readers on one buffer — including two copies of the same reader — race on nothing. A reader shared by reference across threads does race on its own cursor, exactly as any two callers of a stateful object would.
A buffer that stops holding its bytes mid-read is not detected. The member is const Buffer& buffer;, and each read re-asks GetData() for the address and GetSize() for the size. If the buffer is released between two reads, the next read gets a new or null address with no indication that anything changed; a null address turns into a read from &bufferBase[cursor] with a null base, which the bounds test does not catch — see IsValidIndex.
