RequestTasks

member of hbe::ResourceManager Engine/Resource/ResourceManager.h private noexcept not called an empty placeholder for task-based loading, with no caller

Signature

void RequestTasks(TaskSystem& taskSys) noexcept;   // private

Declared in Engine/Resource/ResourceManager.h; the definition in ResourceManager.cpp is an empty body.

Function description

It does nothing. The definition is two braces, and the only two engine classes it would need are forward declared at the top of the header and never reached from here:

void ResourceManager::RequestTasks(TaskSystem& taskSys) noexcept
{
}

From Engine/Resource/ResourceManager.cpp

It is not called. PostUpdate drains completed loads and RequestLoad records a request, and neither mentions this function, so the queue of requests grows and is never dispatched. That is the current shape of asynchronous loading in this module: the request list and a slot to service it exist, and the servicing step does not.

What the signature promises is the intent: it takes a TaskSystem&, which is what a caller would need to hand each pending LoadingRequest to a worker. The private types it would walk are ResourceItem and LoadingRequest, both declared just above the data members on the class page.

Parameters

ParameterTypeIntended use
taskSysTaskSystem& Unused. Named for the TaskSystem that would run the loads this function would submit

Return value

None.

Notes

Nothing loads through this path. A request recorded by RequestLoad stays recorded: the function that would turn requests into tasks is empty and uncalled. Documenting it as if it dispatched would describe a mechanism the engine does not have, so the entry point for that behaviour is this page until it is implemented.
