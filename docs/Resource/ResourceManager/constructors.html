ResourceManager

member of hbe::ResourceManager Engine/Resource/ResourceManager.h noexcept = default one default constructor, taking nothing — there is still nothing for an argument to configure

Signature

ResourceManager() noexcept;

Defined in Engine/Resource/ResourceManager.cpp as ResourceManager::ResourceManager() noexcept = default;.

Function description

Default-constructs the two members, which for TVector means two empty vectors and no allocation. The nested item types are never touched: an item is created by a load, and the loads are declared only.

No overload takes a path table, an allocator or a TaskSystem. That is not an oversight at this size — the manager would have no use for any of them until something implemented loading — but it does mean a caller cannot today decide which allocator scope a resource table should live in, or which task system an asynchronous load would be posted to. Whoever implements the loaders has to answer both, either by adding a constructor here or by reaching through the Engine reference the class already accepts in PostUpdate.

Parameters

None.

Return value

Constructors have no return value. The object produced holds zero items and zero pending requests.

Examples

There is exactly one construction of a ResourceManager in the engine, and it is implicit: the manager is a by-value member of Engine, so it comes into being with the engine and needs no call of its own. From Engine/Engine/Engine.h: 

MemoryManager memoryManager;
SystemStatistics statistics;
Logger logger;
TaskSystem taskSystem;
ResourceManager resourceManager;
std::unique_ptr<OS::Application> application;

From Engine/Engine/Engine.h

Being a plain member rather than a pointer or a smart handle, it exists for the whole life of the process and is destroyed with the engine; Engine::GetResourceManager() hands out the same object to anyone who asks, and nothing copies or moves this class — it declares no copy or move operation, and an engine subsystem shared by reference is not meant to be moved anyway.

Construction is not start-up. EInitLevel has no resource level, Engine::Initialize never mentions the manager, and SetResourceManagerReady() is never called — so IsResourceManagerReady() reports false even though the object is alive and reachable. Treat the ready flag as unwired rather than as a signal that construction failed.
