~ResourceManager

member of hbe::ResourceManager Engine/Resource/ResourceManager.h noexcept = default drops the item table, and with it every buffer the manager was holding

Signature

~ResourceManager() noexcept;

Defined in Engine/Resource/ResourceManager.cpp as ResourceManager::~ResourceManager() noexcept = default;.

Function description

Defaulted, which for this class is not a noop: the members own real things. Members are destroyed in reverse declaration order, so loadingRequests goes first — a vector of raw pointers, and dropping it releases the pointer values only, never the items — and then resources goes, destroying each ResourceItem in turn. Each item's path is an interned StaticString needing no teardown, and each item's Buffer runs its releaser, so an item holding a file mapping gets that mapping synchronised, unmapped and its handle closed here.

The byte counts and the count field are plain integers, so nothing is reported at destruction about how much was released or how many items were still resident. The vector's own storage returns through DefaultAllocator, meaning the allocator scope that frees it is the one open when the manager dies — for the engine's member instance, during Engine teardown.

Parameters

None.

Return value

void, and noexcept: nothing about the release is reported to the engine tearing it down.

Examples

Illustrative — no code calls or declares a ResourceManager of its own; the engine's member instance is destroyed as part of Engine teardown, which is quoted on the constructors page. 

{
        hbe::ResourceManager resourceManager;
        // ... items would have been added by Load / RequestLoad ...
}       // ~ResourceManager: loadingRequests dropped, then each ResourceItem, then each Buffer's releaser
Destroying the manager does not consult referenceCount, and does not care whether a handle is still in use. The count is never incremented by anything, so there is no "still referenced" state to respect: whatever the table holds is released the moment the manager goes. Combined with Resource holding nothing at all, a handle that outlives its manager is not detected, not invalidated and not diagnosable — it simply never referred to anything in the first place. A buffer with no releaser in the table at this moment takes the warning path described on Buffer's destructor and leaks quietly at shutdown.
