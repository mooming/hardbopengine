Module Index / Math

Math

namespace hbe Engine/Math 18 headers, 17 sources — vectors, matrices, quaternions, transforms, bounding volumes, sampling

Module description

Value types, all templated on the scalar type, so the same geometry exists in float and double without a second implementation. Three transform types rather than one, because they answer different questions: UniformTransform for uniform scale, RigidTransform for rotation and translation only, and Transform when a hierarchy and a cached world matrix are needed. Bounding volumes come in both aligned (AABB) and oriented (OBB) forms, and the sampling headers carry stratified sampling and Monte Carlo integration.

Handedness is not a per-object choice: CoordinateOrientation decides it for the whole build from RIGHT_HANDED_COORDINATE, and every rotation trig call in the module goes through it.

Module variables

Nothing at module scope. The numeric constants the module leans on — Pi, HalfPi, TwoPi, Epsilon, SqrEpsilon — are in Core § Module variables, and the named values on a type (Vector3::Zero, Matrix4x4::Identity) are class-static, listed with each class page. Keeping the constants in one header is what stops two files disagreeing about what π is to eight digits.

Vector2, Vector3, Vector4 (Engine/Math/Vector2.h, Vector3.h, Vector4.h)

Each vector class has its own page — properties, named constants, every method, and the shared VectorCommonImpl.inl surface they all carry: Vector2, Vector3, Vector4. The three differ in their constructors, their named constants, and what their arity adds — cross product and angles on Vector3, the homogeneous fourth component on Vector4.

Matrix2x2, Matrix3x3, Matrix4x4 (Engine/Math/Matrix2x2.h, Matrix3x3.h, Matrix4x4.h)

Each matrix class has its own page, sharing the MatrixCommonImpl.inl surface: Matrix2x2, Matrix3x3, Matrix4x4. The pages carry the row-major storage convention, the defects the current code carries (Matrix3x3::Inverse's double scaling, SetEulerZ/SetRotationZ's m33 write), and the per-class rotation members with their unit conventions.

Quaternion (Engine/Math/Quaternion.h)

Quaternion — unit-quaternion rotation: factories from Euler axes and axis-angle, conversion to and from matrices, composition, inverse and conjugate, and both linear and spherical interpolation. The page carries the class's standing unit-length assumption and its degree and radian conventions.

UniformTransform (Engine/Math/UniformTransform.h)

UniformTransform — rotation, one uniform scale, translation: the shape most game objects have, and the type Transform caches its world transform as. The page carries the members that cannot be used as declared.

RigidTransform (Engine/Math/RigidTransform.h)

RigidTransform — rotation and translation with no scale, padded for fixed-size placement: the type for cameras and physics bodies.

Transform (Engine/Math/Transform.h)

Transform — a scene-graph node: local rotation, scale and translation, plus children and a cached world transform. The page carries what invalidates the cache and what does not.

AABB (Engine/Math/AABB.h)

AABB — axis-aligned bounding box stored as two corners, empty until the first Add; the standard broad-phase volume.

OBB (Engine/Math/OBB.h)

OBB — oriented bounding box: centre, half-extents and a rotation quaternion. The page carries the stubbed intersection test and the Closest center-displacement.

Sampling and integration

Three class templates, used by the rendering tests' integration work: each takes the function, the density and the sampler objects as template parameters, so a caller's callables cost nothing at the call. StratifiedSampling splits an interval into strata and hands out one at a time; ImportanceResampling weights and stores samples, then integrates by picking and perturbing them; MonteCarloIntegrator is the plain importance-sampled estimator, usable as a callable.
