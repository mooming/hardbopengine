Module Index / Math

Math

namespace hbe Engine/Math 18 headers, 17 sources — vectors, matrices, quaternions, transforms, bounding volumes, sampling

Module description

Value types, all templated on the scalar type, so the same geometry exists in float and double without a second implementation. Three transform types rather than one, because they answer different questions: UniformTransform for uniform scale, RigidTransform for rotation and translation only, and Transform when a hierarchy and a cached world matrix are needed. Bounding volumes come in both aligned (AABB) and oriented (OBB) forms, and the sampling headers carry stratified sampling and Monte Carlo integration.

Handedness is not a per-object choice: CoordinateOrientation decides it for the whole build from RIGHT_HANDED_COORDINATE, and every rotation trig call in the module goes through it.

Module variables

Nothing at module scope. The numeric constants the module leans on — Pi, HalfPi, TwoPi, Epsilon, SqrEpsilon — are in Core § Module variables, and the named values on a type (Vector3::Zero, Matrix4x4::Identity) are class-static, listed with each class below. Keeping the constants in one header is what stops two files disagreeing about what π is to eight digits.

Prefer SqrLength() when you are comparing magnitudes: Length() takes a square root that a comparison does not need. Normalize() is not const — it rewrites the vector it is called on.

Lerp is cheaper and stops being a rotation at the poles; Slerp keeps constant angular speed and costs a trig call. Multiplying a quaternion by a vector rotates that vector — the result is a TVec3, not a quaternion, which is why the operator is declared with the vector on the right.

Transform (Engine/Math/Transform.h)

Class description

A scene-graph node's transform: local rotation, scale and translation, plus children. Reading the world transform is where the design shows — the non-const form returns a cached value and rebuilds only when something invalidated it, while the const form computes without caching, because a const reader must not be able to mutate a cache from a shared reference.

Template parameters

TNumber — scalar type. Aliases: TFTransform for float, TDTransform for double.

Class properties

rotation, scale, translation, plus the child list and the cached world transform — all reached through the methods below.

Class methods

void Attach(Transform& transform) noexcept;
void Detach(Transform& transform) noexcept;
void DetachAll() noexcept;
void Invalidate() noexcept;      // drop the cached world transform

[[nodiscard]] const TUniformTRS& GetWorldTransform() noexcept;        // cached
[[nodiscard]] TUniformTRS GetWorldTransform() const noexcept;          // computed, not cached
[[nodiscard]] const TUniformTRS& GetLocalTransform() const noexcept;
Move a node and the cache is stale. Writing local rotation, scale or translation does not know it was written: call Invalidate() after mutating a node that others read, or their world transforms keep the old value. This is the single most common way this type is used wrong, and the const overload exists precisely so a read-only path cannot make the same mistake in the other direction.

None.

Sampling and integration

Three class templates, used by the renderer's shading work. They are grouped in one section because their contract is shared: they take the sampler, the function and the probability density as template parameters, so a caller's lambdas cost nothing at the call.

Class descriptions

TypeHeaderWhat it does
StratifiedSampling<TReal = double, TInteger = uint32_t>StratifiedSampling.hDraws one sample per stratum from a range sampler; ChangeSubGroup(delta) moves to the next subgroup
ImportanceResampling<TInput, TOutput, TReal, TInteger>ImportanceResampling.hResample redraws samples against a density; Integrate accumulates an integral over iterations from a discrete and a uniform sampler
MonteCarloIntegrator<TInput, TOutput, TReal, TInteger>MonteCarloIntegrator.hUsable as a callable: operator()(result, f, p, sample, numIterations), returning whether the estimate completed

Template parameters, properties, methods

The parameter lists above are the whole story on the types; the exact method signatures take the function, density and sampler objects as arguments and write their result through an out-parameter, following docs/CodingStandards.md's out prefix rule. The headers carry them, and this page does not invent overloads.
