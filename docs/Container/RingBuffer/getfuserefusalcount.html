GetFuseRefusalCount

member of hbe::RingBuffer Engine/Container/RingBuffer.h report how often the block fuse refused growth

Signature

[[nodiscard]] size_t GetFuseRefusalCount() const noexcept

Function description

The constructor's inMaxBlocks is a fuse: a producer that needs a new block when the queue already holds that many is refused rather than allowed to grow without bound. Every such refusal counts one here, so this counter separates two things a caller cannot otherwise tell apart — a queue that was refusing work and a queue that was merely slow to accept it. Push reports the same event as EPushResult::Full, which is the answer a caller acts on; this is the tally a caller reads afterwards.

Counters are relaxed atomics written under the management mutex, so reading one never synchronises with anything and a reader can see a value that is briefly stale. Read it together with GetDeferredBlockCount: refusals while blocks sit deferred says the retirement handover, not the workload, is what is holding the chain at its cap.

Parameters

NameWhat the caller must supply
noneThis method takes no argument.

Return value

The count as of this call. It never decreases; it counts refusals, not refused elements, so one producer retrying a full fuse forty times counts forty.

Examples

Illustrative — the real call sites are the diagnostic testlets in Engine/Container/RingBuffer.cpp, which print every counter of a queue when a round fails to finish.

if (queue.GetFuseRefusalCount() != 0 && queue.GetDeferredBlockCount() != 0)
{
        log("chain is at its cap with retired blocks still parked");
}
