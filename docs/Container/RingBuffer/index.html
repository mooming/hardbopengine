RingBuffer

Engine/Container/RingBuffer.h namespace hbe final Lock-free multi-producer single-consumer FIFO over a chain of lock-free fixed-size rings, owning its elements and recycling its blocks

Class description

A first-in first-out queue for the shape the engine was asking for: many threads enqueue, exactly one thread dequeues, elements are values rather than caller-owned nodes, and the number of elements in flight is in the millions rather than the dozens. It is a chain of fixed-size blocks. Each block is one pluggable fixed-size ring — the template parameter U — so the rules that decide whether a slot is ready, free or taken are the ring's own, not a second protocol written beside it. The block adds exactly one thing of its own: an atomic claim counter that caps the block at one lap of that ring. Producers never wait for each other and never allocate on the hot path; the consumer walks the ring's slots in order.

That structure buys the two properties a linked-list MPSC cannot give at this scale. Memory is one allocation per U::GetCapacity() elements instead of one per element, and no element is ever lost because a producer stalled — a slot that is claimed but not yet published is seen as such and reported as EPopResult::Blocked, so the consumer can go and do something else instead of spinning, and cannot skip past it either.

Two of the operations are deliberately single-threaded. The consumer's position in the chain is a plain pointer, and its position inside the current block belongs to the ring, so Pop and IsEmpty belong to one thread; making them safe for several would mean either a lock on the hot path or a second generation of indices. Pushing from many threads is the whole point; draining from many is a different container.

Block memory comes from MemoryManager (Engine/Memory/MemoryManager.h) against the allocator that was current when the queue was constructed, so a queue charged to a subsystem shows up under that subsystem in the ledger. Recycling is enabled: a block the consumer has left is freed once no producer is standing inside it, and the memory comes back into the same pool. Growth is capped by the constructor's fuse, so a queue with no consumer refuses work rather than eating the heap.

Algorithm, invariants, the memory-ordering table and the cost model are in the design document: RingBuffer design.

Template parameters

ParameterKindWhat it must satisfy
T type A value type the queue can own. It must be copy-constructible from const T& (that copy is what Push performs inside the slot the block's ring reserves), move-assignable (that is how Pop hands the element over) and destructible (the queue destroys the slot's object after handing it over, and again for anything still queued at teardown). It must not be an lvalue-reference type and its destructor must not throw. There is no compile-time check for the first three: they are diagnosed where the template is instantiated, inside Push, Pop and DestroyAll.
U type, constrained by CFixedRing<T, U> The fixed-size ring each block is built from. One concept states the whole contract, and it is stated as a concept rather than a static_assert in the class body so that a wrong U is refused at the point of use with constraints not satisfied instead of a failure somewhere inside a member function. It requires, in order:
  • typename U::ValueType names T exactly — the block must hold what the queue hands it, not something convertible to it;
  • std::default_initializable<U> — the chain placement-constructs a block with no arguments, because it does not know the element count in advance;
  • !std::copy_constructible<U> — copying a ring that owns slots would hand the same slot to two owners, so a backend that permits the copy is refused here rather than debugged later;
  • U::GetCapacity() returning std::size_t, and that capacity being a power of two greater than one — the chain's arithmetic assumes a mask, and a capacity of one makes “one lap” meaningless;
  • Push(const T&) and Push(T&&) returning EPushResult, and Pop(T&) returning EPopResult — the shared types themselves, not per-class enums reached through typename U::: one type for the backend's answer and the chain's answer means the forwarding cannot drift, and no separate clause has to check that the enumerators exist. A backend must still be able to answer with Pushed, Full, Element and Empty, and both spellings of an element are demanded, since a block that cannot take an rvalue would quietly turn every Push(value) into a copy;
  • IsEmpty() and GetSlotVersion() — Pop cannot tell “nothing yet” from “nothing ever again” without them, and the difference is what EPopResult::Blocked and block retirement both rest on.
Four engine containers satisfy it today: AtomicFixedRingMPSC, AtomicFixedRingMPMC, FixedRingMPSC and FixedRingMPMC; the static_assert group in the TEST_ENABLED region of Engine/Container/RingBuffer.h fails the build if one ever stops satisfying it. A U of a different capacity is not a different tuning of the same queue: the capacity is how many elements a block can hold before the chain links the next one, so it is also the amortisation unit for growth, retirement and hazard scans — which is why the testlets in Engine/Container/RingBuffer.cpp choose capacities of 2, 4 and 8, small enough to hit those rare paths on purpose.
TAllocator type, default DefaultAllocator<T> An allocator for the queue's own storage, named as a template parameter for the same reason the other containers name one: the queue's memory should be chargeable to a caller-chosen allocator without the queue knowing which one. It must satisfy the standard allocator requirements and be rebindable, because the queue allocates no T objects with it - the blocks and the producer slot array are raw bytes reached through TAllocator::rebind<std::uint8_t>, and the deferred list is a std::vector over rebind<Block*>. The member is default-constructed, so the allocator decides its own target: DefaultAllocator captures the constructing thread's allocator id, which is why a queue built inside an AllocatorScope charges everything to that scope's node of the allocator tree. Because the chain allocates on producer threads and frees on the consumer, an injected allocator must tolerate concurrent use — the pool-allocator contract says what the default does and does not tolerate. It is never copied into a block, and nothing on the consumer path reads it.

Coverage

This page documents every entry the header declares, with one omission recorded rather than glossed: the concept CFixedRing<T, U> has no page of its own — it constrains this one class and means nothing away from it, so its whole contract lives in the U row of the template-parameter table above, exactly as CLockable is documented on the page of the class it constrains in docs/Core/ScopedLock/index.html; and the three aliases (StorageAllocator, DeferredAllocator and DeferredList) have no pages of their own - they name no runtime behaviour, and what they guarantee is stated in the TAllocator row of the template-parameter table above. What follows are the claims the reference could not establish by testing, recorded rather than glossed.

Not establishedWhy, and what was done instead
That the block declaration is necessary, as opposed to merely argued for. No testlet can schedule the interleaving it guards — the window is two instructions wide and holds no user code — and deleting the declaration changed nothing: every testlet still passed, so the guard has no control demonstrating its necessity in this form. ThreadSanitizer did catch the earlier version of this protocol, which is why the protocol is as it is, and that history together with the ordering argument is recorded in the design document. Read that argument sceptically: it is the whole case.
That a producer slot is ever given back. It is not. A thread that pushes and then exits keeps its slot for the life of the queue, so the bound is on the number of threads that ever push, not on the number pushing at once. Nothing in the engine cycles unbounded thread identities through one queue; a caller that does must size inMaxProducers for it.
A measured throughput or a false-sharing figure. Adjacent slots share tag cache lines, which is a deliberate trade for memory density. The trade has now been measured: adding one publication gate per slot to a bare claim-and-write ring is the largest single term in the cost of a push (4.3 ns to 24.1 ns per element at one producer), while moving the block's claim word off the first tag line and line-aligning the tag array changed end-to-end throughput by less than the run-to-run noise. The numbers and the method are in the design document. The design document records it as an open measurement rather than a number.
A call site. Nothing in the engine uses this container yet, so every example on these pages is labelled illustrative.
