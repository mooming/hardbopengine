Push

member of hbe::RingBuffer Engine/Container/RingBuffer.h copy a value onto the tail block from any thread, with two reservations and no lock on the hot path

Signature

[[nodiscard]] EPushResult Push(const T& inItem) noexcept

Function description

Enqueues a copy of inItem. Any thread may call it and any number of them at once; the only thread that must not is the one consumer, and only because it has Pop instead.

The hot path reserves twice and locks nothing. One atomic compare-and-swap on the tail block's claim counter reserves a place in that block — the same counter is what caps a block at one lap of its ring — and the block's ring backend then makes its own slot reservation, constructs the copy and publishes it. Nothing is locked, nothing is allocated, and no other producer's progress is required. The chain never touches a payload or a publication index itself; the backend owns both, which is what makes the backend pluggable. The design document prices that second reservation.

Before the block is touched it is declared: the thread stores the block's address into its own producer slot, then reads tail once more and restarts if it has moved. Those two sequential-consistency reads around one store are what make it safe for the consumer to recycle blocks at all — a block cannot be freed while a slot declares it, and a producer cannot be left holding a block that was freed before it declared one. The declaration is cleared as soon as the block's ring has taken the element, before this call returns.

A block is one ring of U, so it holds BlockCapacity elements, where BlockCapacity is U::GetCapacity(), and it is handed over after one lap: a claim of BlockCapacity sends the producer to the successor or to a new block, and a block is never filled a second time. Extending the chain takes the management mutex, so the locking cost is at most one acquisition per BlockCapacity elements, and only on the thread that happens to arrive at a full tail. The queue can refuse: see the return values.

Parameters

NameWhat the caller must supply
const T& inItem The value to store. The block's ring backend constructs it in the ring's own storage and then publishes it, so a copy constructor that blocks delays the publication of this one element and nothing else.

Return value

ValueWhen it comes back
EPushResult::PushedThe copy is in the block's ring and visible to the consumer.
EPushResult::FullThe chain already holds maxBlocks live blocks, so growing would exceed the fuse. Nothing was written. Retry later, after the consumer has drained and recycled a block. This answer also covers the one case the design forbids rather than handles — the ring answering Full to a reservation the chain had already won, which means one lap is not being enforced; it asserts in a non-release build and is reported as Full rather than silently retried.
EPushResult::TooManyProducersEvery producer slot is claimed, so this thread cannot be tracked and was refused rather than left untracked. Raise inMaxProducers at construction.

Examples

Illustrative — no call site for this exists in the repository.

for (Task* task = dequeueWork(); task != nullptr; task = task->next)
{
        if (queue.Push(*task) != TaskQueue::EPushResult::Pushed)
        {
                break;
        }
}
