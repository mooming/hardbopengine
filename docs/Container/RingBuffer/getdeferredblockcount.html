GetDeferredBlockCount

member of hbe::RingBuffer Engine/Container/RingBuffer.h report how many retired blocks are still parked

Signature

[[nodiscard]] size_t GetDeferredBlockCount() const noexcept

Function description

A block the consumer has left is only retired, not freed, while a producer is still standing inside it: the hazard scan in IsBlockShadowed parks it in a deferred list and RetryDeferredBlocks frees it once no producer slot names it. This counter is that list's depth, so it reports how much of the queue's memory is alive for no reason except an unfinished handover.

The depth rises and falls during healthy work — a producer pre-empted between reserving a slot and leaving the block parks that block for a moment — and the shape worth watching is one that stays non-zero while GetFuseRefusalCount climbs, because that is a chain whose cap is held down by parked blocks rather than by its workload.

The slot a parked block waits for names the producer thread in this queue instance: a thread that pushes into several queues of the same type holds one slot in each, and a token cached from one queue is not trusted by another.

Parameters

NameWhat the caller must supply
noneThis method takes no argument.

Return value

The number of blocks parked in the deferred list as of this call. It can rise and fall; a queue with no consumer drains nothing, so its list stays empty while its live blocks climb to the fuse instead.

Examples

Illustrative — the real call sites are the diagnostic testlets in Engine/Container/RingBuffer.cpp.

const size_t live = queue.GetGrowCount() - queue.GetRetireCount();
log("blocks: %zu live, %zu parked", live, queue.GetDeferredBlockCount());
