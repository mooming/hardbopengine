Pop

member of hbe::RingBuffer Engine/Container/RingBuffer.h take the oldest element from the one consumer thread, distinguishing empty from claimed-but-unpublished

Signature

[[nodiscard]] EPopResult Pop(T& outItem) noexcept

Function description

Takes the oldest element out of the queue, if one is ready. The single consumer thread only. The chain-side cursor it advances, head, is an ordinary non-atomic pointer, and the position inside a block is the ring backend's own read index, which nothing but this call moves; a second consumer would corrupt both silently.

It never spins and never waits. It asks the head block's ring for an element, and an empty answer from that ring is not yet an answer about the queue, so the chain makes two further tests before it concludes anything. claim ahead of ring.GetSlotVersion() means a producer has reserved a place in the block that the ring has not taken yet; and !ring.IsEmpty() means the ring has taken a slot whose payload is not published yet. Either is a commitment. Answering "empty" to a commitment loses an element that is already owed, and stepping past it to a later slot would break first-in first-out, so the honest third answer is required and is what this method returns. Only when both tests find nothing in flight does the chain look for a successor, and only the absence of one earns Empty.

When the head block is drained and a newer block exists — a block gains a successor only once its claim reached BlockCapacity, so a drained block with a successor behind it is always a block that was filled to its cap — the cursor moves to that block and the one it leaves is retired. RetireBlock first moves tail off that block, so no producer can acquire it afresh, then frees it unless some producer's slot still declares it — in which case the block joins the deferred list and is freed by a later advance or by a producer that reaches the fuse. That is what bounds the chain at maxBlocks under a consumer that keeps up.

The backend moves the element into outItem, destroys its own copy and releases the slot, so a recycled slot is indistinguishable from a virgin one. That is the backend's work, not the chain's: the queue keeps no element bookkeeping of its own, which is why the same chain runs on any ring that satisfies CFixedRing.

Parameters

NameWhat the caller must supply
T& outItem Written only when the result is EPopResult::Element. On Empty and Blocked it is left exactly as the caller passed it, which the tests assert.

Return value

ValueWhat it means for the caller
EPopResult::ElementoutItem holds the oldest element. Call again to take the next.
EPopResult::EmptyNothing is in flight on the head block — neither a chain reservation the ring has not taken nor a ring slot still waiting for its payload — and that block is still the tail of the chain. A producer may add work at any moment, so this is not a promise.
EPopResult::BlockedAn element is committed somewhere on the path between the chain's reservation and the ring's publication, so the oldest element is neither present nor absent. The element exists and is on its way; the caller must not treat this as empty and must not look past it. Each occurrence increments GetBlockedCount.

Examples

Illustrative — no call site for this exists in the repository.

Task task;
for (EPopResult result = queue.Pop(task); result != EPopResult::Empty; result = queue.Pop(task))
{
        if (result == EPopResult::Blocked)
        {
                doSomethingElseUseful();

                continue;
        }

        run(task);
}
