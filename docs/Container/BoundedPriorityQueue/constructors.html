member of hbe::BoundedPriorityQueue Engine/Container/BoundedPriorityQueue.h zeroes two counters and allocates nothing — copy and move are both deleted

Signature

BoundedPriorityQueue() noexcept
		: totalSize(0)
		, highestBucket(0)

BoundedPriorityQueue(const BoundedPriorityQueue&) = delete

BoundedPriorityQueue(BoundedPriorityQueue&&) = delete

Function description

One constructor that does real work, and two refusals. The default constructor zeroes totalSize and highestBucket and allocates nothing — no matter how many priority levels the instantiation declares. The bucket array is std::array<std::optional<TBucket>, MaxPriority>, and a disengaged optional holds no deque, so declaring a 256-level queue constructs 256 empty optionals and no bucket. Buckets are created on the first Push to their level, by AcquireBucket.

Copy and move construction are both = delete: the queue cannot be copied, moved, or handed over by value. Its lifetime is the scope or object that declares it, and handing the contents over means draining them with Pop. Assignment is deleted in both forms too — see the class page.

Parameters

None. There is no sizing form, no allocator form and no range form.

Return value

A constructor has no return value. What you can observe afterwards is IsEmpty (true) and Size (0).

Examples

	Deque<WorkItem> fifoQueue;
	BoundedPriorityQueue<WorkItem> priorityQueue;

From Engine/Core/TaskStream.h, TaskStream

The engine's drain lanes are declared exactly like this: default-constructed members beside the containers they serve. Engine/Core/MainThreadTaskQueue.h declares the same shape with explicit template arguments (BoundedPriorityQueue<TaskItem, 256, MaxQueueSize>), which is the pattern for a bounded level count with a bucket hint.
