Clear

member of hbe::BoundedPriorityQueue Engine/Container/BoundedPriorityQueue.h resets every bucket — the buffers are freed, unlike Deque::Clear

Signature

void Clear() noexcept

Function description

Resets every bucket's optional, so every engaged deque is destroyed — its elements with it and its buffer back to the deque's allocator. This is the opposite of Deque::Clear, which destroys elements but keeps its buffer: after this call the queue holds no allocations at all, exactly as it was constructed.

totalSize returns to 0 and highestBucket to 0. Every reference, pointer or iterator into the queue dies here. The walk is over the whole level array — the cost is MaxPriority bucket resets, not a sweep over the elements.

Parameters

None.

Return value

None. Afterwards IsEmpty is true and Size is 0.

Examples

Illustrative — no call site for this exists in the repository.

queue.Clear();
assert(queue.IsEmpty());

The engine's queues are drained by Pop loops, not cleared; Clear is the bulk path when the contents should simply stop existing.
