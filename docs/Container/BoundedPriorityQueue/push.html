Push

member of hbe::BoundedPriorityQueue Engine/Container/BoundedPriorityQueue.h 2 overloads noexcept append into the bucket the item's own priority field selects — the highest number wins, never the lowest

Signature

void Push(const T& item) noexcept;
void Push(T&& item) noexcept;

Function description

Three steps, in a deliberate order: the priority is read out of the item and widened to std::size_t, the bucket for that value is created on first use and appended to, then totalSize is incremented and highestBucket raised if this priority is the new maximum. The move overload reads item.priority before it moves the item, so the priority used for routing is the real one.

Two ordering decisions are encoded here and are not visible from the signature. Urgency runs upward: the highest priority number is the most urgent, and Pop takes from highestBucket down. And within one bucket the deque is appended at the back and drained from the front, so two items with the same priority run in arrival order — first in, first out — not last-in-first-out.

Buckets exist only while they hold something. The first push to a priority allocates a Deque for it — sized BucketSizeHint when that template argument is above zero, otherwise the deque's own default of four slots, rounded up to a power of two — and the bucket is released the moment it drains. A queue that never sees priority 200 never pays for one.

The priority is an array index, and nothing bounds it. The body is AcquireBucket(static_cast<std::size_t>(item.priority)) and that resolves to buckets[priority] on a std::array of MaxPriority entries — no assert, no check, no clamp, in any configuration. It is safe by convention: MaxPriority defaults to 256 and the intended priority field is a uint8_t, so 255 is the largest value an item can carry. Break either half of that convention and the push writes outside the array. Instantiating MaxPriority below 256 while leaving an eight-bit priority field in place is enough — and the same hole is in the item's own hands: any element whose priority field is wider than eight bits reaches past the end on its own.
The item's priority is read once, at push time, and never looked at again. Nothing re-reads item.priority after insertion, so mutating the field of an element that is already queued does not move it to another bucket — the stored item and the index it lives at disagree, and the queue has no way to notice. That is why the engine's real "re-prioritise" path removes and re-pushes: see PushRange and Remove for the pair the task system uses.

Parameters

ParameterTypeRequirement
item const T& / T&& Must expose a readable priority member whose value fits below MaxPriority, and must be copy-constructible for the first overload, move-constructible for the second. Copy semantics are the default container's: the queued element is a copy, so a change to the caller's object after the push is invisible to the queue. The header's own note adds HasFinished() to the type requirements — that member is not called by this class; it belongs to the predicates callers hand to Remove

Return value

void. Size() is one larger, IsEmpty() is false, and Top() returns this item immediately if its priority is at or above everything already queued. Nothing reports whether the bucket had to be created — the only observable difference is one extra allocation the first time a given priority is used.

Examples

Real call site — the task system's work queue.

// Engine/Core/TaskStream.h
BoundedPriorityQueue<RangedTask> priorityQueue;

// Engine/Core/TaskStream.cpp
priorityQueue.Push(task);                   // line 82 — routed by task.priority, oldest-first within the level

// Engine/Core/TaskSystem.cpp
taskQueue.Push(task);                       // line 149 — same shape on a second BoundedPriorityQueue

Both queues use the default template arguments, so both are 256 levels with buckets sized by Deque's default. The one instantiation in the engine that sizes buckets explicitly is Engine/Core/MainThreadTaskQueue.h: using TQueue = BoundedPriorityQueue<TaskItem, 256, MaxQueueSize>; — 256 levels, every bucket created with room for MaxQueueSize items, paid for only on the levels that are actually used.
