Top

member of hbe::BoundedPriorityQueue Engine/Container/BoundedPriorityQueue.h a copy of the most urgent item, without removing it

Signature

[[nodiscard]] std::optional<T> Top() const noexcept

Function description

The most urgent item without removing it: the front of the highest populated bucket, same item Pop would hand out next. An empty queue answers std::nullopt — no assert.

Because the method is const and returns std::optional<T> by value, you get a copy, not a reference: nothing in the queue is touched, no bucket is released, no counter moves. The copy is the whole cost, and it is also the safety — there is no reference that a later Pop or Clear could invalidate. Note that the copy's priority byte is the value as stored; only Pop rewrites it to the served level.

Parameters

None.

Return value

TypeWhat you get
std::optional<T> A copy of the front of the highest populated bucket, or std::nullopt when the queue is empty

Examples

	auto workItemOpt = taskQueue.Top();
	if (!workItemOpt.has_value())
	{
		outTask.reset();

		return;
	}

	const WorkItem& workItem = workItemOpt.value();

From Engine/Core/TaskSystem.cpp, TaskSystem::Dequeue

The engine's pattern is inspect-then-decide: Top to read the item's affinity, then a separate Pop to remove it. Between the two calls the queue belongs to the same lock, which is the only reason the pair is safe — see IsEmpty for the synchronisation story.
