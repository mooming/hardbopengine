BoundedPriorityQueue

Engine/Container/BoundedPriorityQueue.h namespace hbe template <typename T, std::size_t MaxPriority = 256, std::size_t BucketSizeHint = 0> final one Deque per priority level, drained highest-first and oldest-first within a level

Class description

The queue is a fixed array of optional deques, indexed by priority. A level's deque is created by the first Push that names it and released the moment it drains, so an idle level costs nothing beyond its slot in the array and a queue with 256 declared levels can hold a single item. Selection is one variable: highestBucket tracks the largest priority that currently holds something, and Pop takes the front of that deque. Within a level, items append at the back and leave from the front, so equal priorities run in arrival order.

This is the most-used container in the module. Engine/Core/TaskSystem.h holds BoundedPriorityQueue<RangedTask> taskQueue;, Engine/Core/TaskStream.h holds BoundedPriorityQueue<RangedTask> priorityQueue; beside its FIFO deque, and Engine/Core/MainThreadTaskQueue.h aliases BoundedPriorityQueue<TaskItem, 256, MaxQueueSize>.

"Bounded" bounds the priority range, not the number of items. There is no maximum size, no full state and no refusal anywhere in this class: totalSize is a plain counter that goes up for ever, and each level's deque grows by doubling the way Deque does. A producer that outruns the consumer makes this queue larger without limit — the bound in the name is the MaxPriority array, which is about how many levels exist. Nothing named "bounded" should be trusted to bound a backlog, and this one does not.
The priority value is an unchecked array index. Push computes static_cast<std::size_t>(item.priority) and indexes std::array with it — no assert, no clamp, in any configuration. It is correct only while the convention holds: an eight-bit priority field against MaxPriority = 256. Lower MaxPriority below the range of the element's priority field, or widen that field, and pushes corrupt memory outside the array in every build.
Urgency runs upward. The largest priority number is the most urgent — the opposite of the convention in most schedulers, and invisible in a test that only ever uses one level. Combined with oldest-first within a level, the full ordering rule is: highest number wins, ties broken by arrival.
The object cannot be moved, copied, or relocated after construction. Both copy and move constructors and both assignment operators are explicitly deleted and the destructor is defaulted, so a queue lives where it is declared — as a member of TaskSystem, TaskStream or MainThreadTaskQueue, which is how every real use does it. There is no allocator parameter of any kind either: the buckets are Deque objects and each takes DefaultAllocator on its own, which is the memory-scope rule that applies to every container in this module.

MaxPriority std::size_t, defaults to 256 Number of levels, and therefore the array size and the largest usable priority value minus one. It is a compile-time constant, not a capacity: nothing about it limits how many items the queue holds. It also fixes the object's footprint — one std::optional<Deque<T>> per level is inline storage in the owning object, empty or not, so 256 levels cost 256 handles whether or not they are used
BucketSizeHint std::size_t, defaults to 0 Capacity a bucket is created with, applied through if constexpr: above zero the deque is constructed with that many slots, rounded up to a power of two of at least 4; zero leaves the deque its own default of 4. Only levels that are actually used pay this — which is what makes BoundedPriorityQueue<TaskItem, 256, MaxQueueSize> in MainThreadTaskQueue affordable

Class properties

Every member and every nested type of this class is private — the class has no public nested type and no public constant, and its access section opens only at the constructor.

highestBucket std::size_t highestBucket; private The most urgent populated level. When the queue is empty it may sit at a level that holds nothing; every reader checks totalSize first, which is what makes that harmless

Non-member helper functions

None. The header declares nothing at namespace scope besides the class and its test collection, and it exposes no type of the kind LinkedList and HashMap document on their pages. Everything it needs from outside is Deque plus the standard headers <array>, <optional>, <cstddef> and <utility> — the only container in this module whose storage type comes from the standard library, which is worth knowing when comparing it to the hand-written containers around it.
