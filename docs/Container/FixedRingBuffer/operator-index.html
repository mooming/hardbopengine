operator[]

member of hbe::FixedRingBuffer Engine/Container/FixedRingBuffer.h position from the front, resolved through WrapIndex — fatal assert out of range

Signature

TElement& operator[](TIndex index) noexcept

const TElement& operator[](TIndex index) const noexcept

Function description

The element at index positions from the front — index 0 is Front, the oldest element, and Size() - 1 is Back. The address is resolved through WrapIndex(head + index), so it is correct in a wrapped ring, where the oldest element no longer sits at slot 0 of the buffer: 

		if (q.Size() != 3 || q[0] != 3 || q[1] != 4 || q[2] != 5)

From Engine/Container/FixedRingBuffer.cpp, FixedRingBufferTest::Prepare()

In that test the buffer wrapped twice before the reads, and q[0] still answers the oldest element. The guard is FatalAssert(IsValidIndex(index)) — an out-of-range index stops the process rather than reading a dead or foreign slot. There is no iteration beside this: the class declares no begin/end, so 0 .. Size() - 1 through this operator is the only ordered walk.

Parameters

ParameterTypeRequirement
indexTIndex (int) A position from the front, 0 to Size() - 1 — checked by IsValidIndex, not a slot in the raw buffer.

Return value

TElement& — a reference to the live element, mutable through the non-const overload, valid until a Pop, Clear or Swap moves the ring under it.

Examples

Illustrative — the two ends of the valid range:

auto& oldest = q[0];
auto& newest = q[q.Size() - 1];
