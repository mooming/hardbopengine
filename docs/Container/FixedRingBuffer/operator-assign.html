operator=

member of hbe::FixedRingBuffer Engine/Container/FixedRingBuffer.h copy deleted; move assignment is a Swap — capacities travel with the buffer

Signature

FixedRingBuffer& operator=(const FixedRingBuffer&) = delete

FixedRingBuffer& operator=(FixedRingBuffer&& rhs) noexcept

Function description

Two forms, one of them a refusal. Copy assignment is = delete; a fixed-capacity ring is move-only. The move form is Swap and nothing else — noexcept, allocation-free, and safe on self-assignment because a swap with itself is a no-op.

Being a swap, it is not a drain: after a = std::move(b), b holds what a held — buffer, cursors, count and capacity, all five fields — rather than being left empty. The test exploits exactly that shape: 

		FixedRingBuffer<int> q3(1);
		q3 = std::move(q2);
		if (q3.Size() != 2 || q3[1] != 2)

From Engine/Container/FixedRingBuffer.cpp, FixedRingBufferTest::Prepare()

q3 was built with capacity 1 and ends holding q2's buffer of capacity 4 — capacities travel with the buffer, so a move assignment can silently change the destination's ceiling. Check Capacity afterwards if the budget matters.

Parameters

ParameterTypeRequirement
rhsFixedRingBuffer&& The source ring. All five fields are exchanged; it ends holding the destination's former state.

Return value

*this, holding the source's former buffer and contents.

Examples

Illustrative — the swap consequence, spelled out:

a = std::move(b);
// a.Capacity() is now what b.Capacity() was
