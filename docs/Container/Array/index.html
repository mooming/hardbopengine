Array

Engine/Container/Array.h namespace hbe template <typename Element, class TAllocator = DefaultAllocator<Element>> final a dynamic array whose memory comes from an allocator you name, with no growth policy and no copy

Class description

Array holds length elements in one buffer that allocator produced. It is the engine's answer to std::vector with two deliberate absences: there is no capacity beyond the size, and there is no copy. Every element is constructed in place, destroyed explicitly, and freed by the same allocator instance that allocated it, which is what lets an array be pinned to a pool instead of to whatever allocator scope happened to be open when it was built.

Movement is the only way an Array changes hands — the copy constructor and the copy assignment operator are both = delete, and the move constructor and move assignment both delegate to Swap, so a move exchanges three fields and never touches an element.

Array is final. A container that derives from a container turns a destructor into a slicing bug, so the inheritance question is closed at the type.

Template parameters

ParameterKindWhat it must satisfy
Element typename The stored type. It must be move-constructible, because Resize moves every element into the new buffer, and it must be default-constructible, because the sized constructor value-initialises and Resize fills its new tail that way. An element whose address other code holds does not belong in an array that gets resized.
TAllocator class, defaults to DefaultAllocator<Element> Anything with allocate(count) returning a pointer and deallocate(pointer, count). It is held by value, so an adapter holding a reference to a pool inherits that pool's lifetime rule: the pool has to outlive the array. See Memory: allocators.

Class properties

NameDeclarationWhat it means
TIndex using TIndex = int; member type Element count and every index. This is int, not the engine's usual size_t — a count is compared against >= 0 in IsValidIndex, so the signedness is load-bearing rather than an oversight. It does mean an Array index silently widens into a loop counter of another type, and a loop written with size_t compares signed against unsigned.
Iterator using Iterator = Element*; member type A raw pointer. Array satisfies range-for and takes STL algorithms without an adapter, and there is no debug iterator layer to catch a stale one
ConstIterator using ConstIterator = const Element*; member type The const counterpart, and the return type of begin() const
length TIndex length; private The element count, and also the capacity — Size returns it directly
data Element* data; private The buffer, or nullptr for an empty array. A non-positive size at construction takes no memory at all
allocator TAllocator allocator; private Held by value. Chosen before the first allocation and used again by the destructor, so allocation and deallocation cannot end up split across two different pools
