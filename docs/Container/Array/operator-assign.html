operator=

member of hbe::Array Engine/Container/Array.h 2 overloads, one deleted move assignment, implemented as a swap — so the source keeps what the destination used to hold

Signature

Array& operator=(Array&& rhs) noexcept;
Array& operator=(const Array&) = delete;

Function description

The moving overload is Swap(rhs); return *this; — no element is copied, moved or destroyed by the assignment itself. After it, this array holds rhs's length and buffer and rhs holds this array's former length and buffer. It is noexcept because it only reassigns two fields.

The copy overload exists solely to be removed, alongside the deleted copy constructor. An Array cannot be duplicated through any interface: if you need a second array with the same contents you build one and fill it, which is a statement about cost rather than a limitation.

Self-move-assignment is harmless by construction — Swap exchanges the two fields with themselves, leaving the array exactly as it was. That is why this class carries no this != &rhs guard; the containers in this module that do guard (Vector, HashMap, Map) destroy-then-adopt rather than swap, and for those the guard is load-bearing.

The source does not become empty. This is swap semantics, not the std::vector "moved-from is a valid but unspecified empty container" rule: after a = std::move(b);, b.Size() is the size a had, and b owns a's old buffer. Nothing is freed at the point of assignment either — the elements the destination used to hold are destroyed by b's destructor, whenever b's scope ends. A caller that expected the assignment to release memory immediately will find the memory still held, and a caller that expected b to be empty will find it is not. If you want the contents gone, clear them yourself or let b go out of scope.
The allocator is not exchanged, so this assignment re-homes a buffer across allocators in both directions. Each side keeps its own allocator member and will free the buffer it just acquired with it. With DefaultAllocator — which records the allocator id current at construction, not a global — that means a buffer allocated under one memory scope is freed under another; with a pool adapter such as NamedPoolAllocator, a cross-pool free. It is safe only when both arrays draw from the same place, which is the assumption to check before assigning one array to another. See Memory: allocators and Swap, which has the same property and no assignment's expectations around it.

Parameters

ParameterTypeRequirement
rhs Array&& The array whose length and buffer you are taking. Must be a mutable rvalue — std::move of a live array, or a temporary such as the one in streams.Swap(Array<TaskStream>(n)). After the call it is a valid array holding this array's former contents, not an empty shell
(deleted overload) const Array& Present only to make a copy a compile error. The error names this operator, not the constructor, so a "copy assignment of Array is deleted" diagnostic can mislead a reader into thinking copying is supported in some other form; it is not

Return value

TypeWhat you get
Array& Reference to *this, now holding the source's former buffer, so chained assignment compiles. Not [[nodiscard]], so discarding it is not diagnosed. Never a reference to rhs — a common reading of "swap" semantics, and wrong

Examples

Illustrative — no call site for this exists in the repository. The engine's real arrays are given their buffer with Swap or a constructor; see Engine/Core/TaskSystem.cpp and Engine/Core/ResultContainer.cpp for those.

hbe::Array<TaskStream> oldStreams(4);
hbe::Array<TaskStream> newStreams(8);

oldStreams = std::move(newStreams);

oldStreams.Size();     // 8: oldStreams now owns the 8-element buffer
newStreams.Size();     // 4, not 0 — newStreams owns what oldStreams held

The pattern the engine actually uses, which avoids the second name entirely by assigning into a swap against a temporary — the real line, from Engine/Core/TaskSystem.cpp: 

streams.Swap(Array<TaskStream>(numHardwareThreads));   // sized temporary in, old buffer out to the temporary

From Engine/Core/TaskSystem.cpp, where streams is Array<TaskStream>. The temporary's destructor is what releases the previous buffer, and because both arrays use the default allocator the un-exchanged allocator member costs nothing here.
