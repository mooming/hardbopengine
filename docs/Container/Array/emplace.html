Emplace

member of hbe::Array Engine/Container/Array.h noexcept destroy the element at an index and build a new one in the same storage — the size never changes

Signature

template<typename... Types>
Element& Emplace(TIndex index, Types&&... args) noexcept;

Function description

Three operations on one slot: assert IsValidIndex(index), call item.~Element() on the element already there, then new (&item) Element(std::forward<Types>(args)...). It is a replacement, not an insertion — there is no Insert in this container, nothing shifts, and Size is the same number before and after.

Because the new object is built in the storage the old one occupied, the element's address is stable. This is the one mutating operation on Array that does not invalidate anything: a pointer or reference to that slot still names the same address, now holding a different object. Contrast Resize, which moves every element and invalidates all of them.

The arguments are forwarded, not copied, so whatever constructor Element(Types...) resolves to is called with exactly what you passed — including move-only arguments. This is how an array of objects that cannot be assigned or copied gets filled: the array is sized first, which default-constructs a placeholder in every slot, and each placeholder is then replaced in place.

The slot must exist, and the check that enforces it has no recovery path. FatalAssert(IsValidIndex(index)) is active in every configuration including Release, per Core: Debug. An index that is one past the end — the natural mistake when Emplace is mistaken for a push — stops the process rather than growing the array. Room is made with Resize first, never by the call itself.
The old element is destroyed before the new one is built, inside a noexcept function. If Element's constructor throws, the slot holds a destroyed object and the exception leaves a noexcept function — the process terminates, and no other slot is affected. An element type whose constructor can throw is the case to construct somewhere you can catch instead.

Parameters

ParameterTypeRequirement
index TIndex (int) An index the array already has: 0 to Size() - 1. Negative is out of range, not counted from the end
args Types... Zero or more arguments forming a valid Element constructor call. May be empty, which value-initialises the slot — the same thing the sized constructor already did, so an argument-less Emplace is a destroy-and-rebuild of a slot that was already default-constructed

Return value

TypeWhat you get
Element& The newly constructed element, at the address the destroyed one occupied — the same reference operator[] would give for that index. Not [[nodiscard]]; ignoring it is how most call sites use it

Examples

The task system sizes its array of streams first, then builds each stream in its slot. This is a real sequence, in file order, from the engine's startup path: 

// streams is Array<TaskStream>, a member of TaskSystem
streams.Swap(Array<TaskStream>(numHardwareThreads));   // numHardwareThreads default-constructed slots

{
        auto index = GetBaseTaskStreamIndex();
        streams.Emplace(index, "Base", index);        // TaskStream("Base", index) built in slot 0

        index = GetIOTaskStreamIndex();
        streams.Emplace(index, "IO", index);          // TaskStream("IO", index) built in slot 1
}

for (TIndex i = 0; i < workerCount; ++i)
{
        streams.Emplace(i, streamName.c_str(), i);    // the same call with computed arguments
}

From Engine/Core/TaskSystem.cpp, in TaskSystem's startup path. The two arguments after index are forwarded straight into TaskStream's constructor.

What that sequence costs, stated once so nobody has to rediscover it. Sizing the array default-constructs every slot, and each Emplace destroys that placeholder and constructs again. For an element whose default construction is free — TaskStream's is close to it — that is a rounding error and the alternative (an array that can only hold copyable things) is worse. For an element that allocates in its default constructor, you are paying that allocation once per slot and throwing it away, which is the argument for a container of pointers instead.
