RingQueue

Engine/Container/RingQueue.h namespace hbe template <typename TElement, class TAllocator = DefaultAllocator<TElement>> final a fixed-capacity ring: one buffer, a power-of-two mask, and a capacity that is chosen once at construction

Class description

RingQueue is the bounded sibling of Deque: same idea — one buffer, a head and a tail cursor, everything wrapped by index & (cap - 1) — but the buffer is allocated once by the constructor and never touched again. Push and pop are constant time with no allocation, no deallocation and no element movement, which is exactly what a fixed-size producer/consumer window needs. The trade is that Capacity() is a hard ceiling: Push into a full ring is a fatal assert.

The capacity is rounded up to a power of two — std::bit_ceil on the requested value — because the wrap is a bit and against cap - 1 rather than a modulo. Ask for 100 and you get 128, so Capacity() is a fact to read back, never an assumption to make.

There is no default constructor, and the capacity cannot be re-chosen afterwards. The only non-move constructor is explicit RingQueue(TIndex fixedCapacity), guarded by FatalAssert(fixedCapacity > 0, "RingQueue capacity must be positive"). A RingQueue member therefore has to be initialised where it is declared or in the constructor's member list; it cannot be left empty and filled in later, it cannot be a value in a container that default-constructs its elements, and the way to reset one is Clear() — not "resize it", because nothing here resizes.
TAllocator is a type used twice through two different default-constructed objects, and no instance is ever stored. The constructor runs TAllocator alloc; data = alloc.allocate(pow2Capacity); and the destructor runs TAllocator alloc; alloc.deallocate(data, cap); — a second, freshly default-constructed object. There is no constructor parameter that accepts an allocator, so an allocator with state cannot be configured at all: whatever DefaultAllocator records at construction (Memory: allocators) is recorded twice, at two different moments, and the free goes through the second recording. This is the strictest allocator contract in the module: the type must be default-constructible and, to be correct, effectively stateless — a pool adapter holding a pointer to a specific pool will free into whichever pool its default constructor happens to find.
Moves are safe here, including against yourself. The move constructor zero-initialises and then Swaps, so a move allocates nothing — unlike Deque, whose move constructor allocates four slots before swapping. Move assignment is the same Swap, and since a swap with itself changes nothing, q = std::move(q); leaves the queue intact. Both forms still exchange buffers between objects that each hold their own default-constructed allocator, so the allocator caveat above applies to a move as much as to construction.

Template parameters

ParameterKindWhat it must satisfy
TElement typename Copy-constructible for the const Push, move-constructible for the rvalue Push and for Pop — which moves the element out and returns it by value — and constructible from whatever Emplace is given. Default construction is never required, and nothing here ever moves elements between buffers, so an element whose address you hold can safely live in a ring queue. It must be destructible: the ring destroys elements in place on Pop and Clear
TAllocator class, defaults to DefaultAllocator<TElement> allocate(count) returning TElement* and deallocate(pointer, count) with count in elements — one allocation for the whole ring, not per element. Default-constructible, and see the gap above: it is instantiated twice, once to allocate and once to free, and no instance can be supplied
