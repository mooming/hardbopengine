Push

member of hbe::RingQueue Engine/Container/RingQueue.h 2 overloads noexcept construct at the tail cursor — and stop the process if the ring has no room

Signature

void Push(const TElement& value) noexcept;
void Push(TElement&& value) noexcept;

Function description

Both overloads run the same three steps: FatalAssert(!IsFull(), "RingQueue is full"), a placement new (&data[tail]) TElement(...) copying or moving the argument into the slot the tail cursor names, then tail = WrapIndex(tail + 1); ++count;. There is no allocation on this path at all — the buffer was taken once by the constructor and never grows — so the cost is one element construction and two field writes, and the wrap is index & (cap - 1) against the power-of-two capacity.

A full ring is a fatal assert, not an overwrite and not a refusal you can branch on. This is the behaviour a caller most needs to know, and the two natural guesses are both wrong. Nothing is overwritten: the oldest element survives and the cursor never advances past it. And nothing is reported: IsFull() is checked by FatalAssert, which is live in every configuration including Release (Core: Debug), so pushing to a full queue terminates rather than returning a status. There is no TryPush in this class to branch on, and no capacity growth either. The caller's only lever is to size the queue for its worst case at construction, since Capacity() is fixed by the constructor and never changes afterwards.
Copy overload needs a copy constructor; move overload needs the element to stay usable after being moved. The rvalue overload constructs with std::move(value) and leaves the caller's object moved from. Elements that cannot be copied or moved cheaply go in through Emplace, which forwards constructor arguments and hands back a reference to the new element — it has the same full-ring assert.

Parameters

ParameterTypeRequirement
value const TElement& / TElement&& Any element; unlike Queue::Push a temporary binds fine. The only precondition is Size() < Capacity(), and it is asserted rather than tested for a return path

Return value

void. After a successful push Size() is one larger and Back() refers to the new element; after a push into a full ring there is no return, because the process stops. The counterpart at the front, Pop(), returns the element by value — this class is the only one in the module that hands the element out instead of asking you to read it and then remove it.

Examples

Illustrative — no call site for this exists in the repository. Container/RingQueue.h is included by Engine/Test/UnitTestCollection.cpp and by nothing else in Engine/ or Applications/; RingQueueTest in Engine/Container/RingQueue.cpp is the only user.

hbe::RingQueue<Sample> samples(100);   // capacity rounds up: Capacity() == 128

samples.Push(measured);                     // copy
samples.Push(std::move(scratch));           // move; `scratch` is moved from afterwards
samples.Emplace(3, 0.5f);                  // Sample(3, 0.5f) in place, returns Sample&

while (samples.Size() > 1)
{
        samples.Pop();
}

samples.Push(oneMore);                     // room again: Pop is what creates room, nothing else

The loop above is the shape that keeps a ring queue alive: the capacity is a budget you spend with Push and get back only with Pop or Clear. Anything that produces faster than it consumes needs the capacity to cover the whole burst, because the assert is the back-pressure mechanism and it does not negotiate.
