Pop

member of hbe::Queue Engine/Container/Queue.h noexcept destroy the oldest element and move on — the value is not yours unless you took it first

Signature

void Pop() noexcept;

Function description

Two lines: FatalAssert(!container.IsEmpty()), then container.PopFront();. Everything real about this call happens inside the underlying container — for the default Deque that means destroying the element at head and advancing the cursor, leaving capacity untouched. Nothing is returned, so the element is gone the moment the call returns.

Take the element before you pop it, and take it by value. Removal and retrieval are two separate calls, and the one that hands you the element (Front()) returns a reference to storage the next one destroys. The ordering that looks natural is the broken one: 
auto& pending = q.Front();   // reference into the queue's buffer
q.Pop();                       // the element it referred to is destroyed here
Handle(pending);                 // reads a destroyed element
auto pending = q.Front();    // copy or move out first — `auto`, not `auto&`
q.Pop();
Handle(pending);                 // correct

The alternative when copying or moving the element is too expensive is Emplace-ing it elsewhere by reference, or dropping down to the underlying container and using Front() plus PopFront() directly — but the value-before-removal rule does not change with the spelling, because it is the destroy call that ends the reference's lifetime.

An empty queue stops the process, in Release included. The guard is FatalAssert, live in every configuration (Core: Debug), and there is no TryPop-style variant to branch on. IsEmpty() is the check to run first if the producer is not guaranteed to have supplied something.

Parameters

None.

Return value

void. Size() is one smaller and, for the default container, Capacity() is unchanged — the ring keeps the buffer it grew to; only Clear() and destruction release anything. Compare RingQueue::Pop, which returns the element by value and makes this whole ordering question disappear.

Examples

Illustrative — no call site for this exists in the repository. Container/Queue.h is included by Engine/Test/UnitTestCollection.cpp and by nothing else in Engine/ or Applications/. The engine's real FIFO consumer, Engine/Core/TaskStream.cpp, drives a Deque directly with Front() and PopFront() instead of going through this adapter.

hbe::Queue<Job> jobs;

while (!jobs.IsEmpty())                // the guard that keeps Pop out of the assert
{
        auto job = jobs.Front();       // by value, before the destroy
        jobs.Pop();

        job.Run();
}
