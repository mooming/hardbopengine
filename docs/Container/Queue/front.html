Front

member of hbe::Queue Engine/Container/Queue.h the oldest element — aborts on empty through the container's assert

Signature

TElement& Front() noexcept

const TElement& Front() const noexcept

Function description

A reference to the oldest element — the one the next Pop removes. Both overloads forward to the container's Front, and the const form is what a read-only caller gets. For the default container the empty case is an abort, not an exception or a null: 

TElement& Front() noexcept
{
	FatalAssert(!IsEmpty());

	return data[head];
}

From Engine/Container/Deque.h — the non-const Front overload; the const form beside it has the same body.

So calling Front() on an empty queue stops the process. The reference stays valid until the queue changes under it — a Pop, a Clear, or whatever growth does per the container's own contract.

Parameters

None.

Return value

TypeWhat you get
TElement& (or const TElement&) A reference to the head element, mutable through the non-const overload. The const form is what a const queue hands out, and the only one a read-only caller can use

Examples

for (int i = 0; i < 100; ++i)
{
	if (q.Front() != i)
	{
		ls << "Expected " << i << ", got " << q.Front() << lferr;

		return;
	}

	q.Pop();
}

From Engine/Container/Queue.cpp, QueueTest::Prepare()

Read Front(), then Pop() — the standard FIFO drain, and the reason the class page warns that Pop returns nothing: the value has to be taken through this accessor first.
