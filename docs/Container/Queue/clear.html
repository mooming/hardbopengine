Clear

member of hbe::Queue Engine/Container/Queue.h destroys every element, keeps the container's buffer

Signature

void Clear() noexcept

Function description

Forwarded to the container's Clear. For the default container that destroys every element and resets the cursors, keeping the buffer: 

void Clear() noexcept
{
	DestroyAll();
	head = 0;
	tail = 0;
	count = 0;
}

From Engine/Container/Deque.h, Deque::Clear()

So a cleared queue is empty but has not handed its memory back — the buffer and its capacity stay with the container, ready for the next Push. Every reference and pointer into the queue dies here; the element destructors run in queue order.

Parameters

None.

Return value

None. Afterwards IsEmpty is true and Size is 0.

Examples

q.Push(1);
q.Push(2);
q.Clear();

if (!q.IsEmpty())
{
	ls << "Queue should be empty after Clear" << lferr;

	return;
}

q.Push(10);
if (q.Size() != 1 || q.Front() != 10)
{
	ls << "Reuse after Clear failed" << lferr;

	return;
}

From Engine/Container/Queue.cpp, QueueTest::Prepare()

The test's second half is the point of the retained buffer: the queue is reusable immediately after Clear, and the reused queue behaves like a fresh one.
