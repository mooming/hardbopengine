Push

member of hbe::Queue Engine/Container/Queue.h append at the FIFO tail through the container's PushBack

Signature

void Push(const TElement& value) noexcept

void Push(TElement&& value) noexcept

Function description

Two overloads, one forwarding line each: the lvalue form copies into the container's PushBack, the rvalue form moves. The element goes at the back, which is the FIFO tail — the end Pop will reach last.

Both are declared noexcept, which for the copy form is a real commitment: if copying a TElement throws, the exception cannot propagate out of a noexcept function and the process terminates. A queue is the right container only for element types whose copies and moves do not throw.

Growth is not this class's business: when the container is full, PushBack grows by its own rule, and what that does to references and iterators into the queue is the Deque::PushBack contract.

Parameters

ParameterTypeRequirement
valueconst TElement& or TElement&& The element to append. Copied from an lvalue, moved from an rvalue; no other requirement beyond what the container's PushBack imposes.

Return value

None — the operation cannot fail to append; it either grows and succeeds or terminates on a throwing copy.

Examples

Queue<int> q;
q.Push(10);
q.Push(20);
q.Push(30);

From Engine/Container/Queue.cpp, QueueTest::Prepare()

The same test then asserts Front() == 10 and Back() == 30, which is the ordering contract in one line: first in at the front, most recent at the back.
