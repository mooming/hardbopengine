Queue

Engine/Container/Queue.h namespace hbe template <typename TElement, class TContainer = Deque<TElement>> final a first-in-first-out facade: one container member, one forward per operation, nothing of its own

Class description

Queue holds exactly one member, TContainer container;, and every method is a forwarding call against it: Push to PushBack, Pop to PopFront, Front and Back to the same names, Size, IsEmpty and Clear likewise, Emplace to EmplaceBack. The class owns no memory, no allocation logic and no invariants of its own — it restricts the interface, it does not change the implementation.

That makes this page a pointer rather than a specification: the contracts that matter — when the buffer grows, what invalidates a reference, what an allocator does, what a capacity means — belong to Deque (or to whatever you substitute for it), and the rows below say so per method instead of restating them. The two things this adapter adds on its own are the FatalAssert in Pop and the fact that it exposes no iteration at all.

Construction, moving and the memory budget are all the underlying container's, and the default one allocates immediately. Queue() = default; with a TContainer container; member means a default-constructed queue default-constructs its container — and Deque allocates DefaultCapacity = 4 elements in that constructor. So an empty queue is not free, and neither is moving one: the move constructor delegates to the container's, which for Deque allocates four slots before it swaps. Move assignment forwards to the container's move assignment, which for Deque is Swap — so the source queue keeps the destination's former contents rather than being emptied.
There is no allocator parameter anywhere in this class. The second template parameter names a container type, not an allocator, so the only route to a specific pool is through that container's own default-constructed allocator — Deque has no constructor that accepts one either. Everything about which memory scope the buffer lands in, and about what happens when the queue outlives it, is Memory: allocators.

Template parameters

ParameterKindWhat it must satisfy
TElement typename Whatever the container requires, plus copy-constructible for the const Push and for reading Front() before a Pop, since that read has to make a copy rather than keep a reference. No comparison and no default construction of the element is required
TContainer class, defaults to Deque<TElement> The full storage contract, checked at instantiation: default-constructible (the queue's own default constructor needs it), movable, and offering PushBack(const T&), PushBack(T&&), EmplaceBack(args...) returning T&, PopFront(), Front() and Back() in const and non-const, Size(), IsEmpty() and Clear(). Substituting RingQueue works on that list and changes the growth rule to a fatal assert on full; substituting anything that pushes at the front instead of the back silently reverses the order the queue promises

Class properties

NameDeclarationWhat it means
TContainerType using TContainerType = TContainer; member type The storage type spelled back out — the only type alias this class declares. There is no TIndex: Size() returns auto, forwarding the container's own index type, which for Deque is int
container TContainer container; private The one member. It is private and there is no accessor for it, so the underlying container's extra operations — PushFront, Reserve, Capacity, iteration — are unreachable through a queue. Choose the container type before you need them, or hold the container yourself

Non-member helper functions

None. The header declares nothing at namespace scope besides the class and its test collection, and unlike LinkedList or HashMap it brings no supporting type along with it.

No call site in the engine Container/Queue.h is included by Engine/Test/UnitTestCollection.cpp and by nothing else in Engine/ or Applications/. Engine/Core/TaskStream.h holds a Deque<RangedTask> and calls Front() / PopFront() on it directly — so this adapter has never been exercised by production code, and every example here is labelled illustrative
No capacity query and no reserve Deque offers Capacity() and Reserve(); this facade exposes neither, and the container is private. A queue therefore cannot be pre-sized or its headroom inspected without dropping the adapter — an interface limitation, recorded here rather than guessed at
No iteration No begin/end is declared, so the unmasked range pair in Deque is not reachable through a queue — a benefit of the narrow facade, worth knowing if you are tempted to widen it
Threading Nothing here serialises anything; a queue shared between producer and consumer threads needs external synchronisation, which is what TaskStream does around its Deque — documented under Core
