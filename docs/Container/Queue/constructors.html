member of hbe::Queue Engine/Container/Queue.h default builds the container, copy is deleted, move forwards to the container's move

Function description

Three forms, one of them a refusal. The default constructor is = default, which default-constructs the one member, TContainer container; — so an empty queue is as expensive as an empty Deque, and for the default container that is not free: 

Deque() noexcept
	: head(0)
	, tail(0)
	, count(0)
	, mask(DefaultCapacity - 1)
	, data(allocator.allocate(DefaultCapacity))
{
}

From Engine/Container/Deque.h, Deque::Deque()

The copy constructor is = delete — a queue cannot be copied, and attempting it is a compile error, not a deep-copy surprise. The move constructor forwards to the container's move constructor; for Deque that default-constructs a fresh buffer first and then swaps, so the move is not a pure pointer steal, and the source queue ends up holding that fresh empty buffer rather than the destination's old state.

Parameters

None. Neither the default nor the move form takes a sizing, allocator or range argument — the header declares no other constructor.

Return value

A constructor has no return value. What you can observe afterwards is IsEmpty (true) and Size (0).

Examples

Queue<int> q2(std::move(q1));

The test then reads q2.Front() and q2.Size() to confirm the elements travelled with the move — the only exercise this constructor gets in the repository.
