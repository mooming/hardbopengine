PopFront

member of hbe::Deque Engine/Container/Deque.h destroy the front element, advance the head — fatal assert on empty

Signature

void PopFront() noexcept

Function description

Destroys the front element and advances the head cursor — FatalAssert(!IsEmpty()) first, so popping an empty deque stops the process. It returns nothing: read the element through Front first, which is exactly the pairing the engine's drain loop uses. 

			workItem = fifoQueue.Front();
			fifoQueue.PopFront();

From Engine/Core/TaskStream.cpp, TaskStream::Update()

Capacity is untouched — popping never shrinks the allocation, and the slot the head cursor vacated is immediately reusable by the next PushFront. Every reference and iterator to the removed element dies here; references to the surviving elements do not move.

Parameters

None.

Return value

None. Afterwards Size is one smaller and Capacity is unchanged.

Examples

		d.PopFront();
		if (d.Size() != 2 || d.Front() != 20)
