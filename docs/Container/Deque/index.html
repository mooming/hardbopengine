Deque

Engine/Container/Deque.h namespace hbe template <typename TElement, class TAllocator = DefaultAllocator<TElement>> final a ring buffer with push and pop at both ends, indexed through a power-of-two mask

Class description

Deque keeps one buffer and two cursors. head names the oldest element and moves backwards on a push at the front; tail names the next free slot at the back and moves forwards. Every slot number is produced by WrapIndex(index) { return index & mask; }, so capacity is always a power of two and Reserve doubles until it covers a request. Neither end costs a shift, which is what makes this the container the task system queues FIFO work with — Engine/Core/TaskStream.h declares Deque<RangedTask> fifoQueue; beside its priority queue.

Access is by position: operator[] resolves data[WrapIndex(head + index)], and Front and Back are the two ends. Indexed access is correct in every state of the ring, including a wrapped one; the pointer range begin to end is not, and that difference is the single most important thing on this page.

A default-constructed deque allocates immediately, and so does moving one. The default constructor's member list is data(allocator.allocate(DefaultCapacity)) — four elements taken before anything is pushed. This is the only container in the module that spends an allocation on an empty object: Array, Vector, HashMap and Map all construct to a null buffer. It gets worse through the move constructor, which delegates to that constructor and then swaps: Deque(Deque&& rhs) : Deque() { Swap(rhs); }. Every move of a deque therefore performs an allocation it does not want, and hands the discarded four-element buffer to the moved-from object to free. Put a deque where it will not be moved, or move it once at startup.
The allocator is never exchanged, and here the move makes that observable twice over. After a move the destination frees the buffer c rhs allocated using its own default-constructed allocator, and rhs frees the freshly allocated buffer it just received using its own. With DefaultAllocator holding the scope id captured at construction, both frees can land in a scope that did not allocate them; with a pool adapter they land in the wrong pool. Reserve and the destructor also use whichever allocator the object holds, so a deque that outlives its memory scope is the same hazard as everywhere else in this module — see Memory: allocators.

Template parameters

ParameterKindWhat it must satisfy
TElement typename Copy-constructible for the const-reference pushes, move-constructible for the rvalue ones and for every growth (a reserve moves all the elements), and constructible from whatever the EmplaceFront and EmplaceBack calls are given. No default construction is required by anything except a growing Resize-style use, which this class does not offer; no assignment or comparison is required at all. An element whose address is held elsewhere does not belong in a deque that grows
TAllocator class, defaults to DefaultAllocator<TElement> allocate(count) returning TElement* and deallocate(pointer, count), with count in elements — the buffer is one allocation, not per-element. Held by value, never exchanged by a move, and there is no constructor that accepts one: the type is the only choice a caller gets, so a pool has to be reachable from a default-constructed allocator object
