Reserve

member of hbe::Deque Engine/Container/Deque.h noexcept double the ring until it covers the request, rewriting the elements unwrapped in the process

Signature

void Reserve(TIndex newCapacity) noexcept;

Function description

Returns when newCapacity <= Capacity(). Otherwise it starts from the current capacity and doubles — newMask = (newMask + 1) * 2 - 1 — until the width covers the request, allocates that many elements, copies the live ones into slots 0 .. count - 1 by walking them logically (WrapIndex(head + i), which is why reading through begin would have been wrong), destroys the sources, returns the old buffer, and sets head = 0, tail = count and the new mask.

Capacity is therefore always a power of two — the mask is what makes WrapIndex a single and — and the number asked for is a floor, not a target, exactly as in HashMap::Reserve. A request of 100 on a fresh deque lands on 128, and the floor under it is DefaultCapacity = 4.

Because the copy leaves the elements unwrapped, this call also repairs begin to end: with head = 0 and tail = count, the range is valid again until the next PushFront wraps the cursor. That is an observation about the current state, not a technique — a ring that is pushed at both ends will wrap again, and there is nothing to reserve that keeps it unwrapped.

It cannot shrink, and a failed allocation is not checked. A request at or below the current capacity returns without doing anything, so unused capacity can never be handed back except by destroying the deque; and the allocation result is written through immediately, so a null return is a crash rather than a no-op — unlike Array::Resize, which tests the pointer and keeps its old state. Every pointer, reference and iterator into the deque is invalidated by a reserve that does anything, because the elements are moved into a new buffer.

Parameters

ParameterTypeRequirement
newCapacity TIndex (int) Elements you want the ring to hold before it grows again. Counted in elements, not bytes. Rounded up to the next power of two at or above the current capacity; zero and negative are below any capacity and do nothing

Return value

void. Capacity() afterwards reports what the ring actually became, and Size() is unchanged by definition — a reserve moves elements, it does not add them.

Examples

Illustrative — no call site for this exists in the repository. The engine's one Deque user lets the queue grow on its own.

hbe::Deque<int> queue;            // the default constructor already allocated 4 slots
queue.Capacity();                     // 4

queue.Reserve(100);                    // Capacity() == 128, not 100
queue.Reserve(8);                       // below capacity: nothing happens, memory stays allocated

for (auto i = 0; i < queue.Size(); ++i)
{
        Use(queue[i]);               // always the right loop, reserve or no reserve
}
