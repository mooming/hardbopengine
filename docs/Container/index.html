Module Index / Container

Container

namespace hbe Engine/Container 10 headers, 10 sources — the engine's own containers, each one documented on its own page

Module description

The engine's data structures, written once and instantiated everywhere: contiguous storage where a resize is an explicit call, rings where both ends are hot, open addressing where keys are hashed, and one atomic chain where threads need a pool. Seven of the ten take an allocator as a template parameter and default to DefaultAllocator, so memory accounting follows the container rather than the call site and a container placed in a frame-scoped arena frees with the arena. For the standard containers rebound the same way, see HSTL; the rule of thumb is that engine internals use this module and interoperating code uses HSTL.

The allocator story is not uniform, and the differences are contracts rather than details — see Shared conventions and each class page. In short: Array is the only container with a constructor that accepts an allocator instance; RingQueue accepts the type but stores no instance, allocating and freeing through two separate default-constructed objects; Queue takes the container it adapts rather than an allocator; and AtomicStackView has none at all, because it stores nothing but a pointer.

Shared conventions

Four rules repeat across these headers. Each is stated once here and referenced from the class pages.

RuleWhat it means at a call site
A move or swap never takes the allocator with it. No move constructor, move assignment or Swap in this module exchanges the allocator member, and several default-construct a fresh one on the destination. So the object that ends up holding a buffer frees it through its own allocator instance, not the one that allocated it — with DefaultAllocator capturing its memory scope at construction, a moved container can free into a scope that did not own the memory. The rule and its consequences are Memory: allocators; the per-class evidence is on each class page (Array, LinkedList, Deque, HashMap, Map)
Index types are per container, not module-wide. The contiguous containers declare their own using TIndex = int;, which shadows the engine-wide hbe::TIndex (size_t) inside their scope. The odd ones out are LinkedList::Count, which returns the engine-wide Index, and BoundedPriorityQueue::Size, which returns std::size_t. A loop written with one type against another container's Size() is a signedness mismatch with no diagnostic
Two guard families, and they differ in Release. FatalAssert fires in every configuration and is what protects element access and empty-container reads here; Assert is live in Debug and Dev only, and is what LinkedList::Remove and IsEmpty use — so Release builds run the list's precondition violations silently. The family is documented once, in Core: Debug
Construction and iteration have sharp corners. Deque allocates in its default constructor — and so does moving one, because the move constructor delegates to it; RingQueue has no default constructor at all and refuses to size itself; and Deque::begin to end is a valid range only while the ring is unwrapped, which a wrapped deque silently is not

Module variables

None at module scope. Tunables live with the container they belong to — Vector::DefaultCapacity, Deque::DefaultCapacity and Map::DefaultCapacity are each 4; HashMap carries MinCapacity = 4 and MaxLoadFactor = 0.7; Array has no default at all, which is the point of it; RingQueue has no default capacity either and must be constructed with one; and BoundedPriorityQueue's priority ceiling is a template argument. A container that sized itself from a global would couple every user of the module to one choice.

Module functions

None — every callable name this module exports is a member of a template. Three names do live at namespace scope in hbe, and each is documented on the class page that owns it rather than as a module entry: LinkedListNode (the node, which is also the element holder LinkedList's allocator must be sized for), EHashEntryState (the per-slot state the table runs on) and CNext (the concept that constrains AtomicStackView's element type).

Array (Engine/Container/Array.h)

Contiguous array whose size is a decision you make: construction sizes it, and it changes only when you call Resize. It is non-copyable, so a size chosen to fit a memory layout cannot be duplicated behind your back. Class page: Array.

Correcting the old guide. This module used to be described as "fixed-size, no resizing". Array::Resize exists now, so that sentence is no longer true — but the reason it was written that way is worth keeping: an Array was the container you reached for precisely because it never grew on its own. It still does not grow implicitly.
Array::TIndex is int. The engine-wide hbe::TIndex is size_t. Inside an Array scope the name resolves to the member alias, so an index computed from a size_t narrows without a diagnostic. Write the type you mean at the call site.
Resize behaviourContract, from the header
GrowingEvery element below the old Size() keeps its value, moved into the new buffer; the new tail is default-constructed
ShrinkingElements from newSize up are destroyed and their memory returned
Same sizeReturns immediately — nothing is touched
ZeroNot a failure: empties the array and gives the buffer back
Allocation failureAsserts and leaves the array exactly as it was, at its old size with its old buffer, so a caller can ask again later
What must not live hereAn element that is expensive to move, or one whose address someone else holds: every element is moved on resize, so a pointer into a resized array points into a freed buffer

Method pages: constructors, destructor, operator=, operator[], begin, end, Size, IsValidIndex, Resize, Emplace, GetIndex, ToRawArray, Clear, Swap.

Vector (Engine/Container/Vector.h)

Dynamic array with geometric growth: PushBack, EmplaceBack and the growing paths of Resize and Reserve reach an internal Grow that reserves max(DefaultCapacity, capacity * 2), so the first buffer is 4 elements and every later one doubles. There is no Insert and no Erase — this is a back-only dynamic array. References and iterators are invalidated by any growth. Class page: Vector.

Method pages: constructors, PushBack, EmplaceBack, Resize, Reserve, Swap, operator[].

HashMap (Engine/Container/HashMap.h)

Open-addressing hash map with tombstones and a 0.7 load factor; storage is one allocation typed as DefaultAllocator<uint8_t>, so slot metadata and slots share a buffer. Removal leaves a tombstone, and tombstones count toward the growth pressure — Remove never shrinks the table. Reserve is a minimum: capacity doubles from where it is, so it reports a number at or above what you asked for, never the number itself. Class page: HashMap.

Method pages: Insert, Remove, Reserve, operator[].

Map (Engine/Container/Map.h)

Sorted map kept in one array of pairs and searched by binary search — not a tree. Ordered iteration and cache-linear lookup, paid for by shifting the tail of the array on every interior Insert. There is no capacity query and no Reserve: the array grows by doubling, privately. Class page: Map.

Method pages: Insert, Remove, operator[].

LinkedList (Engine/Container/LinkedList.h)

Doubly-linked list; each node is a single allocation through the container's own node allocator. Two properties differ from how this class was described before: it keeps no element count (there is no Size(); Count(value) counts matches of a value), and Remove takes TType&, not const TType& — the element is located by address, and the type is what enforces that. Class page: LinkedList.

Method pages: Remove, operator=.

Deque (Engine/Container/Deque.h)

Ring-buffer deque: push and pop at both ends, one buffer, capacity always a power of two because Reserve doubles to a mask. The buffer holds a valid contiguous range only while the ring is unwrapped — and it wraps on PushFront, which is why begin and end are documented as a hazard and why indexed access through operator[] is the correct traversal. The default constructor allocates, and so does moving a deque. Class page: Deque.

Method pages: PushBack, begin, end, Reserve.

Queue (Engine/Container/Queue.h)

FIFO adapter: one TContainer container; member, defaulting to Deque<TElement>, and one forwarding call per operation. The interface is the point — the container is private, so PushFront and Reserve are unreachable and a caller cannot reach around the adapter. Note the template parameter is a container type, not an allocator, and that this class therefore exposes no capacity query. Class page: Queue.

Method page: Pop.

RingQueue (Engine/Container/RingQueue.h)

Fixed-capacity ring buffer: capacity is set by the only constructor, rounded up to a power of two, and never changes — which is what makes it safe where an allocation mid-frame would not be. Two corrections to the earlier description: there is no default constructor, and a push into a full ring does not overwrite the oldest entry and does not return a failure — Push fatal-asserts, in every configuration. Class page: RingQueue.

Method page: Push.

BoundedPriorityQueue (Engine/Container/BoundedPriorityQueue.h)

One Deque per priority level, held in a fixed array of optionals and created on first use, so push and pop are O(1) and an unused level costs nothing. The most-used container in the module — three engine sites, listed under Who uses what. Ordering runs upward (the highest number is most urgent) and oldest-first within a level. The priority value indexes that array with no bounds check, and "bounded" bounds the levels, not the item count. Class page: BoundedPriorityQueue.

MethodPurpose
Pop, Top Most urgent item as std::optional — empty means the queue was empty, which is why neither returns a reference, and why Top() copies
Remove Drop every item the predicate accepts by rotating every populated level; returns how many went, and moves everything whether or not anything matched
PushRange2 template overloads An iterator pair, or any container with const begin and end — one Push per element, no batch allocation

Method pages: Push, PushRange, Remove. The member alias TPredicate = bool (*)(const T&) is a plain function pointer, not a functor, so a lambda passed to Remove must be captureless.

AtomicStackView (Engine/Container/AtomicStackView.h)

Lock-free LIFO stack built on compare-and-swap over a single std::atomic<T*>. It is a view: the nodes it links are owned elsewhere and are never destroyed here, which is what the CNext constraint on the element type is for. Pop returns nullptr both when the stack is empty and when another thread won the race, and neither Push nor the destructor frees anything. Class page: AtomicStackView.

Method pages: Push, Pop.
