Module Index / Container

Container

namespace hbe Engine/Container 10 headers, 10 sources — the engine's own containers, every one templated on an allocator

Module description

The engine's own data structures. Every container here takes its allocator as a template parameter and defaults to DefaultAllocator<T>, so memory accounting follows the container rather than the call site, and a container placed in a frame-scoped arena frees with the arena. For the standard containers rebound the same way, see HSTL; the rule of thumb is that engine internals use this module and interoperating code uses HSTL.

Module variables

None at module scope. Tunables live with the container they belong to — Vector::DefaultCapacity is 4, HashMap's load factor is 0.7, BoundedPriorityQueue's priority ceiling is a template argument. A container that sized itself from a global would couple every user of the module to one choice.

None — every name this module exports is a template.

Vector (Engine/Container/Vector.h)

Class description

Dynamic array with geometric growth. PushBack, EmplaceBack and Insert-style paths call an internal Grow when full, which reserves max(DefaultCapacity, capacity * 2) — so the first buffer is 4 elements and every later one doubles. Iterators and references are invalidated by any growth.

Array (Engine/Container/Array.h)

Class description

Contiguous array whose size is a decision you make: construction sizes it, and it changes only when you call Resize. It is non-copyable, so a size chosen to fit a memory layout cannot be duplicated behind your back.

Correcting the old guide. This module used to be described as "fixed-size, no resizing". Array::Resize exists now, so that sentence is no longer true — but the reason it was written that way is worth keeping: an Array was the container you reached for precisely because it never grew on its own. It still does not grow implicitly.

Template parameters

ParameterDefaultMeaning
Element—Element type
TAllocatorDefaultAllocator<Element>Where storage comes from

Class properties

Storage pointer and length; header-private. The member aliases are the ones a caller types: TIndex = int, Iterator = Element*, ConstIterator = const Element*.

Array::TIndex is int. The engine-wide hbe::TIndex is size_t. Inside an Array scope the name resolves to the member alias, so an index computed from a size_t narrows without a diagnostic. Write the type you mean at the call site.

Resize behaviourContract, from the header
GrowingEvery element below the old Size() keeps its value, moved into the new buffer; the new tail is default-constructed
ShrinkingElements from newSize up are destroyed and their memory returned
Same sizeReturns immediately — nothing is touched
ZeroNot a failure: empties the array and gives the buffer back
Allocation failureAsserts and leaves the array exactly as it was, at its old size with its old buffer, so a caller can ask again later
What must not live hereAn element that is expensive to move, or one whose address someone else holds: every element is moved on resize, so a pointer into a resized array points into a freed buffer

BoundedPriorityQueue (Engine/Container/BoundedPriorityQueue.h)

Class description

Bucket-based priority queue for items tagged with a priority in 0–255: one bucket per priority, so push and pop are O(1) and the ordering is only as fine as the priority you tag with. This is the queue TaskStream drains.

Template parameters

ParameterDefaultMeaning
T—Item type; the item itself carries its priority
MaxPriority256Bucket count, i.e. the priority range
BucketSizeHint0Initial bucket capacity; 0 lets the container choose

Class properties

The buckets and the total count; header-private. The engaged-bucket-means-non-empty invariant is maintained in one place only, which is what lets Pop and Remove skip re-checking it.

Pop, TopHighest-priority item, as std::optional — empty means the queue was empty, which is why neither returns a reference

Non-member helper functions

The member alias TPredicate = bool (*)(const T&) — a plain function pointer, not a functor, so a lambda passed to Remove must be captureless.
