operator[]

member of hbe::Map Engine/Container/Map.h insert-or-read; a created slot gets a default-constructed value

Signature

TValue& operator[](const TKey& key)

TValue& operator[](TKey&& key)

Function description

Insert-or-read, in one operator. FindIndex locates the key; when it exists you get its value, and when it does not the key is inserted in sorted position with a default-constructed value and you get a reference to that. There is no way to ask which of the two happened — check Size before and after if the difference matters — and there is no const overload: a read-only caller uses Find or Contains, since a lookup that may insert cannot be const.

Neither overload is noexcept: a missing key means Grow may allocate. And an insertion shifts every entry above the key one slot right, so references and iterators into the map die on the inserting form of this call — the reading form touches nothing.

The two overloads differ only in how the key arrives: copied from an lvalue, moved from an rvalue.

Parameters

ParameterTypeRequirement
keyconst TKey& or TKey&& The key to read or create. The value type must be default-constructible, because a created slot starts as TValue{}.

Return value

TValue& — a reference to the existing or just-created value, mutable, valid until the next insertion or removal moves the array.

Examples

		Map<int, int> m;
		m[1] = 10;
		m[2] = 20;
		m[3] = 30;

		if (m[1] != 10 || m[2] != 20 || m[3] != 30)

From Engine/Container/Map.cpp, MapTest::Prepare()

The same test then checks m.Size() == 3 — three writes through operator[] created exactly three entries, which is the insert-or-read contract in one line.
