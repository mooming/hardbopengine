Rehash

member of hbe::HashMap Engine/Container/HashMap.h one new block for entries and states, every live entry re-hashed into it, tombstones dropped

Signature

void Rehash(TIndex newCapacity) noexcept

Function description

Private. Rebuilds the table at a new capacity, and it is the only member that ever allocates. One block is taken for both arrays — sizeof(Pair) * newCapacity bytes of entries immediately followed by sizeof(EHashEntryState) * newCapacity bytes of states — every state is initialised to Empty, and then the live entries move: each occupied slot of the old table is re-hashed, probed into the new table, move-constructed into its new slot, and destroyed where it was. Tombstones are not migrated — they vanish, which is how a rehash pays off the debt ShouldGrow was counting.

Every reference and iterator into the map dies here, and the iteration order changes with the capacity. The old block is returned through the map's allocator once the move is done.

Rehash is what Reserve and Grow both call, so every capacity change in the class funnels through this one method.

Parameters

ParameterTypeRequirement
newCapacityTIndex (int) The new slot count. The masking in the re-insertion probes assumes a power of two — which is what Reserve's doubling and Grow's doubling both produce.

Return value

None. Afterwards Capacity is newCapacity, Size is unchanged, and the tombstone count is 0.

Examples

Illustrative — private, and reachable only through Reserve and Grow.

auto h = hash(oldEntries[i].key) & static_cast<std::size_t>(newCapacity - 1);
auto idx = static_cast<TIndex>(h);

The re-insertion's first two lines: the entry's slot in the new table is computed fresh — nothing about its old position survives, which is why iteration order changes on every rehash.
