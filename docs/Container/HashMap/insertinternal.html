InsertInternal

member of hbe::HashMap Engine/Container/HashMap.h grow if the load factor says so, then occupy the first free slot — default-constructed value

Signature

std::pair<bool, TIndex> InsertInternal(const TKey& key) noexcept

std::pair<bool, TIndex> InsertInternal(TKey&& key) noexcept

Function description

Private. The insertion engine behind operator[], Insert and InsertInternal's callers, in three steps. ShouldGrow first — a map at its load factor Grows before anything is placed. Then the probe: an Occupied slot with an equal key answers {false, slot} — the duplicate case, and the reason Insert can refuse. Otherwise the first non-occupied slot takes the entry: a tombstone is reclaimed (its count drops by one), the pair is constructed with the key and a default-constructed value, the state goes to Occupied, and the answer is {true, slot}.

The two overloads differ only in how the key arrives — copied from an lvalue, moved from an rvalue. The method is noexcept, so a key copy or pair construction that throws terminates the process; and a probe that reaches a full table fatal-asserts with "HashMap should have grown before reaching full capacity" — the load-factor guard is what makes that branch unreachable in practice.

Parameters

ParameterTypeRequirement
keyconst TKey& or TKey&& The key to file. Duplicates are answered, not refused — the caller decides what false means.

Return value

TypeWhat you get
std::pair<bool, TIndex> first: whether a new entry was created (false for a duplicate key). second: the slot — the existing entry's for a duplicate, the new one otherwise

Examples

Illustrative — private, and reachable only through operator[] and Insert.

auto [inserted, slot] = InsertInternal(key);
if (inserted)
{
	entries[slot].value = value;
}

That is Insert's tail: create the slot with its default value, then assign the caller's value into it — the two-step that makes Insert refuse duplicates while operator[] overwrites.
