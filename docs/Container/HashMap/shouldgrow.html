ShouldGrow

member of hbe::HashMap Engine/Container/HashMap.h cap == 0, or count + tombstones at the 0.7 load factor

Signature

[[nodiscard]] bool ShouldGrow() const noexcept

Function description

Private. The load-factor decision every insertion runs first: cap == 0 — nothing allocated yet, grow now — or count + tombstoneCount >= cap * MaxLoadFactor, with MaxLoadFactor = 0.7 from the class's own constant. The arithmetic is done in double, explicitly cast on both sides, so the comparison is not silently integer-truncated.

Tombstones count toward the load: a map that has had many removals grows even when Size is small, because the dead slots still lengthen every probe sequence. Only Clear or Rehash clears that debt.

Parameters

None.

Return value

true when the next InsertInternal must Grow first — the empty table, or the load factor reached. [[nodiscard]], so discarding the answer is a compile error.

Examples

Illustrative — private, and reachable only through InsertInternal.

if (ShouldGrow())
{
	Grow();
}

That is InsertInternal's opening move — the guard that keeps the fatal "should have grown" branch unreachable.
