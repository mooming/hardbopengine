operator=

member of hbe::HashMap Engine/Container/HashMap.h copy deleted; move releases the destination, then takes everything including the hashing policy

Signature

HashMap& operator=(const HashMap&) = delete

HashMap& operator=(HashMap&& rhs) noexcept

Function description

Two forms, one of them a refusal. Copy assignment is = delete; a hash map is move-only. The move form is noexcept and guarded against self-assignment — assigning a map to itself changes nothing.

For a genuine move, the destination first Releases itself — its own pairs destroyed, its own buffer returned through its own allocator — then takes every field including the moved hash and keyEqual, and zeroes the source. The class page records the consequence worth knowing: the adopted buffer was allocated by the source's allocator but will be freed by the destination's, so those two must be interchangeable — which for the default DefaultAllocator they are.

The source ends truly empty: null pointers, zero counters. Nothing of the destination's former state survives anywhere.

Parameters

ParameterTypeRequirement
rhsHashMap&& The source map. Its table, counters and hashing policy are taken; it is left null and empty.

Return value

*this, holding the source's former table and entries.

		m3 = std::move(m2);
