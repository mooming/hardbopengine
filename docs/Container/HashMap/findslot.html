FindSlot

member of hbe::HashMap Engine/Container/HashMap.h the linear probe everything is built on — stops at Empty, steps over Tombstone

Signature

TIndex FindSlot(const TKey& key) const noexcept

Function description

Private. The probe sequence everything else is built on: hash the key, mask with cap - 1, then walk forward — linear probing — until one of three things happens. An Occupied slot whose key equals the request (by TKeyEqual) returns its index. An Empty slot returns -1 at once, because nothing past an empty slot can hold the key. A Tombstone is stepped over and the walk continues — a removed key must not end the search early, or entries probed past it would become unreachable.

The walk is bounded by cap probes, so a full table of non-matching slots answers -1 rather than looping forever. It never allocates and never mutates, which is what makes Contains and the const Find possible on a const map.

Parameters

ParameterTypeRequirement
keyconst TKey& The key to locate. THash and TKeyEqual must agree with how the entries were inserted.

Return value

TypeWhat you get
TIndex (int) The slot index of the matching Occupied entry, or -1 when the key is absent — including when its slot is a tombstone

Examples

Illustrative — private, and reachable only through the lookups it serves.

auto idx = FindSlot(key);
if (idx >= 0 && states[idx] == EHashEntryState::Occupied)
{
	return entries[idx].value;
}

That shape opens operator[], Insert and Remove alike: locate, then check the state before trusting the slot.
