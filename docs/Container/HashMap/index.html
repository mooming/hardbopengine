HashMap

Engine/Container/HashMap.h namespace hbe template <typename TKey, typename TValue, class THash = std::hash<TKey>, class TKeyEqual = std::equal_to<TKey>, class TAllocator = DefaultAllocator<uint8_t>> final open-addressed map with linear probing and tombstones, in one byte-typed allocation

Class description

HashMap keeps two parallel arrays in a single allocation: entries, an array of Pair, and states, an array of EHashEntryState — Empty, Occupied or Tombstone per slot — the enum is described under Non-member helper functions, where the header actually puts it. The allocation is requested as a byte count from a DefaultAllocator<uint8_t> and then carved up by pointer arithmetic, which is why the allocator parameter on this container is a byte allocator where the other containers take an element allocator.

A lookup hashes to hash(key) & (cap - 1) and probes forward, one slot at a time, stopping at the first Empty slot as proof of absence. Capacity is therefore required to be a power of two and is always one: Reserve doubles up to it, and the internal growth starts at MinCapacity = 4 and doubles from there. The growth point is count + tombstoneCount >= cap * MaxLoadFactor with MaxLoadFactor = 0.7.

Deletion is a tombstone write rather than a blank, because blanking a slot in the middle of a probe chain makes everything that probed past it unfindable — Remove carries the consequence: tombstones are charged against the load factor, so a churn workload grows this table permanently.

The two iterator types are real classes rather than pointer aliases as in Vector: each holds the map and a slot index and skips non-occupied slots on operator++. That is what lets iteration walk over the gaps, and it makes Iterator and ConstIterator distinct types — unlike Map, where ConstIterator is a using for Iterator.

Copies are deleted; the move constructor and move assignment take every field including hash and keyEqual — and not the allocator, which is the hole described in the row for operator= below.

Template parameters

ParameterKindWhat it must satisfy
TKey typename Copy-constructible for the Insert overloads that take a const key, move-constructible for the one that takes an rvalue, and it is stored inside the slot, so a key whose hash changes while it is in the map cannot be found, removed or overwritten. The default hasher and equality are std::hash<TKey> and std::equal_to<TKey>, so any type those are not specialised for needs the next two parameters
TValue typename Default-constructible and assignable, not merely constructible from something: the slot is built as Pair{key, TValue{}} and the caller's value is assigned into it afterwards, and operator[] hands back a default-constructed value for a key it had to create. Move-constructible as well, because a rehash moves every pair into the new table
THash class, defaults to std::hash<TKey> Callable as hash(key) returning an integral value — the result is masked with static_cast<std::size_t>(cap - 1) and then narrowed to int for the slot index, so a hasher returning a non-integral type does not compile and one returning values above INT_MAX in the low bits is masked before the narrowing anyway. Held by value and copied on move, so a stateful hasher (seeded, counting) keeps working; only its address changes
TKeyEqual class, defaults to std::equal_to<TKey> Callable as keyEqual(stored_key, sought_key) returning something testable — the stored key is the first argument, so an asymmetric comparator reads backwards if you assume the other order. It is consulted only on a hash collision in the same probe sequence; two keys that hash identically and compare unequal sit in consecutive slots
TAllocator class, defaults to DefaultAllocator<uint8_t> Anything with allocate(count) and deallocate(pointer, count) — and here count is a byte total, because the value type is uint8_t: the container computes sizeof(Pair) * cap + sizeof(EHashEntryState) * cap itself. The returned address is then reinterpret_cast to Pair*, so this container has no alignment guarantee beyond what the allocator gives a byte buffer; a Pair with a wide alignment requirement is a portability question, not a compile error. Never exchanged by a move, so a moved map frees its adopted buffer with the allocator it default-constructed

Non-member helper functions

None. The header does declare one more thing at namespace scope: enum class EHashEntryState : uint8_t { Empty, Occupied, Tombstone }, the state byte this map probes against. It is not a member of the class and a caller cannot pass it to anything — every operation that touches it is private — so it is documented in this class page rather than as an entry of its own, and the module page's Coverage records that choice.

Probing quality The header implements linear probing, which clusters on collision. How badly a given key set behaves is a measurement, not a header fact, and nothing here claims a number beyond the 0.7 growth point the code states
Allocator and assert contracts DefaultAllocator<uint8_t>'s behaviour belongs to Memory. Nothing in this class asserts on a failed allocation — there is no assert on the growth path at all; the asserts that do exist, in Iterator::operator++ and operator*, are FatalAssert, documented in Core: Debug
