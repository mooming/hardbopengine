PushBack

member of hbe::Vector Engine/Container/Vector.h 2 overloads noexcept append one element, growing the buffer by doubling when the current one is full

Signature

void PushBack(const TElement& value) noexcept;
void PushBack(TElement&& value) noexcept;

Function description

If count == capacity the private Grow runs first, which calls Reserve with max(DefaultCapacity, capacity * 2) — so the first buffer is 4 elements and each later one is double the previous. The element is then constructed into data[count] by copy or by move according to which overload matched, and count is incremented.

Amortised constant time, with the cost concentrated in the growth: appending n elements to an empty vector allocates on the log₂ n doublings and moves every live element on each of them. Stating a capacity first with Reserve or the sized constructor removes that entirely.

Both overloads return void, so the element you added is not handed back; reach it as Size() - 1 through operator[], or through Back(). EmplaceBack is the sibling that returns a reference, and it is the one to use when the caller needs the address of what it just created.

A push that crosses the capacity boundary invalidates every pointer, reference and iterator into the vector — including to elements you did not touch. They were moved, not copied, so their values survived and their addresses did not. Below the boundary nothing is reallocated and existing addresses stay good, which is the asymmetry that produces the intermittent bug: the same code is correct at size 3 and wrong at size 4. If addresses must hold, reserve up front or store indices instead of pointers — and note that std::find over a vector you then push to has exactly this shape.
A growth failure is not reported, because nothing checks for one. The growth path is Reserve, which uses the allocator's return value without testing it. A failed allocation therefore does not turn into a declined append: it turns into writes through a null or wrong buffer. Both overloads are noexcept as well, so a copy or move constructor that throws terminates the process instead of unwinding the append.

Parameters

ParameterTypeRequirement
value const TElement& Copy-constructible TElement. The copy is made into the vector's buffer; the argument is untouched
value TElement&& Move-constructible TElement. Chosen by an rvalue, including the result of std::move. Caution: if the argument is a reference into this same vector and the push triggers a growth, the reallocation happens before the move — the source has already been destroyed. This is why v.PushBack(std::move(v.Back())); is a use-after-free rather than a duplicate

Return value

void on both overloads. There is no status, no reference to the new element and no signal when a growth was needed; Capacity before and after is the only way to see one happen.

Examples

Illustrative — no call site for this exists in the repository; see the note on the constructors.

hbe::Vector<Light> lights;

for (const auto& source : sceneLights)
{
        lights.PushBack(source);             // const overload: copy-construct
}

lights.PushBack(Light{"flare", 1.f});      // rvalue overload: move-construct
const auto appended = lights.Size() - 1;  // PushBack returned nothing, so locate it
lights[appended].intensity = 4.f;

The nearest real use of this method name in the module is on a different container — fifoQueue.PushBack(task); in Engine/Core/TaskStream.cpp, where fifoQueue is Deque<RangedTask>. Same append-and-grow shape, different invalidation rules.
