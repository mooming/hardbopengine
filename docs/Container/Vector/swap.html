Swap

member of hbe::Vector Engine/Container/Vector.h noexcept three std::swap calls over count, capacity and the pointer — the only way this container gives memory back early

Signature

void Swap(Vector& rhs) noexcept;

Function description

std::swap is applied to count, to capacity and to data. No element is constructed, moved or destroyed, so the operation is constant time, allocation-free and noexcept. Afterwards each vector holds the other's buffer, element count and capacity.

The parameter is a plain lvalue reference, so two named vectors swap directly — a.Swap(b); compiles here. Contrast Array::Swap, whose parameter is Array&& and which therefore requires std::move on the argument. Same intent, two spellings inside one module — the kind of divergence that makes a copied call site fail to compile rather than fail to work.

There is no self-swap guard and none is needed: swapping a field with itself leaves it equal. Swapping with a vector of a different capacity is normal and costs nothing — that is the idiom this function is most useful for, since a vector never releases capacity by itself (see Resize).

The allocator is not swapped, so each side frees the buffer it adopted with the allocator it already had. allocator is not in the list of exchanged fields, and DefaultAllocator carries the allocator id captured when it was constructed — so a vector built inside one memory scope and swapped with one built inside another ends up releasing memory into a scope that did not allocate it. With one allocator scope in play (the common case, and every configuration the engine actually builds) this costs nothing and changes nothing; with a pool adapter it is a cross-pool free. The same property makes the move constructor and move assignment allocator-blind. See Memory: allocators.
Iterators keep their addresses and change their owner. A pointer into a swapped buffer still points at the same bytes and the same live object, but those bytes are now elements of the other vector, addressed by its count. Nothing is invalidated by Swap in the memory sense — a range iterated across a swap simply stops belonging to the vector you are asking about.

Parameters

ParameterTypeRequirement
rhs Vector& A modifiable vector of the same TElement and TAllocator types; a named lvalue is fine. After the call it holds this vector's former buffer, count and capacity — it is not emptied unless it started empty, which is what makes the release pattern below work

Return value

void. Nothing can fail and nothing is reported: four swaps and no allocation, so there is no status to check and no state that can come out wrong.

Examples

Illustrative — no call site for this exists in the repository; see the note on the constructors.

Release a buffer while keeping the vector — the shrink-to-fit this class does not provide otherwise:

{
        hbe::Vector<Light> empty;        // no buffer, no capacity
        lights.Swap(empty);          // lights: Size() == 0, Capacity() == 0
}                                     // `empty` is destroyed here and releases the buffer

Exchange contents without touching an element:

current.Swap(next);                  // O(1); no element constructed, moved or destroyed
current.Swap(current);               // legal, and a no-op
