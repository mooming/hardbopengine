Vector

Engine/Container/Vector.h namespace hbe template <typename TElement, class TAllocator = DefaultAllocator<TElement>> final a growing array with a capacity of its own — append freely, and the buffer doubles when it fills

Class description

Vector stores count elements in a buffer of capacity elements and grows that buffer itself: whenever an append finds count == capacity, the private Grow requests max(DefaultCapacity, capacity * 2) from Reserve, so the first allocation is 4 elements and every later one is double. That is the whole difference from its sibling Array, which keeps one number for both and reallocates whenever you change the size. Append-heavy code wants this one; code with a size someone decided wants Array.

Capacity is visible and separately controllable — Capacity(), Reserve, and a shrinking Resize that leaves the buffer standing. A vector can therefore be given its working set once and then pushed to without a single further allocation, which is the only way its address stability can be relied on.

Copy construction and copy assignment are deleted; the move constructor steals three fields and zeroes the source. The class is final, so no derived container can turn its destructor into a slicing bug.

Two facts a caller cannot see from the type. Every growth moves all the elements, so pointers, references and iterators into a vector are valid only until the append that crosses the capacity boundary — see PushBack. And no path in this class checks the allocator's return value: a failed allocation is not a declined append or a failed resize, it is a null buffer behind a plausible Capacity(). That is a deliberate difference from Array, and the reason which allocator you bind is a decision here.

Template parameters

ParameterKindWhat it must satisfy
TElement typename The stored type. Move-constructible — every reallocation moves each element, and the moves happen inside a noexcept function, so a throwing move constructor terminates rather than unwinding. Default-constructible if the vector is ever grown with Resize or EmplaceBack() with no arguments. Copy-constructible for PushBack with an lvalue and for the std::initializer_list constructor. No assignment, comparison or hash is required by anything here — FindIndex is the one member that asks for operator==
TAllocator class, defaults to DefaultAllocator<TElement> Anything with allocate(count) returning TElement* and deallocate(pointer, count), where count is in elements of the allocator's own value type — DefaultAllocator<T>::allocate multiplies it by sizeof(T), which is why this container can pass a bare element count while HashMap passes a byte count against DefaultAllocator<uint8_t>. Held by value, so it is copied in and must outlive the vector. Nothing in this class ever exchanges it: neither Swap nor either move operation touches it

Class properties

To bind a vector to a named pool you have to give it a pool-holding TAllocator type that is default-constructible, which is the constraint that decides which allocators can be used here at all
count TIndex count; private Live elements; what Size() returns and what IsValidIndex compares against
capacity TIndex capacity; private Slots allocated. The gap between it and count is the number of appends that will not reallocate, and deallocate is called with this value, not with the count
data TElement* data; private The buffer, or nullptr before the first allocation. Data() hands it out; the destructor returns it to the allocator with capacity as its count argument
