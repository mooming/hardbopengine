EmplaceBack

member of hbe::Vector Engine/Container/Vector.h noexcept build the element inside the buffer from its constructor arguments, and get a reference to it back

Signature

template<typename... Types>
TElement& EmplaceBack(Types&&... args) noexcept;

Function description

Grows the buffer first if count == capacity, exactly as PushBack does, then constructs TElement(std::forward<Types>(args)...) in the slot at data[count], increments count and returns a reference to the new object. Nothing is copied or moved into place: the arguments go straight into the element's own constructor, so a type with no available copy or move — or one whose copy you would rather not pay for — is appendable here and nowhere else in this class.

The distinction from Array::Emplace matters, because the names are the same and the operations are not. Array::Emplace(index, ...) requires a slot that already exists, destroys whatever is in it and changes no size; EmplaceBack adds a slot, changes the size and may reallocate. Both leave the element at a stable address — one because nothing moved, the other because it was constructed after any move had already finished.

The reference returned points into the vector's buffer, so it is good until the next growth, Resize, Clear or destruction. It is not [[nodiscard]]; ignoring it is normal.

An argument that refers into this vector is read after the reallocation that destroys it. The arguments are references bound at the call, but the growth runs before the constructor does. So v.EmplaceBack(v.Back()); or v.EmplaceBack(v[0].name); is sound while there is spare capacity and a use-after-free the moment the push crosses the capacity boundary — the version that passes a test with three elements and corrupts memory with four. Copy the argument to a local first, or reserve enough room that no growth can happen.
The same two hazards the append path always carries. A growth moves every live element, so all other pointers, references and iterators into the vector die here even though their values survived; and the growth goes through Reserve, which does not test the allocator's return value, so an allocation failure is not reported as anything. noexcept means a throwing constructor terminates rather than unwinding.

Parameters

ParameterTypeRequirement
args Types... Zero or more arguments forming a valid TElement constructor call. Empty is legal and value-initialises the new element — the same result as Resize(Size() + 1), with a reference handed back

Return value

TypeWhat you get
TElement& The element just constructed, in the vector's buffer. Mutable even when the arguments were all const, because it is a fresh object rather than a copy of one — which is the point: fill it in through the reference instead of constructing a temporary and appending it. Valid until the next operation that reallocates

Examples

Illustrative — no call site for this exists in the repository; see the note on the constructors.

hbe::Vector<Light> lights;
lights.Reserve(64);                          // buy the room first, then the reference is stable

auto& flare = lights.EmplaceBack("flare");   // Light("flare") built in place
flare.intensity = 4.f;                       // written through the returned reference

auto& fill = lights.EmplaceBack();           // value-initialised element, slot 1
fill = flare;                                // both are elements of the same buffer

The first line is the whole discipline this page teaches: the reference returned is only as durable as the buffer it lives in, and a Reserve is what makes "hold the reference" a statement that stays true.
