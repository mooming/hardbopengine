GetNodeOf

member of hbe::LinkedList Engine/Container/LinkedList.h recover the node from the element's address — the same address, asserted first

Signature

Node* GetNodeOf(TType& element) noexcept

Private — reachable only through the class's own removal and insertion paths, documented here because the address-to-node cast is the module's most surprising trick.

Function description

Recovers the list node from an element the list owns, in one line: 

Assert(ContainsElement(element));

return reinterpret_cast<Node*>(&element);

From Engine/Container/LinkedList.h, LinkedList::GetNodeOf(TType&)

It works because the node's first member is the element — a LinkedListNode lays out value before the two link pointers — so the element's address and its node's address are the same address. The ContainsElement assert is what makes the cast sound: for any TType object the list did not allocate, &element is somebody else's memory wearing a node's clothes, and dereferencing it would read the bytes behind it as link pointers.

Remove, AddPrevious and AddNext all route their element arguments through here — that is why those methods take non-const references and why the contract says the element must be one the list owns.

Parameters

ParameterTypeRequirement
elementTType& An element this list allocated — asserted, not assumed. A foreign object fails the assert in a checked build.

Return value

The node holding the element — its previous and next links are the list's to rewire.

Examples

Illustrative — private, and reachable only through the element-taking members.

return Iterator(RemoveNode(GetNodeOf(element)));

That is Remove's body: reference in, node recovered, node removed, iterator to the survivor out.
