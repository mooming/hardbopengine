ContainsElement

member of hbe::LinkedList Engine/Container/LinkedList.h the identity test — is this exact object one of this list's own nodes?

Signature

[[nodiscard]] bool ContainsElement(const TType& element) const noexcept

Private — reachable only through the class's own removal and insertion paths, documented here because it owns the ownership rule they enforce.

Function description

The identity test: Contains(&element) — is this exact object the payload of one of this list's own nodes? It is the precondition GetNodeOf asserts before recovering a node from an element's address, which is only meaningful for an element this list actually allocated. Value equality — Contains(const TType&)'s question — is deliberately not sufficient here: two equal elements in different nodes are different nodes, and recovering "the node of" the wrong one would splice the wrong link.

The non-const reference parameters of Remove, AddPrevious and AddNext are what make this check hard to bypass: a temporary cannot bind, so the assert is a backstop rather than the only line of defence.

Parameters

ParameterTypeRequirement
elementconst TType& A candidate element; only its address is read.

Return value

true when the element's address matches one of this list's nodes, false otherwise. [[nodiscard]], so discarding the answer is a compile error.
