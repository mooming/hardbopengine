IsEmpty

member of hbe::LinkedList Engine/Container/LinkedList.h head == nullptr — and there is no Size beside it

Signature

[[nodiscard]] bool IsEmpty() const noexcept

Function description

head == nullptr — after an invariant assert that a null head implies a null tail. There is no Size() beside it: a linked list that counted its length would have to walk, so the class offers only the emptiness question and lets everything else be an iteration.

The private insertion helpers lean on this test to recognise the first element — an empty list takes the new node as both head and tail at once — so the state it reports is load-bearing, not cosmetic.

Parameters

None.

Return value

true when the list holds no nodes, false otherwise. [[nodiscard]], so discarding the answer is a compile error.

Examples

		intList.Clear();

		if (!intList.IsEmpty())

From Engine/Container/LinkedList.cpp, LinkedListTest::Prepare()

That test's name is the point — "Clear leaves no tail behind": after a Clear, both pointers must be null, and this is the check that catches a stale tail.
