member of hbe::LinkedList Engine/Container/LinkedList.h two nulls and an allocator — no allocation, no copy, a stealing move

Signature

LinkedList(const LinkedList&) = delete

LinkedList() noexcept
		: head(nullptr)
		, tail(nullptr)

LinkedList(LinkedList&& rhs) noexcept
		: head(rhs.head)
		, tail(rhs.tail)

Function description

Three forms, one of them a refusal. The default constructor sets head and tail to nullptr and allocates nothing — an empty LinkedList is two nulls and an allocator, the cheapest state in the module. Copy construction is = delete.

The move constructor steals the two pointers and zeroes the source — the chain changes owner with no node touched. The allocator member is not moved: each list keeps its own, so the nodes a moved-away list once allocated are freed, eventually, by whichever list holds them now, through that list's allocator.

Parameters

None. There is no sizing form — a list's shape is decided by its insertions, not its construction — and no allocator argument; the allocator arrives as a template parameter.

Return value

A constructor has no return value. What you can observe afterwards is IsEmpty (true) and begin == end.
