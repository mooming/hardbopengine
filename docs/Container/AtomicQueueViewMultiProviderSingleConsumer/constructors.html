Function description

One constructor, and it takes nothing: both fields start nullptr, which is a complete and usable empty queue. There is no capacity to size, no buffer to reserve and no allocator to talk to — an instance is two machine words (measured: sizeof 16, alignof 8), so a queue can be a member of another object, a static, or a file-scope global without any allocation happening anywhere. That is the same zero-footprint property that makes this class usable on the paths where a lock would cost more than the queue saves.

A second, deleted constructor refuses copies, and its reasoning is the same as the deleted assignment below: an object that names someone else's producer stack is not a second queue but a second name for one, with no rule about which name may pop from it.

Moving is impossible, and the header never says so. No move constructor or move assignment is declared, and the implicit ones are removed by the compiler because std::atomic is neither copyable nor movable — verified on this toolchain, not inferred: is_copy_constructible, is_copy_assignable, is_move_constructible and is_move_assignable all report false for AtomicQueueViewMPSC<Node>. The effect is correct (a queue mid-flight cannot be relocated while producers hold pointers into it) but it is an inference a caller has to discover at the call site, because only the copy half is spelled out. AtomicStackView is in exactly the same position, so the two lock-free classes of this module share the flaw rather than one of them being out of line.

Parameters

None. The deleted copy constructor takes a const reference to another queue and is not a usable route to an object — see the Signature above for both declarations as the header writes them.

Return value

Construction has no return value; it cannot fail and cannot throw, and the object it leaves behind is an empty queue on which every operation of the class is immediately legal.
