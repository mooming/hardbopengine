IsEmpty

member of hbe::AtomicQueueViewMultiProviderSingleConsumer Engine/Container/AtomicQueueViewMultiProviderSingleConsumer.h true only when both the producer stack and the consumer's private list hold nothing

Signature

[[nodiscard]] bool IsEmpty() const noexcept

Function description

One expression over both halves of the state: oldest == nullptr && newest.load(relaxed) == nullptr. The second half is a relaxed load of an atomic; the first is a plain read of the consumer's own list. It is the only operation besides Pop that can see a node sitting in the private list, and that is the whole reason it has to read two fields.

Reading only the producer stack is the tempting wrong version, and it is wrong in the direction that loses work: a Pop that refills has already removed the entire producer stack from newest, so a queue still holding two unreleased nodes answers "empty" to a test that looks at one field. The testlet IsEmpty Covers the Stolen Batch as Well as the Producer Stack exists to keep that from being reintroduced quietly, and it was checked against exactly that defect: with the single-field test restored, the testlet fails with that sentence as its report.

The consumer thread only, for the same reason Pop is. The oldest half of this read is unguarded. Any thread other than the consumer calling this is a data race, and a producer calling it would in any case be asking a question that has no stable answer — by the time the call returns, the consumer may have taken everything the call just saw.
True is stronger than false. A true means both halves were empty at the instant the two reads were performed, and since only a producer can add, a subsequent Push can still arrive — so it is a statement about a moment, not a licence to destroy the queue on the assumption that nothing is in flight. false only says at least one half held something, which under contention may be one node that is already on its way out. Neither answer is a count: the class deliberately offers none, because counting a live lock-free chain means a walk that can change underneath it.

Parameters

None.

Return value

TypeMeaning
bool true when neither the producer stack nor the consumer's private list held a node when both were read; false when either did
