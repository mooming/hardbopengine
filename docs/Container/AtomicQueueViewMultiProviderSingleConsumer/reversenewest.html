ReverseNewest

member of hbe::AtomicQueueViewMultiProviderSingleConsumer Engine/Container/AtomicQueueViewMultiProviderSingleConsumer.h claim the entire producer stack with one exchange and reverse it into hand-out order

Signature

T* ReverseNewest() noexcept

Function description

The step that turns a stack into a queue, in two moves. First newest.exchange(nullptr, std::memory_order_acquire) detaches the producer stack wholesale: the caller gets the most recently pushed node and every node linked behind it, and leaves the atomic holding nullptr. Then a plain three-pointer walk reverses the chain, so the node that was pushed first ends up at the front and is what the walk returns. There are no atomics in the walk and no compare-and-swap in it, because exactly one thread ever runs it.

An exchange rather than a compare-and-swap, and the choice is the reason the queue has no ABA exposure: detaching is one instruction, so there is no window in which a value is read, examined, and then conditionally written — the only pattern that lets a stale pointer slip back in. A producer whose push was in flight against the old head simply finds its compare-and-swap failed, re-reads the head (now nullptr), and retries against an empty stack. Its node was never linked into the chain that got taken, so nothing has to be undone.

The acquire ordering is what makes the stolen nodes' contents visible: each producer published its node with a release compare-and-swap, and this acquire load synchronises with the ones whose links it now walks. Everything the caller wrote into a node before pushing it is readable after this returns.

Cost, stated honestly. This function's work is proportional to the number of nodes the producers had accumulated since the last refill — one read and two writes per node, each node visited exactly once in its lifetime. Amortised across a drain that is one pass per node; concentrated on one call, it is the reason a single Pop can be slower than the ones that follow it. A caller with a latency budget on the consume side should count this pass against it.
Private, and legal only under the single-consumer rule. The walk reads and writes next fields of nodes that producers may concurrently be pushing away from — a producer writes the link field of the node it is pushing, never of a node already in the chain, which is what keeps the two sets of writes disjoint. Two threads running this function on the same queue would both be rewriting the same chain, and no atomic protects them from each other.

Parameters

None.

Return value

TypeMeaning
T* The oldest node of the batch that was just detached, linked forward through the batch in push order and consumed from here on by Pop alone. nullptr when the producer stack was already empty, which is the common answer from a queue that has nothing to hand out

Examples

The function in full — Engine/Container/AtomicQueueViewMultiProviderSingleConsumer.h. Shown because its length is the argument for the design: seven lines of pointer work, no CAS loop, no reclamation.

T* ReverseNewest() noexcept
{
        auto* node = newest.exchange(nullptr, std::memory_order_acquire);
        T* reversed = nullptr;

        while (node != nullptr)
        {
                auto* next = node->next;
                node->next = reversed;
                reversed = node;
                node = next;
        }

        return reversed;
}
