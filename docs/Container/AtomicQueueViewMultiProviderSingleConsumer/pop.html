Pop

member of hbe::AtomicQueueViewMultiProviderSingleConsumer Engine/Container/AtomicQueueViewMultiProviderSingleConsumer.h take the oldest node a refill can reach from the one consumer thread, and own it completely afterwards

Signature

T* Pop() noexcept

Function description

Three steps, and only the middle one is interesting. If the consumer's private list is empty the call first calls ReverseNewest, which claims everything the producers had accumulated and returns it in hand-out order; if that yields nothing the call returns nullptr. Otherwise it detaches the head of oldest, advances oldest to the node behind it, clears the detached node's next, and returns the node. No compare-and-swap appears anywhere on this path — the consumer never races, because there is only one of it.

The branch that refills is marked unlikely, which is the shape of a drain loop rather than a guess about a particular workload: refilling happens once per burst, and every subsequent pop in that burst reads the private list plain. The cost of the marked branch is proportional to the burst it reclaimed, so a single call can take longer than the hundred that follow it — see the class description for the amortisation argument.

Clearing next before returning is not tidiness. A node that comes back out of this queue arrives with no link into a chain the caller cannot see, so the caller can hold it, overwrite it, or push it back in without inheriting a stale pointer. The testlets assert this on every pop, not just once.

One consumer thread, and the compiler will not tell you if you forget. oldest is a plain T*, and the reason it is not atomic is the single-consumer rule itself. Two threads calling Pop race on that pointer and will hand the same node to both of them while corrupting the list behind them — there is no assert and no diagnostic, because an assert costs an atomic and the whole point of the class is that this half of the algorithm needs none. The rule is what makes ReverseNewest legal to write with ordinary assignments, so it is load-bearing rather than advisory.
What a null return means, and what it does not. It means the queue held nothing reclaimable at that instant: the private list was empty and the producer stack was empty when it was claimed. It does not mean no node is coming — a push that had not yet won its compare-and-swap simply had not enqueued anything yet. Nothing can be stranded by an early null, because a node becomes visible to a refill in the same instruction that enqueues it, so the next refill sees it; the stress testlets terminate on a counted total rather than on the first null, which is the correct drain shape for any queue whose producers are still running. A drain loop that stops at the first null is stopping on an instant, not on an empty queue.
The node is yours, entirely, the moment it comes back. No thread inside the queue will touch it again — see Push for why that is true here and would not be true of a queue that links by writing the previous node's field. Destroy it, reuse it, or hand it to another structure; the only obligation left is the ordinary one that the object's own lifetime rules impose.

Parameters

None.

Return value

TypeMeaning
T* The node that has been in the queue longest among the ones a refill could reach, its next cleared, now owned by the caller. nullptr means nothing was reclaimable at that instant — not an error, and not a promise that the queue is still empty a moment later

const bool allReturned = WaitUntil([&]()
{
        for (int spin = 0; spin < 512 && returned < nodeCount; ++spin)
        {
                auto* node = queue.Pop();

                if (node == nullptr)
                {
                        std::this_thread::yield();

                        continue;
                }

                node->next = nullptr;
                node->token = round;

                std::this_thread::yield();

                if (node->token != round)
                {
                        ++clobbered;
                }

                node->token = -1;
                ++returned;
                ++handedBack;

From Engine/Container/AtomicQueueViewMultiProviderSingleConsumer.cpp, the "A Popped Node Belongs to Its Owner and to No One Else" testlet

Two habits in that loop are the ones a caller of this class should copy. The drain is bounded by a deadline through WaitUntil, so a lost node becomes a reported failure instead of a hung test, and the node is written to after it has been popped and then checked — a producer that could still reach a handed-back node would show up as a corrupted token rather than as a theory.
