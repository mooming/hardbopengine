RetireBlock

member of hbe::AtomicRingQueueMultiProviderSingleConsumer Engine/Container/AtomicRingQueueMultiProviderSingleConsumer.h recycle a drained block unless a producer is still standing inside it

Signature

void RetireBlock(LinkNode* inBlock, LinkNode* inSuccessor) noexcept

Function description

Recycles the block the consumer has just finished with: fully claimed, fully drained, and no longer the head, so no element can still be waiting inside it.

It does two things in one critical section, and their order is the whole correctness argument. First it compares-and-swaps tail from this block to its successor, so from that instant no producer can acquire the block afresh — tail only ever moves forward. Then it scans the producer slots for a thread still declaring this block, and frees it or defers it accordingly. Reversing those two steps is not a detail: retiring a block that tail still names leaves producers reaching into freed memory, which is exactly the defect this order was introduced to close.

A deferred block goes on deferredBlocks and is retried by RetryDeferredBlocks on the next advance and on every attempt to grow. The scan is at most inMaxProducers words, on a path taken once per block.

Parameters

NameWhat the caller must supply
LinkNode* inBlock The block the consumer just left. Called by the consumer only, with the cursor already moved off it.
LinkNode* inSuccessor The block inBlock links to, which becomes the new tail if tail still names the block being retired. It must not be null: a block with no successor is never retired.

Return value

Nothing. Whether the block was freed is visible as GetRetireCount and as the live-block count the fuse enforces.
