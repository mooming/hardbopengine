Push

member of hbe::AtomicRingQueueMultiProviderSingleConsumer Engine/Container/AtomicRingQueueMultiProviderSingleConsumer.h copy a value onto the tail block from any thread, with one compare-and-swap and no lock on the hot path

Signature

[[nodiscard]] EPushResult Push(const T& inItem) noexcept

Function description

Enqueues a copy of inItem. Any thread may call it and any number of them at once; the only thread that must not is the one consumer, and only because it has Pop instead.

The hot path is one atomic compare-and-swap on the tail block's claim counter, a placement copy into the slot that counter just handed over, and one release store to that slot's tag. Nothing is locked, nothing is allocated, and no other producer's progress is required.

Before the block is touched it is declared: the thread stores the block's address into its own producer slot, then reads tail once more and restarts if it has moved. Those two sequential-consistency reads around one store are what make it safe for the consumer to recycle blocks at all — a block cannot be freed while a slot declares it, and a producer cannot be left holding a block that was freed before it declared one. The slot is cleared after the tag is published.

A block holds BlockSlots slots; filling one moves the thread to the next. Extending the chain takes the management mutex, so the locking cost is at most one acquisition per BlockSlots elements, and only on the thread that happens to arrive at a full tail. The queue can refuse: see the return values.

Parameters

NameWhat the caller must supply
const T& inItem The value to store. It is copied into the queue's own storage by the copy constructor, which runs after the slot is claimed and before the slot is published — a copy constructor that blocks delays publication of that slot and nothing else.

Return value

ValueWhen it comes back
EPushResult::PushedThe copy is in a slot and visible to the consumer.
EPushResult::FullThe chain already holds maxBlocks live blocks, so growing would exceed the fuse. Nothing was written. Retry later, after the consumer has drained and recycled a block.
EPushResult::TooManyProducersEvery hazard slot is claimed, so this thread cannot be tracked and was refused rather than left untracked. Raise inMaxProducers at construction.

Examples

Illustrative — no call site for this exists in the repository.

for (Task* task = dequeueWork(); task != nullptr; task = task->next)
{
        if (queue.Push(*task) != TaskQueue::EPushResult::Pushed)
        {
                break;
        }
}
