Function description

Builds an empty queue that has requested no memory for elements yet: blocks are created on demand by the first producer that needs one. The constructor does allocate two things — the producer slot array, inMaxProducers cache lines, because a producer's slot has to exist before that producer is allowed to declare a block, and the deferred-block vector's capacity, so that deferring a recycle never allocates at runtime.

It also settles where the queue's memory is charged. The allocator member is default-constructed, which for DefaultAllocator means capturing the calling thread's allocator id at this moment, and the deferred list rebinds its own allocator from that member. Every block, the producer slot array and the deferred buffer are therefore charged to the context that created the queue, whichever thread happens to grow the chain, and reported under one node of the allocator tree - with no allocator id stored by the queue and no AllocatorScope at the call sites, because DefaultAllocator opens the scope itself.

The queue owns its blocks and its elements and holds thread-affine state, so copying is deleted and moving is not offered: std::mutex and std::atomic members make a moved-from queue meaningless.

Parameters

NameWhat the caller must supply
size_t inMaxBlocks The fuse: how many blocks may be live at once. Live capacity is therefore inMaxBlocks × BlockSlots elements. A drained block still counts against the fuse until the consumer advances past it, so a producer that fills the queue with no consumer running stops at exactly this many slots.
size_t inMaxProducers How many distinct producer threads may push. One slot each. Passing 0 leaves the queue unpushable, which AcquireProducerToken asserts on.

Return value

Nothing. A queue whose hazard array could not be allocated is not marked invalid — it simply refuses every push with EPushResult::TooManyProducers, and the allocation failure is already logged by the allocator.
