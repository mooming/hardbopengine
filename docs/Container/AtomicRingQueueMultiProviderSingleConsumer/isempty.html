IsEmpty

member of hbe::AtomicRingQueueMultiProviderSingleConsumer Engine/Container/AtomicRingQueueMultiProviderSingleConsumer.h decide emptiness from the claim counter and the consumer cursor together, from the consumer thread

Signature

[[nodiscard]] bool IsEmpty() const noexcept

Function description

Reports whether the consumer has nothing left to take. Evaluate it from the consumer thread, like Pop: it reads the consumer's own non-atomic cursor.

Two words decide it, and one word is not enough. claim on the head block counts slots that producers have committed to, and the cursor counts slots the consumer has finished with; the queue is empty only once the cursor has caught up with every claim and the head block is still the last block of the chain. Reading claim alone would call a drained queue non-empty forever after its first push, and reading the cursor alone would call a queue with a claim in flight empty, which is how an element that is already committed gets dropped on the floor.

The answer is a snapshot, not a promise: a producer can push the instant after it returns true. It is a drain condition and a shutdown condition, not a lock.

Parameters

NameWhat the caller must supply
noneThis method takes no argument.

Return value

true when the consumer's cursor has passed every claim on the head block and that block is still the tail of the chain, including the case where the queue has never been pushed to at all. false otherwise, including the blocked case, where an element is committed but not yet published — a queue can report non-empty while Pop returns EPopResult::Blocked and is right to do so.
