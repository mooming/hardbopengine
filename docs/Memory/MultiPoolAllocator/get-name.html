GetName

member of hbe::MultiPoolAllocator Engine/Memory/MultiPoolAllocator.h A copy of the name the allocator was constructed with - log category and cache key at once.

Signature

[[nodiscard]] auto GetName() const

Function description

Returns the name the instance was constructed with. The body is one line and lives in the header: 

		return name;

From Engine/Memory/MultiPoolAllocator.h, MultiPoolAllocator::GetName()

auto deduces by value, so the return is a copy of the StaticString member rather than a reference into the allocator. A caller may keep it past the allocator's lifetime, which is what makes it usable from a destructor's own report.

The name is the log category of every line this instance writes, and name.GetID() is the key GenerateBanksByCache reads and ReportConfiguration writes under — see what an allocator name is worth for what the manager stores of the string itself, which is nothing at all without PROFILE_ENABLED.

A bank's name is not this name. Each bank is named name + '_' + blockSize + '_' + numberOfBlocks at the moment it is built (Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::GenerateBank()), so a bank's name records the geometry it was created with and never changes even though the bank's availability does. The allocator's own name is the only stable identifier a caller can hold.
Nothing locks, and nothing needs to. name is written once in the constructor's member initialiser list and never assigned again, so every reader of this member — any thread, any time — sees the same string. It is the one member of the class a caller may read while another thread is allocating from it, and only because it never changes.

Parameters

None.

Return value

TypeWhat you get
StaticString (deduced by auto) A copy of the construction-time name. Never empty by contract of this class, although a null const char* argument is turned into "None" by the manager at registration and not by this member

Examples

ReportConfiguration is the only internal caller — it takes the name through this member and hashes it into the cache key in one statement:

From Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::ReportConfiguration()

	auto uniqueName = GetName();
	mmgr.ReportMultiPoolConfiguration(uniqueName.GetID(), std::move(configs));

Outside the class, engine code identifies an instance by its id rather than its name: Logger::StartTask asks GetID for the handle it hands the manager (Engine/Log/Logger.cpp).
