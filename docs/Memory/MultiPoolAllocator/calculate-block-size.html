CalculateBlockSize

member of hbe::MultiPoolAllocator Engine/Memory/MultiPoolAllocator.h Private: round a request up to minBlock times a power of two - the whole size-class policy in four lines.

Signature

[[nodiscard]] size_t CalculateBlockSize(size_t requested) const

Function description

Private. The rounding rule of the whole allocator: a block size is minBlock times a power of two, never smaller than the request. 

	size_t blockSize = (requested + minBlock - 1) / minBlock;
	blockSize = std::bit_ceil(blockSize);
	blockSize *= minBlock;
	blockSize = std::max(minBlock, blockSize);

	return blockSize;

From Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::CalculateBlockSize()

Called only by NewBankAllocate, so it shapes banks that are about to be created — never a bank that already exists. A bank built from the initializer list or from the cache keeps whatever size it was given, however untidy, and a request below that size is served by it regardless of this rule.

The result is always at least the request and never more than double it. That upper bound is the reason NewBankAllocate can trust its own bank: the 2× ceiling in GetBankIndex rejects a bank whose size exceeds twice the rounded request, and a bank rounded by this rule can never exceed twice that same figure. The last statement, std::max(minBlock, blockSize), is what guarantees the lower bound for a request below the minimum.
minBlock is a divisor, and it is only ever assigned from a constructor argument. A minBlockSize of zero reaches this division unchecked from either constructor and is integer division by zero — a trap, not a wrong answer. Zero is not the only unexamined value either: nothing requires the figure to be a power of two, and nothing compares it to Config::DefaultAlign, so minBlockSize = 24 yields block sizes of 24, 48, 96 … and the pool underneath then rounds each of them up to a multiple of 16 (Engine/Memory/PoolAllocator.cpp, OS::GetAligned). The bank's real block size is then no longer a multiple of the figure this function computed, and the two disagree about the size class the bank belongs to.
Waste grows with the ladder. A 65-byte request against minBlock 16 takes a 128-byte block, so up to just under half the reserved memory of a class is unusable by design. That is the cost of the power-of-two ladder — one multiply instead of a search — and it is the figure PrintUsage exposes as Max Usage per bank against Memory = usage / capacity.
