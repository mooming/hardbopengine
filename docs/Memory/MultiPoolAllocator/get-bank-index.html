GetBankIndex

member of hbe::MultiPoolAllocator Engine/Memory/MultiPoolAllocator.h Private: which bank serves this size, and which bank owns this pointer - both answered by a linear scan.

Signature

[[nodiscard]] size_t GetBankIndex(size_t nBytes) const

[[nodiscard]] size_t GetBankIndex(void* ptr) const

Function description

Private, and the two overloads answer two different questions with the same return convention: an index into banks, or banks.size() to mean "none". Every caller tests the answer with >= banks.size() rather than comparing against a sentinel.

The size overload chooses where a request should go. It walks from the smallest block size up, and stops at the first bank that is large enough, not full, and not wasteful: 

	nBytes = std::max(minBlock, nBytes);
	const auto doubleSize = nBytes * 2;

	const auto len = banks.size();
	for (size_t i = 0; i < len; ++i)
	{
		auto& bank = banks[i];
		if (nBytes > bank.GetBlockSize())
		{
			continue;
		}

		if (bank.GetAvailableBlocks() <= 0)
		{
			continue;
		}

		if (bank.GetBlockSize() > doubleSize)
		{
			return len;
		}

		return i;
	}

	return len;

The pointer overload answers who owns this block, and can only answer it by asking everyone: 

	size_t index = 0;

	for (auto& bank : banks)
	{
		if (bank.IsMine(ptr))
		{
			return index;
		}

		++index;
	}

	return index;

From Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::GetBankIndex(void*)

PoolAllocator::IsMine is a range test against the bank's buffer (Engine/Memory/PoolAllocator.cpp), so a block anywhere inside a bank — including the bank's own base address — reports that bank, and the lowest-indexed owner wins.

OverloadCostWhat the answer depends on
GetBankIndex(size_t) One scan of the banks from the smallest, at most reaching the end The requested size, minBlock, the banks' block sizes, and how many blocks are free right now
GetBankIndex(void*) One scan of the banks, stopping at the owner Only the address and the banks' buffer ranges — never occupancy or size
The size answer is not a function of the size. A bank that has run out of blocks is skipped, so the same request can be served by the 128-byte bank at one moment and by a freshly generated 256-byte bank the next, and the choice is made against mutable state with no lock (Engine/Memory/MultiPoolAllocator.cpp). The 2026-10-05 review of the thread-safe twin records this as the prerequisite for any locking redesign — "making size to bank a pure function", because the free path has to scan every bank by pointer range precisely because the size path will not commit to one. Callers today get a correct answer, not a predictable one: which block size served a pointer cannot be inferred from the pointer, and nothing in this class returns it.
The 2× rule refuses a bank rather than skipping to a better one. When the first sufficient non-full bank is more than double the request, the loop returns "none" immediately. It does not continue looking: banks ascend in size, so every later bank is larger and would waste more. "None" means a new bank gets built at the exact rounded size, and the ladder grows by one — which is how a pool that started at {64 … 4096} ends up owning a 16-byte bank after a single 8-byte request.
Rounding happens here first. nBytes is raised to minBlock before the comparison and before the 2× ceiling, so a request below the minimum block size is measured as the minimum. That is why an allocator built with a large minBlockSize treats every small request as that size, and why the doubling ceiling is computed on the rounded figure rather than the raw one.

Parameters

ParameterTypeRequirement
nBytes size_t Size overload. The requested byte count; raised to minBlock by the first statement. Zero is legal here and answers with the smallest bank — Allocate has already returned null for zero before reaching this
ptr void* Pointer overload. Any address; one outside every bank answers with banks.size(). Null answers the same way unless a bank's buffer begins at address zero

Return value

TypeWhat you get
size_t An index into banks, or banks.size() for "no bank". The sentinel is one past the end rather than an invalid index, so the caller must compare with >=; both callers in this class do
