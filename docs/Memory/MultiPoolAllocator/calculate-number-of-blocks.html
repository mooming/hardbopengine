CalculateNumberOfBlocks

member of hbe::MultiPoolAllocator Engine/Memory/MultiPoolAllocator.h Private: turn a bank's byte target into a block count, with a floor of sixteen blocks.

Signature

static size_t CalculateNumberOfBlocks(size_t bankSize, size_t blockSize)

Function description

Private, and the only static helper in the class: it does not read the object's state, so the bank size and block size have to be handed to it explicitly. It converts a bank's byte target into a block count, with a floor. 

	size_t numberOfBlocks = (bankSize + blockSize - 1) / blockSize;

	constexpr size_t megaBytes = 1024 * 1024;
	if (blockSize < megaBytes)
	{
		numberOfBlocks = std::max(MinNumberOfBlocks, numberOfBlocks);
	}
	else
	{
		numberOfBlocks = std::max((size_t) 1, numberOfBlocks);
	}

	return numberOfBlocks;

From Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::CalculateNumberOfBlocks()

The floor is MinNumberOfBlocks, sixteen, and it applies to every class under one mebibyte. Above that, the floor is one block.

allocationUnit is a target for small classes and a floor for large ones. A bank reserves blockSize × numberOfBlocks, and both of the rules above can push that figure above bankSize: a class at or above one mebibyte gets at least one whole block, and any class under it gets at least sixteen. A caller who passes a small allocationUnit to keep banks small therefore gets the opposite for any class near or above it. Nothing caps the result, and the product is taken again by the pool, whose only overflow witness is totalSize <= 0 — an unsigned comparison that can detect an exact wrap to zero and nothing else (Engine/Memory/PoolAllocator.cpp).
Each bank is a registration, and registrations are a shared resource. The count this returns becomes one PoolAllocator, which registers itself with the manager and takes one slot from the 255 the process shares (Engine/Memory/PoolAllocator.cpp, Engine/Memory/AllocatorID.h). The block count is free; the bank it describes is not.
Sixteen blocks is a latency choice, not a correctness one. Sixteen blocks per class is what lets a size class absorb sixteen allocations of churn before the allocator grows again, and each growth is a fallback event that borrows a fresh buffer from the parent and re-sorts the ladder. Lowering the floor trades memory for more of those events; there is no configuration knob — the constant is a static constexpr member of the class.
