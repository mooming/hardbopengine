GetID

member of hbe::ThreadSafeMultiPoolAllocator Engine/Memory/ThreadSafeMultiPoolAllocator.h The registration id this instance was given, which is what AllocatorScope and every MemoryManager dispatch use.

Signature

[[nodiscard]] auto GetID() const

Function description

Declared and defined in Engine/Memory/ThreadSafeMultiPoolAllocator.h: the body is return id;, so the deduced return type is TAllocatorID — int (Engine/Memory/AllocatorID.h).

This is the id the constructor receives from MemoryManager::RegisterAllocator, and it is what makes the object addressable by the rest of the memory system: the registration record holds the pointer to this instance and two trampolines into Allocate and Deallocate, so MemoryManager::Allocate(id, nBytes) lands here. The engine never stores the id anywhere else — every caller either holds the object or reached it through this accessor.

Three states, in order. During construction it is InvalidAllocatorID, which the member initialiser list sets and the registration replaces with the last statement of the constructor body; that ordering is harmless because a caller who has not finished constructing the object cannot have handed its address to anyone. After construction it is stable, and this accessor reads it without taking lock. After the destructor it is still the old number: the destructor deregisters the allocation but never clears id, while MemoryManager returns that registration slot to the pool the next RegisterAllocator draws from (Engine/Memory/MemoryManager.cpp) — so a stale id can name a different allocator by the time you ask.

This is the accessor AllocatorScope is built on. AllocatorScope carries a template constructor taking anything that answers GetID() (Engine/Memory/AllocatorScope.h), which is how AllocatorScope inputAllocScope(inputAlloc) makes this allocator the ambient one for a region (Engine/Log/Logger.cpp). Scoping to an allocator whose id is still InvalidAllocatorID scopes to that sentinel, and MemoryManager answers such a request with an error log and a redirect to allocator 0 (Engine/Memory/MemoryManager.cpp) — with MEMORY_LOGGING_ENABLED 0 in this tree, that redirect is silent.

Parameters

None.

Return value

Examples

From Engine/Log/Logger.cpp

AllocatorScope inputAllocScope(inputAlloc);

The object is passed, not the number: the scope template calls GetID on it (Engine/Memory/AllocatorScope.h), so the id this page returns is what the allocator-selection thread-local holds for the duration of the region (Engine/Log/Logger.cpp).
