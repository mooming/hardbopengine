ThreadSafeMultiPoolAllocator

member of hbe::ThreadSafeMultiPoolAllocator Engine/Memory/ThreadSafeMultiPoolAllocator.h Records the ambient allocator as the bank backing store, boots from the configuration cache or from a brace list, and registers one allocator id.

Signature

explicit ThreadSafeMultiPoolAllocator(const char* name, size_t allocationUnit = DefaultBankUnit,
										  size_t minBlockSize = DefaultMinBlock)

ThreadSafeMultiPoolAllocator(const char* name, TInitializerList initialConfigurations,
								 size_t allocationUnit = DefaultBankUnit, size_t minBlockSize = DefaultMinBlock)

Function description

Both constructors are defined in Engine/Memory/ThreadSafeMultiPoolAllocator.cpp and do the same four things in the same order: record where the backing memory should come from, build the initial bank list, add up the banks' capacities, and register the object with MemoryManager. They differ only in step two.

From Engine/Memory/ThreadSafeMultiPoolAllocator.cpp, ThreadSafeMultiPoolAllocator::ThreadSafeMultiPoolAllocator()

parentID = MemoryManager::GetCurrentAllocatorID();

MemoryManager::scopedAllocatorID is a thread-local that starts at 0, which is MemoryManager::SystemAllocatorID (Engine/Memory/MemoryManager.cpp), so an allocator constructed with no AllocatorScope open banks on the system allocator. That recorded id, not the scope open at any later moment, is what every bank buffer is taken from and returned to — see the destructor.

The single-argument form takes no banks from the caller. It asks GenerateBanksByCache for the configuration a previous run saved under this name and, on a name miss, starts with an empty list and grows on demand through NewBankAllocate. The brace-list form ignores the cache: it copies the list into an inline vector, asserts initialConfigurations.size() <= 128, sorts it by block size and builds one bank per entry named <name>_<blockSize>_<numberOfBlocks>.

Registration is the last statement, and it publishes the object: the registration record holds this plus two trampolines that cast that pointer back and call Allocate and Deallocate. Neither constructor acquires lock, which is safe only because the pointer is not reachable until that final call.

Nothing here validates a bank entry, and a failed registration is not reported. A list entry such as {64, 0} reaches PoolAllocator, whose constructor returns before initialising its free list when blockSize * numberOfBlocks is not positive (Engine/Memory/PoolAllocator.cpp), leaving that bank's availables holding no value at all. And RegisterAllocator answers with InvalidAllocatorID once the engine's MaxNumAllocators registration slots are exhausted; this constructor stores that value without asserting it, unlike PoolAllocator, which asserts its own id (Engine/Memory/PoolAllocator.cpp). Both are recorded as open robustness findings in JOURNAL.md, 2026-10-05, and described under Coverage.
An instance stays where it was built. The class declares no copy and no move, and the std::mutex lock member is neither copyable nor movable, so all four of std::is_copy_constructible_v, std::is_move_constructible_v, std::is_copy_assignable_v and std::is_move_assignable_v are false for it — a static_assert probe over the header passes on all four, and a copy attempt reports call to implicitly-deleted copy constructor of 'hbe::ThreadSafeMultiPoolAllocator' with the note implicitly deleted because field 'lock' has a deleted copy constructor. That is the stability the registration record requires: it stores the address, not a copy.

Parameters

ParameterTypeRequirement
nameconst char*Becomes StaticString name on construction and is used three ways: the answer of GetName, the log category passed to Logger::Get, and the prefix of every bank name. It is also the cache key, so two instances with one name read and write one cached configuration. MemoryManager::RegisterAllocator substitutes "None" for a null name in its own record only
initialConfigurationsTInitializerList — std::initializer_list<PoolConfig>Second overload only. At most 128 entries, and nothing checks an entry's values; {blockSize, numberOfBlocks} pairs are sorted by block size, not merged, so a repeated block size becomes two banks
allocationUnitsize_tBytes a bank generated later aims to hold; stored as bankSize. Defaults to DefaultBankUnit, one megabyte. No effect on the banks this constructor builds
minBlockSizesize_tStored as minBlock: the floor of any block size and the quantum of CalculateBlockSize. Defaults to DefaultMinBlock, 16. Below sizeof(size_t) it collides with the free-list link a block must hold, which PoolAllocator asserts on instead of clamping

Return value

A constructor has no return value. The observable results are GetID — the registration id, or InvalidAllocatorID if the engine had no slot left — and GetName, together with the line RegisterAllocator logs as [RegisterAllocator] <name>(<id>).

Examples

From Engine/Log/Logger.cpp, Logger::Logger()

, inputAlloc("LoggerInputPool")

The only production instance: name only, so both the bank unit and the minimum block size take their defaults and the bank list comes from the configuration cache if one was ever saved (Engine/Log/Logger.cpp, Engine/Log/Logger.h).

From Engine/Memory/ThreadSafeMultiPoolAllocator.cpp

ThreadSafeMultiPoolAllocator sharedAllocator(allocatorName, {{16, 16}, {32, 16}, {64, 16}, {128, 16}, {256, 16}});

The form the test suite uses everywhere: a fixed block-size ladder, so a measured request lands in a known bank instead of triggering growth mid-measurement. A local of this kind is the norm precisely because the type cannot be moved.
