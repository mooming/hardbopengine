Deallocate

member of hbe::ThreadSafeMultiPoolAllocator Engine/Memory/ThreadSafeMultiPoolAllocator.h Returns a block to the bank that owns the address; a pointer from elsewhere is a fatal report and no release.

Signature

void Deallocate(void* ptr, size_t size)

Function description

Defined in Engine/Memory/ThreadSafeMultiPoolAllocator.cpp. A null pointer is a no-op, with an assert that the caller is not silently dropping a size. A real pointer is matched to its bank by address: GetBankIndex(void*) asks every bank IsMine(ptr), and the whole scan runs inside one std::lock_guard on lock.

The gap between those two groups is the whole point of this function's shape. The diagnostic allocates — a Logger call builds its input buffer under an AllocatorScope over a ThreadSafeMultiPoolAllocator (Engine/Log/Logger.cpp) — and the mutex is not recursive, so a log line emitted from inside the locked region can re-lock the mutex the same thread already holds and never come back. Recording a flag and reporting after the scope closes is the fix for exactly that, recorded in JOURNAL.md, 2026-10-05.

A pointer this class did not hand out is reported, not released. The foreign branch returns without freeing anything, and the branch ends the process wherever asserts are live: a FatalError log flushes, calls debugBreak() and then Assert(false) (Engine/Log/Logger.cpp, Engine/Core/Debug.h), and Assert aborts outside the Release configuration (CMakeLists.txt defines RELEASE_BUILD only for Release). Note what this class does not do: PoolAllocator::Deallocate forwards a pointer it does not own to its parent (Engine/Memory/PoolAllocator.cpp). The multi-pool has no such redirect, because with several banks it cannot know a parent owns the address. Freeing through the wrong allocator is therefore a leak plus a fatal report, not a recovery.
The size argument is checked, not used. The block returns to its bank's free list by address; size only feeds Assert(size <= bank.GetBlockSize()), which is live in Debug and Dev and compiled away in Release, and — under PROFILE_ENABLED, which this tree defines as 0 — the reported byte count. Pass the size you asked Allocate for, not the bank's block size: the assert compares against the block size, so the request can only ever satisfy it.
Cost, and why a bank never shrinks. A release costs an O(banks) address scan under the mutex — the review of 2026-10-05 measured the mutex plus that scan at 8.6 percent relative to the single-threaded twin MultiPoolAllocator, uncontended (JOURNAL.md). Returned blocks go back on the bank's free list and stay there; the only path that gives memory back to parentID is the destructor. Cross-thread returns are cheap in the measurements recorded in the locking design document, so a block freed by a thread other than the one that took it costs nothing special.
