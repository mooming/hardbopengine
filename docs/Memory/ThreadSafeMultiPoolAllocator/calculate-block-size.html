CalculateBlockSize

member of hbe::ThreadSafeMultiPoolAllocator Engine/Memory/ThreadSafeMultiPoolAllocator.h private Round a request up to minBlock times a power of two — the whole set of block sizes an instance can ever have.

Signature

[[nodiscard]] size_t CalculateBlockSize(size_t requested) const

Function description

Private, defined in Engine/Memory/ThreadSafeMultiPoolAllocator.cpp, and called from NewBankAllocate alone. It is arithmetic on minBlock, which the constructor fixes and nothing else assigns, so it needs no lock and no other state:

From Engine/Memory/ThreadSafeMultiPoolAllocator.cpp, ThreadSafeMultiPoolAllocator::CalculateBlockSize() const

size_t blockSize = (requested + minBlock - 1) / minBlock;
blockSize = std::bit_ceil(blockSize);
blockSize *= minBlock;
blockSize = std::max(minBlock, blockSize);

Read together, those four lines define the entire set of block sizes an instance can ever have: minBlock times a power of two. The request is divided up in units of minBlock (rounded up), that count is rounded up to a power of two by std::bit_ceil, and the product is floored at minBlock once more for the case where the request is zero or smaller than the floor.

RequestBlock size at minBlock = 16Note
0 to 1616Requests below the floor are indistinguishable — this is why Allocate treats a zero-size request before ever reaching here
17 to 3232Two units
33 to 6464Three units rounds up to four
65 to 128128Five units rounds up to eight
129 to 256256Nine rounds up to sixteen
This answer is not necessarily the bank's final block size. PoolAllocator rounds what it is given through OS::GetAligned(std::max(inBlockSize, sizeof(size_t)), Config::DefaultAlign) (Engine/Memory/PoolAllocator.cpp), so a bank's real block size is at least this result, at least sizeof(size_t) and a multiple of 16. With the default minBlock of 16 the two agree; an instance constructed with a smaller minimum block does not get the size class this function appears to promise, and a caller working out which class its request falls into has to apply that floor too.
It sets the size half of a bank; the count half belongs to CalculateNumberOfBlocks. The pair together decides how much memory one growth event takes from parentID, and the refusal rule in GetBankIndex — never serve a request from a bank whose block is more than double it — is what keeps this rounding ladder from turning into waste: the ladder is the reason a 33-byte request gets its own 64-byte class instead of riding on a 4,096-byte bank.
Nothing validates minBlock on the way in. The constructor stores whatever minBlockSize the caller passed. A value below sizeof(size_t) is caught one step later — PoolAllocator asserts that a block can hold the free-list link it has to store (Engine/Memory/PoolAllocator.cpp) — but a value of 0 divides by zero in the first line of this function, before any bank exists to complain.

The only call site, and the whole of what a growth event decides: the size comes from the request, the count from bankSize, and the two are passed on together (Engine/Memory/ThreadSafeMultiPoolAllocator.cpp).
