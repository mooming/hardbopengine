GetAvailable

member of hbe::InlineMonotonicAllocator Engine/Memory/InlineMonotonicAllocator.h Capacity minus cursor: the exact figure Allocate compares against, counting the arena only and ignoring the parent.

Signature

[[nodiscard]] size_t GetAvailable() const

Function description

Defined inline in Engine/Memory/InlineMonotonicAllocator.h as InlineMonotonicAllocator::GetAvailable(). Two lines: an assertion that the cursor has never passed the capacity, and the subtraction. 

Assert(Capacity >= cursor);

return Capacity - cursor;

From Engine/Memory/InlineMonotonicAllocator.h, InlineMonotonicAllocator::GetAvailable() const

The figure is exact in the only sense that matters to a caller: Allocate compares against this same function, so there is no second accounting that could disagree with it, and "this request fits" is decidable before the request is made. It is a read of one plain size_t under a const member function — no lock, no atomic, and no synchronisation of any kind, so concurrent with a bump it is a snapshot that may already be stale.

What it measures is the arena, and nothing else. Capacity is the array bound of buffer and cursor counts rounded bytes, so the answer ignores whatever the recorded parentID could still serve: an answer of 0 does not predict failure, it predicts that the next Allocate warns and forwards. The rounding is visible here too — since Allocate tests the aligned request, every non-zero request needs at least Config::DefaultAlign (16) bytes available, and the last 15 bytes of an arena are unreachable for any allocation. Sizing Capacity in multiples of 16 is what stops a seventh of the arena from being reserved for nothing.

The assert is the mirror image of GetUsage's, and one of the two fires on a legal state. This one reads Capacity >= cursor and so accepts a completely full arena, returning 0; GetUsage reads cursor < Capacity and aborts on exactly that state. In Release Assert is an empty inline function in Engine/Core/Debug.h, so a cursor past the capacity — reachable only through a data race or corruption, since the guard in Allocate prevents it — yields an unsigned subtraction that wraps to a huge figure rather than a complaint.

Parameters

None.

Return value

TypeWhat you get
size_tCapacity - cursor: bytes still bumpable in this object's own array, counted in the rounded sizes the arena actually spends. Zero means the next request is forwarded to parentID, not that an allocation will fail.

Examples

Illustrative — no call site for this exists outside Allocate itself; the testlets in Engine/Memory/InlineMonotonicAllocator.cpp read GetUsage and never this.

using Allocator = InlineMonotonicAllocator<2048>;

Allocator alloc("InlineMonotonicAllocator");

while (alloc.GetAvailable() >= 16)
{
	auto ptr = alloc.Allocate(64);
	…
}

The comparison needs the >= 16 rather than a bare > 0 for the reason above: a request of 1 byte is rounded to 16 before it is tested, so an arena reporting 8 bytes available would forward it anyway. Reading availability before asking is the only way to keep a request inside the arena, because the overflow path reports nothing in this configuration.
