IsMine

member of hbe::InlineMonotonicAllocator Engine/Memory/InlineMonotonicAllocator.h Private: an address-range test on the member array, and the only thing that decides which allocator a release reaches.

Signature

[[nodiscard]] bool IsMine(TPointer ptr) const

Function description

Defined inline in Engine/Memory/InlineMonotonicAllocator.h as InlineMonotonicAllocator::IsMine(TPointer ptr) const, in the private section after every public member. It answers one question — is this address inside my array — and that answer is what routes every release this object performs. 

auto bytePtr = reinterpret_cast<const uint8_t*>(ptr);
if (bytePtr < buffer)
{
	return false;
}

if (bytePtr >= (buffer + Capacity))
{
	return false;
}

return true;

From Engine/Memory/InlineMonotonicAllocator.h, InlineMonotonicAllocator::IsMine(TPointer ptr) const

The interval is [buffer, buffer + Capacity): the lower bound rejects anything below the array, the upper bound is the one-past-end address and rejects it and everything above. Nothing else is consulted — no bitmap, no size table, no record of what Allocate handed out — because a bump allocator needs none for its own allocation and this is the only ownership question it ever asks. The consequence is that the function answers "is this address in me", not "did I give this block out": an address in the untaken tail, or 100 bytes into the middle of a live block, returns true exactly as a real block does, and Deallocate will then ignore it as though it had been released.

The comparison is between a pointer into this object and a pointer from somewhere else, which the language leaves unspecified; in practice it is a plain address ordering, and it is what makes the forwarding branch of Deallocate work: a block that Allocate obtained from parentID cannot lie inside this object's own array, so it is recognised as foreign and returned to the parent. A null pointer is not special-cased before this test, which is why Deallocate inherits the manager's Assert(nBytes == 0) for a null release.

Private, so a caller cannot use it as a guard. Code outside the class cannot ask whether a pointer belongs to an arena; the only way to find out is to call Deallocate and let the same test decide the branch in private. This is also the mechanism behind the hazard on the class page: because the range is the test, a pointer from the original is not "mine" as far as a copy is concerned — each object tests against its own array — so the copy forwards it to its parent, and the release reaches an allocator that never handed it out.
