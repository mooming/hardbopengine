GetID

member of hbe::InlineMonotonicAllocator Engine/Memory/InlineMonotonicAllocator.h The registration id an AllocatorScope takes; a routing index whose object is fixed by the constructor, not by this call.

Signature

[[nodiscard]] auto GetID() const

Function description

Defined inline in Engine/Memory/InlineMonotonicAllocator.h as InlineMonotonicAllocator::GetID() const. auto deduces TAllocatorID (int, from Engine/Memory/AllocatorID.h) and the value returned is what the constructor stored from MemoryManager::RegisterAllocator. This is the class's only public handle on its registration; every usage figure is a plain member read instead.

The id is what makes the arena usable by code that never sees the object. Passing it to an AllocatorScope installs it as this thread's scoped allocator, so every later unscoped allocation — an HVector growing, an hbe::String being built — is dispatched by MemoryManager::Allocate(scopedID, nBytes) through the registration to Allocate. An AllocatorScope can also be built from the object directly: the template constructor in Engine/Memory/AllocatorScope.h calls GetID() for you.

The id is a routing index, not a claim about which object answers. The registration stored the constructor's this, so MemoryManager::Allocate(GetID(), n) mutates the cursor of the object that was registered — never a copy of it, even though a copy returns the same id from this function. The id also stops being valid the moment the destructor returns, and the slot it occupies can be handed to a later allocator by MemoryManager::RegisterAllocator. Hold it on the stack, next to the object, which is what every call site in the repository does.

If registration failed — RegisterAllocator returns InvalidAllocatorID after a fatal-error log when the 256-slot proxy pool is empty, and the constructor does not test the result — this function returns that sentinel. MemoryManager::Allocate asserts id != InvalidAllocatorID, then replaces an out-of-range id with 0 and logs, so a failed registration turns the arena into a forwarding layer onto the system allocator and keeps running. The bump path is unaffected: Allocate called directly still serves from buffer.

Parameters

None.

Return value

auto → TAllocatorIDThe registration id, by value. InvalidAllocatorID if registration failed; dangling-in-spirit once the object is destroyed, because the slot is back in the proxy pool.

Examples

	AllocatorScope scope(alloc.GetID());

}

The scope is opened on the id, not on the object, and it is closed before the arena is destructed — the ordering that keeps every allocation inside the scope pointed at a registration that is still alive.
