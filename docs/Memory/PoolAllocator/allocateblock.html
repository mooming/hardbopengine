AllocateBlock

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h Private: pops the free list; a null pointer and a logged usage count when the pool has nothing left.

Defined in Engine/Memory/PoolAllocator.cpp as PoolAllocator::AllocateBlock(). Private, and the only place the free list moves forward. Allocate is what decides whether a request is this function's business at all.

From Engine/Memory/PoolAllocator.cpp, PoolAllocator::AllocateBlock()

The empty pool is a log line and a null pointer, nothing else. It does not consult the parent, does not enlarge the buffer and does not assert; that decision is Allocate's and it was already taken, by the size comparison that put this request inside the pool's budget. The log goes through MemoryManager::LogError, which is silent unless MEMORY_LOGGING_ENABLED is on, so the null is the only signal a caller can depend on. The message carries the pool's own usage as used / total blocks, which is the one diagnostic that distinguishes "empty" from "corrupt".
Any link value at or above the block count ends the walk. The else branch sets the head to null, so the terminator is a range rather than one reserved number — the constructor's last block carries numberOfBlocks, and WriteNextIndex cannot write that value without tripping its assertion. What a released block carries instead, when the list had no head, is the question the class Coverage section leaves open; here it is visible only as the branch that decides whether the pool believes it still has blocks left.
The counters close the operation, and the profile peak rides along. After the branch the function asserts numberOfFreeBlocks > 0 and numberOfFreeBlocks <= numberOfBlocks, decrements the free count, and under PROFILE_ENABLED raises maxUsedBlocks to the new number of blocks checked out (GetUsedBlocksMax). The assertion that the count is above zero is what would catch a free list whose count and head disagree — a Release build carries on and the count wraps.
It returns an address it does not validate. There is no IsMine check and no check that the head names a block that is actually free: the function trusts the list. Two releases of one block, or a buffer written out of bounds by a holder, are visible here only as a null pointer arriving too early or an address arriving twice (Deallocate records both arithmetic outcomes).
