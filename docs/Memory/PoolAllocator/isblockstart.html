IsBlockStart

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h Private: inside the buffer is not enough — a block also has to begin where its stride says it begins.

Signature

bool IsBlockStart(Pointer ptr) const

Function description

Defined in Engine/Memory/PoolAllocator.cpp as PoolAllocator::IsBlockStart(Pointer ptr) const. It is IsMine and one further test: the distance from the base of the backing allocation has to be a whole number of strides. Its only caller is Deallocate, which asks it after IsMine has already accepted the pointer and before anything is written into it. 

	if (!IsMine(ptr))
	{
		return false;
	}

	return static_cast<size_t>(static_cast<Byte*>(ptr) - buffer) % blockSize == 0;

From Engine/Memory/PoolAllocator.cpp, PoolAllocator::IsBlockStart(Pointer ptr) const

What it refuses, and what that refusal buys. A free list stores its links inside the free blocks themselves, at offset zero, and WriteNextIndex writes there without asking who else is using those bytes. Before this test existed, releasing block + 1 — a pointer IsMine happily accepts, because the range test has no notion of a boundary — wrote a link over the first stride of a block somebody was still holding and pushed that interior address onto the list, so the same memory could be handed out a second time. In a Debug and Dev build the misalignment was caught downstream by the allocator's own alignment assertion; in a Release build, where assertions are compiled out, nothing said anything at all. This is the check that makes the refusal a refusal in every configuration, and it reports itself through MemoryManager::LogError at the call site.
Cost, and why there is no table behind it. Two pointer subtractions and one modulo against blockSize, with no per-block metadata and no extra memory: a pool of a million blocks carries no bitmap that could have answered this question. The stride is already known to be a multiple of the allocation's alignment — the constructor raises it to sizeof(TSize) and aligns it — so a block start is also an aligned address, and the modulo cannot be replaced by an alignment test without accepting addresses that lie between two blocks.
It answers one question, so a second release still passes. This test asks where a pointer sits, never whether the block is free. Releasing the same block twice keeps its address on the list twice and is caught, if at all, by the free-count assertion at the end of Deallocate — which a Release build removes. Coverage records the double release as still undetected; a bitmap would be the price of closing it, and that trade has not been made.

Parameters

NameTypeMeaning
ptrPointerA candidate block. It is not dereferenced here, so an uninitialised block stays unread; a null pointer fails IsMine, whose own test is skipped entirely when the pool holds no buffer.

Return value

TypeWhat you get
booltrue only when the pointer is inside the backing allocation and an exact multiple of blockSize from its base — in which case those bytes belong to the pool's own bookkeeping. Everything else, including an interior address and anything outside the buffer, is false.
