GetName

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h nodiscard A copy of the interned name the constructor was given.

Signature

[[nodiscard]] auto GetName() const

Function description

Defined in the class body of Engine/Memory/PoolAllocator.h, returning the name member. The declared type is auto, so the return is a StaticString copy rather than a reference: the caller keeps a valid name even after the pool is gone. The name is the one the constructor was given, interned by StaticStringTable::Register() and passed a second time to MemoryManager::RegisterAllocator() for the registration record.

On a moved-from pool this answers an empty string. The move constructor assigns rhs.name = StaticString(); (Engine/Memory/PoolAllocator.cpp), and the same applies to a pool whose construction stopped at the zero-capacity early return (constructors), whose name was interned before that branch. A log line built from it prints nothing where the pool's name used to be.
The pool's registration name can differ from this one. MemoryManager::RegisterAllocator() substitutes "None" for a null name in its own copy, and under PROFILE_ENABLED stores its own copy in the statistics record. So a name read from the manager's usage report is not necessarily the string this function returns.

Parameters

None.

Return value

TypeWhat you get
StaticStringA copy of the pool's name, safe to hold past the pool's lifetime. Interned, so the copy is an id, not a string allocation.

Examples

Illustrative — no call site for this exists in the repository.

auto poolName = pool.GetName();
log.Out(ELogLevel::Info, [poolName](auto& ls) { ls << poolName.c_str() << " is out of blocks"; });

The reason the return is a copy: MultiPoolAllocator and ThreadSafeMultiPoolAllocator name their banks by appending the block size and block count to the parent's name before constructing each pool (Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::GenerateBank()), so a bank's own name is the only thing that identifies it in a log after the vector has been reordered.
