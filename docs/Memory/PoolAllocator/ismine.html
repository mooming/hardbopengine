IsMine

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h Whether the address falls inside the pool's buffer — a range test, not an ownership record.

Signature

bool IsMine(Pointer ptr) const

Function description

Defined in Engine/Memory/PoolAllocator.cpp as PoolAllocator::IsMine(Pointer ptr) const. It is a comparison against one address range, and nothing more. 

auto bytePtr = static_cast<Byte*>(ptr);
auto offset = static_cast<size_t>(bytePtr - buffer);
auto totalSize = blockSize * numberOfBlocks;

return buffer <= bytePtr && offset < totalSize;

From Engine/Memory/PoolAllocator.cpp, PoolAllocator::IsMine(Pointer ptr) const

True means "this address is inside my buffer", not "this address is one I handed out". The test is byte-range only, so it answers true for the middle of a block, for a block sitting on the free list, and for a block the pool released an hour ago. It is the right question for routing a release (Deallocate asks exactly this before it decides whether the pointer is the parent's) and the wrong question for validating a pointer you are unsure of.
The range is fixed, so the answer never changes. buffer, blockSize and numberOfBlocks are written once by the constructor and never again, so two calls with the same pointer agree however much allocation happened between them. One address one past the end is excluded: offset < totalSize, not <=. A moved-from pool, whose buffer is null and whose byte count is zero, claims nothing.
The comparison is arithmetic on pointers, and it is not a check that the pointer is one the pool owns. Because Deallocate forwards anything this answers false for to the pool's parent (MemoryManager::Deallocate(parentID, ptr, size)), a wrong answer here decides which allocator is asked to free the memory. Callers that want certainty about ownership should compare against the pointer they were given by Allocate rather than asking this afterwards.
