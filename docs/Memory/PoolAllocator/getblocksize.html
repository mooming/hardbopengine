GetBlockSize

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h nodiscard The block stride actually in force, after the constructor floored and aligned the request.

Signature

[[nodiscard]] auto GetBlockSize() const

Function description

Defined in the class body of Engine/Memory/PoolAllocator.h, returning blockSize — the stride the pool actually lays its blocks out at, after the constructor floored the request at sizeof(size_t) and rounded it up to Config::DefaultAlign. The declared type is auto, so the return is TSize, which is size_t. 

blockSize(OS::GetAligned(std::max(inBlockSize, sizeof(TSize)), Config::DefaultAlign))

From Engine/Memory/PoolAllocator.cpp, PoolAllocator::PoolAllocator()

Every size decision a caller makes should read this, not the constructor argument. The request and the answer differ for any request that is not already a multiple of 16: 24 becomes 32, 100 becomes 112, and 32 stays 32 — the three cases the testlet Allocation With A Clamped Block Size asserts in Engine/Memory/PoolAllocator.cpp. Everything downstream uses the answer: the block stride, the capacity, the usage charge and the comparison a request is measured against in Allocate.
It is also the alignment the pool can offer. Blocks sit at buffer + index * blockSize, so a stride that is a multiple of 16 is what keeps every block 16-byte aligned — provided the parent's buffer is, which the testlet checks on the block addresses rather than assuming (OS::CheckAligned, Engine/Memory/PoolAllocator.cpp). The class takes no alignment argument, so this is the closest thing to an alignment guarantee it has, and a type needing more is under-aligned silently (Allocate, review finding 9).

Parameters

None.

Return value

TypeWhat you get
TSizeThe block stride in bytes: floored at sizeof(size_t), rounded up to Config::DefaultAlign (16), and equal to GetSize's answer for any pointer. Zero on a moved-from pool.

From Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::GetBankIndex(size_t) const

The bank-selection scan measures a request against this rather than against the size a bank was asked for — the correct pairing, because a bank created for 24 bytes serves 24-byte requests at a 32-byte stride. The same accessor is the key a bank is recorded under in MultiPoolAllocator::ReportConfiguration(), so the aligned value is also what the next boot's bank sizes are rebuilt from.
