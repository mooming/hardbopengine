GetAvailableMemory

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h nodiscard Free blocks times block stride, in bytes — a derived figure with nothing behind the multiplication.

Signature

[[nodiscard]] size_t GetAvailableMemory() const

Function description

Defined in the class body of Engine/Memory/PoolAllocator.h as numberOfFreeBlocks * blockSize. A derived figure, with nothing behind it that GetAvailableBlocks and GetBlockSize do not already say.

It is capacity in blocks expressed in bytes, and it overstates what a caller can use. The multiplication is honest about the buffer but not about the pool's granularity: 100 free blocks of 32 bytes report 3,200 bytes available, and a request for 33 bytes gets none of them — it goes to the parent instead (Allocate). Free bytes here do not add up to a large allocation.
The identity with the other two figures always holds. GetCapacity() - GetUsage() equals this, because all three are products of the same two counters (GetUsage, GetCapacity). A discrepancy between them is not a rounding artefact; it means the counters were written from two threads, which this class does not prevent.

Parameters

None.

Return value

TypeWhat you get
size_tFree blocks times block size, in bytes. Excludes anything the parent is holding on the pool's behalf.

Examples

Illustrative — no call site for this exists in the repository.

if (pool.GetAvailableMemory() < neededBytes)
{
	log.Out(ELogLevel::Warning, [&pool](auto& ls) { ls << "pool nearly exhausted: " << pool.GetAvailableMemory(); });
}

The engine reports bank usage through the multi-pool's own PrintUsage(), which prints committed bytes and capacity rather than the remainder, so no code asks this question. Nothing in the tree calls it, and the name is the only thing that makes it look used.
