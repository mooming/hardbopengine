GetBuffer

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h nodiscard Base address of the pool's one backing allocation — the address the parent gave and the address the parent gets back.

Signature

[[nodiscard]] auto GetBuffer() const

Function description

Defined in the class body of Engine/Memory/PoolAllocator.h, returning buffer — the Byte* the constructor obtained from one call to MemoryManager::Allocate() and the same address the destructor hands back to the recorded parent. The declared type is auto, so the return is Byte*.

One address, fixed for the pool's life, and the only memory the pool owns. The pool never grows, so this is also the address range IsMine tests and the range a diagnostic prints as [start, start + GetCapacity()). It is nullptr on a moved-from pool and on one whose construction stopped at the zero-capacity early return (constructors). The alignment of the blocks inside it comes from whoever allocated it, not from the pool (GetBlockSize).
Nothing about the buffer is safe to keep past the pool. The bytes go back to the parent id when the destructor runs, and the parent may hand them to another allocator immediately. Holding this pointer, or a pointer to a block inside it, past the pool's destruction is the use-after-free the destructor does not detect, because it never checks whether blocks came back.
Everything inside the buffer belongs to the pool's bookkeeping or to a holder. Reading it is harmless; writing to it outside a block you were given corrupts the pool, and the pool cannot detect that — the only witness is a free-list index that no longer makes sense, reported one release late by Deallocate. To ask whether a pointer is inside, call IsMine rather than open-coding this address plus GetCapacity.

Parameters

None.

Return value

TypeWhat you get
Byte*Base of the pool's single backing allocation, valid while the pool is alive and un-moved. Not a block, not a size, and not something to free.

Examples

			PoolAllocator alloc("BaseAllocTestAlloc", 1024, 1024);
			ls << "First Pool Allocator Buffer =  " << static_cast<void*>(alloc.GetBuffer()) << ", Allocated by "
			   << MemoryManager::GetCurrentAllocatorID() << lf;

From Engine/Memory/DefaultAllocator.cpp, BaseAllocatorTest::Prepare()

The test prints the buffer address next to the id that supplied it, which is the pair worth reading together: the address is the pool's, the ownership is the parent's. The multi-pool prints the same value as the start of a bank's range when no bank will claim a released pointer (Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::Deallocate()).
