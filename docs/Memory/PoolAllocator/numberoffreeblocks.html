NumberOfFreeBlocks

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h nodiscard The same free-block count GetAvailableBlocks reports, under a second name and with no caller.

Signature

[[nodiscard]] auto NumberOfFreeBlocks() const

Function description

Defined in the class body of Engine/Memory/PoolAllocator.h, returning numberOfFreeBlocks — the same member GetAvailableBlocks returns. The two are interchangeable in every respect: same value, same size_t, same absence of locking, same dependence on no other state. It is the one accessor in the class without a Get prefix, which is the only difference a reader can see from the declaration.

Two names, one counter, no second opinion. There is no computation here that could disagree with the other accessor, so comparing the two proves nothing about the pool's health. Nothing in Engine/ or Applications/ calls this one; the multi-pool that banks pools asks GetAvailableBlocks. Treat this as an alias kept for callers outside the tree, and prefer the Get-prefixed name in new code so the two do not drift into meaning different things.

Parameters

None.

Return value

TypeWhat you get
TSizeBlocks on the free list. numberOfBlocks minus this is what GetUsage divides by the stride to get bytes.

Examples

Illustrative — no call site for this exists in the repository.

if (pool.NumberOfFreeBlocks() < highWatermark)
{
	log.Out(ELogLevel::Warning, [&pool](auto& ls) { ls << "pool low on blocks: " << pool.NumberOfFreeBlocks(); });
}

Every real use of a free-block count in the tree is the multi-pool asking the other accessor before choosing a bank (Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::GetBankIndex(size_t)), which is the shape this snippet imitates.
