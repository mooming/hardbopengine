GetCapacity

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h nodiscard Block stride times block count — the one allocation the pool owns, and its whole budget.

Signature

[[nodiscard]] size_t GetCapacity() const

Function description

Defined in the class body of Engine/Memory/PoolAllocator.h as numberOfBlocks * blockSize. It is the exact byte count the constructor asked the parent for and the exact count the destructor hands back — the same expression, computed three times from two members that never change after construction. 

const TSize totalSize = blockSize * numberOfBlocks;

From Engine/Memory/PoolAllocator.cpp, PoolAllocator::PoolAllocator()

Capacity is measured after the block size was floored and aligned. A pool requested as 24 bytes by 64 blocks has a capacity of 32 × 64 = 2,048, not 1,536 (block size rounding). Anything that sizes or budgets a pool from the request rather than from this answer is working with a number the pool does not use.
This is the whole budget; the pool never grows. There is no second allocation, no bank generation and no fallback inside the pool — an oversized request goes to the parent and an exhausted one returns nullptr (Allocate). The bytes counted here are the only bytes the pool will ever own, and growing is the caller's job. The multi-pool allocators are that job, done once, for a ladder of block sizes.

Parameters

None.

Return value

TypeWhat you get
size_tBytes in the pool's single backing allocation. Zero on a moved-from pool or one whose construction stopped at the zero-capacity early return. GetUsage + GetAvailableMemory is always this number.
