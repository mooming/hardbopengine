GetID

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h nodiscard The registration id the manager keys this pool by, or InvalidAllocatorID when there is none.

Signature

[[nodiscard]] auto GetID() const

Function description

Defined in the class body of Engine/Memory/PoolAllocator.h, returning id by value — the TAllocatorID the constructor obtained from MemoryManager::RegisterAllocator(). It is the id the AllocatorProxy record is keyed by, which is what Allocate passes as the first argument of FallbackAllocate and what the destructor hands to DeregisterAllocator. The body sits in the header, so the call inlines into every includer.

InvalidAllocatorID is the only state this reports, and it means the pool owns nothing. The id is InvalidAllocatorID before the constructor's registration line, on a pool whose construction stopped at the zero-capacity early return (constructors), and on a pool that has been moved from (operator=). It is a real test of "is this pool live", which is how the destructor chooses its branch.
The id is borrowed, not owned, and it does not survive the pool. MemoryManager::DeregisterAllocator() returns the proxy record to the manager's free pool (Engine/Memory/MemoryManager.cpp), so the number becomes available to the next allocator registered. Keep this value only as long as the pool is alive; holding it past destruction points at whoever got the id next, and the manager's only guard is a range check (IsValid).

Parameters

None.

Return value

TypeWhat you get
TAllocatorIDThe registration id of this pool, or InvalidAllocatorID (-1) when there is none. Allocation against the id goes to the same pool, through the proxy's function pointers — with the caveat the move constructor records.

Examples

for (auto& bank : banks)
{
	auto& proxy = mmgr.GetAllocatorProxy(bank.GetID());
	proxy.threadId = currentTID;
}

A bank's id, used while the banks are still alive, to re-stamp each pool's proxy before the vector is cleared — the MEMORY_VERIFICATION_ENABLED path that records which thread owns a registration. Nothing in the tree allocates through a bank's id, which is the one use the stale-proxy caveat would otherwise make dangerous.
