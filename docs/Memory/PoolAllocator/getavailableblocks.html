GetAvailableBlocks

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h nodiscard Blocks still on the free list — the direct answer to whether the pool can serve the next request.

Signature

[[nodiscard]] TSize GetAvailableBlocks() const

Function description

Defined in the class body of Engine/Memory/PoolAllocator.h, returning numberOfFreeBlocks — the only counter the class maintains, from which every other figure is arithmetic. It is the count of blocks on the free list, so it is the direct answer to "can this pool serve the next request".

Non-zero is a snapshot, not a reservation. Nothing is synchronised, so on a pool that another thread can reach the count may be stale before the caller finishes reading it, and a following Allocate can still return nullptr. The engine's own caller uses this to decide whether to generate a new bank, and then allocates without re-checking (Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::GetBankIndex(size_t)).
Blocks the pool cannot serve are not counted here either way. A request larger than a block never consumes the free list (Allocate sends it to the parent), so this count says nothing about whether the pool can serve a particular request size — only whether it has any block left. Compare against GetBlockSize for the size question; that is the pairing the bank scan above makes.

Parameters

None.

Return value

TypeWhat you get
TSizeBlocks on the free list — size_t, unsigned. A caller comparing it with <= 0 is comparing against zero, which is what the engine does; the comparison reads as signed and the value is not. NumberOfFreeBlocks answers the same number under a second name.

Examples

		if (bank.GetAvailableBlocks() <= 0)
		{
			continue;
		}

From Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::GetBankIndex(size_t) const

A bank with no free block is skipped rather than chosen, and the scan falls through to generating a new bank when none qualifies. It is the only production use of this accessor, and it is a decision made on a number that allocation is about to change.
