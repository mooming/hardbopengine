GetUsage

member of hbe::PoolAllocator Engine/Memory/PoolAllocator.h nodiscard Blocks checked out, charged at the pool's block stride.

Signature

[[nodiscard]] size_t GetUsage() const

Function description

Defined in the class body of Engine/Memory/PoolAllocator.h as (numberOfBlocks - numberOfFreeBlocks) * blockSize: the blocks currently checked out, charged at the pool's block stride. Both operands are the pool's own counters, so the figure is the pool's view of itself and nothing the callers know can contradict it.

Usage is counted at the stride, not at the request. A pool of 4096-byte blocks from which a hundred callers each took 50 bytes reports 409,600 bytes in use (Engine/Memory/PoolAllocator.cpp, the Allocation & Deallocation testlet is exactly this shape). That is the right number for "how much of my buffer is committed" and a misleading one for "how many bytes did my subsystem ask for" — and the gap between the two is the padding the pool exists to create.
Requests the parent served are not in it. An oversized request leaves the counters untouched (Allocate returns before the free list is touched), so a pool can be reporting zero usage while a caller holds a large allocation that came through it. The bytes exist — they belong to the parent. The PROFILE_ENABLED fallback counter in the manager is the only place that traffic is totalled, and that build does not compile in this tree (Coverage).
Nothing is excluded, including leaked blocks. A block that was handed out and never released stays in this figure for the pool's life, and the destructor neither reports it nor refuses to run. Read this next to GetCapacity and GetAvailableBlocks before deciding a pool is healthy: an exhausted pool and a leaking pool look identical here.

Parameters

None.

Return value

TypeWhat you get
size_tBytes committed to holders, at GetBlockSize() per block. Zero on a moved-from pool or one whose construction stopped early. The exact complement of GetAvailableMemory against GetCapacity.

Examples

for (auto& pool : banks)
{
	log.Out([&pool](auto& ls)
	{
		ls << '[' << pool.GetBlockSize() << "] Memory = " << pool.GetUsage() << " / " << pool.GetCapacity()
		   << ", Max Usage = " << (pool.GetUsedBlocksMax() * pool.GetBlockSize());
	});

From Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::PrintUsage()

The usage report prints each bank's committed bytes against its capacity, which is the pairing this figure was built for. Note where the quote lives: MultiPoolAllocator::PrintUsage() is a #if PROFILE_ENABLED function, so this call site — like the peak in its second line — never runs in a build this tree compiles (Coverage).
