Destroy

member of hbe::Optional Engine/Memory/Optional.h private the single teardown: a flag cleared, or a destructor run because the flag said so

Signature

void Destroy(True_t)

void Destroy(False_t)

Function description

Private, and the single teardown path of Optional. The destructor, Reset, both optional-taking assignment operators, both Emplace overloads and the move constructor all call it as Destroy(typename IsReferenceType<TType>::Result());. Which of the two bodies runs is fixed by the element type, not by the caller.

OverloadBodyWhat it means
Destroy(True_t) hasValue = false; and nothing else A reference element type has nothing to destroy: the optional holds only an address, and the object behind it was never its to release
Destroy(False_t) if (hasValue) { Value().~TType(); } then hasValue = false; A value element type gets its destructor run explicitly on the storage, then the flag is cleared — the exact counterpart of the placement new in ConstructAt

The value overload tests the flag for itself. Its guard means a stray call on an already-empty optional is a no-op, which is why some call sites guard and others do not: Reset returns early on the same condition before it gets here, and assignment relies on this guard instead. Both orders end with the flag false.

The flag is the whole basis for running a destructor. Nothing here knows whether a constructor ever ran over those bytes — it trusts hasValue, which is a public field, and which the copy and move constructors leave uninitialised when their source is empty. An indeterminate true therefore reaches Value().~TType(), and what that does depends on TType's destructor and on the bytes it finds. The reference overload cannot fail this way: it never touches the storage.

No memory returns anywhere. The destructor call releases whatever the element owns, but the optional's own bytes are a member array: nothing is freed, no allocator id is involved, and the array is not zeroed, which is why a re-filled optional is written by ConstructAt rather than cleared first.

Parameters

ParameterTypeRequirement
True_t / False_tthe trait's ResultSelects the overload from TType. Passing the tag that does not match the element type is a compile-time mismatch, not a runtime choice

Return value

None. The only guarantee it makes is the final one on both paths: HasValue is false when it returns, and any reference previously handed out by operator* or Value is no longer usable.

Examples

The value overload, guard included:

Value().~TType();

From Engine/Memory/Optional.h, Optional::Destroy(False_t)

The explicit destructor call is the reason this class needs a destructor at all — a member array of bytes does not run one by itself. Its mirror is the placement new in ConstructAt(False_t, Types&&...), and the pairing between the two is the only ownership this template ever has over an element.
