CopyValue

member of hbe::Optional Engine/Memory/Optional.h private adopt the source flag and its bytes or value - and never destroy what is already there

Signature

void CopyValue(True_t, const Optional& rhs)

void CopyValue(False_t, const Optional& rhs)

Function description

Private, and reached only from the copy constructor and operator=(const Optional&), always as CopyValue(typename IsReferenceType<TType>::Result(), rhs). Both overloads begin by adopting the source's flag — hasValue = rhs.hasValue; — and then bring the element across, one way for a reference element type and another for a value type.

OverloadBodyWhat arrives
CopyValue(True_t, const Optional&) memcpy(value, rhs.value, sizeof(TType)); The stored address, copied as bytes. No object is constructed and the source keeps its value — copying an alias yields a second alias to the same object
CopyValue(False_t, const Optional&) Value() = rhs.Value(); An assignment of the source element into this storage — so the element here must already have been constructed, or this assigns into raw bytes

The reference form's length is the referent's size, not the pointer's. The storage is sized by IsReferenceType<TType>::TypeSize, which for a reference type is sizeof(T*) (Engine/Core/CommonUtil.h), while the copy asks for sizeof(TType) — the size of the referred-to type. For a referent smaller than a pointer the copy is short, and the remaining bytes of the destination keep whatever they already held. Whether that matters depends on byte order and on the destination's prior contents, and neither is fixed anywhere in the code, so this page records the mismatch without claiming a particular wrong address as the result.

Neither overload destroys what it is about to overwrite. The flag is overwritten from the source before anything else happens, so a destination that held a value has its old element's destructor skipped — and for a value type, its old element overwritten by an assignment it never consented to. Every call site is responsible for emptying first: assignment does (operator=(const Optional&) calls Destroy before this), and the copy constructor does not need to because it is constructing. That is also why self-assignment is undefined here: the caller destroys first, and this then reads the value that was just destroyed.

Parameters

ParameterTypeRequirement
True_t / False_tthe trait's ResultSelects the overload from TType; never a caller's free choice
rhsconst Optional&The source, which must hold a value — the call is made under if (rhs.hasValue), and this function does not re-test it. Must not be *this

Return value

None. The observable outcome is HasValue matching the source and the element being present; nothing reports whether the destination had to be vacated.

Examples

The reference form is a raw byte copy:

memcpy(value, rhs.value, sizeof(TType));

From Engine/Memory/Optional.h, Optional::CopyValue(True_t, const Optional& rhs)

MoveValue(True_t, Optional&) performs the same memcpy and then clears the source's flag, so aliasing and moving a reference-typed optional are the same byte operation with different bookkeeping afterwards. The value twin of this function is the assignment in the table above; its moving counterpart is MoveValue(False_t, Optional&).
