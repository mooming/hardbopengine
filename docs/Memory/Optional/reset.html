Module Index / Memory / Optional / Reset

Reset

member of hbe::Optional Engine/Memory/Optional.h empty the optional - destroy for a value type, clear the flag for a reference, nothing at all when already empty

Signature

void Reset()

Function description

Defined in the class body of Engine/Memory/Optional.h. It returns immediately when hasValue is false, and otherwise calls Destroy(typename IsReferenceType<TType>::Result()); — the same call the destructor makes. After it, the optional is empty and the flag is false.

What "empty" costs depends on the element type, because Destroy is overloaded on the True_t/False_t trait result: for a reference type it clears the flag and touches nothing else, and for a value type it runs Value().~TType() on the storage before clearing the flag. Either way the bytes are left where they are — this class never frees, never zeroes and never returns anything to an allocator.

It is idempotent and unconditional about the caller's references. Calling it on an already-empty optional is a no-op rather than an error. But nothing tracks the references handed out earlier by operator* or Value: after a reset, a value-type reference points at a destroyed object and a reference-type reference still points at the original object — which is alive, but no longer reachable through the optional that named it.

Two ways to say it, one behaviour. opt = nullptr; selects operator=(std::nullptr_t), whose body is a call to this function. Reaching an empty optional through the assignment form from an element type — operator=(TType&) on an empty optional — goes the other way and Emplaces instead.

Parameters

None.

Return value

None, and nothing is reported: an optional that was already empty and one that just released a value both return the same way. HasValue afterwards is the only observation available.

Examples

The early exit, before any destruction is considered:

if (!hasValue)

It is what keeps opt = nullptr; cheap on an already-empty optional, and what makes the guard unnecessary-but-harmless in the callers that do not have it: Destroy tests the flag again on the value path. The paired operation that goes the other way — empty, then filled — is Emplace.
