ConstructAt

member of hbe::Optional Engine/Memory/Optional.h private where an element arrives: an address stored for a reference type, a placement new for a value type

Signature

void ConstructAt(True_t, TType& inValue)

template <typename... Types>
	void ConstructAt(False_t, Types&&... args)

Function description

Private, and the only place Optional puts an element into its storage. The True_t/False_t parameter is not a caller's choice: every call site passes typename IsReferenceType<TType>::Result() or names one of the two tags directly, so an instantiation gets exactly one of these bodies.

Reference element types: ConstructAt(True_t, TType&)

Stores the address of the argument into the byte array, treating the array as a pointer slot (reinterpret_cast<TPtr&>(value[0]) = inValuePtr;). It checks that address with Assert, then re-reads the value through Value and asserts that the address of what it can reach equals the address it was given — a self-check that the cast and the storage agree — and finally sets hasValue = true. Nothing is copied, and nothing is constructed: the optional becomes an alias for an object it does not own.

Value element types: ConstructAt(False_t, Types&&...)

Sets hasValue = true first, then new (value) TType(std::forward<Types>(args)...); — a placement new into the member array, with the caller's arguments forwarded. That ordering means the flag is true while the constructor is still running, so a destructor that ran in that window would see a live flag over a half-built object.

Neither overload destroys what was already in the storage. Both assume the caller emptied the optional first, and both Emplace and operator=(TType&) do exactly that. A caller that reached ConstructAt without a preceding Destroy would leak the old element's resources and overwrite it in place — which no outside caller can do, since this is private, but it is the invariant every call site is responsible for.

The reference form's two checks are Assert, not FatalAssert. Engine/Core/Debug.h gives Assert an empty definition in RELEASE_BUILD, so a shipped build stores whatever address it is handed — including null — and the later read in GetValue(True_t) dereferences it. And because the optional holds only an address, the referred object's lifetime is the caller's problem: the optional cannot tell that it died, and Destroy(True_t) will clear the flag without touching it.

Return value

None, and no failure is reported on either path. The only state change a caller can observe is HasValue becoming true — for a value type, becoming true before the element exists.

Examples

The value path, in its entirety:

hasValue = true;
new (value) TType(std::forward<Types>(args)...);

From Engine/Memory/Optional.h, Optional::ConstructAt(False_t, Types&&...)

Both lines sit at the same indentation in the header, and their order is the ordering note above. The paired teardown is Destroy(False_t), which runs the destructor this placement new created — and which is reached only when the flag reads true.
