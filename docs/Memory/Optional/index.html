Optional

Engine/Memory/Optional.h final class template namespace hbe a value or nothing, entirely inside the caller - the state a caller can test, and the two very different ways of reading an empty one

Class description

template <typename TType> class Optional final at Engine/Memory/Optional.h: a value-or-nothing that lives entirely inside the caller's object, with no heap allocation and no separate control block. It is the shape the engine returns when an answer may legitimately be absent, and it does two things std::optional does not: it accepts a reference type as its element, storing a pointer instead of an object, and it carries its state in a plain public bool.

The whole object is two members — hasValue and an aligned byte array — and everything else is a function that reads or writes them. There is no allocator, no parent, no id, and no TAllocatorID anywhere in this header; the storage is a member of whatever holds the optional, so its lifetime is the owner's.

The state a caller can test

One boolean, spelled three ways. All three read the same field, so they cannot disagree:

FormWhat it answersPage
opt.hasValueThe field itself — public, readable and writable by anything that holds the optionalClass properties

Two states exist, not three: constructed-with-a-value and constructed-without-one. There is no "moved-from-but-valid" state, because a move clears the source's flag (MoveValue ends with rhs.hasValue = false;), and no "destroyed-but-valid" state, because Reset and the destructor both clear the flag as their last act.

What reading an empty optional does

ReadWhat happens when hasValue is false
*opt Both overloads open with FatalAssert(hasValue). In Engine/Core/Debug.h that flushes the logs, prints a [FatalAssert] line, calls debugBreak() and then std::abort() — and it is not inside any build guard, so the process ends in a Release build exactly as it does in Debug. There is no return value to inspect afterwards
opt.Value() Nothing checks the flag. For a value type the reference is a reinterpret cast of the raw byte array, so a caller reads memory that was never constructed — and may write it, because the non-const overload returns a modifiable reference. For a reference type the stored pointer is dereferenced after Assert(valuePtr != nullptr), and Assert is defined away in RELEASE_BUILD, so a null there is a null dereference in a shipped build
HasValue(), operator bool These are the reads that answer honestly, and they are the only two that do not touch the storage

operator* guards, Value() does not — and both are marked [[nodiscard]]. The difference is the whole safety story of this type: the operator asserts loudly and aborts, the accessor is unchecked and silent. A caller who prefers the accessor's name because it reads better has dropped the only check between "there is no value" and "here is a reference to whatever those bytes happen to hold". The two const overloads behave the same way as their non-const twins.

The copy and move constructors do not set the flag when the source is empty. Neither appears in an initializer list, and neither branch assigns hasValue in that case — the copy constructor reads the field instead of writing it, in else if (hasValue), and the move constructor calls Destroy, which itself begins by testing the flag. For an empty source, the new object's state therefore comes out of uninitialised storage, and for a value type the Destroy(False_t) path can end in an explicit destructor call on memory no constructor ever ran over. Every other path in the class assigns the flag: the other three constructors, both CopyValue overloads, both MoveValue overloads, ConstructAt, Destroy and Reset. The hole is only in those two constructors, and it is only reachable when the source is empty.

Self-assignment is not handled, and both copy and move assignment destroy before they copy. operator=(const Optional&) calls Destroy on its own value, then CopyValue from the argument; if the argument is this object, the copy reads the value it just destroyed. operator=(Optional&&) has the same shape with MoveValue. There is no address comparison in either — see operator=.

Reference element types

Optional<T&> is a supported instantiation, and it is a different object internally. The storage is sized by IsReferenceType<TType>::TypeSize (Engine/Core/CommonUtil.h), which is sizeof(T) for a value type and sizeof(T*) for a reference, and every private helper is overloaded on True_t/False_t from that same trait's Result. For a reference element the optional stores the address of someone else's object (ConstructAt), so it names a value it does not own: the referred object's lifetime is nobody's responsibility here, and Destroy for a reference type only clears the flag.

Non-member helper functions

None. There is no operator==, no Nullopt type of its own (the std::nullptr_t overloads stand in for one), no operator->, and no value_or. Engine/Memory/Optional.h includes Core/CommonUtil.h for True_t, False_t and IsReferenceType, Core/Debug.h for the two assert shapes, Core/Types.h for Byte, and OSAL/OSMemory.h.
