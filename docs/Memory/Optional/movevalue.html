MoveValue

member of hbe::Optional Engine/Memory/Optional.h private the copy that empties the source - which is what makes a moved-from optional empty rather than duplicated

Signature

void MoveValue(True_t, Optional& rhs)

void MoveValue(False_t, Optional& rhs)

Function description

Private, and reached only from the move constructor and operator=(Optional&&), always under if (rhs.hasValue). Each overload does the work of its CopyValue twin and then empties the source, which is the one thing that makes a moved-from optional empty rather than a duplicate of the value that moved out of it.

OverloadBodySource afterwards
MoveValue(True_t, Optional&) memcpy of sizeof(TType) bytes, then rhs.hasValue = false; Empty. Both optionals still hold the same address, but only this one will report it — the alias was duplicated, not transferred
MoveValue(False_t, Optional&) Value() = std::move(rhs.Value());, then rhs.hasValue = false; Empty by the flag, and moved-from by TType's own move assignment — which is a state TType defines, not this class

Both start with hasValue = rhs.hasValue; — under the call site's guard that is always true — so this function also decides the destination's flag without consulting its own previous state.

Neither overload destroys what the destination already held. The value-type path assigns into the existing element, and the reference-type path overwrites the stored address, both without running anything on the old contents. The move constructor is fine — it is constructing. The move assignment is where the pairing matters: operator=(Optional&&) calls Destroy first, and if the source is the same object the element has been destroyed before this function reads it. That is the self-move case, and nothing here detects it.

The reference form leaves the source's address in place. Only the flag is cleared, so the bytes of the source still contain the address of the object now also aliased by the destination — harmless while the flag is false, and visible if anything ever sets the flag again without filling (the empty-source constructor hole is exactly that).

Parameters

ParameterTypeRequirement
True_t / False_tthe trait's ResultSelects the overload from TType
rhsOptional&The source. Must hold a value (the call sits under a rhs.hasValue test) and must not be *this, since the destination is destroyed before this runs

Return value

None. Afterwards the destination holds the value and rhs reports empty through HasValue; nothing says whether the destination had to be vacated first.

Examples

The value path, and the line that empties the source:

Value() = std::move(rhs.Value());
rhs.hasValue = false;

From Engine/Memory/Optional.h, Optional::MoveValue(False_t, Optional& rhs)

The two lines are adjacent in the header, which is what guarantees the source is never left holding a value the destination also claims. Contrast CopyValue, which leaves the source filled — and note that the destination's flag is set from the source before either of these lines runs.
