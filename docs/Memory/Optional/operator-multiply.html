operator*

member of hbe::Optional Engine/Memory/Optional.h 2 overloads the checked read: FatalAssert first, which ends the process in every build configuration

Signature

TType& operator*()

const TType& operator*() const

Function description

Two dereference operators defined in the class body of Engine/Memory/Optional.h, each two lines: FatalAssert(hasValue); then return Value();. They are the checked way to read an optional, and the check is the point.

The constness of the overload follows the constness of the optional, so a const Optional& yields a const TType&. There is no operator->, so reaching a member goes through the reference: (*opt).Member().

What happens when the optional is empty

FatalAssert is not a debug facility. In Engine/Core/Debug.h it flushes the logs, prints a [FatalAssert] line naming the file and line, calls debugBreak() and then std::abort() — and unlike Assert, whose definition is empty in RELEASE_BUILD, it sits outside any build guard. Reading an empty optional through this operator ends the process in every configuration the engine builds.

There is no message. The message-less overload of FatalAssert is the one taken here, so the only report is the file and line of the assert inside the header plus its standing note that a message-less assert "has no other way to say what it caught". No accessor on the optional — not the element type, not the caller's variable name — appears in the output. Whoever debugs it starts from a header line and works back out of the log.

The assert tests the flag and nothing else. It is satisfied by hasValue being true, however it got there: written by hand through the public field, or left as residue by the copy or move constructor of an empty source. In both cases the assert passes and the reference returned is to bytes that were never constructed (Value, which performs no check of its own). Treat HasValue as the precondition and this operator as the action, not as a validator.

Parameters

None.

Return value

TypeWhat you get
TType& / const TType&The element, by reference — a borrow of the optional's storage, valid only while the optional still holds it. A later Reset, reassignment or destruction invalidates it, and for a reference element type it is an alias to an object the optional does not own. Not marked [[nodiscard]], unlike Value.

Examples

The guard is one line and it is unconditional:

FatalAssert(hasValue);

From Engine/Memory/Optional.h, Optional::operator*

Because that line has no else and no fallback return, the checked read has exactly two outcomes: the element, or the end of the process. Callers that must survive an absent value test first — if (opt) { use(*opt); } — or read the flag with HasValue and branch. The unchecked sibling is Value, which trades the abort for silence.
