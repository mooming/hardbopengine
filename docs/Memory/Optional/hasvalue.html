HasValue

member of hbe::Optional Engine/Memory/Optional.h the state, by value - the only question this class can answer about its own contents

Signature

[[nodiscard]] auto HasValue() const noexcept

Function description

Defined in the class body of Engine/Memory/Optional.h; the body is return hasValue;. The declared return type is auto, so a caller receives bool by value — a copy of the flag, not a reference to it, which also means the answer cannot be invalidated by anything that happens afterwards.

It is the explicit spelling of the test that operator bool spells implicitly, and of the field hasValue itself. Three names for one boolean, and no other state exists to test: an optional is either holding something or holding nothing.

This is the only question the class can answer about its own contents. There is no empty(), no has_value(), no capacity, and nothing that inspects the storage — so where a caller must not read the element, this is the gate to stand in front of operator* and Value. The first re-checks the flag and aborts on it; the second does not look at it.

It reports the flag, not a validated invariant. The field is public, so a caller can set it without constructing anything, and the copy and move constructors leave it uninitialised when their source is empty. Both cases produce an optional that answers true here while its bytes were never built. This function cannot tell that story — it is a getter, not a validator.

None.

Return value

Examples

The one line of the body:

return hasValue;

From Engine/Memory/Optional.h, Optional::HasValue

Inside the class the same field is read directly and far more often — by operator*, by both assignment forms that take an optional, by Reset, by Emplace and by Destroy — because the writers need the flag to decide whether to destroy what is already there before putting something new in.
