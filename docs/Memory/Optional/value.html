Value

member of hbe::Optional Engine/Memory/Optional.h 2 overloads the unchecked read: a reference to the storage, with no test of the flag at all

Signature

[[nodiscard]] TType& Value()

[[nodiscard]] const TType& Value() const

Function description

Two accessors defined in the class body of Engine/Memory/Optional.h, each one line: return GetValue(typename IsReferenceType<TType>::Result());. The trait picks which GetValue overload runs, so this function has two behaviours and no test of its own — it never reads hasValue.

That makes it a different instrument from operator*:

*optopt.Value()
Checks the flagYes — FatalAssert(hasValue)No
If the optional is empty (value type)The process abortsA reference to raw bytes that no constructor ran over — readable and, through the non-const overload, writable
If the optional is empty (reference type)The process abortsGetValue tests the stored pointer with Assert, which Engine/Core/Debug.h defines away in RELEASE_BUILD, and then dereferences it
Marked [[nodiscard]]NoYes, both overloads

Reading an empty optional through this function is silent. Nothing in the value path complains: the reference comes from a reinterpret cast of the byte array (GetValue(False_t)), so a caller gets a plausible-looking reference to indeterminate memory and the first symptom is a garbage value somewhere downstream. The reference path is the one case where a check exists at all — and it is a Debug-only Assert that the stored pointer is not null, so in a shipped build a null there is a null dereference. Choosing this spelling over operator* trades a guaranteed, immediately-reported stop for undefined behaviour.

Internally it is the write path as much as the read path. Optional(const TType&) fills itself with Value() = value after setting the flag, and CopyValue(False_t, const Optional&) and MoveValue(False_t, Optional&) assign through it. Those are calls made on storage whose construction is exactly what this function does not verify, which is why the flag is set first in the constructor: the ordering is the only thing that makes the sequence honest.

Parameters

None.

Return value

TypeWhat you get
TType& (non-const) / const TType& (const)The element, by reference, whether or not one is there. For a reference element type this is the object whose address the optional stored — the optional does not own it, so the referent may already be gone. The reference stays valid only until the next Reset, reassignment, Emplace or destruction.

Examples

The body, with the trait selecting the implementation:

return GetValue(typename IsReferenceType<TType>::Result());

From Engine/Memory/Optional.h, Optional::Value

Both overloads end with that call, and GetValue is where the reinterpret cast lives. A caller that wants a check has exactly one option: HasValue first, then operator* — which performs the same test again and stops the process if the answer was no.
