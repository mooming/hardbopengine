Function description

Five constructors defined in the class body of Engine/Memory/Optional.h, all defined inline. Three of them state their result unambiguously and two do not.

OverloadWhat it leaves behind
Optional()Empty: hasValue(false) in the initializer list. The byte array is untouched — never zeroed — but nothing reads it while the flag is false
Optional(const TType& value)Filled: hasValue(true), then Value() = value. Note the order — the flag is set before the value is written, and the write goes through Value, so for a value type this assigns into storage no constructor ran over
Optional(std::nullptr_t)Empty, by the same initializer list as the default constructor. It exists so Optional<T> opt = nullptr; reads as intended
Optional(const Optional& rhs)When rhs holds a value: CopyValue adopts the flag and the bytes or value. When rhs is empty: the constructor writes nothing, and its else if (hasValue) branch reads this object's own flag before it has a value
Optional(Optional&& rhs)When rhs holds a value: MoveValue adopts it and clears the source's flag. When rhs is empty: it calls Destroy, which begins by testing a flag that this constructor never set

Neither the copy nor the move constructor initialises hasValue. Neither appears in an initializer list, so for an empty source the flag is whatever the bytes of the new object happened to hold. The copy constructor then tests it, and the move constructor hands it to Destroy, whose value-type overload runs Value().~TType() whenever the flag reads true — a destructor call on storage no constructor ever ran over. The consequence depends on stack or heap residue, so it is silent most of the time. Copying or moving a filled optional is unaffected: both paths assign the flag from the source.

There is no converting constructor from anything except const TType& and std::nullptr_t. A value convertible to TType but not of it does not fill an optional; and the variadic Emplace, which does accept arbitrary arguments, is the only way to build an element from constructor arguments.

Parameters

ParameterTypeRequirement
valueconst TType&The element to hold. For a reference element type this is the object the new optional will refer to — it is not copied, only its address is taken (ConstructAt)
rhsconst Optional& / Optional&&The source. Safe to hold a value; an empty source is the case that leaves the new object's flag unset

Return value

Constructors return nothing. There is no failure to report: an optional that could not be constructed is indistinguishable from one that was constructed empty, because the flag is the only state and this is the code that writes it.

Examples

Reading a copied optional is only meaningful if the source held something:

if (rhs.hasValue)

From Engine/Memory/Optional.h, Optional::Optional(const Optional&)

That test is the first line of both the copy constructor and operator=(const Optional&) — the assignment form sets the flag on the empty branch because it has already destroyed and cleared its own, whereas the constructor has no own state to clear and so never writes the flag at all. See the class page's gap note for the consequence.
