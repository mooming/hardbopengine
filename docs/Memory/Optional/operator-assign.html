operator=

member of hbe::Optional Engine/Memory/Optional.h 4 overloads assign into a live value or fill an empty one; both optional-taking forms destroy first and neither survives self-assignment

Signature

Optional& operator=(TType& value)

Optional& operator=(const Optional& rhs)

Optional& operator=(Optional&& rhs)

Optional& operator=(std::nullptr_t)

Function description

Four assignment operators in the class body of Engine/Memory/Optional.h, each returning *this and each written as a short sequence of tests on hasValue. They differ in one important respect from the constructors: every one of them writes the flag.

OverloadWhat it does
operator=(TType&) Already holding a value: assigns through Value and returns. Empty: fills by Emplace. So an empty optional becomes filled and a filled one is updated in place — never destroyed and rebuilt
operator=(const Optional&) If this holds a value, Destroy runs first; then if rhs holds a value, CopyValue adopts a copy of it. If rhs is empty, nothing is copied and the result is empty
operator=(Optional&&) Same shape with MoveValue, which additionally clears the source's flag — so a moved-from optional is genuinely empty afterwards, not dangling
operator=(std::nullptr_t) Calls Reset. The one form that never throws, copies or moves anything

Neither optional-taking form handles assigning an object to itself. Both destroy their own value before looking at the source, so opt = opt; and std::move(opt2) onto opt2 run the destructor of the element and then read it: CopyValue assigns from rhs.Value() and MoveValue moves from it, and when &rhs == this both are reading the value that was just destroyed. No comparison of addresses appears in either operator, and nothing logs the attempt.

The value form takes a non-const lvalue reference. operator=(TType&) is the only assignment from an element, so assigning from a const TType, a temporary, or the result of an expression does not select it — and unlike the other three it does not destroy first, which is what makes "assign into a filled optional" an in-place update. For a reference element type, in-place assignment writes through the stored address to the object being referred to; the optional never re-points at a different object this way, because re-pointing would mean Emplace.

Parameters

operator=(std::nullptr_t) takes a null pointer constant and ignores its value.

Return value

TypeWhat you get
Optional&*this, in its post-assignment state. All four return it, so chains work; none reports whether anything was destroyed, copied or moved.

Examples

The value form is the only one that emplaces rather than overwriting:

Emplace(value);

From Engine/Memory/Optional.h, Optional::operator=(TType& value)

It is reached only on the empty branch, and it is the same call an outside caller could make directly — see Emplace. The nullptr form's counterpart is Reset, and the two together are the whole of "put a value in / take it out" at this interface.
