GetName

member of hbe::SystemAllocator Engine/Memory/SystemAllocator.h The literal SystemAllocator, answered by the object rather than by the registration record

Signature

[[nodiscard]] auto GetName() const

Function description

Defined in the class body of Engine/Memory/SystemAllocator.h: return "SystemAllocator";, deducing const char* to a static string literal — always valid, owned by nobody, and the same text the manager separately writes into slot 0's statistics when it registers the system allocator (MemoryManager::RegisterSystemAllocator calls OnRegister("SystemAllocator", false, Config::MemCapacity), Engine/Memory/MemoryManager.cpp). The two spellings are independent: this one answers the object, that one fills the record, and only the source keeps them identical.

One live use exists inside the class itself: the investigator's log line, which prefixes its allocation report with GetName() so raw-pointer and placed-pointer figures arrive labelled (Engine/Memory/SystemAllocator.h, inside AllocateBytes). That path is compiled only when the memory-investigation switches are on, which in this tree they are not.

Parameters

None.

Return value

const char* to the literal "SystemAllocator". Compare AllocatorProxy::GetName, which answers from the registration record and degrades to "NoName" without profiling.

Examples

			engine.Log(ELogLevel::Info, [this, rawPtr, ptr](auto& ls)
			{ ls << '[' << GetName() << "][Investigator] RawPtr = " << rawPtr << ", ptr = " << (void*) ptr; });
