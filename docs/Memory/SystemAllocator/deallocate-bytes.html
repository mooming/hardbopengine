DeallocateBytes

member of hbe::SystemAllocator Engine/Memory/SystemAllocator.h Private: assert, undo the investigation build's pointer placement, report, and hand the block back - free, protect, or VirtualFree

Signature

void DeallocateBytes(void* ptr, std::size_t nBytes)

Function description

Private; defined in the class body of Engine/Memory/SystemAllocator.h and reached only through deallocate. It is the exact inverse of AllocateBytes, and the order of its steps is the contract: assert the pointer, undo the investigation build's pointer placement, file the statistics report, then hand the block back.

The undo is the reason the byte count is a parameter at all. On the investigation path the pointer this function was handed is usually not the block base — the allocator returned an end-aligned address — so the base is recomputed as bytePtr + nBytes - allocSize, with the same page rounding the allocation applied; a wrong nBytes here releases (or protects) the wrong range. The underrun-check switch makes the handed pointer the raw base and skips the arithmetic. Then, under PROFILE_ENABLED, comes mmgr.ReportDeallocation(GetID(), ptr, nBytes, allocated) — the heap path deriving allocated from OS::GetAllocSize(ptr), the investigation path from the page-rounded size — guarded on that path by Assert(nBytes <= allocated) under MEMORY_VERIFICATION_ENABLED. Finally the block leaves: OS::VirtualFree, or — with the dangling-pointer switch on — OS::ProtectMemory, leaving the pages mapped but unreadable so any later touch faults, or in the shipped configuration, plain free(ptr).

The precondition is asserted twice before anything happens — once by the public deallocate and once here with the message "[SysAlloc][Dealloc] Null Pointer Error" — and neither assert exists in a shipped build, where a null pointer continues into whichever release the configuration selects.

Parameters

ParameterTypeRequirement
ptrvoid*The pointer the allocation returned — asserted non-null, and on the investigation path geometrically meaningful: the base is computed from it, so it must be that pointer, unchanged.
nBytesstd::size_tThe requested byte count the allocation was asked for; the reporting input on one path and the base-pointer's second operand on the other.

Return value

None. The block is freed, protected, or — in a shipped build given a null pointer — released into whatever the underlying free call does with null.

Examples

#if MEMORY_DANGLING_POINTER_CHECK_ENABLED
		OS::ProtectMemory(rawPtr, allocated);
#else // MEMORY_DANGLING_POINTER_CHECK_ENABLED
		OS::VirtualFree(rawPtr, allocated);
#endif // MEMORY_DANGLING_POINTER_CHECK_ENABLED

The investigation path's two exits: free the pages, or keep them mapped and inaccessible so a use-after-free becomes a crash at the illegal touch instead of silent corruption. The dangling-pointer semantics themselves belong to the OSAL entry for OS::ProtectMemory, which this wave has not written — recorded as an omission on the class page.
