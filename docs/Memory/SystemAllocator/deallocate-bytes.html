DeallocateBytes

member of hbe::SystemAllocator Engine/Memory/SystemAllocator.h Private: assert, undo the investigation build's pointer placement, probe, report, and hand the block back - free, protect, or VirtualFree

Signature

void DeallocateBytes(void* ptr, std::size_t nBytes)

Function description

Private; defined in the class body of Engine/Memory/SystemAllocator.h and reached only through deallocate. It is the exact inverse of AllocateBytes, and the order of its steps is the contract: assert the pointer, undo the investigation build's pointer placement, file the statistics report, then hand the block back.

The undo is the reason the byte count is a parameter at all. On the investigation path the pointer this function was handed is never the block base — the guard occupies one page, and end placement moves the address again — so the base is recomputed with the same page rounding the allocation applied: one page back on front placement, bytePtr + nBytes - pageCount * pageSize on end placement; a wrong nBytes here releases (or protects) the wrong range. Then, with the dangling-pointer switch on and before anything else touches the block, comes the probe: one volatile read through the handed pointer. A live allocation answers silently; a freed one faults right here, because the previous release protected the whole mapping and the mapping is never returned to the OS — page protection is the state that says "freed", so this one-byte read is the double-release detector and the faulting call is its diagnosis. Under PROFILE_ENABLED comes mmgr.ReportDeallocation(GetID(), ptr, nBytes, allocated) — the heap path deriving allocated from OS::GetAllocSize(ptr), the investigation path from the guarded, page-rounded size — guarded on that path by Assert(nBytes <= allocated) under MEMORY_VERIFICATION_ENABLED. Finally the block leaves: OS::VirtualFree, or — with the dangling-pointer switch on — OS::ProtectMemory over the whole mapping, guards included, leaving the pages mapped but unreadable so any later touch faults, or in the shipped configuration, plain free(ptr).

The precondition is asserted twice before anything happens — once by the public deallocate and once here with the message "[SysAlloc][Dealloc] Null Pointer Error" — and neither assert exists in a shipped build, where a null pointer continues into whichever release the configuration selects.

The two byte arguments are two different quantities, and the pairing is what makes usage reach zero. nBytes is what the caller asked for; allocated is what this allocator really owns, read back from OS::GetAllocSize on the heap path. They differ by whatever malloc rounded up to, and the report sends both: requested totals move by the first, usage by the second. That is the same figure AllocateBytes credited, so a block that came and went leaves usage at zero — the property DeregisterAllocator's leak check depends on. It is also the property this function used to break: its shipped-path declaration of allocated sat behind #ifndef MEMORY_INVESTIGATION_ENABLED, a macro Engine/Config/BuildConfig.h always defines (as 0), so the line never compiled and the release debited the caller's nBytes against a credit of the malloc size. Every block then left a residue of the padding behind, and the figure the leak check reported was that residue — measured at 9012 and 32884 bytes in two runs of the same suite, both non-zero for a process with nothing outstanding. Reading a value macro takes #if, not #ifdef; the same trap is what the InlineMonotonicAllocator pages describe from the other side.

Parameters

ParameterTypeRequirement
ptrvoid*The pointer the allocation returned — asserted non-null, and on the investigation path geometrically meaningful: the base is computed from it, so it must be that pointer, unchanged.
nBytesstd::size_tThe requested byte count the allocation was asked for; the reporting input on one path and the base-pointer's second operand on the other.

Return value

None. The block is freed, protected, or — in a shipped build given a null pointer — released into whatever the underlying free call does with null.

Examples

#if MEMORY_DANGLING_POINTER_CHECK_ENABLED
		OS::ProtectMemory(rawPtr, allocated);
#else // MEMORY_DANGLING_POINTER_CHECK_ENABLED
		OS::VirtualFree(rawPtr, allocated);
#endif // MEMORY_DANGLING_POINTER_CHECK_ENABLED

The investigation path's two exits: free the pages, or keep them mapped and inaccessible so a use-after-free becomes a crash at the illegal touch instead of silent corruption. The dangling-pointer semantics themselves belong to the OSAL entry for OS::ProtectMemory, which this wave has not written — recorded as an omission on the class page.
