SystemAllocator

member of hbe::SystemAllocator Engine/Memory/SystemAllocator.h Default construction of a class that holds nothing, plus an MSVC-only converting constructor for the standard allocator protocol

Signature

SystemAllocator() = default

#ifdef _MSC_VER
	template <class U>
	SystemAllocator(const SystemAllocator<U>&)

Function description

The default constructor is defaulted in the class body of Engine/Memory/SystemAllocator.h; there is nothing to initialise, because the class declares no data members. An instance is interchangeable with any other instance of any instantiation — that claim is what operator== hard-codes to true.

The second declaration sits behind #ifdef _MSC_VER: a converting constructor from any SystemAllocator<U> with an empty body. Its purpose is the standard allocator protocol — MSVC's container machinery rebinds an allocator to a node type and then constructs the rebound object from the original, and without this template constructor that line will not compile there. It is invisible on the compilers this tree is built with: clang and gcc preprocessor it away, which also means the AST-driven method gate never sees it (the class page's Coverage row records exactly that).

Parameters

ParameterTypeRequirement
(unnamed)const SystemAllocator<U>&Any instantiation of the same template; the parameter is read by nothing because the constructor under _MSC_VER has an empty body and the defaulted one takes no argument.

Return value

None; constructors. A constructed allocator is immediately usable, needs no registration, and owns nothing.

Examples

	static TSysAlloc systemAllocator;

From Engine/Memory/MemoryManager.cpp, MemoryManager::RegisterSystemAllocator()

The engine's one instance: a function-local static SystemAllocator<uint8_t> constructed on first use, its operations wrapped in lambdas and installed into proxy slot 0. Nothing else in the tree constructs a SystemAllocator; everything else reaches it through the manager or names the type in template arguments.
