AllocateBytes

member of hbe::SystemAllocator Engine/Memory/SystemAllocator.h Private: where bytes come from - malloc in a shipped build, page-rounded virtual blocks with end-aligned pointers in an investigation build, and the profiling report either way

Signature

void* AllocateBytes(std::size_t nBytes)

Function description

Private; defined in the class body of Engine/Memory/SystemAllocator.h and reached only through allocate. This is where the class's one decision — where bytes come from — is made, and the preprocessor selects between two very different answers.

In the shipped configuration, the body is auto ptr = (T*) malloc(nBytes); and nothing else before the report: the pointer, null on failure, is returned as given. With MEMORY_INVESTIGATION_ENABLED, the request is rounded up to whole pages (pageCount = (nBytes + pageSize - 1) / pageSize over OS::GetPageSize()), the block comes from OS::VirtualAlloc, and the pointer handed back is chosen to make off-by-N writes fault or show: unless the underrun-check switch is on, the returned pointer is placed at the block's end minus the requested bytes, so the first byte past the caller's region is past the mapped block. With MEMORY_LOGGING_ENABLED every such allocation logs raw base and placed pointer through the engine logger. One further statement in this configuration deserves recording for what it is: a special case for nBytes == 1 that assigns 1 to nBytes — a no-op edit left in the source, changing nothing.

Under PROFILE_ENABLED both configurations then file the statistics report — mmgr.ReportAllocation(GetID(), ptr, nBytes, allocated), with allocated read back from OS::GetAllocSize(ptr) on the heap path and equal to the page-rounded size on the virtual one. That is also the only reason this function touches MemoryManager::GetInstance(): in the shipped configuration (profiling off) the byte layer stands entirely on its own, engine or no engine — the fact the class page's note is about.

Parameters

ParameterTypeRequirement
nBytesstd::size_tByte count, computed by the caller as n * sizeof(T); on the investigation path it is also the geometry input that decides the returned pointer's position inside the block.

Return value

An untyped pointer to room for nBytes — never tested for null here, and the investigation path's pointer is deliberately not the block base in the default switch combination, which is why DeallocateBytes recomputes the base from the size before releasing.

Examples

		const auto pageSize = OS::GetPageSize();
		const size_t pageCount = (nBytes + pageSize - 1) / pageSize;
		const size_t allocSize = pageCount * pageSize;
		auto rawPtr = OS::VirtualAlloc(allocSize);
