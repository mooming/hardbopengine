operator==

member of hbe::SystemAllocator Engine/Memory/SystemAllocator.h Always true, across every pair of instantiations: the statelessness of the class written where the standard library looks for it

Signature

template <class U>
	bool operator==(const SystemAllocator<U>&) noexcept

Function description

Defined in the class body of Engine/Memory/SystemAllocator.h as a literal return true;, for every U. This is the statelessness of the class written where the standard library looks for it: all SystemAllocator instantiations draw from the same system heap and own nothing, so memory allocated through one may be released through any other, and a container may rebind (rebind) without asking permission. The comparison reads no operand — neither the object it is called on nor the one it is handed.

Neither comparison is const-qualified. The declaration is non-const member syntax — bool operator==(const SystemAllocator<U>&) noexcept — so the comparison will not compile through a const allocator object. That excludes a generic container that stores its allocator as const, and it is invisible on this tree's compilers only because nothing in the tree instantiates one that way. A caller adopting this allocator for a standard container should treat it as a defect of the interface, not a rule to code around by const-casting.

Parameters

ParameterTypeRequirement
(unnamed)const SystemAllocator<U>&Any instantiation; it is not examined.

Return value

true. Always, for every pair of instantiations, in both build configurations.

Examples

Nothing in the tree compares allocators of this type; the operator exists for the standard allocator requirements the class otherwise meets, and the sibling operator!= answers its half of the pair.
