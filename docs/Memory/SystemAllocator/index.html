SystemAllocator

Engine/Memory/SystemAllocator.h class template namespace hbe The stateless system-heap allocator in standard-library shape: element arithmetic over a private byte layer that is malloc/free in a shipped build and page-rounded virtual blocks in an investigation build, and the allocator proxy slot 0 stands for

Class description

template <class T> class SystemAllocator at Engine/Memory/SystemAllocator.h is the engine's stateless allocator over the operating-system heap, written in the shape the standard library expects: a value_type, a rebind, allocate(n)/deallocate(ptr, n) in element counts, and comparisons that answer every question "yes, they're the same." Every instance of every T is the same allocator — the class holds no members — so any one may release memory obtained through any other. In the shipped configuration of this tree the two operations are malloc and free behind one byte-width layer each, plus reporting; a build with MEMORY_INVESTIGATION_ENABLED replaces the pair with page-rounded OS::VirtualAlloc blocks and pointer placement deliberately chosen to make out-of-bounds writes visible. The build variants belong to the two private helpers, AllocateBytes and DeallocateBytes.

The engine's own instance is fixed and singular: MemoryManager::RegisterSystemAllocator makes a function-local static SystemAllocator<uint8_t> systemAllocator;, wraps its allocate/deallocate in two lambdas, and writes them straight into proxy slot 0 — never through the free list, never by RegisterAllocator (Engine/Memory/MemoryManager.cpp). Slot 0's identity is MemoryManager::SystemAllocatorID, which GetID hard-matches, and slot 0 is what the manager's invalid-id corrections land on: the allocator that answers when no scope opinion exists.

In the shipped configuration this allocator is the one that does not need the engine. With PROFILE_ENABLED 0 (the setting in Engine/Config/BuildConfig.h) neither helper touches MemoryManager::GetInstance() — the reporting calls sit inside the guard — so SystemAllocator allocates and frees correctly before the manager exists and after it dies. Turn profiling on and that changes: every operation then reports through the manager, whose GetInstance ends the process if no manager is alive.
A failed malloc is returned, not diagnosed. The default-mode path is auto ptr = (T*) malloc(nBytes); followed by reporting, and the pointer — possibly null — is returned to the caller (Engine/Memory/SystemAllocator.h). It is the callers above, not this class, that turn a null return into an assert: MemoryManager::Allocate asserts its result non-null, the free New helper has no such check and would placement-construct through null.
