Function description

Defined in the class body of Engine/Memory/AllocatorProxy.h. The initializer list writes four values — id(InvalidAllocatorID), next(nullptr), allocator(nullptr), allocate(nullptr), deallocate(nullptr) — and the body is empty. The result is the empty record: an identity no allocation may use (InvalidAllocatorID is -1, the sentinel of Engine/Memory/AllocatorID.h) and two null operation pointers, so a record built by this constructor forwards nothing to anyone.

This is the starting state of every element of MemoryManager's allocators[MaxNumAllocators] array before any registration touches it. MemoryManager::MemoryManager() then overwrites only id, with the slot number, for slots 1 through MaxNumAllocators - 1 and parks them in proxyPool; slot 0 keeps the constructor's InvalidAllocatorID until RegisterSystemAllocator fills its operation pointers (Engine/Memory/MemoryManager.cpp). It is also the state the dummy returned by GetAllocatorProxy is rebuilt to on every invalid-id call, and the state of a proxy between being released from the free list and being filled by RegisterAllocator.

A null operation pointer is an assert, not a graceful failure. MemoryManager::Allocate and MemoryManager::Deallocate assert their operation pointer is non-null immediately before calling it (Engine/Memory/MemoryManager.cpp). Outside a build where Assert has teeth, the following line dereferences the null pointer — so a record still in this constructed state must never receive traffic, which is why deregistration is allowed to leave the record parked in the free list rather than in a routable slot.

Parameters

None.

Return value

Constructs the empty proxy record; nothing is allocated and nothing is registered.

Examples

static AllocatorProxy dummy;
new (&dummy) AllocatorProxy();

return dummy;

From Engine/Memory/MemoryManager.cpp, MemoryManager::GetAllocatorProxy(TId)

The invalid-identity answer: the static dummy is re-constructed into this exact state on every call, so every caller handed a proxy for a bad id holds the same record, and any reference kept from an earlier bad call is reset under its owner. An allocation through it takes the null-allocate assert described above.
