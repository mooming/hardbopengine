Module Index / Memory / AllocatorID / IsValid

IsValid

member of hbe::AllocatorID Engine/Memory/AllocatorID.h free function in namespace hbe the range test every indexed access into the allocator table runs first - and the only thing it can prove about an id

Signature

[[nodiscard]] inline bool IsValid(TAllocatorID id) noexcept

Function description

Declared at namespace scope in Engine/Memory/AllocatorID.h and defined in the header, so it is available to every translation unit that includes the id type and is reachable unqualified. It answers one question: is this value inside the array the manager keeps its proxies in. The body is the range test id >= 0 && id < MaxNumAllocators, and nothing else.

That makes it a memory-safety check, not a liveness check. A valid id may name a slot that holds no registration, a registration that has already retired, or a registration of an entirely different allocator that took the slot after it was recycled — see the class page for what an id's lifetime actually is (AllocatorID). InvalidAllocatorID is -1, so it fails this test, which is what lets every allocator use IsValid(GetID()) and GetID() != InvalidAllocatorID interchangeably for the "am I registered" question.

The manager holds a private copy of this rule rather than calling it. MemoryManager::IsValid is a static member whose body repeats id >= 0 && id < MaxNumAllocators verbatim (MemoryManager::IsValid). Almost every call in Engine/Memory/MemoryManager.cpp uses the member; the free function here is the one allocators and callers outside the manager see. The two can only disagree if one of the two expressions is edited.
Passing the test does not mean the slot is usable. Where an id is used as an index after a check, the code still handles the case that the slot is empty: MemoryManager::GetAllocatorProxy answers a failed check by logging an error and returning a freshly constructed static proxy whose function pointers are null, and a deregistered proxy keeps its slot with exactly those null pointers. So a stale-but-in-range id walks straight past this function and reaches a proxy that cannot allocate.

Examples

The bounds test is the guard in front of every indexed access the manager makes:

return allocators[id];

From Engine/Memory/MemoryManager.cpp, MemoryManager::GetAllocatorProxy(TId id)

The line above is the fall-through of that function: it is reached only once IsValid(id) has passed, and it is the reason the check exists at all — allocators is a fixed array of MaxNumAllocators proxies, so an unchecked index is an out-of-bounds reference into the manager itself. Allocators use the same function on their own stored id to decide whether they ever got registered; PoolAllocator::GetID is where such an id is read back.
