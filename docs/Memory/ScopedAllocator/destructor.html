~ScopedAllocator

member of hbe::ScopedAllocator Engine/Memory/ScopedAllocator.h Defaulted, and the defaulting is the contract: reverse declaration order restores the outer id before the owned allocator dies

Signature

~ScopedAllocator() = default

Function description

Declared defaulted in the class body of Engine/Memory/ScopedAllocator.h — and the defaulting is the entire contract. C++ destroys members in reverse declaration order, and the members are declared allocator first, scope second; so teardown runs scope-restore, then allocator-death: the thread's scoped id returns to the outer value through AllocatorScope's destructor while the allocator it names is still fully alive, and only then does the allocator's own destructor release its buffer and deregister its id.

Read the hazard note on the scope destructor page first, because this ordering exists to answer it: an allocator destroyed while its own scope is open releases its buffer through whatever the ambient scope points at, and this module has already carried that bug once. Composing allocator and scope into one object with one fixed member order removes the chance for callers to get that ordering wrong — which is what ScopedAllocator is for.

Reverse-order destruction fixes the allocator's own teardown, not its customers'. An object the subtree allocated from this allocator and failed to release before this object dies is released under the outer scope, routed to the wrong allocator (the id-free release paths read the current value, not the pointer's history — see the free helpers). Everything living inside the redirection must die inside it.

Parameters

None.

Return value

None. After it returns, the thread allocates by the outer id and the owned allocator's registration is gone.

Examples

			ScopedAllocator<TAlloc> scope1("NestedStack1", 512);
