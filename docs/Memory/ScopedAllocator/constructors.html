ScopedAllocator

member of hbe::ScopedAllocator Engine/Memory/ScopedAllocator.h One perfect-forwarding constructor builds the owned allocator first and opens the scope over it second; every way to copy or move the pair is deleted

Signature

ScopedAllocator(const ScopedAllocator&) = delete

ScopedAllocator(ScopedAllocator&&) = delete

template <typename... Types>
	ScopedAllocator(Types&&... args)
		: allocator(std::forward<Types>(args)...)
		, scope(allocator)

Function description

One live constructor, defined in the class body of Engine/Memory/ScopedAllocator.h, perfect-forwarding its whole argument pack twice over: allocator(std::forward<Types>(args)...) builds the owned allocator in place with exactly the arguments the caller wrote, and scope(allocator) then opens an AllocatorScope over the finished object — through that class's template constructor, which asks the allocator for its GetID(). Member-initialisation order is declaration order, so the allocator is a complete, registered object before the scope reads its id; the constructor has no body statements and no error path of its own — if the allocator's construction stops early (a zero-capacity request, a failed registration), the scope is opened over whatever id the object reports, and AllocatorScope documents what each id value then means.

The copy and move constructors are deleted, as is assignment in both directions. The prohibition is not a style preference: the owned allocator's registration typically records the object's address, and the owned scope carries a restore obligation tied to one stack position. Duplicating the pair would duplicate the registration's subject or the obligation; moving either would strand one of them. A ScopedAllocator is therefore constructed where its redirection is wanted and destroyed where it should end.

Parameters

ParameterTypeRequirement
argsTypes&&...Whatever TAlloc's own constructor takes — for the tree's uses, the linear and pool allocators' arguments such as a name and a capacity. Forwarded unmodified; nothing here inspects or validates them.

Return value

None; a constructor. On return the calling thread allocates from the owned object until this object's scope ends.

Examples

		using TAlloc = StackAllocator;
		int depthSeed = 0;

		ScopedAllocator<TAlloc> scope0("NestedStack0", 1024);
