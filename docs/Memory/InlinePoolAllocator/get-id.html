GetID

member of hbe::InlinePoolAllocator Engine/Memory/InlinePoolAllocator.h The pool's registration id, or InvalidAllocatorID outside the window in which the pool is registered.

Signature

[[nodiscard]] auto GetID() const

Function description

Defined inline in the class body of Engine/Memory/InlinePoolAllocator.h; it returns id by value, the TAllocatorID (which is int) that RegisterAllocator obtained from MemoryManager::RegisterAllocator(). Two callers inside the class need it — AllocateBytes passes it to MemoryManager::FallbackAllocate so a fallback is attributed to this pool, and both PROFILE_ENABLED reporting calls key on it — and a caller outside the class needs it to open an AllocatorScope on the pool.

The id is InvalidAllocatorID outside the window between registration and deregistration. The default constructor initialises id to InvalidAllocatorID and registration happens later in the same constructor's body, so a pool that died mid-construction reports no id; DeregisterAllocator restores the same value, so a pool that has already been torn down also reports no id and a second pass is a no-op. This is the only "is the pool live" test the class offers.
The id is borrowed and it does not survive the pool. MemoryManager::DeregisterAllocator() returns the proxy record to the manager's free pool, so the number becomes available to the next allocator that registers — the same reuse hazard recorded on PoolAllocator's page, and worse here because these pools are members of temporary containers and register and deregister constantly as those containers are built and destroyed. Keep the value only as long as the pool is alive. Nothing here documents what a stale id resolves to afterwards beyond the manager's own range test (IsValid).

Parameters

None.

Return value

TypeWhat you get
TAllocatorIDThis pool's registration id, or InvalidAllocatorID (-1). It is not a handle, not a lease, and not stable across the pool's destruction.

Examples

auto ptr = mmgr.FallbackAllocate(GetID(), parentID, nBytes);

From Engine/Memory/InlinePoolAllocator.h, hbe::InlinePoolAllocator::AllocateBytes()

The id identifies the pool to the manager while the bytes come from parentID: the fallback is charged to the parent for memory and to this pool for the fallback count.
