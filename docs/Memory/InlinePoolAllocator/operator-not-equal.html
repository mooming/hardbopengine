operator!=

member of hbe::InlinePoolAllocator Engine/Memory/InlinePoolAllocator.h Always true, even for an object compared with itself - the counterpart of an operator that is always false.

Signature

bool operator!=(const InlinePoolAllocator&) const

Function description

Defined inline in the class body of Engine/Memory/InlinePoolAllocator.h. The body is return true; and the parameter is unnamed: nothing is examined. It is the exact counterpart of operator==, which always answers false, so the pair is internally consistent even though neither reports anything about the objects.

A pool is unequal to itself. pool != pool is true. Code that uses inequality as a liveness or identity test — the shape many allocators invite, because an allocator that compares equal is usually the same allocation source — will loop or branch wrongly here. The one honest liveness question this class answers is whether GetID still holds a real registration.
Why both operators are here. Because the class is used as a std::vector and std::basic_string allocator by HInlineVector and HInlineString, and allocator equality is a question the container side has historically been allowed to ask. The engine answers it with two constants rather than implement a comparison it considers meaningless; the effect on container move and swap paths is recorded on operator==.
