GetBlockSize

member of hbe::InlinePoolAllocator Engine/Memory/InlinePoolAllocator.h Objects of type T per block after the pointer-size floor - a compile-time constant, not a measurement.

Signature

[[nodiscard]] static auto GetBlockSize()

Function description

Defined inline in the class body of Engine/Memory/InlinePoolAllocator.h; the body returns ActualBlockSize, which is std::max(BlockSize, sizeof(void*)). The unit is objects of type T, not bytes — the byte figure the pool actually strides by is BlockSizeInBytes, which is sizeof(T) * ActualBlockSize and is not exposed by any accessor. Static, so it is callable on the type with no object, and the answer is a compile-time constant: it reports the template arguments, not anything about the running pool.

This is the number a caller must compare with the template argument. A pool declared InlinePoolAllocator<void*, 4, 8> answers 8, not 4, because a free block has to be wide enough to hold the next-pointer of the free list. Any calculation of capacity that uses the literal BlockSize instead of this answer under-counts the pool. GetNumBlocks is the same idea for the depth, and the two together are as much capacity information as the class gives: see the gap on usage figures.

Parameters

None.

Return value

TypeWhat you get
size_tActualBlockSize — objects of type T that fit in one block, after the sizeof(void*) floor.

Examples

From Engine/Memory/InlinePoolAllocator.cpp, InlinePoolAllocatorTest::Prepare()

The stress harness prints it as the pool's identity, which is the honest use: it distinguishes the eight testlets from one another. It is not a measure of what a request may ask for — allocate takes elements, and the request fails into the parent above ActualBlockSize elements without reporting anything.
