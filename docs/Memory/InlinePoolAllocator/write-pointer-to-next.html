WritePointerToNext

member of hbe::InlinePoolAllocator Engine/Memory/InlinePoolAllocator.h The free list's only encoding: a block that is free stores the address of the next free block inside itself.

Signature

static void WritePointerToNext(void* ptr, void* nextPtr)

Function description

Private and static, defined inline in the class body of Engine/Memory/InlinePoolAllocator.h. It stores nextPtr in the first sizeof(void*) bytes of the block at ptr: 

void** ptrArray = static_cast<void**>(ptr);
auto& pointerToNext = reinterpret_cast<void*&>(ptrArray[0]);
pointerToNext = nextPtr;

From Engine/Memory/InlinePoolAllocator.h, hbe::InlinePoolAllocator::WritePointerToNext()

That is the whole encoding of the free list: a block that is free carries the address of the next free block inside itself, so the pool needs no separate bookkeeping array. Two callers, both inside this class — the constructor links the array block by block (constructors) and terminates the list by writing a null into the last block, and DeallocateBytes writes the current head into a block just before making that block the head.

The link is an address, and that is a statement about where the pool may live. Because the free list stores real pointers rather than offsets, the array must never be relocated: a pool copied byte-for-byte into other storage would keep links pointing into the object it came from. The design is consistent with that constraint — the array is a member of a fixed object, the class declares no move operation, and the copy constructor asserts — but the constraint is real, and it is the reason the pool cannot support the realloc-style growth a pointer-indexed design would allow. PoolAllocator stores an index for exactly that reason; here the storage can never move, so the cheaper encoding is safe.
Two requirements sit outside this function, and it cannot check either. The block must be at least one pointer wide — which is what ActualBlockSize's sizeof(void*) floor guarantees, not BlockSize as written — and the block must be aligned well enough for a pointer store, which the array's alignas(AlignUnit) and the constructor's Assert(OS::CheckAligned(block[0])) are for. What the function does not do is bounds-check or type-check its destination: DeallocateBytes validates with IsValidPointer before writing, but the constructor's linking loop and any future caller write wherever they are told.
