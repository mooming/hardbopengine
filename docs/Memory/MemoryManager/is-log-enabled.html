IsLogEnabled

member of hbe::MemoryManager Engine/Memory/MemoryManager.h The gate every memory diagnostic passes — one config parameter, and hard-coded false in this tree.

Signature

bool IsLogEnabled(ELogLevel level) const

Function description

Defined in Engine/Memory/MemoryManager.cpp as MemoryManager::IsLogEnabled(), and it exists so that a log line can be free: Log asks this first and returns before building anything if the answer is no.

	static TAtomicConfigParam<uint8_t> CPLogLevel("Log.Memory", "The Memory System Log Level",
												  static_cast<uint8_t>(Config::MemLogLevel));

	if (static_cast<uint8_t>(level) < CPLogLevel.Get())
	{
		return false;
	}

	return true;
#else // MEMORY_LOGGING_ENABLED
	return false;
#endif // MEMORY_LOGGING_ENABLED

From Engine/Memory/MemoryManager.cpp, MemoryManager::IsLogEnabled()

Two consequences of writing it this way. The filter compares the ordinal of an ELogLevel (Verbose = 0 through FatalError) against the configured threshold, so a higher threshold silences the chattier levels and the enum's declaration order is the verbosity order — a new enumerator inserted anywhere other than the end changes every filter in the module. And the config parameter is a function-local static: the parameter named "Log.Memory" is not registered with the engine's parameter system until the first call, and its default is Config::MemLogLevel (1 in Engine/Config/EngineConfig.h, i.e. Verbose suppressed, Info and above allowed).

In this repository the answer is always false. MEMORY_LOGGING_ENABLED is 0 in Engine/Config/BuildConfig.h with no per-configuration override, so the whole method compiles to return false;: no memory diagnostic is ever emitted, no "Log.Memory" parameter is ever registered, and every lambda passed to Log, LogWarning or LogError is discarded without being called. That is why the rest of the class is written the way it is — a null return from Allocate on a bad id is "reported" by a line that cannot print.
The check is a filter, not a level mapping. Callers choose the level themselves and there is no per-call-site override: the pool module logs the requests it had to send elsewhere at Warning (LogWarning), its routine detail at Info/Verbose, and its fatal conditions at FatalError — those fatal lines are then filtered too, which is the asymmetry Log documents.
