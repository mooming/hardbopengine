GetGlobalAllocationBytes

member of hbe::MemoryManager Engine/Memory/MemoryManager.h Cumulative bytes requested through the global entry points — a delta measure, and it excludes SystemAllocator's own traffic.

Signature

[[nodiscard]] static size_t GetGlobalAllocationBytes() noexcept

Function description

Defined in Engine/Memory/GlobalAllocation.cpp as MemoryManager::GetGlobalAllocationBytes(): one relaxed load of the globalAllocationBytes atomic that RecordGlobalAllocation grows. It is a size_t total of bytes requested through the replaced operator new over the whole life of the process.

Cumulative, not live — read it as a delta or not at all. Freeing does not reduce it, so the absolute number says nothing about how much memory the process holds. The only meaningful use is the difference across a region of interest, which is what the test harness does (Engine/Test/TestCollection.cpp, TestCollection::RunTestAt()): snapshot, run the testlet, snapshot, subtract, subtract the released bytes, clamp at zero. Subtracting two reads of this getter alone measures "bytes requested in that window", not "bytes still held".
SystemAllocator's own traffic is absent, and that is load-bearing. The counters sit in the replacement operator new, but SystemAllocator::AllocateBytes() calls malloc directly (Engine/Memory/SystemAllocator.h) and is therefore never seen here. Since every pool's backing buffer arrives through the system allocator — PoolAllocator, MonotonicAllocator and StackAllocator each call Allocate with no id, which lands on slot 0 — the bytes a pool bank costs are not in this total either. Attributing them here would charge a pool's bank to whichever testlet happened to trigger the allocation. The two measures are kept apart on purpose: this one counts bytes requested through global entry points, ReportAllocation counts capacity obtained per registered allocator, and the manager's design document is where the profiling side is described.
The OS bucket is a subset, not a second total. Requests whose return address lies inside the macOS shared cache are added to this total and to GetOSAllocationBytes. Engine-only traffic is this minus that, and the harness computes exactly that difference with an unsigned-safe clamp.

Parameters

None.

Return value

TypeWhat you get
size_tCumulative bytes requested through the engine's global allocation entry points since process start. Zero before the first accounted allocation; never decremented; excludes malloc traffic that never passed through operator new.

Examples

const auto globalBytesBefore = MemoryManager::GetGlobalAllocationBytes();
		…
		testlet.Run(logStream);

		…
		const auto globalBytesOverBody = MemoryManager::GetGlobalAllocationBytes() - globalBytesBefore;
		…
		const auto osBytesOverBody = MemoryManager::GetOSAllocationBytes() - osBytesBefore;
		…
		const auto engineBytesOverBody =
				globalBytesOverBody > osBytesOverBody ? globalBytesOverBody - osBytesOverBody : 0;

From Engine/Test/TestCollection.cpp, TestCollection::RunTestAt()

The only reader in the tree. The clamp is not decoration: the two buckets are read as separate relaxed loads rather than sampled together, and RecordAllocation() increments the global total before the OS bucket, so a concurrent allocator can make the OS difference come out above the global difference. Unsigned arithmetic would turn that into a huge number; the clamp turns it into zero.
