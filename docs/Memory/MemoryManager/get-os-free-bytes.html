GetOSFreeBytes

member of hbe::MemoryManager Engine/Memory/MemoryManager.h Bytes released by OS-image callers — bucketed by who frees, not by who allocated.

Signature

[[nodiscard]] static size_t GetOSFreeBytes() noexcept

Function description

Defined in Engine/Memory/GlobalAllocation.cpp as MemoryManager::GetOSFreeBytes(): one relaxed load of the globalOSFreeBytes atomic. Bytes released through the replacement operator delete by a caller whose return address lies inside the macOS shared cache. 

void RecordDeallocation(size_t size, void* caller) noexcept
{
	hbe::MemoryManager::RecordGlobalFree(size);

	if (IsOSImageCaller(caller))
	{
		globalOSFreeBytes.fetch_add(size, std::memory_order_relaxed);
		globalOSFreeCount.fetch_add(1, std::memory_order_relaxed);
	}
}

From Engine/Memory/GlobalAllocation.cpp, RecordDeallocation()

A block is bucketed by who frees it, not by who allocated it. The release path tests the return address of the code calling operator delete, exactly as the allocation path tests its own caller, and nothing anywhere pairs a pointer with its original bucket. So a std::string allocated inside the shared cache and destroyed by engine code adds to GetGlobalFreeBytes and not here, and the pair GetOSAllocationBytes/GetOSFreeBytes is not a live OS-heap figure. Read the two release counters only as "how much releasing this kind of caller did".
The size recorded here is the block, not the request. An unsized operator delete(void*) carries no size, so Deallocate() substitutes OS::GetAllocSize(ptr). The block can be larger than the original request, which is the mechanism behind the release-side overshoot described on GetGlobalFreeBytes — and it applies to this bucket identically, since the same value is what gets added.
