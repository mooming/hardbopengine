Delete

member of hbe::MemoryManager Engine/Memory/MemoryManager.h Destruct then release one element — and a null pointer is a null dereference, not a no-op.

Signature

template <typename Type>
	void Delete(Type* ptr)

Function description

Defined in the class body of Engine/Memory/MemoryManager.h, and the whole body is two statements in a fixed order: 

ptr->~Type();
DeallocateTypes<Type>(ptr, 1);

From Engine/Memory/MemoryManager.h, MemoryManager::Delete()

Destruct first, then release, so the destructor still sees a live object in live memory. The release is DeallocateTypes with a count of one, which recomputes sizeof(Type) and re-reads this thread's scope — so both halves of the pairing (New and Delete) must see the same allocator, and both must name the same type.

A null pointer is a null dereference here, not a no-op. There is no test before ptr->~Type();, and an explicit destructor call through a null pointer is undefined behaviour whatever the type. This is the opposite of Deallocate, which ignores a null block and asserts its size was zero, and of SysDeallocate, which lets the underlying free(nullptr) absorb it. A caller that wants "delete if present" must write the test itself.
Deleting through a base pointer is wrong twice. Type decides both statements independently: it picks which destructor runs (so a non-virtual base destructor is undefined behaviour, as ever) and it picks the byte count handed to the allocator, because DeallocateTypes computes 1 * sizeof(Type). An object created by New<Derived> took sizeof(Derived) bytes from the allocator, so Delete<Base> releases a smaller count — and a size mismatch is precisely what corrupts a pool's bookkeeping (Deallocate, ReportDeallocation). Pass the type you created.
The destructor runs before the memory is handed back, and nothing protects it afterwards. DeallocateTypes does not clear the caller's pointer, and the manager keeps no record of live blocks (the reports it receives are counters), so the pointer dangles in exactly the way an ordinary delete leaves one. A destructor that throws is not caught: the block would already have been claimed by the allocator, and the release never happens.

Parameters

ParameterTypeRequirement
Typetemplate parameterThe type the object was created as by New. It determines the destructor and the release size, so a base-class spelling breaks both.
ptrType*A live object from New, non-null, allocated from the allocator that is current now. Never a new-created object: the release would go to a pool that never saw it.

Return value

void. Nothing is reported and nothing is cleared; the caller's pointer becomes dangling rather than null.
