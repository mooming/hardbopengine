GetGlobalFreeCount

member of hbe::MemoryManager Engine/Memory/MemoryManager.h Cumulative releases through the global entry points — the denominator a window's request count is read against.

Signature

[[nodiscard]] static uint64_t GetGlobalFreeCount() noexcept

Function description

Defined in Engine/Memory/GlobalAllocation.cpp as MemoryManager::GetGlobalFreeCount(): one relaxed load of the globalFreeCount atomic. Cumulative number of releases that reached the engine's replacement operator delete family since process start.

Every form funnels through the same accounting call, including those that carry extra parameters: the sized, aligned and nothrow overloads all arrive at the file's single Deallocate(), so a release is counted once whatever the calling convention was. A null pointer is the one case that is not — Deallocate() tests ptr != nullptr first, so a no-op delete of a null pointer neither counts nor records bytes.

A release with no recorded allocation still increments this. Nothing pairs a pointer with the request that produced it, so a block allocated before these counters existed, or by a malloc outside that translation unit, raises this count without ever having raised GetGlobalAllocationCount. That is the accepted cost of cumulative counters; the alternative, a per-pointer ledger, would have to allocate from inside operator delete.
Requests and releases are counted; retention is derived from bytes. The harness prints the release count beside the request count but sets its per-testlet ceiling on retained bytes (Engine/Test/TestCollection.cpp, TestCollection::RunTestAt()), because an unsized delete inflates the byte side through the block size it reports (GetGlobalFreeBytes) while the count side stays exact. The two counts are the leak-shaped signal; the byte difference is the number a ceiling can be enforced against.
