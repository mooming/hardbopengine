GetInstance

member of hbe::MemoryManager Engine/Memory/MemoryManager.h The one instance, as a reference — and a fatal abort, not a null, once it is gone.

Signature

static MemoryManager& GetInstance()

Function description

Defined in Engine/Memory/MemoryManager.cpp as MemoryManager::GetInstance(), and the whole body is FatalAssert(mmgrInstance != nullptr); followed by return *mmgrInstance;. The pointer it reads is a file-scope static in that same translation unit, not a member, and it is written by exactly two places: the constructor, which publishes this after asserting the slot was empty, and the destructor, which clears it.

Absence is an abort, never a null. FatalAssert flushes the logs, prints its message, calls debugBreak() and then std::abort() (Engine/Core/Debug.h) — in every configuration, including Release, unlike Assert, which compiles away there. So a call before the engine's MemoryManager member is constructed, or after it is destroyed, is not a value you can test for. The only guard the engine offers is Engine::IsMemoryManagerReady(), set by the constructor's last act (Engine/Engine/Engine.h).
Usable earlier than the engine is initialised. Because Engine::memoryManager is an ordinary member (Engine/Engine/Engine.h), it is constructed as part of Engine::Engine() — before Engine::Initialize() runs, and before logger, statistics and taskSystem exist. Every allocator in the module assumes the window is open and calls GetInstance() from its own constructor (Engine/Memory/MonotonicAllocator.cpp, MonotonicAllocator::MonotonicAllocator(); Engine/Memory/InlinePoolAllocator.h, InlinePoolAllocator::RegisterAllocator()). What is not ready during that window is the logger: the constructor's own cache load logs while Engine::isLoggerReady is still false.

The returned reference is to the manager itself, never a copy — the class deletes both the copy constructor and copy assignment precisely because two objects would fight over mmgrInstance. The reference is valid for as long as the Engine object, which in every application in this repository is a static-lifetime object, so storing it for a process's whole life is what the allocators do.

Parameters

None.

Return value

TypeWhat you get
MemoryManager&The single instance. Non-null by construction: a null instance aborts inside this call instead of producing a reference to test. Its lifetime is Engine's.

Examples

auto& mmgr = MemoryManager::GetInstance();
auto newBody = mmgr.New<Body>(std::forward<Types>(args)...);

From Engine/Memory/Shareable.h, Shareable<TType, RefCount>::Body::Create()

The dominant shape in the engine: take the instance, then use the typed New/Delete pair on it. There are over thirty such sites; the allocators reach the manager the same way to register themselves (Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::MultiPoolAllocator()) and to report what they handed out (ReportAllocation).
