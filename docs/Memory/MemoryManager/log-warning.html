LogWarning

member of hbe::MemoryManager Engine/Memory/MemoryManager.h Log at Warning — the level every allocator uses for a request it had to send elsewhere.

Signature

void LogWarning(const TLogFunc& func) const

Function description

Defined in the class body of Engine/Memory/MemoryManager.h — the whole definition is Log(ELogLevel::Warning, func);, so the call inlines into every includer and there is no .cpp half. It fixes one thing about Log: the level.

ELogLevel::Warning is the fourth ordinal in Engine/Log/LogLevel.h, above the Verbose/Info band that the default "Log.Memory" threshold of Config::MemLogLevel (1) suppresses, so once memory logging is enabled a warning is one of the levels that reliably gets through IsLogEnabled. That is what makes it the right level for the module's most common notable event: a request this allocator could not serve and had to send somewhere else.

The parameter is a const TLogFunc&, unlike Log's by-value one. The caller still converts its lambda to a std::function at the call site — that cost is paid either way — but the wrapper itself is not constructed twice, and the referenced temporary lives to the end of the full expression, which is all Log needs.
Every warning in this module is discarded in a build of this repository. The gate is MEMORY_LOGGING_ENABLED, not the level, and Engine/Config/BuildConfig.h sets it to 0. So "warn the caller that this block is not coming from the pool they thought it was" currently means: do the forwarding, and record nothing. The flag LOG_BREAK_IF_WARNING in Engine/Config/BuildConfig.h is likewise 0, so a warning that does get printed in another build does not trap either.

Parameters

funcconst TLogFunc&A std::function<void(std::ostream&)> — normally a lambda capturing what the line needs. Invoked at most once, and only when the level passes.

Examples

const auto freeSize = GetAvailable();
if (unlikely(size > freeSize))
{
	auto& mmgr = MemoryManager::GetInstance();
	mmgr.LogWarning([size, freeSize](auto& ls)
	{ ls << "The requested size " << size << " is exceeding its limit, " << freeSize << '.'; });

	auto ptr = mmgr.Allocate(parentID, requested);

	return ptr;
}

From Engine/Memory/MonotonicAllocator.cpp, MonotonicAllocator::Allocate()

The module's characteristic use: an allocator that has to fall back to its parent says so at Warning rather than failing, and the same shape appears in InlineMonotonicAllocator::Allocate(). Note that the message names no allocator — the id is not captured — so even when it prints it can only be attributed by reading the surrounding log lines.
