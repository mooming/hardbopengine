PostEngineInit

member of hbe::MemoryManager Engine/Memory/MemoryManager.h An empty hook with one caller — the manager's post-start-up seam, and today it does nothing.

Signature

void PostEngineInit() noexcept

Function description

Defined in Engine/Memory/MemoryManager.cpp as MemoryManager::PostEngineInit(), and the body is empty — a pair of braces and nothing else. The noexcept is therefore trivially satisfied, and the call has no observable effect in any configuration, because there is no preprocessor branch inside it either.

What it owns is a position in the start-up order. Engine::PostInitialize() calls it, and that is the only call site, so the manager is given one hook that runs after construction (MemoryManager) and after Engine::Initialize() has brought the other subsystems up. Everything the manager actually needs for its own setup it performs in the constructor: slot 0 and the configuration cache. Nothing has yet needed a second phase.

It is a seam, not a no-op bug. The two hooks this class exposes to the engine's lifecycle are this method and PreEngineShutdown, called from Engine::PostInitialize() and Engine::PreShutdown() respectively. Anything the manager must do once a logger exists can only go here, because the constructor runs while Engine::logger has not been constructed yet (the constructor says why that matters). No such work is written today.
Named omission: what this hook is for. No source, comment or test states an intended use for an empty post-init beyond its position in the start-up order, and no test asserts that it runs. The page says only what the code shows — an empty noexcept body with one caller — and does not guess at the design intent.

Parameters

None.

Return value

void. No failure is possible and none is reported.
