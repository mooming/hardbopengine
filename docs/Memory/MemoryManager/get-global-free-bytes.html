GetGlobalFreeBytes

member of hbe::MemoryManager Engine/Memory/MemoryManager.h Cumulative bytes released globally — retention is this subtracted from the requested total, clamped at zero.

Signature

[[nodiscard]] static size_t GetGlobalFreeBytes() noexcept

Function description

Defined in Engine/Memory/GlobalAllocation.cpp as MemoryManager::GetGlobalFreeBytes(): one relaxed load of the globalFreeBytes atomic that RecordGlobalFree grows. Cumulative bytes released through the engine's replacement operator delete over the life of the process.

This total can legitimately be larger than the one it is subtracted from. The unsized operator delete(void*) carries no size, so the release path asks the system heap what the block actually was — RecordDeallocation(size != 0 ? size : OS::GetAllocSize(ptr), caller); in Deallocate() — and a block is never smaller than what was asked for. Retention is therefore derived, never tracked: GetGlobalAllocationBytes minus this, clamped at zero, and the clamp exists precisely because the subtraction is unsigned and the two totals are not guaranteed to be ordered.
Nothing outside the replaced operators is counted here. std::free called directly — which is what SystemAllocator::DeallocateBytes() does (Engine/Memory/SystemAllocator.h) — never reaches this counter, and neither does a block released by an allocator that owns it. This is the release-side mirror of the rule stated on GetGlobalAllocationBytes: the two global counters describe the operator new/operator delete pair only, and the per-allocator statistics are a separate measure entirely.

Retention per testlet, computed from four clamped differences. It is the only quantity in this family that a ceiling is set against: a stress loop may request a great deal while holding almost none of it, and only the requested-minus-released difference separates that from a leak of the same size.
