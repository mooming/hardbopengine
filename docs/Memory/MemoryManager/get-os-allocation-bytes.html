GetOSAllocationBytes

member of hbe::MemoryManager Engine/Memory/MemoryManager.h Global bytes whose caller sits inside the macOS shared cache — a bucket inside the global total, zero everywhere else.

Signature

[[nodiscard]] static size_t GetOSAllocationBytes() noexcept

Function description

Defined in Engine/Memory/GlobalAllocation.cpp as MemoryManager::GetOSAllocationBytes(): one relaxed load of the globalOSAllocationBytes atomic. Bytes requested through the global entry points by a caller whose return address lies inside the macOS shared cache.

The bucket is filled by RecordAllocation() in that file, and nothing else: 

void RecordAllocation(size_t size, void* caller) noexcept
{
	hbe::MemoryManager::RecordGlobalAllocation(size);

	if (IsOSImageCaller(caller))
	{
		globalOSAllocationBytes.fetch_add(size, std::memory_order_relaxed);
		globalOSAllocationCount.fetch_add(1, std::memory_order_relaxed);
	}
}

From Engine/Memory/GlobalAllocation.cpp, RecordAllocation()

caller is __builtin_return_address(0) evaluated inside the replacement operator new, which is therefore the address of whatever called operator new — a libc++ function growing a std::string or a std::vector on Apple platforms typically. IsOSImageCaller() resolves the shared cache range once, lazily, through _dyld_get_shared_cache_range, caches base and size in two atomics published by a queried flag, and then answers address - base < size.

A bucket inside the global total, not a second total — and zero off Apple. Every OS-bucket request is also in GetGlobalAllocationBytes, because the global call happens first and unconditionally. Engine-owned traffic is the global figure minus this one, and that subtraction is the only reason the bucket exists: without it, a libc++ reallocation inside the shared cache is charged to whichever testlet happened to trigger it. Off __APPLE__ the macro hands the accounting a null caller and IsOSImageCaller returns false unconditionally, so all four OS counters stay 0 on Linux and Windows builds.
The answer is "who called operator new", not "who needed the memory". Attribution is a return-address range test only. Code that lives in the shared cache may be allocating on behalf of the engine — a std::string member of an engine object is the plain case — and that traffic is in this bucket all the same. What the page does not claim, because no source states it, is a rule for deciding which OS-bucket bytes were "really" engine memory; see this class's Coverage table.

Examples

const auto osBytesBefore = MemoryManager::GetOSAllocationBytes();

std::string grow;

for (int i = 0; i < 4096; ++i)
{
	grow.push_back('y');
}

const auto osBytesAfter = MemoryManager::GetOSAllocationBytes();

if (osBytesAfter - osBytesBefore < grow.size())
{
	ls << "The OS bucket did not see the string growth bytes" << lferr;
}
