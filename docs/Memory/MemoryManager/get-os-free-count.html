GetOSFreeCount

member of hbe::MemoryManager Engine/Memory/MemoryManager.h Release count for the OS-image bucket — attributed by the freeing call site, not the allocating one.

Signature

[[nodiscard]] static uint64_t GetOSFreeCount() noexcept

Function description

Defined in Engine/Memory/GlobalAllocation.cpp as MemoryManager::GetOSFreeCount(): one relaxed load of the globalOSFreeCount atomic, incremented in the same block as GetOSFreeBytes whenever IsOSImageCaller() accepts the caller of a replaced operator delete. The two OS release counters therefore never disagree about which releases were counted; they disagree only about what each release was worth in bytes.

As on every other member of this family, attribution is by the releasing call site rather than by the block's history (GetOSFreeBytes), the counters are cumulative and never decrement, and the whole bucket is permanently 0 on a build that does not define __APPLE__.

What a request-versus-release comparison in this bucket can and cannot tell you. GetOSAllocationCount minus this is not outstanding OS memory, because a block allocated by OS code is not required to be freed by OS code. The pair is a measure of how much shared-cache code allocated versus how much it freed, which is a meaningful pairing for a single library's own traffic and a misleading one across the whole process.
