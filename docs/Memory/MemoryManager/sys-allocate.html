SysAllocate

member of hbe::MemoryManager Engine/Memory/MemoryManager.h Slot 0 directly, bypassing the scoped id — for a block a pool should not be made to hold.

Signature

void* SysAllocate(size_t nBytes)

Function description

Defined in Engine/Memory/MemoryManager.cpp as MemoryManager::SysAllocate(). It reaches slot 0 by name — auto& allocator = allocators[SystemAllocatorID]; — and calls through it, so it bypasses three things that Allocate performs: the range check, the thread's scoped allocator, and the FORCE_USE_SYSTEM_MALLOC substitution (which would be a no-op here anyway). 

auto& allocator = allocators[SystemAllocatorID];
	if (unlikely(allocator.allocate == nullptr))

		// … the fatal-error message lambda …
		});

		return nullptr;
	}

	return allocator.allocate(&allocator, nBytes);

From Engine/Memory/MemoryManager.cpp, MemoryManager::SysAllocate()

The userData handed to the function pointer is &allocator — the proxy slot itself, not the proxy's allocator field. That is safe only because the two lambdas installed by RegisterSystemAllocator ignore their first parameter and close over a function-local SystemAllocator<uint8_t> instead; a registration that used its userData would be handed the wrong object on this path.

What "system" means at the bottom of the stack. Slot 0's allocate function ends in SystemAllocator<uint8_t>::AllocateBytes() (Engine/Memory/SystemAllocator.h): malloc(nBytes) in this tree, or page-granular OS::VirtualAlloc with the block placed at the tail of the reservation when MEMORY_INVESTIGATION_ENABLED is on. Under PROFILE_ENABLED it reports the capacity OS::GetAllocSize(ptr) obtained — that is the traffic behind SystemStatistics::ReportSysMemAlloc (ReportAllocation). These bytes never appear in the global counters, because they go through malloc and not through the replaced operator new.
Zero is not normalised, and a null result is a log rather than a stop. Allocate answers size == 0 with nullptr before doing anything else; this method passes 0 straight through to malloc, whose answer for a zero-byte request is implementation-defined. Nor is the result checked: where Allocate carries Assert(ptr != nullptr, "Allocation Failed"), this returns whatever came back. The only internal guard is the null function pointer test above, which logs at FatalError and returns null — after a deregistration or before the constructor has reached slot 0. Callers here do not check either: LogLine::LogLine() copies into the returned pointer immediately.
Use it for what a pool should not hold. The unsized Allocate(size_t) goes to this thread's scoped allocator, which is usually somebody's pool — a pool that cannot return a block until it is destroyed, and that dies with its owner. A block that must outlive scopes, or that is too big to belong to one, is what this entry point is for; its partner SysDeallocate is the only correct release, because Deallocate(ptr, n) would route by the ambient scope.

Parameters

ParameterTypeRequirement
nBytessize_tByte count, passed unchanged to the system allocator. Unlike Allocate, no zero-size special case and no alignment guarantee beyond malloc's.

Return value

TypeWhat you get
void*Raw storage from the system heap; nullptr if slot 0 has no allocate function, and possibly for a zero-byte request. Must be released with SysDeallocate and the same size.

Examples

auto& mmgr = engine.GetMemoryManager();
longTextSize = size + 1;
longText = (char*) mmgr.SysAllocate(longTextSize);
std::copy(&inText[0], &inText[longTextSize], longText);

From Engine/Log/LogLine.cpp, LogLine::LogLine()

A log line longer than the inline buffer: its lifetime is the log record's, not the emitting thread's scope, so it cannot live in whatever pool happens to be current — and at shutdown the matching release, LogLine::~LogLine()'s mmgr.SysDeallocate(longText, longTextSize);, runs long after those scopes are gone. It is the only call site of this pair outside the module.
