GetGlobalAllocationCount

member of hbe::MemoryManager Engine/Memory/MemoryManager.h How many requests reached the global entry points — the figure a testlet compares before and after its body.

Signature

[[nodiscard]] static uint64_t GetGlobalAllocationCount() noexcept

Function description

Defined in Engine/Memory/GlobalAllocation.cpp as MemoryManager::GetGlobalAllocationCount(): a single relaxed load of the globalAllocationCount atomic. It is the number of requests that reached RecordGlobalAllocation since process start — one per operator new, operator new[] and their aligned and nothrow forms — and it is the figure the test harness compares before and after a testlet body.

A request is counted even when no byte is requested, and a failed request is not counted at all. The zero-size normalisation is applied to the allocation and not to the accounting: RecordAllocation(size, caller) is handed the caller's size, so a zero-byte operator new adds nothing to GetGlobalAllocationBytes but does add one here. On the other side, when malloc returns null the loop either gives an installed new_handler its turn or reports and aborts, and RecordAllocation is reached only after a successful allocation — so this counts allocations that succeeded, not calls that were made.
64-bit where the byte total is size_t. Both widths are what the declarations say; the pairing that matters for a caller is GetGlobalFreeCount, which is uint64_t as well, so a request-versus-release comparison never widens or truncates.

Parameters

None.

Return value

TypeWhat you get
uint64_tCumulative successful requests through the global allocation entry points. Cumulative in the same sense as the byte total: a release never reduces it.

Examples

const auto totalBefore = MemoryManager::GetGlobalAllocationCount();

grow.push_back('y');

const auto totalAfter = MemoryManager::GetGlobalAllocationCount();

if (totalAfter <= totalBefore)
{
	ls << "OS image traffic bypassed the global total" << lferr;
}
