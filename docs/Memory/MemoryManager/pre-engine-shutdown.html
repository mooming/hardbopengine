PreEngineShutdown

member of hbe::MemoryManager Engine/Memory/MemoryManager.h The one call site of SaveMultiPoolConfigs — and under this tree's PROFILE_ENABLED it is an empty body.

Signature

void PreEngineShutdown() noexcept

Function description

Defined in Engine/Memory/MemoryManager.cpp as MemoryManager::PreEngineShutdown(), and its entire body is one guarded call: 

#if PROFILE_ENABLED
	SaveMultiPoolConfigs();
#endif // PROFILE_ENABLED

From Engine/Memory/MemoryManager.cpp, MemoryManager::PreEngineShutdown()

Engine/Config/BuildConfig.h defines PROFILE_ENABLED as 0 with no per-configuration override, so in every build of this repository the function compiles to an empty noexcept body: the multi-pool geometry measured during the run is not written anywhere, and the next run reads whatever the previous profiled run left behind.

Only what has already been reported is saved, and most pools have not reported yet. SaveMultiPoolConfigs serialises multiPoolConfigLog — the table that ReportMultiPoolConfigutation appends to — and this is its only call site. A multi-pool reports from its own destructor (Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::~MultiPoolAllocator() calls ReportConfiguration()), which runs during ~Engine, i.e. after the Engine::PreShutdown() call that lands here. The one pool that is in the file is the logger's: Engine::PreShutdown() calls logger.ReportMemoryConfiguration() immediately before this method, which is the ordering that makes the cache useful at all. Anything else that reports from a destructor appends its entry after the write and loses it with the manager.
"Pre" means before member destruction, not before teardown. The call site is Engine::PreShutdown(), while allocators are still alive and still registered — which is what allows a report made from here to reach the file at all. The manager's own teardown is ~MemoryManager, a separate and later event, reached through member destruction rather than through this hook.

Parameters

None.

Return value

void. A failed write is logged by SaveMultiPoolConfigs and does not change anything the caller can see.

Examples

void Engine::PreShutdown()
{
	using namespace StringUtil;
	auto log = Logger::Get(ToCompactMethodName(__PRETTY_FUNCTION__));

	log.Out("Engine PreShutdown [Start]");

#if PROFILE_ENABLED
	logger.ReportMemoryConfiguration();
#endif // PROFILE_ENABLED

	memoryManager.PreEngineShutdown();

	log.Out("Engine PreShutdown [Done]");
}

The single caller, and the whole of the ordering: report first, save second, both guarded by the same macro. Read together with the gap above, this is the pair of lines that decides which allocators' geometry survives a run.
