GetName

member of hbe::MemoryManager Engine/Memory/MemoryManager.h The literal "MemoryManager" — an assert-prefix helper, not a logger category and not the allocator-name getter.

Signature

static const char* GetName()

Function description

Defined in Engine/Memory/MemoryManager.cpp as MemoryManager::GetName(), and the body is return "MemoryManager"; — a string literal, not a member, not a StaticString, and not configurable. It is the class's own name, nothing more.

Its one use in the module is to build a diagnostic prefix on the dispatch path: Assert(allocProxy.allocate != nullptr, "[", GetName(), "::", __func__, "][Error] ", "No allocate function, ID = ", id); in Allocate. Every other message in the class either hard-codes its own prefix or omits one, so the string is not a logging contract: Log lines are written by the call site's lambda and the manager's name appears in them only when the author typed it.

Not a logger category, and not the allocator-name getter. The logging entry points reach the engine's logger through Log and its level filter (IsLogEnabled), which never consults this name. And it is a different function from AllocatorProxy::GetName(), which answers "NoName" or a stored AllocStats::name, and from GetAllocatorName, which answers per registered allocator. Three "names" in one module, three different sources of truth.
Static, and const char* into static storage. Safe to hold for the life of the process, safe to call before an instance exists — there is no this, no allocation and no initialisation order dependency, unlike nearly everything else in the class.

None.

Return value

Examples

From Engine/Memory/MemoryManager.cpp, MemoryManager::Allocate()

The only call site in the repository, and a small lesson in why the rest of the class does not use it: the matching release path writes its prefix by hand and gets it wrong — Assert(allocProxy.deallocate != nullptr, "[MemoryManager::Allocate][Error] No allocate function, ID = ", id); in Deallocate says Allocate inside a deallocation failure. A prefix built from this function cannot drift like that.
