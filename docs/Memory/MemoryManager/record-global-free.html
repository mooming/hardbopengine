RecordGlobalFree

member of hbe::MemoryManager Engine/Memory/MemoryManager.h The release half of the global accounting, cumulative like the allocation side, so nothing is ever validated against its allocation.

Signature

static void RecordGlobalFree(size_t nBytes) noexcept

Function description

Defined in Engine/Memory/GlobalAllocation.cpp as MemoryManager::RecordGlobalFree(): a relaxed fetch_add of nBytes into globalFreeBytes and of 1 into globalFreeCount. Like the allocation side it is noexcept, touches nothing but those two atomics, never logs and never allocates.

Every replaced operator delete in that file reaches it through one shared release function, Deallocate(), and that is where the size argument is decided: 

if (ptr != nullptr)
{
	RecordDeallocation(size != 0 ? size : OS::GetAllocSize(ptr), caller);
	std::free(ptr);
}

From Engine/Memory/GlobalAllocation.cpp, Deallocate()

The unsized operator delete(void*) — the form most generated code calls — arrives with no size at all, so the release path asks the system heap how large the block really is. The consequence a reader of the byte totals must carry: OS::GetAllocSize reports the block, which can be larger than what was requested, so GetGlobalFreeBytes can legitimately outrun GetGlobalAllocationBytes even with no bug anywhere.

Cumulative on both sides, so a release is never validated against its allocation. Nothing here pairs a pointer with the request that produced it, and nothing subtracts, so a block allocated before these counters existed — or by a malloc outside this translation unit — can be released without driving any figure negative. It simply increments a total whose matching request was never recorded. The engine's only defence against that asymmetry is at the reader end: the test harness clamps each difference at zero (Engine/Test/TestCollection.cpp, TestCollection::RunTestAt()).

Parameters

nBytessize_tThe size being released — for an unsized delete, the block size the system heap reported rather than anything the caller knew.

Return value

void. The counters only ever grow, so there is no underflow to report.

The harness brackets every testlet with the four global getters and derives retained bytes as requested-minus-released, clamped at zero, which is the number a per-testlet allocation ceiling is compared against. No production call site exists: Deallocate() in Engine/Memory/GlobalAllocation.cpp is the only caller.
