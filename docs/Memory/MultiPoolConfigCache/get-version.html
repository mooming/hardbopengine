GetVersion

member of hbe::MultiPoolConfigCache Engine/Memory/MultiPoolConfigCache.h static nodiscard the one format version this build writes and the only one it accepts

Signature

[[nodiscard]] static auto GetVersion()

Function description

Defined in the class body of Engine/Memory/MultiPoolConfigCache.h. Its whole purpose is to be the public window onto a private constant: version is declared static constexpr TVersion version = 0; in the private section, and this returns it by value. The declared return type is auto, so what a caller actually gets is TVersion — uint32_t — not a reference and not the constant's own type identity.

It is used once, by Serialize, which streams GetVersion() as the second field of the file, immediately after the class-name tag from GetClassName.

The reader does not ask this function. Deserialize compares the number it read against the private version constant directly, not against GetVersion(). Both name the same constant, so the two paths cannot disagree today — but it means the accessor is a convenience for the writer and for outside callers rather than the single source the format's version flows through.

There is exactly one version this build accepts, and accepting another is not implemented. A mismatch is an Error log naming the read number and a false return: the file is ignored, not upgraded, not migrated, not partially read. So bumping version is the whole of the format-change story — every existing .multiPoolConfig.dat becomes dead weight, and the next run relearns its bank sizes by demand. Nothing in the file records which version a human should migrate from.

Parameters

None.

Return value

TypeWhat you get
auto, deduced to TVersion (uint32_t)The format version this build writes and the only one it reads: 0. Marked [[nodiscard]], and it is static, so it answers without an instance.

Examples

The one call site, writing the field a later load will compare against:

bos << GetVersion();

From Engine/Memory/MultiPoolConfigCache.cpp, MultiPoolConfigCache::Serialize

On the other side, Deserialize reads the field into a local TVersion inVersion = 0 and refuses the file unless it equals version. Together the two lines are the engine's entire forward-compatibility policy for this file: write the number, refuse anything that does not carry the same number.
