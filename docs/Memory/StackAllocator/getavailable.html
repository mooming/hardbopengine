GetAvailable

member of hbe::StackAllocator Engine/Memory/StackAllocator.h nodiscard capacity - cursor: bytes left in the buffer, never counting the parent that the overflow path can still reach.

Signature

[[nodiscard]] size_t GetAvailable() const

Function description

Defined in Engine/Memory/StackAllocator.cpp as StackAllocator::GetAvailable() const. Two lines: an assertion that the cursor never ran past the buffer, then the subtraction. 

Assert(capacity >= cursor);

return capacity - cursor;

From Engine/Memory/StackAllocator.cpp, StackAllocator::GetAvailable() const

Both operands are buffer properties, so this is the space left in this buffer and nothing else: capacity is the constructor argument already rounded up to a multiple of Config::DefaultAlign, and cursor is the bytes charged against it by Allocate. The same pair of lines is what Allocate itself consults before deciding whether to serve a request or hand it to the parent.

Zero available does not mean allocation fails, so this is not a capacity-to-allocate figure. Allocate answers a request this number cannot cover by calling MemoryManager::FallbackAllocate(GetID(), parentID, requested). An allocator reporting 0 available will still hand out memory — from the parent, outside this buffer, and invisible to both this function and GetUsage(). Use this number to reason about where the next block will come from, not about whether one will.
The last partial alignment unit of a buffer is not reachable through this number. The comparison in Allocate is size > freeSize where size is the rounded request and freeSize is exactly what this function returns. With 10 bytes available, a request of 10 rounds to 16, and 16 is greater than 10, so the request goes to the parent. A partially-consumed buffer therefore reports a small non-zero availability that no caller can ever use up.
The assertion is the only place a cursor overrun would be caught. Assert(capacity >= cursor) is the reason a corrupted cursor is visible at all in a checked build; in Release, hbe::Assert (Engine/Core/Debug.h) is an empty inline function and the subtraction simply wraps to a huge value that Allocate would read as "plenty of space left". See Coverage for the zero-capacity case, which the strict form of the sibling assertion makes interesting.

From Engine/Memory/StackAllocator.cpp, StackAllocatorTest::Prepare(), Nested Usage testlet

The engine's only real use of this function is the nested-scope testlet, which prints the availability of every open stack at each level of a six-deep ScopedAllocator nesting to show a New<long double> at the innermost level charging only the innermost stack. It is a diagnostic reading, which is what this function is good for: it answers a question about one buffer, and no question about anything else.
