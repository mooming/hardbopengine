GetSize

member of hbe::StackAllocator Engine/Memory/StackAllocator.h static Always answers 0: a stack cannot recover a block's size from a bare pointer, and says so by returning zero.

Function description

Declared and defined entirely in the class body of Engine/Memory/StackAllocator.h. It names no parameter, ignores the one it is given, and answers 0. The header writes "Not Supported" above it — the only remaining trace of the explanation this page exists to replace. 

static size_t GetSize(Pointer)
{
	return 0;
}

From Engine/Memory/StackAllocator.h, class StackAllocator

The answer is a consequence of the representation, not an oversight. A stack records nothing per block: Allocate moves cursor and stores no size, no header and no footer, so no information recoverable from a bare Pointer exists to be reported. That is exactly why Deallocate demands the byte count as a parameter — the caller is the only place that number survives.

The stub is indistinguishable from a real answer, and there is no way to tell it is a stub. The return type is size_t and the failure value is 0, the same value a caller would receive for a block of zero bytes. A caller that treats GetSize(ptr) == 0 as "this block is empty" or as "the allocator does not know" has read a meaning into the number that the function never claimed to carry. Compare PoolAllocator::GetSize, which answers the real block size from the pool's geometry and is [[nodiscard]]; this one is neither.
It is static, so it answers the same for every stack and needs no object. No instance is required to call it, which is a clue to its content: nothing here reads buffer, capacity, cursor or the registration id. It is present because allocator-shaped classes in this module carry a GetSize, not because a stack can answer the question.
No caller in the tree. The only allocator GetSize call site in the repository is PoolAllocatorTest::Prepare() in Engine/Memory/PoolAllocator.cpp, asking a PoolAllocator. Whether this function exists to satisfy a future common allocator interface or is simply inherited habit is not recorded anywhere in the source; see Coverage.

No code asks a StackAllocator — not the engine, not the applications, and not the class's own testlets in Engine/Memory/StackAllocator.cpp. A caller who needs a block's size has to keep the number it passed to Allocate.
