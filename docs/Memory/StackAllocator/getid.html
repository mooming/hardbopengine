Module Index / Memory / StackAllocator / GetID

GetID

member of hbe::StackAllocator Engine/Memory/StackAllocator.h nodiscard The registration id the manager keys this stack by, and the handle an AllocatorScope is opened with.

Signature

[[nodiscard]] auto GetID() const

Function description

Declared and defined in the class body of Engine/Memory/StackAllocator.h: it returns id, so the deduced return type is TAllocatorID (int, Engine/Memory/AllocatorID.h) by value. Because the body lives in the header it inlines into every includer; the rest of the class is in Engine/Memory/StackAllocator.cpp. The value is whatever MemoryManager::RegisterAllocator() returned to the constructor — a slot index in the manager's allocator table, in the range 0 to MaxNumAllocators - 1 (256).

This is the handle a caller needs to make the stack the current allocator. Every use the repository makes of it opens an AllocatorScope over the value: AllocatorScope scope(stack.GetID());, after which containers built in that scope allocate and release through this object without naming it. The class also uses it on itself — Allocate passes it as the first argument of MemoryManager::FallbackAllocate(GetID(), parentID, requested), and the destructor hands it to MemoryManager::DeregisterAllocator.
The number is recycled the moment the object dies, so an id you keep has a shelf life. MemoryManager::DeregisterAllocator() (Engine/Memory/MemoryManager.cpp) clears the proxy's function pointers and ends proxyPool.Push(allocator);, which makes the same index available to the next allocator registered. A value held past this object's destruction addresses whoever received that slot next, and the manager's only guard on the allocation and release paths is the range check IsValid(id). In this configuration the leak-checking early return that would have withheld the id sits inside #if PROFILE_ENABLED, which is 0, so recycling is unconditional here.
InvalidAllocatorID is a state that can persist, and it does not mean the stack owns nothing. The constructor initialises id to InvalidAllocatorID (-1) before the registration call, and a registration failure leaves it there: MemoryManager::RegisterAllocator() logs a FatalError and returns InvalidAllocatorID when its proxy pool is empty (MaxNumAllocators registrations already live). Unlike a pool, this class has no early return on that path — the buffer was already taken and is still held, so an invalid id here means "unregistered but holding memory", and the destructor will still return that buffer and then ask the manager to deregister an id the manager will reject with an Error log. No testlet drives either allocator to that state; see Coverage.

Parameters

None.

Return value

TypeWhat you get
auto, deduced as TAllocatorID (int)The registration id, or InvalidAllocatorID (-1) when registration failed. Valid values are 0 <= id < MaxNumAllocators per hbe::IsValid. The attribute is [[nodiscard]].

From Engine/Memory/StackAllocator.cpp, StackAllocatorTest::Prepare()

The whole of the engine's usage in one line: the id turns an ordinary allocator object into the thread's current one for the lifetime of a scope. Note the declaration order the destructor depends on — stack is declared before scope, so the scope closes first and the buffer is returned while the allocator that supplied it is still current.
