operator*

member of hbe::Shareable Engine/Memory/Shareable.h The pointer-handle spelling of Get: the same shared object by reference, with the same two hazards.

Signature

[[nodiscard]] TType& operator*()

[[nodiscard]] const TType& operator*() const

Function description

The pointer-handle spelling of Get, and byte for byte the same function: two overloads defined inline in the class body of Engine/Memory/Shareable.h, each returning body->GetBody(); — a reference to the data member of the shared Body. Whatever is true of Get is true here, including the two that matter most: neither overload tests body, so an empty handle is undefined behaviour, and the non-const overload hands out a mutable reference to an object that other handles may share, with the copy-on-write policy left entirely to the caller (GetReferenceCount is the input that policy reads).

Two spellings, one contract — and the tree uses both. hbe::String reaches the same object through this operator where it wants an element ((*buffer)[0], (*buffer)[i]) and through Get where it wants the container (buffer.Get().data()). Neither is preferred by anything in the source; the difference is readability at the call site, not behaviour.

Examples

From Engine/String/String.cpp, String::Clone

Both overloads at once, and the pattern this operator exists for: a brand-new String whose handle owns a fresh, unshared buffer, and a fresh assertion that the allocation succeeded. *(str.buffer) is the mutable overload and *buffer the const one, so the assignment copies the old value's characters into storage nobody else can see — the count is not consulted here precisely because String str; guarantees it is 1 (constructors).
