Swap

member of hbe::Shareable Engine/Memory/Shareable.h Exchange the two handles' pointers: no count moves, nothing allocates, nothing is destroyed.

Signature

void Swap(Shareable& rhs)

Function description

Defined inline in the class body of Engine/Memory/Shareable.h. Three pointer assignments exchange the two handles' body members. No count is read, incremented or decremented: after the exchange each handle names the object the other used to name, and each object's owner count is exactly what it was.

The one operation here that reshapes nothing and can throw nothing. Because the two handles merely exchange pointers, no destructor runs and no allocation or deallocation happens — which is what makes this the safe way to move a value between owners, and why hbe::String builds its assignment on it: the copy path constructs a temporary and swaps with it, so the buffer the old value owned is released by that temporary's destructor rather than by an in-place release. Swapping with yourself is harmless for the same reason — the three assignments put back what they took.
It takes a mutable reference, so both sides must be modifiable and neither may be a temporary. The parameter is Shareable&, which will not bind a const handle and will not bind an rvalue. Where a temporary has to be swapped, it must be given a name first — the shape String::Swap(String&& target) uses: it takes the rvalue by name and then calls buffer.Swap(target.buffer) on that name (Engine/String/String.h, String::Swap). Self-swap is safe; swapping with an empty handle is safe and simply leaves one handle empty and one not.

Parameters

ParameterTypeMeaning
rhsShareable&The handle to exchange objects with. Empty on either side is fine.

Return value

None. Both handles are modified; the shared objects are not.

Examples

	void Swap(String&& target) noexcept
	{
		Index tmpHashCode = hashCode;
		hashCode = target.hashCode;
		target.hashCode = tmpHashCode;

		buffer.Swap(target.buffer);
	}

From Engine/String/String.h, String::Swap

hbe::String's own swap, and the tree's only call of this function: the cached hash travels with the value by being swapped separately, while the buffer changes hands without a single reference-count operation. The two String objects end up owning each other's former buffer, and every other handle that shared either buffer is unaffected.
