Release

member of hbe::Shareable Engine/Memory/Shareable.h Give up this handle's reference early, exactly as the destructor would - and tell no one else that the object may now be gone.

Signature

void Release()

Function description

Defined inline in the class body of Engine/Memory/Shareable.h, and the same three lines as the destructor: test body, call body->Dereference(), set body = nullptr. The difference is only when it runs — here the caller decides, mid-life, instead of at scope exit. Afterwards this handle is empty: false, count 0, and safe to destroy, copy or overwrite.

What "give up the reference" means depends on the count, and it is the same rule the destructor documents: the decrement is guarded by if (count > 0) inside Body::Dereference(), and if the decrement reaches zero the same call runs MemoryManager::Delete<Body>(this), destroying TType and returning the block through the allocator that is current at that instant (destructor carries the cross-allocator consequence).

Nothing here tells the other handles anything. A release does not clear other handles, does not notify them, and does not make them empty — if this was the last reference, every other handle naming the object is now dangling, and the class offers no way to discover that except its own count, which the dangling handles still report as they were. So Release() is only a safe early drop when this handle is the last owner or when no other handle can still be used. The tree's one user never calls it: a search of Engine/ and Applications/ finds no caller of Release on a Shareable, which is why the pages describe it from the source and quote no usage.
operator= is the only in-source caller. The assignment operator begins with Release(); so that the old object's reference goes before the new one is taken — which is why self-assignment through that operator ends up emptying the handle rather than crashing (see that page).

Parameters

None.

Return value

None. The function reports neither whether it released anything nor whether the object died. A caller that needs to know can compare GetReferenceCount before and after — on the same thread, since the counter is not atomic.

Examples

	void Release()
	{
		if (body != nullptr)
		{
			body->Dereference();
			body = nullptr;
		}
	}

The whole function. It is the shortest statement of the class's contract there is: one handle, one reference, and the object survives exactly as long as somebody still holds one.
