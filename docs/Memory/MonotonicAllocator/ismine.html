IsMine

member of hbe::MonotonicAllocator Engine/Memory/MonotonicAllocator.h private nodiscard Private range test on the buffer, and the only switch deciding whether a release is ignored or forwarded to the parent.

Signature

[[nodiscard]] bool IsMine(const TPointer ptr) const

Function description

Defined in Engine/Memory/MonotonicAllocator.cpp as MonotonicAllocator::IsMine(TPointer ptr) const, declared private and [[nodiscard]] in the header. A range test against the backing buffer, and nothing more: it never consults cursor, so it cannot say whether an address was ever handed out. 

auto bytePtr = static_cast<uint8_t*>(ptr);
if (bytePtr < buffer)
{
	return false;
}

if (bytePtr >= (buffer + capacity))
{
	return false;
}

return true;

From Engine/Memory/MonotonicAllocator.cpp, MonotonicAllocator::IsMine(TPointer ptr) const

Its one job is routing, and here that job carries more weight than it does anywhere else in the module. Deallocate asks it first and splits on the answer: true means "ignore the call", false means "forward the release to parentID, where memory really is given back". It is the only question that decides whether a release does anything at all.

True means "inside my buffer", not "a block I handed out" — and on this class, true means "will not be freed". The test is arithmetic on one address range, so it answers true for the middle of a block, for the gap between two blocks, for the unwritten tail of a block whose charge was rounded up, and for the buffer's own base address. The class keeps no record that could distinguish those — no header, no free list, no generation counter. Two consequences worth stating plainly: a pointer one byte into a live block is answered true exactly as the block's base is, and the buffer's own base is answered true, which is how a destructor dispatching into the wrong allocator loses its buffer to this predicate's silence.
The range is fixed for the object's whole life, so the answer never changes. buffer and capacity are written once by the constructor and never again, so two calls with the same pointer agree however much allocation happened between them. The interval is half-open: an address exactly one past the end is not yours — which is why a zero-byte request against a full buffer, answered with buffer + capacity by Allocate, is an address this class disowns.
A null pointer is answered "not mine", which is a dispatch, not a rejection. nullptr compares below a live buffer, so Deallocate forwards (nullptr, size) to parentID; the manager's release entry then fires Assert(nBytes == 0) on a null pointer, so releasing null with a non-zero count aborts in Debug and Dev. With a failed construction the buffer is null and the second comparison (ptr >= buffer + capacity) rejects every input, including null. See Coverage.
It is private, and unlike the stack's copy it is [[nodiscard]]. No caller outside the class can reach it, so the only observable behaviour is Deallocate's choice of destination. StackAllocator::IsMine declares the same private predicate without the attribute — the one point where the two classes' private interfaces differ in spelling rather than in effect. Both uses are in a condition, so the attribute changes nothing today.

From Engine/Memory/MonotonicAllocator.cpp, MonotonicAllocator::Deallocate(Pointer ptr, TSize requested) noexcept

The whole of the function's use, and the shape every allocator in this module repeats: ownership is decided by address range, and a pointer the range does not claim is sent to the parent. Here the branches are not symmetric — the claimed branch does nothing — so this predicate is effectively the question "is this memory the parent's?", and a caller who wants certainty that an address belongs to this object must compare it against the pointer Allocate returned.
