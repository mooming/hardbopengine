Module Index / Memory / PoolConfig / operator<

operator<

member of hbe::PoolConfig Engine/Memory/PoolConfig.h the module's one ordering rule: ascending by block size, and by nothing else

Signature

bool operator<(const PoolConfig& rhs) const noexcept

Function description

Defined in the class body of Engine/Memory/PoolConfig.h, and its whole body is return blockSize < rhs.blockSize;. It compares block size and ignores numberOfBlocks completely, which makes it a strict weak ordering over sizes: two entries that differ only in count are equivalent under it.

That one line is the ordering rule for the entire pool-configuration surface, because every sort in the module is std::sort over this comparator:

  • PoolConfigUtil::Normalize() sorts the caller's list before it folds equal sizes together
  • PoolConfigUtil::MergeMax() sorts both inputs, walks them as two ascending sequences, and sorts the merged result again
  • MultiPoolConfigCache::Serialize() calls Normalize() first, so the cache file is written in this order and the next boot reads it back that way

The fold that depends on it is the run-detection in PoolConfigUtil::Normalize(): it advances to a new size whenever config.blockSize != blockSize, which is correct only while equal sizes are adjacent. Sorting guarantees that, and the trailing Assert(configs.size() == numUniqueBlocks) is the check that they stayed that way.

Equivalence here is not equality. Because the comparator ignores the count, a std::find_if that matches on item.blockSize == key (MultiPoolAllocator::ReportConfiguration()) and this comparator agree by coincidence of subject, not by construction — and nothing in the type offers an operator== at all. Sorting a list of configurations is therefore stable in size but free to reorder two same-size entries, which is harmless only because their counts are summed.

Return value

booltrue when this configuration's block size is strictly smaller than rhs's. Two configurations of equal size return false in both directions, which is what "equivalent" means to std::sort.

Examples

The declaration order in a normalised list is this comparator's output:

std::sort(configs.begin(), configs.end());

From Engine/Memory/PoolConfigUtil.cpp, PoolConfigUtil::Normalize(TPoolConfigs&)

The same call appears in PoolConfigUtil::MergeMax() and, through Normalize(), in MultiPoolConfigCache::Normalize(). See Normalize for what the sorted list is then folded into, and the class page for what a list that never got sorted costs downstream.
