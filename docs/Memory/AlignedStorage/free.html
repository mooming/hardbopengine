Free

member of hbe::AlignedStorage Engine/Memory/AlignedStorage.h const noexcept return the buffer through the allocator, with the base pointer and byte count Allocate recorded

Signature

template <typename TAllocator>
	void Free(TAllocator& inAllocator) const noexcept

Function description

Two statements and a guard. A handle whose raw is null owns nothing and returns immediately, which makes this safe to call unconditionally from a destructor that may be running on a partially-constructed owner. Otherwise the recorded base pointer — never aligned — is cast back to the allocator's own byte pointer type and released with the recorded bytes: 

using BytePointer = std::remove_pointer_t<decltype(std::declval<TAllocator&>().allocate(1))>;
inAllocator.deallocate(reinterpret_cast<BytePointer*>(raw), bytes);

The byte-pointer type is deduced from what the allocator's allocate returns, in an unevaluated context, so no call site has to know that this module's allocators happen to trade in std::uint8_t*. Both casts in the class are here or in Allocate; a site that goes through the handle writes neither cast, nor the padding arithmetic, nor the byte count.

It destroys nothing. Free releases raw memory. Every TObject built in the buffer must already have had its destructor run — the handle knows the buffer's extent and so could in principle destroy bytes / sizeof(TObject) elements, but it does not, because the usual caller built fewer objects than the buffer could hold (a queue block holds whatever was published before it was retired, not BlockSlots of them) and guessing would be worse than refusing. The element lifetime is the caller's, exactly as it was with a raw deallocate.
const means the handle is still full afterwards. Free cannot clear the fields it reads, so calling it twice on the same handle frees the same memory twice. The engine's users avoid this by construction — the queue frees a block only on the path that discards that block — but a hand-written second call is not caught. Reset deliberately if a path can reach a second free: allocation = AlignedStorage<LinkNode>{};

Parameters

ParameterTypeRequirement
inAllocator TAllocator& An lvalue allocator whose deallocate(pointer, size_t bytes) accepts the pointer and byte count Allocate used. It need not be the same object — a rebound allocator of the same type and target is fine, which is what the queue does, since it stores one allocator and constructs a StorageAllocator at each call — but it must route to the same pool, or memory leaves through the wrong accounting node

Return value

void. deallocate has nothing to report and the function adds nothing: it is noexcept, allocation-free, and cannot fail. A handle that owned nothing and a handle that released a buffer look identical afterwards, which is the one consequence of const a caller has to remember.

Examples

These are the engine's two real call sites, from AtomicRingQueueMultiProviderSingleConsumer.

Release one retired block, whose handle travelled with it:

StorageAllocator storageAllocator{allocator};
inBlock->allocation.Free(storageAllocator);

Release the producer slot array from a destructor that must also survive a constructor that failed early:

StorageAllocator storageAllocator{allocator};
slotAllocation.Free(storageAllocator);              // no-op when the constructor never got a buffer
