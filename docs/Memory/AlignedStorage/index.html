AlignedStorage

Engine/Memory/AlignedStorage.h namespace hbe template <typename TObject> final one over-allocated buffer and the three facts a correct deallocate call needs about it — the unaligned base, the aligned address, and the byte count

Class description

An allocator hands back a pointer aligned for the bytes it manages, which is not necessarily aligned for the object you intend to build there. The standard fix is the one this class implements: ask for more bytes than the objects need, round the returned address up to the alignment the type wants, and build there. Doing it inline costs the caller three pieces of bookkeeping — where the buffer really starts, where the objects live, and how many bytes were requested — and all three must survive to the release call. Kept as separate fields at each use site, they are three ways for a deallocate to disagree with its own allocation.

AlignedStorage<TObject> keeps them together as one value. Allocate owns the padded request, the rounding and the failure check; Free owns the release, and can only be given the pointer and the size that Allocate recorded. Neither constructs nor destroys a TObject: the buffer is raw, and placement-new plus an explicit destructor call belong to whoever asked for the space. That is deliberate — the reason to over-allocate in this engine is to build something inside a larger structure, as AtomicRingQueueMultiProviderSingleConsumer does for its blocks and its producer slot array.

The rounding is the usual bit trick, and the padding is exactly alignof(TObject) bytes: 

bytes   = sizeof(TObject) * count + alignof(TObject)
aligned = (raw + alignof(TObject) - 1) & ~(alignof(TObject) - 1)

alignof is guaranteed a power of two by the language, so the mask is a genuine round-up. The worst case advances the address by alignof(TObject) - 1 bytes, one less than the slack that was requested, so an aligned address for count objects always fits inside the buffer. The cost is one word of padding per allocation, one mask, and one extra field — bytes — that a hand-written version would have to recompute at the free site anyway.

It aligns to the type's own requirement, not to a fixed size. A caller that wants a block on its own cache line does not pass 64 to this class; it declares alignas(64) on the type, and alignof then reports 64. That is how the queue gets cache-line-separated blocks — its LinkNode is declared alignas(AlignSize) — and it is why this class never needs an alignment argument: alignment is a property of the type, and the type is already a template parameter.

Template parameters

ParameterKindWhat it must satisfy
TObject typename The type the buffer is meant to hold. Nothing is required of it — no constructor, destructor, move or default construction is ever performed here, since nothing is constructed here. It must be a complete type at the call, because sizeof and alignof are both evaluated

The allocator is not a template parameter of the class, only of the two methods that need it. A storage value records three numbers and holds no allocator, so a handle does not claim a dependency on a type it never stores; the allocator is deduced at each call site, and its own byte-pointer type is deduced from what its allocate returns.

Class properties

Type + NameDefault ValueDescription
std::byte* raw; nullptr The pointer the allocator returned, before rounding. This is what Free hands back, and it is the field a hand-written version is most likely to lose — a caller who kept only the aligned pointer cannot free the buffer at all. It is also the success flag: Allocate leaves it null when the allocator returned nothing
TObject* aligned; nullptr raw rounded up to alignof(TObject) — the address to placement-new into, and the one every element access goes through. Never null when raw is not: the padding is sized so the rounding always fits
size_t bytes; 0 The padded byte count the allocator was asked for, sizeof(TObject) * count + alignof(TObject). Recorded, not recomputed, so the release cannot pass a count that differs from the request. Set even when the allocation failed, which is why raw and not bytes is the field to test

Non-member functions

None. AlignedStorage.h declares the one struct and nothing at namespace scope; there are no operators, no swap, and no factory free function — Allocate is a static member because the allocator it uses is an argument, not a default.

Coverage

GapDetail
Overflow of the padded size sizeof(TObject) * inCount + alignof(TObject) is computed in size_t and is not checked. A count large enough to wrap it produces a small allocation and an aligned pointer inside it, so count is a precondition rather than a validated input — the same assumption every other caller of allocate in this module makes
What the allocator guarantees Which pool the bytes come from, whether they are already aligned for some types, and what deallocate requires beyond pointer-plus-count: all in Memory: allocator catalogue. This class assumes nothing beyond those two operations existing
Nothing measures this class No unit testlet exercises AlignedStorage directly; it is covered by whichever container uses it. Today that is AllocateBlock and the queue's constructor, whose testlets would fail loudly on a wrong rounding or a wrong release
