~Task

member of hbe::Task Engine/Core/Task.h defaulted and trivial: a task releases nothing, because a task owns nothing

Signature

~Task() = default

Function description

Declared defaulted in Engine/Core/Task.h as Task::~Task(). It releases nothing, because a task owns nothing that outlives it: userData, abandonedUserData and name are borrowed, and the result packet is a member rather than memory the task allocated.

Being defaulted, it is trivial — verified with std::is_trivially_destructible_v<hbe::Task>, which is true. A task's end is therefore not an event: nothing is freed and no state is reset when one dies. When a record is reused, the previous task's fields are still in place until LoadIntoRecord overwrites them, which is why that call reloads every field rather than only the ones it was handed.

The class is neither copy-assignable nor copy-constructible. numFinishedSubTasks is a std::atomic member, and the implicitly-declared copy operations are deleted because of it — verified with std::is_copy_assignable_v<hbe::Task> and std::is_copy_constructible_v<hbe::Task>, both false. That is why the registry has a fill-in-place call at all: TaskRegistry cannot assign one task over another, so LoadIntoRecord sets the fields where the record sits.

Parameters

None.

Return value

None.

Examples

From Engine/Core/TaskRegistry.cpp, TaskRegistry::DeallocateBank()

for (std::size_t record = 0; record < recordsPerBank; ++record)
{
    bank[record].~Record();
}

MemoryManager::GetInstance().Deallocate(bankAllocatorID, bank, recordsPerBank * sizeof(Record));

Records are placement-new'd into a raw block (TaskRegistry::AllocateBank()), so the registry ends them explicitly, one per record, and then returns the block to its allocator. The call is what ~Task() makes cheap: destroying a record runs an empty destructor, and the loop exists because the records were constructed by hand, not because a task holds anything to release.
