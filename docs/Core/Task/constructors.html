Task

member of hbe::Task Engine/Core/Task.h build a task with no registry identity — the engine issues tasks through the registry instead

Signature

Task() noexcept

Task(StaticString taskName, TRunnable func, void* userData) noexcept

Function description

Both overloads are defined in Engine/Core/Task.cpp as Task::Task() and Task::Task(StaticString, TRunnable, void*). They initialise numSubTasks, numGeneratedSubTasks, numFinishedSubTasks, func and userData; the named overload additionally initialises name. Everything else keeps its in-class initialiser: the notice pair to nullptr, offerTime to zero, id to a null TaskID.

Neither constructor gives the task an identity. id is written only by LoadIntoRecord, which only TaskRegistry::Create() calls. A task built here therefore reports a null GetID, and every WorkItem generated from it carries that null identity: TaskRegistry::Find() answers nullptr for a null ID (Engine/Core/TaskRegistry.cpp), and the stream that dequeued such an item takes the released-task path — report and fire the abandonment notice, run nothing (TaskStream::TryExecuteWorkItem() in Engine/Core/TaskStream.cpp). A task constructed directly is test scaffolding, not work the scheduler can see.

This is why TaskSystem::CreateTask and TaskSystem::EnqueueTask are the paths the engine uses. The class is not copyable or assignable either — the destructor page states the consequence and LoadIntoRecord is what the registry does instead.

Constructors. No value is reported, and no failure is possible: nothing is allocated and no registry is touched.

Examples

From Engine/Core/TaskRegistry.cpp, TaskRegistryTest

Task task("JoinTask", RegistryTestRunnable(), nullptr);

if (task.HasDone())
{
    ls << "A task with nothing reserved reported itself done before anything ran." << lferr;
}

task.ReserveSubTasks(3);

The only call sites for the named overload in this repository are unit tests (TaskRegistryTest here, and Engine/Core/TaskSystem.cpp constructs a bare Task task; in its empty-task test). Both use the null identity deliberately: they exercise the join counter without a scheduler. Production code uses TaskSystem::CreateTask, and the task-system tests wrap that in the TrackedTask helper (Engine/Core/TaskSystem.cpp), which asserts the registry really did issue a record.
