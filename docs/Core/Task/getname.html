GetName

member of hbe::Task Engine/Core/Task.h the task's log label, returned as a pointer identity rather than a copy

Signature

[[nodiscard]] auto GetName() const noexcept

Function description

Defined in the header Engine/Core/Task.h as Task::GetName(); the body is return name;. The deduced return type is StaticString, which is a pointer identity into static storage rather than a buffer, so returning it by value copies the reference and not the text. A caller may keep the returned value for as long as the string literal behind it lives.

The name is a label, not a key: it is what a task's warnings, errors and asserts are filed under, and it is never used to find a task. Lookup goes through TaskID only. That is deliberate — WorkItem used to carry a copy of this name for its drop warning, and the copy was dropped because the registry cannot confirm a name belongs to the task that produced an ID.

A task that was never loaded has no name. name is written by the named constructor and by LoadIntoRecord; the default constructor leaves it default-constructed, and StaticString::IsNull() is how a caller can tell. The registry always names a task it issues, so an unnamed task is one built by hand.

Parameters

None.

Return value

TypeWhat you get
StaticStringThe task's label by value; null for a task that was never named

Examples

From Engine/Core/WorkItem.cpp, WorkItem::Run()

auto runnable = task.GetRunnable();
if (runnable == nullptr)
{
    current = end;

    auto logger = Logger::Get(task.GetName());
    logger.OutError([](auto& ls) { ls << "Null Runnable."; });

    return false;
}

The name is read at the moment something goes wrong, which is its only real use: it is the log category the line is filed under. The item's own range is closed first, so a null runnable finishes the slice rather than stalling the lane on it.
