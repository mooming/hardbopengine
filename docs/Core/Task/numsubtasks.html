NumSubTasks

member of hbe::Task Engine/Core/Task.h the declared join size — the number the join is compared against, and 0 is a refusal

Signature

[[nodiscard]] auto NumSubTasks() const noexcept

Function description

Defined in the header Engine/Core/Task.h as Task::NumSubTasks(); the body is return numSubTasks; and the deduced return type is TNumSubTasks. It reports what was declared by ReserveSubTasks, not what has run, not what is queued, and not what the splitter intended — those are three different numbers, and this is the first one.

It is the denominator of the join: ReportFinishedSubTask compares against it and HasDone compares against it. Outside the class it has one reader in the engine, and that reader treats zero as a refusal.

Zero means "nothing was ever declared", and that is a refusal. TaskSystem::DispatchSuccessor() checks this before queueing anything for a successor (Engine/Core/TaskSystem.cpp): an outcome is delivered as one item covering the successor's whole range, and a successor with no reserved subtask has no join for that item to close, so the dispatch is refused with a log line naming the record.
Read plain, with no ordering against the write. numSubTasks is an ordinary byte, so this accessor has no synchronisation with the reserve that set it. That is safe under the rule the reserve page states — reserve once, before the first item is queued — and unsafe for a task whose count is being written while other threads read it. For a progress figure that survives concurrency, read NumFinishedSubTasks, which is the atomic half.

Return value

Examples

From Engine/Core/TaskSystem.cpp, TaskSystem::DispatchSuccessor()

if (successor->NumSubTasks() == 0)
{
    auto log = Logger::Get(GetName());
    log.OutError([successorID](auto& ls)
    {
        ls << "Record " << successorID.index << " generation " << successorID.generation
           << " is named as a successor but reserved no subtask, so there is no work item to queue for it: an"
           << " outcome is delivered as one item covering the successor's whole range, which is one reserved"
           << " subtask. Nothing was dispatched. ";
    });
    return;
}

The check is not paranoia about a strange value: a successor is created by a caller that has not queued it, so the reservation is the only evidence that anybody intends the successor to run at all.
