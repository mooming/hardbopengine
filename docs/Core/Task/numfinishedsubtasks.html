NumFinishedSubTasks

member of hbe::Task Engine/Core/Task.h the join counter as a relaxed number: how many items reported, not whether the task finished

Signature

[[nodiscard]] auto NumFinishedSubTasks() const noexcept

Function description

Defined in the header Engine/Core/Task.h as Task::NumFinishedSubTasks(); the body is return numFinishedSubTasks.load(std::memory_order::relaxed); and the deduced return type is TNumSubTasks. It is the join counter read as a number rather than as an event.

The relaxed load is the whole point of exposing it: this call answers "how many have reported", and it deliberately takes no part in ordering the finished task's writes before anybody else observes them. That ordering belongs to ReportFinishedSubTask, which increments the same counter with sequential consistency and is the only call that says a join closed.

Within the class this has exactly one reader. HasDone is its only caller in Engine/Core/Task.h and in Engine/Core/Task.cpp; the value is not exposed anywhere else in the interface, because a count on its own invites the comparison that is wrong to make — see HasDone for why the engine declined to publish this as a completion query.

Parameters

None.

Return value

TypeWhat you get
TNumSubTasks (uint8_t)How many items have reported finished, counted from the last record issue. May exceed NumSubTasks if more items were generated than reserved

Examples

From Engine/Core/Task.h, hbe::Task

[[nodiscard]] bool HasDone() const noexcept
{
    return numSubTasks > 0 && NumFinishedSubTasks() >= numSubTasks;
}

The only call site. Note the two halves of the test: the count alone would report an empty, never-dispatched task as done, which is precisely the false answer this accessor must not be used to produce on its own.
