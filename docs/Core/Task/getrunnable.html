GetRunnable

member of hbe::Task Engine/Core/Task.h the function pointer every item of this task is about to call

Signature

[[nodiscard]] TRunnable GetRunnable() const noexcept

Function description

Defined in the header Engine/Core/Task.h as Task::GetRunnable(); the body is return func;. It hands back the one function pointer every item of this task calls. TRunnable is std::size_t(*)(void* userData, std::size_t startIndex, std::size_t endIndex) (Engine/Core/Runnable.h): the return value is how many indices this call processed, and a smaller number than the range means the runnable is not finished — the item's current advances by that much and the item is re-added to the lane it came from.

One caller in the engine, and it is the important one: WorkItem::Run reads this into a local before anything else (Engine/Core/WorkItem.cpp), so the value that is called is the value that was read.

nullptr is not ignored. A null runnable closes the item's range (current = end), logs an error under the task's own name, and returns false. A task with no runnable therefore consumes its items and reports none of them finished: its join never closes, and its successor is never dispatched.
Written twice, read constantly, guarded by nothing. func is set by the named constructor and by LoadIntoRecord, and the only other writer is SetRunnable. Reading it while another thread writes it is a race the type does not prevent; the engine never writes a runnable after a task has been issued, which is what keeps the plain read honest.

Parameters

None.

Return value

TypeWhat you get
TRunnableThe stored function pointer — nullptr for a task built by the default constructor and never given one

Examples

From Engine/Core/WorkItem.cpp, WorkItem::Run()

auto runnable = task.GetRunnable();
if (runnable == nullptr)
{
    current = end;

    auto logger = Logger::Get(task.GetName());
    logger.OutError([](auto& ls) { ls << "Null Runnable."; });

    return false;
}

auto userData = task.GetUserData();
auto delta = runnable(userData, current, end);
current += delta;

Read once per item, immediately before the call, and checked before use — the one place in the engine that turns a mis-created task into a log line rather than a jump through a null pointer.
