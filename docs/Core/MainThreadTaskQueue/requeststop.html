RequestStop

member of hbe::MainThreadTaskQueue Engine/Core/MainThreadTaskQueue.cpp Clears the running flag; nothing in the class or the engine acts on it.

Signature

void RequestStop() noexcept

Function description

Defined in Engine/Core/MainThreadTaskQueue.cpp as MainThreadTaskQueue::RequestStop(); the body is isRunning = false; — one relaxed-enough atomic store, the default sequence consistency on a std::atomic<bool>.

It requests a stop that nothing performs. ProcessTasks never reads the flag: its loop ends when the queue reads empty. No other method consults it, and no code in Engine/ or Applications/ calls this function on a MainThreadTaskQueue. The engine's real shutdown signalling lives one class up, on TaskStream (closeRequested, isDrainingForShutdown, and TaskSystem::RequestOtherStreamsClose, Engine/Core/TaskStream.cpp). Searching for RequestStop finds call sites, but they belong to TaskHandle::RequestStop and TaskProvider::RequestStop — a different class with a different meaning (Engine/Core/TaskProvider.h).
The name promises a handshake; the code is a flag write. Read as written, this is "mark the queue as no longer intended to run", which is useful to a future drainer and to no current one. A caller today who calls it and then expects the drain to stop gets a full drain of everything already queued plus anything posted meanwhile.
It is outside the lock, deliberately. "isRunning stays outside queueLock: it is only ever touched as an atomic and guards nothing, so pulling it into the critical section would widen the lock for no protection" (Engine/Core/MainThreadTaskQueue.h). Any future wiring must keep that property: a drainer that checks the flag must not take the lock to do it, or the flag becomes a reason to hold the mutex across a callable invocation.

Parameters

None. There is no reason code, no drain-now-versus-drain-later choice, and no way to undo it — the constructor is the only writer of true.

Return value

void. Nothing reports whether the queue had already been stopped, and nothing wakes a drainer that is waiting elsewhere — there is no condition variable in this class.

Examples

Illustrative — this function has no call site in the repository.

queue.RequestStop();
const auto drained = queue.ProcessTasks();   // still drains everything, including anything posted meanwhile

Written out, the gap is visible: the only way to make this class stop draining is to stop calling ProcessTasks, which is why the engine controls it from the stream's loop rather than through the queue.
