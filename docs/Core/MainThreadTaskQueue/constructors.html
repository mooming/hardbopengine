From Engine/Core/MainThreadTaskQueue.cpp

The body initialises nothing. Both members are default-constructed: queue starts empty and queueLock starts unlocked, and neither needs a value supplied here.

Empty does not mean cheap, and the constructor is where the cost is paid. The container's 256 priority buckets are an inline array of empties, so construction allocates nothing for the items — but it reserves 10,320 bytes inside whatever holds the queue (measured: sizeof(MainThreadTaskQueue), confirmed by the compiler on this tree). Every TaskStream owns one as postedTasks (Engine/Core/TaskStream.h), so this constructor runs once per stream and the footprint is per stream as well.
Not defaulted, unlike the destructor — the pair is asymmetric on purpose. The destructor (~MainThreadTaskQueue) is = default in the header, while this one keeps a definition in the source even though that definition is empty, because the house rule puts a non-template body in the .cpp. The class is final and holds a std::mutex, so it is neither copyable nor movable; each instance lives where it was constructed, which for the engine's uses is a TaskStream member.

Parameters

None. There is no constructor that takes a capacity, a priority ceiling, or an initial state — all three are compile-time decisions of the aliases.

Return value

Nothing: construction cannot fail, because nothing is allocated that could refuse.

Examples

From Engine/Core/TaskStream.h

MainThreadTaskQueue postedTasks;

The engine never constructs this class directly; it appears as a member and is therefore built and destroyed with its stream. That is why the destructor's silence about queued work matters: the stream's own shutdown pump is what tries to drain it before then (Engine/Core/TaskSystem.cpp).
