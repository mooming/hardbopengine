IsRunning

member of hbe::MainThreadTaskQueue Engine/Core/MainThreadTaskQueue.cpp Reports that flag; no caller exists in the repository.

Signature

[[nodiscard]] bool IsRunning() const noexcept

Function description

Defined in Engine/Core/MainThreadTaskQueue.cpp as MainThreadTaskQueue::IsRunning(); the body is return isRunning; — an atomic load of the flag the constructor set to true and that only RequestStop ever clears.

No caller exists. Nothing in Engine/ or Applications/ asks a MainThreadTaskQueue whether it is running. The similar-looking calls elsewhere are different classes: TaskSystem::IsRunning(), which the engine loop spins on (Engine/Engine/Engine.cpp, Engine/Log/Logger.cpp), and TaskStream's own close flags. Read together with RequestStop, the pair is currently inert state — documented here because both entries exist in the header and a reader must be able to find out what they do, which is: store and report a byte nobody reads.
What it can never tell you is whether work is pending. The flag and the queue are independent: a running queue can be empty, and a stopped queue can hold a thousand callables, all of which ProcessTasks will still run. A caller deciding whether to wait must ask HasPendingTasks, and must be ready for that answer to be a moment rather than a state.
Thread-safe as a read, uninteresting as a decision. The flag sits outside queueLock precisely because it is only ever touched as an atomic (Engine/Core/MainThreadTaskQueue.h), so reading it from another thread is well-defined — it simply describes a value that, in this build, changes nothing about what the class will do next.

Parameters

None.

Return value

TypeWhat you get
booltrue unless RequestStop has been called on this queue — which nothing in the repository does. Never re-true once cleared: the constructor is the only writer of that value

Examples

Illustrative — this accessor has no call site in the repository.

while (queue.IsRunning())
{
    queue.ProcessTasks();   // the loop would end here only if something else stopped it
}

The loop this accessor invites does not exist, and would be wrong even if it did: nothing breaks it except an external decision to clear the flag from a thread that also knows the drainer will look. That is the missing half of the handshake the names RequestStop / IsRunning imply.
