MainThreadTaskQueue

Engine/Core/MainThreadTaskQueue.h A locked, priority-ordered queue of callables, drained by whoever asks - one per task stream.

Class description

class MainThreadTaskQueue final at Engine/Core/MainThreadTaskQueue.h: a lock-guarded, priority-ordered queue of void (*)(void*) callables, drained by whoever calls ProcessTasks. Its name records its original purpose — work that a worker thread wants executed on the process main thread — and its actual shipping use is broader: every TaskStream owns one as postedTasks (Engine/Core/TaskStream.h), drained at the top of that stream's pass, so a "posted" callable now runs on whichever stream it was posted to. TaskSystem::DispatchToMainThread() keeps the old meaning by routing to the base stream's queue (Engine/Core/TaskSystem.cpp), which is the stream the engine loop drives.

The lock guards the container, and the tasks run outside it. BoundedPriorityQueue mutates a plain size counter and its bucket vectors in both push and pop, so an unsynchronised hand-off raced on that counter — "measured under ThreadSanitizer, where Push raced IsEmpty and Pop on the same object" (Engine/Core/MainThreadTaskQueue.h). Invoking a queued callable under a non-recursive mutex would deadlock the moment it posted more work, which is exactly what posted callables do: ProcessTasks pops under the lock and calls with it released, and the stream's pass says so in its own comment — "They run with the queue's lock released, so a posted callable may post again" (Engine/Core/TaskStream.cpp).
Priority is a byte, highest wins, and the direction was inverted deliberately. Enqueue's default of 128 is the middle of the range "so a caller that states nothing sits between urgent work and background work rather than silently joining one end". The note attached to it is a migration warning: the direction was inverted on 2026-09-18 along with BoundedPriorityQueue, which now drains the highest number first, "so anything that previously passed a small number expecting urgency now reads as low urgency" (Engine/Core/MainThreadTaskQueue.h).
Nothing bounds the number of queued callables, and the constant named for a bound is not one. MaxQueueSize = 1024 is passed as BoundedPriorityQueue's third template parameter, whose documented meaning is BucketSizeHint: the capacity a bucket is created with the first time a priority is used (Engine/Container/BoundedPriorityQueue.h). Push checks no capacity at all, so an enqueue cannot fail or drop — and a priority level that receives one item reserves a deque sized for 1024 of these 24-byte items, about 24 KB per populated priority, per stream (Engine/Container/Deque.h). Buckets are released when they run dry, so the cost is paid only by levels that hold something at the same time.
Reporting is a locked read, and the mutex is mutable for that reason. HasPendingTasks is const and takes queueLock, which is why the member is declared mutable std::mutex queueLock with the reason written at its declaration. The queue holds no stop flag: ProcessTasks ends when the queue is observed empty, and the stream's own shutdown uses different flags (closeRequested, isDrainingForShutdown in Engine/Core/TaskStream.cpp).
