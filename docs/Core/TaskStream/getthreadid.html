GetThreadID

member of hbe::TaskStream Engine/Core/TaskStream.h The identity of the thread the stream believes is driving it.

Signature

[[nodiscard]] TThreadID GetThreadID() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskStream.h; there is no counterpart in Engine/Core/TaskStream.cpp. The identity of the thread the stream believes is driving it, as std::thread::id.

Three places write it, and none of them is the constructor. Start records the calling thread for the base stream only; RunLoop records the worker's own thread as its first act; and Update records whatever thread arrives first if the field is still default — which is how the IO stream, whose Start returns without touching it, gets an owner. A stream nobody has ever driven therefore reports a default std::thread::id, and that default is the value the class itself tests for: the two configuration checks run if (threadID != TThreadID{}) (Engine/Core/TaskStream.cpp).
The field is a plain member that one thread writes and others read, and the reads are the ones that police other threads. ConfigureBudget and ConfigureRate compare the caller's thread against this field from the caller's thread, and a driven stream's first pass writes it while another thread may be asking those questions (Engine/Core/TaskStream.cpp). There is no atomic and no lock on either side, so the check is a heuristic that can read a stale value; it is also Debug-only, since it is an Assert (Core/Debug.h, CMakeLists.txt).
For a driven stream the answer is a historical record, not a current fact. The base stream is driven by whatever thread runs the engine's loop, and the IO stream by the logger's driver thread; once recorded, the value never follows a driver that changes, and the pass does not re-record it — the test is if (threadID == TThreadID{}), not "is this me" (Update). Two different threads driving the same stream therefore produce one answer and one unsynchronised race, and this accessor reports neither.
Two places ask the question this accessor exists for, and both are mapping a thread to a stream. TaskSystem::GetStreamIndex(TThreadID) scans the streams for the one that claims a given thread, and the logger records which thread the IO stream believes is driving it so its own allocations can be attributed to that thread (Engine/Core/TaskSystem.cpp, Engine/Log/Logger.cpp). The class itself reads the field constantly for its checks, without the accessor (Engine/Core/TaskStream.cpp). For the thread object — to join it or test it — use GetThread.

Parameters

None.

Return value

TypeWhat you get
auto deducing std::thread::idThe first thread that claimed this stream, or a default std::thread::id if none has; the value is never updated after the first claim

Examples

From Engine/Core/TaskSystem.cpp, TaskSystem::GetStreamIndex()

if (auto& stream = streams[i]; stream.GetThreadID() != id)
{
    continue;
}

The accessor as a lookup key: the stream whose recorded driver equals a thread's id is that thread's stream (Engine/Core/TaskSystem.cpp). It works only because the id is recorded once and never revised — the limitation stated above.

From Engine/Core/TaskStream.cpp, TaskStream::ConfigureBudget()

if (threadID != TThreadID{})
{
    Assert(std::this_thread::get_id() == threadID, "Stream ", name,
           " had its budget configured from another thread while it is running. The allowance is an "
           "unsynchronised field this stream reads every pass, so that is a data race. Use RequestBudget, "
           "which the stream applies to itself.");
}

The field's real consumer: an owner-thread check that is skipped entirely while this accessor would report a default id (Engine/Core/TaskStream.cpp, RequestBudget for the form that needs no check).
