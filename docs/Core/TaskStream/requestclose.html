RequestClose

member of hbe::TaskStream Engine/Core/TaskStream.h Ask this one stream to finish its work and close, and wake it if it is sleeping.

Signature

void RequestClose() noexcept

Function description

Declared in the header Engine/Core/TaskStream.h, defined in Engine/Core/TaskStream.cpp. Ask one stream to finish its work and close, and wake it if it is sleeping. Asking is not closing: IsClosed is the answer that says it happened.

It is per stream by design, because the global switch is too blunt to order a shutdown. "The counterpart to a shutdown request. One global flag stops every stream in the same instant, which abandons whatever each of them already holds and closes the base stream along with the rest even though that stream still owns the end of the run. Closing is therefore per stream and ordered by whoever drives the shutdown: everything else first, the base stream last." (Engine/Core/TaskStream.h) The engine uses it that way: every user stream is asked first, and the base stream is asked last. 
for (auto& stream : streams)
{
    if (&stream != &baseStream && &stream != &loggerStream)
    {
        stream.RequestClose();
    }
}

From Engine/Core/TaskSystem.cpp, TaskSystem::RequestOtherStreamsClose()

What each kind of stream does with the flag is different, and one kind does not finish because of it. A worker's RunLoop tests it before every pass and leaves the loop when it is set, then drains and marks itself closed. A driven stream has no loop: Update sees the flag after processing posted callables and returns false, so it stops taking work but never sets isClosed — that is CloseDrivenStream's job, and the header is explicit about the consequence of forgetting it: "a stream whose closed state is never set is a stream that any correct future waiter would wait on forever" (Engine/Core/TaskStream.h).
Posted callables still run after the ask. Update pumps postedTasks before it tests the flag, so work posted before the close request is still executed by a driven stream's next pass (Engine/Core/TaskStream.cpp). Work posted after the ask is queued and reaches a driven stream only if a pump runs — which is why the shutdown reports HasPostedTasks rather than assuming the queue is empty.
The release store carries nothing, and notify_all does not make the close immediate. WaitForWork has no predicate, so a wake-up only ends the sleep; the worker still has to run a pass that re-reads the flag before it leaves. And nothing here drains: the ask starts the close, and DrainForShutdown is what runs the remaining work — with a deadline, after which the rest is reported abandoned (Engine/Core/TaskStream.h).
The engine asks twice of the two driven streams, and the second ask is dead weight. CloseDrivenStream calls this itself as its first act, and TaskSystem::JoinAndClear then calls RequestClose() on the IO stream and the base stream again after closing them (Engine/Core/TaskSystem.cpp). Storing true twice is harmless — there is no counter and no edge to miss — but the ordering it appears to express is already fixed by the close call above it.

Parameters

None. There is no reason string, no drain timeout, and no way to withdraw the request.

Return value

void. Nothing reports whether the stream was already closed or already asked; read IsCloseRequested and IsClosed.
