DrainForShutdown

member of hbe::TaskStream Engine/Core/TaskStream.h Run this stream's own remaining work inside a wall-clock window, then abandon what is left.

Signature

[[nodiscard]] std::uint64_t DrainForShutdown() noexcept

Function description

Defined in Engine/Core/TaskStream.cpp as TaskStream::DrainForShutdown(). Run this stream's own remaining work, then stop: the graceful half of closing, called by RunLoop after its loop exits. 

isDrainingForShutdown = true;
const auto deadline = std::chrono::steady_clock::now() + shutdownDrainDeadline;

std::uint64_t passes = 0;

while (Update() && std::chrono::steady_clock::now() < deadline)
{
    ++passes;
}

isDrainingForShutdown = false;

From Engine/Core/TaskStream.cpp

Provider probing is suspended for the whole drain, and the reason is that a provider has no reason to stop. "Provider probing is suspended, because a provider can answer every request with another item and a drain that never ends is not a close." (Engine/Core/TaskStream.h) The flag is read by Update's probe loop, so during the drain the stream runs what it already holds and takes nothing new from its producers — while the general queue fallback stays live, since that is not provider probing (Engine/Core/TaskStream.cpp).
The bound is a wall clock because a resumable task defeats any pass limit. "The bound is a wall clock rather than a pass count, because a resumable task is re-added on every pass and would outrun any pass limit - a bound that such work can defeat is not a bound." (Engine/Core/TaskStream.h) The window is shutdownDrainDeadline, and it differs by stream: the constructor gives the base and IO streams std::chrono::milliseconds::zero and every worker 2000 ms (Engine/Core/TaskStream.cpp). For the two engine streams the loop therefore runs exactly one pass — the first — and stops, by design: "the IO stream's work is the log buffer, and writing a line re-posts the drain task, so draining it to emptiness is a loop that ends only at the deadline - measured at over 2.6 million passes and the full window for no work but its own."
The returned count is not the number of passes that ran. The condition is Update() && now < deadline, and ++passes sits in the body — so the pass that ended the drain is never counted, whether it ended by finding nothing or by arriving after the deadline. What the number is exactly: passes that took or dropped something and were followed by a still-open window. A worker that ran three productive passes and then a final empty one reports 2 (Engine/Core/TaskStream.cpp).
Whatever is left when the deadline passes is abandoned with a notice, and the report says so in the open. After the loop the drain calls AbandonHeldWork and, if the count is non-zero, warns: "a task that cannot finish inside the drain deadline is a defect in that task, and the shutdown must report it and proceed - reporting it means firing the notice as well, not only naming a number." (Engine/Core/TaskStream.cpp) The deadline belongs to the task that overran it, not to the shutdown.

Parameters

None. The window comes from shutdownDrainDeadline, which no public call sets — it is fixed per stream at construction.

Return value

TypeWhat you get
std::uint64_tPasses taken inside the window, excluding the one that ended the drain; 0 for the base and IO streams, whose window is zero. Abandoned items are reported by this call directly, not returned

The only caller: a worker's own exit path, where the drain runs before the close mark so that anything watching IsClosed is entitled to assume the stream holds nothing it intends to run (Engine/Core/TaskStream.cpp).
