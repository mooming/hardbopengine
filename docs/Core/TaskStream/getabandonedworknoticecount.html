GetAbandonedWorkNoticeCount

member of hbe::TaskStream Engine/Core/TaskStream.h Times this stream abandoned a held work item at close.

Signature

[[nodiscard]] std::size_t GetAbandonedWorkNoticeCount() const noexcept

Function description

Declared in the header Engine/Core/TaskStream.h, defined in Engine/Core/TaskStream.cpp. How many work items this stream has abandoned at close, counted whether or not anybody had asked to be told about them.

The name promises notices; the field counts items, and the header says so out loud. "This counts work items the stream abandoned at close, whether or not their requestor had asked to be told. A stream can abandon ten items and notify nobody and still read ten here, so the full answer to 'did anybody find out' is this counter together with the notices requestors actually received." (Engine/Core/TaskStream.h) The implementation matches the header rather than the name: AbandonHeldWork adds the number of items it discarded, and FireAbandonedNotice only calls a callback when the item carries one (Engine/Core/TaskStream.cpp). Read this as "items abandoned at close" and confirm notification through the callbacks a requestor installed.
Work dropped by a running stream is not here, and the header routes the reader elsewhere. "Work dropped by a running stream reports through GetAgedOutWorkCount and its own notice instead." (Engine/Core/TaskStream.h) Released-task drops join the age drops in being counted by neither counter — ReportReleasedTask only logs (Engine/Core/TaskStream.cpp) — so the two counters together are not a total of work this stream gave up on, only of the two kinds that were thought worth counting.
A non-zero value is the shutdown saying it cancelled promises. Every item behind the number was taken off a lane and never run; its task's declared join will not be filled by this stream (AbandonHeldWork). The count is the same figure the closing warning prints, and the warning's own last line is the reason the counter is not enough: "The count is not the report: an item discarded without a word is a promise cancelled silently." (Engine/Core/TaskStream.cpp) Nothing resets it, so a value may belong to an earlier close of a stream in a long-running test process.

Parameters

None.

Return value

TypeWhat you get
std::size_tItems abandoned at close since construction, whether or not a callback fired for them; excludes age drops and released-task drops

Examples

From Engine/Core/TaskStream.cpp, TaskStream::AbandonHeldWork()

abandonedWorkNoticeCount.fetch_add(abandoned, std::memory_order_relaxed);

return abandoned;

The only writer: one batched add of the items just discarded, after their notices have fired and before the count is returned to the reporter (Engine/Core/TaskStream.cpp). It is a batch add, so a reader between two items of one abandonment sees a stale figure — which is why the reporter uses the return value rather than a re-read.
