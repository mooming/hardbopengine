HasPostedTasks

member of hbe::TaskStream Engine/Core/TaskStream.h Whether a callable is waiting for this stream's driver.

Signature

[[nodiscard]] bool HasPostedTasks() const noexcept

Function description

Defined in Engine/Core/TaskStream.cpp as TaskStream::HasPostedTasks(); the body is one call, postedTasks.HasPendingTasks() (MainThreadTaskQueue::HasPendingTasks). Whether any callable is waiting to be run by this stream's driver.

The header bounds what a "no" is worth, and the bound is about the poster rather than the queue. "A snapshot across another thread's queue: a false answer of 'none' is only sound once the poster has stopped." (Engine/Core/TaskStream.h) This is the read that a shutdown uses to decide whether work remains, and a shutdown can only trust it after the code that posts has finished posting — which is why the engine's shutdown checks it in the same breath as the lane depths rather than on its own (Engine/Core/TaskSystem.cpp). 
while (std::chrono::steady_clock::now() < pumpDeadline &&
       (!AreUserStreamsClosed() || baseStream.HasPostedTasks() || baseStream.CountPendingItems() > 0))
{
    baseStream.Update();
    std::this_thread::sleep_for(std::chrono::milliseconds(1));
}

From Engine/Core/TaskSystem.cpp, TaskSystem::JoinAndClear()

The condition keeps pumping the base stream while any of the three sources still holds work: a user stream not closed, a posted callable unwritten, a lane item untaken. Read as a stop condition, this accessor is "the main thread still owes somebody a callback".

A "yes" is stale the moment it is read, and that direction is the harmless one. A true answer only says at least one callable existed an instant ago; the pump that follows will run it, or find it already run by Update (Engine/Core/TaskStream.cpp). A false answer is the one that can end a shutdown too early, so the engine's loop tests it once more after the loop before reporting: the abandoned-posted-work check that follows this same call is what catches work left behind by a deadline that expired (Engine/Core/TaskSystem.cpp).
It is a const method on a queue that is not const inside. The pending count is read under the queue's own lock by the container (HasPendingTasks), so this is one of the few reads of posted state that is synchronised (Engine/Core/MainThreadTaskQueue.h) — unlike CountPendingItems, which reads the lane containers with no lock at all.
