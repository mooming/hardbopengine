GetMaxAge

member of hbe::TaskStream Engine/Core/TaskStream.h The staleness ceiling this stream enforces, so a temporary one can be undone.

Signature

[[nodiscard]] std::chrono::nanoseconds GetMaxAge() const noexcept

Function description

Declared in the header Engine/Core/TaskStream.h, defined in Engine/Core/TaskStream.cpp, returning drainPolicy.GetMaxAge(). The staleness ceiling this stream is enforcing right now, or zero when it enforces none.

The reason the getter exists is set-and-restore. "Readable so a caller that temporarily tightens a shared stream can put back exactly what it found. A test that configured a shared stream without restoring it would leave every later collection running under someone else's policy." (Engine/Core/TaskStream.h) It is a read of the same field SetMaxAge writes, so it sees a change the moment it is made — the pair is one unsynchronised field of StreamDrainPolicy.
A zero answer is the default, not a configured state, and the two are indistinguishable. A stream is constructed unlimited, and a caller can set the ceiling to zero to mean the same thing (Engine/Core/TaskStream.h). A test that wants to prove a ceiling was restored can therefore only prove it is unlimited, never that someone else's value was properly put back.

Parameters

None.

Return value

TypeWhat you get
std::chrono::nanosecondsThe age ceiling in force, or 0 for unlimited. Work older than this is dropped by the pass that finds it (SetMaxAge)

Examples

Illustrative — the engine never tightens a ceiling today; the pair is exercised by the task-system tests.

const auto saved = stream.GetMaxAge();
stream.SetMaxAge(std::chrono::milliseconds(50));

RunCollectionThatMustNotRunStaleWork();

stream.SetMaxAge(saved);

The restore is the point of the read. Without it the stream keeps a foreign ceiling for the rest of the run, and the only symptom is work disappearing with an age warning on a stream nobody configured (ReportAgedOutWorkItem, GetAgedOutWorkCount).
