From Engine/Core/TaskStream.cpp

Three refusals, each silent, each reported by the caller instead. A lane that is ELane::None, a provider already on this lane, and a lane whose eight slots are full all return false without a word; TaskProvider::RegisterOnStream is the layer that logs, as an error, "The lane list already holds this provider or is full, so the drain will not ask it." (Engine/Core/TaskStream.cpp, Engine/Core/TaskProvider.cpp). The duplicate check is the whole reason re-attaching is safe: "Registering the same provider on the same lane twice is refused, because the drain walks the list and would ask it twice per pass" (Engine/Core/TaskStream.h).
The lane is selected through a helper whose out-of-range value is the rejection. ProviderSlot maps FIFO to 0 and Priority to 1, and ELane::None to 2 — while laneProviders is a std::array<LaneProviders, 2> (Engine/Core/TaskStream.h). So "no lane" lands on an index that does not exist, and the bounds test at the top is what turns it into a refusal. The same trick guards the other two provider calls, all of which begin with the same four lines.
Eight per lane is a bound to keep the list inline, not a limit anyone is expected to reach. "The realistic figure is one, and a lane is asked at most once per pass per provider registered on it, so this is a bound to keep the list inline rather than a limit anyone is expected to reach" (Engine/Core/TaskStream.h). The list is raw TaskProvider* — no ownership, and no knowledge of when the provider dies, which is exactly what DetachProvider exists to keep honest.
Attaching notifies the condition variable, so a late provider is asked without waiting for outside work. A stream parked in WaitForWork wakes on this, finds its lanes empty, and asks the newly registered producer (Engine/Core/TaskStream.cpp). Without the notify, attaching to an idle stream would look like it had no effect until someone enqueued an item.
Registration order is drain order. DrainProvidersLocked walks this array from index 0 and returns the first item produced, so the position a provider takes here is its position in the scheduling queue for that lane (Engine/Core/TaskStream.cpp). There is no rotation, so the seventh provider attached is the seventh asked.
