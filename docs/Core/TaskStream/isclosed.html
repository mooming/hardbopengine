IsClosed

member of hbe::TaskStream Engine/Core/TaskStream.h Whether this stream has drained its work and left its loop, or been closed by its driver.

Signature

[[nodiscard]] bool IsClosed() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskStream.h; there is no counterpart in Engine/Core/TaskStream.cpp. Whether this stream has finished: drained what it intended to run and left its loop, or been marked closed by the driver that owned it.

Two writers, one per kind of stream, and both are the last word about that stream's work. A worker sets it with a release store as the final statement of RunLoop, after DrainForShutdown returns. A driven stream has it set by CloseDrivenStream, which uses an acquire-release exchange so a second caller sees the first one's true and stands down (Engine/Core/TaskStream.cpp). Either way the answer implies the drain ran and the held items were either run or abandoned with a notice (AbandonHeldWork).
This is what a shutdown waiter watches, and there is nothing to wait on — the engine polls. "Whoever orders the shutdown waits on this rather than on a thread handle, because a driven stream has no thread to join." (Engine/Core/TaskStream.h) In practice that waiting is a loop, because isClosed is an atomic with no condition variable of its own: 
while (std::chrono::steady_clock::now() < pumpDeadline &&
       (!AreUserStreamsClosed() || baseStream.HasPostedTasks() || baseStream.CountPendingItems() > 0))
{
    baseStream.Update();
    std::this_thread::sleep_for(std::chrono::milliseconds(1));
}

From Engine/Core/TaskSystem.cpp, TaskSystem::JoinAndClear()

The shutdown drives the base stream while it waits, because the streams that still have work to do are driven by that pump; a waiter that only slept would be waiting for pumps nobody is running (Engine/Core/TaskSystem.cpp).

The teardown asserts on it, in Debug only. TaskSystem::JoinAndClear finishes with a per-stream check: "Stream name is being destroyed without having been closed. Every stream must be closed - drained if it owns a thread, marked closed by its driver if it rides one - before the task system tears itself down." (Engine/Core/TaskSystem.cpp) That check is an Assert, compiled away unless __DEBUG__ is defined — Debug only (Core/Debug.h, CMakeLists.txt).
Closed does not mean empty, and it does not mean the work ran. A drain that reached its deadline abandons what was left, and an abandoned item is counted and notified rather than executed (GetAbandonedWorkNoticeCount). A true here says the stream is finished with the work; whether that work was run or discarded is a different question, answered by the counters and the notices.

Parameters

None.

Return value

TypeWhat you get
booltrue once the stream has been drained-or-closed and will run nothing further; false while it still owns a driver or has work in hand

Examples

From Engine/Core/TaskSystem.cpp, TaskSystem::AreUserStreamsClosed()

if (!stream.IsClosed())
{
    return false;
}

The engine's only aggregate use: every stream that owns a thread must report closed before the shutdown stops pumping the base stream. The base and IO streams are excluded from that sweep because their drivers close them explicitly, later (Engine/Core/TaskSystem.cpp, CloseDrivenStream).
