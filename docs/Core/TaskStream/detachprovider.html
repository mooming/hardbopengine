DetachProvider

member of hbe::TaskStream Engine/Core/TaskStream.cpp Remove a producer from one lane, waiting out a Produce already in flight.

Signature

[[nodiscard]] bool DetachProvider(TaskProvider& provider, StreamDrainPolicy::ELane lane) noexcept

Function description

Declared in Engine/Core/TaskStream.h, defined in Engine/Core/TaskStream.cpp as TaskStream::DetachProvider(): remove one provider from one lane's list, and say whether it was there. 

std::scoped_lock<std::mutex> lock(queueLock);
auto& list = laneProviders[slot];

for (TIndex index = 0; index < list.count; ++index)
{
    if (list.items[static_cast<size_t>(index)] != &provider)
    {
        continue;
    }

    for (TIndex shift = index; shift + 1 < list.count; ++shift)
    {
        list.items[static_cast<size_t>(shift)] = list.items[static_cast<size_t>(shift + 1)];
    }

    list.items[static_cast<size_t>(list.count - 1)] = nullptr;
    --list.count;
    return true;
}

return false;

From Engine/Core/TaskStream.cpp

The lock is the wait. "Takes this stream's queue lock, which is the same lock a drain holds across Produce - so a detach that arrives mid-call simply waits, and there is no window where a provider is erased while its item is on the way. That is R37's guarantee, and R40 is the reason it costs no counter or wait loop: the lock is the wait." (Engine/Core/TaskStream.h). No generation counter, no in-flight flag, no sleep loop — the mutual exclusion is the whole synchronisation.
It removes the first matching entry and stops, so the list holds a provider at most once. That is guaranteed upstream — AttachProvider refuses a duplicate on the same lane — and this function relies on it rather than checking for a second match (Engine/Core/TaskStream.cpp). Compaction is shift-down, so a provider registered after the one removed moves one slot earlier, and the drain order changes accordingly.
The return value drives the provider's registration count, which is what its destructor asserts on. Only a true makes TaskProvider::UnregisterFromStream decrement registeredCount, so a detach of a lane that never held the provider cannot push the count negative (Engine/Core/TaskProvider.cpp). This is the function that decides whether R37's rule is satisfiable at all.
A lane that is ELane::None returns false before the lock, through the same ProviderSlot bounds test AttachProvider uses — index 2 against a two-element array (Engine/Core/TaskStream.cpp). A caller that detaches both lanes unconditionally therefore makes one real call and one no-op, which is why TaskProvider::DetachFrom consults its recorded mask instead of guessing.
