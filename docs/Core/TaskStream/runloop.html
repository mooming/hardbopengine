RunLoop

member of hbe::TaskStream Engine/Core/TaskStream.h Run this worker stream's thread body until a close is requested, then drain and mark it closed.

Signature

void RunLoop() noexcept

Function description

Defined in Engine/Core/TaskStream.cpp as TaskStream::RunLoop(). The body of a worker stream's thread: bind this thread to the stream, drive passes until a close is requested, drain what is left, and mark the stream closed. 

AllocatorScope scope(allocator);

TaskSystem::SetThreadName(name);
TaskSystem::SetStreamIndex(streamIndex);

const auto log = Logger::Get(name);
log.Out([name = name](auto& ls) { ls << name.c_str() << " has begun."; });

threadID = std::this_thread::get_id();

while (likely(!closeRequested.load(std::memory_order_acquire)))
{
    if (!Update())
    {
        WaitForWork(std::chrono::milliseconds(10));
    }
}

const auto drainPasses = DrainForShutdown();

log.Out([name = name, drainPasses](auto& ls)
{ ls << name.c_str() << " closed after draining " << drainPasses << " pass(es)."; });

isClosed.store(true, std::memory_order_release);

From Engine/Core/TaskStream.cpp

Identity is set once for the thread's whole life, which is the difference from a driven pass. The allocator scope, the thread name and the thread-local stream index are entered here and left only when the thread exits; Update enters and restores them around each pass, because "a shared driver does not belong to this stream for the whole of its life" (Engine/Core/TaskStream.h). A task that outlives the pass it ran in — a resumable item pushed to a re-add buffer — still allocates from this stream's pool when the loop runs it, which is true here and not necessarily true under an external driver.
Only a worker stream ever runs this function. Start returns before creating a thread for the base stream and the IO stream, so the two engine streams are never closed by this path: their close is CloseDrivenStream, called by whoever withdraws the driver, and the header states why it has to exist — "a stream whose closed state is never set is a stream that any correct future waiter would wait on forever" (Engine/Core/TaskStream.h).
The ten-millisecond wait is the loop's only latency knob, and it is a ceiling on a stall, not on a wake-up. WaitForWork returns as soon as anything notifies — an enqueue, an AttachProvider, a WakeUp, a RequestClose — so a busy stream never waits; the 10 ms bounds how long a missed notify can cost an otherwise-quiet stream. Passing 10ms here is what makes the loop's worst-case response to a new item ten milliseconds rather than a frame (Engine/Core/TaskStream.cpp).
The order of the last three statements is the shutdown's contract. The loop exits on closeRequested, then DrainForShutdown runs the stream's own remaining work with provider probing suspended, and only then does isClosed get its release store. A waiter that sees IsClosed() true is therefore entitled to conclude the stream holds nothing it intends to run — which is what makes the ordered shutdown ("everything else first, the base stream last") safe to drive from one thread (Engine/Core/TaskStream.h).
The thread's exit path runs user code, and a throw from it escapes the loop's noexcept. The drain and the abandoned-work notices fire on this thread after the loop ends; a notice that throws, or a task that throws on its last pass, propagates out of a noexcept function and calls std::terminate (Engine/Core/TaskStream.cpp). Nothing here catches, and the engine's runnable signature offers no exception contract.

Parameters

None.

Return value

void. Returning from this function is the thread's last act; the join that waits for it is Join, and the state that says the work finished is IsClosed.
