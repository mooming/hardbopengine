~TaskStream

member of hbe::TaskStream Engine/Core/TaskStream.h Defaulted: members die, work held in the lanes goes with them, and nothing is said.

Signature

~TaskStream() = default

Function description

Declared = default in the public section of Engine/Core/TaskStream.h. It has no body to read: members are destroyed in reverse declaration order, and nothing else happens — no drain, no abandonment, no notice, no join, and no assert.

Destroying a stream whose worker thread is still joinable ends the process. std::thread's own destructor calls std::terminate when the thread is joinable, and thread is declared after queueLock and cv, so it is destroyed before them and while they are still intact to be raced (Engine/Core/TaskStream.h). The class offers no guard against that; the shutdown offers two, and one of them is Debug-only: 
Assert(stream.IsClosed(), "Stream ", stream.GetName(),
       " is being destroyed without having been closed. Every stream must be closed - drained if it owns a "
       "thread, "
       "marked closed by its driver if it rides one - before the task system tears itself down.");

From Engine/Core/TaskSystem.cpp, TaskSystem::JoinAndClear()

The join sweep that precedes it skips a stream whose thread is not joinable (GetThread), so the contract in force is: RequestClose, then join or close, then destroy — and the assert that would catch a breach is compiled away unless !RELEASE_BUILD is defined, which the build sets for Debug alone (Core/Debug.h, CMakeLists.txt).

Work still held at destruction is destroyed in silence. The lanes are ordinary containers, so their items go away without a log line and without a notice: the reporting is AbandonHeldWork's job, and that call has to be made before this one (CloseDrivenStream, DrainForShutdown). A stream destroyed without it has cancelled every promise its items carried and told nobody — the failure the closing reports describe as "a promise cancelled silently" (Engine/Core/TaskStream.cpp). Items parked in readdingFifo and readdingPriority are in the same position even when the close path does call AbandonHeldWork, because that call empties the lanes only.
Nothing about the destructor depends on which kind of stream this was. A worker and a ride-on stream are destroyed the same way; the difference is entirely in how each reached a destroyable state — a worker after RunLoop returned and its thread was joined, a ride-on stream after CloseDrivenStream marked it closed (Engine/Core/TaskStream.h). The defaulted destructor cannot tell those stories, which is why both paths print their own report before it.
No virtual destructor, and none is needed. The class is final and is never a base: streams live in an array inside TaskSystem by value (Engine/Core/TaskSystem.cpp) and nothing deletes one through a pointer, so the non-virtual defaulted destructor is the correct shape rather than an oversight (Engine/Core/TaskStream.h).

Parameters

None.

Return value

Nothing. It is = default, so it is also not noexcept-declared beyond what the members' own destructors imply — none of which are expected to throw.
