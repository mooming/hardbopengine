SetDrivenByShutdownPump

member of hbe::TaskStream Engine/Core/TaskStream.h Mark that the shutdown path has taken over this stream's pumping; never cleared.

Signature

void SetDrivenByShutdownPump() noexcept

Function description

Declared in the header Engine/Core/TaskStream.h, defined in Engine/Core/TaskStream.cpp. Mark that the engine's shutdown path has taken over this stream's pumping. It sets one plain bool, and never clears it.

Not clearing it is the whole design of the flag. "Mark that the shutdown path has taken over this stream's pumping. Never cleared. Not cleared on exit, because a run in which the rescue ever happened is a run whose provenance is already compromised, and a reader that checks after the fact must still be able to see it." (Engine/Core/TaskStream.h) The question it answers is about the run as a whole — "did the engine loop drive this, or did the shutdown?" — and a flag that went back to false would answer "the loop did" for a run where the loop never finished the job.
The failure it guards against is a suite that passes for the wrong reason, and the header tells the story. "That is a legitimate rescue for real shutdowns and a serious liability for verification: work that only ever runs there has proved nothing about the engine loop, which is how a deleted loop header left the whole suite green: the shutdown drain ran the suite and reported results as if the loop had pumped it." (Engine/Core/TaskStream.h) And the honest limit of the flag, stated by the same comment: "Provenance alone cannot detect a loop that pumps once and stops … What closes that case is the suite's shape … This flag is the second of the two halves."
One call site, at the moment the rescue begins. IsClosed shows the loop that sets it: TaskSystem::JoinAndClear marks the base stream before pumping it under a wall-clock bound, so every pass that the shutdown drives is attributed to the shutdown (Engine/Core/TaskSystem.cpp). Nothing calls it on a worker stream — a worker's thread is its own driver, and the shutdown only asks it to stop (RequestClose).
The write is unsynchronised, and the reader is not necessarily on the same thread. drivenByShutdownPump is a plain bool beside atomics such as isClosed and closeRequested (Engine/Core/TaskStream.h). It is safe because of when it is called — from the thread that is about to pump, before anything else can query it — not because of how it is written. Another writer, or a test that calls it to fake provenance, gets no protection and no detection.

Parameters

None. There is no argument to say which pump took over, and no form that clears the mark.

Return value

void. It does not report whether the mark was already set — see IsDrivenByShutdownPump for the read.

Examples

From Engine/Core/TaskSystem.cpp, TaskSystem::JoinAndClear()

baseStream.SetDrivenByShutdownPump();

while (std::chrono::steady_clock::now() < pumpDeadline &&
       (!AreUserStreamsClosed() || baseStream.HasPostedTasks() || baseStream.CountPendingItems() > 0))
{
    baseStream.Update();
    std::this_thread::sleep_for(std::chrono::milliseconds(1));
}

Set before the loop rather than inside it, because the claim is about the whole pumping episode that follows (Engine/Core/TaskSystem.cpp).
