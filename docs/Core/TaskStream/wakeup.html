WakeUp

member of hbe::TaskStream Engine/Core/TaskStream.h Wake one thread parked waiting to drive this stream.

Signature

void WakeUp() noexcept

Function description

Defined in Engine/Core/TaskStream.cpp as TaskStream::WakeUp(); the body is one line. 

cv.notify_one();

From Engine/Core/TaskStream.cpp

Wake one thread parked in WaitForWork on this stream. Nothing is enqueued, nothing is set, and nothing is recorded: the call changes no state the stream can read afterwards.

It wakes at most one waiter, and there is at most one waiter in practice. The only thread that parks on this condition variable is the stream's own driver, inside WaitForWork; enqueues also use notify_one, and only RequestClose uses notify_all (Engine/Core/TaskStream.cpp). A second thread waiting on the same stream by hand would not be woken by this call.
A stream that is not waiting loses nothing and gains nothing. A notification with no waiter is discarded — the condition variable keeps no counter — so calling this on a busy stream, or on a driven stream between its passes, has no effect at all (Engine/Core/TaskStream.cpp). The base stream is the case to remember: nothing parks in WaitForWork unless its host driver chooses to, so a wake aimed at it is usually a no-op.
The engine's one use is urgency, not correctness. The logger calls this after appending a line when the task system is running, so the IO stream's driver stops sleeping and writes now rather than at the end of its 20 ms patience (Engine/Log/Logger.cpp). The work was already queued; the wake only decides when someone looks.

Parameters

None.

Return value

void. It does not report whether anybody was waiting, so a caller cannot tell a delivered wake from a discarded one.

Examples

From Engine/Log/Logger.cpp, Logger::AddLog()

if (taskSystem.IsRunning())
{
    taskSystem.GetIOTaskStream().WakeUp();
}

The guard is the interesting part: the logger runs before the task system exists and after it is gone, so the wake is conditional on the system being up, and the stream it names is the one the logger itself drives (Start, WaitForWork).
