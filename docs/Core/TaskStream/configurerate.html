From Engine/Core/TaskStream.cpp

Zero means one, not "never serve this lane". The header states it in the declaration itself: "Zero weights are treated as one, not as 'never serve this lane'." (Engine/Core/TaskStream.h) There is no way to park a lane through the ratio; the mechanism that stops a lane being served is the allowance, which belongs to ConfigureBudget and StreamDrainPolicy::ConfigureAllowance.
The thread check is a Debug-only check of a real race. The weights are plain fields of StreamDrainPolicy, and the field they gate is read by ChooseLane inside Update — a lane choice that happens on every pass (ChooseLane). Writing them from another thread while a stream runs is a data race, and the detection is an Assert, which is compiled away unless !RELEASE_BUILD is defined — the Debug configuration only (Core/Debug.h, CMakeLists.txt). In Dev and Release the call is unsynchronised and silent.
The check is also skipped while the stream is unbound. It runs if (threadID != TThreadID{}), and threadID is default until a worker's RunLoop records it, until the base stream's Start records it, or until a driven stream's first Update records it — the IO stream in particular has no thread id until its first pass (Engine/Core/TaskStream.cpp). A rate change aimed at a stream that has not been driven yet is never detected, which is also the window in which the change is meant to be made.
The ratio takes effect on the next lane choice, and it is expressed in allowance units. StreamDrainPolicy::ConfigureRate owns the arithmetic: the weights split the allowance the stream was configured with, so a stream with an unlimited allowance has a ratio with nothing to divide — the lane book is only charged when a budget is being measured (Update, GetAccumulatedCPUTime).
