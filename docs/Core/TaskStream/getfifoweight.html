GetFifoWeight

member of hbe::TaskStream Engine/Core/TaskStream.h The FIFO lane's configured share of the stream's allowance.

Signature

[[nodiscard]] uint32_t GetFifoWeight() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskStream.h, returning drainPolicy.GetFifoWeight(); there is no counterpart in Engine/Core/TaskStream.cpp. The FIFO lane's configured share of the stream's allowance.

It reports what was configured, not what the policy treats as in force. ConfigureRate documents that "Zero weights are treated as one, not as 'never serve this lane'" (Engine/Core/TaskStream.h), and this accessor forwards the stored value to StreamDrainPolicy::GetFifoWeight — so a caller that passed 0 reads 0 back and must remember that the lane is being served as a weight of one.
A weight on a stream with no allowance divides nothing. The ratio splits the CPU allowance, and with no allowance configured the lane book is never charged at all — the drain charges ChargeFifo and ChargePriority only inside the branch that measures CPU (Update, GetAccumulatedCPUTime). Reading a weight here says nothing about whether the ratio has any effect on this stream.
The getter exists so a temporary re-rate can be undone exactly, in the same idiom as GetMaxAge: save, configure, restore (Engine/Core/TaskStream.h).

Parameters

None.

Return value

TypeWhat you get
uint32_tThe stored FIFO weight, as ConfigureRate left it. The pair with GetPriorityWeight is the ratio

Examples

From Engine/Core/TaskStream.cpp, TaskStream::ConfigureRate()

drainPolicy.ConfigureRate(fifoWeight, priorityWeight);

The one writer of the field this reads, and the only place the ratio is ever set in the class (Engine/Core/TaskStream.cpp). Its own callers are all unit-test code — every ConfigureRate call site in the repository sits inside the #ifdef __UNIT_TEST__ region of Engine/Core/TaskSystem.cpp — so a stream nobody re-rated reads back the constructed default, and a non-default reading means a test set it.
