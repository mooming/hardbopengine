Join

member of hbe::TaskStream Engine/Core/TaskStream.h Wait for this worker stream's thread to leave its loop; unsafe on a ride-on stream.

Signature

void Join() noexcept

Function description

Declared in the header Engine/Core/TaskStream.h, defined in Engine/Core/TaskStream.cpp. Wait for this worker stream's thread to leave RunLoop.

Called on a stream with no thread, this call terminates the process. std::thread::join throws std::system_error when the thread is not joinable, and this function is noexcept — so the throw finds no handler and std::terminate runs (Engine/Core/TaskStream.h). The base stream and the IO stream never get a thread (Start returns before creating one), so they are exactly the streams this must not be called on. The engine's own shutdown checks first: 
auto& thread = stream.GetThread();
if (unlikely(!thread.joinable()))
{
    ...
}

thread.join();

From Engine/Core/TaskSystem.cpp, TaskSystem::JoinAndClear() (the elided body continues to the next stream)

The engine does not use this function; it reaches for the thread directly. JoinAndClear takes GetThread(), tests joinable(), and calls join() itself, which is the only call site of either form in the repository (Engine/Core/TaskSystem.cpp). This wrapper is never called — it is the accessor GetThread with the safety check removed, and it is the reason the class needs neither: the check has to be at the call because the state that decides it lives in the thread object.
Joining is not the shutdown, and it is not what tells you a stream finished its work. A worker's thread exits RunLoop only after the drain has run, so a join does imply the drain happened; but a driven stream has no thread to join at all, which is why the header directs a shutdown waiter elsewhere: "Whoever orders the shutdown waits on this rather than on a thread handle, because a driven stream has no thread to join" (IsClosed, Engine/Core/TaskStream.h).
Double-joining is the same failure as joining a threadless stream. A joined std::thread is no longer joinable, so the second call throws into a noexcept function (Engine/Core/TaskStream.h). Nothing here records that the join already happened — thread itself is the only witness, and it is readable through GetThread.

Parameters

None.

Return value

void. It returns once the thread has run its exit path, including the drain and the close report.

Examples

Illustrative — no call site for this exists in the repository; the shutdown joins through GetThread() instead.

stream.RequestClose();

if (stream.GetThread().joinable())
{
    stream.Join();
}

The guard is not decoration: it is the difference between waiting for a worker and terminating the process on a ride-on stream. The order matters too — RequestClose sets the flag and notifies, and only then is there a loop for a join to wait out.
