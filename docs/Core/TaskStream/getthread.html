GetThread

member of hbe::TaskStream Engine/Core/TaskStream.h The stream's thread object, for a shutdown that has to ask whether there is one.

Signature

[[nodiscard]] std::thread& GetThread() noexcept

[[nodiscard]] const std::thread& GetThread() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskStream.h; there is no counterpart in Engine/Core/TaskStream.cpp. Both overloads return the std::thread member by reference — the const form yielding a reference to a const thread — because the only useful thing to do with a thread is to ask it whether it is joinable, and that question has to be asked of the object, not a copy.

Two overloads, one difference that is not what it looks like. The const overload can join nothing: std::thread::join() is not a const operation, so what it offers is inspection — joinable(), get_id(), comparison. Both forms hand out a reference into the stream, so both die with it; a reference kept past the stream's destruction is dangling, and unlike GetName there is no value form to keep instead (Engine/Core/TaskStream.h).
The engine uses this instead of Join, and the reason is the check Join lacks. 
auto& thread = stream.GetThread();
if (unlikely(!thread.joinable()))
{
    continue;
}

thread.join();

From Engine/Core/TaskSystem.cpp, TaskSystem::JoinAndClear()

The base and IO streams never had a thread (Start returns before creating one), so their entry in the sweep must be recognised and skipped; joining a non-joinable thread throws, and Join is noexcept, which turns the throw into std::terminate (Engine/Core/TaskStream.h). This accessor is what makes the shutdown loop able to tell the two kinds of stream apart.

It is also the hole in Start's second-call guarantee. The same reference is how a caller could reach the member Start assigns to: assigning to a joinable std::thread calls std::terminate, and nothing in the class marks a stream as started (Engine/Core/TaskStream.cpp). Exposing the thread is the cost of making the shutdown joinable at all; the safety of both operations belongs to the code that holds the stream.
