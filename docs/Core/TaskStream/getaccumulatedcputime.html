GetAccumulatedCPUTime

member of hbe::TaskStream Engine/Core/TaskStream.h CPU time this stream has charged to its budget in the current window.

Signature

[[nodiscard]] std::chrono::nanoseconds GetAccumulatedCPUTime() const noexcept

Function description

Defined in Engine/Core/TaskStream.cpp as TaskStream::GetAccumulatedCPUTime(); the body is one call, budget.GetAccumulated() (CPUBudget::GetAccumulated). The CPU time this stream has charged to its budget since the window last reopened.

Zero usually means nothing was being measured, not that work was free. "A stream with no allowance does not measure its tasks at all. A measurement that cannot change a decision is a syscall billed to every task for nothing, and an unlimited budget cannot change a decision. Consequently GetAccumulatedCPUTime stays zero until an allowance is set - that is the absence of accounting, not a task that cost nothing." (Engine/Core/TaskStream.h) The gate is one boolean in the pass — budget.GetAllowance().count() > 0.0 — around BeginTask and EndTask (Update, ConfigureBudget). One application sets an allowance — the engine-test application gives the base stream a one-millisecond window — so on every other stream in every run this reads zero whether or not tasks ran (ConfigureBudget).
The number is reset, so it is a window reading rather than a life total. The pass that reopens the window calls budget.Reset(), which clears the accumulated charge (RequestWindowAdvance, CPUBudget::Reset). A reader comparing two reads has to know whether a window closed between them; the counter that never resets is GetDrivenPassCount, and the counters that never reset but count refusals are GetLaneWorkRefusalCount and its siblings.
Readable from anywhere, written by one thread, and the header states exactly what a foreign reader sees. "Readable from any thread, though it is written only by the stream's own thread; reading it elsewhere sees the value as of the last task that thread finished." (Engine/Core/TaskStream.h) A task in flight is not in the number, which is the same boundary as the overshoot rule: a running task is charged when it ends (MayTakeNewWork).
The field itself is not atomic. CPUBudget keeps its accumulated charge as a plain duration written by the owning thread (CPUBudget::EndTask), so the header's "readable from any thread" describes intent rather than a synchronised read: a concurrent read while the owner is charging a task is an unsynchronised read of a plain field, and nothing in either class detects it (Engine/Core/TaskStream.h).

Examples

From Engine/Core/TaskStream.cpp, TaskStream::Update()

const auto chargedBefore = chargingBudget ? budget.GetAccumulated() : std::chrono::nanoseconds::zero();
if (chargingBudget)
{
    budget.BeginTask();
}

The pass reads the same field to price a single task: after EndTask() it subtracts this reading from the next one and charges the difference to the lane the item came from (Engine/Core/TaskStream.cpp). That is the only consumer of the number inside the engine.
