AbandonHeldWork

member of hbe::TaskStream Engine/Core/TaskStream.h Discard every held work item, firing each one's abandonment notice, and say how many.

Function description

Defined in Engine/Core/TaskStream.cpp as TaskStream::AbandonHeldWork(). Discard every work item this stream still holds in its two lanes, firing each item's abandonment notice on the way out.

From Engine/Core/TaskStream.cpp

This is the only place the engine drops work it will never run and also tells somebody. "A closing stream must call it before reporting, because a count without a notice is a promise that was cancelled silently." (Engine/Core/TaskStream.h) The notice is fired per item, before the item is gone, and the count of notices is what GetAbandonedWorkNoticeCount reports — a caller learns through its own callback first and the counter second (FireAbandonedNotice).
It takes no lock, so its safety is the caller's arrangement, not its own. Every other reader of fifoQueue and priorityQueue holds queueLock; this function walks both containers with no lock at all (Engine/Core/TaskStream.cpp). That is sound exactly when no producer can be enqueueing and no driver can be inside a pass, which is why both call sites are places where the driver has already been withdrawn — the worker's exit path, and a driven stream closed after its driver is cleared (RunLoop, CloseDrivenStream). Called anywhere else, it races an EnqueueFifo.
Items sitting in the re-add buffers are not abandoned, and nothing counts them. A pass that takes an unfinished item parks it in readdingFifo or readdingPriority until the next pass puts it back on its lane (Update). This function empties only the two lanes, and CountPendingItems counts only the two lanes, so an item in a buffer is invisible to both the count and the abandonment: it will never run, and its notice will never fire (Engine/Core/TaskStream.cpp). The window is one item per lane, created by the last pass of a stream that closes before running again.
The returned count is the same measurement a reporter used to take from the queue depths. "The number of items abandoned, which is the count the closing report used to obtain from CountPendingItems alone - the same measurement, taken by whoever is about to destroy the items." (Engine/Core/TaskStream.h) Report the returned number, not a fresh count: after this call the lanes are empty and a later count reads zero.

if (const auto abandoned = AbandonHeldWork(); abandoned > 0)
{
    Logger::Get(name).OutWarning([name = name, abandoned](auto& ls)
    {
        ls << name.c_str() << " is closing with " << abandoned
           << " item(s) still held. They are abandoned, not requeued, and every requestor that asked to be told "
              "has been told, on this thread, as each one was dropped."
           << " The count is not the report: an item discarded without a word is a promise cancelled silently.";
    });
}

The count is used as a condition, not as the report — the notices have already fired by the time this line runs, which is the ordering the header asks for (Engine/Core/TaskStream.h).
