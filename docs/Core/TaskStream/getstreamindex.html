GetStreamIndex

member of hbe::TaskStream Engine/Core/TaskStream.h This stream's index in the task system, the value every route uses.

Signature

[[nodiscard]] auto GetStreamIndex() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskStream.h; there is no counterpart in Engine/Core/TaskStream.cpp. This stream's index in the task system's stream array — the value every other type routes by.

It is a constructor argument, not an assignment the system makes, and that is what closes the routing loop. TaskSystem constructs each stream with its own slot index and never changes it (Engine/Core/TaskSystem.cpp, TaskStream), so the index a stream reports is the index its tasks were offered to. The type is hbe::TStreamIndex, which is int (Core/TaskStreamIndex.h), and auto in the declaration deduces that.
A default-constructed stream reports index 0, which is the base stream's index. The default constructor initialises streamIndex(0) (Engine/Core/TaskStream.cpp), and TaskSystem::BaseStreamIndex is 0, so the object that means "no stream" and the object that means "the engine's own stream" answer this question identically. The two are told apart by the name (GetName is empty on the former) and by whether a task system was ever recorded (Start), never by the index alone.
The index is what Update publishes for the duration of a pass. Each pass calls TaskSystem::SetStreamIndex(streamIndex) and restores the previous value on the way out, so code running inside a task can ask which stream it is on — and code running on a driven thread can ask the same question while the answer belongs to whichever pass is in flight (Start, Engine/Core/TaskStream.cpp). The budget and provider paths also compare against it: the base stream is the only one that runs the budget window pass (RequestWindowAdvance).
