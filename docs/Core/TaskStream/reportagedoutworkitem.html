From Engine/Core/TaskStream.cpp

The wording is deliberately the same shape as a released task's, because the reader's question is the same. "Same vocabulary as a released task on purpose: in both cases the engine had work, decided not to run it, and owes whoever queued it a sentence saying which. age is measured against the engine's own epoch base, so it is comparable with the lane time book in the same log." (Engine/Core/TaskStream.h) ReportReleasedTask is the sibling line; the difference a reader looks for is the reason clause — "aged Nns, older than this stream's max age" against "because that task had already been released".
The caller computes the age, and the two callers compute it the same way. Update passes now - workItem->offerTime where now is time::ElapsedSinceEngineEpoch() in nanoseconds, so the number in the line is elapsed-from-offer and the epoch base is shared with the policy's own book (SetMaxAge). Nothing here validates age, so a caller passing a wall-clock duration instead would print a number that is not comparable with anything (Engine/Core/TaskStream.cpp).
It reports only: it does not count, does not notify and does not drop. The count is the caller's agedOutWorkCount increment and the notification is FireAbandonedNotice, called on the line after this one (Engine/Core/TaskStream.cpp). Splitting the three is what lets a future drop site log with a different sentence while still being unable to skip the notice.
The line names a record by index and generation, not by task name. A dropped item is a WorkItem, and the stream never looked the task up to print this — the lookup happens before, and its failure has its own report (ReportReleasedTask). So the line is greppable by TaskID parts, and finding the task's name means taking those numbers back to TaskRegistry::Find while the generation still matches (Engine/Core/TaskStream.cpp).
