TaskStream

member of hbe::TaskStream Engine/Core/TaskStream.h Build an inert stream: a name, an index, and a shutdown window chosen by index.

Signature

TaskStream()

explicit TaskStream(StaticString name, TStreamIndex streamIndex)

Function description

Both defined in Engine/Core/TaskStream.cpp as TaskStream::TaskStream(). Neither starts anything: no thread is created, no task system is recorded, and nothing is configured. A constructed stream is inert until Start gives it a system and a driver. 

TaskStream::TaskStream()
    : streamIndex(0)
    , loopCount(0)
    , allocator("None")
{
    Assert(threadID == std::thread::id());
}

TaskStream::TaskStream(StaticString name, TStreamIndex streamIndex)
    : name(name)
    , streamIndex(streamIndex)
    , loopCount(0)
    , allocator(name)
    , shutdownDrainDeadline(streamIndex == TaskSystem::BaseStreamIndex || streamIndex == TaskSystem::IOStreamIndex
                                    ? std::chrono::milliseconds::zero()
                                    : std::chrono::milliseconds(2000))
{
    auto log = Logger::Get(name);
    log.Out([name = name](auto& ls) { ls << name.c_str() << " is created."; });
}

From Engine/Core/TaskStream.cpp

The named constructor is where a stream's shutdown window is decided, and it is decided by index. The base and IO streams get std::chrono::milliseconds::zero and every other index gets 2000 ms, because for the engine's own streams "run until the queues are empty" is not what closing means — the IO stream's work is the log buffer, and writing a line re-posts the drain task (DrainForShutdown, Engine/Core/TaskStream.h). The comparison is against TaskSystem::BaseStreamIndex and TaskSystem::IOStreamIndex, so the rule travels with the index and not with a name: construct a stream with index 0 and it closes with no window (Engine/Core/TaskStream.cpp).
The default constructor is a placeholder that does not match any real stream. It names its allocator pool "None", leaves name empty and taskSystem null, and takes streamIndex = 0 — the base stream's index — while leaving shutdownDrainDeadline at the member default of 2000 ms (Engine/Core/TaskStream.cpp, Engine/Core/TaskStream.h). So a default-constructed stream reports the base stream's index with the base stream's window not applied to it, and calling Update on one dereferences the null task system (Start is what records it). It exists because TaskSystem builds its stream array by Array<TaskStream> reallocation and element construction (Engine/Core/TaskSystem.cpp) and needs a default-constructible element type.
The object cannot be copied or moved, and the reason is the members rather than a declaration. Neither constructor declares copy control; the class holds std::mutex, std::condition_variable and std::thread, whose own special members are deleted, so TaskStream's copy constructor, copy assignment and move constructor are implicitly deleted. That was confirmed by compiling a probe in which std::is_copy_constructible_v, std::is_copy_assignable_v and std::is_move_constructible_v were each asserted false (c++ -std=c++2b -fsyntax-only, no diagnostic). A stream therefore lives where it was constructed — which is what makes its streamIndex a stable identity (GetStreamIndex) and the this captured by Start's thread lambda always valid.
Nothing validates the index against the system that will own the stream. The constructor takes streamIndex as given, and the only checks that ever compare it to anything are the base-stream tests inside Start, Update and this constructor's own deadline rule (Engine/Core/TaskStream.cpp). A stream constructed with an index beyond the array it is later placed in is not detected by this class; it simply never runs the base-stream duties, and the shutdown's expectations about which index those belong to go unmet.
