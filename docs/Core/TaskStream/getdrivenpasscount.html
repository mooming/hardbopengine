GetDrivenPassCount

member of hbe::TaskStream Engine/Core/TaskStream.h How many Update passes this stream has run, on whichever thread drove it.

Signature

[[nodiscard]] std::uint64_t GetDrivenPassCount() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskStream.h; there is no counterpart in Engine/Core/TaskStream.cpp. How many Update passes this stream has run, on whichever thread drove it.

It counts passes, not work, and it is the only pass accounting a ride-on stream has. The field is incremented at the top of every pass, before anything is taken, so it counts attempts — including the pass that found nothing and the pass that only ran posted callables (Engine/Core/TaskStream.cpp). It is what CloseDrivenStream prints in the close line, "closed after N driven pass(es)", which is the only figure a driven stream reports about its own life.
The field is a plain counter, and its thread rule is stated as a convention rather than enforced. The header describes the sibling counter loopCount as "Written by the single thread driving this stream, so it needs no atomic", and drivenPassCount is the same kind of field with no such note (Engine/Core/TaskStream.h). A read from another thread — the shape a shutdown reporter or a watch uses — is an unsynchronised read of a field being incremented elsewhere; the value may be stale or torn on a platform where that matters, and nothing detects it.
It is not the same number as GetLoopCount, and both are incremented in the same pass. loopCount is incremented inside the pass, after the stream index and allocator have been entered; drivenPassCount is incremented before posted callables run. A pass that ends early — a close request, seen two statements after the pump — advances the driven count and not the loop count (Engine/Core/TaskStream.cpp). Use the driven count for "how many times was this stream pumped", the loop count for "how many times did it get as far as deciding what to run".
