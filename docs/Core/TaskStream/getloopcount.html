GetLoopCount

member of hbe::TaskStream Engine/Core/TaskStream.h How many passes reached the lane decision, written by the stream's own driver.

Signature

[[nodiscard]] auto GetLoopCount() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskStream.h; there is no counterpart in Engine/Core/TaskStream.cpp. How many passes reached the point of deciding what to run, as std::uint64_t.

The header states this field's thread rule in one clause, and the clause is a convention. "Written by the single thread driving this stream, so it needs no atomic." (Engine/Core/TaskStream.h) The field is a plain std::uint64_t; the rule is true of a worker whose loop is the only driver and is a promise rather than a mechanism for a driven stream, where the "single thread" can be whichever host thread arrives (Start). A cross-thread read of it is unsynchronised, and nothing detects that.
It is not GetDrivenPassCount, and the gap between them is a diagnostic. Update raises the driven count before anything else happens and the loop count only after the stream index and allocator scope have been entered and the posted callables run — so a pass that returned early on a close request advanced one counter and not the other (Engine/Core/TaskStream.cpp). A stream whose driven count leads its loop count by a lot has been pumped repeatedly while declining to take work, which is what a closed-but-still-driven stream looks like.
Nothing in the engine reads it. No line in Engine/ or Applications/ calls this accessor (Engine/Core/TaskStream.cpp); the class writes the field for whoever is watching from outside — a harness that wants to prove a stream was driven at least N times, which the shutdown pump proves nothing about on its own (IsDrivenByShutdownPump).
It never resets, and it counts attempts rather than work. A pass that found nothing, a pass that only ran posted callables, and a pass that dropped a dead item all count here (Engine/Core/TaskStream.cpp). It is a life total, so a non-zero value says only that this stream ran at some point since construction — the counters that name a specific event are GetLaneWorkRefusalCount, GetAgedOutWorkCount and their siblings.
