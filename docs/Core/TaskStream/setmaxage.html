SetMaxAge

member of hbe::TaskStream Engine/Core/TaskStream.h Set the oldest work this stream will still run; zero means unlimited.

Signature

void SetMaxAge(std::chrono::nanoseconds maxAge) noexcept

Function description

Declared in the header Engine/Core/TaskStream.h, defined in Engine/Core/TaskStream.cpp, forwarding to drainPolicy.SetMaxAge(maxAge). Set the oldest work this stream is still willing to run; zero means unlimited, and unlimited is the default.

The ceiling is a property of the stream, and the header explains why it is not a property of the task. "A stream whose frame budget slipped can still be holding work whose context was destroyed, re-pointed or simply irrelevant several frames ago; running it late is worse than not running it, because the work looks fresh to whoever queued it and stale to whoever owns the state it touches. The ceiling is stated here rather than per task because staleness is a property of the stream: the same task is still worth running on a background stream and worthless on a frame-bound one." (Engine/Core/TaskStream.h)
Over-age work is dropped, and dropping it is a three-part act. The pass judges age after the task lookup and before the run: 
if (const auto now = std::chrono::duration_cast<std::chrono::nanoseconds>(time::ElapsedSinceEngineEpoch());
        drainPolicy.IsOverAge(workItem->offerTime, now))
{
    agedOutWorkCount.fetch_add(1, std::memory_order_relaxed);
    ReportAgedOutWorkItem(*workItem, now - workItem->offerTime);
    FireAbandonedNotice(*workItem);
    restore();
    return true;
}

From Engine/Core/TaskStream.cpp, TaskStream::Update()

Counted, logged, and notified — "over-age work is dropped, reported and notified exactly like work whose task was released - it is never run, never requeued, and never silently discarded" (Engine/Core/TaskStream.h; ReportAgedOutWorkItem, FireAbandonedNotice, GetAgedOutWorkCount). The pass then returns true: a drop is a pass that did something.

Age is measured from the item's offer time against the engine epoch, so the clock is shared and the ceiling is absolute. The instant compared is time::ElapsedSinceEngineEpoch() and the stamp is WorkItem::offerTime, set when the item was built — which means age keeps accruing while work waits behind a long task, and a stream that is starved by policy (StreamDrainPolicy) ages its whole lane whether or not it is running (Engine/Core/TaskStream.cpp).
Only the item is dropped, not the task — and the task may never be finished by anyone. A work item covers one index range of a task that declared a join. Dropping one sub-task leaves the declared count unfulfilled, so a caller that tightens a ceiling on a stream that carries split work must be ready for a task that never completes; the notice fired here is the only signal it gets (FireAbandonedNotice).

The getter's stated purpose is restoration: "Readable so a caller that temporarily tightens a shared stream can put back exactly what it found." Set-and-restore is the whole idiom, and a caller that sets a ceiling without saving the previous value leaves it on the stream for whoever runs next (Engine/Core/TaskStream.h).
