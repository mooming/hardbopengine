TaskStream

Engine/Core/TaskStream.h One stream's two lanes and everything that makes them runnable: the queues, the drain policy, the CPU budget, the provider lists and the posted-task pump.

Class description

class TaskStream final at Engine/Core/TaskStream.h: one lane pair — a FIFO lane and a priority lane — plus the lock, condition variable, CPU budget, drain policy, provider lists and posted-task queue that make those lanes runnable by a thread. It is where work is taken, and the class the task system spends most of its rules arguing about.

Two lanes, one policy, one budget — and the three books are kept separately on purpose. fifoQueue and priorityQueue hold work; StreamDrainPolicy decides which lane to serve next from per-lane time shares and a staleness ceiling; CPUBudget decides whether the stream may take work at all. The header insists on reading both throttles: "the engine throttles from two books, and a watch that reads only one cannot see work held by the other" (Engine/Core/TaskStream.h).
A stream may be threaded or driven, and both paths run the same Update. A worker stream owns a std::thread and parks on cv between passes; the engine's own streams are pumped by whoever owns that thread, which is why taskSystem is "recorded rather than looked up: Update may run on a thread that outlives the engine, so it cannot resolve the task system through the live engine the way a thread-owned loop can" (Engine/Core/TaskStream.h). drivenPassCount and drivenByShutdownPump exist for the driven case.
Posted work lives on the stream, beside the lanes, rather than next to the stream that posted it. postedTasks is a MainThreadTaskQueue, and the header records the bug that fixed: "a wait that drives the stream then cannot fail to reach posted work, which was a real deadlock and not a hypothetical one" (Engine/Core/TaskStream.h). One pump reaching everything is the invariant; isPumping and nestedPumpAllowed are what stop a pump from nesting inside itself.
Shutdown is a drain with a deadline, and the deadline differs by stream. isDrainingForShutdown suspends provider probing — a stream on the way out finishes what it holds and asks nobody new — while shutdownDrainDeadline bounds the attempt. The default is 2000 ms, and the base and IO streams get none: "'run until the queues are empty' is not what closing them means: the IO stream's work is the log buffer, and writing a line re-posts the drain task, so draining it to emptiness is a loop that ends only at the deadline - measured at over 2.6 million passes and the full window for no work but its own" (Engine/Core/TaskStream.h).
Every refusal is counted, because a stream that declines work looks identical to one with nothing to do. generalQueueRefusals (allowance spent, work left in the general queue), laneWorkRefusals (a pass found lane work and the policy returned no lane), providerAsksWhileSpent ("It must stay zero: a spent stream that still manufactures work will run work it has no right to"), agedOutWorkCount and abandonedWorkNoticeCount. The last two are the observable form of the two failures a queue can commit against a caller's work: dropping it for age, and abandoning it at shutdown (Engine/Core/TaskStream.h).

Template parameters

None. TaskStream is final and not a template; the variability a stream carries is in the policy, budget and lane weights it is configured with.

Non-member helper functions

One file-local helper, in an anonymous namespace in Engine/Core/TaskStream.cpp: constexpr size_t ProviderSlot(StreamDrainPolicy::ELane lane) maps FIFO to 0, Priority to 1 and ELane::None to 2 — "an out-of-range index when the lane is None" — so each of the three provider calls rejects a no-lane request with the same bounds test against a two-element array.
