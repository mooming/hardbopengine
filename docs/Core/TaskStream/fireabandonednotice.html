From Engine/Core/TaskStream.cpp

The single place that decides whether to notify a work item's requestor that the item will never run. Every drop site that holds an item calls it, so a new drop site cannot log without notifying, or notify without a log line to go with it (Engine/Core/TaskStream.h).

Log text stays per-site; only the decision to notify is shared. "Update's" released-task line, its aged-out line, the drain's abandonment line and the driven close's abandonment line each say something different about why the work died — and each of them calls this afterwards (Engine/Core/TaskStream.h, ReportReleasedTask, ReportAgedOutWorkItem, DrainForShutdown, CloseDrivenStream). The helper owns the callback, not the sentence.
It runs a caller's function pointer on the stream's thread, inside the stream, with no guard. The notice is invoked synchronously where the drop happened: inside Update under nothing but the pass's own scope, or inside the drain after the loop. A notice that blocks delays the stream — and a notice that throws propagates out of a noexcept function into std::terminate (Engine/Core/TaskStream.cpp). The item's abandonedUserData is passed through untouched, so its lifetime is the poster's obligation at post time, not this call's.
A null notice is not a lost signal; it is the requestor's choice. An item built without a notice is dropped silently by design, which is why the count of abandoned items and the count of requestors informed are different numbers: GetAbandonedWorkNoticeCount counts items, and the header states that "a stream can abandon ten items and notify nobody and still read ten here" (Engine/Core/TaskStream.h).
The one mechanism whose failure is invisible is why a test is allowed to see this at all. The header's reason for the friend class TaskSystemTest declaration sitting beside this member: "an item that should notify and silently does not looks exactly like a stream with nothing to report", and the alternative — publishing a drop-site helper as engine API — "is the trade that gets used by accident later" (Engine/Core/TaskStream.h). The function is therefore private and testable, and not public.

void. It does not report whether a notice fired, so a caller cannot count notifications from this call's result — the counters exist for that, and they count items instead.
