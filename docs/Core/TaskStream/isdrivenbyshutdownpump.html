IsDrivenByShutdownPump

member of hbe::TaskStream Engine/Core/TaskStream.h Whether the shutdown pump has ever driven this stream rather than the engine loop.

Signature

[[nodiscard]] bool IsDrivenByShutdownPump() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskStream.h; there is no counterpart in Engine/Core/TaskStream.cpp. Whether the engine's shutdown path has ever taken over this stream's pumping, rather than the engine loop driving it.

A plain read of a one-way mark, and its whole use is provenance. The flag is set by SetDrivenByShutdownPump and never cleared, so a true answers "did the rescue ever run this stream in this process", not "is the rescue running it now" (Engine/Core/TaskStream.h). A test that found true after a run has learned that some work executed on the shutdown's pump — which is why the header insists the flag is one of two halves.
The header names the case this flag cannot catch. "Provenance alone cannot detect a loop that pumps once and stops: before the suite was split, one Update() was enough to run all 59 collections inside a single work item, so the flag was legitimately false in the defective build and the run looked clean." (Engine/Core/TaskStream.h) What closes that hole is the shape of the suite — one task per testlet, each posting its successor, with the harness refusing a gap. Reading this flag as proof that the engine loop worked is the mistake the comment was written to prevent.
The read is unsynchronised by construction. drivenByShutdownPump is a plain bool, not an atomic (Engine/Core/TaskStream.h), unlike the close flags beside it. It is readable at all because of when it is written — the driver thread, before the pump it marks — so a reader on a different thread is relying on that arrangement rather than on the type.
The engine sets the flag; the test harness is the party that asks. The writer is TaskSystem::JoinAndClear, and the reader is the per-testlet entry of the unit-test suite, which asks the base stream before the testlet runs and records the answer against the run (Engine/Test/UnitTestCollection.cpp). Its comment gives the reason for the timing: "Asked of the stream before the testlet runs, because this is a question about who is driving, and a testlet that has already reported cannot answer it." On a worker stream the answer is always false: the shutdown only asks a worker to close, and the worker's own thread does the rest (RunLoop, RequestClose).

Parameters

None.

Return value

TypeWhat you get
booltrue if the shutdown pump has ever driven this stream in this process; false means either the loop drove it or the stream was never driven at all

Examples

From Engine/Core/TaskSystem.cpp, TaskSystem::JoinAndClear()

baseStream.SetDrivenByShutdownPump();

The writer, and the reason the read is meaningful: the mark goes down at the moment the shutdown commits to pumping the base stream itself (Engine/Core/TaskSystem.cpp). The suite's read turns that into a verdict — a run in which the flag is set has had its results produced by the rescue path, and the harness notes it so the run cannot look like a pass (Engine/Test/UnitTestCollection.cpp).
