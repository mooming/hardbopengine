Dequeue

member of hbe::TaskStream Engine/Core/TaskStream.h Private helper that pops whichever lane holds work, ignoring the drain policy; declared and never called.

From Engine/Core/TaskStream.cpp

Pop the priority lane if it holds anything, else the FIFO lane, else clear the output. The design choice is stated where the helper was written: it "serves work whenever there is any, without consulting the drain policy: the rate and the budget gate the stream's own loop, and gating here would let a caller's refill stall on an exhausted allowance." (Engine/Core/TaskStream.cpp) It is the lane-taking half of Update extracted, minus the policy decision: the pass chooses a lane and takes from that lane alone, while this takes from whichever lane is non-empty and always takes the priority lane first.

It has no caller. Not one. Update does the same work inline under one lock and consults ChooseLane first (Update), and the only friendship that could reach a private member here is friend class TaskSystemTest, whose tests do not call it: no line in Engine/ or Applications/ calls this function (Engine/Core/TaskStream.cpp). Its comment describes a caller — "a caller's refill" — that the codebase does not contain. It is compiled only because a private member function is never reported as unused, and it is the single member of this class not declared noexcept.
It is not merely unused, it is not equivalent: it spends lane credit it never asked for. Both branches call drainPolicy.CommitTake, which is the call that records a take against the lane the policy is balancing (StreamDrainPolicy::CommitTake). A pass that took work through this helper would consume a lane's share without ChooseLane having granted it, and would take the priority lane whenever it held anything regardless of the configured ratio — the exact inversion of the reason Update asks the policy first (Engine/Core/TaskStream.cpp).
What the helper does get right is the lock. It takes queueLock for the whole pop, so it is safe against a concurrent producer — the guarantee that makes it look finished. The defect is not its body but its place: the class already has a correct lane take inside the pass, and this is a second copy of the mechanism with a different policy (Engine/Core/TaskStream.cpp).
