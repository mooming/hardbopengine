GetAgedOutWorkCount

member of hbe::TaskStream Engine/Core/TaskStream.h Times this stream dropped work for being older than its max age.

Signature

[[nodiscard]] std::size_t GetAgedOutWorkCount() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskStream.h; there is no counterpart in Engine/Core/TaskStream.cpp. How many work items this stream has dropped for being older than its max age (SetMaxAge).

The header states why a counter rather than a log line, and it is a testability argument. "A counter rather than a log scrape, so a caller can tell 'the ceiling never fired' from 'the ceiling fired and I cannot see it'. A drop that is invisible in both places is the defect this feature exists to avoid, so it must be visible in one of them by construction." (Engine/Core/TaskStream.h) It is incremented in the same three-statement block that logs and notifies, so the two cannot disagree about a drop that happened — but only this one is readable by a test. 
agedOutWorkCount.fetch_add(1, std::memory_order_relaxed);
ReportAgedOutWorkItem(*workItem, now - workItem->offerTime);
FireAbandonedNotice(*workItem);

From Engine/Core/TaskStream.cpp, TaskStream::Update()

What a non-zero value means: this stream threw away work it was configured to throw away. Age is judged against WorkItem::offerTime and the engine epoch after the task lookup, so every item counted here was live work that arrived too late to be worth running (SetMaxAge). A rising count is a latency symptom upstream — the queue is deeper or slower than the ceiling assumes — and the tasks those items belonged to declared a join those items will now never fill (FireAbandonedNotice). With the ceiling at zero, which is the constructed default, this counter can never move, so a non-zero reading always names somebody's configured ceiling.
Zero resets, and neither does this counter. Nothing clears it — not the window reopen, not the drain, not the close — so it is a life total and a non-zero answer may describe an earlier phase of the process (Engine/Core/TaskStream.cpp). Its companion for work dropped at close, not for age, is GetAbandonedWorkNoticeCount, and the two together are the whole record of work this stream gave up on.

Read the ceiling and the counter together: the first says what was configured, the second says whether it bit (Engine/Core/TaskStream.h). A ceiling of zero with a non-zero counter is impossible; a ceiling of zero with a zero counter proves nothing about the run, because nothing was ever eligible to age out.
