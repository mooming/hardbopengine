constructors

member of hbe::ScopedLock Engine/Core/ScopedLock.h takes the lock on the spot, and in a profiled build also records the hold's start, threshold and call site

Signature

// Shape compiled when PROFILE_ENABLED is 1 (Engine/Config/BuildConfig.h defines it as 0 today):
explicit ScopedLock(TLockable&amp; lockable, float timeOutSec = 0.01f,
                   const TSrcLoc&amp; srcLoc = TSrcLoc::current());
ScopedLock(const ScopedLock&amp;) = delete;

// Shape compiled when PROFILE_ENABLED is 0:
ScopedLock(TLockable&amp; lockable);
ScopedLock(TLockable&amp; lockable, float);
ScopedLock(TLockable&amp; lockable, float, const TSrcLoc&amp;);
ScopedLock(const ScopedLock&amp;) = delete;

Function description

Every shape does the one thing a caller depends on: the constructor body calls lockable.lock() before it returns, so a guard that exists holds the lock, and the guard is the only handle on it. There is no unlock member and no release-on-failure path — the destructor is the only way the lock comes back. The result of lock() is discarded, whatever the lockable returns; the guard assumes acquisition succeeded.

When PROFILE_ENABLED is 1 the constructor is explicit — a lockable reference never becomes a guard by implicit conversion — and its member-initialization list records time::TStopWatch::now() into startTime before lock() runs, together with the timeout threshold and the call site. Under __DEBUG__ the body then multiplies the stored threshold by Config::DebugTimeOutMultiplier (2.0f, Engine/Config/EngineConfig.h:41), so a debug build tolerates twice the wall time before the destructor complains.

When PROFILE_ENABLED is 0 — every configuration shipped today — the lockable reference is the only argument that survives. The two additional constructors accept (lockable, float) and (lockable, float, TSrcLoc) and delegate to the one-argument form, discarding the timing arguments. That is deliberate: a call site that names a timeout and a source location compiles identically whether or not profiling is built in.

The one-argument constructor of the profiling-disabled shape is the one constructor in this class that is not explicit. The profiled shape marks its constructor explicit; the compiled-out shape leaves the single-argument form implicit. Copy-initialization — ScopedLock guard = mutex; — therefore names a locking intent in the build where the timing members do not exist, and fails to compile in the profiled one.
A timeout named at a call site is ignored, silently, when profiling is compiled out. The argument is accepted and dropped. It is not a runtime feature with a runtime off-switch — Engine/Config/BuildConfig.h defines PROFILE_ENABLED as 0 and no build configuration in this repository overrides it — so a call site written as ScopedLock(m, 5.0f) locks exactly like ScopedLock(m) today, and only means something if that header is edited.

The copy constructor is = delete, and no move constructor is implicitly generated: the user-declared copy constructor and the user-provided destructor jointly suppress it (confirmed by a -fsyntax-only probe of the same declaration pattern with std::is_move_constructible_v). A guard is therefore born in a scope and dies in that scope; nothing can carry the lock elsewhere. That matters because lock() ran on the constructing thread, and lockables that track an owner — std::mutex among them — require the matching unlock() on the same thread. The guard relies on the scope rule to give it that; it checks nothing itself.

Parameters

ParameterTypeRequirement
lockable TLockable& The mutex being held. Not owned: the guard stores a reference, so the lockable must be alive when the guard is destroyed, and the guard must not outlive it. It must satisfy CLockable — lock() and unlock() — and whatever state lock() expects (unlocked, unlocked-by-this-thread, recursive count) is the caller's obligation, not the guard's.
timeOutSec float (default 0.01f; accepted-and-discarded when PROFILE_ENABLED is 0) Hold threshold in seconds. The destructor warns when the measured span exceeds it; <= 0 disables the warning without disabling profiling state. Under __DEBUG__ the stored value is doubled by Config::DebugTimeOutMultiplier.
srcLoc const TSrcLoc& (default TSrcLoc::current(); accepted-and-discarded when PROFILE_ENABLED is 0) Call site written into the timeout warning's log line. Defaults to the construction point, which is the only value that makes the warning actionable. The type's own availability is qualified on the class page's Coverage section.

Return value

A constructed guard that already holds the lock. There is nothing to inspect afterwards: the class exposes no accessor and no query — its entire API is that it exists for the duration of a scope.

Examples

Illustrative — no call site for this exists in the repository. The only instantiation of ScopedLock anywhere in the tree is the explicit definition template class ScopedLock<std::mutex>; in Engine/Core/ScopedLock.cpp; even Engine/Engine/Engine.cpp, which includes the header, locks with std::lock_guard instead.

std::mutex counterLock;
long long committedCount = 0;

void Commit(int count)
{
        hbe::ScopedLock guard(counterLock, 0.05f);   // locks here
        committedCount += count;
}                                                                // unlocks here

Template argument deduction supplies TLockable = std::mutex from the first argument; the second names the hold threshold that only a profiled build reads. In every configuration shipped today the call is exactly the one-argument lock — see the destructor for what the threshold would do.
