TaskProduceContext

Engine/Core/TaskProvider.h The two facts a stream hands its providers: which stream is asking, and when.

Class description

struct TaskProduceContext final at Engine/Core/TaskProvider.h: everything a stream hands its providers on a Produce call, which is deliberately two facts — which stream is asking, and the instant of the drain.

FieldWhy it is here
streamA provider attached to several streams must know which one is asking — "it is the only way a provider can aim a successor task back at the right place" (Engine/Core/TaskProvider.h)
nowPassed rather than pulled, so every provider in one drain reasons about the same instant and none reaches for a global to find out what time it is
It carries no remaining budget, by decision. "The stream alone decides whether to call Produce at all; a provider also gating on the same figure creates two authorities over one quantity, and when they disagree exactly one of them is right while both look authoritative" (Engine/Core/TaskProvider.h). A provider that wants to stop being asked has Stop and DetachFrom; reading a budget it does not own is not among its options.
now is an instant, not a duration — a time::TEngineTimePoint, which is a std::chrono::time_point<std::chrono::steady_clock>, the same clock the engine epoch is taken from (Engine/Core/Time.h). Comparing two of them is valid arithmetic; subtracting two independently anchored durations is not. To turn this instant into an elapsed span, subtract time::GetEngineEpoch().
Both fields have defaults, so a context can be built that describes no drain. TaskProduceContext{} is well-formed C++ and means "stream 0, at the clock's zero time point" — and a provider that compares now against an item's stamp would compute an age of the whole uptime of the process. The ForStream factory is the convention, not a gate: the struct is aggregate-initialisable, and nothing detects a hand-built context. The header's own reasoning for the factory is the counter-argument to building one any other way — two providers in one drain would then reason about two different times, and a caller could not tell a scheduling effect from a clock effect.
How the engine builds one. TaskStream::DrainProvidersLocked() calls ForStream once per drain and hands the same context to every provider on that lane, returning the first item produced (Engine/Core/TaskStream.cpp). The context is a parameter, never stored: a provider that keeps it across calls is holding an instant that has already passed.

Non-member helper functions

None, and no operators: the context is copied by reference into Produce and compared by nobody. Its two fields are public because the type is a value passed for reading, and a provider reads them directly — this is the only place in the provider interface where a stream's state arrives without a getter.
