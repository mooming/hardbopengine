SetStreamIndex

member of hbe::TaskSystem Engine/Core/TaskSystem.h claims a stream for the calling thread by writing a thread_local index, which is the only thing that makes IsBaseThread, IsIOThread and the general queue's affinity rule mean anything

Signature

	static void SetStreamIndex(TIndex index) noexcept;

Function description

One assignment to thread_local TIndex StreamIndex, declared at Engine/Core/TaskSystem.cpp:24 and initialised to NonStreamIndex. A thread that nobody has called this for is not a stream, and nothing can tell it apart from a stream that has gone away — the value is the whole distinction.

Two shapes of use exist, and the difference between them is a real contract:

ShapeWhereDuration of the claim
Permanent claim TaskStream::RunLoop, Engine/Core/TaskStream.cpp:707 For the life of the thread. A stream that owns its own thread is that stream and nothing else
Pass-scoped claim TaskStream::Update, Engine/Core/TaskStream.cpp:365-369 One drain pass. The previous index is saved first and restored on the way out, because a driven stream shares its driver thread with whatever else that thread does
An index that is left set is a lie the whole engine believes. The value decides three things at once: whether this thread counts as the base stream, whether it counts as the IO stream, and which bit the general task queue sets in a work item's affinity when this thread fails to take it — see Dequeue. A thread that returns from a driven pass without restoring NonStreamIndex keeps charging work to a stream it is no longer serving, and nothing detects it: the value is a bare integer with no owner to check it against.

Parameters

ParameterTypeRequirement
index TIndex (int) The stream this thread is to be treated as, or NonStreamIndex — static_cast<TIndex>(-1) — to say it is none. No range check is performed against the stream array; an index above streams.Size() is accepted and is simply out of range for TaskStreamAffinity, which drops bits at or above its width

Return value

void. It cannot refuse, and it does not report the index it displaced.

Examples

From Engine/Core/TaskStream.cpp

// A driven stream shares its driver thread with whatever else that thread does, so the index and the allocator are
// entered and left around this pass rather than assumed for the lifetime of the thread.
const TStreamIndex previousStreamIndex = TaskSystem::GetCurrentStreamIndex();
TaskSystem::SetStreamIndex(streamIndex);
AllocatorScope scope(allocator);

auto restore = [&]() { TaskSystem::SetStreamIndex(previousStreamIndex); };

The base stream and the IO stream are driven by other threads — the engine loop and the logger's thread — so their identity has to be borrowed for the length of a pass and handed back. restore is called on every exit path of that function, which is the part a reader should copy: the scope is the pass, not the thread.
