HasStream

member of hbe::TaskSystem Engine/Core/TaskSystem.h whether the stream at index exists at this instant — the precondition of every call that reaches a stream by number, and not a lifetime guarantee

Signature

	[[nodiscard]] bool HasStream(TIndex index) const noexcept;

Function description

A bounds test on the stream array. Streams are built by Initialize and cleared by JoinAndClear, so the array is empty before startup and again once the pump has joined — and the index the caller is asking about is usually one of the constants, which look valid forever.

Reaching a stream by an unchecked index does not always fail. GetStream answers an index outside a built array with stream 0 rather than with a failure, so an unchecked index means work on the base stream, not a crash — the task simply runs somewhere plausible. Only an empty array stops, and it stops inside Array::operator[], because there is no stream 0 to hand back. That asymmetry is why this test matters: the loud case is the rare one.

It answers "can I index this now" and nothing more. It is not a lifetime guarantee across the call: a concurrent JoinAndClear can retire the stream between the test and the use, so a caller logging while another thread tears the pump down still needs its own ordering. The engine's own users treat it exactly that way — RequestOtherStreamsClose and JoinAndClear test before touching index 0, and ParallelFor refuses a whole split when one named index is not a stream.

Parameters

ParameterTypeRequirement
index TIndex (int) A candidate stream index. Negative values and values at or above the stream count answer false, which is the whole point — NonStreamIndex (-1) is a legitimate argument and answers false

Return value

TypeWhat you get
bool True while the array holds that index. Says nothing about whether the stream is closed, draining, or about to be retired
