GetIOTaskStreamIndex

returns 1 — the IO stream's index, and the number every worker range in the engine is measured from

Signature

static TIndex GetIOTaskStreamIndex() noexcept
{
        return IOStreamIndex;
}

Function description

Returns the constant IOStreamIndex (Engine/Core/TaskSystem.h:44), which is 1. Stream 0 is the base stream and stream 1 is the IO stream; everything from index 2 up is a worker created by BuildStreams, one per hardware thread past those two.

The value does real work as a boundary, not just as a name. ParallelFor's count form computes firstWorker = GetIOTaskStreamIndex() + 1 and chooses only from that range, which is what makes "never the base stream, never the IO stream" expressible without naming streams; RequestOtherStreamsClose spares this stream and the base stream when it asks everything else to close, because log work runs here and the reporting has to finish before the executor of it goes away.

The stream exists; its thread does not. The IO stream has no thread of its own — BuildStreams hands it to the logger with SetIODriver and the logger's own thread drives it. So this index names a queue and a drain policy, not a thread you can join, and a task queued here runs only while the logger is driving.

Parameters

None.

Return value

TypeWhat you get
TIndex (int) 1, always. Worker streams begin at 2; on a two-core machine there are none

Examples

From Engine/Core/TaskSystem.cpp

const TIndex firstWorker = GetIOTaskStreamIndex() + 1;
const TIndex numWorkers = streams.Size() > firstWorker ? streams.Size() - firstWorker : 0;

The worker-range computation inside ParallelFor, at Engine/Core/TaskSystem.cpp:556-557. Expressed as an offset from the IO stream rather than as the literal 2, so the two reserved streams can be re-ordered without every range in the engine moving with them.
