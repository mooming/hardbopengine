Update

member of hbe::TaskSystem Engine/Core/TaskSystem.h runs one engine frame of base-stream work inside the base frame budget — and stops early the moment a pass finds nothing to do

Signature

	void Update() noexcept;

Function description

Defined in Engine/Core/TaskSystem.cpp as TaskSystem::Update(). The base stream has no thread of its own — it rides the engine loop — so this call is not a tick that notifies something elsewhere; it is where base-stream work runs. Engine::Run calls it in a loop, and the loop's other statement is a std::this_thread::yield().

The deadline comes from time::GetBaseFramePeriod, derived from GetBaseFrameRate and described in its own header note as "the number budgets are measured against". That makes this function and RunBudgetWindowPass read the same yardstick, which is how a CPU allowance and a frame boundary can stay in step without either one owning the other.

The loop is work-driven, not time-driven. TaskStream::Update returns true when it took or dropped something and false when it found nothing, so the first empty pass leaves the loop even if the frame period has most of its time remaining. The deadline is a ceiling on one call, not a promise to fill it. 

if (streamIndex == TaskSystem::BaseStreamIndex)
{
	taskSys.RunBudgetWindowPass();
}

From Engine/Core/TaskStream.cpp, TaskStream::Update()

Advancing the CPU-budget windows is a side effect of this call. Inside the base stream's own pass, when its index is BaseStreamIndex, RunBudgetWindowPass is invoked (Engine/Core/TaskStream.cpp). So a thread that stops calling Update does not merely stop running base-stream tasks — every stream's budget window stops reopening too, and a stream whose allowance is spent takes nothing from its own lanes until one reopens.
One driver at a time, and the driver is the engine-loop thread. Every pass on a driven stream enters and restores the thread-local stream index and the allocator scope, precisely because a shared driver does not belong to that stream for its whole life (Engine/Core/TaskStream.h). Two threads calling Update on the same task system put two drivers on the base stream at once, and the ownership questions the rest of the engine asks — IsBaseThread, the owner-thread budget asserts, which allocator a task charges to — stop having one answer. Nothing here detects the second driver.

Parameters

None.

Return value

void. Whether any work ran is not reported; a caller that needs to know asks the stream, or uses TestHelper::DriveUntil, which is this call wrapped around a predicate.
