AreUserStreamsClosed

member of hbe::TaskSystem Engine/Core/TaskSystem.h true when every stream but the base and the IO stream has drained and left its loop — the condition JoinAndClear waits on

Signature

	[[nodiscard]] bool AreUserStreamsClosed() noexcept;

Function description

Defined in Engine/Core/TaskSystem.cpp as TaskSystem::AreUserStreamsClosed(). It scans the array, skips the two engine streams by address, and returns false at the first stream that has not reported itself closed. "User streams" is the same set RequestOtherStreamsClose asks to close: every stream that is neither the base stream nor the IO stream. "Closed" is the stream's own IsClosed() — for a stream that owns a thread, that means it saw the close request, drained what it held, and left its loop; it does not mean the thread has been joined, which is a later step in JoinAndClear.

Its one engine caller is the shutdown pump, which tests it every millisecond alongside two other conditions — posted work on the base stream and queued items — until either they all clear or the 2000 ms bound expires.

Unlike its sibling, this one has no guard for an empty array. RequestOtherStreamsClose tests HasStream before it looks at stream 0; this function calls GetStream immediately. On a built task system that is harmless. On an empty one — before Initialize, or after JoinAndClear has cleared the array — GetStream takes its out-of-range path and returns streams[0] of an array with no elements, where Array::operator[] asserts. The only reason this is not seen in the engine's own path is that JoinAndClear calls it inside a branch already conditioned on hasStreams. Ask it only of a task system that has streams.

Parameters

None.

Return value

TypeWhat you get
bool True when every stream other than the base and the IO stream reports itself closed — including the case where there are no such streams at all. Not a statement about the base or IO streams, and not a statement about whether any thread has been joined
