GetIOTaskStream

the stream at index 1 — the one with no thread of its own, which makes this the handle the logger needs in order to drive it

Signature

TaskStream& GetIOTaskStream() noexcept;

const TaskStream& GetIOTaskStream() const noexcept;

Function description

Two overloads that differ only in the constness of the method, defined at Engine/Core/TaskSystem.cpp:726 and :731. Each names its return type: TaskStream& outside a const method, const TaskStream& inside one. They used to be auto& and deduce those types from the constness of the enclosing method, which meant the declaration on a page could not state what a caller got; naming the type is what allowed the body to move into the source file.

The IO stream exists so that log work has somewhere to live that the engine loop does not have to service. It has no thread: BuildStreams hands it to the logger at its last statement, Logger::Get().SetIODriver(&GetIOTaskStream()) (Engine/Core/TaskSystem.cpp:782), and the logger's own thread drives it from then on.

Two statements here are not guarded, and one of them is load-bearing at shutdown. Indexing is unchecked — no HasStream test, unlike RequestOtherStreamsClose — so on an empty array the index assert inside Array fires. JoinAndClear calls this after clearing its guard variable but inside the branch that already established streams exist, which is the only reason the teardown path is safe. The logger does the same from the other side: it takes this handle in StartTask (Engine/Log/Logger.cpp:319), reads its thread id at :320, and wakes it at :493 — all after the task system was initialized, never before.

Parameters

None.

Return value

TypeWhat you get
TaskStream& / const TaskStream& Stream 1. The const overload answers const TaskStream&, Mutable in the non-const form: enqueueing, waking and closing it are all available, and closing it is what JoinAndClear does after withdrawing the driver

Examples

From Engine/Log/Logger.cpp

taskSys.EnqueueTask(ioStreamIndex, *drainTask);

auto& ioTaskStream = taskSys.GetIOTaskStream();
threadID = ioTaskStream.GetThreadID();

Engine/Log/Logger.cpp:317-320. The logger queues its drain task and then records which thread now owns that work — a fact it can only get from the stream, because the stream's id was recorded on the logger's own thread at its first pass (GetStreamIndex explains when).
