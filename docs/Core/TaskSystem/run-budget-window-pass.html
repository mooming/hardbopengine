RunBudgetWindowPass

closes every stream's CPU-budget window once per base frame period, by request rather than by force — because a budget belongs to the thread that spends it

Signature

void TaskSystem::RunBudgetWindowPass() noexcept
{
        const auto now = time::GetNow();
        const auto period = time::GetBaseFramePeriod();

        if (lastBudgetWindowAdvance != time::TTime{} && now - lastBudgetWindowAdvance < period)
        {
                return;
        }

        lastBudgetWindowAdvance = now;
        numBudgetWindowsAdvanced.fetch_add(1, std::memory_order_relaxed);

        for (auto& stream : streams)
        {
                stream.RequestWindowAdvance();
        }
}

Function description

Defined at Engine/Core/TaskSystem.cpp:412. An allowance that closes nothing is a measurement that changes no decision, which makes it a syscall billed per task for nothing. The window is what makes an allowance mean "per frame period" — the yardstick every budget in the engine is measured against, from the same GetBaseFramePeriod that Update uses for its deadline, so the two cannot drift apart.

The first call always advances: lastBudgetWindowAdvance starts default-constructed, and the guard skips only a second pass inside the same period. Afterwards it advances at most once per period, however many times it is called — cheap enough to call from a loop, which is how it is used.

Nothing here writes a budget. Each stream is signalled and reopens itself on its next pass, where windowAdvanceRequested.exchange(false) triggers budget.Reset() and ends the drain round (Engine/Core/TaskStream.cpp:377-381). A budget charges the CPU time of the thread that owns it, and a reset executed elsewhere would race that thread's BeginTask / EndTask pairing on the very fields that decide whether a charge is one task or a thread's whole life.
Its one caller is the base stream's own pass, and the timing state is unsynchronised on purpose. The call sits inside the base stream's update, guarded by streamIndex == BaseStreamIndex (Engine/Core/TaskStream.cpp:390-393), which is reached through Update. lastBudgetWindowAdvance is a plain field with no lock, because a second caller would need one just to decide a timestamp. A second caller also breaks the assumption the streams make about who reopens them: a thread that stops driving the base stream stops advancing every stream's window with it, and a stream whose allowance is spent takes nothing from its own lanes until a window reopens.

Parameters

None.

Return value

void. Whether this call advanced a window is visible in GetNumBudgetWindowsAdvanced, which is the only way to prove the pass is alive.

Examples

{
