GetNumHardwareThreads

returns std::thread::hardware_concurrency() cast to TIndex, with no clamp and no fallback, and it is the only figure that decides how many streams the engine will have

Signature

static TIndex GetNumHardwareThreads() noexcept
{
        const auto hardwareConcurrency = std::thread::hardware_concurrency();
        const auto numAvaibleHardwareThreads = static_cast<TIndex>(hardwareConcurrency);

        return numAvaibleHardwareThreads;
}

Function description

A read and a cast. The standard library returns unsigned int and documents the result as a hint; here it arrives narrowed to TIndex, which is int (Engine/Container/Array.h:20). Nothing else is examined: no affinity query, no reservation, no minimum.

Its one consumer is the constructor, which stores the result in numHardwareThreads for the life of the object, and that number is the stream array's size: BuildStreams builds numHardwareThreads streams — the base stream, the IO stream, and one worker per remaining core. Fewer than ENGINE_MIN_HARDWARE_THREADS (4, Engine/Config/BuildConfig.h:21) stops the engine at a FatalAssert inside BuildStreams, so the smallest configuration this engine runs on has two worker streams and never fewer.

The standard library calls this a hint; the engine treats it as a fact. The documented wording is that the value "is system- and implementation-specific, and may not be exact, but just an approximation", that it "does not need to match the actual number of processors or cores available in the system" because a system "can support multiple threads per processing unit, or restrict the access to its resources to the program", and that "if this value is not computable or well defined, the function returns 0". None of that caution survives the assignment: construction stores it, and BuildStreams creates exactly that many TaskStream objects. A process whose access is restricted — a container, or an affinity mask, which is the second clause above — is therefore given a stream for every core in the machine rather than for the cores it may use, and nothing re-asks the question later. The FatalAssert in the constructor is the one place the caution is honoured: a 0 becomes a halt, not a task system with no streams.

Parameters

None.

Return value

TypeWhat you get
TIndex (int) A copy of the implementation's hardware thread count, or 0 if it could not be determined. Not clamped to ENGINE_MIN_HARDWARE_THREADS, which BuildStreams checks separately

    : isRunning(false)
    , name("TaskSystem")
    , numHardwareThreads(GetNumHardwareThreads())
    , engineLoopThreadID(std::this_thread::get_id())
{
