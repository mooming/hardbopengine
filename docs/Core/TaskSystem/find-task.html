FindTask

resolves an identity to the record behind it, or to nullptr — the only way to know a tracked task still means what it meant when it was issued

Signature

Task* TaskSystem::FindTask(TaskID id) noexcept
{
        return taskRegistry.Find(id);
}

Function description

A forward to TaskRegistry::Find at Engine/Core/TaskSystem.cpp:314. The identity carries an index and a generation; the generation is what makes a stale identity answer nullptr instead of returning the new task that inherited the freed record.

nullptr therefore covers three distinct histories: the identity was never issued, the task has been released, or the record has since been issued to another task. The caller cannot tell them apart and does not need to — a caller must handle null, and there is no variant of this call that returns a task it cannot verify.

The pointer is not a lease. It stays valid memory for the life of the registry, but if the task is released on another thread while it is being read, the fields read are whatever the record happened to hold at that moment — not a statement about the task a caller asked for. There is no lock around the record, and none is coming: an engine that refused to put a mutex on the offer path has already declined the one a record read would need. Read it, use it, and do not hold it across a call that might release.

Parameters

ParameterTypeRequirement
id TaskID An identity from CreateTask, ParallelFor or GetSuccessor. A null identity is a valid argument and yields nullptr

Return value

TypeWhat you get
Task* The record the identity names, or nullptr. Not a copy, not a lease, and not stable across another thread's ReleaseTask
