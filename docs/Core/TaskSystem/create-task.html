CreateTask

member of hbe::TaskSystem Engine/Core/TaskSystem.h asks the registry for a record and hands back the identity that names it — a forward with one contract worth reading, which is what a null return costs

Signature

	[[nodiscard]] TaskID CreateTask(StaticString taskName, TRunnable func, void* userData) noexcept;

Function description

One forward to TaskRegistry::Create at Engine/Core/TaskSystem.cpp. It exists so that callers reach the registry through the task system rather than holding the registry itself — GetRegistry is the door to that, and it is narrower on purpose.

What comes back is a TaskID: an index into the record table plus a generation, so that an identity held past its task's release can be recognised as stale rather than silently naming a different task. The three arguments are stored in the record; the runnable is not called here, and nothing is queued.

A null identity means the task will never run, and it is not this call's job to make room. TaskRegistry::Create returns a null TaskID when the table has no free record. A refused task is not tracked, is not run, and the refusal is logged with the task name and the capacity — because a task that silently never runs is indistinguishable from one still waiting. The create path never grows the table: growth is Grow(), which is legal only where no lookup is in flight, so a refusal here is a sizing problem to fix somewhere else. The engine's own growth path is Initialize, from the configuration parameters it reads.
Untracked work items are dropped, not delayed. A work item carries the identity of its task, and a stream resolves that identity to run it. An item whose identity was never issued — a task built by hand rather than through this call — resolves to nothing, so the item is discarded. This is why EnqueueTask insists on a tracked task, and why DispatchSuccessor refuses rather than guessing.

Parameters

ParameterTypeRequirement
taskName StaticString A label for logs and reports. The bytes must outlive the record's use of them, so call sites pass literals
func TRunnable The runnable that does the work. Stored, never called here
userData void* Handed to the runnable untouched. Its lifetime is the caller's to guarantee across every item this task's work can produce — see ParallelFor for what "every item" can mean

Return value

TypeWhat you get
TaskID The identity that names the tracked task, or a null TaskID when the registry has no free record. IsNull() is the test

Examples

From Engine/Log/Logger.cpp

taskID = taskSys.CreateTask("Logger", runnable, this);

auto* drainTask = taskSys.FindTask(taskID);
if (drainTask == nullptr)
{
        AddLog(GetName(), ELogLevel::Error, [](auto& logStream)
        {
                logStream << "The task registry could not track the logger's drain task, so log lines are flushed"
                          << " inline by whoever produces them.";
        });
        return;
}

taskSys.EnqueueTask(loggerStreamIndex, *drainTask);

Engine/Log/Logger.cpp, where the logger registers the task that writes its queue. This is the refusal path being honoured by the engine's own code: a null record is not ignored and not retried, it changes what the logger does — log lines get flushed inline by whoever produces them, and the IO stream is never asked to run a task that does not exist. The same file shows the pairing this call expects: CreateTask then FindTask then EnqueueTask.
