RequestShutDown

member of hbe::TaskSystem Engine/Core/TaskSystem.h clears isRunning and asks every stream but the base and the IO stream to close — a request that ends the run without abandoning anything that is already queued

Signature

	void RequestShutDown() noexcept;

Function description

Two statements, at Engine/Core/TaskSystem.cpp. The first ends the run — Engine::Run spins while (taskSystem.IsRunning()) at Engine/Engine/Engine.cpp, so clearing the flag is how a task stops the engine. The second begins the teardown of everything that is not needed to finish the run.

"Closing" here means draining, not stopping. Each asked stream finishes the work it already holds and then leaves its loop; the request that ends a run must not be the thing that abandons queued items. And the base stream is deliberately not closed, because it still owns the end of the run — final statistics, the last log lines, and whatever the closing streams hand back. Log writing is itself a task on a stream, so an executor closed before the reporting it must carry out turns an orderly end into a flush timeout.

It does not wait, and it does not free anything. This is a request: streams notice it on their next pass. The join, the logger flush and the release of the IO driver all happen in JoinAndClear, which is what Engine::Run calls after its loop exits. A caller that wants to know when the others have actually left asks AreUserStreamsClosed.

Safe to call twice, and safe to call after the teardown. RequestOtherStreamsClose returns immediately when there is no stream 0, and after JoinAndClear the stream array is empty — which is exactly the state Engine::ShutDown finds it in, since Run has already joined by then.

Parameters

None.

Return value

void. Nothing is reported, and nothing is waited for.

        log.Out("Shutting down...");

Engine/Engine/Engine.cpp. Read it together with Run, which joins at line 145 before this is ever reached: in the normal path this call lands on an already-cleared task system and costs one flag store and one early return. It is the path where Run was never entered — or where a task called this and something else reached ShutDown first — that it is there for.
