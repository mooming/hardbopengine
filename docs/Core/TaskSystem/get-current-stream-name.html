GetCurrentStreamName

member of hbe::TaskSystem Engine/Core/TaskSystem.h returns the calling thread's thread_local name — the same variable GetCurrentThreadName returns, so the two can never disagree

Signature

	static StaticString GetCurrentStreamName() noexcept;

Function description

Reads thread_local StaticString ThreadName (Engine/Core/TaskSystem.cpp:23), which is written only by SetThreadName. There is exactly one name stored per thread, and this function and GetCurrentThreadName are two doors onto it: their bodies are the same return ThreadName; at Engine/Core/TaskSystem.cpp:45 and :50.

One name, two questions. A stream thread's name is its stream name, because TaskStream::RunLoop labels the thread with the stream's name and nothing else ever renames it — so on a worker thread "which stream" and "which thread" have the same answer. They come apart on the two driven streams: the logger's driver thread is "LogDriver" while serving the IO stream, and the engine-loop thread is "EngineLoop" while serving stream 0. Ask the index, not the name, when the question is really about streams: GetCurrentStreamIndex is the one that can be compared against BaseStreamIndex.

Before SetThreadName has ever run on a thread, the name is a default-constructed StaticString, not an empty string with a name in it.

Parameters

None.

Return value

TypeWhat you get
StaticString A pointer-and-length view of whatever SetThreadName last stored on this thread. The bytes are not copied, so reading them after the named object is gone is the caller's problem — which is why every writer passes a literal or a name the stream itself owns

Examples

Illustrative — GetCurrentStreamName has no call site anywhere in Engine/, Applications/ or Examples/; only its definition at Engine/Core/TaskSystem.cpp:45 mentions it.

auto log = Logger::Get("MyCode");
log.Out([&](auto& ls) { ls << "running on " << TaskSystem::GetCurrentStreamName().c_str(); });

Its twin does have a real use: the task-system unit tests print GetCurrentThreadName() beside GetCurrentStreamIndex() when a stream-identity assertion fails (Engine/Core/TaskSystem.cpp:2101-2105). Both names would print the same word there, which is the plainest evidence that the pair is one variable seen twice.
