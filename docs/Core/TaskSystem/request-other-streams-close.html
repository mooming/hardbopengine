RequestOtherStreamsClose

asks every stream to close except the base stream and the IO stream — idempotent, and safe to call on a task system that has already been torn down

Signature

void RequestOtherStreamsClose() noexcept
{
        // No streams means nothing to ask. Reaching for index 0 of an empty array is an index assert, and this path is
        // reached a second time from the destructor after the streams have already been cleared.
        if (!HasStream(GetBaseTaskStreamIndex()))
        {
                return;
        }

        TaskStream& baseStream = GetStream(GetBaseTaskStreamIndex());
        TaskStream& ioStream = GetStream(GetIOTaskStreamIndex());

        for (auto& stream : streams)
        {
                if (&stream != &baseStream && &stream != &ioStream)
                {
                        stream.RequestClose();
                }
        }
}

Function description

Defined at Engine/Core/TaskSystem.cpp:133. It carries no state of its own: it asks, and the streams notice on their own passes. Two callers use it — RequestShutDown, and JoinAndClear, which must ask before it can wait, because a wait for streams that were never asked to close is a wait that never ends.

The two exclusions are decided by address, not by index: the loop compares &stream against the two it fetched first. That is what lets the same test be used on an array whose element order is not something the caller controls.

The IO stream is spared with the base stream, and not by accident. Log writing is a task that runs on the IO stream. Closing the executor of the reporting before the reporting is done leaves a drain task in flight that can never run again, and every late log line then waits on it — which is why JoinAndClear flushes the logger while both engine streams are still alive, and why this function will not close either of them.
The guard is the whole reason the destructor can call it. An empty streams array has no element at index 0, and reaching for one is an index assert inside Array. HasStream answers that case first, so the second pass from the destructor — after JoinAndClear has already cleared the array — returns instead of aborting. Compare AreUserStreamsClosed, which has no such guard.

Parameters

None.

Return value

void. It reports nothing — not even how many streams it asked — and it does not wait for any of them. AreUserStreamsClosed is the only witness that the asking worked.
