IsIOThread

member of hbe::TaskSystem Engine/Core/TaskSystem.h asks whether the calling thread currently claims the IO stream, which can only ever be true on the logger's thread and only while it is driving

Signature

	static bool IsIOThread() noexcept;

Function description

One comparison of the thread_local index against IOStreamIndex, which is 1 (Engine/Core/TaskSystem.h:30). Mechanically it is IsBaseThread with a different constant, and it inherits that function's whole subtlety: the claim is per-pass on a driven stream, not per-thread.

No thread belongs to the IO stream. The IO stream has no thread of its own: BuildStreams ends by handing it to the logger with Logger::Get().SetIODriver(&GetIOTaskStream()), and the logger's own thread drives it from there. So this is true exactly while that thread is inside a driven pass on stream 1, and false the moment the pass returns — on that same thread, without anything else having happened. The thread's own name stays "LogDriver" throughout; see GetCurrentStreamName.

Parameters

None.

Return value

TypeWhat you get
bool True only on the logger's driver thread and only during a pass driving stream 1. False everywhere else, including on that same thread between passes

Examples

Illustrative — no call site for this exists in the repository.

if (TaskSystem::IsIOThread())
{
        // this thread is draining log work right now; do not wait for the logger here
}

The shape it would be used for is the one the shutdown code had to learn the hard way: log writing is a task on the IO stream, so code that runs while the IO stream is being driven must not block waiting for the logger to finish — JoinAndClear documents the ordering that this check would express.
