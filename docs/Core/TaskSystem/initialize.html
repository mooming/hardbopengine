Initialize

member of hbe::TaskSystem Engine/Core/TaskSystem.h reads four configuration parameters, gives the registry its capacity, and builds every stream — the call that turns an empty task system into the running one

Signature

void Initialize() noexcept

Function description

Defined in Engine/Core/TaskSystem.cpp as TaskSystem::Initialize(). In order, it does five things:

StepWhat happensVisible as
Log filter Installs a filter for the "TaskSystem" logger fed by the atomic configuration parameter Log.TaskSystem, defaulting to Warning Task-system log lines below Warning are dropped until the parameter is raised
Registry capacity Reads Task.RegistryInitialRecords, Task.RegistryGrowByRecords and Task.RegistryMaxRecords, then taskRegistry.Initialize("TaskRegistry", …) and SetMaxCapacity How many task records exist before the first growth, and the ceiling
Streams Calls BuildStreams One TaskStream per hardware thread: "Base", "IO", then "Worker1" …
Threads Each stream with a thread of its own is started, and isRunning is set to true Engine::Run's loop condition becomes true
IO driver Logger::Get().SetLoggerStream(&GetIOTaskStream()) The logger's thread begins driving the IO stream; see IsIOThread
Exactly once per instance, on the constructing thread. BuildStreams asserts std::this_thread::get_id() == mainThreadID before it creates anything, so calling this from a thread other than the one that constructed the task system stops there. A second call is worse than redundant: streams.Swap(Array<TaskStream>(numHardwareThreads)) hands the old buffer to the temporary, and the temporary's destruction destroys every live TaskStream — whose std::thread member is still joinable, and destroying a joinable std::thread calls std::terminate. Nothing checks for the second call, so the guard is the caller's discipline.

The three registry parameters are function-local static objects, so they register with the configuration system the first time through and are never re-registered. Changing Task.RegistryMaxRecords at runtime still works, because SetMaxCapacity reads it on each Initialize — but only on a call that must not happen.

Parameters

None. Everything it needs comes from the configuration system and from construction-time state.

Return value

void. It cannot fail softly: the minimum hardware-thread requirement is a FatalAssert inside BuildStreams.

Examples

From Engine/Engine/Engine.cpp

if (HasFlag(levels, EInitLevel::TaskSystem))
{
        taskSystem.Initialize();
        isTaskSystemReady = true;
}

if (HasFlag(levels, EInitLevel::Logger))
{
        logger.StartTask(taskSystem);
        isLoggerReady = true;
}

Engine/Engine/Engine.cpp. Note what the order buys: the task system exists before the logger registers its log-writing task with it, so the log driver has a stream to be handed to. Requesting EInitLevel::Logger implies EInitLevel::TaskSystem a few lines earlier for the same reason. Engine::Run then refuses to start without it: FatalAssert(isTaskSystemReady, "Engine::Run needs EInitLevel::TaskSystem").
