DispatchSuccessor

delivers a finished task's outcome: copies its result packet onto the recorded successor and queues that successor on the stream the packet names — six ways this declines, four of them out loud

Signature

void DispatchSuccessor(TaskID finishedTask) noexcept;

Function description

Defined at Engine/Core/TaskSystem.cpp:431. This is the arrow between two tasks, and the thread that closed the join runs it — whichever worker happened to finish the last work item, not a thread chosen for the purpose. Nothing accumulates in between: there is no completion buffer, no per-stream queue of finished tasks, no scan of the registry. A task carries its own outcome, so the outcome is already in the hands of the thread holding the task, and one enqueue is the whole delivery.

What must be true, in the order it is checked

#TestIf it fails
1 finishedTask names a tracked task Quiet return. No log line — a null identity, or a task built by hand rather than created through the task system, has nowhere to have recorded a successor
2 A successor is recorded (GetSuccessor is not null) Quiet return. Fire-and-forget work reaches this line constantly; a log per join would be a log per task
3 The producer's packet names a destination stream Logged error. "…recorded a successor and closed its join, but its result packet names no destination stream… A chain that stops here has no symptom until something downstream waits." A routing decision nobody has made is not guessed at — see SetSuccessor for where the byte comes from
4 The named destination is a stream this engine has (HasStream) Logged error naming the index, the successor and how many streams exist
5 The successor is still tracked (FindTask) Logged error. "…a successor released while its producer ran abandoned the outcome it asked for" — see ReleaseTask
6 The successor reserved at least one subtask Logged error. An outcome is delivered as one item covering the successor's whole range, which is one reserved subtask; with none, there is no item to queue

On success, exactly three things happen: a lookup, a 128-byte packet copy onto the successor's own packet — overwriting whatever the successor held there, because the successor's packet is the outcome slot and parameters for a successor have to travel somewhere the successor reads them — and one push under the destination stream's queue lock.

The delivery is always the FIFO lane. The final statement is streams[destination].EnqueueFifo(...). A producer's priority does not travel with its outcome, and WorkItem::priority is not carried across — see the lane and priority distinction on Enqueue. A chain that must arrive on the priority lane has to say so in the successor's own work, not hope the byte carries.
One lock is the whole coupling, and it is the destination stream's. A worker delivering into a stream can wait for that stream's queue lock, and a stream holds its lock across the lane rotation that picks its next work item. The wait is one push long, and only ever for a stream somebody named out loud. The alternative — a completion list the base stream drains — moves that wait off the worker and onto memory, at the price of a container that outlives the task it describes; that shape was declined three times, at R23 for the result buffer, in commit ac496e6 for the result container, and while writing R30 for the completion list.

Parameters

ParameterTypeRequirement
finishedTask TaskID The identity of the task whose join just closed. A null identity has nowhere to have recorded a successor, so nothing runs — and nothing says so, per row 1 above

Return value

TypeWhat you get
void Nothing to the caller. Whether the chain continued is visible only in the log, or in the successor running. A caller that must know should read the successor's state, not this call's

WorkItem::Run returns true only for the item that closed the join, so exactly one of a task's items reaches this line, and it reaches it on the thread that finished the work. That is what makes the shape free at any chain depth: A wakes B by one push, B wakes C by another, and no stack grows past one link.
