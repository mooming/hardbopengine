GetStreamName

the name of the stream at index, or "Unknown" — the one accessor in this class that answers a bad index with a word instead of a failure

Signature

[[nodiscard]] StaticString GetStreamName(int index) const noexcept
{
        if (unlikely(!streams.IsValidIndex(index)))
        {
                static StaticString unknown("Unknown");
                return unknown;
        }

        return streams[index].GetName();
}

Function description

Defined at Engine/Core/TaskSystem.cpp:671. Names come from BuildStreams: index 0 is "Base", index 1 is "IO", and workers are "Worker1", "Worker2" … in creation order. The name a log line carries for a task is this one, not the thread name — though on a worker the two are equal, because TaskStream::RunLoop labels the thread with the stream's name (GetCurrentStreamName).

An invalid index answers "Unknown", and that is a deliberate difference from its neighbours. This function is for reports. GetStream answers the same bad index by handing back the base stream, which is a decision rather than a label — see the hazard there. Both differ from HasStream, which is the only one of the three that can tell the caller something went wrong. A log line that says Unknown is the visible symptom of a stream index that outlived the streams.

Parameters

index int A stream index. Declared as int rather than TIndex; they are the same type today (TIndex is int), so the spelling is cosmetic

Return value

Examples

Illustrative — the engine names streams from inside the task system and through the logger's own category; there is no engine call site of this accessor to quote.

log.Out([&](auto& ls) { ls << "refused on stream " << taskSys.GetStreamName(index); });

Which is the shape it is for: a report about an index the caller did not create. During teardown that string is the difference between "worker went away" and a crash report naming nothing.
