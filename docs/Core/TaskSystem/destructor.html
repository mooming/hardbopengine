~TaskSystem

calls JoinAndClear and nothing else, which is what keeps an abandoned Engine from terminating the process

Signature

~TaskSystem() noexcept
{
        JoinAndClear();
}

Function description

Declared noexcept at Engine/Core/TaskSystem.h:68 and defined at Engine/Core/TaskSystem.cpp:89. Its entire body is one call.

In the normal path this is a second pass over work that is already finished: Engine::Run calls JoinAndClear itself at Engine/Engine/Engine.cpp:145, long before Engine is destroyed. What reaches the destructor's call is an Engine that was constructed and never run, or one whose run was left early — and for that case the call is not a formality.

Without this call, teardown terminates the process. Each TaskStream owns a std::thread thread (Engine/Core/TaskStream.h:94) and declares ~TaskStream() = default (Engine/Core/TaskStream.h:166) — it does not join. The standard library is explicit about what follows: the thread destructor "destroys the thread object. If the thread is joinable when destroyed, terminate() is called." So a task system that was started and never joined would take the process down during member destruction, after the destructor's own body had already run and while nothing was doing anything wrong on the surface. JoinAndClear joins every joinable stream and then clears the array, so by the time the members are destroyed there is no live thread left to terminate on.

The order is what makes that work: a destructor body runs before its members, so streams is still intact when JoinAndClear walks it. The same function is idempotent enough for the second pass — after the first one the array is empty, and RequestOtherStreamsClose returns at once when there is no stream 0, which is the guard that was added for exactly this caller.

Parameters

None.

Return value

A destructor. On return, no stream thread is running, the stream array is empty, and the logger has been released from driving the IO stream.

Examples

Illustrative — no call site for this exists in the repository; it happens when Engine is destroyed.

{
        Engine engine;
        engine.Init(...);          // EInitLevel::TaskSystem: streams are built
}                                    // never runs: ~TaskSystem joins the streams here

The engine is a member of the application's own object in every example under Applications/, so the branch that matters — a constructed task system whose run loop was never entered — is reachable without any unusual code. Engine::Run asserts isTaskSystemReady rather than the reverse, so "initialized but not run" is a state the class is expected to survive.
