IsBaseThread

member of hbe::TaskSystem Engine/Core/TaskSystem.h asks whether the calling thread currently claims stream 0 — not whether it constructed the task system, and not whether it is where Engine::Run lives

Signature

	static bool IsBaseThread() noexcept;

Function description

One comparison of the thread_local index against BaseStreamIndex, which is 0. It is true while the caller is inside a base-stream drain pass, which on this engine means on the engine-loop thread with the claim that TaskStream::Update takes for the length of the pass (Engine/Core/TaskStream.cpp:365-369). One statement outside that pass the same thread answers false, because the claim is restored — see SetStreamIndex.

It is not the "did I build this" question, and it once could not be asked. The thread that constructed the task system is recorded separately, in engineLoopThreadID, and JoinAndClear and BuildStreams test that instead. Before NonStreamIndex existed, the default stream index was 0, so every thread — application threads, the engine loop before it claimed a stream — answered true. That made this function useless as a check and let the assert in BuildStreams pass on any thread at all. It is now a real question; it still is not the question "am I the constructing thread".

Parameters

None.

Return value

TypeWhat you get
bool True only while the caller claims stream 0. False on the engine-loop thread between passes, false on any thread the application created, false on every worker and on the IO stream

Examples

Illustrative — IsBaseThread has no call site in the repository; its unit-test use at Engine/Core/TaskSystem.cpp:2103 prints the value rather than branching on it.

if (TaskSystem::IsBaseThread())
{
        // safe to touch base-stream-only state from inside a pass on it
}

Code that needs the constructing thread rather than stream 0 has no accessor for it today — engineLoopThreadID is private and unexposed — so the two questions cannot be confused by accident, only by reading the wrong one into the other's name.
