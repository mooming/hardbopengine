GetStreamIndex

which stream this OS thread owns, found by scanning every stream — the outside view of the same fact GetCurrentStreamIndex reports from inside

Signature

TaskSystem::TIndex TaskSystem::GetStreamIndex(TThreadID id) const noexcept
{
        TIndex index = NonStreamIndex;

        auto size = streams.Size();
        for (decltype(size) i = 0; i < size; ++i)
        {
                if (auto& stream = streams[i]; stream.GetThreadID() != id)
                {
                        continue;
                }

                index = i;
                break;
        }

        return index;
}

Function description

Defined at Engine/Core/TaskSystem.cpp:682. The two accessors answer the same question from opposite ends: a thread asks its own thread_local index with GetCurrentStreamIndex, while a third party holding a std::thread::id asks this one, which searches.

Each stream's thread id is recorded once, at three different moments depending on what kind of stream it is.

StreamWhen its thread id is recordedWhich thread it names
Base (0) TaskStream::Start, Engine/Core/TaskStream.cpp:305-307 The thread that called Initialize — the engine loop. This is the value TestHelper::DriveUntil compares itself against
IO (1) On the first driven pass, Engine/Core/TaskStream.cpp:328-330 The logger's thread. Until that first pass the stream has no id to match, so this function returns NonStreamIndex for the logger's own thread
Workers (2 up) TaskStream::RunLoop, Engine/Core/TaskStream.cpp:712 The stream's own thread, as soon as it begins
The field this scan reads is not synchronised. TThreadID threadID (Engine/Core/TaskStream.h:78) is a plain std::thread::id — not atomic, not written under a lock. It is written by the owning or driving thread and read by this function, which any thread may call, so a scan that runs while a stream is recording its id for the first time is a data race in the standard's terms. In practice the type is a small trivially-copyable value and the engine's own reads are few — this scan, and TestHelper::DriveUntil's comparison, and Logger::StartTask reading the IO stream's id — which is exactly the pattern that passes for years and then reports a wrong answer on hardware nobody tested. Ask before Initialize has returned and the race is not available.

Parameters

ParameterTypeRequirement
id TThreadID (std::thread::id) Usually std::this_thread::get_id(), or a saved id from a stream's own thread. A default-constructed id matches a stream whose id has not been recorded yet, which is a real state before the first pass rather than an impossible one

Return value

TypeWhat you get
TIndex (int) The first stream whose recorded thread id equals id, or NonStreamIndex (-1). Not the caller's current claim — a borrowed pass on a driven stream changes the thread-local index and not this answer

Examples

Illustrative — no engine call site exists; the test suite compares stream ids where a page cannot quote one.

const TIndex owner = taskSys.GetStreamIndex(std::this_thread::get_id());
if (owner == TaskSystem::NonStreamIndex)
{
        // this thread is not a stream: it takes nothing from the general queue
}

The test against NonStreamIndex is the useful one, because it is the answer for every thread the application created — and the consequence is documented on Dequeue: such a thread neither takes general-queue work nor is recorded as having looked at it.
