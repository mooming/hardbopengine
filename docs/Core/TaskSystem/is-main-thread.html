IsMainThread

member of hbe::TaskSystem Engine/Core/TaskSystem.h const noexcept true on the thread that constructed this task system — the one thread allowed to build, configure and tear the streams down, and the identity the policy is stated against

Signature

[[nodiscard]] bool IsMainThread() const noexcept

Function description

Defined in Engine/Core/TaskSystem.cpp as TaskSystem::IsMainThread(): one comparison of std::this_thread::get_id() against mainThreadID. That member is a const TThreadID written once, in the constructor's initializer list at Engine/Core/TaskSystem.cpp:83, and never again — so the answer is fixed for the life of the instance and cannot drift.

It exists to carry one policy: setup and configuration belong to this thread. Building the streams, installing the logger's stream and closing them are the actions that decide what every other thread may assume, so they happen in one place, in order, on one thread. Before this accessor the policy was still enforced, but only from inside TaskSystem, because mainThreadID was a private member with no accessor — BuildStreams compared the raw member and JoinAndClear gated on the comparison. Anything outside the class that needed the same answer had to guess at it, and the guess available was IsBaseThread, which is a different question.

This is not IsBaseThread, and the difference is not cosmetic. IsBaseThread() reads the thread-local StreamIndex, so it answers this thread is draining the base stream right now — true only inside a base-stream pass, and NonStreamIndex on every thread outside one, including this thread. IsMainThread() answers this thread is the one that built the task system — true outside a pass and false inside one, because a thread inside a base pass is still the same thread. Neither implies the other, and the two together are what the configuration checks assert. See Logger::SetLoggerStream for the pair in use.

The name "main thread" names the thread that built the task system — not the process's first thread and not the OS's UI thread, and not the thread main is written in, either. An embedder that constructs the engine on some other thread moves the policy with it, which is the intended reading: the name describes a role the constructor claims, and the logger's own driver thread is a different thread with a different job, however the host happens to be shaped.

Parameters

None.

Return value

TypeWhat you get
bool True when the calling thread is the one that constructed this TaskSystem. Says nothing about whether that thread is currently draining a stream — for that, ask IsBaseThread or read GetCurrentStreamIndex — and nothing about whether the engine has been initialised, since the identity is captured before Initialize runs
