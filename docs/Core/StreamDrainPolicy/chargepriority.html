ChargePriority

member of hbe::StreamDrainPolicy Engine/Core/StreamDrainPolicy.cpp Adds a task's CPU time to the priority lane's accumulation for this round.

Signature

void ChargePriority(std::chrono::nanoseconds spent) noexcept

Function description

Defined in Engine/Core/StreamDrainPolicy.cpp as StreamDrainPolicy::ChargePriority(); the body is priorityUsed += spent;. The exact counterpart of ChargeFifo for the priority lane: unconditional accumulation, no mode check, and read by ChooseLane only when an allowance is configured.

Because the two accumulations are summed to decide whether the round is over, an item charged to the wrong lane is not a cosmetic error — it moves the boundary between the two shares. The shipping call site decides by the lane it took from, not by the item's priority byte (TaskStream::Update(), Engine/Core/TaskStream.cpp), which is the only rule that can be right: the priority byte says how an item was bucketed at insertion, not which queue it came out of.

Both accumulations are compared against the allowance as a sum. A priority lane can be charged past its own share without stopping the stream — the test An empty lane does not hold its share hostage charges 0.6 ms to a 0.5 ms share inside a 1 ms allowance and requires the lane still to be served (Engine/Core/StreamDrainPolicy.cpp) — but the same sum reaching 1 ms ends the round for both lanes at once, via IsRoundExhausted.

Parameters

ParameterTypeRequirement
spentstd::chrono::nanosecondsCPU time the task consumed, attributed to the priority lane because the item was taken from that queue

Return value

void. Read it back with GetPriorityUsed, on the owning thread.

Examples

From Engine/Core/TaskStream.cpp, TaskStream::Update()

if (chargingBudget)
{
    budget.EndTask();

    const auto spent = budget.GetAccumulated() - chargedBefore;
    if (lane == StreamDrainPolicy::ELane::Priority)
    {
        drainPolicy.ChargePriority(spent);
    }

chargedBefore is the budget's accumulation captured before the run, so the charge is exactly what this one item cost — including the case where the item was re-queued unfinished and will be charged again on its next run.
