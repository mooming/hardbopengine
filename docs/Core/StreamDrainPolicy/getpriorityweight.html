GetPriorityWeight

member of hbe::StreamDrainPolicy Engine/Core/StreamDrainPolicy.cpp The configured priority weight, not the normalised share.

Signature

[[nodiscard]] uint32_t GetPriorityWeight() const noexcept

Function description

Defined in Engine/Core/StreamDrainPolicy.cpp as StreamDrainPolicy::GetPriorityWeight(); the body is return priorityWeight;. The priority side of the configured rate, with the same guarantees as GetFifoWeight: never zero, because ConfigureRate rewrites a zero to one, and only meaningful next to the other weight.

Which queue it describes is fixed, not configured: the priority lane is the stream's BoundedPriorityQueue buckets keyed on the item's priority byte, and the FIFO lane is the arrival-order deque. Raising this weight changes how CPU time is divided between those two structures, never how an item is placed in one of them.

A high priority weight is not a priority. Priority within a stream is the byte an item is enqueued with; this weight only decides how much of the stream's allowance the priority queue gets to spend. A stream at 1:64 still serves the FIFO lane when the priority queue is empty, and still borrows the other lane's share (ChooseLane) — so the weight is a fair-share guarantee, not a preemption rule.
The sum of the two weights is added in uint32_t before the share divides by it, so a pair that overflows 32 bits yields a nonsense ratio; keep derived weights well inside 31 bits in total. Details on GetFifoWeight.
