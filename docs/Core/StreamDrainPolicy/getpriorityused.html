GetPriorityUsed

member of hbe::StreamDrainPolicy Engine/Core/StreamDrainPolicy.cpp CPU time the priority lane has spent this round; reporting only.

Signature

[[nodiscard]] std::chrono::nanoseconds GetPriorityUsed() const noexcept

Function description

Defined in Engine/Core/StreamDrainPolicy.cpp as StreamDrainPolicy::GetPriorityUsed(); the body is return priorityUsed;. CPU time charged to the priority lane in the current round, and nothing since the last EndRound — the exact counterpart of GetFifoUsed.

This accumulation is what makes a lane's share meaningful: ChooseLane compares it against GetPriorityShare to decide whether that lane still has room, and sums it with the FIFO lane's figure against the allowance to decide whether the round is over at all.

Nothing in the repository reads it. Declaration, definition, no call site — including in Engine/Core/StreamDrainPolicy.cpp's own tests, which assert the decisions rather than the counters. Reporting accessors with no reporting caller are the sort of field a later change quietly stops maintaining, which is worth knowing before building a diagnostic on top of them.

Parameters

None.

Return value

TypeWhat you get
std::chrono::nanosecondsCPU time charged to the priority lane this round by ChargePriority; it can exceed that lane's share, because the gate is on acquiring and not on execution

Examples

Illustrative — no call site for this exists in the repository.

const bool overShare = drainPolicy.GetPriorityUsed() >
        std::chrono::duration_cast<std::chrono::nanoseconds>(drainPolicy.GetPriorityShare());

Exactly the test ChooseLane applies internally, written out — and the reason reading it from outside is only legitimate on the owning thread: the same field is being incremented by that thread between passes, with no lock and no atomic.
