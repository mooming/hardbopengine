PriorityCredit

member of hbe::StreamDrainPolicy Engine/Core/StreamDrainPolicy.cpp Private, and nothing calls it.

Signature

[[nodiscard]] int64_t PriorityCredit() const noexcept

Function description

Defined in Engine/Core/StreamDrainPolicy.cpp as StreamDrainPolicy::PriorityCredit(); the body is return priorityCredit;. The private read side of the priority lane's rotation counter, counterpart of FifoCredit.

Nothing calls it, in this class or anywhere else. Its declaration and definition are the only occurrences in the repository: ChooseLane reads the field, CommitTake and EndRound write it, and the tests assert through the lane choices. Documented because the entry exists in the header; the honest summary is dead code with a coherent purpose, the same as FifoCredit.

The comparison that gives the counter its shape is fifoCredit >= priorityCredit, evaluated only when both lanes have work and the stream is unlimited — so a lane's credit only matters relative to the other one. The replenishment rule is likewise joint: CommitTake tops both up only once both have reached zero or below, which is why a light lane is not starved by a heavy one at 1:3 (the test of that name requires at least one FIFO serve in eight takes).

Examples

Illustrative — this accessor is private and has no caller; the behaviour it observes is tested through ChooseLane.

policy.ConfigureRate(1, 3);

const auto counts = DriveTakes(policy, 8);

From Engine/Core/StreamDrainPolicy.cpp, StreamDrainPolicyTest

At 1:3 the helper drives eight takes and the test requires the lighter lane to be served at least once and the heavier one at least as often. Each take in that helper both CommitTakes and charges one nanosecond to the lane chosen, which is the ordering the class expects: credit at the take, CPU time afterwards.
