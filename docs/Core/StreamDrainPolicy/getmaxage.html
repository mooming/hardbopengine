GetMaxAge

member of hbe::StreamDrainPolicy Engine/Core/StreamDrainPolicy.cpp The staleness ceiling as set - the read half of a change-then-restore.

Signature

[[nodiscard]] std::chrono::nanoseconds GetMaxAge() const noexcept

Function description

Defined in Engine/Core/StreamDrainPolicy.cpp as StreamDrainPolicy::GetMaxAge(); the body is return maxAge;. The ceiling exactly as SetMaxAge left it — including a negative value, which this reports faithfully even though IsOverAge treats it as unlimited.

Its purpose is stated in the header: the read half of a change-then-restore. A caller that borrows a stream it does not own needs the current ceiling to put it back, because the ceiling is per stream and not something a second caller can recompute (Engine/Core/StreamDrainPolicy.h).

Not the same question as "how old is the oldest item". This reports the configured limit; the age of what is queued is a property of the WorkItem stamps and is only visible by sweeping the stream's queues. The test A fresh item under the ceiling is admissible pairs the two: SetMaxAge sets a 1 ms ceiling and an item at 100 µs is admitted, so a GetMaxAge reading tells you nothing about whether the next offer will be accepted.

The pairing is what a caller that borrows a stream it does not own must do, and the repository's only example of it is a test: the #ifdef __UNIT_TEST__ region of Engine/Core/TaskSystem.cpp stores const std::chrono::nanoseconds ceilingFound = baseStream.GetMaxAge();, sets a ceiling to measure staleness, and restores ceilingFound on every exit path — because a ceiling set to zero to prove a point is a stream the next test inherits. No shipping code sets a ceiling, so this read is currently a test's safety net and nothing else.
