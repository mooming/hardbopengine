FifoCredit

member of hbe::StreamDrainPolicy Engine/Core/StreamDrainPolicy.cpp Private, and nothing calls it - not even this class.

Signature

[[nodiscard]] int64_t FifoCredit() const noexcept

Function description

Defined in Engine/Core/StreamDrainPolicy.cpp as StreamDrainPolicy::FifoCredit(); the body is return fifoCredit;. A private accessor for the rotation counter that decides the lane when a stream has no allowance: ChooseLane compares the two credits against each other and sends a tie to the FIFO lane.

Nothing calls it — not even this class. The declaration and the definition in Engine/Core/StreamDrainPolicy.cpp are its only occurrences in the repository: ChooseLane reads the fifoCredit field directly, CommitTake and EndRound write the field directly, and being private it has no external user to serve. It is documented here because the entry exists in the header and a reader must be able to find out what it was for; the honest summary is that it is dead code with a coherent purpose.

The counter itself is real and in use, so the value it would return is meaningful: it starts at the configured weight, is decremented by CommitTake on each take from this lane, and both counters gain their weights back together when both reach zero or below. It is a signed counter, so a lane can go negative — that is how the heavier lane pays for its extra serves before the light one is replenished.

None.

Return value

Examples

Illustrative — this accessor is private and has no caller; the behaviour it observes is tested through ChooseLane.

Eight takes with both lanes loaded at a 3:1 rate give 6:2, which is the credit mechanism's whole contract and is asserted through the lane choices rather than through this counter. A test that read the counter instead would pin the mechanism and lose the promise.
