ChargeFifo

member of hbe::StreamDrainPolicy Engine/Core/StreamDrainPolicy.cpp Adds a task's CPU time to the FIFO lane's accumulation for this round.

Signature

void ChargeFifo(std::chrono::nanoseconds spent) noexcept

Function description

Defined in Engine/Core/StreamDrainPolicy.cpp as StreamDrainPolicy::ChargeFifo(); the body is fifoUsed += spent;. One accumulation, no clamping, no mode check: the amount is added whether or not an allowance is configured, and ChooseLane only consults the accumulation when there is one.

The charge belongs after the task ran. TaskStream::Update() brackets the item's execution in a time::ScopedTime, asks the CPU budget how much it accumulated, and charges that difference to the lane the item came from (Engine/Core/TaskStream.cpp) — so the figure is measured CPU time attributed through the budget, not wall-clock duration of the pass.

A lane overshoots its share by the length of its longest task. A task cannot be stopped once taken, so this call is how the overshoot gets recorded rather than prevented: the shares gate acquiring, never execution. Reading fifoUsed as "nothing from this lane is in flight" is the mistake the header warns a caller must not make.
Charges accumulate until EndRound. They are per round, not per pass, and a stream whose window never advances never reopens its shares — the accumulations then keep growing and ChooseLane keeps answering None.

Parameters

ParameterTypeRequirement
spentstd::chrono::nanosecondsCPU time the task consumed. A negative value would move the accumulation backwards; nothing here rejects one

Return value

void. Read it back with GetFifoUsed, on the owning thread.

Examples

From Engine/Core/TaskStream.cpp, TaskStream::Update()

const auto spent = budget.GetAccumulated() - chargedBefore;
if (lane == StreamDrainPolicy::ELane::Priority)
{
    drainPolicy.ChargePriority(spent);
}
else
{
    drainPolicy.ChargeFifo(spent);
}

The charge is conditional on the stream actually carrying a budget — the surrounding code only brackets the run with budget.BeginTask() / EndTask() when an allowance is set. An unbudgeted stream therefore charges nothing, which is consistent with its shares being unlimited anyway.
