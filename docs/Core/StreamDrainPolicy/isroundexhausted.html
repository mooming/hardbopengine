From Engine/Core/StreamDrainPolicy.cpp, StreamDrainPolicy::IsRoundExhausted()

The first test is the load-bearing one: for an unlimited stream this is always false, because a round is defined by the allowance. A caller that gated its reset on this answer alone would never reset an unbudgeted stream — which is why CommitTake replenishes credit on its own terms rather than waiting for a round to close.

The comparison is the same sum ChooseLane uses before it returns a lane, so the two agree: when this says true, ChooseLane answers ELane::None whatever the lanes hold.

Nothing outside this class's tests asks the question. In Engine/ and Applications/ the only call sites are in Engine/Core/StreamDrainPolicy.cpp's own test collection. TaskStream::Update() ends the round on a different event — a budget-window advance — so a stream's shares reopen on the window cadence, not when this predicate turns true (Engine/Core/TaskStream.cpp). Treat this as the accessor that states the round's state, not as the hook that closes it.

const auto overspill =
        std::chrono::duration_cast<std::chrono::nanoseconds>(std::chrono::duration<double, std::milli>{0.6});
policy.ChargeFifo(overspill);
policy.ChargePriority(overspill);

if (!policy.IsRoundExhausted())
{
    ls << "1.2 ms charged against a 1 ms allowance did not exhaust the round." << lferr;
}

Both lanes charged past their own half-share but each still inside the stream total would not exhaust anything; it is the sum that closes a round. The same test then requires ChooseLane to answer None, and EndRound to reopen both.
