IsOverAge

member of hbe::StreamDrainPolicy Engine/Core/StreamDrainPolicy.cpp Three guards before the comparison, each load-bearing.

Signature

[[nodiscard]] bool IsOverAge(std::chrono::nanoseconds offerTime, std::chrono::nanoseconds now) const noexcept

Function description

Defined in Engine/Core/StreamDrainPolicy.cpp as StreamDrainPolicy::IsOverAge(), in one expression with three conjuncts, each of which is load-bearing: 

return maxAge.count() > 0 && offerTime.count() > 0 && now - offerTime > maxAge;

From Engine/Core/StreamDrainPolicy.cpp, StreamDrainPolicy::IsOverAge()

GuardWhat it protects
maxAge.count() > 0The feature is off by default, not merely unreadable — without this a zero ceiling would become "drop everything" and every existing stream would start discarding tasks
offerTime.count() > 0Work with no stamp cannot be dated, so it is run rather than guessed stale; a negative stamp lands here too
now - offerTime > maxAgeStrict, so work exactly as old as the ceiling is still admissible and one nanosecond more is not

This class owns no clock. now is passed in by the caller, and the shipping caller reads it from the engine epoch at the moment of judgement (Engine/Core/TaskStream.cpp), which is the same clock that stamps offerTime — the two must agree or the delta is meaningless.

The boundary is pinned on both sides by a test, and the test's own comment says why. A stream with no max age ages nothing out, and work it cannot date is never judged asserts that an unlimited stream spares 10 s-old work, that an unstamped item survives a 20 ms ceiling, that 21 ms of age does not survive one, and that work exactly 20 ms old does survive it — because pinning only the far side would let the comparison silently become >=, "and a ceiling that is one nanosecond stricter than documented is a starvation change nobody approved" (Engine/Core/StreamDrainPolicy.cpp).
Judgement happens after the task lookup, on the worker thread, for one item. TaskStream::TryExecuteWorkItem() tests this only once the item's task has been found, so a released task keeps its existing explanation rather than acquiring a second one, and both lanes pass the same point — one rule covers both queues. A refusal there counts agedOutWorkCount, reports the item, fires its abandoned notice and returns the item to the pool; it is a drop, not a re-queue (Engine/Core/TaskStream.cpp).

Examples

From Engine/Core/TaskStream.cpp, TaskStream::TryExecuteWorkItem()

if (const auto now = std::chrono::duration_cast<std::chrono::nanoseconds>(time::ElapsedSinceEngineEpoch());
        drainPolicy.IsOverAge(workItem->offerTime, now))
{
    agedOutWorkCount.fetch_add(1, std::memory_order_relaxed);
    ReportAgedOutWorkItem(*workItem, now - workItem->offerTime);
    FireAbandonedNotice(*workItem);
    restore();
    return true;
}

The whole feature from the outside: one call, then a count, a report and a notice. The ceiling that made the decision was set by SetMaxAge, and the report carries the age so a reader can tell a stream that is merely behind from one whose ceiling is too tight for its own task durations.
