IncFallbackAllocCount

member of hbe::SystemStatistics Engine/Core/SystemStatistics.h Add one when a pool allocator falls back to the system - live in every build.

Signature

void IncFallbackAllocCount() noexcept

Function description

Defined in the header Engine/Core/SystemStatistics.h. Adds one to fallbackAllocCount with fetch_add(1, std::memory_order_relaxed). Counts the moment a pool allocator has to go outside its pools — a new bank, which means a system allocation. Two call sites, both compiled in every configuration: this one and the same statement in ThreadSafeMultiPoolAllocator (Engine/Memory/ThreadSafeMultiPoolAllocator.cpp).

Live, unlike everything else on this page — and the last line of the report. This is one of only two counters the engine actually fills, and Print gives it the final figure before the closing banner. A non-zero value is a real signal: it says a pool ran short and the allocator fell back to the system, which is the event a memory review wants counted (Engine/Core/SystemStatistics.cpp, Engine/Memory/MultiPoolAllocator.cpp).
Called from the allocation path, so it is on the hot path's books. One relaxed atomic add per fallback — negligible against the bank creation that follows it, which computes a block size and takes allocator locks (Engine/Memory/MultiPoolAllocator.cpp). Both allocators, plain and thread-safe, raise the same counter on the same class of event, so the number is per-engine rather than per-allocator.

Parameters

None.

Return value

void. The count is not returned; the only reader is Print.
