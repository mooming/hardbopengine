ReportSysMemDealloc

member of hbe::SystemStatistics Engine/Core/SystemStatistics.h Under PROFILE_ENABLED only: count one system deallocation and subtract from the running total.

Signature

void ReportSysMemDealloc(size_t usage) noexcept

Function description

Declared in Engine/Core/SystemStatistics.h under #if PROFILE_ENABLED, defined in Engine/Core/SystemStatistics.cpp under the same condition, compiled out in every configuration (Engine/Config/BuildConfig.h). This page is written from the source text rather than from behavior.

Records one system deallocation: under sysMemReportLock it increments deallocCount and subtracts usage from totalUsage. It is the mirror of ReportSysMemAlloc minus the high-water mark and minus the warning. 

std::lock_guard lock(sysMemReportLock);
++deallocCount;

Assert(totalUsage >= usage);
totalUsage -= usage;

From Engine/Core/SystemStatistics.cpp, SystemStatistics::ReportSysMemDealloc() (under PROFILE_ENABLED)

The guard against underflow is an Assert, so in Dev and Release an unbalanced free wraps the total to a huge number. Assert compiles to nothing unless !RELEASE_BUILD is defined, and only the Debug configuration defines it (Engine/Core/Debug.h). The subtraction is unsigned, so a report of a byte count that was never added — or one added twice — leaves totalUsage near size_t's maximum, and Print would then print that as the current system memory usage without a single word about the cause. The same one-way-trust pattern is recorded for the CPU budget (CPUBudget::EndTask).
It never touches maxUsage, which is what makes the pair of figures in the report meaningful. The high-water mark is raised only on the way up (ReportSysMemAlloc), so the report line "System Memory Usage = current / peak" prints a peak that is not revised downward (Engine/Core/SystemStatistics.cpp). Both counters are plain size_t under a mutex, and Print reads them with no lock at all.

Parameters

NameTypeMeaning
usagesize_tBytes returned by this deallocation; assumed to have been counted by a previous ReportSysMemAlloc, with nothing but a Debug assert enforcing it

Return value

void. No report of the resulting total, and no rejection: the subtraction happens whatever the value, and the only witness is the assert that shipping builds do not contain.
