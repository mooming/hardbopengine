SystemStatistics

member of hbe::SystemStatistics Engine/Core/SystemStatistics.h Zeroes every counter, takes the start instant, and tells the engine statistics are ready.

Function description

Defined in Engine/Core/SystemStatistics.cpp; declared in Engine/Core/SystemStatistics.h. Zeroes the six atomic counters and the four allocation figures, takes the start time as "now", sets the current time to the same instant, and then tells the engine that statistics exist. The explicit matters: an Engine& is not silently an Engine&-to-statistics conversion waiting to happen.

The two time fields the getters hand out are not initialized here, and nothing else initializes them either. The initializer list names startTime and currentTime and stops (Engine/Core/SystemStatistics.cpp), and the header declares double timeSinceStart; and float deltaTime; with no default member initializer (Engine/Core/SystemStatistics.h). The only writer of both is UpdateCurrentTime, which has no caller anywhere in Engine/ or Applications/. So GetTimeSinceStart and GetDeltaTime return indeterminate values, and Print prints one of them (Engine/Core/SystemStatistics.cpp).
Construction is an ordering step as much as an initialization step. 
startTime(time::TStopWatch::now())
    , currentTime(startTime)
{
    Assert(engine.IsMemoryManagerReady());
    engine.SetSystemStatisticsReady();
}

From Engine/Core/SystemStatistics.cpp, SystemStatistics::SystemStatistics()

It asserts that the memory manager exists and then announces that statistics are ready, so the engine's own construction sequence has to build the memory manager first and this last (Engine/Engine/Engine.h holds it as a plain member). Both statements are load-bearing in opposite ways: the Assert is compiled out unless !RELEASE_BUILD is defined, so a wrong order is silent in Dev and Release; SetSystemStatisticsReady is not, and is what other engine subsystems wait on. The class also refuses to compile at all on a platform where std::atomic<uint64_t> is not always lock-free — a class-scope static_assert in the header, before the first member (Engine/Core/SystemStatistics.h).

Parameters

NameTypeMeaning
engineEngine&The owning engine, used only during construction — for the readiness assert and the readiness call. The class stores no reference to it

Return value

None — a constructor. The object it produces has counted nothing, knows the start instant, and is not yet able to answer a question about elapsed time.

Examples

There is one instance, built as a member of Engine (Engine/Engine/Engine.h), and every other subsystem reaches it through the engine: 

auto& engine = Engine::Get();
auto& statistics = engine.GetStatistics();
statistics.IncFallbackAllocCount();

From Engine/Memory/MultiPoolAllocator.cpp, MultiPoolAllocator::NewBankAllocate()

The engine is not copied or moved, so neither is this, and the counters are never reset — the object lives exactly as long as the run (~SystemStatistics).
