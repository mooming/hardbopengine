~SystemStatistics

member of hbe::SystemStatistics Engine/Core/SystemStatistics.h Defaulted: reports nothing, and the shutdown print must happen before it runs.

Signature

~SystemStatistics() = default

Function description

Declared and defaulted in the header Engine/Core/SystemStatistics.h; nothing in Engine/Core/SystemStatistics.cpp. It destroys the six atomics, the mutex, the four allocation figures, the two time points and the profile vector, and reports nothing — the shutdown report is Print, and whoever wants it must call it before this runs.

It is = default and the class is final, so there is nothing a subclass could get wrong here. class SystemStatistics final (Engine/Core/SystemStatistics.h) means the destructor is never virtual-dispatched, and no member of this class needs releasing by hand: the atomics and integers are trivial, sysMemReportLock is a std::mutex whose destructor aborts the process if it is still locked, and allocStats — declared only when PROFILE_ENABLED is set, which no configuration does (Engine/Config/BuildConfig.h) — is a vector that frees itself.
A report that arrives during teardown is a use-after-free with no guard against it, because the only reports left are compiled out. ReportSysMemAlloc and ReportSysMemDealloc are called from MemoryManager when the system allocator hands out or takes back memory (Engine/Memory/MemoryManager.cpp) — but those call sites sit inside #if PROFILE_ENABLED regions, and the flag is unconditionally 0 (Engine/Config/BuildConfig.h), so no build in the tree can produce that traffic. The live counters are incremented from the allocators and the logger (IncFallbackAllocCount, IncEngineLogCount), and a relaxed fetch_add on a destroyed atomic is undefined. The engine's own shutdown sequence prints statistics near the end of Engine::ShutDown and then tears the rest down (Engine/Engine/Engine.cpp), which is the ordering that keeps that theoretical.

Parameters

None.

Return value

None. It is defaulted, so it is noexcept by the usual rules and runs whatever the members' own destructors do.

Examples

Nothing in the engine destroys a SystemStatistics explicitly: it is a member of Engine (Engine/Engine/Engine.h) and dies with it, after Print has already written the last report at the end of Engine::ShutDown (Engine/Engine/Engine.cpp). That sequence is the whole reason the shutdown numbers appear in a log at all.
