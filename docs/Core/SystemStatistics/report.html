Report

member of hbe::SystemStatistics Engine/Core/SystemStatistics.h Under PROFILE_ENABLED only: append one AllocStats record for the profile dump.

Signature

#if PROFILE_ENABLED
	void Report(const AllocStats& allocStats) noexcept

Function description

Declared in Engine/Core/SystemStatistics.h under #if PROFILE_ENABLED, defined in Engine/Core/SystemStatistics.cpp under the same condition, and PROFILE_ENABLED is defined as 0 unconditionally in Engine/Config/BuildConfig.h — so neither half is compiled in any configuration the tree builds. This page is therefore written from the source text, and it says so plainly: no verification pass can see a declaration the preprocessor removes, and nothing here was observed running.

Its whole body is allocStats.emplace_back(stats); — it appends the memory module's AllocStats record (Engine/Memory/AllocStats.h) to the vector that PrintAllocatorProfiles would walk. It takes no lock, unlike its two siblings. 

void SystemStatistics::Report(const AllocStats& stats)
{
    allocStats.emplace_back(stats);
}

From Engine/Core/SystemStatistics.cpp, SystemStatistics::Report() (under PROFILE_ENABLED)

The declaration says noexcept and the definition does not, so the moment anyone sets PROFILE_ENABLED to 1 this translation unit stops compiling. A definition that omits an exception specification its declaration carries is rejected by the compiler — confirmed with a minimal translation unit (struct S { void F() noexcept; }; plus void S::F() {}, which clang refuses with "is missing exception specification 'noexcept'"). All three profile reporters have the same mismatch, so the profiling half of this class is not merely unused but unbuildable as written (Engine/Core/SystemStatistics.h, Engine/Core/SystemStatistics.cpp).
Its caller is the memory manager, behind the same flag. The one call site is inside a #if PROFILE_ENABLED region of Engine/Memory/MemoryManager.cpp, alongside ReportSysMemAlloc. So the vector this fills and the function that would print it are both driven by the memory module, and neither exists in a shipping build (Engine/Memory/MemoryManager.cpp).

Parameters

allocStatsconst AllocStats&One allocator's statistics record, copied into the vector; named stats in the definition, which is the same object under a different name

Return value

void. Nothing reports whether the entry was stored, and the vector grows unboundedly — there is no cap and no clear, which matters only in a build that compiles this at all.

Examples

There is no reachable call site to quote; the caller is described above and lives in the memory module. What the entry does with the record — printing a per-allocator profile line — is AllocStats::Print's duty (the memory module), reached only from PrintAllocatorProfiles.
