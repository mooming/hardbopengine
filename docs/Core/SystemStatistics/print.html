Print

member of hbe::SystemStatistics Engine/Core/SystemStatistics.h The shutdown report, eleven lines: two live counters, six structurally zero, one uninitialized.

Signature

#endif

Function description

Defined in Engine/Core/SystemStatistics.cpp. The shutdown report: eleven lines out through the logger under the name from GetName, covering frames, logs, running time, system allocation and fallback allocation. It takes no lock, resets nothing, and can be called any number of times — each call writes a fresh block.

Two of the six counters are live, six lines are structurally zero, and one prints an uninitialized field. What the report can honestly say in a build made from this tree:
LineSourceStatus in every shipping configuration
Frame CountIncFrameCountalways 0 — no caller
Slow Frame CountIncSlowFrameCountalways 0 — no caller
Engine Log CountIncEngineLogCountlive — Engine::Log
Log Count / Long Log CountIncLogCount, IncLongLogCountalways 0 / 0 — both increments sit inside #if PROFILE_ENABLED
Running TimetimeSinceStartindeterminate — UpdateCurrentTime is never called and the field is never initialized
Allocation Count / System Memory UsageallocCount and friendsalways 0 — written only by the PROFILE_ENABLED reporters
Fallback Allocation CountIncFallbackAllocCountlive — both pool allocators
The two log counters are read once, up front, and reused; the rest are read inline. 
auto curLogCount = logCount.load(std::memory_order_relaxed);
auto curLongLogCount = longLogCount.load(std::memory_order_relaxed);

From Engine/Core/SystemStatistics.cpp, SystemStatistics::Print()

That is a deliberate consistency choice, not an accident: the "Long Log Count = X / Y" line divides one counter by the other, and reading them at two different moments could produce a ratio that never existed. The other counters appear once each, so they have nothing to be consistent with. Every load is relaxed — no ordering is promised against the threads doing the incrementing, which is the right price for a statistics dump and the reason none of these numbers can be used as evidence that something else has happened (Engine/Core/SystemStatistics.cpp).

The four allocation figures are read plain, while their only writers hold a mutex. ReportSysMemAlloc and ReportSysMemDealloc update allocCount, deallocCount, totalUsage and maxUsage under sysMemReportLock, and this function reads all four with no lock (Engine/Core/SystemStatistics.cpp). In a build where profiling is off — that is, every build — the fields are never written after construction, so the read is harmless and the numbers are zeros. Were PROFILE_ENABLED ever set to 1, a report from another thread during this print would be a data race on plain size_t.

Parameters

None.

Return value

void. Output goes to the logger, not to a stream a caller controls, and there is no level argument: the report is written at the logger's default level under the "SystemStatistics" category.

One call, at shutdown, alongside the other end-of-run dumps, after the task system has been joined (Engine/Engine/Engine.cpp) — so the counters are at their final values by then for everything that is incremented on a worker thread. The next line is PrintAllocatorProfiles, which in this configuration writes nothing at all.
