GetName

member of hbe::SystemStatistics Engine/Core/SystemStatistics.h A function-local static string, so the same name for every instance and valid after this object dies.

Signature

[[nodiscard]] const StaticString& GetName() const noexcept

Function description

Defined in Engine/Core/SystemStatistics.cpp. Returns a name that is not a member: the body creates a function-local static StaticString name("SystemStatistics") and returns a reference to it, so every instance of the class reports the same string, and the string is the name of the class rather than of anything configurable.

The static is the point, and it makes this the one accessor here that is safe to call at any time. A function-local static is initialized once, by the first thread to reach it, and lives until the program ends (Engine/Core/SystemStatistics.cpp) — so the reference stays valid after this object is destroyed, and two instances (there is only one, but the reasoning holds) cannot disagree. The string is interned, which is what StaticString means in this engine: the name occupies a slot in the static-string table rather than a buffer owned by this object.
It exists to label the log lines this class writes, and the two printers are its only users. Both Print and PrintAllocatorProfiles open their output with Logger::Get(GetName()), so "SystemStatistics" is the logger category the shutdown report is filed under (Engine/Core/SystemStatistics.cpp). No caller outside the class asks for the name.

Parameters

None.

Return value

TypeWhat it tells the caller
const StaticString&A reference to a program-lifetime static holding "SystemStatistics". Never empty, never null, and the same object for every caller — safe to keep, safe to compare by address

Examples

auto log = Logger::Get(GetName());

log.Out("= System Statistics ==========================");

From Engine/Core/SystemStatistics.cpp, SystemStatistics::Print()

The category is chosen once per print call, and the whole report goes out under it (Engine/Core/SystemStatistics.cpp). PrintAllocatorProfiles asks for the same name at a different level (ELogLevel::Verbose), which is how the two reports are separated without being different categories.
