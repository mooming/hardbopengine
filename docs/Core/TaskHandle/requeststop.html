RequestStop

member of hbe::TaskHandle Engine/Core/TaskProvider.h Const and idempotent; doing nothing on an empty token keeps teardown guard-free.

Signature

void RequestStop() const noexcept

Function description

Defined in Engine/Core/TaskProvider.cpp as TaskHandle::RequestStop(). 

if (provider != nullptr)
{
    provider->Stop();
}

From Engine/Core/TaskProvider.cpp

One guarded forward. const because stopping does not alter the token: "any copy of it can issue the same request, and a token that became unusable once used would have to be kept mutable everywhere" (Engine/Core/TaskProvider.h). The effect lands on the provider's atomic flag, where every copy of the token and the provider itself will see it through IsStopRequested.

Doing nothing on an empty token is deliberate. "So that a registry entry that was never filled can be stopped on a teardown path without a caller-side guard" (Engine/Core/TaskProvider.h). This is the call a teardown loop should make unconditionally — over every slot of a table, empty or not — and the reason the boolean test is not a prerequisite of it.
"Request" is the accurate word, and the gap is in the drain path rather than in this call. The provider's own contract states what a stop means: "Stop is not cancellation. Tasks already taken run to completion - the task system cannot stop one - so 'stopped' means no further Produce calls, not no further work" (Engine/Core/TaskProvider.h). The page for TaskProvider::Stop records what the shipping drain path does with the flag this sets — and it is worth reading before relying on a stop as a way to quiet a producer.
Safe from any thread, and it does not wait for anything. The store is a release store on an atomic, and nothing here takes a lock, joins a thread, or touches a stream's provider list — which is the point: a caller on an arbitrary thread has no right to edit a container another thread is iterating (Engine/Core/TaskProvider.h). A caller that needs the producer actually removed from a stream needs DetachFrom, and that is a call on the provider, not on a token.

Parameters

None. There is no "stop after N items" or "stop and drop" variant; the request is one bit with no parameters to negotiate.

Return value

void. Nothing reports whether the token was empty, whether a stop had already been requested, or whether anybody will act on it. Read IsStopRequested for the first two.

Examples

From Engine/Core/TaskProvider.cpp, TaskProviderTest

RecordingProvider other("ProviderStopProbe2", System());
const auto otherHandle = other.GetHandle();
otherHandle.RequestStop();
if (!other.IsStopRequested())
{
    ls << "RequestStop through a handle did not reach the provider." << lferr;
}

The request asked to be visible on the provider, which is the whole obligation this call has. The token's lifetime rule still applies at the call: a handle whose provider has already been destroyed reaches this code's one pointer dereference, and nothing here can notice (Engine/Core/TaskProvider.h).
