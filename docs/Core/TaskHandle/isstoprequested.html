Function description

From Engine/Core/TaskProvider.cpp

Two reads in one expression: the stored pointer, then the provider's atomic stop flag — a std::atomic<bool> loaded with acquire semantics by TaskProvider::IsStopRequested. Safe from any thread, and it is the only question about a provider that a token holder may ask from anywhere without leaving the provider's own contract (Engine/Core/TaskProvider.h).

An empty token answers false, and false here has two causes. Short-circuiting on a null pointer and a provider that has not been stopped produce the same answer, and this call cannot tell them apart. Use the boolean test first when the distinction matters — for instance when reporting that a teardown had nothing to stop.
The answer is a moment, and the state it reports is one-way. A stop request is never cleared: nothing writes false back to the flag, so once this reads true it will keep reading true for as long as the provider lives (Engine/Core/TaskProvider.h). The reverse is not a promise — a true says somebody asked, not that any stream has stopped calling Produce. The stream that drains a provider is the party that has to act on the flag, and the page for TaskProvider::Stop records what the shipping drain path does with it.
Every copy of a token reports the same answer. The flag lives on the provider, not the token, so issuing RequestStop through one copy is visible through all of them and through TaskProvider::IsStopRequested called directly. That is what makes RequestStop const: the token is a name for the provider, not a resource it owns.

The pairing the type exists for: a stop issued on the provider must be visible through a token that knows nothing but the address, because both reads reach the same atomic on the same object. The test asserts the same equality in the other direction as well — a request made through a second provider's handle must not appear on the first (Engine/Core/TaskProvider.cpp).
