TaskHandle

Engine/Core/TaskProvider.h A control token for one TaskProvider: the thing worth holding to stop a producer.

Class description

class TaskHandle final at Engine/Core/TaskProvider.h: a control token for one TaskProvider, held by whoever needs to stop it. A stream cannot stop a task that has already been taken, so the thing worth holding on to is the producer: stopping a provider ends the supply of work without disturbing work already in flight. The token is what lets a stream, a registry, or a subsystem manager say "that one" without owning the provider (Engine/Core/TaskProvider.h).

PropertyAs implemented
Size and contentsOne TaskProvider*, null when the token refers to nothing
OwnershipNone — the handle cannot keep its provider alive and does not extend its life by a moment
CopyingImplicitly copyable; every copy names the same provider and can issue the same request
Thread-safetyRequestStop and IsStopRequested are safe from any thread; what GetProvider permits afterwards is not
A handle outliving its provider dangles, and no check here can detect that. "The owner's lifetime rule is that handles die first" (Engine/Core/TaskProvider.h). Nothing in the type participates in that rule: there is no generation, no registry lookup, and no liveness probe — IsStopRequested and RequestStop both dereference the stored pointer the moment they are called on a non-empty token. The provider's own protection runs the other way: TaskProvider::~TaskProvider asserts that it is registered on no live stream, which guards the stream's copy of the pointer and not a handle-holder's.
Nothing in the engine stores one. TaskStream's per-lane provider lists hold raw TaskProvider* (Engine/Core/TaskStream.h), and a search of Engine/ and Applications/ outside Engine/Core/TaskProvider.cpp finds no GetHandle call and no TaskHandle object. The consumers the class is written for — a registry entry, a subsystem manager — do not exist yet; the calls are exercised by TaskProviderTest (Engine/Core/TaskProvider.cpp).
What stopping does and does not mean is the provider's rule, not this class's. "Stop is not cancellation. Tasks already taken run to completion - the task system cannot stop one - so 'stopped' means no further Produce calls, not no further work" (Engine/Core/TaskProvider.h). The page for TaskProvider::Stop also records the gap between that promise and the shipping drain path, which is what a handle-holder is really relying on.
