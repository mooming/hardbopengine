TaskHandle

member of hbe::TaskHandle Engine/Core/TaskProvider.h An empty token, or a token naming a provider the caller must keep alive.

Signature

TaskHandle() = default

explicit TaskHandle(TaskProvider& provider) noexcept

Function description

The default constructor is spelled = default in Engine/Core/TaskProvider.h and leaves the single member at its default member initialiser, nullptr. The taking constructor is defined in Engine/Core/TaskProvider.cpp: 

TaskHandle::TaskHandle(TaskProvider& target) noexcept
    : provider(&target)

From Engine/Core/TaskProvider.cpp

It takes a reference and stores the address. There is no constructor that takes a pointer, so an empty token can only be made by the default constructor — the two empty-producing routes a nullable type usually has are collapsed into one. The parameter is named in the header as provider and in the source as target; the declaration is what documents the call.

explicit is load-bearing. A handle is not a value the provider can be quietly converted into, which matters because a handle is copyable, assignable and droppable: an implicit conversion would let a function taking TaskProvider& hand back control of itself without saying so. The empty constructor is deliberately not explicit, so a default-constructed token still appears where a "no provider" value is wanted.
Neither constructor can be checked afterwards, and neither extends the provider's life. The class stores the address and nothing else, so "handles die before their provider" (Engine/Core/TaskProvider.h) is enforced by whoever holds the handle, at the point the provider is destroyed — not here. TaskProvider's own destructor asserts about registrations on live streams, which is a different set of holders than the set of tokens issued by TaskProvider::GetHandle.

Parameters

ParameterTypeRequirement
providerTaskProvider&The provider to control. It must outlive this token and every copy of it; a derived provider is accepted as its base, which is the intended use — the token controls the producer, not the derived type

Return value

Nothing. Construction cannot fail: taking the address of a live object has nothing to check, and the empty token is a value rather than an error.

Examples

From Engine/Core/TaskProvider.cpp, TaskProviderTest

const auto handle = provider.GetHandle();

The route every real handle comes from — TaskProvider::GetHandle() returns a token built by this constructor — and the reason the pair exists in the header at all: a caller that wants a token asks the provider for one instead of forming an address itself. No shipping code does this yet; TaskStream's lane lists hold raw TaskProvider* (Engine/Core/TaskStream.h).
