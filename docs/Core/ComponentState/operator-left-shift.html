operator<<

namespace hbe, Engine/Core/ComponentState.h prints an enumerator as its name by indexing a five-entry table with the enumerator's number, checking nothing

Signature

inline std::ostream& operator<<(std::ostream& os, const ComponentState& state)
{
        static const char* names[] = {"NONE", "BORN", "ALIVE", "SLEEP", "DEAD"};

        os << names[static_cast<int>(state)];
        return os;
}

Function description

Stream insertion for the enumeration, so a Component's state can be reported as ALIVE instead of 2. The mechanism is a table lookup: the enumerator is cast to int and used to index names, a function-local static array of five string literals at Engine/Core/ComponentState.h:23.

The inline is load-bearing, not decorative. This is a namespace-scope function defined in a header that Engine/Core/Component.h includes, so without it every translation unit that includes the header would emit its own definition and the link would fail. That is the case the inline rule warns about: the keyword is redundant on an in-class member and required here.

The index is unchecked. names holds five entries and static_cast<int>(state) is not constrained before it is used at Engine/Core/ComponentState.h:25, so any value outside 0 to 4 reads outside the array. The type makes such a value reachable: the underlying type is int, so static_cast<ComponentState>(99) is a well-formed ComponentState that no accessor in this engine would ever have produced. There is no assert, clamp or fallback string. This matters most in the place the operator exists for — a failure report about an unexpected state — because printing the very value that is wrong is what crosses the boundary.

Parameters

ParameterTypeRequirement
os std::ostream& Any writable stream. The engine's unit-test harness passes its own log stream, which supports this operator through Log
state const ComponentState& One of the five enumerators declared by the enum. Values produced by casting an arbitrary int are not handled — see the hazard above

Return value

TypeWhat you get
std::ostream& The same stream that was passed in, with the enumerator's name appended, so further << operations chain onto it. Nothing is inserted on failure — there is no failure path
