ComponentState

Engine/Core/ComponentState.h the five lifecycle states a Component passes through, and the only value ComponentSystem reads when it decides what to do with one

Class description

ComponentState is an enum class over int with five enumerators. It is the whole state of a component: Component stores one in its protected state member, and everything a component is at a given moment — enabled, asleep, awaiting release — is expressed by which enumerator it holds. There is no flag word and no separate enabled bit; IsEnabled() is the test state == ALIVE.

Values are written through Component::SetState, SetEnable and Destroy, and they are consumed by ComponentSystem::ProcessTransition, which switches on the state of everything in its transition list: ALIVE calls OnEnable() and moves the component into the update list, SLEEP calls OnDisable() and moves it to the sleep list, and DEAD runs the release path. Anything else reaches a default that asserts, so NONE and BORN reaching that switch is treated as a bug rather than a state.

The release path rewinds the state before it disables. For DEAD the transition is SetState(SLEEP), then OnDisable(), then SetState(DEAD), then Release() — Engine/Core/ComponentSystem.h through :121. A component that reads its own state inside OnDisable() therefore sees SLEEP, never DEAD, and code that tests for DEAD there is testing something that cannot be true at that moment.

Template parameters

None — an enumeration is not a template, and this one is not parameterised on anything.

Class properties

NameDeclarationWhat it means
NONE= 0 enumerator The state a component holds straight after Component::Component(const char*) at Engine/Core/Component.h: constructed, not yet registered with a system. Reaching the transition switch in this state asserts
BORN= 1 enumerator Set by ComponentSystem::Create() when a component is added. The unit tests assert this value after registration (Engine/Core/ComponentSystem.cpp). Not a valid state at transition time
ALIVE= 2 enumerator Enabled and updated. ComponentSystem::ProcessInit() sets it, and SetEnable(true) sets it. The transition switch calls OnEnable() and puts the component on the update list
SLEEP= 3 enumerator Disabled but alive: SetEnable(false) sets it, and the switch calls OnDisable() and moves the component to the sleep list. It is also the value a component sees inside OnDisable() while being released
DEAD= 4 enumerator Requested by Component::Destroy(). The switch disables, then calls Release(). It is the only state whose handler changes the state twice

The underlying type is int, spelled enum class ComponentState : int. The five values are the ones the header declares; nothing in the engine stores a state produced any other way, which matters because the stream operator below indexes an array by this number.

Class methods

None — an enumeration declares no members. Reading and writing the state goes through Component's accessors, not through this type.

The transition machine itself This page states which state means what and which handler reads it. Who moves a component from one state to another, and in what order the lists are processed, is ComponentSystem's contract and belongs to ComponentSystem
The assert text on the default path The default path of ComponentSystem::ProcessTransition() formats the offending value with a %d conversion, which is why an unexpected state is reported as a number and not a name even though the name operator above exists. Formatting and severity belong to Log
Component behaviour per state What OnEnable(), OnDisable() and Release() do is the subclass's; the engine declares them pure virtual on Component
