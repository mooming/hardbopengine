TaskStreamAffinityBase

Engine/Core/TaskStreamAffinity.h namespace hbe final which streams a piece of work may run on, as a bitmask stored inverted: a zero bit permits, a one bit excludes

Class description

template <unsigned int NumBits> class TaskStreamAffinityBase final at Engine/Core/TaskStreamAffinity.h: a bitmask of which task streams a piece of work may run on, one bit per stream index, densely packed — bit i lives in word i / 64 at shift i % 64. The engine uses the NumBits = 64 instantiation, aliased at namespace scope as TaskStreamAffinity, and embeds it in WorkItem, which is why the type's width is paid once per queued item.

The mask is stored inverted: a zero bit means permitted, a one bit means excluded. The names describe the permitted set, not the bits, so Unset(i) excludes stream i and Set(i) permits it again. The field's own label in the header says so — "Bit 0: set / Bit 1: unset" — and Get returns the inversion back: it answers true when the stored bit is 0. A reader who assumes one bit means one permitted stream will get this type exactly backwards, and every symptom of that is a task refusing the only stream it was allowed to run on.

One writer and one reader in the shipping engine, and they are one page apart. WorkItem::WorkItem() (Engine/Core/WorkItem.cpp) takes two streams away from every item it builds — the base stream and the IO stream, the two executors with no thread of their own — and TaskSystem::Dequeue() (Engine/Core/TaskSystem.cpp) consults the mask before lifting an item out of the general queue. 

affinity.Unset(TaskSystem::GetBaseTaskStreamIndex());
affinity.Unset(TaskSystem::GetIOTaskStreamIndex());

From Engine/Core/WorkItem.cpp, WorkItem::WorkItem()

A fresh mask is a fresh permission set: the constructor zeroes every word, so a default-constructed mask permits every in-range stream index, and narrowing it is the caller's first act. The width is pinned by a test in this module's collection (A mask reserves one word per 64 bits and not one per 8, Engine/Core/TaskStreamAffinity.cpp) because the type's previous encoding was internally consistent: its word count was derived from bytes per word where the division needed bits per word, which made the buffer eight times as long as it needed — 64 bytes for a 64-stream mask — while still behaving correctly.

The 64-bit instantiation is a ceiling the engine does not enforce. TaskStreamAffinity is TaskStreamAffinityBase<64>, while the stream count comes from TaskSystem::GetNumHardwareThreads() with no cap. On an engine with more than 64 streams, every index from 64 up is out of range for a work item's mask, and out of range Get answers "not permitted" — so the general queue would refuse such a stream permanently rather than admitting it. The template itself has no such limit (the tests instantiate 517 bits); it is the alias the engine uses that is 64 wide.
