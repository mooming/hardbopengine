Set

member of hbe::TaskStreamAffinityBase Engine/Core/TaskStreamAffinity.h despite the name, this gives a stream back: the bit is cleared, and a cleared bit means permitted

Signature

void Set(unsigned int bitIndex) noexcept

Function description

Defined in the header Engine/Core/TaskStreamAffinity.h as TaskStreamAffinityBase::Set(). Despite the name, this call gives a stream back — it clears the bit, and a zero bit is the encoding for "permitted". The pair to remember is: Unset excludes, Set permits. 

const auto index = GetBitsArrayIndexOf(bitIndex);
auto& value = bitBuffer[index];
const auto numShift = bitIndex - (index * BitsPerUnit);
TBitArrayUnit mask = 1;
mask = mask << numShift;
mask = ~mask;

value = value & mask;

From Engine/Core/TaskStreamAffinity.h, TaskStreamAffinityBase::Set()

The same in-range guard as Unset sits above this: an index at or above GetNumBits() returns immediately. That matters more here than it does for exclusion, because the one call site that would want to widen a mask past the range is the one that cannot.

Permission cannot be granted to a stream the mask does not address. TaskSystem::Dequeue() handles an affinity refusal by calling Set on the refusing stream's own index (Engine/Core/TaskSystem.cpp) — a no-op whenever that index is at or past 64, which is the width of the alias WorkItem embeds. On an engine with more than 64 streams, the general queue would answer those streams with Get = false forever.
The one shipping caller writes through a copy, so its permission is discarded. TaskSystem::Dequeue() takes the head item with TaskQueue::Top(), which returns std::optional<WorkItem> by value (Engine/Container/BoundedPriorityQueue.h), and the Set below is applied to that local copy — affinity is mutable, so it compiles and then evaporates with the optional when the function returns without popping. The item still queued at the head keeps its original mask, so the same stream and the same item do refuse each other again on the next pass. TaskSystem::Dequeue states the opposite ("the same item and stream cannot refuse each other twice"); the source is quoted here because the difference is observable — an excluded stream head-of-line blocks on that item until some permitted stream takes it. Reported to the reviewer rather than corrected from here.
