From Engine/Core/TaskStreamAffinity.h, TaskStreamAffinityBase::TaskStreamAffinityBase()

bitBuffer{0} writes 0 to the first word and value-initialises the rest, so every bit in the mask ends up 0. Because this type stores its mask inverted, that state is permitted on every stream in range — not "permitted nowhere", which is what a reader expecting a conventional bitmask would infer. The test Default Constructor (Engine/Core/TaskStreamAffinity.cpp) walks all 517 bits of a wide instantiation and fails if any of them reads false.

It is a user-provided constructor rather than = default, so the type is not trivially default-constructible (verified: std::is_trivially_default_constructible_v<hbe::TaskStreamAffinity> is false). It stays trivially copyable (verified true), and so does WorkItem, which embeds it — an item is still copied wholesale on every enqueue, re-add and lane sweep.

Narrowing a mask is always the caller's next call, never the constructor's job. The one place the engine narrows at construction does it explicitly, two lines after the member is built: WorkItem::WorkItem() takes the base stream and the IO stream away from every item (Engine/Core/WorkItem.cpp). A mask built anywhere else permits all 64 in-range streams until somebody says otherwise.

Parameters

None.

Return value

Constructors. No failure is possible: the object is a fixed array of words with nothing to acquire.

Examples

From Engine/Core/WorkItem.cpp, WorkItem::WorkItem()

affinity.Unset(TaskSystem::GetBaseTaskStreamIndex());
affinity.Unset(TaskSystem::GetIOTaskStreamIndex());

The item's affinity member is default-constructed with the rest of the item and then narrowed immediately: every queued item is barred from the two streams that have no thread of their own, and permitted on every worker stream the engine has (up to the mask's 64-bit limit).
