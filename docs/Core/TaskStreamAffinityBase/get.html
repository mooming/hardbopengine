Function description

From Engine/Core/TaskStreamAffinity.h, TaskStreamAffinityBase::Get()

The answer is permission: true means this stream may run the work. Two directions of the design are worth holding on to. A zero bit means permitted, so a fresh, untouched mask (constructor) answers true for every in-range index. And an out-of-range index answers false, which is the safe direction: the padding bits of a partially filled last word are unreachable, and their stored 0 — which this encoding would otherwise read as permission — can never become permission to run something.

An index that is not a stream index is refused for the same reason. TaskSystem::Dequeue() asks with GetCurrentStreamIndex(), whose "no stream" value (TaskSystem::NonStreamIndex) is negative and therefore far outside the mask — a thread that claimed no stream cannot take anything from the general queue. The relationship is asserted rather than assumed: static_assert(TaskSystem::NonStreamIndex >= TaskStreamAffinity::GetNumBits()); (Engine/Core/TaskSystem.cpp).
Permission to run is not permission to be honest about the queue. This is a one-bit answer with no history: it cannot say whether the stream was excluded deliberately, excluded by a caller whose index was out of range (Unset reports nothing), or simply never mentioned because the index is past GetNumBits(). The one place the shipping engine reads it is the guard in TaskSystem::Dequeue(), and what a refusal costs the queue is that class's contract, not this one.
