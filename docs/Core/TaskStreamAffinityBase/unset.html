Unset

member of hbe::TaskStreamAffinityBase Engine/Core/TaskStreamAffinity.h despite the name, this takes a stream away: the bit is set, and a set bit means excluded

Signature

void Unset(unsigned int bitIndex) noexcept

Function description

Defined in the header Engine/Core/TaskStreamAffinity.h as TaskStreamAffinityBase::Unset(). Despite the name, this call takes a stream away. The mask stores the excluded set, so writing a 1 into the bit means the stream is barred, and the name describes the permitted set rather than the operation on the bits. 

const auto index = GetBitsArrayIndexOf(bitIndex);
auto& value = bitBuffer[index];
const auto numShift = bitIndex - (index * BitsPerUnit);
TBitArrayUnit bit = 1;
bit = bit << numShift;

value = value | bit;

From Engine/Core/TaskStreamAffinity.h, TaskStreamAffinityBase::Unset()

The guard above the quoted block is the first thing in the function: an index at or above GetNumBits() returns immediately, changing nothing and reporting nothing. It is what keeps the padding bits of a partially filled last word out of reach — a bit at index 517 in a 517-bit mask cannot be excluded, because no such index exists, and the words' extra bits therefore never mean anything.

A silent return is the only answer a bad index gets. No assert, no log, no return value. Excluding stream NumBits or higher looks like a call that succeeded and did nothing, and the same is true of a mistyped constant: Unset(70) on the engine's 64-bit alias bars nothing at all, so work a caller believed confined to a subset of streams stays permitted on every stream in range.
Idempotent, and independent of every other bit. A second call on the same index changes nothing further, and the test Taking away one stream leaves every other stream alone (Engine/Core/TaskStreamAffinity.cpp) excludes each of seven probe indices — 0, 1, 63, 64, 127, 128 and 516 — on a 517-bit mask and then requires that no other index changed, which is the assertion that would catch two streams colliding on one bit.

Parameters

Examples

From Engine/Core/WorkItem.cpp, WorkItem::WorkItem()

affinity.Unset(TaskSystem::GetBaseTaskStreamIndex());
affinity.Unset(TaskSystem::GetIOTaskStreamIndex());

Every work item is barred from streams 0 and 1 — the base stream that rides the engine loop and the IO stream driven by the logger — while staying permitted on the worker streams. Read with the inverted encoding in mind, these two lines mean what they look like they mean; read as ordinary bit surgery they would mean the opposite.
