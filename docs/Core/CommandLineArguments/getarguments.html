GetArguments

member of hbe::CommandLineArguments Engine/Core/CommandLineArguments.h The argument container, read-only - and always empty, because nothing populates it.

Signature

[[nodiscard]] auto& GetArguments() const noexcept

Function description

Defined in the header Engine/Core/CommandLineArguments.h. Returns arguments by reference — and because the member function is const, the deduced auto& is a const Array<String>&, so a caller can read the arguments but cannot change or grow the container through this accessor.

The reference is always to an empty array, because nothing has ever been put into it. Parse walks argv and prints it; the only member function of the array it calls is nothing at all (Engine/Core/CommandLineArguments.cpp). So GetArguments().Size() is 0 for every instance that has ever existed, and the Print line that reports the count prints zero. The accessor is correct and complete; the population step is missing.
Handing out the container rather than a copy is both the cheapest and the only option. Array deletes its copy constructor and copy assignment (Engine/Container/Array.h), so a by-value accessor would not compile; and since the array is non-copyable, a caller that wants its own copy has to build one element by element. The reference stays valid for the object's life — the array is a member, not a temporary — and its elements are Strings, which are themselves reference-counted views.
