CommandLineArguments

member of hbe::CommandLineArguments Engine/Core/CommandLineArguments.h Default constructor deleted; the taking one forwards to Parse and stores nothing itself.

Signature

CommandLineArguments() = delete

CommandLineArguments(int argc, const char* argv[])

Function description

Two declarations, one page, because they are one decision: an instance exists only if a real command line made it. The default constructor is deleted in the header Engine/Core/CommandLineArguments.h; the taking constructor is defined in Engine/Core/CommandLineArguments.cpp and its whole body is Parse(argc, argv);.

The taking constructor stores nothing itself, and the function it calls stores nothing either — so a constructed object is empty whatever the command line was. Parse asserts argc > 0, echoes each argv entry to std::cout, and returns; it never assigns executablePath, never assigns executableFilename, and never appends to arguments (Engine/Core/CommandLineArguments.cpp). The three members therefore hold what their own default constructors give them: two empty Strings and an empty Array. The header's @brief — "Parses and stores command line arguments passed to the application" — describes an intention the body does not carry out (Engine/Core/CommandLineArguments.h).
Deleting the default constructor is what makes the empty object impossible to make by accident — which is the only guarantee this class gives. Every instance must name an argc and an argv, so a reader can at least tell where the (empty) contents came from. Note what is not deleted: the copy operations are implicit, and the Array member is non-copyable (Engine/Container/Array.h deletes both), so the implicit copy constructor and copy assignment of this class are defined as deleted. The class is final and movable in nothing but name — the array's move operations are what would decide that, and they are the array's own business.
Nothing in the engine or any application ever constructs one. No line in Engine/ or Applications/ mentions this class outside its own two files, so the engine's command line is not routed through it at all (Engine/Core/CommandLineArguments.h). That makes every statement on these five pages a reading of the source rather than an observation of behavior — including the echoing in Parse, which would print one line per argument if it ever ran.

Parameters

argcintArgument count, passed to Parse and asserted to be positive; not stored

Return value

None — a constructor. The object it produces reports an empty path, an empty filename and zero arguments, whatever was passed in.

Examples

There is no call site to quote. The shape the interface invites is CommandLineArguments(args, argc, argv)-style construction in an application entry point followed by Print — and the reason no such code appears here is that no such code exists in the tree (Engine/Core/CommandLineArguments.h).
