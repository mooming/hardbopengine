Reset

member of hbe::CPUBudget Engine/Core/CPUBudget.cpp Forgets everything charged and stops measuring; a window boundary falls between tasks.

Signature

void Reset() noexcept

Function description

Defined in Engine/Core/CPUBudget.cpp as CPUBudget::Reset(). 

accumulatedNanos.store(0, std::memory_order_relaxed);
isMeasuring = false;

From Engine/Core/CPUBudget.cpp, CPUBudget::Reset()

The allowance survives; only the spending is forgotten. After this call a stream whose allowance was fully spent permits work again, which is what makes a budget a rate rather than a lifetime quota — the test Reset restores the allowance spends a 2 ms allowance with 12 ms of busy work, requires the refusal, then requires both the acceptance and a zero accumulation after the reset (Engine/Core/CPUBudget.cpp).

It also stops measuring, and an in-flight charge is lost rather than deferred. Clearing isMeasuring means a later EndTask hits the guard and charges nothing, so a BeginTask that was open when the window moved contributes nothing to the new window. That is the accepted cost of a reset that must not be executed from another thread: the boundary falls between tasks, and a task straddling it is billed to neither window.
Only the owning thread calls this, and the window mechanism is built to keep it that way. TaskSystem::RunBudgetWindowPass() merely sets a per-stream flag (TaskStream::RequestWindowAdvance()), and TaskStream::Update() performs the reset on its own thread at the top of its next loop, paired with StreamDrainPolicy::EndRound() so the lane shares reopen on the same beat (Engine/Core/TaskSystem.cpp, Engine/Core/TaskStream.cpp). A reset executed on the pass thread would land between the owner's BeginTask and EndTask, costing either a lost charge or the thread's whole life billed to the budget (Engine/Core/TaskStream.h).

Parameters

None. The allowance is not a parameter here precisely because a window does not change what a stream is allowed to spend.

Return value

void. Nothing reports whether anything had been charged, and no callback tells the drain policy — the caller must pair the two resets itself.

Examples

From Engine/Core/TaskStream.cpp, TaskStream::Update()

if (windowAdvanceRequested.exchange(false, std::memory_order_relaxed))
{
    budget.Reset();

One exchange, one reset of both books, whichever thread asked for the window to move. The cadence comes from TaskSystem::RunBudgetWindowPass(), which advances at most once per time::GetBaseFramePeriod (Engine/Core/TaskSystem.cpp) — so a stream that is never scheduled keeps its spent budget until the base stream runs the pass again.
