CPUBudget

Engine/Core/CPUBudget.h One stream's allowance of measured CPU time, configured as a duration and spent as work runs.

Class description

class CPUBudget at Engine/Core/CPUBudget.h: one stream's allowance of measured CPU time, configured as a duration and spent as work runs. A stream asks CanTakeWork before it acquires anything and stops acquiring while the allowance is spent. Nothing is preempted — a task already running runs to completion, so a single long task overshoots the allowance by its own length, and that overshoot is bounded by the longest task rather than by the budget (Engine/Core/CPUBudget.h).

QuantityUnitWhose decision it encodes
Allowance — Configure, GetAllowancestd::chrono::duration<double>, secondsWhat a caller can put in a config file and reason about
Spending — BeginTask / EndTask, GetAccumulatedthe owning thread's CPU time, nanosecondsWhat the stream actually consumed, excluding time it spent blocked

The two are different quantities deliberately: a budget that charged wall time would bill a stream for work that was only ever blocked. The platform clock behind the measurement is clock_gettime(CLOCK_THREAD_CPUTIME_ID) on macOS and Linux and GetThreadTimes on Windows (Engine/OSAL/OSXThread.cpp, Engine/OSAL/LinuxThread.cpp, Engine/OSAL/WindowsThread.cpp), and the engine's own test of it is that 80 ms of sleep advances it by less than 20 ms (Thread CPU Time Ignores Sleeping, Engine/OSAL/OSThread.cpp).

Zero means unlimited, and that is the state every shipping stream is in. An allowance of zero is what a stream that has not been given a budget gets, so the primitive is inert until something configures it. Searching Engine/ and Applications/ for callers of TaskStream::ConfigureBudget and TaskStream::RequestBudget finds only the test app (Applications/EngineTest/TestMain.cpp) and the unit-test region of Engine/Core/TaskSystem.cpp — no engine configuration sets an allowance, so today this class measures and refuses nothing in a shipping build.
An unmeasured stream pays nothing for the budget, by design. A stream with no allowance does not call BeginTask or EndTask at all: a measurement that cannot change a decision is a syscall billed to every task for nothing, and an unlimited budget cannot change a decision. The consequence a reader must not misread is that TaskStream::GetAccumulatedCPUTime() stays zero until an allowance is set — that is the absence of accounting, not a task that cost nothing (Engine/Core/TaskStream.h, restated on GetAccumulated).
Not thread-safe for the things that matter, and the split is exact. A budget belongs to exactly one stream thread, which is the thread whose CPU time is charged; allowance, taskStart and isMeasuring are plain fields that only that thread touches. The two atomics are the deliberate exceptions: requestedAllowanceNanos carries a request from any thread to the owner, and accumulatedNanos is atomic because it is read for diagnosis from threads that do not own the budget. "That makes the read well-defined; it does not make BeginTask and EndTask portable to another thread" (Engine/Core/CPUBudget.h).
The gate goes in front of acquiring work and never in front of finishing it. Refusing to dequeue is the mechanism; refusing to finish work already in flight would turn a budget into a way to strand results. TaskStream::MayTakeNewWork() states the rule and its one shipping wiring: in front of the general queue, and not in front of a stream's own lanes, because a lane entry is either a task nobody has taken or one taken and paused before it finished, and refusing the lane would strand the second kind (Engine/Core/TaskStream.h).
A window is what makes a spent budget spendable again, and it is reopened by the owner. The base stream's pass calls TaskSystem::RunBudgetWindowPass(), which signals every stream (Engine/Core/TaskSystem.cpp); each stream then calls Reset on its own thread at the top of its next loop. A reset executed on another thread would land between that thread's BeginTask and EndTask, which is why the signal is a flag and not a call (Engine/Core/TaskStream.h).
