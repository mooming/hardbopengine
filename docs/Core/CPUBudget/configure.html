Configure

member of hbe::CPUBudget Engine/Core/CPUBudget.cpp Direct store of the allowance; legal only on the owning stream thread.

Signature

void Configure(std::chrono::duration<double> allowance) noexcept

Function description

Defined in Engine/Core/CPUBudget.cpp as CPUBudget::Configure(); the body is allowance = newAllowance;. A plain store to a plain field, which is the whole point and the whole hazard: the field is read once per pass by the owning stream in CanTakeWork, and nothing synchronises it.

Only the owning stream thread may call this, and the wrapper is where that is checked. TaskStream::ConfigureBudget() Asserts that the caller is the stream's own thread once the stream has a thread identity, and its message names the alternative: "Use RequestBudget, which the stream applies to itself" (Engine/Core/TaskStream.cpp). The assert exists only in configurations that define !RELEASE_BUILD, so outside a debug build a cross-thread call is simply a data race on a double duration.
Zero means unlimited; a negative figure behaves as unlimited but is not the stated way to ask for it. Unlike StreamDrainPolicy::ConfigureAllowance, which clamps a negative to zero on the way in, this stores what it is given — and CanTakeWork's first test is allowance.count() <= 0.0, so the difference is invisible in behaviour and visible in GetAllowance, which reports the negative back.

One pairing a caller must maintain itself: the drain policy divides the same allowance between the stream's two lanes, so TaskStream::ConfigureBudget() calls this and StreamDrainPolicy::ConfigureAllowance() with one figure. Configuring one without the other leaves a stream whose lanes are divided against a budget it no longer has.

Parameters

ParameterTypeRequirement
allowancestd::chrono::duration<double>CPU time this stream may spend per accounting window. Zero means unlimited. The yardstick is time::GetBaseFramePeriod, so a caller states CPU per frame period and leaves the arithmetic alone (Engine/Core/TaskStream.h)

Return value

void. Nothing reports that the allowance took effect, and nothing resets the accumulation — a stream raised from a spent allowance stays spent until its next Reset.
