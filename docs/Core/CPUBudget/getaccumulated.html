GetAccumulated

member of hbe::CPUBudget Engine/Core/CPUBudget.cpp CPU time charged since the last reset - the one figure any thread may read.

Signature

[[nodiscard]] std::chrono::nanoseconds GetAccumulated() const noexcept

Function description

Defined in Engine/Core/CPUBudget.cpp as CPUBudget::GetAccumulated(); the body is return std::chrono::nanoseconds{accumulatedNanos.load(std::memory_order_relaxed)};. The one figure on this budget that any thread may read, because the field behind it is atomic.

Well-defined does not mean current. The accumulation is written only by the owning stream thread, so a reader elsewhere sees the value as of the last task that thread finished — including the task in flight right now, which is not yet counted (Engine/Core/TaskStream.h, GetAccumulatedCPUTime). It is a diagnostic reading, not a lock on the budget.
Zero has two meanings and the counter cannot tell them apart. It is zero when nothing has been charged and when nothing has been measured: a stream with no allowance never calls BeginTask, so its accumulation stays at zero however much CPU its tasks consumed. Reading zero as "this stream is idle" is the mistake the header calls out by name.

Its in-class use is more interesting than its reporting use: TaskStream::Update() reads it before and after a run and charges the difference to the drain policy lane that produced the item, which turns a running total into a per-task figure without any per-task state (Engine/Core/TaskStream.cpp, and ChargeFifo on the receiving end).

The stream's public reporting hook, documented as readable from any thread. A caller comparing two reads to measure a task's cost must accept that a window Reset between them makes the difference negative — the reason the shipping caller brackets the read with its own budget check rather than subtracting across arbitrary points.
