From Engine/Core/CPUBudget.cpp, CPUBudget::ApplyRequestedAllowance()

One exchange does the whole hand-off: it takes the pending figure and clears the slot in the same operation, so a request cannot be applied twice and two concurrent appliers cannot both see it. The return tells the caller what changed, which is what makes the dependent update possible — the apply is not just a store, it is an event the stream can react to.

Call it only on the thread that owns this budget, because its last act is an ordinary store to allowance, the field the owner reads every pass. That is the reason RequestAllowance exists at all; calling this from the requesting thread would be exactly the data race the request path was built to avoid (Engine/Core/CPUBudget.h).
The return value is what keeps the drain policy honest. TaskStream::Update() does not re-read the allowance after applying it; it uses the returned figure to reconfigure the lane shares in the same breath, so a lane ratio is never computed against a figure the stream no longer has (Engine/Core/TaskStream.cpp). A caller that ignored the optional and called GetAllowance unconditionally would reconfigure the drain policy on every pass for no change.
The applied figure is what survived a nanosecond cast, not what was requested. The round trip duration<double> → nanoseconds → duration<double> truncates fractions of a nanosecond, so GetAllowance after an apply can differ from the duration passed to RequestAllowance in the last digits. The test A requested allowance is applied once by the owner and the latest request wins checks whole milliseconds for that reason (Engine/Core/CPUBudget.cpp).
