HasFinished

member of hbe::WorkItem Engine/Core/WorkItem.h constexpr-ready, noexcept whether this item consumed its whole index range — not whether its task is done

Signature

[[nodiscard]] bool HasFinished() const noexcept;

Function description

One comparison: current >= end. It answers a question about this item and says nothing about the task — a task split into four slices has three items that report finished while the join is still open, and one that closes it.

The stream uses it to decide whether a returned item goes back on the lane. A runnable may legitimately complete only part of its range; the item is then re-added to the lane it came from with current left where the run stopped, which is the behaviour the resume test exists to protect.

Parameters

None.

Return value

true when this item consumed its whole range. Not a statement about the task, its join, or its result.

It also returns true for an empty slice. A range where start == end satisfies current >= end at construction, which is why an empty split is refused at the point it is asked for rather than queued and counted as progress.

Example

if (item.HasFinished())
{
    queue.Push(item);       // nothing left of this slice
}
else
{
    lane.Push(item);          // same item, later start, same age and same notice
}
