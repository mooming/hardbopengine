WorkItem

Engine/Core/WorkItem.h namespace hbe class, final 72 bytes what a task stream queue actually holds: one task, one slice of its index range, and how much of that slice has run

Class description

A WorkItem is the queue element, not the unit of work. The unit is Task; this is one offer of one slice of that task, together with the progress cursor current that lets a runnable return part of its range and be re-added to the lane it came from. It is produced only by the engine — the constructor is private and Task and TaskStream are its only friends — and it is copied constantly: on every enqueue, on every re-add after an unfinished run, and on every sweep that moves work between lanes.

It replaced RangedTask, which was this data plus a copy of the task's name and measured 128 bytes. The name had exactly one reader: the warning issued when an item is dropped because its task was already released — and there the registry can no longer confirm the name belongs to the task that produced the ID, so the copy was both expensive and untrustworthy. TaskID is the identity that still means something at a drop site. See decidedWorkItemBytes, which exists to make any change to this width loud rather than silent.

The item is where the abandonment notice and the age clock live. Both are carried on the item rather than read back from the task because at the moments they matter the task is exactly what is missing: a dropped item's record may already be released, or reused by another tenant. Anything stored only on the task is unreachable precisely when it would be needed.

Template parameters

None. WorkItem is a concrete final class.

public TIndex start, end The half-open index range this offer covers. end is one past the last index, and the pair is why the item is not just {taskID, priority}
public mutable TIndex current One past the last index run so far. A runnable is allowed to return part of its range and the stream re-adds the item where it left off; a task whose runnable never finishes in one call is only correct because of this field
public FAbandonedNotice abandonedNotice Optional callback fired if this item is dropped without running; nullptr means nobody is listening. Copied like every other field, so an item re-added after a partial run and every slice of a split job keep the notice their task was offered with. Set through TaskSystem::SetAbandonedNotice
public void* abandonedUserData The requestor's context, passed through untouched. Its lifetime belongs to whoever set the notice and must outlive every drop this item can suffer; the engine never clears it
public std::chrono::nanoseconds offerTime The owning task's age clock, stamped when the registry loaded that task's record. Read only by a stream that configured a max age; with none configured it costs a load nobody performs. An item re-added after a partial run keeps the age it was offered with rather than becoming younger

Construction is private — WorkItem(Task&, TIndex, TIndex, uint8_t) — and reachable only through Task (which stamps the notice pair and the age clock from itself) and TaskStream. Copy assignment is defaulted, and there is deliberately no move special member: the type is a 72-byte value that is copied on every queue operation, and naming a move here would suggest the copies are an accident.

Non-member helpers

The header also declares FAAbandonedNotice, the function-pointer type the notice fields hold: 

using FAAbandonedNotice = void (*)(TaskID abandonedTask, void* userData) noexcept;

It is called on the thread that dropped the work, at most once per item, and never for work that ran. The callee must not block, must not take the task or stream lock, and must not look up the task record — that record is being dropped around this call, which is the entire reason the notice carries an ID rather than a pointer. Requests are made per task through TaskSystem::SetAbandonedNotice; nothing in this header offers a way to install one globally, because a default that notifies is a default that notifies for every task in the engine.
