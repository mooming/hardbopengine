operator-less

member of hbe::WorkItem Engine/Core/WorkItem.h noexcept the priority queue's ordering key: the insertion label, and nothing else

Signature

bool operator<(const WorkItem& other) const noexcept;

Function description

priority < other.priority and nothing else: a higher number is more urgent, and ties are left to the container's own order, which is oldest-first within a level. There is no task identity, no age and no stream in the comparison, so an item cannot become more urgent by waiting — aging, if a project ever wants it, is a decision made at the drain site and not here.

Parameters

ParameterMeaning
otherAnother item, compared only by its priority byte

Return value

true when this item is less urgent than other.

Consulted by one container, on one lane. This is the ordering key of BoundedPriorityQueue, which reads priority once at insertion and files the item in a bucket — the bucket index is the priority. The FIFO lane never calls this and never looks at the byte, so a caller who queued on FIFO and expected an ordering effect will see none.

Example

// Only ever used by the container; callers choose a lane instead:
taskSystem.EnqueueTask(stream, task, /*priority*/ 7, StreamDrainPolicy::ELane::Priority);
