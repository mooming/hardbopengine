True_t

Engine/Core/CommonUtil.h a type-level true: the empty class a compile-time trait names when the property it tests holds, so overload sets can branch on a type instead of on an if

Class description

True_t is an empty final class with no members of any kind. It carries no state and is never read; the only thing it does is have a name distinct from False_t, which is enough to make two overloads distinguishable. The pair plays the role a boolean template parameter would, with one advantage that the engine actually uses: because the tags are function parameters, the compiler resolves them by ordinary overload resolution rather than by if constexpr, so a class can give two real function bodies for the two cases instead of one body with a dead branch.

Nothing in this repository asks a question of True_t directly. The single producer is IsReferenceType, whose Result member is True_t for an lvalue reference and False_t otherwise, and whose TypeSize sizes the storage that decision implies. The single consumer is Optional, which writes Result() at each dispatch — a temporary of the tag type, passed by value and discarded — selecting between a reference branch and a value branch. Engine/Memory/Optional.h performs that dispatch sixteen times: in the copy constructor, the move constructor, the copy and move assignment, the destructor, Reset, both Value() accessors, and the private ConstructAt, CopyValue, MoveValue and Destroy overload pairs.

For the reference case the tag selects the branch that stores the referent's address and destroys nothing: ConstructAt(True_t, …) at Engine/Memory/Optional.h:183 writes a void* into the storage at Engine/Memory/Optional.h:192, GetValue(True_t) reads that pointer back and dereferences it at Engine/Memory/Optional.h:234, and Destroy(True_t) at Engine/Memory/Optional.h:264 only clears the hasValue flag, because ending a reference ends nothing. The paired False_t branches construct, assign and explicitly call the destructor instead.

A tag is a compile-time argument, not a runtime value. Reading a True_t object tells you nothing, because there is nothing to read. What matters is which overload the temporary's type selected at compile time; the temporary itself has no state to inspect, and writing one in a place that needs a runtime bool would silently discard the decision at the next brace.

Template parameters

None — True_t is not a template and is not parameterised on anything. It is the *result* of a template: IsReferenceType names it.

Class properties

None — there is no alias, no constant and no field in this class. The declaration is class True_t final { }; at Engine/Core/CommonUtil.h:9.

Class methods

None. No constructor, conversion, assignment or member function is declared, so the implicitly-declared defaults are what a caller gets, and all of them do nothing observable: a True_t copied, moved or destroyed is the same empty object before and after. The absence is the design — a member would give the tag a runtime value to be wrong about.

final closes the type against derivation. A subclass could not add behaviour worth having either: overload selection looks at the type written in the call, and any such subclass would be a different type, selecting a different — or no — overload.

Non-member helpers

None belong to this type. Engine/Core/CommonUtil.h also declares the namespace-scope functions GetAs, SetAs, CopyAs, ToAddress and CountOf, which have no relationship to the tag pair and are documented in Module functions.

What each selected branch actually does — the pointer store, the memcpy, the explicit destructor call — is Memory's contract, and the storage asymmetry named in IsReferenceType's hazard is a finding against that module rather than against this type
Usage outside the trait A grep of Engine/, Applications/ and Examples/ finds no other use of the name. The pair is not a general-purpose boolean vocabulary of this engine and no other trait produces it today, so a reader who reaches for True_t for a new trait is its first user
