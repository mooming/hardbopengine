GetAttachedCount

member of hbe::TaskProvider Engine/Core/TaskProvider.h How many streams this provider currently feeds.

Signature

[[nodiscard]] TStreamIndex GetAttachedCount() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskProvider.h; there is no counterpart in Engine/Core/TaskProvider.cpp. One read of the number of slots in use — streams, not lanes, since one stream attached on both lanes still counts once.

It counts recorded attachments, not registrations, and the two can differ. The number that decides whether this object may be destroyed is registeredCount, and RegisterOnStream moves it only when a real stream accepted the provider. A provider attached to an index the engine does not have reports a count here and a registration count of zero — the R37 distinction that keeps such a probe legal to destroy (Engine/Core/TaskProvider.h). Read this number as "how many streams I asked to feed", not as "how many streams hold my address".
No lock, because the class has none. The field is a plain TStreamIndex written by AttachTo and DetachFrom, so a read from another thread while either runs races it. The header's only thread-safety claim on this class is on IsStopRequested; everything else here, reads included, belongs to the owner's thread.
The tests read this rather than trusting a call's effect. Attaching one stream on two lanes must leave 1, attaching the same lane twice must leave 1, and filling the table must stop at MaxAttachedStreams (Engine/Core/TaskProvider.cpp) — each of those is a statement about the merge rule in AttachTo, observable nowhere else.

Parameters

None.

Return value

TypeWhat you get
TStreamIndex (int)Streams currently recorded as fed by this provider, from 0 to MaxAttachedStreams. It is not a count of streams that will actually ask, and it is not the figure the destructor asserts on

Examples

From Engine/Core/TaskProvider.cpp, TaskProviderTest

if (provider.GetAttachedCount() != 1)
{
    ls << "Attaching stream 3 on two lanes took " << provider.GetAttachedCount()
       << " slots, so one stream must not own two entries." << lferr;
}

The one-slot-per-stream rule pinned by a count rather than by reading the array, which is the only way the rule can be tested at all from outside the class (Engine/Core/TaskProvider.cpp).
