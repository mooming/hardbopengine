LaneBit

member of hbe::TaskProvider Engine/Core/TaskProvider.h Translate an ELane into the bit an attachment records, or zero for no lane.

Signature

[[nodiscard]] static constexpr std::uint8_t LaneBit(StreamDrainPolicy::ELane lane) noexcept

Function description

Declared and defined in the header Engine/Core/TaskProvider.h; there is no counterpart in Engine/Core/TaskProvider.cpp. A constexpr translation from the lane an ELane names to the bit an attachment records, and the only place the two encodings meet.

The bits are named explicitly rather than derived from ELane's values, and the header states the trap that bought that decision. "ELane::None occupies zero, so a positional encoding would give 'no lane' a bit of its own and a stream could match it" (Engine/Core/TaskProvider.h). A shift of 1 << static_cast<int>(lane) would compile, would look clever, and would make "no lane" attachable.
Zero is the answer that means "no lane", and it is a control value, not a mask. AttachTo tests this result first and refuses the attachment when it is zero, because an attachment with no lane "would sit in the slot and never be drained" (Engine/Core/TaskProvider.h). The fall-through that produces zero covers ELane::None and any value that is neither lane — so a cast of an out-of-range integer into ELane lands on the refusal path rather than on a lane.
It is a one-lane-at-a-time function, not a mask builder. A provider attached to both lanes of a stream ends up with both bits set because AttachTo ORs each call's bit into the mask — GetAttachedLanes then reports 3. There is no form that takes a mask, so a caller cannot attach both lanes in one call, which is deliberate: naming both lanes says this provider may be drawn on by either, and doubling the calls-per-drain has to be a decision rather than a default.

Parameters

ParameterTypeRequirement
laneStreamDrainPolicy::ELaneOne lane. None yields 0, which every caller treats as "do not attach"

Return value

Examples

From Engine/Core/TaskProvider.cpp, TaskProvider::AttachTo()

const std::uint8_t laneBit = LaneBit(lane);

if (laneBit == 0)
{
    auto log = Logger::Get(name);
    log.OutError([name = name, stream](auto& ls)
    {
        ls << "TaskProvider " << name.c_str() << " was attached to stream " << stream
           << " with no lane, so nothing was attached. An attachment with no lane sits in a slot that no"
           << " drain ever reads.";
    });
    return;
}

The refusal is reported rather than accepted because the symptom of a lost attachment is invisible: a stream that quietly never gets work, with no log line to connect it to the call that dropped it (Engine/Core/TaskProvider.h).
