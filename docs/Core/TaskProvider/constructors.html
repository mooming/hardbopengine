From Engine/Core/TaskProvider.cpp

Two members are initialised and nothing else happens: no allocation, no registration, no attachment. A constructed provider feeds no stream until AttachTo names one, which is what lets a provider be constructed before the engine exists — a property the header claims deliberately: "Taking it here rather than reaching for the engine instance keeps this type usable by code that constructs a provider before the engine exists, and keeps the unit probes able to attach to stream indices the engine does not have" (Engine/Core/TaskProvider.h).

The task system is held as a reference, so it is a lifetime obligation written into the type. A provider cannot be reseated onto another system, and a provider whose system has been destroyed is dangling in the one field that matters for RegisterOnStream and UnregisterFromStream. The constructor cannot check the relationship, because a reference to a live object is exactly what it cannot distinguish from a dead one.
Copying is deleted, and the reason is the registration list. TaskProvider(const TaskProvider&) and its assignment operator are = delete in the public section: a stream's lane list holds this object's address, so a copy would either duplicate a registration that names the original or silently produce a provider that feeds nothing while believing it feeds something. Identity here is the address, as GetHandle also assumes.
The parameter is named name in the header and providerName in the source, because the member and the argument would otherwise collide in the initialiser list. The header's spelling is the documented one: name and targetSystem. The name is copied into a StaticString, so the caller's buffer is not retained — and the name is what every report from this class prints, including the two failure lines that identify a producer that was lost (Engine/Core/TaskProvider.cpp).

Return value

Nothing. Construction allocates nothing and attaches nothing, so there is nothing to fail; a provider that cannot produce is one whose Produce reports none.

Examples

From Engine/Core/TaskProvider.cpp, TaskProviderTest

RecordingProvider provider("ProviderStopProbe", System());
provider.AttachTo(1, StreamDrainPolicy::ELane::Fifo);

Construction then attachment, in that order, is the only usable sequence: a provider built with a task system it never attaches to is a valid object that will never be asked anything, which is also the state RegisterOnStream reports when the named stream does not exist.
