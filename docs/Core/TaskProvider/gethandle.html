GetHandle

member of hbe::TaskProvider Engine/Core/TaskProvider.h A token that can request this provider's stop from code that was not given the provider.

Signature

[[nodiscard]] TaskHandle GetHandle() noexcept

Function description

Declared and defined in the header Engine/Core/TaskProvider.h; there is no counterpart in Engine/Core/TaskProvider.cpp. Wraps this object's address in the one token type that can ask a provider to stop, so a caller can hand out the ability to wind a producer down without handing out the producer.

What the token can do is exactly two things, and both are cheap. See TaskHandle: TaskHandle::RequestStop forwards to Stop, and TaskHandle::IsStopRequested forwards to IsStopRequested. It cannot detach, cannot cancel, and cannot create work — the handle is a wind-down signal with a read-back, which is all the provider contract offers (Engine/Core/TaskHandle.cpp).
The handle is a raw pointer with no lifetime claim, so it is only valid while the provider is. TaskHandle::GetProvider documents "No ownership - valid while the provider is", and nothing here registers or unregisters handles: a token outliving its provider is a dangling pointer whose two methods both dereference it (Engine/Core/TaskHandle.cpp). The safe pattern is to hand the handle to something that will finish before the provider is destroyed, and to obey the destruction rule with DetachAll rather than relying on a Debug-only assert.
It is not const, and that is load-bearing for the handle's purpose. Stop mutates the provider's atomic, so a handle built from a const provider would be a handle that could not do the one thing it exists for. A provider reached through a const reference can still be inspected with GetName and the attachment accessors, which are const (Engine/Core/TaskProvider.h).
Nothing mints handles except this call, and nothing tracks how many are outstanding. There is no registry of live handles, so a provider cannot see or wait for its token holders — meaning a stop request cannot be used to synchronise with code that holds one. What it does give is a value type small enough to store anywhere a request needs to outlive the caller's scope (Engine/Core/TaskHandle.cpp).

Parameters

None. The handle always names the provider it was taken from; there is no way to take a handle for another provider.

Return value

TypeWhat you get
TaskHandleA token holding this provider's address, never null — TaskHandle{} is the empty handle, and this function cannot produce one

Examples

Illustrative — no shipping code takes a handle yet, because no shipping code builds a provider either.

const auto handle = provider.GetHandle();
handle.RequestStop();

if (!provider.IsStopRequested())
{
    // A token holder's request failed to reach the provider it names.
}

Round trip through the token, which is the assertion the unit test makes directly on the provider instead (Engine/Core/TaskProvider.cpp): a request made through a handle is visible on the provider with no other involvement from the owner.
