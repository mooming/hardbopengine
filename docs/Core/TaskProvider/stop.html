Stop

member of hbe::TaskProvider Engine/Core/TaskProvider.h Request that this producer wind down; not cancellation, and the shipping drain does not yet read the flag.

Signature

void Stop() noexcept

Function description

Declared and defined in the header Engine/Core/TaskProvider.h; there is no counterpart in Engine/Core/TaskProvider.cpp. One release store of a flag that is never cleared — the entire mechanism, and it is worth being precise about what that buys.

The header's own framing is blunt about what this is not. "Stop is not cancellation. Tasks already taken run to completion - the task system cannot stop one - so 'stopped' means no further Produce calls, not no further work" (Engine/Core/TaskProvider.h). The unit of control in this design is the drain, and a task in flight has no stop input at all.
No shipping code reads the flag, so "no further Produce calls" is not what happens today. Searching Engine/ and Applications/ for readers of the flag finds only IsStopRequested itself and the handle that forwards to it; the drain path TaskStream::DrainProvidersLocked asks every provider on its lane whatever the flag says (Engine/Core/TaskStream.cpp). What a caller can rely on right now is therefore narrower than the contract: a stopped provider that checks its own flag can decline to produce, and code outside the engine can see the request. The stream will keep asking (Engine/Core/TaskProvider.h).
It removes nothing, so it is not a teardown step. The provider stays on the stream's lane list and stays registered; the destructor's R37 assert is unaffected, and calling this before destroying a provider satisfies nothing. DetachFrom is the call that removes the registration and waits for a drain in flight (Engine/Core/TaskProvider.h).
The flag is one-way and the class offers no reset. Nothing clears stopRequested — not AttachTo, not destruction of a successor, nothing — so a provider stopped once reports stopped forever, and a "resume" has to be a new provider object. That is a deliberate asymmetry: a request that can be withdrawn would need a second flag to distinguish it from a new request racing the withdrawal.
A release store with no paired value, because the flag carries no other data. The acquire in IsStopRequested is what makes a reader that sees true also see everything the requesting thread published before calling this — which is the only reason a provider that inspects its own flag inside Produce can act on state the requester set first.

Parameters

None. There is no reason string, no drain timeout, and no per-stream variant: the request is per provider, and every stream feeding it sees the same flag.

Return value

void. It cannot fail — there is no state to reject and no queue to notify — and it does not report whether anything was already stopped.

Examples

From Engine/Core/TaskHandle.cpp, TaskHandle::RequestStop()

if (provider != nullptr)
{
    provider->Stop();
}

The handle's forwarding is the whole call chain: a token holder asks, the provider records, and the answer is visible to anyone who asks afterwards. Which is also the shape of the gap — the last step of the promise, the stream ceasing to ask, is the step no shipping code performs (Engine/Core/TaskStream.cpp).
