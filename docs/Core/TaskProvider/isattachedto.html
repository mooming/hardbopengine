IsAttachedTo

member of hbe::TaskProvider Engine/Core/TaskProvider.cpp Whether a stream is currently draining this provider on any lane.

Signature

[[nodiscard]] bool IsAttachedTo(TStreamIndex stream) const noexcept

Function description

Defined in Engine/Core/TaskProvider.cpp as TaskProvider::IsAttachedTo(): a linear search of the slot list for one stream index, ignoring which lanes were named.

Any lane counts as attached. The mask is not consulted, so a stream attached on the priority lane alone answers true. For the lanes themselves, ask GetAttachedLanes — it returns the same mask this function searches for, and zero for the same "not found" (Engine/Core/TaskProvider.cpp).
"Attached" here means recorded, not accepted. A provider that named a stream the engine does not have, or that a full lane list refused, is attached by this answer and will never be asked anything (RegisterOnStream reports both). The drain does not consult this list at all — R38: "that registration - not this provider's slot list - is what the drain reads" (Engine/Core/TaskProvider.h).
It is the observable half of the attachment contract. Both the budget test and the stream-affinity test assert with it: "the provider attached only to the worker stream, so its work is budget-bound" (Engine/Core/TaskSystem.cpp). Since the tests attach to stream indices rather than to stream objects, an index-based predicate is the only way to state that claim at all.
No lock, and the same ownership rule as every other read here. The list is mutated unsynchronised by AttachTo and DetachFrom, so this predicate belongs to the owner's thread; the one member of this class that is safe from anywhere is the stop flag, read by IsStopRequested (Engine/Core/TaskProvider.h).
