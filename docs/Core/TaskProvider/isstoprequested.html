IsStopRequested

member of hbe::TaskProvider Engine/Core/TaskProvider.h Whether a stop has been requested; readable from any thread, and one-way.

Signature

[[nodiscard]] bool IsStopRequested() const noexcept

[[nodiscard]] bool IsStopRequested() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskProvider.h and marked there @threadsafe{any}@const{true}: the one member of this class that may be called from anywhere.

It is the read half of the only synchronised state a provider owns. An acquire load, paired with the release store in Stop, so a reader that sees true also sees what the requesting thread published first. Everything else on this object — the slot list, the lane masks, the counts — is unsynchronised and belongs to the owner's thread (Engine/Core/TaskProvider.h).
The intended reader is the provider itself. "Implementations may check it from inside Produce and return nullopt" (Engine/Core/TaskProvider.h) — which is the only mechanism that currently makes a stop request change behaviour, because the stream's drain does not consult the flag before asking (Stop documents the search that establishes this). A provider that does not check is asked forever.
It is also what a holder of a TaskHandle sees. TaskHandle::IsStopRequested forwards here, so the question "did anyone ask this producer to wind down?" is answerable by code that was never given the provider. That is the useful half of the feature today: the request is observable even though the drain does not act on it (Engine/Core/TaskHandle.cpp).
A stale-true is possible by design and a stale-false is not worth reasoning about. Once set, the flag never clears, so a true stays true. A false means only "not requested as of the load" — a stop that lands one instruction later is already in flight, so a caller must not read this as permission to skip calling Stop (Engine/Core/TaskProvider.h).

Return value

The test asserts the write/read pair rather than any effect on a drain, which is the honest scope of the feature: the flag is set, the flag is seen, and the question of who acts on it is still open in the shipping path (Engine/Core/TaskProvider.cpp).
