GetAttachedLanes

member of hbe::TaskProvider Engine/Core/TaskProvider.cpp The lane mask recorded for one stream, or zero when not attached to it.

Signature

[[nodiscard]] std::uint8_t GetAttachedLanes(TStreamIndex stream) const noexcept

Function description

Defined in Engine/Core/TaskProvider.cpp as TaskProvider::GetAttachedLanes(): the lane mask recorded for one stream, or zero when the provider is not attached to it.

The mask is cumulative, because AttachTo ORs each call's bit into it. Attaching the FIFO lane and then the priority lane yields LaneBitFifo | LaneBitPriority, and there is no way to take one lane back without DetachFrom, which drops the whole stream (Engine/Core/TaskProvider.cpp). A caller that needs "this lane only" cannot get it by detaching and re-attaching while a drain is live without accepting the gap in between.
Zero is doing two jobs, and they cannot be told apart. It is both "not attached to this stream" and the mask LaneBit returns for ELane::None — a value this class never stores, since AttachTo refuses a no-lane attachment before it reaches the array. Ask IsAttachedTo to separate the two cases (Engine/Core/TaskProvider.cpp).
The mask is bookkeeping on this side of the pair only. The stream keeps its own per-lane lists — up to MaxProvidersPerLane providers each — and the drain reads those. This mask says what the provider asked for; it does not say the stream accepted it, and RegisterOnStream reports a refusal rather than correcting it (Engine/Core/TaskProvider.h).
Two bits set means two registrations and up to two asks per drain pass — once for the FIFO lane's policy, once for the priority lane's. That doubling is the hazard the header says "has to be the caller's decision and never a default", and this accessor is the only way to see after the fact whether it was taken (Engine/Core/TaskProvider.h).
