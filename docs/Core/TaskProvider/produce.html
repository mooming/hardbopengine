Produce

member of hbe::TaskProvider Engine/Core/TaskProvider.h Pure virtual: hand the draining stream its next item, or report that there is none.

Signature

virtual std::optional<WorkItem> Produce(const TaskProduceContext& context) noexcept = 0

Function description

Pure virtual, declared in Engine/Core/TaskProvider.h: the whole producer interface, and the only way work enters a stream's lanes from outside that stream. The stream asks, the provider answers with an item or with nothing, and the answer ends the lane's drain for that pass.

Called on the draining stream's thread with that stream's queue lock held (R40), and the header draws three lines from that fact. "do not enqueue into that stream from here - EnqueueFifo/EnqueuePriority take the same non-recursive mutex and would deadlock; do not block; and do not touch another stream's queue" (Engine/Core/TaskProvider.h). What is expected is building a task (TaskSystem::CreateTask) and declaring its join (Task::ReserveSubTasks), "since the task registry has its own lock and takes it before the stream does nowhere".
Blocking here does not stall one stream politely — it holds a lock every producer of that queue is waiting on. The lock is the stream's queueLock, which TaskStream::EnqueueFifo and EnqueuePriority take from any thread that wants to put work on that stream (Engine/Core/TaskStream.cpp). An implementation that waits on anything — a latch, an allocator that might block, a subsystem lock held by a task that wants to enqueue — converts a local wait into a stalled producer path for the whole stream, and the deadlock case is the same call made back into the stream it was called from.
The answer decides the drain, and "nothing right now" is not an error and not a way to quit. "nullopt ends this lane's drain for the pass - the provider is asked again on a later pass, so reporting nothing is never a way to stop being asked (that is what Stop and DetachFrom are for)" (Engine/Core/TaskProvider.h). The cost of that design is one call per drain per provider, which is the price the class pays for having no HasWork predicate to go stale.
The stream asks its lane's providers in registration order and stops at the first item, so a provider that always has work hides the ones behind it. TaskStream::DrainProvidersLocked walks the list from the front and returns the first has_value() it gets (Engine/Core/TaskStream.cpp). There is no rotation and no round-robin cursor, so with the per-lane list holding up to eight providers, one permanently productive provider at the head means the seven behind it are asked only while it is refusing. Placement in the list is therefore scheduling, and nothing in the interface says where a provider will land.
Asking is itself budget-gated, and that gate is asserted rather than assumed (R39). TaskStream::Update() drains providers only for an empty lane, only when not shutting down, and only while budget.CanTakeWork() — with an Assert at the ask repeating the condition, because "a spent stream would otherwise keep manufacturing work it has no right to run" (Engine/Core/TaskStream.cpp). A provider therefore cannot starve itself by producing eagerly: the stream stops asking before the provider has to say no.
Hand back an item from Task::GenerateSubTask, and expect the stream to re-check the task. "An item naming a task that was released in between is dropped by the stream with the usual warning, so a provider cannot smuggle dead work past the liveness check" (Engine/Core/TaskProvider.h). The convenience that builds a correct item — index range, priority and reserved count agreeing with the task — is MakeWholeItem, kept protected so only providers can reach it.
Returning Stopped is not a way to be left alone. The flag a stop sets is not read by the shipping drain path (Stop records the detail), so an implementation that expects the asking to cease after a stop request will keep being asked. DetachFrom is the call that ends the asking, and it waits for a drain in flight rather than racing it.

The probe exists to make the interface observable rather than assumed: it records the stream index and the instant it was handed, and can be switched between "produced something" and "nothing right now". A real implementation's cheapest correct form is the same shape with the decision replaced by real state — and the header's requirement that an implementation "must be cheap enough to call when idle" is what keeps that shape small (Engine/Core/TaskProvider.h).
