TaskProvider

Engine/Core/TaskProvider.h A producer of tasks, and the unit of lifecycle in the task system: asked for work rather than pushing it, attached to stream lanes, and destructible only once no stream still holds its pointer.

Class description

class TaskProvider at Engine/Core/TaskProvider.h: a producer of tasks, and the unit of lifecycle in the task system. Apps, subsystems and tools are providers, and a provider is asked for work rather than pushing it: a stream drains a provider while the stream's budget lasts and Produce keeps reporting that it produced something. That makes the drain — not the individual task — the unit of control, which is the only unit available given that a task cannot be stopped once taken.

There is no HasWork predicate, and the header records why it was rejected. "By the time Produce runs, a HasWork answer is already advisory because provider state can change in between, so the stream would be steering on a reading it cannot trust" (Engine/Core/TaskProvider.h). The single question is asked at the moment of consequence: Produce returns an item or reports that there is none, and reporting none ends this lane's drain for the pass at the cost of one call per drain thereafter.

A provider that outlives its registration is a dead pointer in a lane list, and the destructor exists to catch it. "R37: a stream holds this object's pointer, so destroying a provider that still feeds one leaves a dead pointer in that lane's list. Detach first." The assert counts registrations, not recorded attachments: an attachment naming a stream the engine does not have puts nothing anywhere, so it cannot dangle and must not be fatal. A destructor assert cannot see a drain in progress, which is why DetachFrom and DetachAll take the target stream's lock rather than clearing flags here (Engine/Core/TaskProvider.h).
The stop flag has no reader in the shipping drain path. The contract is stated plainly: "Stop is not cancellation. Tasks already taken run to completion - the task system cannot stop one - so 'stopped' means no further Produce calls, not no further work" (Engine/Core/TaskProvider.h). In Engine/ and Applications/ nothing outside this class reads the flag: TaskStream::DrainProvidersLocked asks every provider on the lane whatever the flag says (Engine/Core/TaskStream.cpp). See Stop for what a caller can rely on today.
The mechanism is complete and has no shipping user. The only TaskProvider derived class in the repository is a test probe, and every AttachTo call site sits in a unit-test region (Engine/Core/TaskSystem.cpp, Engine/Core/TaskProvider.cpp). The stream side is wired and gated — provider asks are the one path the CPU budget explicitly forbids while spent (R39, Engine/Core/TaskStream.cpp) — but nothing in a shipping build attaches a producer.
Attachment is a lifecycle event on the owner's thread. The provider's own arrays have no lock, so AttachTo, DetachFrom, DetachAll and the const reporting reads are written to be driven by one owner. What makes detaching safe against a concurrent drain is not a lock on this object but the target stream's queue lock, taken per lane inside UnregisterFromStream.
