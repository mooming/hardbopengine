GetName

member of hbe::TaskProvider Engine/Core/TaskProvider.h The name given at construction, returned by value.

Signature

[[nodiscard]] StaticString GetName() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskProvider.h; there is no counterpart in Engine/Core/TaskProvider.cpp. Returns the name given at construction, by value.

By value, because a reference would outlive nothing useful. The name was copied into the member at construction, so a returned StaticString is safe to keep across a provider's destruction — unlike a reference into the provider, and unlike the caller's original buffer, which this class never retains (TaskProvider).
The name exists because the failure reports have to identify a producer that is already gone. Both failure paths print it. A lane list that would not take the provider reports, as an error, "TaskProvider name could not register on stream N. The lane list already holds this provider or is full, so the drain will not ask it."; a stream the engine does not have reports the same opening as a warning, "The attachment is recorded and nothing will ever ask this provider for work." (Engine/Core/TaskProvider.cpp). Attachment is recorded before registration is attempted, so this is the only record of an attachment that silently went nowhere — and a provider that never produced anything is otherwise impossible to attribute.
It is the same string the assert messages carry — the R37 destructor assert, the over-capacity assert, and GetAttachedStream's range assert all lead with name (Engine/Core/TaskProvider.cpp). A provider built with an empty name is therefore harder to find in a log than one built with a real one, and nothing warns about the empty case at construction.

Parameters

None.

Return value

TypeWhat you get
StaticStringA copy of the construction-time name, never empty unless constructed empty; immutable for the provider's life

Examples

From Engine/Core/TaskProvider.cpp, TaskProviderTest

RecordingProvider provider("ProviderStopProbe", System());

The construction site is the only place a provider's name is chosen, and the string chosen there is what every log line about this producer will print (Engine/Core/TaskProvider.cpp). A test double named for what it probes is how the failure lines stay readable when several providers are attached in one test.
