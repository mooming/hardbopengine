TaskID

Engine/Core/TaskID.h namespace hbe final identity of a tracked task: which registry record holds it, and which turn of that record it was issued for

Class description

struct TaskID final at Engine/Core/TaskID.h: which registry record holds a task, and which turn of that record this identity was issued for. It replaces what used to be a reference into the task's memory. A work item that held a reference could be run against — or dropped onto — whatever task later occupied that address; an index plus generation turns that into a checkable claim: the index says which record to look at, the generation says whether that record is still the one the ID named when it was issued. A packet naming a dead task is recognised and dropped rather than followed (R7, docs/TaskSystemRedesign.md).

Every live ID is minted in one function, TaskRegistry::Create() in Engine/Core/TaskRegistry.cpp: it takes a free record, adds one to that record's stored generation, loads the task into the record under the new identity, and returns the pair. 

const TaskID::TGeneration generation = record.generation.load(std::memory_order::relaxed) + 1;
record.generation.store(generation, std::memory_order::relaxed);
record.successor = {};
record.task.LoadIntoRecord(TaskID{recordIndex, generation}, taskName, func, userData);
record.inUse.store(true, std::memory_order::release);
usedRecords.fetch_add(1, std::memory_order::relaxed);

return TaskID{recordIndex, generation};

From Engine/Core/TaskRegistry.cpp, TaskRegistry::Create()

A default-constructed ID refers to nothing (index = NullIndex), and a refusal is reported the same way: when no record is free, TaskRegistry::Create() logs and return {};. One predicate — IsNull — therefore covers both cases, and the engine relies on it: TaskSystem::DispatchSuccessor() in Engine/Core/TaskSystem.cpp ends routing on a null successor ID.

The generation is 32 bits deliberately. A stale ID can only alias a live task after the very same record has been reused four billion times, which no run reaches. A 16-bit generation would make aliasing an everyday hazard in a table of thousands of records and defeat the reason a generation is carried at all.
Equality compares both halves. Two IDs naming the same record at different generations are different tasks. An ID wrapper that ignores the generation to "just get the task" reintroduces exactly the defect this type exists to close; the defaulted operator== cannot be talked into half a comparison, and a hand-rolled index-only comparison is the way to lose that protection.
Nothing in the type stops a hand-written ID. TaskID is an aggregate whose two members are public data — that is how TaskRegistry::Create() builds one with TaskID{recordIndex, generation} — so no constructor enforces that an ID came from the registry. A fabricated ID is caught the same way a stale one is: TaskRegistry::Find() answers nullptr unless the record is live and its generation matches. Hand-writing an ID is therefore never a way past the registry, but it is also never reported as a mistake, and a pair copied out of a log line is indistinguishable from an ID that was issued.
