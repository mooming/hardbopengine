IsNull

member of hbe::TaskID Engine/Core/TaskID.h whether this ID names no task at all — the shared guard for default-constructed IDs and refused creations

Signature

[[nodiscard]] constexpr bool IsNull() const noexcept

Function description

Defined in the header Engine/Core/TaskID.h as TaskID::IsNull(); there is no out-of-line body, so a call is a comparison the caller can fold. It tests one thing: index == NullIndex. The generation is not consulted — an ID naming record NullIndex at any generation names no task, and every ID with a real index names a record whether or not that record is still the one the ID was issued for. Liveness is the registry's question, not this type's.

Two sources produce a null ID and this predicate is the shared guard for both: the default-constructed TaskID, whose in-class initialiser sets index = NullIndex, and the return {}; of a refused TaskSystem::CreateTask — which is what TaskRegistry::Create() does when the free list is empty. Because one test covers both, a call site that takes an ID needs no separate sentinel and no separate failure flag.

Parameters

None.

Return value

true when this ID names no record at all. false does not prove the task is still alive — only that the ID claims a record. Liveness is what TaskSystem::FindTask answers.

Examples

From Engine/Core/TaskSystem.cpp, TaskSystem::DispatchSuccessor()

const TaskID successorID = taskRegistry.GetSuccessor(finishedTask);
if (successorID.IsNull())
{
    return;
}

A task with no successor holds a default-constructed ID — TaskRegistry::Create() clears record.successor to {} when it issues a record, and TaskRegistry::SetSuccessor() is the only writer — so one null test ends the routing path. The probe in Engine/Core/TaskProvider.cpp (DrainingProvider::Produce()) guards a freshly created ID the same way before building a work item for it.
