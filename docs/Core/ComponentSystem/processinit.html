ProcessInit

member of hbe::ComponentSystem Engine/Core/ComponentSystem.h Private: start every waiting component - Init, ALIVE, OnEnable, onto the update list.

Signature

void ProcessInit()

Function description

Private, defined in the header Engine/Core/ComponentSystem.h; reached only from the first phase of Update. It consumes the init list in one go: for each component waiting there, it calls Init, sets the state to ALIVE, calls OnEnable, and moves the component onto the update list. Then the init list is cleared.

This is where the lifecycle's ordering promises are actually made. A component's Init is the only callback it ever sees with the state BORN, because the state is written after Init returns and before OnEnable is called (Engine/Core/ComponentSystem.h). The repository's subclass depends on exactly that, at every callback entry, and its destructor fails the test if any of the four callbacks was missed (Engine/Core/ComponentSystem.cpp).
Everything in the init list is started in the pass that reaches this, with no budget and no limit. The loop has no cap, so a system given ten thousand components by Create calls ten thousand Init bodies — on the calling thread, inside the same call that then updates every one of them and runs the transitions (Update). The test does this with 4096×5 components in non-Debug builds (Engine/Core/ComponentSystem.cpp), so the behavior is measured rather than hypothetical: a system's hitch at first pump is proportional to how much was created since the last pump.
The components leave this function at a different address than they entered it. They are moved onto the update list, and the vector they came from is cleared, so a reference handed out by Create is dead by the time Update returns — and the update list itself reallocates as it grows, since it is an HVector, that is, a std::vector on the engine's allocator (Engine/HSTL/HVector.h). A component's own address must never be the way it is found again (Component::Update).

Parameters

None.

Return value

void. No count of what was started; a caller that wants to know whether the init list had anything in it must ask before the call, since this leaves the list empty whatever happened.

Examples

for (auto& compo : initList)
{
    compo.Init();
    compo.SetState(ComponentState::ALIVE);
    compo.OnEnable();
    updateList.push_back(std::move(compo));
}

initList.clear();

From Engine/Core/ComponentSystem.h, ComponentSystem::ProcessInit()

The three statements in their only order. Note that the component is moved into the update list and then the source list is cleared — the objects in the init list are moved-from shells at the end of this function, which is what the isValid flag in the test's destructor exists to survive (Engine/Core/ComponentSystem.cpp).
