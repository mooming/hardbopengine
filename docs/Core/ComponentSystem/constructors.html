ComponentSystem

member of hbe::ComponentSystem Engine/Core/ComponentSystem.h Names the system and leaves all five lists empty; the name cannot be given later.

Signature

		: name(name)
		, initList()
		, updateList()
		, swapUpdateList()
		, sleepList()
		, transitionList()

Function description

Defined in the header Engine/Core/ComponentSystem.h; Engine/Core/ComponentSystem.cpp contains no definition of it — the whole template, including this constructor, lives in the header. It stores the system's name and leaves all five lists empty, which means a freshly built system converts to false and its Update does nothing.

The name is the only state this class owns outright, and it is the one the engine reports. The five HVectors are default-constructed in the initializer list even though the default constructor would do that by itself — the list is a declaration of intent, and the effect is the same. Unlike the component's name, which nothing reads, this one is the label a system is identified by from outside (GetName).
There is no default constructor, so a system cannot be a member that is named later. The only constructor takes a name and is not explicit, so a const char* converts to a system wherever one is expected — a hazard for aggregate or brace-initialization contexts, and the reason the repository constructs it explicitly: 
ComponentSystem<Test> testSystem("TestSystem");

The template argument is the concrete component type, stored by value, not a pointer and not the Component base (Engine/Core/ComponentSystem.h).

None — a constructor. The constructed system is empty: every list default-constructed, and the conversion to bool therefore false.

Components are then added through Create, which forwards its arguments to the component's constructor and puts the result in the init list. A system is a value: nothing in the engine allocates one, and Test — the component type it is parameterized on — is a local struct inside the test lambda (Engine/Core/ComponentSystem.cpp).
