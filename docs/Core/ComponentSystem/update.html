Update

member of hbe::ComponentSystem Engine/Core/ComponentSystem.h The whole pump: init, then update, then transition, in one call.

Signature

void Update(const float deltaTime)

Function description

Defined in the header Engine/Core/ComponentSystem.h; no definition in Engine/Core/ComponentSystem.cpp. The whole pump, in three fixed phases, and the only public way to make a component system do anything: 

ProcessInit();
ProcessUpdate(deltaTime);
ProcessTransition();

From Engine/Core/ComponentSystem.h, ComponentSystem::Update()

That order is the lifecycle contract of the entire module. A component created before this call is added, initialised, enabled and updated in this one call (ProcessInit hands its results to ProcessUpdate's list), and a component that retires itself during its update is disabled, released and destroyed before this call returns (ProcessTransition). Nothing is deferred to a later pass, and nothing here can be reordered without changing what a component is allowed to assume about its own state (the lifecycle table).

One thread runs all three phases, and that thread owns every component's state. Every callback and every list mutation happens inside this call, so the component that runs is decided here and nowhere else (Engine/Core/ComponentSystem.h). Nothing takes a lock — the class has none — which makes this the single-thread contract of the module: call it from one thread, and do not touch a component from another while it runs. The system itself has no guard against being called concurrently.
On a system whose components have all gone to sleep, this call does nothing and returns — forever. All three phases iterate lists that are empty in that situation, while the sleep list — which no phase reads — keeps the system non-empty (the conversion to bool). A driver written as while (system) { system.Update(dt); } is therefore correct only for components that always end in Destroy, which is exactly the set the repository's test uses, and it spins without bound for a component that parks itself with SetEnable(false) (Engine/Core/ComponentSystem.h).
Not noexcept, and an escaping exception stops the phase mid-list. The three Process* functions are not noexcept either, and each phase clears its list only after the loop over it finishes (Engine/Core/ComponentSystem.h). A component whose Init throws leaves the rest of the init list unprocessed and un-cleared — so the same component would be initialised again on the next call. The engine's own convention is that exceptions do not escape a callback; this class does nothing to enforce it.

Parameters

NameTypeMeaning
deltaTimeconst floatPassed verbatim to every component's Update. This class never measures time, never clamps it, and never looks at it; the repository's driver supplies a constant 0.033f

Return value

void. Nothing reports how many components ran, how many were initialised, how many died, or whether the system has anything left — a caller that wants to know whether to keep pumping asks the conversion to bool, with the limitation recorded there.

The whole of the engine's use of this class: thousands of components created, then driven to empty and timed, which is also how the lifecycle is verified — every component's callbacks record what state they saw, and the destructor fails the test if a component was destroyed without having seen all four of them (Engine/Core/ComponentSystem.cpp).
