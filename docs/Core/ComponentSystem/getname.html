GetName

member of hbe::ComponentSystem Engine/Core/ComponentSystem.h The system's name as a C string, owned by the system.

Signature

[[nodiscard]] inline const char* GetName() const noexcept

Function description

Defined in the header Engine/Core/ComponentSystem.h, and the only member of the class marked inline explicitly — every other body is inline by virtue of living in the class, since the whole class is a template. Returns the name handed to the constructor, as a C string.

It converts on the way out, and the pointer it hands back belongs to the system. The body is return name.ToCharArray(); — the stored hbe::String is asked for its character buffer (Engine/String/String.h). The pointer stays valid while the system is alive and while its name is unchanged, which for this class is the same thing: nothing writes name after the constructor. It is not a copy, so it must not outlive the system — and it is not a view into any component, whose name is a separate field (Component::GetName, which returns a String reference rather than a C string).
Nothing in the engine asks a component system its name. No call site in Engine/ or Applications/ reads it, and the class itself never logs, so there is no diagnostic in the tree that would show it. It is the accessor a report would use, alongside Component::GetName, which shares the same silence (Engine/Core/ComponentSystem.h).

Parameters

None.

Return value

TypeWhat it tells the caller
const char*The name as a NUL-terminated C string, owned by the system's String. Never null for a system built by this class's only constructor, which cannot be given a default name; it becomes dangling when the system is destroyed
