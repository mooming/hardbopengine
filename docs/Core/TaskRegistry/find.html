From Engine/Core/TaskRegistry.cpp

Three acquire loads, each answering a different question, and no lock anywhere. The bank bound is what makes the pointer arithmetic safe: AllocateBank fills a bank and then publishes bankCount with release semantics, so a reader that acquires a count covering that bank is guaranteed to see the bank's contents. The generation compare is what makes a recycled record read as absent rather than as someone else's task — the case the identity exists to catch.

Three different histories share one answer, and the caller cannot tell them apart. Nullptr means the index was never issued, the task has been released, or the record has been re-issued to another task (Engine/Core/TaskRegistry.h). That is deliberate — none of the three entitles a caller to touch a task — but it means a null from this call is not evidence about which happened, and a diagnostic that needs to know must ask GetCount or look at the release path's own log.
The pointer is valid memory for the life of the registry, and it is not a lease. "If the task is released on another thread while it is being read, the fields read are whatever they held, not a guarantee about what they say" (Engine/Core/TaskRegistry.h). The record's memory is never freed or moved while the registry lives — that is what banks buy — so a dereference cannot fault; what it can do is report a task that was released mid-read, or one that was re-issued mid-read, because the release and re-issue paths only publish inUse and the generation and leave the task's own fields alone.
recordsPerBank is read here without synchronisation, and that is safe only while it does not change. The divisor decides which bank an index lives in, so a lookup in flight during a Initialize that changed the grow-by would compute a different bank than the one the index was issued against. This is the same hazard Grow documents as "legal only while no lookup is in flight", and it is why sizing belongs between frames on the owner rather than on a task path.
