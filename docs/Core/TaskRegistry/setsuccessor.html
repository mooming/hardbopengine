Defined in Engine/Core/TaskRegistry.cpp as TaskRegistry::SetSuccessor(): resolve the record, or log and give up, then store the successor.

From Engine/Core/TaskRegistry.cpp (the elided block is the error log quoted below)

This field is the entirety of what the task system knows about chains — "a job, an optional successor, and a join counter" (R9). Where the successor runs is not stored here: the completing task writes a destination byte into its own result packet, and TaskSystem::DispatchSuccessor reads that, so routing stays data the registry carries rather than a pipeline the engine has to understand (Engine/Core/TaskRegistry.h).

It takes no lock, and successor is not atomic. The record is reached through FindLiveRecord, which reads its flags relaxed and takes no lock, and what follows is a plain store to a 16-byte TaskID. Create writes the same field under registryLock, so a successor recorded on one thread while another thread's Create recycles that record is an unguarded concurrent write (Engine/Core/TaskRegistry.cpp). The safe pattern in the engine is the one already in use: set the chain at creation time, from the thread that holds both identities — which is what TaskSystem's split path does, recording the successor and the destination byte together (Engine/Core/TaskSystem.cpp).
A successor is a promise about the future, not a lease. "It is dispatched when the join closes, and if it has been released by then the dispatch is refused and logged rather than run" (Engine/Core/TaskRegistry.h). Nothing here checks that successor names a live task, and nothing keeps it alive — recording an ID that will be released by the time the join closes is accepted at this line and discovered at dispatch.
Naming a task that is not tracked does nothing and is reported. The error names the registry, the index and the generation, and states the consequence a reader needs: "so nothing will be dispatched when that join closes" (Engine/Core/TaskRegistry.cpp). Same rule as Release — an untracked identity is never silently accepted.

Parameters

Return value

void. No indication whether the record was found, so a caller cannot distinguish "recorded" from "logged and dropped" except by reading the log or asking GetSuccessor afterwards.

The pairing that makes a chain deliverable: recording the successor here is meaningless unless the completing task also names where the result goes, and a chain that closes without a destination is the error DispatchSuccessor logs — a chain that stops with no symptom until something downstream waits.
