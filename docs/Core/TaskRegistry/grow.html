Grow

member of hbe::TaskRegistry Engine/Core/TaskRegistry.cpp Adds one bank; false when a ceiling or MaxBanks refuses it.

Signature

[[nodiscard]] bool Grow() noexcept

Function description

Defined in Engine/Core/TaskRegistry.cpp as TaskRegistry::Grow(); the body is one locked call into the bank allocator. 

std::scoped_lock<std::mutex> lock(registryLock);
return AllocateBank() != nullptr;

From Engine/Core/TaskRegistry.cpp

Exactly one bank, never more, and never by accident: AllocateBank refuses on two ceilings — the configured max capacity and the fixed MaxBanks size of the bank table — and a caller that needs N records calls this N times. Growth is a decision made where memory may be taken rather than a policy that springs into action when the table is full, because Create deliberately never grows.

"Legal only while no lookup is in flight" — and the reason is arithmetic, not locking. The class note is explicit: growth is for "between frames on whoever owns the registry. Nothing grows it from a task: an allocation that lands on the path a task runs makes the task, and not the caller, pay for a table it had no part in sizing" (Engine/Core/TaskRegistry.h). The bank publication itself is safe against a concurrent Find — the bank's records are constructed before bankCount is released — but the allocation is a megabyte, and the free-list head is rewritten under a lock the lookup path does not take.
The cost is 1 MiB at the default grow-by, and it is paid in one allocation. recordsPerBank * sizeof(Record) = 4096 × 256 bytes, taken from bankAllocatorID — the allocator chosen at Initialize, not the ambient one. A caller sizing a registry is pricing banks, not records: this is the call where the abstract capacity becomes a number of megabytes.
A refusal is reported by ReportRefusedGrowth and leaves the table untouched. The log names the capacity requested, the capacity held, the ceiling (0 meaning none) and the bank limit (Engine/Core/TaskRegistry.cpp) — the three numbers that decide whether the answer is "raise the ceiling" or "this table is finished". The return value is the only programmatic signal, and [[nodiscard]] is what the engine has for a growth failure policy: whoever asked decides what to do.

Parameters

None. There is no requested-size form: a grow-by is fixed by Initialize, which keeps every bank identical and the index arithmetic trivial.

Return value

TypeWhat you get
booltrue when the table now holds GetGrowBy more records; false when a ceiling, the bank limit, or the allocator refused — in every one of those cases the capacity is exactly what it was

Examples

From Engine/Core/TaskRegistry.cpp, TaskRegistryTest

registry.Initialize("PacketTest", 8, 4);

The tests reach growth through Initialize, which allocates the same AllocateBank in a loop — so the bank- refusal paths that this call shares with it are exercised through the ceiling constants rather than through a shipping caller. In the engine, no code calls this at all: the registry is sized once, and a full table is a configuration bug reported by ReportNoRoom.
