ReportRefusedGrowth

member of hbe::TaskRegistry Engine/Core/TaskRegistry.cpp The error line for a refused bank, naming the ceiling and the bank limit.

Signature

void ReportRefusedGrowth(std::size_t requestedCapacity) noexcept

Function description

Defined in Engine/Core/TaskRegistry.cpp as TaskRegistry::ReportRefusedGrowth(). Private, and called from the two rejection branches of AllocateBank — the bank-table limit and the configured ceiling. An allocator failure is reported by a different line, so this one always means "a limit said no", never "memory ran out". 

auto log = Logger::Get(name);
log.OutError([name = name, requestedCapacity, capacity = GetCapacity(), maxCapacity = maxCapacityRecords,
              banks = MaxBanks](auto& ls)
{
    ls << name.c_str() << " could not grow to " << requestedCapacity << " task records; it holds " << capacity
       << ". The ceiling is " << (maxCapacity == 0 ? 0 : maxCapacity)
       << " records, where 0 means no ceiling, and the bank table holds at most " << banks << " banks. ";
});

From Engine/Core/TaskRegistry.cpp

requestedCapacity is what the next bank would have totalled — (bankIndex + 1) * recordsPerBank, computed at the call site — which is what makes the two numbers comparable: the capacity wanted and the capacity held. The ceiling and the bank limit are printed with it because they have different fixes: raise the ceiling, or accept that this table is at its structural limit of MaxBanks banks.

Which branch reached this is visible in the numbers, not in the wording. If the ceiling is non-zero and requestedCapacity exceeds it, the ceiling refused; if the ceiling is zero, the bank table refused. Both branches leave the registry exactly as it was, and both return nullptr so Grow can answer false (Engine/Core/TaskRegistry.cpp).
This line can also arrive from Initialize, where no caller is checking a return value. The initial-allocation loop breaks at the first failed bank and logs only the capacity it achieved, so a registry that came up short because a ceiling refused its own initial banks is reported here — and then, by the next line of that function, as a successful initialisation at the smaller size. Reading the two together is how a short table is recognised as a sizing mistake rather than a mystery.
Distinct from ReportNoRoom, and the difference is the action. This says growth was refused; that one says a task went untracked. A table can hit either: a ceiling of 8192 with 4096 records live triggers this line on the Grow and the other on the next Create.

Examples

Checked before the allocation rather than after, so a capped registry never takes a megabyte bank it must hand straight back — and reported from inside registryLock, which is why the ceiling it prints is the same value the check used (Engine/Core/TaskRegistry.cpp).
