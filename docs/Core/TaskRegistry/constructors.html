TaskRegistry

member of hbe::TaskRegistry Engine/Core/TaskRegistry.cpp Builds an empty registry that takes no memory; Initialize gives it records.

Signature

TaskRegistry() noexcept

TaskRegistry(const TaskRegistry&) = delete

Function description

Defined in Engine/Core/TaskRegistry.cpp as TaskRegistry::TaskRegistry(). It initialiser-lists everything that has a value worth establishing and zeroes the bank table in the body: 

: name("None")
, bankCount(0)
, recordsPerBank(DefaultGrowByRecords)
, maxCapacityRecords(DefaultMaxCapacityRecords)
, freeRecordHead(TaskID::NullIndex)
, usedRecords(0)
, bankAllocatorID(MemoryManager::GetCurrentAllocatorID())
{
    for (auto& bank : banks)
    {
        bank = nullptr;
    }
}

From Engine/Core/TaskRegistry.cpp

No bank is allocated, so a default-constructed registry costs nothing but its own inline state — the 1024-entry pointer table and the mutex. freeRecordHead starts at TaskID::NullIndex, which is the free chain's "no records" marker, so Create on an uninitialised registry refuses immediately rather than dereferencing a null bank.

Construction and sizing are separate on purpose. "A registry lives inside the task system, which is itself default-constructed and sized later, and because the allocator the banks come from is only known once the engine has chosen it" (Engine/Core/TaskRegistry.h). That is why Initialize exists as a call rather than as constructor arguments, and why the constructor captures bankAllocatorID eagerly — the later call refreshes it, and AllocateBank uses whatever it holds.
A constructed-but-never-initialised registry is a live object that can only refuse. GetCapacity reports zero, Create logs an error naming a capacity of zero, and Grow is the only way to give it records — using recordsPerBank as it stands, DefaultGrowByRecords. So a registry that was forgotten rather than configured fails loudly on first use instead of silently tracking nothing.

Parameters

None. Capacity, grow-by and name all arrive through Initialize.

Return value

Nothing: construction allocates no memory and therefore cannot fail. noexcept states the same claim.

Examples

From Engine/Core/TaskRegistry.cpp, TaskRegistryTest

registry.Initialize("PacketTest", 8, 4);

The pair as the tests use it — a default-constructed TaskRegistry on the stack, then a sizing call (Engine/Core/ResultPacket.cpp). The engine's own registry is the same object owned by TaskSystem, sized from its Initialize and reachable through TaskSystem::GetRegistry().
