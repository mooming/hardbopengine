GetRecord

member of hbe::TaskRegistry Engine/Core/TaskRegistry.cpp Index to record with no validity check at all - the caller proved the index.

Signature

[[nodiscard]] Record& GetRecord(std::size_t recordIndex) noexcept

Function description

Defined in Engine/Core/TaskRegistry.cpp as TaskRegistry::GetRecord(); the body is the index computation the whole storage scheme exists to make cheap. 

return banks[recordIndex / recordsPerBank][recordIndex % recordsPerBank];

From Engine/Core/TaskRegistry.cpp

Private, and called from one place — Create, immediately after it has taken an index off the free chain. That is the whole contract: the index came from the registry's own chain, so it names a bank that exists and an offset inside it, and this function adds nothing.

It checks nothing, so it is only ever correct for an index the registry issued. No bound on the bank index, no test against bankCount, no inUse or generation read, no assertion. A foreign or corrupt index here is a wild pointer read rather than a null return, which is the deliberate opposite of Find — the public path that takes an identity from a caller and therefore validates every step of the same arithmetic.
Its safety rests on recordsPerBank being the value in force when the record was issued. The divisor decides which bank an index lives in, so a grow-by that changed between AllocateBank and this read would resolve an existing index into a different bank — the concrete reason Initialize belongs before any task exists and not beside one. FindLiveRecord performs the same division with a bound check, because its input is an identity from elsewhere.
It returns a reference to a record, not a task. The caller gets Record — task, successor, generation, in-use flag and free-list link together — which is what Create needs while it fills a record in place. Anything that should see only the task goes through Find.

Taken from the head of the chain, then unlinked by reading the link stored inside the record itself — the free list lives in the records, which is why a record keeps a nextFreeRecord field even while it is live and unused (Engine/Core/TaskRegistry.h, and the R28 pricing note that explains why it is not aliased onto the successor).
