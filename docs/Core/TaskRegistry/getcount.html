GetCount

member of hbe::TaskRegistry Engine/Core/TaskRegistry.h Live records, read relaxed; the last completed count, not a snapshot.

Signature

[[nodiscard]] std::size_t GetCount() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskRegistry.h; there is no counterpart in Engine/Core/TaskRegistry.cpp. One relaxed atomic load of the counter that Create increments and Release decrements.

"A count read while other threads are creating or releasing is the last one that completed, not a snapshot a decision may be built on. It is there to be looked at, not to be raced against." (Engine/Core/TaskRegistry.h) The distinction is the whole contract. Valid uses are reports and tests; the invalid use is the obvious one — reading this, comparing it to GetCapacity, and deciding whether to grow — because between the read and the decision any number of tasks may have been created or released, and the counter says nothing about which records are free anyway. Room to create is a property of the free chain, and the only authoritative reader of that chain is Create under the lock.
It counts live records, not queued work, and it is not a leak detector by itself. A task that finished and was never released keeps its record and its identity live, so a monotonically climbing count means somebody is not calling Release — the registry test family uses it exactly that way, asserting the count returns to baseline after the drop paths run (Engine/Core/TaskRegistry.cpp).
Relaxed is enough because the counter guards nothing. The publication protocol that a reader must actually rely on is inUse and the generation, both read with acquire by Find. This number is beside that point; a caller that tries to use it as a happens-before edge is building on a value with no ordering.

Parameters

None.

Return value

TypeWhat you get
std::size_tRecords currently tracking a task, as of the most recent completed create or release. It can exceed the momentary truth on a busy table and is never a basis for a decision

Examples

From Engine/Core/TaskSystem.cpp, TaskSystemTest

const std::size_t baseline = registry.GetCount();

Read before and after a scenario rather than used as a gate: the three drop sites — released task, aged-out work, abandoned notice — are tested by asserting the count returns to the baseline, which is a statement about bookkeeping rather than about timing (Engine/Core/TaskSystem.cpp).
