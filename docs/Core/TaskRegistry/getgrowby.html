GetGrowBy

member of hbe::TaskRegistry Engine/Core/TaskRegistry.h Records each Grow adds.

Signature

[[nodiscard]] std::size_t GetGrowBy() const noexcept

Function description

Declared and defined in the header Engine/Core/TaskRegistry.h; there is no counterpart in Engine/Core/TaskRegistry.cpp. One read of the field that is simultaneously the records-per-Grow figure, the size of every bank, and the divisor that turns an index into a bank and an offset.

The figure a caller should compare against what it asked for. Initialize replaces a zero grow-by with DefaultGrowByRecords, so the requested and effective values can differ; this is the effective one, and GetCapacity is expressed in it. The engine's sizing test asserts it equals 4096 (Engine/Core/TaskRegistry.cpp).
It is not a growth policy and not a reservation. One Grow buys exactly this many records and this × sizeof(Record) bytes — 1 MiB at the default — and nothing grows automatically, because Create refuses rather than growing. It is also not advisory: every index computation in Find and GetRecord divides by it, which is the reason the header restricts Initialize to once, before any task exists.

Parameters

None.

Return value

TypeWhat you get
std::size_tRecords per bank, never zero — the constructor seeds it with DefaultGrowByRecords and Initialize refuses to store a zero

The reading that makes a memory budget checkable: capacity times record size is the table's footprint, and grow-by times record size is the cost of the next Grow — the number a caller needs before deciding whether growth is affordable at this point in a frame.
