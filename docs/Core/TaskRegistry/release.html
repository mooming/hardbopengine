Release

member of hbe::TaskRegistry Engine/Core/TaskRegistry.cpp Stops tracking a task and returns its record; a stale ID is reported.

Signature

Function description

Defined in Engine/Core/TaskRegistry.cpp as TaskRegistry::Release(): the creating lock taken again, the identity validated, and the record pushed onto the free chain.

From Engine/Core/TaskRegistry.cpp (the elided block is the error log described below)

inUse is cleared before the record joins the free list, so a lock-free Find that races this call reports the task as gone rather than handing out a task that is about to be re-issued. The task object itself is not destroyed and not cleared: its fields keep their last values until Create overwrites them, which is why a Find result is "whatever they held", not a guarantee.

A stale ID is reported as an error, not tolerated quietly. The log names the index and generation and states the two possible causes: "this is either a double release or an ID from a registry that did not issue it" (Engine/Core/TaskRegistry.cpp). The header explains the stakes — a double release that went unnoticed would link one record into the free chain twice and hand it to two tasks, giving two live identities the same record (Engine/Core/TaskRegistry.h).
The generation is what saves a racing release, and it is checked before anything is freed. Releasing an ID whose record has since been re-issued fails the generation test in FindLiveRecord and is refused, so a task that finished twice, or a caller holding an old copy of an ID, cannot release somebody else's task. Without the generation this call would be a use-after-free generator.
Releasing does not run, cancel, or notify the task. Nothing inspects Record::successor, so a chain whose head is released here simply never dispatches: TaskSystem::DispatchSuccessor refuses a successor whose task cannot be found, and the registry's close-path tests assert that the live count drops when work whose task was released is dropped (Engine/Core/TaskSystem.cpp, Engine/Core/TaskRegistry.cpp). If a caller owes somebody a completion, it owes it before calling this.
