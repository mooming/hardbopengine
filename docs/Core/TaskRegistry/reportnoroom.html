ReportNoRoom

member of hbe::TaskRegistry Engine/Core/TaskRegistry.cpp The error line for a refused task, naming the task, capacity and ceiling.

Signature

void ReportNoRoom(StaticString taskName) noexcept

Function description

Defined in Engine/Core/TaskRegistry.cpp as TaskRegistry::ReportNoRoom(). Private, and called from exactly one place: the branch in Create that finds the free chain empty. 

auto log = Logger::Get(name);
log.OutError([name = name, taskName, capacity = GetCapacity(), maxCapacity = maxCapacityRecords](auto& ls)
{
    ls << name.c_str() << " refused to track " << taskName.c_str() << " because all " << capacity
       << " task records are in use. The task was not tracked and will not run; growing the registry is the"
       << " fix, and its ceiling is " << (maxCapacity == 0 ? 0 : maxCapacity)
       << " records, where 0 means no ceiling. ";
});

From Engine/Core/TaskRegistry.cpp

The whole function is a log line, and the line is the diagnosis: which registry refused, which task went untracked, how many records exist, and what the ceiling is — the four facts that decide whether the fix is Grow, a raised ceiling, or a leak investigation. Everything is captured before the log callback runs, so the figures printed are the ones at the moment of refusal rather than whatever the table looks like when the log thread gets to it.

It is OutError, and the level is the point. "A task that silently never runs is indistinguishable from one still waiting" (Engine/Core/TaskRegistry.h). A warning would be read as a tuning note; this is a task that will never run, on a path where the caller may not check the null identity it was handed.
The sentence "all N task records are in use" is true of the free chain, not necessarily of the tasks. The chain is empty because every record is live, and a record stays live until Release returns it — so a workload that finishes tasks without releasing them reaches this line with the table full of finished work. The count to compare against is GetCount over time, not GetCapacity at one instant.
One refusal, one line. There is no suppression, no counter and no rate limit, so a caller in a loop that creates tasks without checking identities will emit one error per attempt. That is deliberate for a condition this serious, and it is the difference between this and the task streams' one-per-pass reporting of budget refusals (Engine/Core/TaskStream.cpp).
