SetMaxCapacity

member of hbe::TaskRegistry Engine/Core/TaskRegistry.h Caps growth without reserving anything; set it where the registry is built.

Signature

void SetMaxCapacity(std::size_t maxRecords) noexcept

Function description

Declared and defined in the header Engine/Core/TaskRegistry.h; there is no counterpart in Engine/Core/TaskRegistry.cpp. One unsynchronised store, and the header names the two properties that make it safe enough: "This bounds growth; it reserves nothing. Set it where the registry is built rather than while tasks are running, since Grow reads it without a lock."

Grow reads this field without the lock that Grow itself takes. AllocateBank tests maxCapacityRecords > 0 && (bankIndex + 1) * recordsPerBank > maxCapacityRecords inside registryLock, so a writer on another thread is racing a locked reader (Engine/Core/TaskRegistry.cpp). The value is a std::size_t that will not be torn in practice; the header's instruction — configure it where the registry is built — is the actual protection, and it is a rule about ordering rather than about atomicity.
Order it after Initialize or lose it. Initialize stores DefaultMaxCapacityRecords — zero — unconditionally, so a ceiling applied before that call is overwritten and the table grows without bound. This is the one place where two configuration calls have a required order, and the only symptom of getting it wrong is a megabyte bank appearing somewhere nobody capped it.
What it does not do. It does not shrink the table, does not fail a grow that is already in flight, and does not make Create refuse earlier: a creation is refused when the free chain is empty, whether or not the ceiling has been reached. The difference shows only in the log — ReportNoRoom for a full table, ReportRefusedGrowth for a capped one.

Parameters

ParameterTypeRequirement
maxRecordsstd::size_tCeiling in records; 0 lifts the cap. A figure that is not a whole number of banks is effectively the last whole bank below it, since AllocateBank refuses the bank that would cross it

Return value

void. No clamp, no refusal, no report — GetMaxCapacity is what a caller reads back to confirm the store landed after its Initialize.

Examples

Illustrative — no caller sets a ceiling; the engine runs uncapped, and the sizing test asserts the uncapped default.

registry.Initialize("TaskRegistry", TaskRegistry::DefaultInitialCapacityRecords,
                    TaskRegistry::DefaultGrowByRecords);
registry.SetMaxCapacity(65536);

Order matters more than the figure: Initialize first, ceiling second, and the read-back afterwards if the configuration came from data. The ceiling's real purpose is to turn an unbounded growable into a bounded one: without it the only limit is MaxBanks, and 1024 banks of 1 MiB is a gigabyte.
