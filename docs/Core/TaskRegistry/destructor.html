~TaskRegistry

member of hbe::TaskRegistry Engine/Core/TaskRegistry.cpp Destroys and returns every bank; tracked tasks are not released first.

Signature

~TaskRegistry() noexcept

Function description

Defined in Engine/Core/TaskRegistry.cpp as TaskRegistry::~TaskRegistry(). 

const std::size_t allocatedBanks = bankCount.load(std::memory_order::relaxed);
for (std::size_t bank = 0; bank < allocatedBanks; ++bank)
{
    DeallocateBank(banks[bank]);
}

bankCount.store(0, std::memory_order::relaxed);

From Engine/Core/TaskRegistry.cpp

It walks the banks that were published and hands each to DeallocateBank, which destroys the records' lifetimes and returns the bytes to the allocator they came from. The relaxed loads are adequate here because nothing else may be touching this registry at destruction time — the destructor is not a synchronisation point, and the ordering that matters was established when the banks were published.

Tracked tasks are not released, notified, or even counted on the way out. There is no pass over live records, no abandoned notice, and no log line: whatever was created and never Released simply stops existing with the table. That is the registry's half of a shutdown obligation — the engine's half is the task system's close path, which is what drains and reports before the registry is taken apart (Engine/Core/TaskSystem.cpp).
Every bank is destroyed at the size the table currently believes, not at the size it was allocated with. DeallocateBank computes recordsPerBank * sizeof(Record) from the field, and Initialize is free to change that field. A second Initialize with a different grow-by therefore makes the destructor destroy and free a count that does not match what AllocateBank constructed for the earlier banks. The header's rule — call Initialize once, from the task system's own Initialize and nowhere else (Engine/Core/TaskRegistry.h) — is what keeps this unreachable, not any check in the code.
Any thread still inside Find when this runs is a use-after-free. The lookup path takes no lock precisely so that it never delays a creating thread, so there is no handshake here to wait for it. A Find result is valid memory for the life of the registry — and this is where that life ends. The engine's registry outlives every stream because it is owned by the task system, which is why the rule is satisfiable.

Parameters

None.

Return value

Nothing, and no count of what was still tracked. The destructor is noexcept: a bank whose allocator refuses to free it would terminate rather than propagate.
