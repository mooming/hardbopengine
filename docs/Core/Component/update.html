Update

member of hbe::Component Engine/Core/Component.h Pure virtual: the per-pass tick, called with the state ALIVE.

Signature

virtual void Update(const float deltaTime) = 0

Function description

Pure virtual, declared in Engine/Core/Component.h with no implementation anywhere in the engine. The per-frame callback: called once per pass for every component the system considers enabled, with the elapsed time as a float.

The state you observe here is ALIVE, and it is the only state in which this is called at all. ComponentSystem::ProcessUpdate walks its update list and calls this on every entry; the state is set to ALIVE by ProcessInit before the component ever reaches that list, and re-enabled components are put back only when their state is ALIVE (Engine/Core/ComponentSystem.h). The repository's subclass checks it: 
void Update(const float deltaTime) override
{
    if (GetState() != ComponentState::ALIVE)
    {
        ls << "State failure, state = " << GetState() << ", but expected " << ComponentState::ALIVE
           << lferr;
        testResult = false;
    }

    ++updateCount;

    if (updateCount > updateNum)
    {
        Destroy();
    }
}

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

Note the exit: the component retires itself by calling Destroy from inside its own update. That is the intended way to leave — the system checks IsEnabled immediately after this returns and routes the component to its transitions (Engine/Core/ComponentSystem.h).

Your address is not stable across passes, and the object you are is moved on every one. ProcessUpdate moves each entry into a second list and swaps the lists: 
if (!compo.IsEnabled())
{
    transitionList.push_back(std::move(compo));
}
else
{
    swapUpdateList.push_back(std::move(compo));
}
...
std::swap(updateList, swapUpdateList);
swapUpdateList.clear();

From Engine/Core/ComponentSystem.h, ComponentSystem::ProcessUpdate()

A reference or pointer to a component — including one a component saved to itself, or one handed out by ComponentSystem::Create — is therefore stale the moment a pass ends. Anything that must survive a pass has to be found by value or by index, not by address, and the state an update sets is carried along by the move (the constructor page explains what that move requires of a subclass).

deltaTime is a float, and the system supplies it verbatim. Nothing in the engine computes it for you — the caller of ComponentSystem::Update decides its unit and its clamp, and the test harness passes 0.033f on every pass (Engine/Core/ComponentSystem.cpp). A component that divides by it must handle zero itself.

Parameters

NameTypeMeaning
deltaTimeconst floatTime since the previous pass, in whatever unit the caller of the system chose; never inspected by this class, never clamped

Return value

void. A component cannot ask to be skipped or to be removed except by changing its own state — SetEnable to sleep, Destroy to die — which the system reads after this returns.

Examples

The drive loop in the repository is a bare while on the system's own truthiness, so components are updated until every list is empty: 

while (testSystem)
{
    testSystem.Update(0.033f);

    if (!testResult)
        return;
}

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

The system converts to true while any of its three live lists holds something, so this is the lifecycle pump rather than a frame loop (Engine/Core/ComponentSystem.h). There is no engine subsystem that runs a component system today — the only instantiation is this test (the class page).
