IsEnabled

member of hbe::Component Engine/Core/Component.h Whether the state is ALIVE - the question the system routes on after every update.

Signature

[[nodiscard]] bool IsEnabled() const noexcept

Function description

Defined in the header Engine/Core/Component.h. Its body is state == State::ALIVE — enabled means nothing more than "the state is ALIVE", so ALIVE is the only state this reports as enabled and every other state, including BORN and NONE, is reported as disabled.

This is the routing question the system asks after every update. ProcessUpdate calls Update on each component and immediately asks this; a false answer moves the component to the transition list, where GetState decides which callbacks run (Engine/Core/ComponentSystem.h). That is why a change of state made inside an update takes effect at the end of that same update, and why Destroy and SetEnable have no other work to do.
It is const noexcept and lock-free on a plain field, and it cannot distinguish "not yet" from "no more". A component in NONE or BORN answers the same as one in DEAD (ComponentState). Inside Init that means this returns false — the state is set to ALIVE only after Init returns (Engine/Core/ComponentSystem.h) — so setup code must not gate work on being enabled. Only GetState can tell the difference.

Parameters

None.

Return value

TypeWhat it tells the caller
booltrue only in ALIVE. Everything else — NONE, BORN, SLEEP, DEAD, and any value written by SetState that is not one of the enum's five — answers false and will therefore be routed to the transition switch

    }
}
