OnDisable

member of hbe::Component Engine/Core/Component.h Pure virtual: called each time the component stops running, with the state SLEEP.

Signature

virtual void OnDisable() = 0

Function description

Pure virtual, declared in Engine/Core/Component.h, implemented by nobody in the engine. Called every time a component stops being active — whether it is going to sleep or leaving for good.

The state is SLEEP on both exits, so this callback cannot tell them apart — by design. The sleep case calls it while the state is already SLEEP; the death case sets SLEEP, calls it, and only then sets DEAD before Release (Engine/Core/ComponentSystem.h). That intermediate state exists so this callback sees one state and one state only: 
void OnDisable() override
{
    if (GetState() != ComponentState::SLEEP)
    {
        ls << "State failure, state = " << GetState() << ", but expected " << ComponentState::SLEEP
           << lferr;

        testResult = false;
    }

    isOnDisableCalled = true;
}

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

The consequence for a subclass: teardown that must run only once — unsubscribing, releasing a handle — does not belong here, because a component that sleeps and wakes will run this once per sleep. It belongs in Release, which is called once (Engine/Core/ComponentSystem.h).

A component that stops running without changing its state never hears this. Both call sites are in the transition switch, and a component only reaches that switch if IsEnabled answered false at the end of its update (Engine/Core/ComponentSystem.h). A component that is removed by other means — the system destroyed while the component sleeps, or a state that matches none of the switch's cases, whose only handling is an Assert that exists in Debug builds alone — is destroyed with no disable and no release (Release shows the failure test).

Parameters

None.

Return value

void. The outcome is already decided by the state this callback observes: SLEEP means the component goes to the sleep list, and the state set afterwards decides whether it then goes to Release.

Examples

case ComponentState::SLEEP:
    compo.OnDisable();
    sleepList.push_back(std::move(compo));
    break;

case ComponentState::DEAD:
    compo.SetState(ComponentState::SLEEP);
    compo.OnDisable();
    compo.SetState(ComponentState::DEAD);
    compo.Release();
    break;

From Engine/Core/ComponentSystem.h, ComponentSystem::ProcessTransition()

The two exits side by side. The sleep branch moves the component onto a list the system never reads again — see SetEnable — and the death branch leaves it nowhere, so the clear that follows destroys it.
