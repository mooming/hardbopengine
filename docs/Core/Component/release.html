Release

member of hbe::Component Engine/Core/Component.h Pure virtual: final teardown, called once with the state DEAD, just before the object dies.

Signature

virtual void Release() = 0

Function description

Pure virtual, declared in Engine/Core/Component.h, implemented by nobody in the engine. The last callback a component receives: called once, immediately before the component is destroyed, for a component that has been asked to die.

The state is DEAD by the time you are called, and the system arranged that deliberately. The death branch sets SLEEP first, runs OnDisable under that state, then sets DEAD and only then calls Release (Engine/Core/ComponentSystem.h). A subclass checks it: 
void Release() override
{
    if (GetState() != ComponentState::DEAD)
    {
        ls << "State failure, state = " << GetState() << ", but expected " << ComponentState::DEAD << lferr;

        testResult = false;
    }

    isReleased = true;
}

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

The reason for the ordering is that OnDisable and Release are two different duties — undo the enablement, then let go of resources — and a component that branches on its own state in OnDisable must not see DEAD there, or it cannot tell the two exits apart.

Not every component is released, and only a destructor can catch that. Release is reached from exactly one place, the DEAD case of the transition switch (Engine/Core/ComponentSystem.h). A component left sleeping when the system is destroyed is destroyed with no callback at all, and a component whose state is none of ALIVE, SLEEP or DEAD at transition time falls to the switch's default case — where the only statement is an Assert, which is compiled out unless __DEBUG__ is defined. Outside Debug the object is destroyed silently by the following transitionList.clear(). The repository's subclass is written to fail loudly in both cases: 
if (!isInit || !isOnEnableCalled || !isOnDisableCalled || !isReleased)
{
    testResult = false;
    ls << "Test object is destroyed accidently." << lferr;
}

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

Parameters

None.

Return value

void, and there is no second chance: the object is destroyed when the transition list is cleared in the same pass, so anything Release does not free is freed by the destructor without being asked.

Examples

case ComponentState::DEAD:
    compo.SetState(ComponentState::SLEEP);
    compo.OnDisable();
    compo.SetState(ComponentState::DEAD);
    compo.Release();
    break;

From Engine/Core/ComponentSystem.h, ComponentSystem::ProcessTransition()

The dead component is not pushed onto any list, which is how it dies: the loop finishes, transitionList.clear() runs, and with it the destructor (Engine/Core/ComponentSystem.h, ~Component).
