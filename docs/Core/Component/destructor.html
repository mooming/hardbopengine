~Component

member of hbe::Component Engine/Core/Component.h Virtual and defaulted, and the only place a component can learn it was dropped without a release.

Signature

virtual ~Component() = default

Function description

Defined in the header Engine/Core/Component.h; nothing in Engine/Core/Component.cpp. Virtual, so a Component* deletes the real object — though no code in the repository holds a component by pointer: the system stores them by value in an HVector and destroys them by emptying that vector.

The destructor is the last thing to run on a dead component, and it runs without any further callback. Destroy only sets a flag; the release, the disable and the death notice have to happen first, in ComponentSystem::ProcessTransition, and the object is then destroyed when that function clears its working list (Engine/Core/ComponentSystem.h). A subclass that needs to know it is being torn down cannot ask this class anything — GetState still answers DEAD, which is the same answer it gave a moment earlier.
Declaring a destructor here is what makes subclasses immobile. A user-declared destructor suppresses the implicit move constructor and move assignment operator, so every subclass that the system must move has to declare its own — the contract stated in the constructor page and proved by a compiler probe of the real headers. The only subclass in the repository declares one, and it uses it to detect being destroyed the wrong way: 
~Test() override
{
    if (!isValid)
        return;

    if (!isInit || !isOnEnableCalled || !isOnDisableCalled || !isReleased)
    {
        testResult = false;
        ls << "Test object is destroyed accidently." << lferr;
    }
}

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

The move constructor marks the moved-from shell isValid = false so only the surviving object is judged. The assertion it makes is the real lifecycle contract of this class: a component that is destroyed without having seen Init, OnEnable, OnDisable and Release was dropped rather than retired — which is what happens to a component parked in the system's sleep list when the system itself dies (Engine/Core/ComponentSystem.h).

Parameters

None.

Return value

None. The destructor is defaulted, so it releases nothing of this class's own beyond the String name.

Examples

Nothing in the engine deletes a component directly; both destruction paths are the system emptying a list — the dead components at the end of ProcessTransition, and everything still alive when the system is destroyed. The test above is therefore the only place the ordering is checked, and it checks it from the destructor because that is the only moment a component can tell it was never released.
