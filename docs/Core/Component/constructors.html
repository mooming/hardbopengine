Component

member of hbe::Component Engine/Core/Component.h The only constructor: names the component and puts it in ComponentState::NONE.

Signature

Component(const char* name)
		: state(State::NONE)
		, name(name)

Function description

The only constructor, defined in the header Engine/Core/Component.h; there is no counterpart in Engine/Core/Component.cpp, which includes the header and declares nothing. It stores the name as an hbe::String and puts the component in ComponentState::NONE — the state that means "constructed, but no system has taken it yet".

Every component must be named, and there is no default constructor to forget it. A derived class chains to this one, and it is not explicit, so the string literal in a subclass's initializer list is the whole call: 
Test(bool& testResult, TestCollection::TLogOut& ls, TestCollection::LogFlush& lferr)
    : Component("Test")

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

The name is used by nothing inside this class — no method logs it, and it is not the field the system reports (the system has its own name). It travels with the component for whoever asks (GetName).

A subclass that declares nothing extra cannot live in a ComponentSystem, because this class's own destructor suppresses its move operations. virtual ~Component() = default is a user-declared destructor, so the implicit move constructor and move assignment operator are not generated; and the implicit copy constructor, though generated, is defined as deleted, because copying the name member from a const String& is impossible — String's copy constructor takes a non-const reference (Engine/String/String.h). A compiler probe of the real headers confirms all four answers: Component is neither copy- nor move-constructible, and is copy-assignable but not move-assignable. Since the system stores components by value and moves them between its lists on every pass, a subclass must declare its own move constructor and move the base through it — which is exactly what the only subclass in the repository does: 
Test(Test&& rhs) noexcept
    : Component(rhs)

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

Note the form: Component(rhs) binds a non-const lvalue, which selects String's copy constructor and therefore shares the name buffer (String holds a Shareable buffer) rather than stealing it. A subclass that forgets the move constructor does not fail at runtime — it fails to compile inside the system's list operations.

Parameters

NameTypeMeaning
nameconst char*Label stored as a String; converted implicitly, so a literal is enough. Not copied into a fixed buffer, and not read by this class

Return value

None — a constructor. The constructed object is in ComponentState::NONE, which no system transition handles; only ComponentSystem::Create moves it out of that state.

Examples

A component is constructed by the system that will drive it, not by hand, because a component nobody owns sits in NONE forever and never receives Init or Release: 

ComponentSystem<Test> testSystem("TestSystem");

bool testResult = true;
for (int i = 0; i < componentNum; ++i)
{
    testSystem.Create(testResult, ls, lferr);
}

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

Create forwards these arguments to the constructor above, then sets BORN (Engine/Core/ComponentSystem.h). The component is at that moment in the system's init list, and its address is not stable — see Update.
