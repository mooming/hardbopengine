OnEnable

member of hbe::Component Engine/Core/Component.h Pure virtual: called each time the component becomes active, with the state ALIVE.

Signature

virtual void OnEnable() = 0

Function description

Pure virtual, declared in Engine/Core/Component.h, implemented by nobody in the engine. Called every time a component becomes active: once right after Init, and again each time a sleeping component is brought back.

The state is ALIVE on both paths, and that is the whole contract of this callback. ProcessInit sets ALIVE and then calls this, and the transition switch calls it only in the ALIVE case — the case a component reaches by having set itself back to ALIVE during Update (Engine/Core/ComponentSystem.h). The repository's subclass checks it: 
void OnEnable() override
{
    if (GetState() != ComponentState::ALIVE)
    {
        ls << "State failure, state = " << GetState() << ", but expected " << ComponentState::ALIVE
           << lferr;

        testResult = false;
    }

    isOnEnableCalled = true;
}

From Engine/Core/ComponentSystem.cpp, ComponentSystemTest

Because the first call follows Init unconditionally, an enable callback cannot tell "first time" from "again" by asking this class — the state answers ALIVE both times. A component that must distinguish them keeps its own flag, as the test above does with isOnEnableCalled.

The re-enable path is reachable only from inside Update, and only for a component that is still running. The ALIVE case of the transition switch is entered when a component was found not enabled at the end of its update but its state has since become ALIVE again (Engine/Core/ComponentSystem.h) — in practice, a component that called SetEnable twice, or SetState, during its own update. A component that has already been moved to the system's sleep list is never examined again, so bringing it back from there does not call this (SetEnable states the consequence).

Parameters

None.

Return value

void. Nothing checks a return: the system places the component on its update list whatever this callback did, so refusing to be enabled means setting the state back again, not reporting failure.

Examples

case ComponentState::ALIVE:
    compo.OnEnable();
    updateList.push_back(std::move(compo));
    break;

From Engine/Core/ComponentSystem.h, ComponentSystem::ProcessTransition()

The re-enable branch: the callback runs first, then the component is moved back into the update list, so the first Update after this is the next pass. The other call site is the two-line sequence in ProcessInit (Engine/Core/ComponentSystem.h).
