GetPayload

member of hbe::ResultPacket Engine/Core/ResultPacket.h the producer's 120 bytes, aligned and unlengthed; nothing in the engine reads them

Signature

[[nodiscard]] std::uint8_t* GetPayload() noexcept

[[nodiscard]] const std::uint8_t* GetPayload() const noexcept

Function description

Both overloads are defined in the header Engine/Core/ResultPacket.h as ResultPacket::GetPayload(); each body is return payload;. The pointer addresses PayloadBytes bytes (120) that begin immediately after the 8-byte header. The engine never interprets one of them.

The word the producer may write it as is decided by alignment rather than by luck: the class is alignas(std::uint64_t), the header is exactly 8 bytes, and a file-scope static_assert(alignof(hbe::ResultPacket) == sizeof(std::uint64_t)) pins the first half of that claim, while Engine/Core/ResultPacket.cpp asserts at run time that GetPayload() % sizeof(std::uint64_t) == 0. Reading the payload as aligned integers is therefore legal wherever the packet landed, which was the point of the packet not being a byte blob behind a pointer.

No length travels with the pointer. Nothing checks an index against PayloadBytes, on either side. A producer that writes byte 120 walks into memory it does not own — the packet is embedded in a Task inside a registry record, and the payload is the last thing in both — so the bytes past it belong to whatever the record holds next. The width is the caller's to remember: 120 bytes, or a handle to something bigger.
Nothing in the shipping engine reads these bytes. Every call site in the repository is a test (Engine/Core/ResultPacket.cpp, and WriteOutcome() / RunStageThree() in the unit-test region of Engine/Core/TaskSystem.cpp). The delivery path copies the whole 128-byte packet — header and payload together — without looking inside it (TaskSystem::DispatchSuccessor()).

Examples

std::memset(packet.GetPayload(), 0xA5, ResultPacket::PayloadBytes);
packet.SetDestinationStreamIndex(3);

Filling every byte the payload owns, then declaring where it goes and what it is. The assertions that follow read both ends of the range (GetPayload()[0] and GetPayload()[ResultPacket::PayloadBytes - 1]) so that a payload narrower than the constant claims cannot pass by leaving the first byte intact.
