GetKind

member of hbe::ResultPacket Engine/Core/ResultPacket.h what the result is — the producer's choice, and the one byte the engine agrees not to interpret

Signature

[[nodiscard]] std::uint8_t GetKind() const noexcept

Function description

Defined in the header Engine/Core/ResultPacket.h as ResultPacket::GetKind(); the body is return header[KindByteIndex];. It reads byte 0 of the header — the one byte that says what the payload means, and the one byte the engine agrees not to interpret.

Two ranges share the byte. Below FirstApplicationKind (64) is the engine's range; from 64 up belongs to the application, so the engine cannot allocate an application's kind by accident. The split is a boundary rather than a table: nothing in the engine dispatches on it, and whoever sets a kind decides which side of it they are on. The value KindNoResult (0) is reserved and means "no result" — it is the value HasResult tests for, so setting kind 0 is how a producer takes a result back.

The engine's own routing does not read this byte. TaskSystem::DispatchSuccessor() routes on the destination byte (GetDestinationStreamIndex) and never on the kind (Engine/Core/TaskSystem.cpp), so a kind is a message between the task that wrote it and the task that reads it. Every call site of this function in the repository is a test.
Reading the kind is not a synchronisation point. The packet has no atomics and no lock. The ordering that makes a finished task's writes visible to another thread belongs to Task::ReportFinishedSubTask, whose sequential-consistency increment is what closes a join; reading this byte from a third thread while the producing task is still running is a race on an ordinary byte.

Read through the successor's own identity: the producer wrote its own packet, and TaskSystem::DispatchSuccessor() assigned that packet to the successor's before queueing it, which the same test calls "the delivery, not a courtesy". The reader never touches the producer's record.
