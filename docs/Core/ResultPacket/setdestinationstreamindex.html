SetDestinationStreamIndex

member of hbe::ResultPacket Engine/Core/ResultPacket.h address the result at a stream — unchecked here, refused at delivery if the stream is not there

Signature

void SetDestinationStreamIndex(std::uint8_t streamIndex) noexcept

Function description

Defined in the header Engine/Core/ResultPacket.h as ResultPacket::SetDestinationStreamIndex(); the body is header[DestinationByteIndex] = streamIndex;. One byte, no lookup, no check: writing this address does not ask the task system whether that stream exists.

Validation happens later and elsewhere. TaskSystem::DispatchSuccessor() reads the byte back and refuses with a logged error if it names a stream this engine does not have (Engine/Core/TaskSystem.cpp), so a bad destination is a chain that silently stops rather than a write that fails. Addressed-to is a decision the producer makes: Clear deliberately restores NoDestinationStream rather than leaving 0, because a cleared packet must not look addressed to the base stream.

The parameter is a byte and stream indices are not. Everywhere else a stream index is a signed integer (TaskSystem::TIndex), so the caller casts: TaskSystem::RunSplit() writes static_cast<std::uint8_t>(successorStream) after checking HasStream(successorStream) on the signed value (Engine/Core/TaskSystem.cpp). On an engine with 256 streams or fewer that cast cannot lie. On one with more, a successor stream whose index is above 255 passes the existence check and is then truncated — 256 arrives as 0, the base stream — and the delivery happily routes to a different, real stream, because the byte it validates is the truncated one. Recorded here as it behaves and in this page's report as a latent defect: the packet's one byte is the binding width on how many streams can ever be destinations, and nothing enforces that at either end.
A destination with no successor is inert, not an error. This byte only matters to DispatchSuccessor(), which is reached when a join closes and a successor is recorded. Addressing a packet at a stream and never recording a successor delivers nothing, and nothing complains.

Parameters

ParameterTypeRequirement
streamIndexstd::uint8_tThe stream the outcome should be delivered on, or NoDestinationStream (0xFF) for none. Not validated here; a value naming no stream is refused at delivery time

Return value

void. Nothing reports whether the previous destination was overwritten, nor whether the value names a stream.

Examples

From Engine/Core/TaskSystem.cpp, TaskSystem::RunSplit()

if (!successor.IsNull())
{
    SetSuccessor(taskID, successor);
    task->GetResult().SetDestinationStreamIndex(static_cast<std::uint8_t>(successorStream));
}

A split has no producer runnable of its own to write the routing, so this is where the byte comes from — recorded next to the successor itself, before the first item of the split is queued, so a join that closes in the first pass already knows where its outcome belongs.
