Clear

member of hbe::ResultPacket Engine/Core/ResultPacket.h forget every byte of this packet — the state a record comes back in when the registry issues it

Signature

void Clear() noexcept

Function description

Defined in the header Engine/Core/ResultPacket.h as ResultPacket::Clear(). 

std::memset(header, 0, sizeof(header));
std::memset(payload, 0, sizeof(payload));
header[DestinationByteIndex] = NoDestinationStream;

From Engine/Core/ResultPacket.h, ResultPacket::Clear()

Two memsets and one byte put back. The memset leaves both header bytes at 0, which is the wanted value for KindNoResult and the wrong one for the destination — a 0 destination byte is stream 0, the base stream — so the third line restores it to NoDestinationStream. Omitting that line would turn every cleared packet into an address for the main thread's own stream.

It is called when a record is issued, not when a task is finished with: Task::LoadIntoRecord() calls it on the task's member packet before the record is published as in use (Engine/Core/Task.cpp). A reused record must not be able to report the previous occupant's result, and the generation check that stops a stale reader does nothing about a fresh reader of a recycled record — the test A record the registry issues has no result, whatever it held before (Engine/Core/ResultPacket.cpp) exists to pin exactly that.

A producer can clear its own result by writing kind 0. That is the documented way to say "there is no result" while leaving bytes in the payload, and HasResult follows the kind rather than the bytes — the test Clearing the kind is how a producer says there is no result fills a payload with non-zero bytes, sets the kind to KindNoResult, and requires HasResult() to be false.

Parameters

None.

Return value

void. Nothing reports whether the packet had held a result — a second clear is indistinguishable from the first.

Examples

From Engine/Core/Task.cpp, Task::LoadIntoRecord()

numSubTasks = 0;
numGeneratedSubTasks = 0;
result.Clear();
numFinishedSubTasks.store(0, std::memory_order::relaxed);

The packet is an ordinary member of Task, so clearing it is one line among the fields a recycled record must reload. No allocation is involved in any direction: 128 bytes go to zero and stay where they are.
