HasResult

member of hbe::ResultPacket Engine/Core/ResultPacket.h one byte decides it: a producer declared a result, whether or not the payload means anything

Signature

[[nodiscard]] bool HasResult() const noexcept

Function description

Defined in the header Engine/Core/ResultPacket.h as ResultPacket::HasResult(); the body is return header[KindByteIndex] != KindNoResult;. One byte decides it. The payload is not consulted, so bytes written without a kind do not count as a result, and a kind set without a payload does.

The delivery path never asks. TaskSystem::DispatchSuccessor() decides whether to dispatch from the successor's identity, the packet's destination byte and the successor's reserved count — never from this predicate (Engine/Core/TaskSystem.cpp). A producer that set a destination and wrote no result still delivers a successor: the successor runs with a packet whose kind is KindNoResult and whose payload is what Clear left there. Its only call sites in this repository are the tests in Engine/Core/ResultPacket.cpp.
This is the reader's guard, not the writer's. A reader that arrives between a producer writing the payload and the producer calling SetKind sees false and stops — which is why the write order matters and is stated on that page. A reader that sees true has learned a producer declared a result of some kind; it has not learned that the payload is complete, because nothing in this type is atomic.

None.
