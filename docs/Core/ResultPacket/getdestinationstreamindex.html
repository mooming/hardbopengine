GetDestinationStreamIndex

member of hbe::ResultPacket Engine/Core/ResultPacket.h the byte routing reads: where this outcome is delivered, or why the chain stopped

Signature

[[nodiscard]] std::uint8_t GetDestinationStreamIndex() const noexcept

Function description

Defined in the header Engine/Core/ResultPacket.h as ResultPacket::GetDestinationStreamIndex(); the body is return header[DestinationByteIndex]; — byte 1 of the header. It is the only field of this type the engine acts on: the destination byte decides where a finished task's outcome is delivered.

The value is a stream index in the same numbering every other stream reference uses, held in one byte, with NoDestinationStream (0xFF) meaning "addressed to nobody". Two legitimate states use that sentinel: work that reports nothing to anyone, and a caller that reads its own result through its own identity instead of being handed it.

An unwritten destination byte stops a chain, and the log line says so. TaskSystem::DispatchSuccessor() reads this byte and refuses to dispatch when it still says NoDestinationStream (Engine/Core/TaskSystem.cpp) — even when a successor was recorded and the join closed. A split cannot lean on a producer's runnable to write the byte, which is why TaskSystem::RunSplit() writes it itself when the call names a successor (SetDestinationStreamIndex).
The byte is read as a stream index, and it is a byte. A stream index elsewhere in the engine is a signed integer; this one is 8 bits wide, so a destination above 255 cannot be expressed here at all. What the delivery path does with the value it reads is checked (TaskSystem::HasStream), so an out-of-range destination is refused and logged rather than used — see SetDestinationStreamIndex for where the two widths meet.
