ScopedTime

Engine/Core/ScopedTime.h a scope that measures itself: it samples the clock on construction and writes the elapsed span into a caller-owned variable on destruction

Class description

ScopedTime is a measurement guard declared in namespace hbe::time. Its constructor samples the clock; its destructor samples again and assigns the difference to the TDuration reference it was given. There is no accessor and no getter — the output is the caller's variable, which means the value becomes readable only after the guard's scope ends.

The guard is neither copyable nor movable, and the reason is structural: it holds TDuration&, and its copy constructor is explicitly deleted, which also suppresses the implicit move constructor. Verified with a compiler rather than inferred — std::is_copy_constructible_v and std::is_move_constructible_v are both false for ScopedTime. That is the same mechanism the lock guard relies on: a guard that cannot leave its scope cannot report a span that ends somewhere other than where it began.

It is used in production, not only in tests. Engine/Core/TaskStream.cpp wraps one around workItem->Run(*task) inside a nested block, so the timer is destroyed — and the duration written — before the surrounding code reads that duration and compares it against the CPUBudget allowance accumulated around it:

From Engine/Core/TaskStream.cpp

time::TDuration duration;
const bool chargingBudget = budget.GetAllowance().count() > 0.0;
// ...
{
        time::ScopedTime timer(duration);
        if (workItem->Run(*task))
        {
                taskSys.DispatchSuccessor(task->GetID());
        }
}

Beyond that, the type appears in the unit-test timing blocks of the Container, Memory and Math modules, where a pair of guarded blocks measures the engine's container against a standard-library baseline.

The destructor assigns; it does not accumulate. duration = end - start overwrites whatever the referenced variable held. Two guards over the same TDuration therefore leave only the second measurement, and a loop that constructs a guard per iteration with one output variable ends the loop holding the last iteration's span, not the total. To sum spans, keep separate variables or add them explicitly.
Read the output after the closing brace, never inside the scope. The value is written at destruction, which is why the call site above wraps the work in its own block. Reading duration while a guard naming it is still alive yields the previous value — and on a default-constructed local, zero.

Template parameters

None — there is no template here, and no class for one to belong to.

Non-member helpers

None in Engine/Core/ScopedTime.h. The conversions a caller usually wants next — GetNow(), ToFloat(TStopWatch::duration) and the rest — are namespace-scope members of hbe::time declared in Engine/Core/Time.h and documented under Module functions.

Coverage

GapDetail
What a TDuration is Measured here, not assumed: TStopWatch is std::chrono::high_resolution_clock, TTime is a time_point over it, and TDuration is its duration, whose period on this toolchain is 1/1000000000 — nanoseconds. Converting to seconds or milliseconds is time::ToFloat, a module function, and the clock's monotonicity guarantees belong to the standard library rather than to this engine
Clock identity time::GetNow() returns std::chrono::steady_clock::now() (Engine/Core/Time.h) while TTime is a time point over high_resolution_clock. That compiles here because a probe confirmed the two clock types are the same type on this toolchain. On a toolchain where they are distinct, mixing the two APIs would not compile — stated so that a reader does not treat the mix as portable
What the measured span includes Everything between the two samples, including scheduling and any other thread's work that preempts this one. The guard measures wall-clock passage, not CPU time; the accounting that turns such spans into budget charges lives with CPUBudget at the call site above, and its rules are its own
