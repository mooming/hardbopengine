~ScopedTime

member of hbe::time::ScopedTime Engine/Core/ScopedTime.h takes the second sample and publishes the span by assigning it into the caller's variable

Signature

~ScopedTime() noexcept
{
        TTime end = TStopWatch::now();
        duration = end - start;
}

Function description

Two statements, and the second is the class's entire product: a fresh clock sample and an assignment of end - start to the referenced duration. Until this runs, the caller's variable holds whatever it held before; after it, the variable holds the measured span and the guard holds nothing further of interest.

The assignment is a replacement, not an accumulation. Two guards written against one TDuration leave the second span only, so a caller that wants a total must keep separate variables or add the results itself.

noexcept is safe here and worth having: subtracting two time points and assigning a duration cannot allocate or throw. It also fixes the behaviour if a scope is left by an exception — which the engine's exception-free rule intends never to happen — because the span is still written while the stack unwinds. The destructor is the only place the measurement is published, so a guard whose destructor does not run reports nothing at all.

The referenced duration must still exist at destruction. The guard stores TDuration&, so a guard outliving its output variable — declared in the wrong order, or moved somewhere it cannot be — writes through a dangling reference at the closing brace. Normal declaration order (duration first, guard second) is what makes this impossible, and the guard cannot be moved into a position that breaks it because it is neither copyable nor movable.

Parameters

None.

Return value

A destructor returns nothing. The result is the write into the referenced duration, which is why the type has no accessor: reading the measurement means reading the caller's own variable, after the scope.

The block closes at the point the measurement should stop; duration is then read at Engine/Core/TaskStream.cpp:568, converted to seconds by time::ToFloat, and compared against a threshold that produces a Slow DeltaTime warning through Log. That ordering is not incidental: read before the block closes and the warning would be built on a span the destructor has not written yet.
