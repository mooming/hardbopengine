Module Index / Renderer / MeshVertex

MeshVertex

Engine/Renderer/Vulkan/VulkanRenderer.h namespace hbe::Renderer 24 bytes, tightly packed position and normal as two raw float[3] arrays — the only vertex layout the built pipeline can draw

Class description

Six float in a row, named in two groups of three. It exists because the example vertex format, Vertex, carries a colour and no normal, and lit geometry needs the other way round. The header describes it as "Single vertex: position (vec3) + normal (vec3), 24 bytes, tightly packed", and that packing is load-bearing rather than tidy: VulkanRenderer builds its pipeline's vertex input from sizeof(MeshVertex) as the stride and from offsetof(MeshVertex, position) and offsetof(MeshVertex, normal) as the two attribute offsets.

AttributeLocationFormatShader input
position0VK_FORMAT_R32G32B32_SFLOAT layout(location = 0) in vec3 aPosition;
normal1VK_FORMAT_R32G32B32_SFLOAT layout(location = 1) in vec3 aNormal;

Those two rows and the shader declarations are a single promise split across four files: the struct, the pipeline creation, Shaders/MC.vert, and the compiled copy embedded in ShadersSpv.h. Change the struct and nothing fails to compile — the offsets are read at run time — so the mismatch appears as wrong geometry.

Two vertex formats in one module is a fact, not a mistake. Vertex is position plus colour — the unlit example layout. MeshVertex is position plus normal — what lit geometry needs. A pipeline is created against exactly one stride and one pair of offsets, and this engine builds one pipeline, so the type a mesh is built from has to be this one; SetMesh would otherwise read colours as normals.

Template parameters

None — MeshVertex is not a template.

Class properties

NameDeclarationWhat it means
position float position[3]; public data Offset 0, twelve bytes. Object-space position; the vertex shader multiplies it by viewProj * model. A raw array, not Vector3<float> — the layout is meant to be memcpy'd into a buffer, and this keeps the math module out of a GPU-facing struct
normal float normal[3]; public data Offset 12, twelve bytes. Surface normal; the vertex shader forwards it as vNormal. Nothing here or in SetMesh normalises it, so unit length is the generator's job

Coverage

GapDetail
No layout assertion RenderCapabilities asserts its copyability in its own header; this struct asserts nothing. The 24-byte claim is a comment plus arithmetic (six float, alignment 4, so no padding), and the offsets the pipeline uses are taken from the compiler at run time. A field inserted between position and normal would silently move the normal to offset 16 while the shader still read three floats at 12
No tangents, bitangents, texture coordinates or colour There is no field for them and no attribute slot for them. Adding one means changing this struct, the pipeline's attribute array, MC.vert and ShadersSpv.h together
Normalisation and handedness Neither is checked anywhere in this module; the renderer also disables back-face culling (VK_CULL_MODE_NONE) because generated marching-cubes winding is not guaranteed, so a flipped normal shows up as wrong shading rather than as a culled triangle
Comparison and hashing None declared, and none used — vertices go into a std::vector and are copied out by pointer
