SetView

member of hbe::Renderer::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h noexcept copy sixteen column-major floats into the view slot — never sent to the shader on its own, always multiplied first

Signature

void SetView(const float* m) noexcept;

Function description

The body is std::memcpy(viewMat, m, sizeof(viewMat));. What makes this setter different from SetModel is what happens to those sixteen floats afterwards: they are never pushed. During Render the renderer computes viewProj = projMat * viewMat on the CPU — column-major, projection on the left — and pushes the result as PushConstants::viewProj.

That single multiply is what makes the push block fit. The header says so directly: combining view and projection once per frame "is what leaves room for a model matrix" inside the 128 bytes Vulkan guarantees. Three matrices would be 192 bytes, which no device is required to support, and the GLSL push block mirrors the two-matrix decision — Push { mat4 model; mat4 viewProj; }.

The combine runs every frame, from whatever is in the two slots. There is no cached viewProj and no dirty flag, so this setter and SetProj are interchangeable in cost: whichever one you changed, the multiply happens again at record time. Set both, or neither, before Render — a frame recorded between two half-updates renders with a mismatched pair, and nothing warns you.

Parameters

ParameterTypeRequirement
m const float* Sixteen readable float, column-major (element [col * 4 + row]). Not null-checked and not length-checked; a short or null argument is undefined behaviour in the copy. The values are copied during the call, so the caller's array may be reused straight away. Valid before Initialize — the constructor leaves identity in this slot, and a view set before initialization is still there for the first frame

Return value

void. Nothing is validated, allocated or submitted, so there is no failure to report.

Examples

The example has a static camera, so it sets the view once — before the loop, after Initialize and after the projection it will be multiplied with:

From Applications/VulkanExample/Main.cpp

void SetTranslation(float m[16], float x, float y, float z) noexcept
{
        SetIdentity(m);
        m[12] = x;
        m[13] = y;
        m[14] = z;
}

// in main(), once, after Initialize returned true and GetExtent supplied the size:
float view[16];
float proj[16];
SetPerspective(proj, DegreeToRadian(60.0f), static_cast<float>(extent.width) / static_cast<float>(extent.height),
               0.1f, 100.0f);
SetTranslation(view, 0.0f, 0.0f, -3.0f);
renderer.SetView(view);
renderer.SetProj(proj);

A moving camera is the same call moved into the loop, ahead of Render. A camera that changes every frame costs one 4×4 multiply per frame on the CPU — which is the trade this API made deliberately to keep the push block at 128 bytes.
