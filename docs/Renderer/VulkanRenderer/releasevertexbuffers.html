ReleaseVertexBuffers

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private destroy the four mesh handles and zero the counts — no idle wait, the caller owns the timing

Signature

void ReleaseVertexBuffers() noexcept

Function description

Private. Destroys the four mesh handles — index buffer, index memory, vertex buffer, vertex memory, in that order — and zeroes all six pieces of mesh state, including the counts. Every handle is null-checked, so the function is safe on a renderer that never uploaded a mesh, and calling it twice in a row is harmless. 

	if (indexBuffer != VK_NULL_HANDLE)
		vkDestroyBuffer(device, indexBuffer, nullptr);
	if (indexMemory != VK_NULL_HANDLE)
		vkFreeMemory(device, indexMemory, nullptr);
	if (vertexBuffer != VK_NULL_HANDLE)
		vkDestroyBuffer(device, vertexBuffer, nullptr);
	if (vertexMemory != VK_NULL_HANDLE)
		vkFreeMemory(device, vertexMemory, nullptr);

	indexBuffer = VK_NULL_HANDLE;
	indexMemory = VK_NULL_HANDLE;
	vertexBuffer = VK_NULL_HANDLE;
	vertexMemory = VK_NULL_HANDLE;
	vertexCount = 0;
	indexCount = 0;

From Engine/Renderer/Vulkan/VulkanRenderer.cpp, VulkanRenderer::ReleaseVertexBuffers()

There is no device wait idle in here, and that is the whole hazard. Destroying a buffer the GPU is still reading is undefined behaviour in Vulkan, and this function does not protect against it — the caller owns the timing. Its two callers each do: CreateVertexBuffers releases the previous mesh before creating the new one (safe before the loop starts, unsafe while a frame that binds the old buffers is in flight — the SetMesh page states that cost), and Destroy calls it only after vkDeviceWaitIdle.

Parameters

None.

Return value

None — void. On return the renderer holds no mesh: all four handles are null and both counts are zero, so the next frames draw clear colour only.
