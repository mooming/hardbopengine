CreateBuffer

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private one buffer and its host-visible, host-coherent memory — created and allocated, but not bound

Signature

bool CreateBuffer(VkBuffer& buffer, VkDeviceMemory& memory, size_t size, VkBufferUsageFlags usage) noexcept

Function description

Private, and shared by both mesh buffers: CreateVertexBuffers calls it twice, once for the vertex pair and once for the index pair. It does two of the three things a usable buffer needs — creates the buffer, allocates memory that fits it — and deliberately not the third: it does not bind. The caller binds with vkBindBufferMemory itself, which is why both handles travel out by reference.

A zero size is refused up front with a bare false — no log, nothing created. Otherwise the buffer is created with the caller's usage and exclusive sharing, its memory requirements queried, and memory allocated in the one class both mesh buffers want: host-visible and host-coherent, so the upload can map, memcpy, and unmap without flushes — no staging transfer, which the source names as a follow-up rather than implementing. 

	if (!FindMemoryType(physicalDevice, req.memoryTypeBits, properties, ami.memoryTypeIndex))
	{
		LogFailure("no host visible memory type for the mesh buffer");
		vkDestroyBuffer(device, buffer, nullptr);
		buffer = VK_NULL_HANDLE;

		return false;
	}

Only the no-memory-type path cleans up; the allocation failure does not. When no memory type fits, the buffer just created is destroyed and nulled — the block above. When vkAllocateMemory itself fails, the function logs and returns false leaving the buffer alive and unbound; the caller's failure path (SetMesh zeroing the counts) leaves it unreachable but resident until the next upload or Destroy.

Parameters

ParameterTypeRequirement
buffer VkBuffer& Out. Receives the new buffer on success; set to VK_NULL_HANDLE only by the no-memory-type failure path, left untouched otherwise
memory VkDeviceMemory& Out. Receives the allocation on success; stays whatever the caller passed on failure
size size_t Bytes to allocate. Must be non-zero; zero returns false without logging
usage VkBufferUsageFlags The buffer's usage bits — VK_BUFFER_USAGE_VERTEX_BUFFER_BIT or VK_BUFFER_USAGE_INDEX_BUFFER_BIT from the only caller

Return value

true when the buffer exists and memory fitting its requirements is allocated (not yet bound); false on zero size, buffer creation failure, no suitable memory type, or allocation failure — all but the first logged.
