CreateMetalSurface

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private the macOS surface: a CAMetalLayer adopted by a layer-backed view, wrapped by vkCreateMetalSurfaceEXT

Signature

bool CreateMetalSurface() noexcept

Function description

Private, and macOS-only — the implementation lives in Engine/Renderer/Vulkan/VulkanRenderer.mm, the OSAL-style split the module page describes. It is the whole AppKit side of Initialize: build a CAMetalLayer, get it adopted by the window, and wrap it in a Vulkan surface.

The sequence, in order: check window and instance are live; take the NSWindow from the window's native handle; create the default Metal device; build a content view sized to the window's content rect; create the layer; configure it — MTLPixelFormatBGRA8Unorm, framebufferOnly, and contentsScale 1.0 so drawable pixels equal points; adopt it through a layer-backed view; install the view with [nsWindow setContentView:]; and finally call vkCreateMetalSurfaceEXT with the layer. 

	layer.device = metalDevice;
	[metalDevice release];
	layer.pixelFormat = MTLPixelFormatBGRA8Unorm;
	layer.framebufferOnly = YES;

	layer.contentsScale = 1.0;

From Engine/Renderer/Vulkan/VulkanRenderer.mm, VulkanRenderer::CreateMetalSurface()

	VkMetalSurfaceCreateInfoEXT info{};
	info.sType = VK_STRUCTURE_TYPE_METAL_SURFACE_CREATE_INFO_EXT;
	info.pLayer = layer;

	const VkResult result = vkCreateMetalSurfaceEXT(instance, &info, nullptr, &surface);

From Engine/Renderer/Vulkan/VulkanRenderer.mm, VulkanRenderer::CreateMetalSurface()

The layer is configured to match the swapchain, not the other way round. BGRA8Unorm is what CreateSwapchain prefers (VK_FORMAT_B8G8R8A8_UNORM), and AppKit sizes the layer to the view bounds — so the drawable size, and therefore the swapchain extent, follows the window's content rect. That is why CreateSwapchain reads the authoritative size from VkSurfaceCapabilitiesKHR::currentExtent instead of assuming the requested window size.
Manual retain/release, cleaned up per failure. The file is compiled without ARC: MTLCreateSystemDefaultDevice follows the create rule and is released once the layer retains it, the content view is released after the window retains it, and every early failure path releases what it acquired so far before logging and returning false.
On every other platform this function is a stub that returns false. The implementation in VulkanRenderer.cpp is compiled only when PLATFORM_OSX is not defined, and it exists for a link reason, not a behaviour one: without it the symbol would be satisfied from the VulkanRenderer.cpp object and the real Metal surface in VulkanRenderer.mm would silently never run. The stub must stay excluded on macOS.

Parameters

None.

Return value

true when surface holds a live Vulkan surface over the window's Metal layer; false when the window or instance is missing, any AppKit object failed to build, or vkCreateMetalSurfaceEXT failed — each failure logged with its reason or VkResult.

Examples

Illustrative — private, and reachable only through CreateSurface's macOS branch.

#if defined(PLATFORM_OSX)
	return CreateMetalSurface();
#endif

It is the only caller, and on macOS it is the surface step of Initialize.
