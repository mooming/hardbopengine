PickDevice

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private the first adapter with a graphics queue that can present to this surface, and the family index that comes with it

Signature

bool PickDevice() noexcept

Function description

Private. Chooses the adapter and the queue family in one pass, with one rule: the first device offering a queue family that supports both graphics and presentation to this surface. No preference for discrete over integrated, no scoring, no second candidate. Both results are stored together — physicalDevice and queueFamilyIndex — and the family index is reused later by CreateDevice for its single queue and by CreateCommandBuffers for the command pool. 

	for (uint32_t i = 0; i < count; ++i)
	{
		uint32_t qfCount = 0;
		vkGetPhysicalDeviceQueueFamilyProperties(devices[i], &qfCount, nullptr);
		std::vector<VkQueueFamilyProperties> queues(qfCount);
		vkGetPhysicalDeviceQueueFamilyProperties(devices[i], &qfCount, queues.data());

		for (uint32_t q = 0; q < qfCount; ++q)
		{
			if ((queues[q].queueFlags & VK_QUEUE_GRAPHICS_BIT) == 0)
				continue;

			VkBool32 presents = VK_FALSE;
			continueIf(vkGetPhysicalDeviceSurfaceSupportKHR(devices[i], q, surface, &presents) != VK_SUCCESS);
			continueIf(presents != VK_TRUE);

			physicalDevice = devices[i];
			queueFamilyIndex = q;

			return true;
		}
	}

Devices are enumerated twice — once for the count, once to fetch — and a count of zero is its own diagnosed case: the log names the usual causes, a missing VK_ICD_FILENAMES or no MoltenVK install, because an empty device list on a machine with a GPU usually means the loader never saw the driver. A device whose queue query fails for one family is skipped, not fatal — the loop simply tries the next family.

This is the step the capability probe cannot replace. QueryDefaultDeviceCapabilities takes the first enumerated device with no surface in play; picking for real additionally requires a graphics queue that can present, which only a surface makes askable. That is also why CreateSurface must run before this function — the order Initialize fixes is not stylistic.

Parameters

None.

Return value

true when a device and family were chosen and both members are set; false when enumeration failed, no device exists, or no family satisfied both requirements — each case logged through the always-on error logger.

Examples

Illustrative — private, and reachable only as the third step of Initialize.

if (!PickDevice())
	return false;

On success, CreateDevice consumes both members immediately.
