CreateCommandBuffers

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private the command pool and two primary buffers, one per frame in flight, resettable and re-recorded every frame

Signature

bool CreateCommandBuffers() noexcept

Function description

Private. Creates the command pool — for queueFamilyIndex, with VK_COMMAND_POOL_CREATE_RESET_COMMAND_BUFFER_BIT so each buffer can be reset and re-recorded every frame — and then allocates MAX_FRAMES_IN_FLIGHT (2) primary command buffers from it. The pool is the owner: destroying it in Destroy frees the command buffers with it, and no other code path frees them. 

	commandBuffers.assign(MAX_FRAMES_IN_FLIGHT, VK_NULL_HANDLE);
	VkCommandBufferAllocateInfo ai{};
	ai.sType = VK_STRUCTURE_TYPE_COMMAND_BUFFER_ALLOCATE_INFO;
	ai.commandPool = commandPool;
	ai.level = VK_COMMAND_BUFFER_LEVEL_PRIMARY;
	ai.commandBufferCount = static_cast<uint32_t>(MAX_FRAMES_IN_FLIGHT);

From Engine/Renderer/Vulkan/VulkanRenderer.cpp, VulkanRenderer::CreateCommandBuffers()

Two buffers because MAX_FRAMES_IN_FLIGHT is two: the frame being recorded must not be the frame being presented, so each frame slot records into its own buffer and currentFrame selects it. The buffers are re-recorded from scratch every frame — RecordFrame begins each one with VK_COMMAND_BUFFER_USAGE_ONE_TIME_SUBMIT_BIT.

A failed allocation leaves the pool alive. If vkCreateCommandPool fails, nothing was created. If vkAllocateCommandBuffers fails, the pool stays — like the rest of the sequence there is no partial cleanup, and on a failed Initialize it is never destroyed.

Parameters

None.

Return value

true when the pool and both command buffers exist; false at the first failure — pool creation or buffer allocation — each logged with its VkResult.

Examples

Illustrative — private, and reachable only as the ninth step of Initialize.

if (!CreateCommandBuffers())
	return false;

The buffers it creates are the ones RecordFrame records into and EndFrame submits, indexed by currentFrame.
