Initialize

member of hbe::Renderer::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h [[nodiscard]] noexcept the only public route through eleven creation steps, and the only one that can fail

Signature

[[nodiscard]] bool Initialize(OS::Window* window) noexcept;

Function description

Two guards first: if the renderer is already initialized it returns true without doing anything, and a null window returns false immediately. Then eleven private steps run in a fixed order, each one returning false the moment it fails: 

CreateInstance       // asks for the surface, portability-enumeration and platform surface extensions
CreateSurface        // macOS: Metal layer via CreateMetalSurface — Windows: window handle — Linux: fails
PickDevice           // first adapter with a graphics queue that can present to this surface
CreateDevice         // one queue, VK_KHR_swapchain enabled; calls QueryCapabilities on success
CreateSwapchain      // chooses format, present mode, image count and `extent` — once, ever
CreateRenderPass     // colour + depth attachments, one subpass, one external dependency
CreateDepthResource  // depth image at `extent`, device local
CreateFramebuffers   // one per swapchain image
CreateCommandBuffers // one per frame in flight (2)
CreatePipeline       // shader modules from ShadersSpv.h, MeshVertex input, 128-byte push range
CreateSyncObjects    // two semaphores per slot plus a fence, fences created already-signalled

The order is not arbitrary and is not offered as a menu: the surface has to exist before a device can be picked, because queue-family presentation support is queried against that surface, and the render pass has to exist before framebuffers and before the pipeline that is created against it. QueryCapabilities runs inside CreateDevice, which is the first moment a real physical device exists — that is why GetCapabilities costs nothing afterwards, and why a renderer whose Initialize failed before that step reports an unqueried descriptor.

Geometry is deliberately not part of this: vertex and index buffers are created by SetMesh, not here, so a renderer can be initialized before any mesh exists and will present a cleared frame until one arrives.

Failure is final for this object, and it leaks what it built. A false return means the first step that failed — reported through the always-on error logger with its VkResult — and it leaves initialized false. Because Shutdown returns early when initialized is false, the instance, surface or device already created are never destroyed: there is no partial-cleanup path and no public way to force one. Retrying Initialize on the same object would build a second set on top of the first. Treat a false return as "this object is finished" — which is what the example does, by exiting.
On macOS this call touches AppKit, and the header never says so. CreateSurface is CreateMetalSurface there, and that function reads the window's native handle, builds a layer-backed content view and calls [nsWindow setContentView:] — AppKit work, which AppKit itself expects on the main thread. Nothing here checks the thread, records it, or documents the requirement; the example happens to call Initialize from main. See OSAL: Window for the facade that hands out the handle.

Parameters

ParameterTypeRequirement
window OS::Window* The concrete facade — a class, not an interface; there is no IWindow in this tree. Must be non-null, must already have a native handle, and must outlive the renderer: the pointer is stored, used again for the fallback extent inside CreateSwapchain, and never closed or freed by this class. It is read during Initialize only — after that the renderer never asks the window for anything, which is why GetExtent cannot follow a resize. The example shows window.get() from the std::unique_ptr that owns it

Return value

TypeWhat you get
bool true only when all eleven steps succeeded and the renderer is ready for the frame protocol. Also true when it was already initialized, which makes a repeated call harmless but tells you nothing new. false means a step failed: the engine builds without exceptions, so this bool is the entire failure channel, and [[nodiscard]] makes ignoring it a compile error. Two things callers tend to forget: SetMesh before a successful Initialize silently uploads nothing, and GetCapabilities may still report an unqueried descriptor
One device limit can fail this at the pipeline step. The pipeline layout requests a push-constant range of sizeof(PushConstants) — 128 bytes — for the vertex stage. Vulkan guarantees at least 128, so in practice this passes everywhere; on a device reporting a smaller maxPushConstantBytes, vkCreatePipelineLayout fails and Initialize returns false rather than trimming the block. PushConstants carries the mirror rule: the struct, the range and the GLSL push block have to agree.

Examples

The real caller: create the window, make it visible, construct the renderer, and honour the bool — with the logger flushed first because an initialization failure is diagnosed asynchronously.

From Applications/VulkanExample/Main.cpp

auto window = OS::CreateWindow("VulkanExample - Rotating Quad (Vulkan)", 800, 600);
if (!window)
{
        std::cerr << "Error: Failed to create window" << std::endl;
        return 1;
}

window->SetVisible(true);

// Vulkan-only: construct the concrete renderer directly (no factory, no inheritance).
VulkanRenderer renderer;
if (!renderer.Initialize(window.get()))
{
        // The logger is asynchronous: flush so its diagnostics survive this exit.
        Logger::Get().Flush();
        std::cerr << "Error: Failed to initialize Vulkan renderer" << std::endl;
        return 1;
}

const Mesh quad = MakeQuad();
renderer.SetMesh(quad);

Note the order of the last two lines: SetMesh comes after a successful Initialize, which is not a style preference — SetMesh returns at its first line when the renderer is not initialized, so geometry handed over earlier is dropped without a word.

The null-window contract, asserted by the module's own test:

From Engine/Renderer/RendererTest.cpp

// Initialize rejects a null window on purpose - the surface is built from the window,
// and queue family support is queried against that surface. The assertion said the
// opposite; it survived only because Assert() is compiled out in the Release build.
Assert(!renderer.Initialize(window), "Initialize must reject a null window");
