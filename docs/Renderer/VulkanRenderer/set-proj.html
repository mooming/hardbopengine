SetProj

member of hbe::Renderer::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h noexcept copy sixteen column-major floats into the projection slot — the left half of the combined viewProj the shader receives

Signature

void SetProj(const float* m) noexcept;

Function description

The body is std::memcpy(projMat, m, sizeof(projMat));. At record time this slot becomes the left operand of viewProj = projMat * viewMat, so the numbers you supply here are the ones that decide the depth range and the vertical direction of the image — the two places Vulkan differs from OpenGL, and the two this function silently inherits.

Vulkan's clip-space depth is [0, 1], not [-1, 1], and its framebuffer Y axis points down while a right-handed camera's points up. A matrix built for the other convention produces geometry clipped away at the near plane, or an image upside down, or both. The example's own helper carries that comment on its first line, and the renderer does nothing about it: no convention is enforced, no flag exists, and the pipeline compares depth with VK_COMPARE_OP_LESS against a clear value of 1.0.

Ask GetExtent for the aspect ratio, and expect to ask once. The example derives it from the swapchain extent rather than from the 800×600 it requested, because the drawable follows the window's content rect — and it derives it before the loop, which is the only correct placement while extent is fixed at Initialize. Recomputing the projection from a live window size every frame would stretch the image instead of widening the view, because the render pass, viewport and depth image stay at the startup extent.

Parameters

ParameterTypeRequirement
m const float* Sixteen readable float, column-major (element [col * 4 + row]), built for Vulkan's [0, 1] depth and Y-down framebuffer. Not null-checked and not length-checked — a bad pointer is undefined behaviour in the copy, not a rejected call. Values are copied during the call, so a stack array may be reused immediately. Usable before Initialize; the constructor's identity stays until this is called, which renders in raw object coordinates with no perspective at all

Return value

void. The numbers are never inspected, so a degenerate matrix is only discoverable on screen.

Examples

The example builds a Vulkan-correct perspective, sizes it from the renderer rather than the window, and sets it once:

From Applications/VulkanExample/Main.cpp

/// @brief Right-handed perspective mapped into Vulkan's [0, 1] depth and Y-down framebuffer.
void SetPerspective(float m[16], float fovRadians, float aspect, float nearZ, float farZ) noexcept
{
        std::memset(m, 0, sizeof(float) * 16);
        const float f = 1.0f / std::tan(fovRadians * 0.5f);
        m[0] = f / aspect;
        m[5] = -f; // Y flip: world +Y is screen up
        m[10] = farZ / (nearZ - farZ);
        m[11] = -1.0f;
        m[14] = farZ * nearZ / (nearZ - farZ);
}

// in main(), after Initialize returned true:
const VkExtent2D extent = renderer.GetExtent();
SetPerspective(proj, DegreeToRadian(60.0f),
               static_cast<float>(extent.width) / static_cast<float>(extent.height),
               0.1f, 100.0f);
renderer.SetProj(proj);

The engine's own matrix builders are in Math; whichever one is used, the sixteen floats handed to this function are the sixteen the shader multiplies with.
