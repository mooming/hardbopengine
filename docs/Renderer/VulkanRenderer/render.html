Render

member of hbe::Renderer::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h noexcept records this frame's command buffer — nothing is submitted or presented here, and the delta you pass is not read

Signature

void Render(float deltaTime) noexcept;

Function description

One guard, then one private call: returnIf(!(initialized && frameActive)); RecordFrame();. Despite the name, nothing is executed by this function — it fills commandBuffers[currentFrame], and EndFrame is what submits and presents it.

Recording is one pass and one draw, in this shape:

vkBeginCommandBuffer(commandBuffers[currentFrame], ONE_TIME_SUBMIT)
        // framebuffer = framebuffers[imageIndex], renderArea = extent
        // clear colour (0.06, 0.08, 0.12, 1) and depth 1.0, stencil 0
        vkCmdBeginRenderPass → vkCmdBindPipeline
        vkCmdSetViewport / vkCmdSetScissor   // dynamic state, taken from `extent`
        if (indexCount > 0 && vertexCount > 0)
        {
                PushConstants push{};
                push.model    = modelMat;                     // copied
                push.viewProj = projMat * viewMat;            // multiplied here, on the CPU
                vkCmdPushConstants(vertex stage, offset 0, sizeof(PushConstants))
                vkCmdBindVertexBuffers → vkCmdBindIndexBuffer(UINT32)
                vkCmdDrawIndexed(indexCount, 1, 0, 0, 0)
        }
        vkCmdEndRenderPass()
vkEndCommandBuffer()

The multiplication is the reason PushConstants is only two matrices wide: view and projection are combined once per frame on the CPU so that a 128-byte push block can carry both a combined viewProj and a model matrix. The multiply is projMat * viewMat, column-major, so a shader evaluating viewProj * model * position sees the order it expects.

Because the matrices are read at record time, the position of the setters in your loop decides which frame they land in: SetModel before this call affects this frame, after it affects the next. And because the draw is conditional on both counts being non-zero, a renderer with no mesh, or one whose upload failed, records a clear and a present with no draw — the background colour without a shape.

deltaTime is accepted and discarded. The definition spells the parameter out as float /*deltaTime*/, and the body never mentions it: nothing in the recorded frame depends on elapsed time, because the animation in the example is driven by the caller's own angle accumulator. The previous module page presented this argument as the frame delta feeding the render; it does not feed anything. Pass the real delta if you want the call site to be future-proof, but do not assume animation, motion blur or time-based uniforms will follow from it.
Calling Render twice before BeginFrame re-records a command buffer that may still be running. The guard tests frameActive, and EndFrame does not clear that flag — it stays set after a successful frame. A second Render in the same slot therefore calls vkBeginCommandBuffer on a buffer whose previous submission has not been waited on, which is invalid use of a ONE_TIME_SUBMIT buffer, and the matching second EndFrame submits it again. A Render with no BeginFrame at all in this cycle is exactly as wrong, and is the one case the module's test asserts is harmless on a renderer that never initialized. Keep the three calls one-for-one.
A failed vkBeginCommandBuffer still ends in a submit. RecordFrame logs and returns early when begin fails, but EndFrame submits commandBuffers[currentFrame] whenever frameActive is set — so a command buffer that was never begun, and never ended, goes to vkQueueSubmit. The observable result is a submit error on top of the begin error, not a skipped frame; there is no state flag separating "recorded" from "attempted".

Parameters

ParameterTypeRequirement
deltaTime float Seconds since the previous frame by convention — the example measures it with std::chrono::duration<float>, and SystemStatistics::GetDeltaTime is the engine's equivalent. The implementation discards it; any value, including 0, produces the same command buffer today

Return value

void, with no status channel: a frame that recorded nothing because frameActive was false is indistinguishable from one that recorded a full pass, and a failed vkBeginCommandBuffer is reported only through the error logger. If your code needs to know, the observable proxies are the counts — no mesh means no draw — or the log.

Examples

The example measures a real delta, uses it for its own animation, and passes it in anyway:

From Applications/VulkanExample/Main.cpp

        static auto lastTime = std::chrono::high_resolution_clock::now();
        auto currentTime = std::chrono::high_resolution_clock::now();
        float deltaTime = std::chrono::duration<float>(currentTime - lastTime).count();
        lastTime = currentTime;

        angle += deltaTime * 1.2f;
        if (angle > 2.0f * Pi)
                angle -= 2.0f * Pi;

        SetRotationY(model, angle);
        renderer.SetModel(model);

        renderer.BeginFrame();
        renderer.Render(deltaTime);
        renderer.EndFrame();
