GetCapabilities

member of hbe::Renderer::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h const noexcept [[nodiscard]] returns by value the cached descriptor of the device this renderer picked — one copy, no driver call

Signature

[[nodiscard]] RenderCapabilities GetCapabilities() const noexcept;

Function description

return capabilities;. That field was written once, by QueryCapabilities at the end of CreateDevice, which forwards the chosen VkPhysicalDevice to FillRenderCapabilities — the same adapter RHICapabilities::GetCapabilities uses. So the call is a struct copy, safe at any point in the frame loop, and it describes the device this renderer actually selected: the first adapter with a graphics queue that can present to this surface, not merely the first the driver enumerates.

The three states a caller can find it in are worth naming. Before Initialize — or after one that failed before CreateDevice — it is the zero-filled unknown descriptor, with isDeviceQueried == false. After a successful Initialize it is real: name, class, ids, the twenty-one flags and the eighteen limits, read from the driver. After Shutdown it is still the real one, because Destroy resets handles and frame counters but not this field — so a queried result after teardown describes a device that no longer exists.

It returns a copy, not a reference — and the previous module page said otherwise. The header declares RenderCapabilities GetCapabilities() const noexcept; the old page documented const RenderCapabilities&. Binding the result to a const reference (const auto& caps = renderer.GetCapabilities();) is still safe, because the temporary's lifetime is extended by that binding — but caching the address of the result (const RenderCapabilities* p = &renderer.GetCapabilities();) leaves a dangling pointer to a destroyed temporary. Copy it: the type is trivially copyable by an assertion in its own header, and that is the intended way to move it.
Once a device exists, this is the answer to prefer. RHICapabilities::GetCapabilities creates and discards a Vulkan instance to read the first enumerated device, and may describe a different adapter than the one running your frames. Prefer this call for anything after Initialize, and prefer RHICapabilities only for the genuine before-a-window questions. Either way, isDeviceQueried has to be checked before any limit is read: see RenderCapabilities.

Parameters

None.

Return value

TypeWhat you get
RenderCapabilities (by value) A copy of the cached descriptor. isDeviceQueried == true only after a Initialize that reached CreateDevice, and the supportsComputeShader bit inside it is true by definition on Vulkan — Vulkan makes compute mandatory in core, so that bit is not a measurement. [[nodiscard]], so dropping the copy is a compile error

Examples

The module's own test, which pins the state that matters most — a renderer without a device must not claim one — and in doing so documents why the descriptor is never compared with memcmp:

From Engine/Renderer/RendererTest.cpp

AddTest("VulkanRenderer capabilities are unqueried before Initialize", [](auto& log)
{
        VulkanRenderer renderer;
        const RenderCapabilities caps = renderer.GetCapabilities();

        log << "isDeviceQueried=" << caps.isDeviceQueried << " maxTextureDimension2D=" << caps.maxTextureDimension2D;

        // No device exists yet, so the only honest answer is "unknown". An uninitialised
        // renderer used to answer 4096/16/16 as if it had asked the hardware.
        Assert(!caps.isDeviceQueried, "A renderer without a device must not claim queried capabilities");
        Assert(caps.maxTextureDimension2D == 0, "A renderer without a device must not report a texture limit");
});

AddTest("VulkanRenderer capabilities match an unknown descriptor", [](auto& log)
{
        VulkanRenderer renderer;
        const RenderCapabilities caps = renderer.GetCapabilities();
        const RenderCapabilities unknown;

        // Field-by-field, because the descriptor is a bit-field struct and holds a fixed array,
        // so memcmp would compare padding and could report a difference that is not one.
        Assert(caps.isDeviceQueried == unknown.isDeviceQueried, "Unqueried flag must match");
        Assert(caps.maxTextureDimension2D == unknown.maxTextureDimension2D, "Unqueried 2D limit must match");
});

The same shape works in an application: copy it out once after Initialize succeeded, then read maxTextureDimension2D, maxPushConstantBytes or deviceType from your own copy without touching the renderer again.
