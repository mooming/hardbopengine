Shutdown

member of hbe::Renderer::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h noexcept tear the whole Vulkan set down — safe to call twice, safe to call before Initialize, safe because the destructor calls it anyway

Signature

void Shutdown() noexcept;

Function description

The body is a guard and a call: return immediately when initialized is false, otherwise run the private Destroy and clear the flag. That single guard is what makes the function idempotent and what makes the destructor free to call it unconditionally — an object that never initialized, or one already shut down, destroys nothing because there is nothing recorded as owned.

Destroy opens with vkDeviceWaitIdle, which is the only place this class waits for the GPU outside the frame loop, and then destroys in dependency order: the two semaphore arrays and the fences, the mesh's vertex and index buffers, the command pool (which frees its command buffers with it), the pipeline, pipeline layout and both shader modules, the framebuffers, the depth view then image then memory, the swapchain image views then the swapchain, the logical device, and last the surface and the instance. Every handle is set to VK_NULL_HANDLE afterwards.

After a clean Shutdown the object is reusable: initialized is false and the handles are null, so Initialize will build a new set — including re-reading the extent from the window, which is the only way in this API to pick up a resized window. The distinction worth keeping in mind is between a clean shutdown, which can be re-initialized, and a failed Initialize, which cannot, because that path never reaches this function's cleanup.

The window is left alone on purpose. Shutdown destroys the surface that was built from the window's native handle and nothing else: it does not close, hide or free the OS::Window, which the renderer only ever borrowed. The example therefore closes the window on the line after the call — closing it first would yank the handle out from under a surface that is still alive.

Parameters

None.

Return value

void. The Vulkan destroy entry points return nothing, so there is no failure to report even in principle. What you can observe afterwards is the flag the getters key off: initialized is false, so the frame calls become no-ops again — while GetCapabilities and GetExtent keep returning the pre-shutdown values, because Destroy resets handles and frame counters but not answers.

Examples

The example finishes the loop, shuts the renderer down, and only then closes the window and the engine:

From Applications/VulkanExample/Main.cpp

renderer.Shutdown();
window->Close();
hengine.ShutDown();

return 0;

The same call on a renderer that never got a device is the second half of the module's round-trip test, and it must not crash — see the destructor page for that quote.
