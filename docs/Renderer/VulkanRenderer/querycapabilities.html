QueryCapabilities

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private one call: translate the picked physical device into the neutral descriptor GetCapabilities returns

Signature

void QueryCapabilities() noexcept

Function description

Private, and one call long: it forwards physicalDevice to FillRenderCapabilities, which resets capabilities to the all-unknown state and fills it from the device's properties and features. The translation is the adapter's job, not this function's — this function only decides when the translation happens.

And when matters: the only caller is CreateDevice, immediately after the logical device is created, which is the first moment a real physical device exists in this object. Before that point capabilities is the default-constructed, unqueried descriptor — which is what GetCapabilities would report from a renderer whose Initialize failed earlier in the sequence. There is no re-query: capabilities are read once per Initialize and never refreshed.

Parameters

None.

Return value

None — void. The result lands in the private capabilities member, which callers read through GetCapabilities.

Examples

The call site is the entire story, and it is real:

From Engine/Renderer/Vulkan/VulkanRenderer.cpp, VulkanRenderer::CreateDevice()

	vkGetDeviceQueue(device, queueFamilyIndex, 0, &graphicsQueue);

	QueryCapabilities();

Nothing between the two lines: the queue fetch and the capability query are one breath, and both assume physicalDevice is valid, which PickDevice guaranteed two steps earlier.
