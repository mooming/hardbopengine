CreateDepthResource

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private the depth image at extent: create, allocate device local, bind, view — in that order

Signature

bool CreateDepthResource() noexcept

Function description

Private. Builds the depth attachment in four steps, in this order and no other: create the image at extent in depthFormat with optimal tiling and depth-stencil usage, query its memory requirements, allocate device-local memory for it, bind, then create the VK_IMAGE_ASPECT_DEPTH_BIT view. depthFormat was decided one step earlier by CreateRenderPass; the image is sized to the same extent CreateSwapchain captured. 

	if (!FindMemoryType(physicalDevice, req.memoryTypeBits, VK_MEMORY_PROPERTY_DEVICE_LOCAL_BIT, ami.memoryTypeIndex))
	{
		LogFailure("no device local memory type for the depth image");
		vkDestroyImage(device, depthImage, nullptr);
		depthImage = VK_NULL_HANDLE;

		return false;
	}

From Engine/Renderer/Vulkan/VulkanRenderer.cpp, VulkanRenderer::CreateDepthResource()

Only the first failure path cleans up after itself. If no device-local memory type fits, the image is destroyed and nulled before returning false — the block above. But a failed vkAllocateMemory, a failed vkBindImageMemory, or a failed view creation return false leaving the earlier handles allocated, and nothing in this function destroys them. Since Initialize aborts the sequence and Shutdown early-returns when initialized is false, those handles are never freed. This is the same shape the Initialize page documents for the sequence as a whole: partial failure leaks what was built.

Parameters

None.

Return value

true when depthImage, depthMemory and depthImageView all exist and are bound; false at the first failure, each logged — with the image additionally destroyed on the no-memory-type path only.

Examples

Illustrative — private, and reachable only as the seventh step of Initialize.

if (!CreateDepthResource())
	return false;

The view it produces is attached to every framebuffer CreateFramebuffers creates — one depth view shared by all swapchain images, since only one image is rendered at a time.
