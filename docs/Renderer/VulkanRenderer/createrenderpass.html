CreateRenderPass

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private colour plus depth attachments, one subpass, and the external dependency that keeps writes behind the acquire

Signature

bool CreateRenderPass() noexcept

Function description

Private. Builds the one render pass the whole pipeline renders through: two attachments, one subpass, one external dependency. The colour attachment is the swapchain's format — cleared, stored, and left in VK_IMAGE_LAYOUT_PRESENT_SRC_KHR so presentation can take it straight away. The depth attachment is cleared and then discarded (VK_ATTACHMENT_STORE_OP_DONT_CARE), because nothing reads depth back after the frame.

The depth format is chosen here, not by the depth resource: the first of VK_FORMAT_D32_SFLOAT, VK_FORMAT_D24_UNORM_S8_UINT and VK_FORMAT_D16_UNORM that this device can actually use as a depth-stencil attachment, tested in that order. The winner is stored in depthFormat, which CreateDepthResource then builds the image from — so this step must precede that one, and it does. 

	depthFormat = VK_FORMAT_D32_SFLOAT;
	if (!HasDepthSupport(physicalDevice, depthFormat))
		depthFormat = VK_FORMAT_D24_UNORM_S8_UINT;
	if (!HasDepthSupport(physicalDevice, depthFormat))
		depthFormat = VK_FORMAT_D16_UNORM;

From Engine/Renderer/Vulkan/VulkanRenderer.cpp, VulkanRenderer::CreateRenderPass()

The single external dependency is the synchronisation contract of the whole frame loop: it stops the render pass from writing colour or depth until the previous present has finished, because the acquire semaphore is waited on outside the pass. If the pass started writing earlier, two frames could touch the same image.

The two attachment descriptions must stay contiguous. The source says so on purpose: pAttachments is indexed by the attachment references — colour is index 0, depth is index 1 — and a split or reordered array would silently renumber them.

Parameters

None.

Return value

true when vkCreateRenderPass succeeded and renderPass and depthFormat are both set; false when the pass creation failed, logged with its VkResult.

Examples

Illustrative — private, and reachable only as the sixth step of Initialize.

if (!CreateRenderPass())
	return false;

Two consumers follow immediately: CreateDepthResource uses depthFormat, and both CreateFramebuffers and CreatePipeline need the pass itself.
