CreateFramebuffers

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private one framebuffer per swapchain image, each pairing that image's view with the one depth view

Signature

bool CreateFramebuffers() noexcept

Function description

Private. One framebuffer per swapchain image, each pairing that image's colour view with the single shared depthImageView, sized to extent, one layer, against renderPass. The vector is pre-sized to the view count before the loop, so a failure mid-loop leaves earlier entries valid and later entries null — the class pages that index this vector (BeginFrame, which bounds-checks imageIndex against its size) rely on the count matching the swapchain image count. 

	framebuffers.assign(swapchainImageViews.size(), VK_NULL_HANDLE);
	for (size_t i = 0; i < swapchainImageViews.size(); ++i)
	{
		const VkImageView attachments[2] = {swapchainImageViews[i], depthImageView};
		VkFramebufferCreateInfo ci{};
		ci.sType = VK_STRUCTURE_TYPE_FRAMEBUFFER_CREATE_INFO;
		ci.renderPass = renderPass;
		ci.attachmentCount = 2;
		ci.pAttachments = attachments;
		ci.width = extent.width;
		ci.height = extent.height;
		ci.layers = 1;
		const VkResult result = vkCreateFramebuffer(device, &ci, nullptr, &framebuffers[i]);
		if (result != VK_SUCCESS)
		{
			LogFailure("vkCreateFramebuffer", result);

			return false;
		}
	}

From Engine/Renderer/Vulkan/VulkanRenderer.cpp, VulkanRenderer::CreateFramebuffers()

A mid-loop failure leaves the earlier framebuffers alive. Like the rest of the creation sequence, there is no partial cleanup: the function logs the VkResult and returns false, and the already-created framebuffers stay in the vector. On the failed Initialize they are never destroyed — see the failure-path note on CreateDepthResource and the Initialize page's account of the whole sequence.

Parameters

None.

Return value

true when one framebuffer exists per swapchain image; false at the first failed vkCreateFramebuffer, logged with its VkResult.

Examples

Illustrative — private, and reachable only as the eighth step of Initialize.
