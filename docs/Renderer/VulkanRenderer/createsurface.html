CreateSurface

member of hbe::VulkanRenderer Engine/Renderer/Vulkan/VulkanRenderer.h private platform dispatch — Metal layer on macOS, window handle on Windows, false everywhere else

Signature

bool CreateSurface() noexcept

Function description

Private. The platform dispatch point for the window surface: on macOS it hands the whole job to CreateMetalSurface, on Windows it builds a Win32 surface from the window's native handle, and on every other platform it fails without trying. 

#if defined(PLATFORM_OSX)
	return CreateMetalSurface();
#elif defined(PLATFORM_WINDOWS) && defined(VK_USE_PLATFORM_WIN32_KHR)
	VkWin32SurfaceCreateInfoKHR info{};
	info.sType = VK_STRUCTURE_TYPE_WIN32_SURFACE_CREATE_INFO_KHR;
	info.hwnd = reinterpret_cast<HWND>(window->GetNativeHandle());

	return vkCreateWin32SurfaceKHR(instance, &info, nullptr, &surface) == VK_SUCCESS;
#else
	return false;
#endif

From Engine/Renderer/Vulkan/VulkanRenderer.cpp, VulkanRenderer::CreateSurface()

The Windows branch has never been compiled on this machine. Its own source note says so — the development environment is macOS-only — so the path is written but unverified, and the macOS path is the one the three-configuration build actually exercises. On the remaining platforms there is no backend: Linux would need OS::Window to expose its X11 Display*, and GetNativeHandle currently returns only the window id, so the function returns false there and Initialize fails with it.
The Windows branch does not log its failure. It returns the raw VkResult comparison without a LogFailure call, so a failed surface creation there is silent except for the false Initialize returns.

Parameters

None.

Return value

true when the platform surface exists and surface holds a live handle: the macOS answer is CreateMetalSurface's, the Windows answer is vkCreateWin32SurfaceKHR's. false on any failure — including every platform with no backend at all, which is a permanent condition, not a transient one.

Examples

Illustrative — private, and reachable only as the second step of Initialize.

if (!CreateSurface())
	return false;

The surface must exist before device picking: PickDevice queries queue families for presentation support against this surface, which is why it runs third and cannot run earlier.
