IsVulkanSupported

member of hbe::Renderer::RHICapabilities Engine/Renderer/RHICapabilities.h [[nodiscard]] noexcept whether this build was compiled against a Vulkan SDK — a compile-time answer, not a probe

Signature

[[nodiscard]] static bool IsVulkanSupported() noexcept;

Function description

The definition is the macro: it returns VULKAN_SDK, defined in Config/BuildConfig.h as 1 when __has_include found vulkan/vulkan.h in one of four search locations and 0 otherwise. No Vulkan entry point is called, no loader is loaded and no device is enumerated, so the answer cannot vary between two runs on the same binary — it is a property of the build.

What the flag therefore records is header presence at compile time: the machine that built the binary had the SDK. It says nothing about the machine that runs it. A binary built with the SDK returns true on a host with no loader, no installable client driver and no graphics hardware, because nothing at this point in the function could find out.

Do not use this to decide whether the engine can render. It answers "was this compiled with Vulkan", and the honest runtime question — "is there a device here" — is answered only by GetCapabilities and its isDeviceQueried flag, or by the bool from VulkanRenderer::Initialize. Reading this bool as availability produces exactly the failure the deleted guide encouraged: code that branches on an API kind and then assumes a device behind it.

Parameters

None.

Return value

TypeWhat you get
bool true when the translation unit was compiled with VULKAN_SDK set to 1 — that is, the SDK headers were reachable from one of the four paths BuildConfig.h probes. false when they were not, in which case BuildConfig.h also emits a #pragma message naming the per-platform install script. Constant either way, and [[nodiscard]]
The macro's tolerance is not the module's tolerance. BuildConfig.h treats a missing SDK as a warning — "code will still compile" — but Engine/Renderer/CMakeLists.txt makes it fatal for this target: find_path(vulkan/vulkan.h …) and find_library(vulkan …) both FATAL_ERROR, with the comment "The engine is Vulkan-only, so a missing loader is a hard error, not a silent skip." No header in this module guards its #include <vulkan/vulkan.h> on VULKAN_SDK either. In this tree the renderer therefore does not compile out: configure fails. See module variables.

Examples

The only call site in the repository is this module's own test, which reports the value rather than branching on it — the correct treatment, since a build-time constant cannot tell you anything about the machine running the test.

From Engine/Renderer/RHICapabilities.cpp

AddTest("IsVulkanSupported", [](auto& ls)
{
        auto supported = Renderer::RHICapabilities::IsVulkanSupported();
        ls << (supported ? "true" : "false");
});

No code under Engine/ or Applications/ calls this function otherwise, and Engine exposes no renderer accessor at all, so today the value is diagnostic output rather than an input to a decision.
