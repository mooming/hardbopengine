GetCapabilities

member of hbe::Renderer::RHICapabilities Engine/Renderer/RHICapabilities.h [[nodiscard]] noexcept creates and discards a Vulkan instance what this machine can do, probed before any renderer exists

Signature

[[nodiscard]] static RenderCapabilities GetCapabilities() noexcept;

Function description

Builds a throwaway Vulkan instance, enumerates physical devices, hands the first one to FillRenderCapabilities — the same translator the renderer uses, so the field values are real driver answers — and destroys the instance before returning. The descriptor arrives by value; nothing is cached, so a second call does the whole thing again.

The instance it creates asks for VK_KHR_portability_enumeration only when the loader advertises it. That conditional is deliberate and is the one behavioural difference from VulkanRenderer::CreateInstance, which requests the extension unconditionally: conforming drivers need not offer it, and enabling an extension the loader does not know fails instance creation outright, which for a probe would mean reporting "no device" on a machine that has one.

This is not a cheap query, and once a device exists it is the wrong one. Every call pays for instance creation, device enumeration and instance destruction. Worse, it describes the first device the driver enumerates, whereas VulkanRenderer::Initialize picks the first device whose queue family can also present to the real surface — on a machine with more than one adapter, these can be different devices. After a renderer exists, call VulkanRenderer::GetCapabilities: it returns the cached descriptor of the device actually chosen, and costs a copy.

Nothing about a failed probe is fatal. When instance creation fails, or no physical device is enumerated, or the fetch fails, the failure is logged at warning level — no loader, no installable client driver or an incompatible driver is a legitimate environment such as headless continuous integration — and the caller keeps a descriptor whose isDeviceQueried is false. That flag is the branch a caller must write; there is no error code and no exception, because the engine builds without exceptions.

Parameters

None.

Return value

TypeWhat you get
RenderCapabilities (by value) A real descriptor with isDeviceQueried == true when a device answered — name, class, ids, feature bits and limits, all read from the driver. Or a copy of the zero-filled unknown descriptor when nothing could be probed, which is a valid answer rather than a failure to handle. [[nodiscard]], so throwing either away is a compile error

Examples

The branch every caller needs: test the flag before reading a number, and treat an unqueried result as "this machine has nothing to compare against" rather than "this feature is missing".

From Engine/Renderer/RHICapabilities.cpp

AddTest("GetCapabilities reports what the device supports", [](auto& ls)
{
        const Renderer::RenderCapabilities caps = Renderer::RHICapabilities::GetCapabilities();

        if (!caps.isDeviceQueried)
        {
                // No loader, no ICD, or an incompatible driver - a legitimate environment (headless
                // CI, a machine without MoltenVK), so there is nothing to compare against.
                ls << "no Vulkan device available; query skipped";
                return;
        }

        // Identity has to survive the fixed-size copy, and the API version has to be real.
        Assert(caps.deviceName[0] != '\0', "A queried device must report a name");
        Assert(caps.apiVersionMajor >= 1, "A Vulkan device must report API version 1 or newer");
        Assert(caps.maxTextureDimension2D >= 2048, "A Vulkan device supports at least 2048 texels");
});

Two properties the same file asserts are worth copying into any caller: repeated probes must agree on the flag, on the limits and on the name, and a queried device must classify itself as something other than DeviceType::Unknown — the second of those is the one that will fire on a driver reporting VK_PHYSICAL_DEVICE_TYPE_OTHER, which the adapter also maps to Unknown.
