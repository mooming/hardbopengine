OSAL platform split design

The OSAL reference pages own what a caller depends on; this document owns the platform-selection architecture behind them — how one declaration set reaches three operating systems, what the fallback units are for, and the memory semantics the test suite pins. Every claim was read from Engine/OSAL/.

The platform-split pattern

Every OSAL header declares one interface; per-platform units define it. The selection happens at build time: #if defined(PLATFORM_LINUX), PLATFORM_OSX and PLATFORM_WINDOWS choose which Linux*.cpp, OSX*.mm or Win32*.cpp translation unit compiles, exactly the seam the VulkanCapabilities page describes for renderer backends. The public interface is identical across platforms — the class reference of Window or Application states the contract once, and the platform implementations are where the divergence lives. Platform-specific detail that a caller depends on is documented on the owning method page with the file it was read from; this document carries only the pattern itself.

The fallback role of the OS*.cpp units

The OS*.cpp units (OSMemory.cpp, OSAbstractLayer.cpp, OSInputOutput.cpp, OSDebug.cpp, OSThread.cpp) are fallback implementations, compiled only when no platform-specific file is. A build with PLATFORM_LINUX, PLATFORM_OSX or PLATFORM_WINDOWS defined uses the corresponding platform unit instead; the fallback exists so a target with no platform macro still links, and its guards skip the body when a platform implementation is being compiled. It is not a third implementation to keep correct — it is the shape that keeps an unconfigured build honest.

VirtualAlloc and VirtualFree semantics the tests pin

Three behavioural facts the memory tests of OSMemory.cpp pin down, each the record of a defect that once shipped:

  • VirtualFree returns non-zero on success and zero on failure — the Windows error check was once inverted, so a successful free tripped the assert. The check is now if (!result), asserting only on actual failure.
  • On Linux and macOS VirtualFree maps to munmap, not free — the round-trip test verifies that a VirtualAlloc/VirtualFree pair works on every platform rather than only where the call is native.
  • The size parameter reaches the implementation on every platform — a revision once compiled with the parameter unnamed while the body referenced it. The test frees with an explicit size to pin the pass-through.

The page size, where the platform exposes one, must be a power of two — the test asserts it, and the callers that align with it rely on that.
