Engine clock design

One epoch, read constantly, written once — and the defect that shape exists to prevent
Scope. This document owns how Engine/Core/Time.cpp represents engine time and why. The callable contract — what Sleep, ResetEngineEpoch and SetBaseFrameRate promise a caller — is on the reference pages, and the thread-safety claims belong there too.

One epoch for the whole engine

Task deadlines, Render's deltaTime and the log timestamps all measure against a single value, so a deadline set by one subsystem cannot drift away from another reading the same span. Two clocks that agree by accident disagree as soon as one of them is re-based.

The epoch is deliberately taken from the steady clock rather than the wall clock, because an epoch that jumps when the system clock is adjusted would silently expire every deadline in flight — or never expire any of them. A deadline is a statement about elapsed engine time, and only a monotonic source makes that statement mean anything.

Representation: an atomic counter, not a time point

The epoch is held as nanoseconds since the steady clock's own epoch, in an atomic counter rather than a time_point. The reason is the read/write asymmetry: the epoch is read on every deadline check and every frame delta, while it is written at most once, by whoever constructs the engine. A counter makes the hot side a single acquire load.

Initialised on first use, and the D5 defect

The epoch is initialised on first use, which is what keeps the clock meaningful in a process that never builds an Engine. A zero-initialised epoch reads as decades since 1970 — the D5 defect — and a timestamp that far in the past does not announce itself as a bug: it silently ages out every piece of work in the system the first time anything measures it.

The epoch is reachable without Engine::Get, which asserts that an instance exists. Logging has to work in a process that never constructed an Engine, and a clock requiring one would reintroduce exactly that crash. If nothing has set the epoch, it is the first instant anyone asks for, so readings stay meaningful instead of counting from 1970.

Where else to look

The task mechanisms that measure against this epoch are in Task system internals; the CPU budget that bounds a task's consumption is CPUBudget; the logger that stamps with it is Log.
