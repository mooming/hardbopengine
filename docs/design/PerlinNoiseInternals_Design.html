Perlin noise internals design

The PerlinNoise reference page owns what a caller depends on; this document owns the implementation decisions in Engine/Math/PerlinNoise.cpp — how the permutation table is built and indexed, and why the shuffle is specified by arithmetic instead of delegated to the standard library. Every claim here was read from that file.

The permutation table and its doubling

The shuffle is a Fisher-Yates walk over the low half of the table only: the class's At() lookup indexes a doubled table (p[p[p[x] + y] + z]), so only the first 256 entries need to be a permutation — the upper half is the mirror that saves the double-mask the classic formulation performs. The instance's seed fixes the permutation, which is what GetSeed reports.

Negative coordinates wrap, not truncate

The lattice coordinate is cast to the table's unsigned index before the mask is applied. Casting after masking would truncate negative coordinates toward zero, making -0.5 and +0.5 collide with their positive mirror and produce a seam at the origin; casting first wraps them into the table, which is the behaviour the continuity test relies on.

The shuffle is specified, not delegated

The random source behind the Fisher-Yates walk is a golden-ratio counter finalized with the Murmur3 finalizer — every step specified by arithmetic rather than by a library implementation detail. That is the whole point: the shuffle, and therefore the noise a given seed produces, must be identical on every platform. A std::mt19937-based shuffle would tie the noise field to the standard library's implementation, which is allowed to differ.

Ken Perlin's reference gradient selection

The gradient function is Ken Perlin's reference selection for "improved noise" — the twelve edge directions of a cube picked by bit manipulation of the hashed value. It is the published reference behaviour, not a re-derivation, so the noise matches the reference implementation's character.

Why the continuity test is shaped the way it is

Perlin noise is C1 continuous, so a small step in the input must give a proportionally small change in the output. A discontinuity — a wrong fade curve, or a seam at the table period — shows up as a jump comparable to the size of the signal itself, which is why the test samples small steps and near the table period specifically. Negative coordinates and a coordinate past the table period are table indexing traps rather than math problems, so they are sampled on purpose.
