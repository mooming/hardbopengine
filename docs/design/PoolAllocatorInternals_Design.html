Pool allocator internals

Implementation design for Engine/Memory/PoolAllocator.cpp. The caller-facing contract — what PoolAllocator hands out, when it refuses, and what the free-list terminator means — lives on the reference pages; what is recorded here is the geometry those pages depend on, and the reasoning behind the guard testlets.

A free block has to hold the link

A free block stores the next-index link that keeps the free list threaded, so a block smaller than TSize cannot be supported at all. That makes it a precondition rather than something to clamp away, and the constructor treats it as an input error rather than a size worth probing. The block-size range a pool accepts still covers every size above that floor, including the ones alignment rounds up.

Both operands of the capacity arithmetic are members

blockSize is the aligned size every later path uses too — AllocateBlock, Deallocate and GetCapacity. The parameters carry the in prefix precisely so no unqualified name in that arithmetic can silently resolve to the unaligned request instead.

The stride the free list is laid out with

The constructor rounds blockSize up to Config::DefaultAlign, so a request that is not already aligned is the case that matters: the pool used to lay its free list out with the requested stride while walking it with the aligned one, which quietly handed the same block to two callers. The guard testlet therefore probes three sizes. 32 is there because it needs no rounding and so proves the rounding is not over-reaching; 24 is what LinkedList nodes ask for; and 100 lands mid-way between two multiples. Each request in the testlet is 16 bytes, which fits every aligned size in that table, so what the guard exercises is the pool's own block path and never a fallback.

Walking the free list twice

The guard walks the released blocks twice over. A mis-linked free list survives the first pass and only shows itself once the released blocks are walked again.

Check the address, not the stride

Rounding the stride to Config::DefaultAlign only buys aligned addresses if the pool buffer itself is aligned, so the guard asserts on the address of each block rather than on the stride.
