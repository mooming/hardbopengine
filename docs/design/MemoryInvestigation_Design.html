Memory investigation self-tests

Implementation design for the investigator self-tests at the end of Engine/Memory/SystemAllocator.cpp. The checks themselves belong to SystemAllocator; this document records how the three self-tests are meant to be run, because each one is designed to stop the process, which makes a run without these notes look like a crash.

Which switch turns on what

SwitchEffect
MEMORY_INVESTIGATOR_TEST_ENABLEDGates the whole self-test region, and it sits inside __TEST__, so the tests exist only in a test build.
MEMORY_INVESTIGATION_ENABLEDGates the checks themselves. With it off there is nothing to detect, and the region compiles to nothing.
MEMORY_BUFFER_UNDERRUN_CHECK_ENABLEDSelects the under-run testlet, and its #else branch holds the over-run testlet — see below.
MEMORY_DANGLING_POINTER_CHECK_ENABLEDAdds the use-after-free testlet.

Why a self-test ends the process

Each testlet allocates one byte and then writes deliberately outside what it is allowed to: one byte before the block for the under-run test, one byte past it for the over-run test, and the first byte of a block it has already released for the dangling-pointer test. The point is that the investigator must react, and the reaction is a signal, so the run stops on that line. The three comments that used to sit on those writes told the reader to comment the write out to reach the next testlet: the deliberate write is the end of that testlet by design, and a passing investigator is observed as the signal it posts, not as the testlet returning.

The over-run test is the branch where the under-run check is off

The two buffer testlets are #if and #else of a single switch, so a build gets the under-run test when MEMORY_BUFFER_UNDERRUN_CHECK_ENABLED is on and the over-run test when it is off. That is recorded here as the shape of the code rather than as an intent: nothing in the switches says that over-run coverage is the reward for disabling the under-run check, so whichever was meant, the two cannot both be exercised in one build.

Two shapes that look wrong rather than designed

  • The over-run testlet writes buffer - 1 before it writes past the end, so it commits an under-run while standing in the branch compiled with the under-run check disabled. If the branch is meant to isolate the over-run case, that write does not belong to it.
  • The dangling-pointer testlet announces itself as Overrun Test: in its own log line. The test is a use-after-free test, and the label would send a reader looking in the wrong place.
