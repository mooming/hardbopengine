Get

member of hbe::ConfigParam Engine/Config/ConfigParam.h const noexcept [[nodiscard]] the hot-path read: one field or one atomic load, and no lookup anywhere

Signature

[[nodiscard]] T Get() const noexcept;

Function description

Returns value by value. When IsAtomic is true the storage is std::atomic<T> and this is an atomic load with the default memory order; when it is false the storage is a plain T and this is a field read. Either way there is no lock, no map, no interned string and no std::function call — which is the entire reason this class exists instead of a call to ConfigSystem::GetByte at the point of use.

The whole body is two statements, and the first is conditional: 

#ifdef __DEBUG__
        Assert(IsAtomic || std::this_thread::get_id() == threadID);
#endif // __DEBUG__
return value;

That assertion is the thread-affinity rule for non-atomic parameters, stated once for Set and here. For an atomic parameter the condition is satisfied by IsAtomic alone and the thread is never compared.

Parameters

None.

Return value

TypeWhat you get
T (a copy) The current value as its own type — uint8_t for the log-level parameters, size_t for the task registry sizes, float for the task stream threshold. A copy, not a reference: the value can change underneath a caller and the caller's copy will not notice, which is exactly what you want in a comparison like if (level < static_cast<ELogLevel>(CPLogLevel.Get()))
A non-atomic parameter read from another thread is an assertion in Debug and Dev, and a silent data race in Release. Assert aborts the process when it fires, and it is compiled in only under __DEBUG__ — which Debug and Dev builds define through CMakeLists.txt, and Release does not (BuildConfig). So the same code either stops where it happened or reads a field another thread is writing, with no diagnostic in either build to distinguish "checked and safe" from "not checked at all". If the value is read from more than one thread, declare the parameter atomic; the assertion is a development aid, not a guarantee.
Absent ≠ zero, and this is the read that tells you what is actually stored. Unlike every by-name read in ConfigSystem, which answers a missing key with a stand-in value (GetInt and its siblings), this function can only be called on a parameter you already hold — so its answer is always a real value. When a caller needs to distinguish "unset" from "set to 0", read through the owner's ConfigParam rather than through a name.

Examples

All four engine call sites read it inside the check the value gates. Two of them:

static hbe::TAtomicConfigParam<uint8_t> CPLogLevel("Log.Level", "The Default Log Level",
                                                  static_cast<uint8_t>(ELogLevel::Info));

if (level < static_cast<ELogLevel>(CPLogLevel.Get()))
{
        return;
}

From Engine/Log/Logger.cpp, hbe::Logger::AddLog

if (deltaTime > thresholdDuration.Get())

From Engine/Core/TaskStream.cpp — inside the stream loop, so the parameter is re-read every iteration and a write by name takes effect immediately

The remaining registrations live in Engine/Engine/Engine.cpp, Engine/Memory/MemoryManager.cpp and Engine/Core/TaskSystem.cpp; three of them are read once at initialisation and their value is then handed to another object, which is the pattern where a later write by name changes nothing (Set).
