ConfigParam

Engine/Config/ConfigParam.h namespace hbe template <typename T, bool IsAtomic = false> final one setting a subsystem owns: read it as a member, changed by name through ConfigSystem

Class description

A value, its name and its description, which announces itself to the registry at construction. The point of the class is the split it creates: the owner holds the object and reads the setting with Get() — a field read, or one atomic load — while a debug overlay, a shutdown dump or a console reaches the identical value by name through ConfigSystem. Neither half stores the setting, which is why a change made by name is visible to the owner on the next read with no notification mechanism anywhere.

The constructor is the only non-trivial part: it stores the default, then calls ConfigSystem::Get().Register(*this). Registration is therefore not optional and not deferred — building the object is registering it.

Every parameter the engine registers today is a function-local static inside the function that first needs it, and every one of them — eight in a default build, nine with MEMORY_LOGGING_ENABLED compiled in — uses the atomic form; the whole set is listed on GetSize.

Once registered, an instance cannot be moved, copied or destroyed quietly. Register captures &param inside both closures it stores, and this class holds a std::mutex member — which is neither copyable nor movable — so the compiler refuses a copy or move of a ConfigParam anyway. That is a service rather than a limitation: a parameter that changed address would leave the registry pointing at its old location. Keep one at static or member lifetime in an object that outlives every read of its key.
The std::mutex lock member locks nothing. It is declared and never used: Get and Set touch value directly with no guard, so the class provides no mutual exclusion of its own. Thread safety comes entirely from std::atomic<T>, which the IsAtomic argument selects. A parameter declared with IsAtomic = false is a plain field: reading it from one thread while another writes it is a data race, guarded only by a debug assertion on thread identity — see Get.

Template parameters

ParameterKindWhat it must satisfy
T typename The value type. Only five are registrable — bool, uint8_t, int, size_t, float — because Register has an overload per exactly those five and no template fallback, so any other T compiles as a ConfigParam and then fails at the registration call inside its own constructor. With IsAtomic the type additionally has to be usable as std::atomic<T>, which rules out anything non-trivially-copyable. Note there is no double and no uint32_t: a setting that needs one is a float or a size_t here, or it is not a config parameter
IsAtomic bool, defaults to false Selects the storage: TValue becomes std::atomic<T> or plain T. true is what makes a write from any thread legitimate; false binds the parameter to the thread that constructed it, enforced by an assertion only under __DEBUG__ (Debug and Dev, per BuildConfig). It also picks the Register overload, though not the map — both forms of one type land in the same map, so a name-based reader cannot tell them apart

Class properties

NameDeclarationWhat it means
MaxNameLength static constexpr size_t MaxNameLength = 127; public constant Declared and used by nothing — not by this header, not by ConfigParam.cpp, not by StaticString, which interns whatever it is given. A long name is not truncated to 127 characters by anything in the engine, so treat this as an aspiration the code does not enforce
MaxDescLength static constexpr size_t MaxDescLength = 127; public constant Same: declared, never read, no effect on a description of any length
TValue using TValue = std::conditional_t<IsAtomic, std::atomic<T>, T>; member type The actual storage type, and the single place IsAtomic has an effect. Every read of value is an atomic load or a field load through this alias
name StaticString name; private only under ENGINE_PARAM_DESC_ENABLED The interned name, built from the constructor's inName. With the macro 0 the member does not exist, GetName answers the interned string "None", and registration therefore collides every parameter of one map onto that single key
desc StaticString desc; private only under ENGINE_PARAM_DESC_ENABLED The interned description. Its only consumer is PrintAllParameters, which prints it in parentheses after the value
value TValue value; private The setting itself, initialised from the constructor's defaultValue and afterwards whatever the last Set wrote — by the owner or by a name-based write through ConfigSystem
lock std::mutex lock; private Never locked. It contributes no thread safety, but it does contribute two real properties: the class becomes non-copyable and non-movable, and every parameter costs a mutex worth of size and construction work whether or not anything uses it
threadID std::thread::id threadID; private only under __DEBUG__ The constructing thread, used by the assertion in Get and Set. Absent in Release, so the thread-affinity rule for non-atomic parameters is not checked there — the assertion and the member vanish together

Class methods

MethodSignatureWhat a caller depends on
constructors ConfigParam(const char* inName, const char* inDesc, T defaultValue, std::thread::id id = std::this_thread::get_id()) One constructor, no overloads. Its final act registers the parameter, so the name must be unique in the map its type belongs to before this returns
GetName StaticString GetName() const The interned name — or an empty StaticString when ENGINE_PARAM_DESC_ENABLED is 0. Not noexcept, because it constructs a StaticString
GetDescription StaticString GetDescription() const The human string a debug UI shows; empty under the same macro. Only the shutdown dump consumes it today
Get T Get() const noexcept The hot-path read: a copy of the value, atomic-loaded when IsAtomic. Asserts thread identity for a non-atomic parameter under __DEBUG__
Set void Set(const T& inValue) noexcept Writes the value; it does not notify anything, so a subsystem that latched this setting at start-up keeps its old copy until it re-reads. Same thread assertion as Get

There is no destructor to document: the class has none, so the compiler-supplied one destroys value, the mutex and the two interned strings — and says nothing to the registry, which is the fact that matters and is spelled out on the ConfigSystem destructor page.

Non-member helper functions

Two aliases at namespace scope, and nothing else:

AliasDeclarationWhat it means
TConfigParam template<typename T> using TConfigParam = ConfigParam<T, false>; The non-atomic spelling. Also declared a second time as a private alias inside ConfigSystem for its Register declarations — same type, two declarations
TAtomicConfigParam template<typename T> using TAtomicConfigParam = ConfigParam<T, true>; The atomic spelling, and the one every engine parameter uses: TAtomicConfigParam<uint8_t> for the log levels (four of them in a default build, five with memory logging compiled in), TAtomicConfigParam<std::size_t> for the three task-registry sizes. The one float parameter is spelled the long way, ConfigParam<float, true>, in Engine/Core/TaskStream.cpp

Coverage

GapDetail
Explicit instantiations in ConfigParam.cpp That source instantiates ConfigParam<T, true> and ConfigParam<T, false> for bool, int, size_t and float. uint8_t — the type five engine parameters actually use — is not among them; it works through implicit instantiation from the header definition. The list is a build-time detail, not API, and is recorded here so its absence from the class sections is not read as an unsupported type
Where a name has to be unique Uniqueness is per map, and the map is chosen by T — the rules, the refusal behaviour and the log level it uses are documented on Register, not duplicated here
Ownership and destruction order The lifetime hazard between a parameter, its owner and the registry singleton is a ConfigSystem-level fact and lives there
Interning mechanics behind StaticString name and desc are interned by the string table, which decides storage and bucket counts (String). This page states only what the members are, not how the table stores them
No file, no persistence, no change notification Nothing loads a parameter's value from disk, nothing saves it, and nothing observes a change. A "configuration file" that feeds these values does not exist — see ConfigFile, which is unrelated to this class and unread by the engine
