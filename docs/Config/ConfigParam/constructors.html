ConfigParam (constructors)

member of hbe::ConfigParam Engine/Config/ConfigParam.h one form, no overloads registers on construction name, description, default — and the act of building the object is the act of registering it

Signature

ConfigParam(const char* inName, const char* inDesc, T defaultValue,
            std::thread::id id = std::this_thread::get_id());

Function description

Interns inName and inDesc into StaticString members, stores defaultValue as the initial value, records the constructing thread, then obtains ConfigSystem::Get() and calls Register(*this). There is no second step, no Init and no way to build an unregistered parameter.

Both halves of that are conditional at compile time. Under ENGINE_PARAM_DESC_ENABLED 0 the initialiser list contains only value, because the name and desc members are not declared at all. Under a build without __DEBUG__ the id argument is accepted and discarded, since the member it would initialise does not exist — a caller may pass a thread id in Release and it changes nothing.

Not explicit, but in practice invisible: the engine builds every one of its parameters as a named static object, never as a conversion.

Construction can leave the object unregistered, and it will not tell you at the call site. The constructor returns normally whether or not Register accepted the name. If the name is already taken in the map that T selects, the registry logs one FatalError line under EngineSettings and installs nothing: your parameter works perfectly for its owner and is invisible by name. If ENGINE_PARAM_DESC_ENABLED is 0, every parameter after the first collides that way, because a parameter with no name member registers under the interned string "None" that every other such parameter shares. Both cases look like a working object.
Order of construction is order of registration, and first wins. Two parameters under the same name in the same map means the one constructed earlier owns the key. In a stock engine this is why the parameters are function-local statics: each is built the first time its subsystem runs, which is deterministic and long before anything reads the key.

Parameters

ParameterTypeRequirement
inName const char* The key everything else uses to reach this value. Must outlive nothing — it is interned here, so a literal or a temporary buffer is fine — but must be unique within the map that T selects. The engine's convention, visible in every call site, is a dotted category prefix: Log.Level, Task.RegistryMaxRecords
inDesc const char* Description shown in PrintAllParameters's dump, also interned. Not stored at all when ENGINE_PARAM_DESC_ENABLED is 0. Say what a value of 0 means if the setting has one — "… 0 means no ceiling" in Engine/Core/TaskSystem.cpp is the model
defaultValue T The value until something writes it. There is no file, no environment and no command line that supplies it — this argument is the only source of a parameter's initial state
id std::thread::id, defaults to the constructing thread The thread later allowed to call Get and Set, and only meaningful for a non-atomic parameter under __DEBUG__. Passing another thread's id is how you bless a parameter that a specific other thread owns; ignored in a build where the member is compiled out

Return value

Constructors have no return value, and nothing here needs one: the two failure modes — duplicate name, and a description build — are reported in the log or not at all, never through the construction itself.

Examples

Real call sites, one per value type that the engine registers.

static hbe::TAtomicConfigParam<uint8_t> CPLogLevel("Log.Level", "The Default Log Level",
                                                  static_cast<uint8_t>(ELogLevel::Info));

From Engine/Log/Logger.cpp

static hbe::TAtomicConfigParam<std::size_t> maxRecords("Task.RegistryMaxRecords",
                                                     "Largest the task record table may grow. 0 means no ceiling",
                                                     TaskRegistry::DefaultMaxCapacityRecords);

From Engine/Core/TaskSystem.cpp

static hbe::ConfigParam<float, true> thresholdDuration(
        "TaskStreamDurationThreshold", "Print a warning log if it detects slower task. (seconds)", 0.16f);

From Engine/Core/TaskStream.cpp

Three things all three share: the object is a function-local static, so it is built once, on the thread that first runs that function, and lives to exit; the type is the atomic form, so a name-based write from anywhere is legal; and the default comes from a named constant or a literal rather than being computed, because the value has to exist before the first Get.

No engine call site uses the non-atomic form. TConfigParam<T> and the four-argument form with an explicit thread id are exercised only by parameters a caller adds. Before reaching for them, read Get: the non-atomic form is a plain field, and its only protection is a Debug-only assertion.
