GetDescription

member of hbe::ConfigParam Engine/Config/ConfigParam.h const, not noexcept the one human-readable sentence a setting carries — paid for by an interned string per parameter

Signature

[[nodiscard]] StaticString GetDescription() const;

Function description

Returns the interned desc member that the constructor built from inDesc. Under ENGINE_PARAM_DESC_ENABLED 0 the member is not declared and the body returns a default-constructed StaticString, which is the interned string "None" — a description that looks present and says nothing.

The only consumer in the engine is ConfigSystem::PrintAllParameters, and it does not call this function at print time: Register calls it once, interns the result into ParamItem::desc, and the dump prints that stored identity. So the description is captured at registration and can never change afterwards, whatever the owning object does with its own members.

A description is not metadata you can skip. It is interned like a key — one entry in the string table per distinct sentence, shared by every parameter that repeats it — and it is the only place a unit or a special value is written down. Compare the two styles in the tree: "Largest the task record table may grow. 0 means no ceiling" states what zero means, while "The Default Log Level" leaves the reader to know that the number is an ELogLevel. The dump is a list of bare numbers otherwise.

Parameters

None.

Return value

TypeWhat you get
StaticString The sentence passed to the constructor, or "None" when descriptions are compiled out. Copying it is copying one interned identity, not a buffer, and the text it resolves to lives as long as the string table

Examples

Where a description is written down, in the form every engine parameter uses:

static hbe::TAtomicConfigParam<std::size_t> maxRecords("Task.RegistryMaxRecords",
                                                     "Largest the task record table may grow. 0 means no ceiling",
                                                     TaskRegistry::DefaultMaxCapacityRecords);

From Engine/Core/TaskSystem.cpp

Illustrative — reading a description from outside the owning subsystem, e.g. to build a tooltip.

// param is the ConfigParam this subsystem owns:
tooltip.SetText(param.GetDescription());
value.SetText(param.GetName());

For the by-name path there is no equivalent read: the registry stores the description inside its entry, and the only way to see it is the dump (PrintAllParameters). A debug UI that wants descriptions for parameters it does not own has to reach the owning objects — a gap recorded on the ConfigSystem Coverage section.
