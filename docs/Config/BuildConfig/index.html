BuildConfig

Engine/Config/BuildConfig.h preprocessor no namespace, no types the defines that decide what gets compiled at all — platform, logging, memory checks, profiling, handedness, Vulkan

Class description

There is no class here. BuildConfig.h is the engine's preprocessor surface: one #define per feature, read before any translation unit picks its code path. Nothing in it has storage, linkage or lifetime, and nothing in it can be called — each use expands at its own site. The consequence is that changing one of these means rebuilding, not restarting: a value a running process could alter would belong to ConfigSystem instead.

The header includes nothing and declares nothing besides the macros, so it can be pulled in from anywhere — EngineConfig.h includes it, and ConfigParam.h reads ENGINE_PARAM_DESC_ENABLED straight from it.

These are switches, not settings. A define set to 0 removes the code that reads it: PROFILE_ENABLED 0 does not make profiling cheap, it compiles the timing out of ScopedLock and the allocator statistics out of Memory, so a benchmark run under one build is not comparable to a run under the other.

Template parameters

Not applicable — BuildConfig.h declares macros, not templates.

LOG_ENABLED #define LOG_ENABLED 1 define Master switch for the asynchronous logger itself, read by Logger
LOG_BREAK_IF_WARNING #define LOG_BREAK_IF_WARNING 0 define At 1, a line at Warning or above is printed inline and reaches debugBreak() instead of going through the async queue. The header comment says "debug only", but the guard is the macro alone — set it to 1 in a Release build and the Release build breaks
LOG_BREAK_IF_ERROR #define LOG_BREAK_IF_ERROR 0 define The same for Error and above. The two macros are ||-combined to decide whether ImmediateLog is compiled at all
LOG_FORCE_PRINT_IMMEDIATELY #define LOG_FORCE_PRINT_IMMEDIATELY 0 define Bypasses the asynchronous logger and prints each line at its call site — the option that keeps log order correct when a crash is about to discard the queue
PROFILE_ENABLED #define PROFILE_ENABLED 0 define Performance profiling: the lock-wait measurement in ScopedLock, the allocator statistics in Memory, and the timing fields in SystemStatistics. Widely read — 25 files branch on it, and Config::DebugTimeOutMultiplier only has an effect inside this branch
RIGHT_HANDED_COORDINATE #define RIGHT_HANDED_COORDINATE define, no value Coordinate handedness. It expands to nothing, so the only test that works on it is #ifdef / #ifndef — #if RIGHT_HANDED_COORDINATE is a preprocessor error. Engine/Math/CoordinateOrientation.h and Vector3 flip their cross and look-at trig with it
LEFT_HANDED_COORDINATE // #define LEFT_HANDED_COORDINATE declared only as a comment The alternative handedness, present in the file only as the line you uncomment to switch. Nothing tests #ifdef LEFT_HANDED_COORDINATE: the code asks whether RIGHT_HANDED_COORDINATE is absent, so defining this one as well does not undo the right-handed branch
MEMORY_INVESTIGATOR_TEST_ENABLED #define MEMORY_INVESTIGATOR_TEST_ENABLED 0 define Memory investigation tests, read by SystemAllocator. Test fixtures are covered by Test
VULKAN_SDK #define VULKAN_SDK 1 or 0 auto-detected 1 when vulkan/vulkan.h is reachable through one of four __has_include probes — the bare header, /opt/homebrew/include, /usr/local/include, External/VulkanSDK/include. Otherwise 0 plus a #pragma message naming the install script for the platform; the code still compiles, and RHICapabilities::IsVulkanSupported answers false as a compile-time constant. See Renderer
__DEBUG__ -D__DEBUG__ on the Debug flag line in CMakeLists.txt build flag, not defined here Gates Assert and nothing else — FatalAssert sits outside the guard and is live in every configuration. The top-level CMakeLists.txt puts -D__DEBUG__ on CMAKE_CXX_FLAGS_DEBUG, and CMAKE_CXX_FLAGS_DEV is defined as ${CMAKE_CXX_FLAGS_DEBUG} -O1, so Dev inherits it and Release does not have it. See Core: Debug

Class methods

None, and none is possible: a macro has no signature, no overload set and no address, so there is nothing to deep-link. This page therefore has no method pages, which is the correct shape for a header of defines rather than a gap in the reference.

Non-member helper functions

Naming follows docs/CodingStandards.md: macros are SCREAMING_SNAKE_CASE with no leading underscore, because a leading double underscore or an underscore followed by a capital letter is reserved to the C++ implementation — which is exactly why __DEBUG__ is legal while a new engine define must not be spelled that way. The __MEMORY_VERIFICATION__ and __FORCE_USE_SYSTEM_MALLOC__ spellings are the retired old names of MEMORY_VERIFICATION_ENABLED and FORCE_USE_SYSTEM_MALLOC; only the names in the table above exist in this header.
