GetMaxSystemMemoryTarget

member of hbe::Config Engine/Config/EngineConfig.h [[nodiscard]] noexcept declared, not defined a declared intent to ask the machine how much memory the engine may target — with no body to answer yet

Signature

[[nodiscard]] size_t GetMaxSystemMemoryTarget() noexcept;

Function description

The declaration is the whole of the public surface. Engine/Config/EngineConfig.cpp includes the header and defines nothing, so there is no body: no algorithm, no query to the operating system, no policy for what "target" means. Nothing under Engine/ or Applications/ calls it either, which is why the missing definition has never surfaced — an unresolved symbol only bites whoever first takes its address.

Its intended place is readable from the neighbours it sits next to. Config::MemCapacity is the fixed 5 GiB ceiling compiled into the binary; a function of this shape, returning size_t and taking nothing, is the per-machine figure a build cannot know — physical memory on the machine actually running the engine. The two questions are different and the pair is the reason both exist: one is "what did we decide to allow", the other is "what could this box support".

Calling it does not compile-fail — it link-fails. A declaration is enough for overload resolution and for &Config::GetMaxSystemMemoryTarget to type-check, so the error appears at link time as an undefined symbol, in whichever configuration happens to be built last. Until a definition exists, size your buffers from Config::MemCapacity, and if you do write the definition, put it in Engine/Config/EngineConfig.cpp, where the declaration already expects it.
[[nodiscard]] and noexcept are both load-bearing on a function with no body: the first means a future caller cannot discard the target it asked for, and the second promises the query never throws — so a real implementation has to answer from a noexcept context, which rules out anything that allocates while asking.

Parameters

None.

Return value

TypeWhat you get
size_t Nothing at present — there is no definition to return a value. The declared type is a byte count, in the same unit as Config::MemCapacity, which is the only comparison a caller could sensibly make against it

Examples

Illustrative — no call site for this exists in the repository, and none can link until a definition is added.

// The shape the declaration implies, written against what does exist.
const auto target = hbe::Config::GetMaxSystemMemoryTarget();   // undefined symbol at link time
const auto ceiling = hbe::Config::MemCapacity;                // 5 GiB, compiled in: this one works

if (target != 0 && target < ceiling)
{
        // a machine that cannot reach the compiled-in ceiling
}

For a memory budget a running engine can actually consult, use the statistics the memory manager reports rather than this declaration — see Memory: MemoryManager and Core: SystemStatistics, which is where MemCapacity is compared against real usage.
