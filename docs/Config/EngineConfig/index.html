EngineConfig

Engine/Config/EngineConfig.h namespace hbe::Config 15 static constexpr constants 1 function the compile-time sizes and caps every other module measures itself against

Class description

A namespace, not a class: hbe::Config holds the numbers the engine sizes itself with — log line length, allocation alignment, memory ceiling, interning-table buckets. Nothing is constructed, nothing is stored per instance, and every value is fixed when the binary is built. The rule the namespace exists to enforce is that a size appears once: a module that needs 1024 characters of log line reads Config::LogLineLength rather than writing 1024, so the constant can be moved without hunting for literals.

It is distinct from the other two Config surfaces in when the value is decided. These are baked in, like BuildConfig.h; only ConfigSystem values change while the process runs. The two do meet: EngineLogLevel and EngineLogLevelPrint are computed from the MEMORY_LOGGING_ENABLED define, and several of these constants are the default a ConfigParam is constructed with — after that the parameter, not the constant, is what a running engine changes.

Every member is static constexpr at namespace scope, so it has internal linkage. A translation unit that takes the address of one gets its own object; there is no single address to compare or share. As a value it behaves identically everywhere, which is how these are used — as array bounds, template arguments and initialisers.
The log level numbers are only meaningful against one legend. The header writes 0: Verbose, 1: Info, 2: Significant, 3: Warning, 4: Error, 5: FatalError, which is exactly ELogLevel — but the constants are typed uint8_t, not ELogLevel, so every consumer casts one way or the other (static_cast<uint8_t>(Config::EngineLogLevel), static_cast<ELogLevel>(logLevel.Get())). A level that drifts between the enum and these literals is not caught by the type system, and the only guard in the header is static_assert(EngineLogLevel <= EngineLogLevelPrint).

Template parameters

None — hbe::Config is a plain namespace, not a template.

DefaultAlign static constexpr size_t DefaultAlign = 16; constexpr Allocation alignment in bytes. The pool allocators widen it per type — std::max(sizeof(T), Config::DefaultAlign) — and the monotonic and stack allocators round with it directly. Anything that hand-computes an offset into an engine buffer has to agree with this number; see Memory
MaxPathLength static constexpr int MaxPathLength = 512; constexpr Longest path measured, not longest path stored. LogLineLength static constexpr int LogLineLength = 1024; constexpr Bytes of text in one stored log line, and the threshold above which a line is flagged long (size >= LogLineLength - 1). Longer output is truncated, not heap-allocated. See Log
LogOutputBuffer static constexpr int LogOutputBuffer = LogLineLength * 128; constexpr 131072. Not a queue size: it is the capacity of the inline string builder each log statement formats into — Logger::TLogStream is InlineStringBuilder<Config::LogOutputBuffer>. It bounds one formatted statement, which is why it is far larger than LogLineLength, the size the line is stored at
LogMemoryBlockSize static constexpr int LogMemoryBlockSize = LogLineLength * 256; constexpr Declared among the logging constants. No consumer in the tree — the logger's pools are MultiPoolAllocator instances constructed by name, not from this number. Inert today, see Coverage
LogNumMemoryBlocks static constexpr int LogNumMemoryBlocks = 1024 * 12; constexpr Same as above: declared, read by nothing
LogForceFlushThreshold static constexpr int LogForceFlushThreshold = 1024 * 8; constexpr Pending bytes that make the logger flush instead of waiting for its next tick — the backpressure that keeps a chatty subsystem from holding an unbounded amount of unwritten text
MaxConcurrentTasks static constexpr int MaxConcurrentTasks = 32; constexpr Declared with the task-system constants, by position in the header. Nothing reads it, so there is no concurrency ceiling in the engine that this number enforces — the task system's actual limits are its own. See Core: TaskSystem and Coverage
DebugTimeOutMultiplier static constexpr float DebugTimeOutMultiplier = 2.0f; constexpr Multiplies ScopedLock::timeOutSec — the wait a lock holds before it reports a slow contention. The multiplication sits inside #if PROFILE_ENABLED and #ifdef __DEBUG__, so with the default PROFILE_ENABLED 0 it changes nothing at all

Coverage

GapDetail
Four constants have no consumer StaticStringBufferSize, LogMemoryBlockSize, LogNumMemoryBlocks and MaxConcurrentTasks are declared and read by nothing under Engine/ or Applications/. Nothing in the header says what any of them is for — they are separated from the rest only by position — so any purpose beyond that, including the ones the previous guide gave them, cannot be confirmed from the code and is not asserted here
GetMaxSystemMemoryTarget has no definition The declaration in EngineConfig.h is the whole of it; Engine/Config/EngineConfig.cpp is three lines and contains no function body. What it is meant to return is therefore unknown, and the page for it documents the declaration and the absence, not a description of behaviour
Where each constant is enforced This page names the reader of each number; what the reader does with it — truncation, rounding, flush scheduling — belongs to Log, Memory, String and HSTL
Changing a value Editing one of these rebuilds the engine; MemCapacity and the log figures change process behaviour, DefaultAlign changes the layout of live allocations, so it is a full clean rebuild rather than an incremental one. docs/BuildSystem.md covers the mechanics
