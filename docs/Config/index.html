Config

namespace hbe namespace hbe::Config Engine/Config 5 headers, 4 sources — compile-time defines, runtime constants, and a key-value parameter database

Module description

Config answers the same question at three different times. Compile time: BuildConfig.h decides what is built at all — platform, logging, memory verification, profiling, coordinate handedness, Vulkan availability. Load time: EngineConfig.h holds the constexpr sizes and caps that other modules size their buffers from. Runtime: ConfigSystem stores named parameters an application or a debug menu can change while the process runs, and ConfigParam<T> is the thread-safe handle a subsystem holds to one of them.

Non-member helper functions

Naming follows docs/CodingStandards.md: macros are SCREAMING_SNAKE_CASE with no leading underscore, because a leading double underscore or an underscore followed by a capital is reserved to the C++ implementation. ConfigSystem (Engine/Config/ConfigSystem.h)

Class description

The runtime key-value parameter database. A subsystem registers the ConfigParam objects it owns; after that the parameters are readable and writable by name, which is what a debug overlay or a saved configuration needs.

Template parameters

None — ConfigSystem is not a template.

Class properties

The registered parameter set; header-private, reached through Get().

Class methods

class ConfigSystem final
{
    [[nodiscard]] static ConfigSystem& Get() noexcept;

    // registration — one overload per parameter type: bool, int, size_t, float
    void Register(TConfigParam<...>& engineParam);

    void SetBool(const StaticString& key, bool value);
    void SetInt(const StaticString& key, int value);
    void SetFloat(const StaticString& key, float value);

    [[nodiscard]] bool GetBool(const StaticString& key) const noexcept;
    [[nodiscard]] int GetInt(const StaticString& key) const noexcept;
    [[nodiscard]] float GetFloat(const StaticString& key) const noexcept;

    void PrintAllParameters() const;
};

Non-member helper functions

None.

ConfigParam (Engine/Config/ConfigParam.h)

Class description

One registered parameter: a value plus the registration that makes it reachable by name through ConfigSystem. This is the handle a subsystem holds, so it reads its setting without a lookup on the hot path.

Template parameters

ParameterMeaning
TValue type — bool, int, size_t or float
IsAtomicWhether the value is stored atomically, which is what makes it safe to write from one thread while another reads it

Class properties

The value, its atomic storage when IsAtomic, and its registered identity and description; header-private.

Class methods

Registration with ConfigSystem::Register, then read and write of the held value.

Non-member helper functions

The alias TConfigParam names an instantiation for the Register overloads.

Build configuration

How the engine is configured and generated lives in docs/BuildSystem.md — including the rule that generated CMakeLists.txt files are never edited by hand. How to build one target quickly lives in docs/HelperScript.md. The flags are repeated here because they are the part a reader of the API page reaches for: 

./build.sh <target> [-dev] [-debug] [-release] [-clean] [-test]

# build VulkanExample in all three configurations, cleaning first
./build.sh Applications/VulkanExample -dev -debug -release -clean

Dev is the default configuration. -test reconfigures with -D__TEST__ -D__UNIT_TEST__ so the unit-test sources compile at all; without it EngineTest builds green while testing nothing. build.sh only builds — it never runs a test binary. To run the suite, see docs/RunningTests.md.
