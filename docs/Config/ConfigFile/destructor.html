~ConfigFile

member of hbe::ConfigFile Engine/Config/ConfigFile.h = default, not virtual frees the map and nothing else — the file was closed long before this

Signature

ConfigFile::~ConfigFile() = default;

Function description

Defaulted, so what runs is the destruction of the two members in reverse declaration order: keymap and then isValid. The map's destruction releases every HString key and value, each on hbe::DefaultAllocator, which is the only cost worth naming.

No stream is involved. Parse held its std::ifstream as a local, so the file handle was closed when the constructor returned; nothing here flushes, closes or re-checks anything — and there is nothing to flush, because this class never writes.

Not virtual, and the class is final, so a ConfigFile reference always names this destructor exactly. Derived-class slicing questions do not arise.

Copy and move are compiler-supplied and therefore deep. The default destructor pairs with a defaulted copy constructor and copy assignment, which copy the whole map, element by element, allocating each string again. A ConfigFile returned by value or stored in a container is therefore not a cheap handle: if a caller wants one loaded file seen from two places, it wants a reference or a pointer to a single object, not a copy of one.

Parameters

None.

Return value

void. Nothing can fail here that a caller could act on: releasing strings through the engine allocator either succeeds or is a bug in the allocator, not a condition to handle.

Examples

Illustrative — no call site destroys a ConfigFile; the class is never instantiated in the repository.

hbe::ConfigFile LoadSettings(const char* directory)
{
        return hbe::ConfigFile(directory, "engine.cfg");   // the map is moved or copied out
}                                          // the temporary's destructor frees nothing extra here

void UseIt()
{
        const auto settings = LoadSettings("config");

        if (!settings.IsValid())
        {
                return;   // destructor still runs, and still frees the empty map
        }
}

The lifetime fact worth carrying out of this page: nothing about a ConfigFile outlives the object, so a TString returned by GetValue is a copy you own and may keep after the file object is gone — unlike const char* data borrowed from a buffer, there is nothing here to dangle.
