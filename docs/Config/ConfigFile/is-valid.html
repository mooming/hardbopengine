IsValid

member of hbe::ConfigFile Engine/Config/ConfigFile.h const noexcept reports one fact: the file opened. Not that it contained anything, and not that it was well-formed

Signature

[[nodiscard]] auto IsValid() const noexcept { return isValid; }

Function description

Defined in the header, and the body is a field read of isValid. The return type is deduced with auto from that bool member, so the signature you type at a call site is bool.

The flag's history is the whole contract. Both constructors set it to false, and Parse sets it to true on exactly one path: the std::ifstream opened successfully and the read loop finished. Every line the loop then rejected — no =, empty key, empty value — is dropped without touching the flag. It says nothing about encoding, about duplicate keys, or about whether a single setting survived.

Parameters

None.

Return value

TypeWhat you get
bool true if the file was opened and scanned, even if it parsed to zero pairs; false only if the file could not be opened — which is also the moment a [ConfigFile] Not Found: … line went to standard output (Parse)
Do not read IsValid() as "the settings are usable", and do not read !IsValid() as an error worth aborting on. The four states a caller actually meets are these, and the flag separates only the first axis:
StateIsValid()keymap.empty()
File missing or unopenablefalsetrue
File present, nothing parseable in ittruetrue
File present, some pairs parsedtruefalse
File valid, then modified through the public maptruewhatever you left
The first two rows differ only in the flag, so a caller that wants "no file" and "empty file" to behave differently must test both columns; the last row exists because keymap is public and no invariant is enforced anywhere.

Examples

Illustrative — no call site for this exists in the repository; nothing constructs a ConfigFile.

const hbe::ConfigFile settings("config/engine.cfg");

if (!settings.IsValid())
{
        // first run: no file yet. Create defaults rather than failing.
}
else if (settings.keymap.empty())
{
        // the file exists but nothing in it parsed — probably hand-edited into junk.
}
else
{
        // genuinely usable: settings.GetValue("…") may return real values
}

[[nodiscard]] makes a bare settings.IsValid(); a compile error, which is the right enforcement for a getter whose only purpose is to be branched on. To see what the file actually contains once you know it is readable, use ForEach.
