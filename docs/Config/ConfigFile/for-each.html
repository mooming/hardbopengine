ForEach

member of hbe::ConfigFile Engine/Config/ConfigFile.h const noexcept visit every parsed pair, in hash order, with no way to stop early

Signature

void ForEach(std::function<void(const TMap::value_type&)> func) const noexcept;

Function description

Calls func once per entry of keymap, passing std::pair<const TString, TString> — the key and the value as parsed. Iteration order is the hash order of an HUnorderedMap, so it is neither file order nor alphabetical, and it can differ between two runs of the same binary on the same file if anything changes the map's bucket count.

The callback returns void, so there is no early exit: to find one key this walks the whole file, which is strictly worse than GetValue and than a direct keymap.find. Its place is where every entry is genuinely wanted — a settings screen, a validation pass, a dump at start-up.

The function object is taken by value, so a capturing lambda is copied into the parameter; and the method is const noexcept, so the callback sees a const map and must not throw — an exception escaping it reaches std::terminate rather than the caller.

An empty callback is not an error, it is a silent no-op. The implementation tests func == nullptr, returns, and reports nothing anywhere. Passing a default-constructed std::function — the result of a std::function you forgot to assign, or a nullable callback forwarded from elsewhere — therefore looks exactly like an empty file. If the callback is optional at your call site, check it before you call; this class will not.

Parameters

ParameterTypeRequirement
func std::function<void(const TMap::value_type&)>, by value Must be non-empty, must accept a const pair reference, and must not throw. It may not modify the pair — the key is const and the value arrives const because the map is const here; writing back means going through the public keymap on a non-const object

Return value

void, and it does not report how many entries it visited. A caller that needs the count reads keymap.size() directly, or counts inside the callback.

Examples

Illustrative — no call site for this exists in the repository; nothing constructs a ConfigFile.

const hbe::ConfigFile settings("config/engine.cfg");

// Validate the keys you expected, and report the ones the file added or lost.
int recognised = 0;
settings.ForEach([&recognised](const auto& entry)
{
        if (entry.first == "max_particles" || entry.first == "vsync")
        {
                ++recognised;
        }
        else
        {
                // entry.first / entry.second are HStrings; report them however this
                // subsystem reports anything else
        }
});

For the dump-style use — printing what the file loaded, since the logger is not involved in the load itself — the same call with a printing body is the whole implementation, and it is the one place where hash order does not matter.

To change a value while walking, do not: this method is const, and inserting through the public map during iteration would invalidate the iterators the loop is using. Read everything you need into your own types inside the callback, then apply it after.
