ConfigFile

Engine/Config/ConfigFile.h namespace hbe final a key = value text file parsed once into a map of strings — read-only, untyped, and not wired to anything

Class description

Construct one from a path and it opens the file, splits every line on the first =, trims both sides and keeps non-empty pairs in keymap (Parse holds the format rules). Both key and value stay strings; nothing here converts a value to a number, a bool or a path, and nothing here stores a type. Lookup is by HString key, case-sensitive, with no prefix or section concept — one flat map.

There is no second constructor argument that means anything except "join these two into a path", no reload, and — the asymmetry most likely to surprise — no write path at all. No member saves, updates or appends, so a configuration edit has to be done by mutating keymap yourself and writing the file out with your own code.

This class is not connected to the rest of Config, and the engine never uses it. No file under Engine/ or Applications/ constructs a ConfigFile, and nothing feeds a ConfigParam from one. A parameter's value therefore comes from the default in its constructor and from no file, whatever a .cfg in the working directory appears to say. Treating this class as "the engine's config file loader" is the single most expensive mistake available here.
Its diagnostics go to standard output, not to the logger. Parse prints [ConfigFile] Open … and [ConfigFile] Not Found: … with std::cout, so they ignore log levels, the LOG_ENABLED switch, categories and the asynchronous queue — they appear even in a build with logging off, and cannot be filtered out.

Template parameters

None — ConfigFile is not a template. Its string and map types are fixed by the aliases below.

Class properties

NameDeclarationWhat it means
TString using TString = HString; public alias Keys and values. HString is a std::basic_string on hbe::DefaultAllocator<char>, so a parsed file is accounted to the engine's allocator rather than to the system heap
TValue using TValue = std::optional<TString>; public alias The result of the one-argument GetValue: an empty optional means "no such key", which is the only way this class reports absence as data instead of as a value
TMap using TMap = HUnorderedMap<TString, TString>; public alias The container: std::unordered_map on the engine allocator, and TMap::value_type — std::pair<const TString, TString> — is what ForEach hands your callback
isValid bool isValid; public Set to false by both constructors and to true only after Parse has opened the file and run its loop. It means "the file was readable", never "the contents parsed" — see the box below, and prefer IsValid()
keymap TMap keymap; public Every pair the parse accepted, in hash order. Public and writable: it is the only way to change what this object thinks the file said, and inserting here does not touch any file

Those two fields are the entire state, and both being public is load-bearing twice over: it is how a caller inspects a loaded file without ForEach, and it means no invariant is protected — nothing prevents isValid == true alongside a keymap you have cleared.

A file that opens but parses nothing is a valid, empty configuration. isValid becomes true as soon as the stream opened, so an empty file, a file of comment-like lines, or one whose lines all have a key but no value gives IsValid() == true with keymap.size() == 0. Every lookup then returns the "not found" answer, which GetValue with a default renders as a normal value. A missing file and an unreadable-content file are distinguishable; a missing file and an empty file are not, unless you also check the map size.

None. ConfigFile.h declares the class and nothing at namespace scope. Trimming is done by StringUtil::Trim inside Parse, documented under String: StringUtil.

Coverage

GapDetail
No writer, and no round trip There is no Save, Write, SetValue or AddKey in the header, so a documentation page cannot describe one. The previous module page claimed "Load, save, and lookup by key" and "read from and written to a file"; the header has no save path, and this page records the absence rather than repeating the claim
No stored path Nothing in the class remembers where it loaded from — the two constructors keep no member for it, and there are only the two public fields above. The previous module page listed "the path they came from" among the properties; the header has no such member
What the parse accepts Parse states the rules the implementation applies (first = splits, both sides trimmed, empty pair members dropped, later duplicate wins) but not the encoding of the file, the platform line endings it tolerates, or what a byte-order mark does to the first key. None of that is handled by name in the code
Declaration and definition disagree on one name The header declares Parse(const char* fileName) and ConfigFile.cpp defines the parameter as filePath. The single-argument constructor passes a full path to it, so the definition's name is the accurate one and the header's is stale — noted here rather than silently corrected
Allocation behaviour of a large file Every key and value is an HString on the engine allocator, so a config file allocates through Memory with no reserve and no arena; how much that costs and which scope it lands in is that module's subject
