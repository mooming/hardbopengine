GetName

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h const noexcept the logger category this class reports under: "EngineSettings"

Signature

[[nodiscard]] const char* GetName() const noexcept;

Function description

Returns the fixed string "EngineSettings" — a string literal in Engine/Config/ConfigSystem.cpp, not a field, so it does not depend on the registry's state and cannot be renamed at runtime.

Its purpose is one thing: the category passed to Logger::Get by every diagnostic this class emits. The duplicate-key refusal from Register, the "key is null" and "is not found" lines from the lookup path, and the dump from PrintAllParameters all appear under this category and nowhere else. That makes it the filter you set when you want to see why a parameter refuses to behave — and, conversely, the reason a misnamed parameter is invisible if you are not looking at this category.

It is not a parameter name. There is no key called EngineSettings in the registry, and the class has no per-instance name to distinguish one registry from another — the function is const and returns the same literal for any instance, including the private one from the public default constructor.

Parameters

None.

Return value

TypeWhat you get
const char* "EngineSettings", NUL-terminated, with static storage — valid for the whole process, so it may be kept. It is a raw C pointer rather than a StaticString, so a caller that wants interning has to construct one

Examples

Illustrative — every call to this function in the engine comes from inside ConfigSystem itself when it builds a logger; no external caller exists.

auto& settings = hbe::ConfigSystem::Get();

// Intern it if you intend to filter on it repeatedly.
const hbe::StaticString category(settings.GetName());
auto log = hbe::Logger::Get(category);

log.OutWarning([](auto& ls) { ls << "config check failed"; });   // lands in the EngineSettings category

Logger::Get and the category filter are documented in Log: Logger; the levels these diagnostics use are ELogLevel.
