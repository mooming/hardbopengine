~ConfigSystem

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h = default, not virtual destroys the entries, never the parameters they point into

Signature

~ConfigSystem() = default;

Function description

Defaulted, so what runs is the destruction of the four TMap members: each entry's ParamItem is destroyed, which destroys the two std::function closures and the interned desc identity. Because those closures captured a ConfigParam by reference, destroying them releases no object — a reference owns nothing. The parameters themselves stay alive or dead exactly as their own owners decided.

It is not virtual, and cannot be reached polymorphically: the class is final, so a ConfigSystem you hold is always a complete ConfigSystem and the static type always names the right destructor.

In a running engine this destructor fires once, at normal exit, when the function-local static inside Get() is destroyed. Since Get() is what Register is called on, and registration happens inside a parameter constructor, the registry is nearly always constructed before the parameters that register into it — and static-lifetime objects are destroyed in reverse order of construction, so the registry is destroyed after them.

That ordering leaves a window in which the entries dangle. Between the destruction of a parameter and the destruction of the registry, every entry that pointed at it is still installed and still callable — there is no Unregister to remove it. Code that runs during static destruction and reaches a parameter by name (GetByte, SetInt, or PrintAllParameters walking everything) invokes a closure whose captured reference names a destroyed object. Nothing here detects it: the maps are intact, the reference is simply stale. Keep name-based access inside main's lifetime, which is what the engine's own call site in Engine::ShutDown does.

Parameters

None.

Return value

void — a destructor has no status to report, and there is none to want: freeing hash nodes cannot fail in a way a caller could act on.

Examples

Illustrative — no call site destroys a ConfigSystem explicitly; the singleton's destructor is the only one and it runs at exit.

// Safe: name-based access while the owners are still alive.
int main()
{
        auto& settings = hbe::ConfigSystem::Get();
        const auto level = settings.GetByte("Log.Level");   // the parameter is alive
}                                          // parameters with static storage die here;
                                           // the registry dies after them

// Unsafe: reaching the same key from a destructor that runs after them.
// hbe::ConfigSystem::Get().GetByte("Log.Level");   // closure into a destroyed ConfigParam

Log.Level is a real uint8_t parameter, registered from Logger::AddLog; see Log: Logger.
