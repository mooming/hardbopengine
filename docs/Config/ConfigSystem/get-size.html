GetSize

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h const noexcept read a count- or capacity-valued parameter, where "not registered" and "zero" are the same answer

Signature

[[nodiscard]] size_t GetSize(const StaticString& key) const noexcept;

Function description

Interns key, looks it up in sizeParams and calls the stored getter, which reaches the owning ConfigParam<size_t>::Get. The value arrives at full width — no narrowing happens anywhere on this path, which is the reason the size_t map exists beside the int one.

The three names that resolve in a stock engine are the task record table sizes, registered by TaskSystem::Initialize:

KeyDefault comes fromMeaning of its own description
Task.RegistryInitialRecordsTaskRegistry::DefaultInitialCapacityRecordsRecords the registry starts with, in banks of the grow-by figure
Task.RegistryGrowByRecordsTaskRegistry::DefaultGrowByRecordsRecords added per growth of the record table
Task.RegistryMaxRecordsTaskRegistry::DefaultMaxCapacityRecordsLargest the table may grow; 0 means no ceiling

Parameters

ParameterTypeRequirement
key const StaticString& The registered name of a size_t parameter; a byte- or float-map name of the same spelling is a miss

Return value

TypeWhat you get
size_t The parameter's current value, or 0 for a null or absent key — and 0 is not a sentinel these parameters avoid: for Task.RegistryMaxRecords the value 0 is documented as "no ceiling". So a typo in that key produces the same number as the most permissive setting that key can hold
Zero is a real, load-bearing value in this map — do not use it as your "missing" test. Written as if (auto ceiling = settings.GetSize("Task.RegistryMaxRecords"); ceiling != 0), an absent parameter takes the "there is a ceiling, and it is 0 records" branch in every reading of the code except the one you intended. Test the parameter's existence where existence matters — its owner registered it, so the owner's own Get is the trustworthy read — and treat this function as the by-name view it is.
What you read may already be stale in a specific way. A parameter holds a value; the subsystem that consumed it at start-up holds its own copy. GetSize("Task.RegistryInitialRecords") tells you what a future Initialize would use, not what the live task registry allocated. The relationship between the two is the same one described on SetSize from the writing side.

Examples

The registration is real; reading these keys by name has no live call site.

static hbe::TAtomicConfigParam<std::size_t> initialRecords(
        "Task.RegistryInitialRecords",
        "Task records the registry starts with, in banks of the grow-by figure",
        TaskRegistry::DefaultInitialCapacityRecords);
static hbe::TAtomicConfigParam<std::size_t> growByRecords("Task.RegistryGrowByRecords",
        "Task records each growth of the task record table",
        TaskRegistry::DefaultGrowByRecords);

taskRegistry.Initialize("TaskRegistry", initialRecords.Get(), growByRecords.Get());
