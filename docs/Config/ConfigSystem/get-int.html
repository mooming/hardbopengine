GetInt

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h const noexcept read an int parameter by name, where the answer for "no such parameter" is -1

Signature

[[nodiscard]] int GetInt(const StaticString& key) const noexcept;

Function description

Interns key, looks it up in intParams and calls the stored getter, which reaches the owning ConfigParam<int>::Get. The lookup does not cross maps, so an identically-named size_t, float or byte parameter is a miss rather than a conversion.

A miss logs one line under EngineSettings and returns -1. That is the only stand-in in this family that is unlikely to be a real value — which is worth more than it sounds, and is still not a guarantee.

Parameters

ParameterTypeRequirement
key const StaticString& The registered name. No int parameter is registered anywhere in Engine/ or Applications/ — the engine's live parameters are four byte, three size_t and one float in a default build — so against a stock engine this function always takes the miss path

Return value

TypeWhat you get
int The parameter's value, or -1 for a null or absent key. Use the answer as a value only for parameters whose legal range excludes -1; a parameter that counts retries, deltas or signed offsets can honestly hold it, and then no caller can tell the two apart
int and size_t are separate maps even though one converts to the other. That separation is deliberate: reading a size_t parameter through an int would narrow a 64-bit count silently, so the design makes it a miss instead. The cost you pay here is that a subsystem which changes a parameter's type from int to size_t breaks every name-based reader without a single compile error — the log line is the only signal, and it is Info-level.

Examples

Illustrative — no call site for this exists in the repository, and no int parameter exists for it to find.

auto& settings = hbe::ConfigSystem::Get();

const auto lanes = settings.GetInt("Audio.LaneCount");

if (lanes <= 0)
{
        // Covers three cases at once and cannot separate them: the parameter is missing, it was
        // registered under another type, or it is genuinely 0 or negative. Only the log says which.
        return;
}

for (int lane = 0; lane < lanes; ++lane)
{
        // …
}

For a count that should never be negative, read it as GetSize from a size_t parameter — the type the engine already uses for its three task-registry settings, whose real registration is on that page.
