SetSize

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h one overload write a count- or capacity-valued parameter — the type that cannot go negative, and cannot be resized by itself

Signature

void SetSize(const StaticString& key, size_t value);

Function description

Looks key up in sizeParams and calls the setter stored there, which forwards to ConfigParam<size_t>::Set. Same shape as every other write here: lookup, null check, call — no entry is created and no value is cached in the registry.

The engine's size_t parameters are the task record table sizes, all three registered by TaskSystem::Initialize and all three read exactly once, before the registry is built: Task.RegistryInitialRecords, Task.RegistryGrowByRecords and Task.RegistryMaxRecords. That reading pattern is the contract this page has to state plainly — see the box below.

Writing a parameter does not reconfigure the subsystem that read it. A ConfigParam is a value with a name attached, not a subscription: the task registry takes its initial capacity, growth step and ceiling as arguments at Initialize time and never asks again. So SetSize("Task.RegistryMaxRecords", …) changes what a future Initialize would read, and changes nothing about the table that already exists. Look for a Set… or Resize-style call on the owning subsystem if you need the change to take effect now; where none exists, the parameter is effectively start-up-only. ConfigParam::Set is the same story from the other side.

Parameters

ParameterTypeRequirement
key const StaticString& The name of a registered size_t parameter. Null is logged at Warning; absent is logged at Info under EngineSettings
value size_t The new count. No validation of any kind: a capacity smaller than the number of things already in flight, or a growth step of 0, is stored without comment. For Task.RegistryMaxRecords the header's own description says "0 means no ceiling", which is the one case where a zero is meaningful rather than degenerate

Return value

void — one log line if the name is null or missing, nothing otherwise. Confirm through GetSize, noting that its not-found answer is 0 and that 0 is a legitimate stored value.

Examples

The registration side is real code; the write side is illustrative, since nothing in the tree writes these keys.

static hbe::TAtomicConfigParam<std::size_t> maxRecords("Task.RegistryMaxRecords",
                                                     "Largest the task record table may grow. 0 means no ceiling",
                                                     TaskRegistry::DefaultMaxCapacityRecords);

taskRegistry.SetMaxCapacity(maxRecords.Get());

From Engine/Core/TaskSystem.cpp, hbe::TaskSystem::Initialize — condensed: the registration and the read are separated by two sibling parameters in the source

Illustrative — the write below has no counterpart in the repository.

auto& settings = hbe::ConfigSystem::Get();
settings.SetSize("Task.RegistryMaxRecords", 8192);   // stored; the live registry does not notice
