Register

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h 10 overloads installs a by-reference path to somebody else's parameter — the only way anything gets into the registry

Function description

Five value types, each with a non-atomic and an atomic form. The two forms of one type install into the same map, so the pair differs only in which ConfigParam specialization it accepts.

Each overload takes the interned identity of the parameter's name, checks that map for it, then stores a ParamItem holding three things: the interned description, a getter that calls param.Get(), and a setter that calls param.Set(value). Both closures capture &param — the registry stores no copy of any value, and a name-based read is a call into the owning object.

The bool overloads declare their value as uint8_t internally, which is why bool and uint8_t parameters share byteParams and why GetByte reads a bool parameter as 0 or 1. The int, size_t and float overloads address their own map each.

A name already present in that map is refused: one line is logged at FatalError under the EngineSettings category — "The key … is duplicated. It's not allowed strictly." — and the function returns without installing anything. Nothing is overwritten and the existing entry keeps pointing at the parameter it was given, so the second parameter simply does not exist as far as name-based access is concerned. The first registration wins.

The parameter must outlive the registry, and there is no way to unregister. A captured reference is not an ownership claim. Every engine parameter is a function-local static, which dies during exit processing while the Get() singleton is destroyed later still, so from the moment an owner dies its entry is a live path into a destroyed object (the destructor page traces the order). Since ConfigParam holds a std::mutex it cannot be copied or moved, meaning a parameter that is registered has a stable address — keep it at static or global lifetime, never in a container that reallocates and never as a temporary.
With ENGINE_PARAM_DESC_ENABLED set to 0 the whole registry collapses onto one key. That macro removes the name and desc members from ConfigParam, so GetName() returns a default-constructed StaticString — which is the interned string "None", not an empty one. This function checks for duplicates but never for a missing name, so within each map the first parameter wins the None key and every later parameter of that same map is refused — at most four entries survive a whole engine built that way, one per map, and the dump prints them all as None. It is defined as 1 in BuildConfig.h; turning it off is not a size optimisation you can make casually.
Registration is a mutation and is not synchronised. Concurrent calls race on the same unordered_map. Build every parameter before starting worker threads — or accept the ordering the engine already has, where a parameter is created the first time its subsystem initialises. Get() repeats why this matters.

Parameters

ParameterTypeRequirement
engineParam TConfigParam<T>& or TAtomicConfigParam<T>&, i.e. ConfigParam<T, IsAtomic> A live parameter whose name is not yet taken in the map its type maps to. It is taken by non-const reference — the parameter is not modified here, but a const object cannot be registered, since the setter the registry stores needs a mutable target. Overload resolution picks the overload from T and IsAtomic; a type outside bool, uint8_t, int, size_t, float has no overload and will not compile

Return value

void, and there is no way to ask whether it worked. Refusal is reported by log line only, so a caller that must know reads the parameter back by name afterwards — and must remember that a missing key answers with a stand-in that looks like a value (GetInt).

Examples

The only call site in the engine: a parameter registers itself as the last act of its own constructor.

ConfigParam(const char* inName, const char* inDesc, T defaultValue,
            std::thread::id id = std::this_thread::get_id())
        : value(defaultValue)
{
        auto& settings = ConfigSystem::Get();
        settings.Register(*this);
}

From Engine/Config/ConfigParam.h, condensed — the real initialiser list is conditional on ENGINE_PARAM_DESC_ENABLED and !RELEASE_BUILD

Which overload that line selects is decided by the parameter's own two template arguments. The engine's live parameters are all TAtomicConfigParam<uint8_t> (the log levels) or TAtomicConfigParam<std::size_t> (the task registry sizes), so every registration in a running build goes through an atomic overload — see ConfigParam constructors for the call sites.
