PrintAllParameters

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h const, not noexcept the shutdown dump of every registered parameter — and by default the level it prints at is filtered out

Signature

void PrintAllParameters() const;

Function description

Opens a logger on the EngineSettings category at ELogLevel::Verbose, walks byteParams, intParams, sizeParams and floatParams in that order, and emits one line per entry in the form name = value (description) — the value produced by calling that entry's getter, the description being the interned string Register took from the parameter. The dump is fenced by a header line and a closing line, so it is findable in a mixed log by eye.

An entry whose getter is empty is reported as an error naming the key ("null getter") and skipped, which is the only way a corrupted entry becomes visible at all. Because the function obtains values by calling every getter, it touches every registered parameter in the process — no other member of this class does that, and it is what makes this the function most likely to reach a stale entry (destructor explains the window).

In a default build it prints nothing. The lines go out at Verbose, and Logger::AddLog drops anything below the global Log.Level parameter, whose default is Info. The filtering happens before the category is consulted, so raising Log.Engine or filtering on EngineSettings does not help — the key to change is Log.Level, with SetByte("Log.Level", 0), before the call. Everything else in the dump is the same either way: it just silently produces no output.

Parameters

None — the dump covers all four maps and cannot be narrowed to one type, one key or one prefix.

Return value

void. The output is a log stream, not data: the entries cannot be enumerated, counted or read back programmatically through this class, so a caller that needs the parameter set as values has to keep its own list. That absence is recorded on the class Coverage section rather than papered over with a workaround this header does not offer.

Examples

The engine's own call site, at shutdown, together with the two lines that would have made it readable:

auto& configSys = hbe::ConfigSystem::Get();

#ifdef __DEBUG__
        //        const auto logLevel = static_cast<uint8_t>(ELogLevel::Verbose);
        //        configSys.SetByte("Log.Engine", logLevel);
        //        configSys.SetByte("Log.Level", logLevel);
#endif // __DEBUG__

// … other shutdown reporting …
configSys.PrintAllParameters();

From Engine/Engine/Engine.cpp, hbe::Engine::ShutDown — the SetByte pair is present in the source but commented out

That comment block is the reason this page says what it says: the mechanism to make the dump visible exists in the tree and is disabled, so a shutdown log with no parameter list is the expected outcome rather than a bug in the registry. To enable it in a ConfigParam-owning subsystem instead of editing the engine, set the level earlier in the run:

Illustrative — this pair has no live call site in the repository.

auto& settings = hbe::ConfigSystem::Get();
settings.SetByte("Log.Level", 0);        // Verbose — the only change that lets the dump through
settings.PrintAllParameters();
settings.SetByte("Log.Level", 1);        // restore: Verbose everywhere is not a state to run in

What the dump shows in a default build is eight lines: four byte-map log levels, three size_t task-registry sizes and one float threshold — see GetSize for the names. Levels and the logger they travel through belong to Log.
