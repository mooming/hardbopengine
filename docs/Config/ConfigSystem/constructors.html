ConfigSystem (constructors)

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h 1 defaulted, 4 deleted one registry per process in practice, because a second one is a registry that knows nothing

Signatures

/// the only constructible form
ConfigSystem() noexcept = default;

/// none of these exist
ConfigSystem(const ConfigSystem&) = delete;
ConfigSystem(ConfigSystem&&) = delete;
ConfigSystem& operator=(const ConfigSystem&) = delete;
ConfigSystem& operator=(ConfigSystem&&) = delete;

Function description

Construction takes four empty hash maps and nothing else — no allocation is required to build an empty registry, no key is read, and noexcept holds because there is no work that can fail. All the class's state is filled later by Register.

The four deletions are the part with intent. A copy of a registry would be a copy of closures that capture other objects' parameters by reference, so a copied entry would be a live path to parameters the copy has no claim on; deleting copy and move makes a ConfigSystem& a reference you cannot accidentally duplicate, and it is what stops the registry being embedded by value somewhere and drifting away from the one everything registers into.

The default constructor is public, so a private registry compiles — and is silently useless. ConfigSystem local; is legal C++ and is not the engine's registry: no ConfigParam points at it, because a parameter registers itself with Get() at construction time. Every GetInt on a local instance reports not-found and returns its stand-in value, every SetInt is refused, and no diagnostic names your instance as the wrong one — the "is not found" line looks identical. Obtain the registry through Get() and there is no way to make this mistake.

Parameters

None. The defaulted constructor takes no argument, and no other constructor exists — you cannot build a registry seeded from something, because there is nothing to seed it from.

Return value

Constructors have no return value. What you get is an object with four empty TMap members and no entries; if the point is to reach the engine's parameters, the object you want is already built and is what Get() hands out.

Examples

Illustrative — no call site for this exists in the repository, because nothing in the engine constructs a second registry.

// What you should write: take the one instance.
auto& settings = hbe::ConfigSystem::Get();
settings.SetByte("Log.Level", 0);

// What compiles and does nothing you can observe:
hbe::ConfigSystem localRegistry;              // empty, and stays empty
localRegistry.SetByte("Log.Level", 0);      // logs "is not found" under EngineSettings

The key "Log.Level" and its type are real: that parameter is a uint8_t registered by Logger::AddLog — see Log: Logger for what setting it does.
