ConfigSystem

Engine/Config/ConfigSystem.h namespace hbe final not copyable, not movable the runtime parameter database: five types in four maps, reached by interned name, changed while the process runs

Class description

A key-value store of accessors, not of values. Each entry holds a getter and a setter closure that read and write somebody else's ConfigParam, so the database never owns a setting and never has to be told a value changed — it just knows how to reach it. That indirection is what makes the two halves of the module fit together: a subsystem holds its parameter and reads it as a direct member access with no lookup, while a debug overlay or a shutdown dump reaches the same number by name through this class.

Keys are StaticStringID — the interned identity of a StaticString — so two literals that spell the same name hash to one entry, and every lookup here interns its key first. The interface takes const StaticString&, never a raw string.

There is exactly one instance in practice, reached with Get(), and one way in: Register is called from the ConfigParam constructor, so a parameter announces itself the moment it is built. Everything else — Set…, Get…, PrintAllParameters — only reaches what is already registered.

A failed lookup is not an error you can detect from the return value. A key that is absent, or a null key, logs one line and then returns a stand-in: false from GetBool and GetByte, -1 from GetInt, 0 from GetSize, 0.0f from GetFloat. Each of those is a legitimate value a real parameter can hold, so GetInt("Budget") == -1 cannot tell you whether the parameter exists. Nothing here throws and nothing returns a status; the log is the only signal.
bool and byte are one map. bool parameters are registered into byteParams as uint8_t, so SetByte writes a bool parameter and GetByte reads one (as 0 or 1), and the reverse is true of SetBool against a uint8_t parameter — which clamps it to 0 or 1. The duplicate-key test is per map, so a name is only forbidden against the other names in its own map.

Template parameters

None — ConfigSystem itself is not a template. The type parameter lives on its nested members (ParamItem<T>, TGetter<T>, TSetter<T>, TMap<T>) and on the ConfigParam<T, IsAtomic> it registers.

ParamItem template<typename T> struct ParamItem final { StaticStringID desc; TGetter<T> getter; TSetter<T> setter; }; public nested type One entry. desc is the interned description taken from the parameter, used only by PrintAllParameters; a default-constructed item has both callables null, which is how an unknown key is answered
TMap template<typename T> using TMap = std::unordered_map<StaticStringID, ParamItem<T>>; public alias The container, keyed on interned identity. Note which hash is used: std::hash<StaticStringID> reinterprets the interned pointer as a number, so bucket position depends on where the string table placed the name
byteParams TMap<uint8_t> byteParams; private Serves bool and uint8_t parameters, which is why one map holds two of the five types
intParams TMap<int> intParams; private Serves int parameters, reached by SetInt and GetInt
sizeParams TMap<size_t> sizeParams; private Serves size_t parameters. Every task-registry tuning knob in the engine lives here
floatParams TMap<float> floatParams; private Serves float parameters

Four maps rather than one variant map is what keeps the value types exact at the boundary: a size_t parameter cannot be read through a path that narrows it to int, because the lookup will not find it at all. The cost is that the type is part of a name's identity — GetInt cannot see a parameter registered as float under the same key.

Non-member helper functions

None. ConfigSystem.h declares the class and nothing at namespace scope; the lookup helper that decides what a missing key does lives in the anonymous namespace of ConfigSystem.cpp and is not a name you can call.

Coverage

GapDetail
No removal, no reset, no enumeration by name There is no Unregister, no Clear, and no way to ask how many parameters exist or to list their names without PrintAllParameters's log output. The header has no such member, so this page documents the absence rather than a substitute
No persistence, and no file feeding it Nothing in the engine reads a ConfigFile into these maps, and nothing writes them out. Registering a parameter gives it its compiled-in default and no file changes that — the two halves of the module are not wired together
Thread safety, stated as what the header guarantees No lock guards the maps. Concurrent lookups are safe once registration is finished, because lookup only reads; concurrent Register is a data race on the same unordered_map. Whether the value behind a getter is a plain field or an atomic depends entirely on the IsAtomic argument of the parameter that owns it, which is ConfigParam's contract
The "not found" stand-in A function-local static ParamItem<T> in ConfigSystem.cpp supplies the empty item a failed lookup returns. It is not API and has no address you can compare against; each page names the value its getter produces instead
Which log level each diagnostic uses The level family, the category filter and the asynchronous destination are documented in Log. This page names the level per call, because a message that is filtered out is invisible in a normal build and that changes which failures you can actually see
