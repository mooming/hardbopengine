SetInt

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h one overload write a registered int parameter by name — and the type, not the number, decides whether it lands

Signature

void SetInt(const StaticString& key, int value);

Function description

Looks key up in intParams and calls the setter stored in that entry, which writes the owning ConfigParam<int>::Set. The lookup is confined to the int map: a name that exists as a size_t, float or byte parameter is reported not-found rather than converted, so a type change in a subsystem silently turns every matching write into a no-op log line.

Failing to find the key is not exceptional here — it is the common case. Ten Set… and Get… names address five maps, but a stock engine registers nothing as int at all (the set of real names is listed on the SetBool page), so every SetInt in a stock build takes the log-and-return path. The function is there for parameters an application adds.

Parameters

ParameterTypeRequirement
key const StaticString& The name of a registered int parameter. Null is logged at Warning; absent is logged at Info under EngineSettings
value int The new value. Signed, so negative is storable — and negative is exactly what GetInt answers for a missing key, which makes -1 a value to avoid in a parameter you intend to probe

Return value

void. There is no distinction in the return channel between "written", "not registered" and "registered under a different type" — only the log line differs. Verify with GetInt.

A null setter is checked before it is called. The entry a failed lookup returns is a default-built ParamItem whose std::function members are empty, and the implementation tests for that and logs "has no setter" before invoking. So the stand-in item cannot crash a write; the cost of the design is only that the failure is quiet.

Examples

Illustrative — no call site for this exists in the repository, and none could take effect until an int parameter is registered.

// Registering first is what makes the write reach anything. The form is from
// Engine/Core/TaskSystem.cpp, which registers its parameters as function-local statics.
static hbe::TAtomicConfigParam<int> maxRetries("Net.MaxRetries",
                                                "Connection attempts before giving up",
                                                3);

auto& settings = hbe::ConfigSystem::Get();
settings.SetInt("Net.MaxRetries", 5);        // now it lands
settings.SetSize("Net.MaxRetries", 5);       // wrong map: logs not-found, changes nothing

Note the second call: the name is correct, the number is in range, and the write still does nothing — because size_t is a different map. That is the failure mode this page exists to warn about.
