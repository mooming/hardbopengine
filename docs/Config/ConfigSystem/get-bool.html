GetBool

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h const noexcept read a byte-map parameter as a bool — and treat its answer as a value, never as an existence check

Signature

[[nodiscard]] bool GetBool(const StaticString& key) const noexcept;

Function description

Interns key, finds the entry in byteParams, calls its getter and narrows the uint8_t the map stores to bool. Both bool and uint8_t parameters live in that map, so a byte parameter holding 7 reads back as true here.

Nothing about the failure path is exceptional: a null key or an absent key produces one log line and a default-built entry whose getter is empty, and the function then returns false. It is const noexcept, so "cannot fail" means "will not tell you" — no assert, no status, no exception; the absence is reported in the log and nowhere else.

Parameters

ParameterTypeRequirement
key const StaticString& The registered name; a string literal converts and interns on the way in. The lookup is confined to the byte map, so a parameter of that name registered as int, size_t or float is not found rather than converted

Return value

TypeWhat you get
bool The parameter's current value, or false if the key is null or absent. Because the two cases are the same answer, GetBool cannot be used to decide whether a parameter exists — and since no bool parameter is registered anywhere in Engine/ or Applications/, every call against a stock engine returns this false
Default-off is the dangerous reading of a missing flag. Code written as if (settings.GetBool("Render.UseDilation")) behaves, when the parameter was never registered or was registered under a different type, exactly like a flag that is legitimately switched off: silently, correctly, and with one Info-level line under EngineSettings as the only evidence. If the feature must be on unless something turns it off, invert the name and test for the negation ("Render.DisableDilation"), so that the stand-in answer is the safe one.

Examples

Illustrative — no call site for this exists in the repository, and no bool parameter is registered for it to find.

auto& settings = hbe::ConfigSystem::Get();

// The owning subsystem registers it, in the form Engine/Core/TaskSystem.cpp uses:
//   static hbe::TAtomicConfigParam<bool> dilation("Render.DisableDilation", "…", false);

if (settings.GetBool("Render.DisableDilation"))
{
        // a missing key and a flag genuinely set to true differ only in the log
}

// A debug overlay that must not lose a value it is about to change:
const bool previous = settings.GetBool("Render.DisableDilation");
settings.SetBool("Render.DisableDilation", true);
// … take the measurement …
settings.SetBool("Render.DisableDilation", previous);

For the log-level parameters that do exist, the byte-typed reader is GetByte; the writers are SetBool and SetByte.
