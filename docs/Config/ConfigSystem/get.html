Get

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h static [[nodiscard]] noexcept the one registry, built on the call that first needed it

Signature

[[nodiscard]] static ConfigSystem& Get() noexcept;

Function description

Returns a reference to a function-local static ConfigSystem instance. Two consequences follow from that one construct, and both matter to a caller. It is built on the first call rather than at load time, so nothing here depends on static-initialisation order — and it is destroyed during exit processing, which is the far end of the lifetime contract described on the destructor page.

The first call is also usually inside a ConfigParam constructor, which calls ConfigSystem::Get() in order to register itself. So in a normal process the registry is older than every parameter in it, and its reference stays valid for the whole run: there is no shutdown call that invalidates it, no reset, and no way to build a competing one that this function would return.

Calling it is free after the first time. The reference is not cached anywhere in the engine, so call sites do call it repeatedly — but a reference held across a function body is the cheaper habit, and it is what the engine's own call site does. noexcept holds even on the constructing call, because that constructor allocates nothing.
Registration is not thread-safe, and this function is where two threads meet. If two ConfigParam objects are constructed concurrently for the first time, both reach Register and mutate the same unordered_map with no lock in between. The singleton's own construction is thread-safe; the maps it hands out are only safe for concurrent lookup. Finish registration before you start threads, or register from one thread.

Parameters

None.

Return value

TypeWhat you get
ConfigSystem& The process-wide registry, never null, never a copy — [[nodiscard]] makes a call whose result is thrown away a compile error, since such a call cannot do anything. The reference is valid until static destruction, and what it can safely do narrows once any owner of a ConfigParam has died: see the destructor

Examples

The engine's own use: take the reference once at the top of the block, then use it.

auto& configSys = hbe::ConfigSystem::Get();

// … a debug-only SetByte pair elided here …

configSys.PrintAllParameters();

From Engine/Engine/Engine.cpp, hbe::Engine::ShutDown

The same call from inside a parameter constructor is what starts the singleton — see Register for that snippet, which is the only other place in the engine that names this function.
