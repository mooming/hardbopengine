GetByte

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h const noexcept read a byte-map parameter — the way to inspect a log level without touching the subsystem that owns it

Signature

[[nodiscard]] uint8_t GetByte(const StaticString& key) const noexcept;

Function description

Interns key, finds its entry in byteParams and calls the stored getter. The map is typed uint8_t and both bool and uint8_t parameters register into it, so this single function reads every log level the engine holds — four of them in a default build, five once MEMORY_LOGGING_ENABLED adds Log.Memory — plus any bool parameter as 0 or 1.

On a miss the answer is the empty entry's stand-in, written in the source as return false; — a bool literal converted to uint8_t, i.e. zero. See what that means below before using the result in a comparison.

Parameters

ParameterTypeRequirement
key const StaticString& The registered name. Byte-map names in a stock engine: Log.Level, Log.Engine, Log.Engine.Print and Log.TaskSystem — Log.Memory is registered only when MEMORY_LOGGING_ENABLED is 1, which it is not by default (BuildConfig). Anything else, including the task-registry sizes, which are size_t, is a miss

Return value

TypeWhat you get
uint8_t The parameter's current value, or 0 for a null or missing key. For the log-level parameters, 0 is ELogLevel::Verbose — the most permissive level there is, so a misspelled name does not look like an error, it looks like "log everything"
A miss and a real value are the same number here, and for these five keys the miss value is the loudest setting. GetByte("Log.En gine") — one stray space — returns 0, and a consumer written as if (level < static_cast<ELogLevel>(threshold)) return; then stops filtering anything out. If the value has to be trusted, confirm the parameter exists first: read it once at start-up, when the log line saying "is not found" is still cheap to notice, rather than inside a per-message path where the same line is emitted over and over and never read.
This is a by-name read of somebody else's hot-path value. The getter is a std::function, so the call costs an indirection and an interned lookup — fine in a debug overlay or a start-up check, wrong inside a per-log-line filter. The engine's own filters read the ConfigParam directly for exactly that reason, and reach the registry only to list and to change.

Examples

Every parameter this can read is registered in the form below; the read itself has no live call site.

static hbe::TAtomicConfigParam<uint8_t> CPLogLevel("Log.Level", "The Default Log Level",
                                                  static_cast<uint8_t>(ELogLevel::Info));

if (level < static_cast<ELogLevel>(CPLogLevel.Get()))
{
        return;
}

From Engine/Log/Logger.cpp, hbe::Logger::AddLog

Illustrative — the read by name, for a debug overlay or a start-up report.

auto& settings = hbe::ConfigSystem::Get();

const auto globalLevel = settings.GetByte("Log.Level");     // 1 = Info in a fresh process
const auto memoryLevel = settings.GetByte("Log.Memory");   // only registered if MEMORY_LOGGING_ENABLED

// The second one is the trap: with memory logging compiled out, that parameter does not exist,
// GetByte answers 0, and the report reads as "memory logging is verbose".

Log.Memory is registered inside #if MEMORY_LOGGING_ENABLED in Engine/Memory/MemoryManager.cpp, and that define is 0 by default (BuildConfig) — so this example is not hypothetical: the parameter is absent in a stock build and the answer you get is the one that looks most like a deliberate setting.
