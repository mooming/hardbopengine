GetFloat

member of hbe::ConfigSystem Engine/Config/ConfigSystem.h const noexcept read a duration or threshold by name, where the answer for a missing key switches every threshold off at once

Signature

[[nodiscard]] float GetFloat(const StaticString& key) const noexcept;

Function description

Interns key, finds its entry in floatParams, calls the stored getter — a call into ConfigParam<float>::Get, which for the atomic form is an atomic load. No rounding, no unit conversion: the number the parameter holds is the number you get, in whatever unit its description names.

One float parameter exists in a stock engine: "TaskStreamDurationThreshold", default 0.16f, seconds, read per task-stream iteration to decide when a task is slow enough to warn about (Engine/Core/TaskStream.cpp).

Parameters

ParameterTypeRequirement
key const StaticString& The registered name of a float parameter. Names in another map are misses, including the byte-map log levels and the size_t registry sizes

Return value

TypeWhat you get
float The parameter's value, or 0.0f for a null or absent key. There is no NaN and no sentinel: a miss is indistinguishable from a parameter deliberately set to zero
A missing threshold reads as zero, and zero is never neutral for a threshold. The live consumer compares deltaTime > thresholdDuration.Get(), so a threshold of 0.0f warns on every task that ran at all. Reach the same key by name through a misspelling and you get the same 0.0f — a log stream that suddenly fills with slow-task warnings and a single Info line under EngineSettings to explain it. Compare against a bound you chose rather than testing for non-zero: if (threshold > 0.0f && threshold < 10.0f) at least rejects the value that a failure produces.
Do not test the result with ==. 0.16f is not exactly representable, so a value that was written as a literal and read back through a computation may differ in the last bits; and 0.0f as a not-found marker is exact, which makes an equality test against it the one comparison that is misleading here. Use a range, or read the parameter that owns the value.

Examples

The registration is real; the by-name read has no live call site.

static hbe::ConfigParam<float, true> thresholdDuration(
        "TaskStreamDurationThreshold",
        "Print a warning log if it detects slower task. (seconds)",
        0.16f);

// … later, per iteration of that stream:
if (deltaTime > thresholdDuration.Get())

From Engine/Core/TaskStream.cpp

Illustrative — reading the same setting from outside the stream, e.g. from a debug overlay.

auto& settings = hbe::ConfigSystem::Get();

const float threshold = settings.GetFloat("TaskStreamDurationThreshold");

if (threshold > 0.0f && threshold < 10.0f)
{
        // a value we can display as a real threshold
}
else
{
        // either absent (0.0f) or set to something that stops the warning working
}

Writing it goes through SetFloat, and unlike the size parameters this one takes effect on the next iteration because the stream re-reads it each time.
