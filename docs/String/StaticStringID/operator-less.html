Module Index / String / StaticStringID / operator<

operator<

member of hbe::StaticStringID Engine/String/StaticStringID.h ordering by table address, not alphabetically

Signature

[[nodiscard]] bool operator<(const StaticStringID& rhs) const

Function description

ptr < rhs.ptr — ordering by table address. The result is deterministic for a given run (the same text always gets the same address, so the same id), which is what an ordered container of ids needs; it says nothing about the text itself. "zebra" may order before "aardvark" purely because of which was interned first.

Never use this for user-facing sorting. The order is insertion history and hash-bucket arithmetic, not lexicographic. Sorting names for display belongs to text comparison over the characters, not to the id.

Parameters

ParameterTypeRequirement
rhsconst StaticStringID& Another id. Its text is never read.

Return value

true when this id's address sorts before rhs's in the intern table.

Examples

The ordering is what lets an id key ordered containers without a text comparison; there is no call site in the repository that relies on it today — the operator exists so an id can be a map key of either kind.
