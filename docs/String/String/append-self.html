member of hbe::String Engine/String/String.h the piece appended in place, 1.5x growth when needed

Function description

The mutating form of Append: the piece goes onto this string's buffer. Growth reserves 1.5× the needed size when the buffer must expand, then resizes and copies the piece in — the loop-friendly allocation pattern: 

	if (newLength > buffer->capacity())
	{
		buffer->reserve(newLength * 3 / 2);
	}

	buffer->resize(newLength);
	memcpy(buffer->data() + length, text, textLength + 1);

From Engine/String/String.cpp, String::AppendSelf(const TChar* text) noexcept — the grow-then-copy shape shared by the int, float, pointer and String overloads

The character overload is the special case — it writes the letter and the terminator in one pass without the reserve logic, since two bytes always fit or the buffer is already at its size: 

	auto& buf = buffer.Get();
	const auto index = buf.size();
	...
	buf.data()[index] = letter;
	buf.data()[index + 1] = '\0';

From Engine/String/String.cpp, String::AppendSelf(const TChar letter) noexcept

An empty String operand appends nothing. These overloads are what operator+= dispatches to.

The TChar overload is a single-pass append on purpose: it takes the buffer reference once, resizes to make room for the letter and the trailing null, and writes both directly — half the Shareable dereferencing of the previous push-then-assign pattern. The trailing null is what keeps c_str() valid without a second pass.
