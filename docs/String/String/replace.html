Replace

member of hbe::String Engine/String/String.h first occurrence in [offset, endIndex) swapped

Signature

[[nodiscard]] String Replace(const String& from, const String& to, Index offset = 0,
								 Index endIndex = InvalidIndex) const noexcept

Function description

The first occurrence of from within [offset, endIndex) is swapped for to; the result is a new string and the receiver is untouched. Defaults make it whole-string: offset = 0, endIndex = InvalidIndex (resolved to the length). Not found, an empty from, or an empty range each return a Clone — replacement that finds nothing still costs a copy.

A search term longer than the range scans out of bounds. The scan loop runs for (Index i = actualOffset; i <= actualEndIndex - searchLength; ++i) with Index = size_t: when searchLength exceeds actualEndIndex, the bound underflows to a huge value and the loop reads past the buffer's characters. ReplaceAll guards exactly this case (if (searchLength > strLength) return Clone();); Replace does not. Passing a from longer than the string — or longer than the range from offset — is undefined behaviour today, not a clean false.

Parameters

ParameterTypeRequirement
fromconst String& The text to find; empty returns a clone. Must not be longer than the search range — see the gap.
toconst String& The replacement; any length, including empty (a deletion).
offsetIndex Search start; invalid values resolve to 0, values at or past the end return a clone.
endIndexIndex Search end (exclusive); InvalidIndex resolves to the length.

Return value

A new String with the first match replaced, or a clone when nothing matched.

Examples

	String str("foo bar foo baz");
	auto result = str.Replace(String("foo"), String("XXX"), 5);

	if (result != "foo bar XXX baz")
	{
		ls << "Replace with offset failed: expected 'foo bar XXX baz', got '" << result.c_str() << "'" << lferr;
	}
