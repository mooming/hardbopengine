member of hbe::String Engine/String/String.h hash first, then length, then bytes

Function description

The String-vs-String form short-circuits on the cached hash before touching a character — which is why a stale hash (see GetBuffer) can make two equal strings compare unequal: 

	if (hashCode != string.hashCode)
	{
		return false;
	}

	const auto length = Length();
	if (length != string.Length())
	{
		return false;
	}

	for (Index i = 0; i < length; ++i)
	{
		if ((*buffer)[i] != (*string.buffer)[i])
		{
			return false;
		}
	}

	return true;

From Engine/String/String.cpp, String::operator==(const String& string) const noexcept

The const char* form is careful at both ends: a null rhs equals an empty string, an empty *this equals only a terminator at rhs[0], and the byte loop is followed by a check that rhs actually ends where the string does — so "abc" does not equal "abcd". The nullptr_t form is buffer->empty() — true only when the buffer holds no characters at all, which is the empty-substring shape, not the default-constructed one (that buffer holds one terminator, and is not == nullptr).
