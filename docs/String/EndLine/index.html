EndLine

Engine/String/EndLine.h final no data a named newline: an empty type that becomes the string literal for one

Class description

A type whose only purpose is to become a newline when a stream takes it. It holds nothing, converts to "\n", and exists so a call site reads as intent — ls << name << hendl — rather than ending a line with an escape sequence that is invisible in the source. 

class EndLine final
{
public:
	[[nodiscard]] operator const char*() const
	{
		return "\n";
	}
};

static constexpr EndLine hendl;

From Engine/String/EndLine.h, complete — this is the whole class

The type earns its place only if something can take it as a type. Nothing in the engine does today: every use relies on the conversion, so hendl reaches the stream as a const char*. It is a named newline, not a manipulator — which is honest, and is what the Coverage table below records rather than glossing over.

Template parameters

None — EndLine is not a template and takes no character or allocator parameters.

Class properties

None. The class has no data members, so it is empty, trivially copyable, and its size is one byte like every other empty type. Copying hendl is free, and there is deliberately nothing to observe about a copy.

Class methods

operator const char* [[nodiscard]] operator const char*() const Returns the string literal "\n" — the whole behaviour of the class

There is no constructor declared, no destructor declared, and no assignment operator: the implicit ones are correct for an empty type, and writing them out would add six lines that a reader has to check are still the defaults.

Non-member helpers

The single instance, and it is the reason the type is usable at a call site at all:

static constexpr EndLine hendl;

constexpr means no construction happens at run time. Declaring it static at namespace scope in a header gives it internal linkage, so each translation unit that includes EndLine.h gets its own object — which is harmless here only because the type is empty and stateless. A type with state would have quietly become several objects, one per translation unit, and inline constexpr is the spelling that gives one object tree-wide.

Do not confuse it with the lf, lfwarn and lferr of Test: those are TestCollection::LogFlush objects whose operator<< emits the testlet's accumulated message at a chosen level. They end a log record. hendl writes one newline character.
