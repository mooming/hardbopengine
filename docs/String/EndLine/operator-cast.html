From Engine/String/EndLine.h, complete

Function description

Returns the address of a two-byte string literal — a newline and its terminator — and nothing else. There is no state to consult, because EndLine has no members, so two calls on two different instances are indistinguishable.

The conversion is what makes hendl usable at all: it is applied implicitly when an output stream's operator<< needs a const char*, which is how ls << hendl writes a newline. Because the result is a literal in static storage, the pointer stays valid for the whole program and must never be freed.

Marked [[nodiscard]]: converting the marker and then throwing the pointer away is a mistake rather than a use, and the build is -Wall -Werror, so a discarded conversion is a compile error rather than a smell.

This is the class's entire callable surface. A reader who has read this page has read EndLine. That is also why the type is documented at all — a class whose API is a single conversion has no method name to search for, which is the case the reference gate used to miss entirely.

Parameters

None. The only operand is the implicit object parameter, and it carries no state.

Return value

TypeWhat you get
const char* Pointer to "\n" in static storage: two bytes including the terminator, valid for the program's lifetime, never to be freed or written through

Examples

using namespace hbe;

std::ostream& ls = ...;
ls << "##### TEST COMPLETED #####" << hendl;      // the conversion, resolved by operator<<

const char* text = hendl;                        // explicit: text[0] == '\n', text[1] == '\0'

The first form is how the tree uses it — Engine/Test/TestEnv.cpp, Engine/Math/AABB.cpp, Engine/Memory/ThreadSafeMultiPoolAllocator.cpp

What it does not do is flush or add a log record. A test's lf, lfwarn and lferr are TestCollection::LogFlush objects whose own operator<< emits the accumulated message at a level; hendl contributes one character and no side effects.
