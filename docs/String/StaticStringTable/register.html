Register

member of hbe::StaticStringTable Engine/String/StaticStringTable.h the mint — hash, search, reuse or store

Signature

[[nodiscard]] StaticStringID Register(const char* str)

[[nodiscard]] StaticStringID Register(const std::string_view& str)

Function description

The mint. Both overloads run the same four steps: hash the text into a bucket (GetTableID), take tableLock, linear-search that bucket, and either reuse the found view's address or store a fresh copy. The id is the address of the stored bytes — the table's memory, never the caller's: 

		auto& table = tables[tableID];
		std::string_view tmp(text);

		auto found = std::find(table.begin(), table.end(), tmp);
		if (found != table.end())
		{
			id.ptr = reinterpret_cast<const uint8_t*>(found->data());

			return id;
		}

		std::string_view sv = Store(tmp);
		table.emplace_back(sv);

		id.ptr = reinterpret_cast<const uint8_t*>(sv.data());

From Engine/String/StaticStringTable.cpp, StaticStringTable::Register(const char* text) — the locked body, table lookup and store

The search is bucket-local, so cost grows with how many distinct texts land in one bucket rather than with the total table size. Registration is serialized per table by tableLock; the store inside the lock descends into Allocate, which takes its own memLock — the fixed lock order is tableLock then memLock, and no path takes them the other way around. The std::string_view overload needs no zero termination from the caller; Store terminates the copy it makes.

Equal text, equal address. Both overloads hash with the same function (StringUtil::CalculateHash), so the same text always lands in the same bucket and the search always finds the earlier registration. A const char* and a std::string_view carrying the same characters produce the same id.

Parameters

ParameterTypeRequirement
strconst char* Zero-terminated text. Read only during this call; the id never references it afterwards.
strconst std::string_view& Character span of any length. Same copy-and-terminate treatment.

Return value

The id naming this text's permanent address in the table. Re-registering the same text returns an id with the same pointer, which is the whole interning contract.

Examples

Every StaticString constructor from characters registers through here; the predefined strings register at construction via RegisterPredefinedStrings.
