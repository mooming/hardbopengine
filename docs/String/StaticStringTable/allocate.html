Allocate

member of hbe::StaticStringTable Engine/String/StaticStringTable.h bump allocation over 1 MiB banks

Signature

static void* Allocate(size_t n)

Function description

The bank bump allocator, private and static — reachable from outside only through the nested Allocator adapter, and from Register through Store. Text bytes come from malloc'd banks of one mebibyte (capacity = 1024UL * 1024, a local constant — not Config::StaticStringBufferSize, which nothing in the engine reads): 

	std::lock_guard lock(memLock);
	while (banks.size() <= bankIndex)
	{
		banks.emplace_back(capacity);
	}

	if (!banks[bankIndex].IsAvailable(n))
	{
		banks.emplace_back(std::max(n, capacity));
		++bankIndex;
	}

	auto& bank = banks[bankIndex];
	auto ptr = bank.Allocate(n);

	return ptr;

From Engine/String/StaticStringTable.cpp, StaticStringTable::Allocate(size_t)

Three facts a caller of the public surface inherits. Storage is bump-only: no per-allocation free, ever — the destructor releases whole banks. An oversized request (larger than one bank) gets a bank of its own, sized max(n, capacity). And a bank that cannot fit a request is abandoned: bankIndex only moves forward, so the failed bank's remaining space is never used again — scattered large registrations can waste bank tails.

Two locks, one order. memLock guards bank growth and cursor advance; Register holds tableLock while calling down into here. The order is always tableLock then memLock; no code path reverses it.

Parameters

ParameterTypeRequirement
nsize_t Bytes to carve out. Callers pass text length plus terminator; there is no upper bound check beyond the bank arithmetic itself.

Return value

A pointer into bank memory, valid until the table is destroyed. Never freed individually; never moved.

Examples

Only Store and the nested Allocator::allocate call it — the latter so that, say, a std::vector templated on the nested allocator grows inside the same banks as the strings it indexes.
