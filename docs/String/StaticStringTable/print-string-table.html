PrintStringTable

member of hbe::StaticStringTable Engine/String/StaticStringTable.h diagnostic dump; its address column is always 0x0

Signature

void PrintStringTable() const

Function description

Diagnostic dump at ELogLevel::Verbose under the table's own category (GetName): the bank list with each bank's cursor against capacity, the non-empty bucket counts, then every interned string with a running index.

The per-element address column always prints 0x0. The loop builds each line from a default-constructed id whose pointer is never assigned: ls << count++ << " : [" << item << "] 0x" << (void*) id.ptr;. The string content and the counts are trustworthy; the hexadecimal column is a defect in the dump, not information about the element.

Parameters

None.

Return value

None — output goes to the logger, not to the caller.

Examples

A debugging aid with no production caller; run it from a debugger or a temporary call site when a cache-of-names bug is suspected.
