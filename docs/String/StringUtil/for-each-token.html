ForEachToken

member of hbe::StringUtil Engine/String/StringUtil.h split by walking; views, not copies

Signature

void ForEachToken(const char* str, const std::function<void(std::string_view)> func,
				  const char* separators = " \t\n\r")

Function description

Splits a C string by walking it once and handing the callback a view per token — no substring is ever built. Runs of separators produce no empty tokens; the final token is emitted after the loop ends. The default separator set is exactly the four whitespace characters — space, tab, newline, carriage return — which is why the tokenizer test's "abc def 123\n 456 \t\n\r 789 000 end." yields seven tokens.

The views are loans, not copies. Each std::string_view points into str; the callback must not outlive them. Collecting tokens means copying them into a TString — which is exactly what the engine's own test does with tokens.emplace_back(token).

Two degenerate inputs have defined behaviour: a null str calls nothing, and a null separators hands the whole string to the callback as one token — splitting is disabled, not crashed into.

Parameters

ParameterTypeRequirement
strconst char* Zero-terminated text to split; null is allowed and means "do nothing".
funcconst std::function<void(std::string_view)> Called once per token, in order. The view is valid only during the call.
separatorsconst char* Zero-terminated set of single-character separators; default is the four whitespace characters. Null disables splitting.

Return value

None — results arrive through the callback.

Examples

Debug symbol demangling splits mangled names with a custom separator set — Engine/OSAL/LinuxDebug.cpp: 

		StringUtil::ForEachToken(strs[i], PerToken, " \t\n\r+");
