StringUtil

Engine/String/StringUtil.h namespace hbe::StringUtil utility header trim, case, prefix and suffix, paths, tokens, reflection names, C-string primitives, hash

Class description

A utility header, not a class: free functions in namespace hbe::StringUtil over text that needs no object of its own. Two groups. The first trims, compares and reshapes a TString (the engine's HString) — Trim, case conversion, prefix and suffix tests, path splitting, tokenising. The second reads names out of the compiler's __PRETTY_FUNCTION__ — ToFunctionName and friends — which is how engine code logs a class or function name without writing it twice. The rest is the C-string layer the log line and the builders are built on: StrLen, StrCopy, and the djb2 CalculateHash the intern table hashes with.

Everything is defined in Engine/String/StringUtil.cpp; the header declares and nothing else. The __PRETTY_FUNCTION__ readers return StaticString, so every extracted name is interned once and compares by pointer afterwards.

The case functions are ASCII-only. ToLowerCase shifts 'A'–'Z' by a fixed offset and Trim tests std::isspace — no locale argument is passed and no Unicode is considered. Non-ASCII bytes pass through untouched, which is a feature for the engine's identifier-and-path workloads and a trap for real text processing.

Template parameters

None — the header declares no class and no function template. The two aliases below are the whole type surface.

Coverage

Every declared function has a page, and each page states the fallback behaviour its __PRETTY_FUNCTION__ input can produce. Not documented here: the StringUtilTest collection in Engine/String/StringUtil.cpp's TEST_ENABLED section (test-only, owning its coverage there), and the exact __PRETTY_FUNCTION__ spellings of compilers other than Clang — the readers are exercised in the tests against this compiler's output, and the pages describe the parsing rules rather than promising a spelling.
