CalculateHash

member of hbe::StringUtil Engine/String/StringUtil.h djb2, identical through both overloads

Signature

[[nodiscard]] size_t CalculateHash(const char* text)

[[nodiscard]] size_t CalculateHash(const std::string_view& str)

Function description

djb2 over the bytes: start at 5381, and for every character hashCode = ((hashCode << 5) + hashCode) + ch — hash times 33 plus the byte. Both overloads run the identical loop (the view one iterates the span, the pointer one walks to the terminator), so the same characters hash to the same value through either — the property that lets StaticStringTable bucket const char* and std::string_view registrations into one interning space: 

size_t CalculateHash(const std::string_view& str)
{
	size_t hashCode = 5381;

	for (size_t ch : str)
	{
		hashCode = ((hashCode << 5) + hashCode) + ch;
	}

	return hashCode;
}

From Engine/String/StringUtil.cpp, StringUtil::CalculateHash(const std::string_view& str)

Note what the loop does not do: no finalisation, no length mixing, no seed. Two strings that are anagrams of each other hash differently only by the luck of the order; this is a table-bucket hash, not a cryptographic or even a well-scattered general-purpose one — and it is also, byte for byte, what String's cached hashCode computes.

Parameters

ParameterTypeRequirement
textconst char* Zero-terminated text; the pointer walk relies on the terminator. Null is not checked.
strconst std::string_view& The span to hash — the overload for bytes that are not terminated, or whose length is already known.

Return value

The djb2 hash of the bytes, as size_t.
