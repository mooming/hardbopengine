StrLen

member of hbe::StringUtil Engine/String/StringUtil.h measured length; the bounded overload never reads past the bound

Signature

[[nodiscard]] size_t StrLen(const char* text)

[[nodiscard]] size_t StrLen(const char* text, size_t bufferSize)

Function description

The two overloads are the safe and the trusting spelling of the same question. The bounded one is strnlen — it never reads past bufferSize bytes, which is the right call for a buffer whose contents some earlier write may have failed to terminate: 

size_t StrLen(const char* text, size_t n)
{
	if (unlikely(text == nullptr || n == 0))
	{
#if !RELEASE_BUILD
		debugBreak();
#endif // !RELEASE_BUILD
		return 0;
	}

	return strnlen(text, n);
}

From Engine/String/StringUtil.cpp, StringUtil::StrLen(const char* text, size_t n)

Both overloads treat a null pointer (and, in the bounded form, a zero buffer size) as a programming error: a debugBreak() in every non-release build, and 0 as the answer in all builds. The unbounded overload is plain strlen and trusts the terminator absolutely — the log line uses the bounded form against Config::MaxPathLength, because a filename buffer is exactly the thing that may not be terminated.

Parameters

ParameterTypeRequirement
textconst char* The buffer to measure; null is a debug break, not a crash.
bufferSizesize_t Bound on the scan, in bytes. Zero is a debug break and answers 0.

Return value

The character count up to the terminator (strlen) or up to the bound, whichever comes first (strnlen); 0 for the rejected inputs.

Examples

The log line measures its inline text with the bounded overload — Engine/Log/LogLine.cpp: 

	const auto length = StringUtil::StrLen(inText, LastIndex);
