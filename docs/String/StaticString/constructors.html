Function description

Two families. The character constructors — const char*, std::string_view, and the template over any type with c_str() — register the text in the global StaticStringTable and keep the returned pointer as the identity: 

StaticString::StaticString(const char* string) noexcept
{
	auto& ssTable = StaticStringTable::GetInstance();
	id = ssTable.Register(string);
}

From Engine/String/StaticString.cpp, StaticString::StaticString(const char* string) noexcept

The default constructor interns "None" once and adopts its id, so it also reads the table — but only on the first call in a program, through a function-local static. The id constructor is the odd one out: it stores the id verbatim and touches nothing, which is how a caller passes an id that is Default (null) or one the table has not seen — the wrapper promises nothing about the text.

The template constructor exists so the engine's string types — HString, HInlineString — construct a StaticString without an explicit c_str() at the call site; the concept requires exactly that member, so anything without one falls back to the const char* or std::string_view overloads.
