Reserve

member of hbe::StringBuilder Engine/String/StringBuilder.h pre-grow so appends do not reallocate

Signature

void Reserve(size_t size) noexcept

Function description

buffer.reserve(size) — pre-grow the buffer so subsequent appends do not reallocate. The one tool a caller has to keep a known-large format allocation-free; without it, a long build pays the geometric growth series. Capacity is not content: Size() is unchanged by this call.

Parameters

ParameterTypeRequirement
sizesize_t Character capacity to guarantee. Passing a size smaller than the current one changes nothing.

Return value

None.

Examples

No call site in the repository today — every builder user appends without reserving and lets the buffer grow. The illustrative shape is a loop that would otherwise realloc per iteration: 

	StringBuilder args;
	args.Reserve(256);
	for (auto& entry : entries)
	{
		args << entry.name << ',' << hendl;
	}

Illustrative — the method is real; the call site is not
