HasFlag

namespace hbe Engine/Engine/EngineInitLevel.h constexpr noexcept the containment test Engine::Initialize uses to decide which subsystems to start

Signature

constexpr bool HasFlag(EInitLevel levels, EInitLevel flag) noexcept;

Function description

constexpr bool HasFlag(EInitLevel levels, EInitLevel flag) noexcept
{
        return (static_cast<uint8_t>(levels) & static_cast<uint8_t>(flag)) == static_cast<uint8_t>(flag);
}

A bitwise containment test on the underlying uint8_t: true when every bit of flag is set in levels. Comparing against flag rather than against zero is what makes a multi-bit flag behave as a subset test rather than an overlap test — although every flag in this enumeration is a single bit today, so the two readings agree.

It is constexpr, so a level set known at compile time can be tested in a constant expression, and it is the function the engine itself calls: three times in Initialize, once per level branch, including the widened set produced by the Logger dependency. A scoped enumeration supplies no such test on its own, which is the reason a free function exists rather than a member.

Asking for None is always true. With flag == 0 the test becomes (x & 0) == 0, which holds for every set including None itself. That is the ordinary algebra of an empty flag set rather than a defect, but it means HasFlag(levels, EInitLevel::None) is not a usable test for "the caller asked for nothing" — compare against EInitLevel::None == levels for that.
An unknown bit passes for every flag it does not touch, and fails for the ones it does. Because the test works on raw bits, a value outside the enumerators — static_cast<EInitLevel>(8), or a set built from one via operator| — answers false for all three real levels and therefore makes Initialize start nothing while still logging that the engine was initialised. Nothing validates the argument anywhere on this path (recorded on the entry page).

Parameters

ParameterTypeRequirement
levels EInitLevel (by value) The set to test — any combination produced by operator|, or one enumerator on its own
flag EInitLevel (by value) The bit or bits to look for. Single enumerators are the intended use; None is true for every set, and All is true only when all three bits are present

Return value

TypeWhat you get
bool true when levels contains all of flag. [[nodiscard]] is not declared, so a test whose result is dropped compiles

Examples

The engine's own use, in dependency order:

if (HasFlag(levels, EInitLevel::Logger))
{
        levels = levels | EInitLevel::TaskSystem;
}

if (HasFlag(levels, EInitLevel::TaskSystem))
{
        taskSystem.Initialize();
        isTaskSystemReady = true;
}

if (HasFlag(levels, EInitLevel::Logger))
{
        logger.StartTask(taskSystem);
        isLoggerReady = true;
}

From Engine/Engine/Engine.cpp, the opening of Initialize.

Note that the Logger test is asked twice, before and after the widening, and the task-system test in between succeeds for a caller who asked only for the logger.

constexpr EInitLevel headless = EInitLevel::TaskSystem | EInitLevel::Logger;

static_assert(HasFlag(headless, EInitLevel::TaskSystem), "the drain task needs the streams");
static_assert(!HasFlag(headless, EInitLevel::Application), "no window server contact");

The second block is illustrative — nothing in the repository performs these tests at compile time — but it is the reason both helpers are constexpr: a tool's level set can be checked before it is ever passed to the engine, which is the one place the Logger-implies-TaskSystem rule can be enforced rather than assumed.
