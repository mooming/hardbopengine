EInitLevel

Engine/Engine/EngineInitLevel.h namespace hbe enum class : uint8_t flag set which subsystems Engine::Initialize starts — three bits, one dependency rule, and two static_asserts holding the set together

Class description

This entry is not a class: it is a scoped enumeration with uint8_t as its fixed underlying type, used as a bit set. Its purpose is the third parameter of Engine::Initialize, and it exists because starting a subsystem can be more than wasted work. The Application level creates the OS application object and connects to a window server, which a headless tool or a CI runner may refuse outright; a converter that turns one file into another needs neither that nor a resource manager, and a flag set lets it say so exactly.

The header is careful about the boundary this type does not control: a level decides what is started, never what exists. The memory manager, the statistics object and the Logger object are members of Engine and are constructed before this type is ever consulted — which is why there is no memory level and why no combination of these bits can produce an engine without an allocator.

Two properties of the type are enforced at compile time rather than left to reading:

static_assert(static_cast<uint8_t>(EInitLevel::None) == 0, "None must select nothing at all");
static_assert(static_cast<uint8_t>(EInitLevel::All) ==
                                          (static_cast<uint8_t>(EInitLevel::TaskSystem) | static_cast<uint8_t>(EInitLevel::Logger) |
                                           static_cast<uint8_t>(EInitLevel::Application)),
                                  "All must be exactly the union of the levels, so adding a level cannot leave it out");

From Engine/Engine/EngineInitLevel.h.

The second is the one that matters as the module grows: adding a fourth level to the enumeration without adding it to All stops compiling, rather than quietly producing a default that under-starts the engine.

Logger implies TaskSystem, and the implication lives in the function, not the type. The logger's drain task is scheduled on the task system's IO stream, so a logger started without streams is a failure waiting to happen. Nothing in the values encodes that: EInitLevel::Logger is a legal, lone value. What enforces the rule is step 1 of Initialize, which ORs TaskSystem into the set whenever the logger bit is present. Any caller that reasons about levels has to know the rule even though the type will not tell it.

Class properties

One row per enumerator. The badge is a label; the sentence beside it is the contract.

NameDeclarationWhat it means
None None = 0 enumerator Starts no subsystem. Two steps of Initialize are not behind any flag, so even this value prints the command line into hardbop.log and runs the post-initialisation hook. A pinned value, guarded by the first static_assert
TaskSystem TaskSystem = 1 << 0 enumerator The worker threads. TaskSystem::Initialize() builds the task registry from three configuration parameters and then BuildStreams(): one stream per hardware thread, with a fixed Base and IO stream, plus the running flag that Run waits on. This is the level whose absence turns Run into a fatal abort and leaves GetTaskSystem() holding an empty object. Core: TaskSystem
Logger Logger = 1 << 1 enumerator The log drain task, not the logger: the object, its pools and ./hardbop.log are already built by the engine's constructor. Adding this bit schedules the task that flushes buffers on the IO stream. Implies TaskSystem — see the note above. Without it, log lines are still produced and are flushed inline by whoever writes them (Log: Logger)
Application Application = 1 << 2 enumerator OS::CreateApplication(), a FatalAssert that it succeeded, then Initialize() on the result. The only level that reaches the window server, and the only one whose absence a caller can observe as a null GetApplication(). OSAL: Application
All All = TaskSystem | Logger | Application enumerator Exactly the union of the three, and the default argument of Initialize — so a caller that states nothing gets what it got before levels existed. Every application in the repository uses this default

Not present, and not expressible: a level for memory, for statistics, or for the resource manager. The first two are constructed before this type is read; the third is simply not wired (Resource: Coverage), which is why IsResourceManagerReady() never answers true.

Class methods

None — an enum class declares no members, and this one declares no member functions at all. What makes the flag set usable is a pair of namespace-scope functions in the same header, documented below and given their own pages: operator| to combine and HasFlag to test. A scoped enumeration gets neither operator implicitly.

Coverage

GapDetail
No level is used in this build Grepping Engine/ and Applications/ for EInitLevel finds the type named only in Engine.cpp, its own header and the default argument. Every call site — Applications/WindowExample/Main.cpp, Applications/VulkanExample/Main.cpp, Applications/EngineTest/TestMain.cpp — passes the default All, so the headless sets are supported by the type and untried by the tree. Recorded on the Initialize page, where the one non-default example is labelled illustrative
Out-of-range values are accepted and silent Nothing validates the argument, so static_cast<EInitLevel>(8) is a value HasFlag answers false for on every flag: Initialize starts nothing and still prints "Engine has been initialized." There is no assertion on unknown bits, and no bit is reserved for them
No other operators No operator&, operator~, operator|= or operator^ is declared, so set logic is limited to combining with | and testing with HasFlag. Inside Initialize the widened set is produced by reassignment rather than by |=, which is what the absence of the compound operator forces
No way to print a level set There is no name lookup, streaming operator or flag-to-string helper for this type, so a log line reporting what was requested has to be assembled by hand. Nothing in the engine prints the level set today — Initialize logs the arguments and the fact of initialisation, not the levels
Which subsystem each level starts Enumerated on Engine::Initialize, in the order the source executes them, with what a skipped level breaks. This page states what the flags are; that page states what they do
Whether more levels are planned A renderer or resource level is a design question with a real answer somewhere in Renderer and Resource, and no answer in this header. The All assertion means whoever adds one must say so here
