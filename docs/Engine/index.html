Engine

namespace hbe Engine/Engine 2 headers, 1 source — the singleton that owns every subsystem and drives the main loop

Module description

One class, and it is the one an application constructs. Engine holds the MemoryManager, SystemStatistics, Logger, TaskSystem and ResourceManager by value as members, so their construction order is its member declaration order and their destruction needs no bookkeeping. EInitLevel is the second header's contribution: which subsystems Initialize starts, so a headless tool can convert a file without ever touching a window server.

Engine (Engine/Engine/Engine.h)

Class description

The main entry point. Construct it, Initialize it, let Run drive the frame loop, and ShutDown on the way out. Copying is deleted: there is one engine per process, and the subsystems it holds by value could not be duplicated meaningfully even if the copy compiled.

None — Engine is not a template.

{
    [[nodiscard]] static Engine& Get();

    void PostInitialize();
    void PreShutdown();

MethodContract a caller depends on
GetReturns the live instance. It asserts that an instance exists, which is why logging and the clock deliberately do not route through it — see the engine epoch note in Core § Time
InitializeStarts the subsystems named by levels, defaulting to EInitLevel::All. It adds the Logger-to-TaskSystem dependency itself rather than trusting the caller to spell it out
Run, ShutDownRun is the frame loop, ShutDown the orderly teardown. An application may drive the polling itself instead of calling Run — the example below is a real application that does — but the shutdown call is not optional. There is no WaitForEnd: the older guide and the README example both list one, and neither name exists in Engine.h
PostInitialize, PreShutdownHooks around the frame loop for subsystem work that must not happen inside a frame
Log, LogError, CloseLog, FlushLog, ConsoleOutLnThe logging front door; the design is in docs/LoggerGuide.md
GetClassNameStatic: the class name without an instance, which is what a log line printed before construction needs

Example

Taken from Applications/WindowExample/Main.cpp, which is a real entry point rather than a sketch:

int main(int argc, const char* argv[]) noexcept
{
    hbe::Engine hengine;
    hengine.Initialize(argc, argv);

    auto* app = hengine.GetApplication();
    if (app == nullptr)
    {
        std::cerr << "Error: Failed to create application" << std::endl;
        return 1;
    }

    auto window = OS::CreateWindow("Hello Window", 800, 600);
    if (!window)
    {
        std::cerr << "Error: Failed to create window" << std::endl;
        return 1;
    }

    while (!window->IsClosed())
    {
        app->PollEvents();
        window->PollEvents();
    }

    window->Close();
    hengine.ShutDown();

    return 0;
}

Three things the real code shows that a sketch tends to hide. Both handles are validated before use, which is what docs/CodingStandards.md requires rather than decoration. A headless tool swaps Initialize(argc, argv) for Initialize(argc, argv, EInitLevel::TaskSystem | EInitLevel::Logger) and never reaches the window code at all. And ShutDown is called explicitly — the destructor is not the shutdown.

EInitLevel (Engine/Engine/EngineInitLevel.h)

Class description

Which subsystems Engine::Initialize should start. A level is a flag, so a caller states the exact set it needs. Starting a subsystem you do not use is not merely wasteful: the Application level creates the OS application object and connects to a window server, which a headless or CI context may refuse outright.

Template parameters

None — EInitLevel is not a template.

Class properties

Not applicable to an enumeration. The fixed underlying type is uint8_t, and the values are single bits:

enum class EInitLevel : uint8_t
{
    None        = 0,
    TaskSystem  = 1 << 0,
    Logger      = 1 << 1,
    Application = 1 << 2,

    All = TaskSystem | Logger | Application
};

Class methods

None — an enum class declares no members.

Two things the header pins down, and both are enforced by static_assert rather than left to reading: None must select nothing at all, and All must be exactly the union of the levels — so adding a level cannot silently leave it out. A level decides what is started, never what exists: the memory manager and the logger object are members and are constructed before this is ever consulted, which is why memory cannot be one of the levels.

Coverage

GapDetail
SetMemoryManagerReady and its four siblings Present in the header as readiness flags set during startup. Described here rather than documented as caller API, because a caller has no reason to set them — if that is wrong, the header should say who may.
The renderer Engine exposes no renderer accessor, so Renderer is reached directly through its factory today. Whether the engine should own it is a design question with a real answer in docs/RendererDesign.html.
