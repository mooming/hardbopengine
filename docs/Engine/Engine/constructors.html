constructors

member of hbe::Engine Engine/Engine/Engine.h 1 real overload, 1 deleted declaring an engine is starting the engine — memory, both log files, the clock and the signal handlers all arrive here, not in Initialize

Signature

/// the one constructor an application calls, by declaring an Engine
Engine();

/// removed: an Engine is never copied — see operator=
Engine(const Engine&) = delete;

Function description

There is one way to construct an Engine: take its address. No argument selects a mode, names a configuration file, chooses an allocator or states which subsystems are wanted — the level argument belongs to Initialize, and the difference between the two calls is the difference between what exists and what runs.

The member list initialises, in this order, and C++ runs it in exactly that order:

  1. preEngineInit(this) — stores the address into the file-static instance pointer, so Engine::Get resolves for everything below.
  2. the five ready flags to false, and the two mutexes, which take no work.
  3. logFile("helowlevel.log") — an std::ofstream is constructed with a path, so the file is created or truncated here, in the process's current working directory. A failure sets its fail bit rather than throwing, and the first Log call is where that surfaces, as Assert(logFile.is_open()).
  4. memoryManager(*this) — registers the system allocator, loads the multi-pool configuration, and raises SetMemoryManagerReady. It asserts that no other memory manager exists, which is the only thing standing between a process and a second Engine.
  5. statistics(*this) — asserts that memory is ready, captures its start time, and raises SetSystemStatisticsReady. Every timestamp in every engine log line is measured from this instant.
  6. logger(*this, "./", "hardbop.log") — the Logger object, its own two pools, its interned path and its open output file, plus the drain-task machinery ready to be started but not started. It raises SetLoggerReady itself. Log: Logger
  7. taskSystem and resourceManager default-construct — no worker threads and no streams yet, but the task system records this thread as the engine loop thread — and application is a null std::unique_ptr.

The constructor body then does three things, none of them level-dependent:

  • time::ResetEngineEpoch() and LogUtil::ResetStartTime() move both clocks' zero point to now — the engine epoch is set in the constructor rather than in Initialize, so a subsystem constructed during member initialisation is already stamping real times (Core: functions, Log: LogUtil).
  • std::signal installs the same handler for SIGABRT, SIGFPE, SIGILL, SIGINT, SIGSEGV and SIGTERM, and for SIGBUS where the platform defines it. The handler flushes or stops the logger, reports the signal and a back trace through LogError, calls CloseLog and exits with 128 + signal number. Note that ShutDown is not among its calls: a signalled process gets its logs written, not its subsystems torn down.
No level can turn any of this off, which is why EInitLevel has no memory level. Memory, statistics, the logger object and both log files are constructed before the level argument is ever read. The levels decide what gets started — threads, the drain task, the OS application — and nothing that exists. A tool that wants "no logging" has to want "no drain task", and the file is opened regardless.

Parameters

None.

Return value

A constructor has no return value. What is observable immediately after one: IsMemoryManagerReady, IsSystemStatisticsReady and IsLoggerReady are true — the last because the Logger constructor raises the flag, not because a level ran; IsTaskSystemReady and IsResourceManagerReady are false; GetApplication() is null; and Engine::Get() already returns this object.

Examples

Every entry point in the repository constructs it the same way, as an object whose scope is main:

int main(int argc, const char* argv[]) noexcept
{
        hbe::Engine hengine;
        hengine.Initialize(argc, argv);

        auto* app = hengine.GetApplication();
        if (app == nullptr)
        {
                std::cerr << "Error: Failed to create application" << std::endl;
                return 1;
        }

From Applications/WindowExample/Main.cpp.

Three consequences of that shape are worth reading off the real code. The scope owns the engine — there is no factory and no destroy call, and the object is gone when main is, which is what makes the destructor's omissions load-bearing. Declaring it before the failure checks means the log files and the memory manager are already alive when the error message is printed, so a start-up that fails is a start-up that is logged. And the early return 1 leaves without calling ShutDown, which by then has real consequences — see the destructor.

The deleted copy constructor is not decorative: MemoryManager and Logger each record the address of the instance that constructed them, so a copied engine would leave two objects each believing it is the one — and MemoryManager's constructor asserts that no other one exists. If a function needs the engine, it takes an Engine&, which is exactly what the resource manager's constructor does (Resource), or it calls Engine::Get().
