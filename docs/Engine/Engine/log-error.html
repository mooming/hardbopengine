LogError

member of hbe::Engine defined inline in the header Log(ELogLevel::Error, func), spelled once so that every caller does not have to

Signature

void LogError(const TLogFunc& func)
{
        Log(ELogLevel::Error, func);
}

Function description

One statement, defined in the class body, so there is no separate symbol and no separate behaviour to learn: everything Log documents applies here, including the ENGINE_LOG_ENABLED gate, the two configuration thresholds, the double invocation of the callable, and the mutex.

What the fixed level buys is a position on the severity scale. Error is near the top of ELogLevel, and both comparisons in Log are ">= the configured value passes", so an error clears the file floor and the console floor at their defaults (Config::EngineLogLevel and EngineLogLevelPrint) — a line reported through this call is visible on standard output as well as in the file unless somebody raises Log.Engine.Print above it at runtime. It can still be silenced: both parameters are mutable configuration (Config: ConfigParam).

Do not confuse it with MemoryManager::LogError. The memory manager declares a member of the same name, also forwarding a level and a callable, and it is that one the allocator sources call. Both reach Engine::Log eventually, but through different filters — MemoryManager applies its own IsLogEnabled test first, under MEMORY_LOGGING_ENABLED. Grep results for LogError mix the two.

Parameters

ParameterTypeRequirement
func const TLogFunc& — std::function<void(std::ostream&)> Same contract as Log's: writes the text, adds no newline, must be safe to run once per sink, and runs under logLock. Captures are evaluated when the closure runs, not when it is created

Return value

void — the same four silent outcomes as Log. Reporting an error and having it displayed are not the same event, and nothing tells you which happened.

Examples

A platform failure path that reports, then asserts:

        auto errorId = GetLastError();

        auto& engine = hbe::Engine::Get();
        engine.LogError([address, n, errorId](auto& log)
        { log << "[OS::ProtectMemory] address = " << address << ", n = " << n << " : error code = " << errorId << endl; });

        hbe::Assert(false);

From Engine/OSAL/OSMemory.cpp.

The pattern used by the engine's own terminating signal handler, three lines in a row:

        engine.LogError([sigNum](auto& ls)
        { ls << "ERROR: signal(" << sigNum << ") received. The application shall be terminated."; });
        engine.LogError([](auto& ls)
        {
                auto stackTrace = OS::GetBackTrace();
                ls << stackTrace << std::endl;
        });

From Engine/Engine/Engine.cpp.

The second one shows the convention these lines follow: capture nothing you cannot read at flush time, and put the formatting inside the closure. Note also that the handler's back trace call ends with std::endl while the engine appends its own newline — the doubled break is visible in the file, and it is the only place in the engine where that happens deliberately.
