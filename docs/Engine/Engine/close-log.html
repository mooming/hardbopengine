CloseLog

member of hbe::Engine Engine/Engine/Engine.h flushes the engine's log file and leaves it open — the name describes the intention, not the effect

Signature

void CloseLog();

Function description

The whole definition, from Engine/Engine/Engine.cpp:

void Engine::CloseLog()
{
        if (!logFile.is_open())
        {
                return;
        }

        logFile.flush();
}

So: an early return when the stream is not open, otherwise a flush — and no close() call. Afterwards the file is still open, Log still writes to it, and its Assert(logFile.is_open()) still passes. The handle is released later by std::ofstream's own destructor, which is the seventh member destruction in ~Engine.

Both call sites in the engine use it as a pre-exit guarantee rather than as a close: the signal handler calls it immediately before exit(128 + signal number), and the destructor calls it as its only statement. A caller finishing a logging session has to look elsewhere: FlushLog is the one that also drains the Logger.

The flush is defensive rather than necessary. Log ends each line with logFile << endl, and std::endl flushes the stream — so in the ordinary path every engine line is already on disk before this call could run. What CloseLog protects against is a stream left with buffered content by some other writer, and the desire to have something in the destructor. It is also the only statement standing between a destructor and the members' own teardown, which is worth knowing when you read the shutdown story.
It says nothing about the other log file. The Logger's ./hardbop.log is a separate stream with a separate buffer and a drain task that owns flushing it. Calling this leaves whatever is in that buffer queued; on the abrupt paths where CloseLog is actually invoked, the handler stops the drain task or flushes it first, and a plain return from main relies on ~Logger (Log: Logger). Do not read "close" as "the logs are done".

Parameters

None.

Return value

void, and it does not report whether the stream was open in the first place — the early return and the flush are indistinguishable to the caller.

Examples

Where it is used: at the end of the terminating signal handler, with the exit status the shell will see.

        engine.LogError([](auto& ls) { ls << "Thank you for playing. Have a great day! :)" << std::endl; });
        engine.CloseLog();

        exit(128 + sigNum);

From Engine/Engine/Engine.cpp.

And once more inside the class itself, as the destructor's entire body: Engine::~Engine() { CloseLog(); } — see the destructor page for what does not appear there.
