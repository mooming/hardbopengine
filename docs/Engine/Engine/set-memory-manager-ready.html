SetMemoryManagerReady

member of hbe::Engine defined inline in the header raises the one flag two other constructors test — a back-channel for the memory manager, public by accident of placement

Signature

void SetMemoryManagerReady()
{
        isMemoryManagerReady = true;
}

Function description

One assignment. It starts nothing, checks nothing, takes no lock, and cannot fail; the flag is a plain bool member set to true and never set back.

The one caller is MemoryManager's constructor, on its last line, once the system allocator is registered and the multi-pool configuration has been loaded. Because that constructor runs from the engine's own member list, the flag is true before Initialize has been mentioned — which is exactly why EInitLevel has no memory level to omit.

This is also the only readiness flag other subsystems consult during construction: SystemStatistics's constructor and Logger's constructor both begin with Assert(engine.IsMemoryManagerReady()) (IsMemoryManagerReady). The flag's real function is to prove construction order inside the engine, where the order is enforced by nothing but the declaration list.

Public, unconditional, and load-bearing for two assertions. Nothing in the header restricts who may call this, and nothing verifies that a memory manager exists. Set the flag from a caller and both constructors that test it start passing on a process whose allocator was never registered — and Assert is the configuration-limited form, so in a Release build even the honest version of that test does not run (Core: Debug). Treat this as the subsystem's own channel and not as engine API; if it is meant to be callable, the header should say who may call it and when.

Parameters

None.

Return value

void. There is no previous state to learn and no way to undo it: destruction does not clear the flag, so after the engine is gone the memory manager's own pointer is null while this flag would still have read true on the object that held it.

Examples

The only call site in the repository is the last line of the memory manager's constructor:

MemoryManager::MemoryManager(Engine& engine) : allocCount(0), deallocCount(0)
{
        Assert(mmgrInstance == nullptr);
        mmgrInstance = this;

        // ... push the allocator proxies, register the system allocator, load the pool configs ...

        engine.SetMemoryManagerReady();
}

From Engine/Memory/MemoryManager.cpp, condensed to the calls that matter here.

Note that the assert one line above is the same pattern pointed the other way: MemoryManager also refuses to be constructed twice, so the engine and the memory manager each guard their own uniqueness, and neither guard is a mutex. Memory: MemoryManager.
