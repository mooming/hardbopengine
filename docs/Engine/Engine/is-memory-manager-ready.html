IsMemoryManagerReady

member of hbe::Engine const the only readiness flag anything actually asks — read by two constructors, as proof that memory came first

Signature

bool IsMemoryManagerReady() const
{
        return isMemoryManagerReady;
}

Function description

A field read, const, so it is callable from a constructor running mid-engine-construction — which is the only situation it is used in. SystemStatistics's constructor and Logger's constructor each open with Assert(engine.IsMemoryManagerReady()). Both are asserting the engine's member declaration order, because nothing else enforces it: the flag is the only in-code evidence that the memory manager finished before the things that allocate from it started.

Raised by SetMemoryManagerReady on the last line of the memory manager's constructor, and never cleared — not by ShutDown, and not during member destruction, where the memory manager is the sixth of seven destructions. So "true" means "was ready at some point", and during teardown that is a statement about the past.

The two asserts that read it are Debug and Dev only. Assert is the configuration-limited form (Core: Debug): it aborts under __DEBUG__ and compiles away otherwise, arguments and all. In a Release build nothing reads this flag at all, so an engine whose memory manager was somehow not first would proceed silently into its remaining constructors. For the ordering that holds in every configuration, compare IsTaskSystemReady's consumer, which uses FatalAssert.

Parameters

None.

Return value

TypeWhat you get
bool False during the first few member constructors of the engine, true from the end of MemoryManager's constructor onwards for the rest of the object's life. Not [[nodiscard]]

Examples

The real use, as the first statement of a constructor that is about to depend on memory:

SystemStatistics::SystemStatistics(Engine& engine) :
        frameCount(0), slowFrameCount(0), /* ... */
        startTime(time::TStopWatch::now()),
        currentTime(startTime)
{
        Assert(engine.IsMemoryManagerReady());
        engine.SetSystemStatisticsReady();
}

From Engine/Core/SystemStatistics.cpp; Engine/Log/Logger.cpp opens its constructor with the same assert.

The pattern is worth naming for anyone adding a subsystem to Engine: take the engine reference, assert this flag, then do work that allocates. It is the one documented use of the five flags as a mechanism rather than as a report.
