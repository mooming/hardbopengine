SetLoggerReady

member of hbe::Engine defined inline in the header raised twice from two different places, which is why the flag it sets cannot answer the question a caller wants to ask

Signature

void SetLoggerReady()
{
        isLoggerReady = true;
}

Function description

One unconditional assignment, called from two places that mean different things. The first is Logger's own constructor — its last statement, after its pools, path and output file are set up — so the flag becomes true while the engine is still being constructed, with no level consulted and no drain task in existence. The second is Initialize, immediately after logger.StartTask(taskSystem), which is where the drain task is actually created.

Two raises, one boolean: the flag records "a logger object exists", and the second raise adds nothing observable to it. There is no counter and no second flag, so no reader can distinguish the two states. IsLoggerReady carries the consequence, and the log module documents it too: Logger.h states in a note that this flag "is not a substitute" for asking whether the drain task is running, because the constructor raises it and it "stays true whether or not a task was ever started".

Do not use this flag to decide whether it is safe to stop the drain task. Logger::StopTask waits for the task to acknowledge, and called with no task running it waits forever; the supported test is Logger::IsDrainTaskRunning(), a single acquire load that may be read from any thread including a signal handler. The engine's own signal handler asks exactly that question rather than this flag (quoted on GetLogger). Log: Logger

Parameters

None.

Return value

void. The flag is never cleared — not when the level is skipped, not by ShutDown, and not when ~Logger clears the logger's own singleton pointer — so it is a one-way latch.

Examples

The two raises, from the two places that make them:

// Engine/Log/Logger.cpp — end of Logger::Logger(Engine&, const char*, const char*)
        flushFuncs.reserve(2);
        flushFuncs.emplace_back([this](const TTextBuffer& buffer) { WriteLog(buffer); });
        flushFuncs.emplace_back([](const TTextBuffer& buffer) { PrintStdIO(buffer); });

        engine.SetLoggerReady();
// Engine/Engine/Engine.cpp — the Logger branch of Initialize
        if (HasFlag(levels, EInitLevel::Logger))
        {
                logger.StartTask(taskSystem);
                isLoggerReady = true;
        }

The first from Engine/Log/Logger.cpp, the second from Engine/Engine/Engine.cpp.

Note that the second site writes the member directly rather than calling this setter, so the setter is not even the single path to the flag — there are two writes plus a constructor raise, and no read that can tell them apart. If the intent was one latch per level, the flag is the wrong shape.
