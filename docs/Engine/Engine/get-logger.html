GetLogger

member of hbe::Engine Engine/Engine/Engine.h the Logger member, for the operations the engine's own logging calls do not expose

Signature

auto& GetLogger()
{
        return logger;
}

Function description

A field read defined inline; the deduced auto& is Logger&. The object is built by the constructor with path "./" and file "hardbop.log", so the reference is never null and the file is already open — but the drain task behind it exists only if the Logger level ran during Initialize (why the flag cannot tell you).

For writing a line this accessor is the wrong door: Log and LogError apply the engine's own level filters and counters, and the Logger's static Get overloads are what the rest of the engine uses for category-attributed lines. This accessor is for the operations that belong to the object rather than to a line: stopping or inspecting the drain task, forcing a flush, installing a per-category filter.

The two routes to the logger disagree about failure. Logger::Get() FatalAsserts that a logger instance was constructed and returns the singleton pointer, which is set by the constructor and cleared by the destructor — so it stops working part-way through member destruction. This accessor reads a member of an object you already hold, so it keeps answering as long as the engine does. In the one place where that difference matters, the terminating signal handler, the engine uses this one.

Parameters

None.

Return value

TypeWhat you get
Logger& The member, mutable, never null, valid for the engine's lifetime. Not [[nodiscard]]

Examples

Every call site in the engine is in the terminating signal handler, which needs to decide between stopping the drain task and flushing inline — a question only the Logger object can answer: 

auto& engine = Engine::Get();
if (engine.GetLogger().IsDrainTaskRunning())
{
        engine.GetLogger().StopTask(engine.GetTaskSystem());
}
else
{
        engine.GetLogger().Flush();
}

From Engine/Engine/Engine.cpp.

The branch is not caution for its own sake: StopTask waits for the drain task to acknowledge, so calling it when no task was ever started waits for something that will never answer. IsDrainTaskRunning is the documented way to ask, and the log module's own note records that Engine::IsLoggerReady is not a substitute for it (Log: Logger).
