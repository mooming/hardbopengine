operator=

member of hbe::Engine Engine/Engine/Engine.h deleted one overload, removed on purpose — an engine is never assigned over

Signature

Engine& operator=(const Engine&) = delete;

Function description

This is the only assignment Engine declares, and it declares it in order to take it away. The declaration earns its place by being explicit: a reader of the header learns that assignment was considered, and a reader of a call site gets a compile error naming the deleted function rather than wondering why an obvious operation is missing.

The consequence is wider than the one operator. Because the class declares a copy constructor — deleted, but declared — the move constructor and move assignment are not implicitly generated either. So Engine has exactly one way to come into existence, the default constructor, and no way to be moved, copied or reassigned. It is a location-bound object: the address it was constructed at is the address it lives at for its whole life.

The reason is in the members, not in taste. Assigning one engine over another would destroy the memory manager, logger and task system of a running process while code on other threads was using them, and those two classes each record the address of the instance that constructed them, so the copies would be two objects each claiming to be the singleton. The deleted copy constructor is the same decision seen from the other side.

Parameters

ParameterTypeRequirement
rhs const Engine& Named in the declaration only — the parameter has no name in the header, because nothing can bind to it. Any attempt is a compile error at the call site, not a runtime failure

Return value

There is no reachable return value: the declaration exists so that no call can be made. The declared return type Engine& is what a non-deleted form would have produced, and it is the only trace of the signature left in the header.

Examples

No example is possible. A call to a deleted function is a compile error, so any snippet here would be a snippet that does not build — instead, this is what the engine's own code does whenever a function needs the engine without owning it. It takes a reference, or it reaches the one instance: 

// Subsystems are constructed with the engine they belong to — Engine.h members, constructed as
// memoryManager(*this), statistics(*this) and logger(*this, "./", "hardbop.log").
explicit MemoryManager(Engine& engine);
explicit SystemStatistics(Engine& engine);
Logger(Engine& engine, const char* path, const char* filename);

// A per-frame entry point takes it as an argument rather than assuming a global:
void ResourceManager::PostUpdate(Engine& engine) noexcept;

// And code that was given nothing reaches the one instance:
auto& taskSystem = Engine::Get().GetTaskSystem();

Signatures from Engine/Memory/MemoryManager.h, Engine/Core/SystemStatistics.h, Engine/Log/Logger.h, Engine/Resource/ResourceManager.h and the call in Engine/Core/Task.cpp.

A container of engines is the shape this deletion forbids. std::vector<Engine> and Array<Engine> cannot hold it — neither copy nor move is available, and the container module's elements are required to move. The process gets one Engine, at a fixed address, for its lifetime; everything else is a reference to it.
