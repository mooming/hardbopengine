GetMemoryManager

member of hbe::Engine Engine/Engine/Engine.h inline in the header the memory manager member, by reference, unconditionally

Signature

auto& GetMemoryManager()
{
        return memoryManager;
}

Function description

A field read, defined inline in the header. The declared return type is auto&, deduced from the member, so the type the caller gets is MemoryManager& — the header never spells it, and the member declaration is where the name of the class is written (Class properties).

There is no readiness test in front of it, and none is needed: the memory manager is constructed by the engine constructor and raises its own flag as it does so, so by the time any caller can reach an Engine this object is built, its system allocator registered and its pool configuration loaded. It is the one subsystem of the five that no level can leave unstarted.

The reference is a view into the engine, not ownership: it is valid for exactly the lifetime of the engine object and is not usable during the memory manager's own destruction, which is the sixth of seven destructions and the point at which remaining allocations stop being tracked.

Most engine code does not go through here. MemoryManager also publishes a static instance accessor that FatalAsserts its own pointer, and the allocator layer uses that path; this accessor is the one that works when the engine reference is already in hand. Which of the two a given caller should use is a Memory question, not a difference in what is returned — both name the same object.

Parameters

None.

Return value

TypeWhat you get
MemoryManager& The member itself, mutable, and never null. Not declared [[nodiscard]], so a call whose result is thrown away compiles silently

Examples

One call site exists in the engine, in the path that handles an unusually long log line: rather than format through the logger's own buffers, it takes the size and allocates through the engine's memory manager. 

if (likely(isLong))
{
        auto& engine = Engine::Get();

#if PROFILE_ENABLED
        auto& stat = engine.GetStatistics();
        stat.IncLongLogCount();
#endif // PROFILE_ENABLED

        auto& mmgr = engine.GetMemoryManager();
        longTextSize = size + 1;
        longText = (char*) mmgr.SysAllocate(longTextSize);
        std::copy(&inText[0], &inText[longTextSize], longText);

        return;
}

From Engine/Log/LogLine.cpp.

The pattern to take from it is the pairing: Engine::Get() to reach the engine, then this call to reach the subsystem, and the allocation made through the returned reference so that it lands in the engine's allocator rather than in whatever scope happens to be open (Memory: allocators).
