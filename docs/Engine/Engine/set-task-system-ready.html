SetTaskSystemReady

member of hbe::Engine defined inline in the header no caller in the repository public setter for the one flag that Run aborts on and ShutDown branches on

Signature

void SetTaskSystemReady()
{
        isTaskSystemReady = true;
}

Function description

It sets one boolean and is never called. Initialize writes the member directly, on the line after taskSystem.Initialize() returns, and nothing else in Engine/ or Applications/ calls this setter. So in every program in the tree the flag means precisely "the TaskSystem level ran to completion" — the faithful meaning, held in place by there being no other writer.

The flag it protects is the most consequential of the five. Run opens with FatalAssert(isTaskSystemReady, "Engine::Run needs EInitLevel::TaskSystem"), which stops the process in every build configuration, and ShutDown reads it to decide whether to call RequestShutDown() at all — the mechanism by which a level that was skipped is also not torn down.

Calling this without starting the task system converts a clear abort into a downstream failure. The setter verifies nothing: no registry, no streams, no hardware-thread check. With the flag true and the level skipped, Run's guard passes and it begins pumping a task system whose stream array is empty; the first path that resolves a stream index indexes an empty Array, which is a fatal assert in every configuration (GetTaskSystem, Container: Array). The message you get then says nothing about the level you did not pass. Do not call this from outside the engine.
There is no setter in the other direction. No member clears this flag, so ShutDown leaves it true after requesting the stop, and a program that shut a task system down and then called Run again would pass the guard a second time — with the streams already joined and cleared. The flag describes what started, never what is currently running; the task system's own atomic running flag is the live state, and that one belongs to Core.

Parameters

None.

Return value

void, and the previous value is not returned, so a caller cannot even detect that it is changing something already set.

Examples

Illustrative — no call site for this exists in the repository. The assignment below is what Initialize does directly, and it is shown to make the pairing explicit; nothing outside the engine should need to write it.

hbe::Engine hengine;

// What the engine does itself, in the TaskSystem branch of Initialize:
//   taskSystem.Initialize();          // registry, streams, running flag
//   isTaskSystemReady = true;         // the flag Run and ShutDown read

// The equivalent from outside — correct only because the call above already happened:
hengine.Initialize(argc, argv, hbe::EInitLevel::TaskSystem);
hengine.SetTaskSystemReady();           // a no-op: already true

// The same call after Initialize(argc, argv, EInitLevel::None) is the hazard above:
// Run() then aborts somewhere other than where the mistake was made.

The honest summary of this member: it exists so the flag has a symmetric interface, and the correct call site for it is the one inside Engine.cpp that does not use it.
