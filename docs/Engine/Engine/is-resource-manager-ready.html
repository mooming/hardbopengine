IsResourceManagerReady

member of hbe::Engine const always false a field read of a flag no code ever sets, for a subsystem no level starts

Signature

bool IsResourceManagerReady() const
{
        return isResourceManagerReady;
}

Function description

Returns the flag. It is initialised to false by the constructor and never written again — SetResourceManagerReady is its only writer and has no caller — so this function answers false for the whole life of every engine, in every configuration and for every level set.

The constant is a fact about the build, not a transient state. EInitLevel declares no resource flag, so Initialize has no branch that could raise it; no frame hook advances the manager either. The manager is constructed as a member and destroyed second, releasing whatever it holds, and nothing between those two moments is the engine's doing (Resource: Coverage). Do not expect this to become true.

Parameters

None.

Return value

TypeWhat you get
bool false, always. Not [[nodiscard]]

Examples

Illustrative — no call site for this exists in the repository, and no code path can make it return true.

if (hengine.IsResourceManagerReady())
{
        // Dead: nothing sets the flag today.
}

// What works now is to use the manager's own state, not the engine's claim about it:
auto& resources = hengine.GetResourceManager();
resources.PostUpdate(hengine);   // public, defined empty — nothing to pump yet

If a caller needs a "resources are usable" signal today, the engine cannot supply one; the buffer factories in the resource module (Resource: module functions) report their own failure, and that is the signal that exists.
