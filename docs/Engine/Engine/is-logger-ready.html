IsLoggerReady

member of hbe::Engine const true for every engine that has ever existed — it reports the logger object, not the drain task, and the log header says so

Signature

bool IsLoggerReady() const
{
        return isLoggerReady;
}

Function description

Returns the flag and nothing else.

The flag is raised by Logger's constructor — the last statement in it — so it is true before Initialize is entered and regardless of the levels passed to it. SetLoggerReady is what the constructor calls; Initialize then sets the same member directly after starting the drain task, which changes nothing observable. There is no clear anywhere: not in ShutDown, and not in ~Logger, which clears the logger's own singleton pointer but leaves this flag set on the engine that is still being destroyed.

The answer is always "yes", so it cannot answer the question that gets asked. What a caller wants to know at a flush or a shutdown is whether a drain task exists: Logger::StopTask waits for a task that may never have started and blocks forever, while Logger::Flush behaves differently depending on whether something is draining. The correct test is Logger::IsDrainTaskRunning(), and Logger.h carries an explicit note about this very accessor: the engine flag "is not a substitute", because the constructor raises it and it "stays true whether or not a task was ever started". That is a header correcting a misunderstanding before it is made.

Parameters

None.

Return value

TypeWhat you get
bool True from the end of the Logger member constructor onward — that is, for any engine you can hold a reference to. False only inside the engine's own construction, before that member runs. Not [[nodiscard]]

Examples

The question you actually have, asked the way the engine asks it:

auto& engine = Engine::Get();

// Not: if (engine.IsLoggerReady()) — true either way.
if (engine.GetLogger().IsDrainTaskRunning())
{
        engine.GetLogger().StopTask(engine.GetTaskSystem());
}
else
{
        engine.GetLogger().Flush();
}

From Engine/Engine/Engine.cpp — the signal handler installed by the engine constructor.

Both branches reach the same destination, a log that has been written; the difference is that one of them can block indefinitely if it is chosen by a flag that cannot tell the two states apart. That is why the check is on the object. Log: Logger.
