IsTaskSystemReady

member of hbe::Engine const the one flag that faithfully records a level — and the only one whose meaning the engine enforces with a fatal assert

Signature

bool IsTaskSystemReady() const
{
        return isTaskSystemReady;
}

Function description

Returns the flag that Initialize raises immediately after taskSystem.Initialize() returns — the only one of the five written solely by a level branch. It therefore answers the question the other four cannot: did this level actually run? The header says as much in a note on Initialize: the ready flags and the application pointer, not the level argument, are the record of what started, and teardown reads those.

The engine consults the member itself rather than this accessor, in two places: Run guards entry with FatalAssert(isTaskSystemReady, "Engine::Run needs EInitLevel::TaskSystem"), and ShutDown uses it to decide whether to request the stop. Both readings are the same value this function returns.

"Ready" means "was started", never "is running". Nothing clears this flag, so it is still true after ShutDown requested the stop and after Run joined every worker thread. The live state is the task system's own atomic running flag, which RequestShutDown clears and BuildStreams sets — and which Core documents. A caller polling this accessor for shutdown progress will wait forever, because it only ever goes one way.

Parameters

None.

Return value

TypeWhat you get
bool True if and only if the TaskSystem level ran — directly requested or added by the Logger dependency — and TaskSystem::Initialize() returned. False for EInitLevel::None and for Application alone. Never false again once true. Not [[nodiscard]]

Examples

Illustrative — no call site for this accessor exists in the repository; the engine reads the member directly. This is the check a level-aware tool should make before it reaches for the task system.

hbe::Engine hengine;
hengine.Initialize(argc, argv, hbe::EInitLevel::TaskSystem);

if (!hengine.IsTaskSystemReady())
{
        // The only honest branch: the level never ran, so the streams do not exist.
        return 1;
}

hengine.GetTaskSystem().Enqueue(task);   // safe: the registry and streams were built
hengine.ShutDown();                       // clears the running flag, so Run() can return
hengine.Run();                            // would abort without the guard above

Compare the failure modes: without the guard, Run gives an immediate fatal abort naming the missing level, while an enqueue that skips the guard is accepted and fails later at a stream index with a message about a bad array subscript (GetTaskSystem). The guard is worth having for the second path.

Note the order of the last two lines. ShutDown is what clears the task system's running flag and Run returns when that flag is clear, so a pump with nothing to end it waits in place — see Applications/EngineTest/TestMain.cpp, where the end comes from inside the work instead (Test: UnitTestCollection).
