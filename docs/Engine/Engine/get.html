Get

member of hbe::Engine static Engine/Engine/Engine.h the reach-everywhere accessor — one file-static pointer, written by the constructor and cleared by nothing

Signature

static Engine& Get();

Function description

Returns *engineInstance, where engineInstance is a static Engine* file-scope variable in Engine/Engine/Engine.cpp. There is no lazy construction, no creation function and no release function: the value is the address the last-constructed Engine passed to PreEngineInit, which is the first member the constructor initialises. That placement is the whole reason the call is usable from inside the engine's own setup — the pointer is live before MemoryManager finishes constructing.

The existence check is Assert(engineInstance != nullptr), which is the Debug and Dev form: it flushes the logs and aborts. In a build without !RELEASE_BUILD the corresponding Assert overload is an empty inline function, so the test is compiled away entirely and a null pointer is dereferenced and the call returns a reference to address zero. Compare the guards a few lines away in the same source file — Initialize's "no OS application created" and Run's "needs EInitLevel::TaskSystem" use FatalAssert, which stops in every configuration. This one does not.

Nothing writes the pointer back to null. PreEngineInit declares no destructor and ~Engine does not touch it, so the window in which Get answers with a partly-destroyed object — every member destructor, which is exactly when allocators report and logs flush — is joined by a window in which it answers with a reference to memory that is no longer an Engine at all. A non-null test cannot distinguish the two cases because it is only ever testing for null.

The accessors it returns are the point. Get is how a translation unit that is given no engine reaches one: Task::Start, MemoryManager, the allocator statistics, the OSAL window implementations and the assert helpers all go through it rather than carrying a reference. That is also why the pointer is set in the constructor's first member — those paths are reachable from the constructors of the members that come after it.
It is called from a signal handler, and everything that path touches takes a mutex. The handler the constructor installs starts with Engine::Get() and continues into GetLogger(), GetTaskSystem() and LogError() — the last of which locks logLock, and through it consoleOutLock. Taking a mutex whose previous owner was interrupted by the very signal being handled is not defined to make progress. The behaviour worth knowing is not that the handler exists but that it can block on a lock held by the code that died.

Parameters

None.

Return value

TypeWhat you get
Engine& The live instance, non-const, so any of the engine's methods may be called through it. There is no const overload and no const Engine& form, so this is the only way in — including for callers that only want to write a log line. It is not declared [[nodiscard]], unlike GetApplication's callers' checks elsewhere in the class

Examples

A handler that has no handle to the engine and no thread that would supply one:

void SignalHandler(int sigNum)
{
        using namespace hbe;

        auto& engine = Engine::Get();
        if (engine.GetLogger().IsDrainTaskRunning())
        {
                engine.GetLogger().StopTask(engine.GetTaskSystem());
        }
        else
        {
                engine.GetLogger().Flush();
        }
        engine.LogError([sigNum](auto& ls)
        { ls << "ERROR: signal(" << sigNum << ") received. The application shall be terminated."; });

        engine.CloseLog();

        exit(128 + sigNum);
}

From Engine/Engine/Engine.cpp — the handler installed by the engine constructor for SIGABRT, SIGFPE, SIGILL, SIGINT, SIGSEGV and SIGTERM.
