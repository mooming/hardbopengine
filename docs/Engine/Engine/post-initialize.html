PostInitialize

member of hbe::Engine Engine/Engine/Engine.h private the post-initialisation hook — the memory manager’s last setup step, bracketed so a log can name a hook that did not return

Signature

void PostInitialize();   // private

Function description

The post-initialisation hook, and the whole body is one call wrapped in two log lines:

auto log = Logger::Get(ToCompactMethodName(__PRETTY_FUNCTION__));

log.Out("Engine PostInitialize [Start]");

memoryManager.PostEngineInit();

log.Out("Engine PostInitialize [Done]");

The two lines exist because this is the boundary a reader of a log wants: every subsystem that takes a post-initialisation step appears between them, so a start line with no matching done line names the hook that did not return. No other structure in Initialize is bracketed that way.

It runs after every selected level has started — after the task system's streams, after the logger's drain task, after the application object if the Application level was requested — which is what makes it the right place for work that must not see a half-built engine. Memory is the only hook called here today.

Parameters

None.

Return value

None.

Notes

  • No level governs it. It runs at the end of Initialize whatever bits were passed, so the memory hook is not optional — the same reasoning that leaves memory out of EInitLevel.
  • The log category is derived, not written. ToCompactMethodName(__PRETTY_FUNCTION__) is what makes the category name the function rather than the class, so these lines are attributable in a log full of GetLogger() categories.
  • Its counterpart is PreShutdown, called at the matching point of ShutDown.
