Initialize

member of hbe::Engine Engine/Engine/Engine.h levels defaulted to EInitLevel::All start exactly the subsystems named, in dependency order, and record on the ready flags what actually started

Signature

void Initialize(int argc, const char* argv[], EInitLevel levels = EInitLevel::All);

Function description

The body is six steps in a fixed order, three of them behind a level test. The order is not stylistic: the task system's streams have to exist before the logger can be given one to run on, and all of the logging has to be live before the OS application starts producing things worth logging. What the Engine constructor already built — memory, statistics, the Logger object, both log files, the signal handlers — is not re-touched here (the constructor page lists it), so this function is only ever about threads, the drain task and the OS application.

StepRuns whenWhat the source doesState left behind
1 Always If the Logger bit is set, the TaskSystem bit is set too: levels = levels | EInitLevel::TaskSystem;. The dependency is closed here rather than documented as a caller's obligation, so the combination "drain task, no streams to run it on" is not expressible through this function A widened level set, local to this call
2 TaskSystem bit set taskSystem.Initialize(): installs the TaskSystem log filter, registers the configuration parameters Log.TaskSystem, Task.RegistryInitialRecords, Task.RegistryGrowByRecords and Task.RegistryMaxRecords, initialises the task registry from the first and second and caps it with the third, then BuildStreams() — which asserts it is running on the thread that constructed the task system, aborts if the machine has fewer than the minimum hardware threads, names this thread the engine loop thread, and creates the stream array with a fixed Base stream, a fixed IO stream and one worker stream per remaining hardware thread isTaskSystemReady = true, worker threads running, registry live
3 Logger bit set logger.StartTask(taskSystem): creates a task named Logger in the registry, enqueues a single-subtask drain onto the IO stream, and records that stream's thread as the thread that owns flushing. If the registry could not track the task, it logs an error and the drain simply is not created — lines then get flushed inline by whichever thread produces them Background drain running, flush thread recorded
4 Always Opens a logger under the category Engine and prints Command Line Arguments, one line per argv[i], then Engine has been initialized. — through the zero-argument Logger::Get(), which works whatever the levels because the Logger singleton is set by its constructor The argument vector in hardbop.log
5 Application bit set application = OS::CreateApplication(); then FatalAssert(application != nullptr, "Application level requested, no OS application created"); then application->Initialize();. This is the step that reaches the window server The unique pointer holds the application
6 Always PostInitialize(): a start and a done line around memoryManager.PostEngineInit(), which is an empty function Nothing beyond two log lines

The levels therefore select three things and only three: worker streams, the log drain task, and the OS application. EInitLevel is the flag type, its None, and the All the default argument uses.

No level, and no combination of levels, omits memory. The memory manager is a member constructed by the constructor, and it is asserted-on by the constructors of both statistics and the logger. A headless tool gets a real memory manager and an open hardbop.log either way; what it can avoid is the one step that talks to the window server. Likewise the resource manager: there is no level for it at all, so it is not "left off", it is never started by anyone (Resource: Coverage).
Skipping the TaskSystem level is not a smaller engine — it is an engine whose Run aborts. That call opens with FatalAssert(isTaskSystemReady, "Engine::Run needs EInitLevel::TaskSystem"), and FatalAssert stops the process in every configuration, Release included (Core: Debug). The same set also leaves every consumer of GetTaskSystem() holding a valid reference to a task system with no registry and no streams — the OSAL window implementations post their events through it (OSAL: Window), so a window opened without this level has nowhere to send what it receives. Choosing Application without TaskSystem is expressible and is almost certainly not what you meant.
A second call re-runs every step, and nothing detects the first one. There is no once-flag, no early return and no assertion against it. Repeating the TaskSystem step re-enters BuildStreams(), which replaces the live stream array in place while its threads are running; repeating the Application step assigns a new unique pointer over the old one, destroying the application the window layer may still be using. Treat Initialize as once per object — the repository's own entry points all do.

Parameters

ParameterTypeRequirement
argc int The count main was given. The only use made of it here is as the bound of the loop that prints the arguments; nothing parses them, so a value that over-states argv is read out of bounds by the printing, not by a parser
argv const char* array of argc entries Each entry is written to the log as its own line, so each must be a null-terminated string that stays alive for the duration of the call. An entry point declared as char** argv needs the cast (const char**) — which is what Applications/VulkanExample/Main.cpp does
levels EInitLevel, defaulted to EInitLevel::All Any combination of the flags, including None. Bitwise-or of the flags is constexpr, so a set can be a compile-time constant. The Logger bit silently adds TaskSystem; there is no flag that starts the resource manager, and no flag whose absence turns off memory, statistics or the log files

Return value

void. Nothing reports which levels ran, whether anything failed, or whether the level set was widened — and a level that was requested but whose step is unconditional (the argument printing, the post-init hook) cannot be distinguished from one that did work. The record of what exists is the state afterwards, not this call: IsTaskSystemReady() is the one flag that tracks a level faithfully, because only step 2 raises it; GetApplication() is non-null exactly when step 5 completed; and IsLoggerReady() tells you nothing about step 3, because the flag was already true before this function was entered.

Examples

The whole-argument-list, default-level form — every application in the repository uses it:

hbe::Engine hengine;
hengine.Initialize(argc, argv);

auto* app = hengine.GetApplication();
if (app == nullptr)
{
        std::cerr << "Error: Failed to create application" << std::endl;
        return 1;
}

From Applications/WindowExample/Main.cpp.

        Engine hengine;
        hengine.Initialize(argc, (const char**) argv);

From Applications/VulkanExample/Main.cpp, whose main takes char** argv.

The headless set the level argument exists for — a converter, a importer, a CI binary:

Illustrative — no call site for this exists in the repository. Grepping Engine/ and Applications/ for EInitLevel finds the type used only inside Engine.cpp and its own header: every caller in the tree passes the default.

hbe::Engine hengine;

// Streams plus the log drain task; no OS application, so no window server contact.
hengine.Initialize(argc, argv, hbe::EInitLevel::TaskSystem | hbe::EInitLevel::Logger);

// The level set is widened to include TaskSystem by step 1, so this is the same as asking for TaskSystem
// alone except that the drain task exists. Memory, statistics and hardbop.log exist either way.
auto& taskSystem = hengine.GetTaskSystem();

// ... schedule the work, then switch the task system off so Run() can return ...
hengine.ShutDown();
hengine.Run();

The ordering in that last pair is not interchangeable: ShutDown is what clears the task system's running flag, and Run returns when that flag is clear. Reversed, the pump has no way to end. Applications/EngineTest/TestMain.cpp solves the same problem from the other side — it calls Run() first and has the test suite itself call Engine::Get().ShutDown() as its last act, so the pump ends from inside (Test: UnitTestCollection).
