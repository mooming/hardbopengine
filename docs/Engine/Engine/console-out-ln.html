ConsoleOutLn

member of hbe::Engine Engine/Engine/Engine.h one mutex-guarded line on std::cout — the single serialisation point for the engine's console output

Signature

void ConsoleOutLn(const char* str);

Function description

void Engine::ConsoleOutLn(const char* str)
{
        std::lock_guard lock(consoleOutLock);
        std::cout << str << std::endl;
}

Two statements, and all of the contract is in them. The lock makes the write atomic against every other call, so two threads' lines cannot interleave character by character. The std::endl appends a newline and flushes the standard stream, so this is an unbuffered write per call — visible immediately, and comparatively expensive in a loop.

Both users in the engine are on the logging path rather than the application path. Log calls it when a line clears the Log.Engine.Print threshold, holding logLock at the time — that is the only lock nesting in the class, always in the same order. The other is Logger::PrintStdIO, the drain task's console sink.

Nothing filters here. No level, no configuration parameter, no ENGINE_LOG_ENABLED gate: whatever is passed is printed. The filtering belongs to the caller — Log decides whether to call this at all, and the log module's per-category filters decide what reaches the drain task that ends up here. A direct call is unconditional output.
It is one call per line, so a multi-line record is not one atomic write. Logger::PrintStdIO loops over the drained buffer and calls this once per entry, each with its own lock acquisition. Two records produced by different threads can therefore have their lines interleaved at line boundaries, and a caller that needs a block to appear together has to build it into a single string first. It also takes const char*, so a built std::string must be passed as .c_str() — and the pointed-to text has to stay alive for the duration of the call, which is why the engine passes temporaries inside the same full expression.

Parameters

ParameterTypeRequirement
str const char* Null-terminated text, readable for the duration of the call. No newline is required — one is appended, and an embedded newline in the string produces a multi-line record with the atomicity caveat above

Return value

void. A failed write to standard output — a closed or redirected-and-broken stream — is not reported; std::cout just sets its fail bit.

Examples

The asynchronous logger's console sink, one call per drained line:

void Logger::PrintStdIO(const TTextBuffer& buffer) noexcept
{
        auto& engine = Engine::Get();

        for (auto& logText : buffer)
        {
                engine.ConsoleOutLn(logText.c_str());
        }
}

From Engine/Log/Logger.cpp.

That loop is the reason this member exists as a separate function rather than as a line inside Log: the drain task runs on a worker stream and needs the same serialisation as the engine's own synchronous console writes. It is also the shape to avoid when a record must land as a unit — build one string, call once.
