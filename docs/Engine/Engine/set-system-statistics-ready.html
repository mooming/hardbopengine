SetSystemStatisticsReady

member of hbe::Engine defined inline in the header the flag nobody reads: raised by the statistics constructor, consulted by no code in the repository

Signature

void SetSystemStatisticsReady()
{
        isSystemStatisticsReady = true;
}

Function description

One unconditional assignment, like its four siblings. Its counterpart IsSystemStatisticsReady has no callers: grepping Engine/ and Applications/ finds the setter and the getter declared, one call to the setter, and nothing that reads the flag. GetStatistics does not test it, ShutDown does not test it, and no level depends on it.

The setter is called from SystemStatistics's constructor, on the line after that constructor asserts memory is ready — so the flag's only real content is a record that the second member of the engine finished constructing. It is a claim about the past rather than a gate on the future, and unlike SetMemoryManagerReady it gates nothing.

Reading it is legal and tells you very little. IsSystemStatisticsReady() returning true is not evidence that counters are meaningful or that a frame has been timed: SystemStatistics is constructed for every engine, with or without every level, and the counters only become interesting once something calls UpdateCurrentTime() and IncFrameCount(). Ask the object, not the flag.

Parameters

None.

Return value

void, with no state reported back and no way to clear the flag afterwards.

Examples

The only call site, at the end of the statistics constructor:

SystemStatistics::SystemStatistics(Engine& engine) :
        frameCount(0), slowFrameCount(0), engineLogCount(0), /* ... */
        startTime(time::TStopWatch::now()),
        currentTime(startTime)
{
        Assert(engine.IsMemoryManagerReady());
        engine.SetSystemStatisticsReady();
}

From Engine/Core/SystemStatistics.cpp, condensed.

Two details worth taking from four lines. The assert is the ordering gate that is enforced — memory first — and it is the memory manager's flag that is tested, not this one. And startTime is captured here, which is the instant every Log timestamp measures from.
