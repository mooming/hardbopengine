GetApplication

member of hbe::Engine const Engine/Engine/Engine.h the OS application the engine owns, as a raw pointer that can be null in three different ways

Signature

OS::Application* GetApplication() const
{
        return application.get();
}

Function description

std::unique_ptr::get() on the member, so the pointer is a borrow: the engine owns the application and destroys it, and a caller that keeps this pointer past that moment keeps nothing. It is declared const because reading a smart pointer's payload does not modify the engine — which makes it one of the few engine accessors callable through a const Engine&, unlike every subsystem accessor beside it.

It is set in exactly one place: the Application branch of Initialize, where OS::CreateApplication() is called, the result is checked with FatalAssert, and Initialize() is called on it. It becomes null again in Run, which resets the pointer before returning, and finally when the engine itself is destroyed — the application is the first member to die.

Null whenBecause
The Application level was never requested The creation branch did not run. This is the only case a caller's null check can actually observe: with the level requested, OS::CreateApplication() returning null trips FatalAssert(application != nullptr, "Application level requested, no OS application created") and the process stops before anyone can ask
Run has returned Run calls application.reset() as its last statement, under the comment "It may terminate the application immediately." Windows and event handles obtained earlier are then dangling
The engine is being destroyed It is the first member destroyed, before the logger even (destruction order)

Parameters

None.

Return value

TypeWhat you get
OS::Application* The owned application, or null. Non-owning, and OS::Application's own contract — what PollEvents drains, what Initialize opens — belongs to OSAL: Application. Not [[nodiscard]], and a discarded call is the same mistake as discarding any other null test

Examples

The check every entry point performs before using it:

auto* app = hengine.GetApplication();
if (app == nullptr)
{
        std::cerr << "Error: Failed to create application" << std::endl;
        return 1;
}

From Applications/WindowExample/Main.cpp — the engine was initialised immediately above this with the default EInitLevel::All, and the window creation follows immediately after the check.

The same test on a worker stream, where the failure is reported instead of exiting the process:

                        auto app = Engine::Get().GetApplication();
                        if (!app)
                        {
                                ls << "Failed to get an application instance" << lf;
                                windowPromise.set_value(nullptr);
                                return;
                        }

From Engine/OSAL/Window.cpp.

The two examples disagree about whether null is fatal, and only one of them is right about the engine. In the first, the level was requested, so null means the FatalAssert already fired and this branch is unreachable; in the second, running on a task stream, the caller has no idea which levels the process asked for, and treating null as an ordinary failure is the correct response. Check the pointer anyway — Run can make one of these pointers null between two uses.
