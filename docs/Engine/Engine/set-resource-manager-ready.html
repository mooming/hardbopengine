SetResourceManagerReady

member of hbe::Engine defined inline in the header no caller in the repository the setter nobody calls, for a subsystem no level starts — which is why its flag is false for the whole process

Signature

void SetResourceManagerReady()
{
        isResourceManagerReady = true;
}

Function description

One unconditional assignment, with no call site anywhere in Engine/ or Applications/. Nothing sets this flag, so IsResourceManagerReady() answers false from the first moment of the engine's life to the last, whether or not the manager holds anything.

The absence is consistent rather than an oversight in one place: EInitLevel declares no resource flag, so Initialize has no branch that could raise it; nothing pumps the manager either, and the manager's own advance hook is an empty body (Resource: Coverage). Every member of this pair — a level that does not exist, a setter with no caller, a getter with no true branch — is a piece of an integration that was laid out and not connected.

Setting it is possible and means nothing to the engine. No code reads the flag: Initialize, Run and ShutDown all ignore it, and GetResourceManager does not test it. Unlike the task system flag, which gates a fatal assert, and the memory manager flag, which gates two constructor asserts, this one gates nothing. A caller that wants the manager driven has to call it directly; raising the flag first only makes the report read better.

Parameters

None.

Return value

void, one-way, and never cleared by anything.

Examples

Illustrative — no call site for this exists in the repository, and there is nothing for it to pair with: the manager has no start function to raise the flag after.

hbe::Engine hengine;
hengine.Initialize(argc, argv);

// There is no "resource manager started" event in the engine, so the flag can only be
// raised by the code that intends to use the manager itself:
auto& resources = hengine.GetResourceManager();
hengine.SetResourceManagerReady();

// ... and then drive it, because no engine loop will:
resources.PostUpdate(hengine);   // declared public, defined empty

The snippet is legal and, at the time of writing, effectless — it exists to show that the flag is decorative until something behind it is implemented. The members that would carry the work, RequestLoad and Load, are declared with no definition, so a program calling them does not link (Resource).
