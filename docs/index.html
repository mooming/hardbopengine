One page per module, one module per directory under Engine/. The page for a module is docs/<Module>/index.html, so the documentation tree and the source tree agree: a class documented on the Memory page lives under Engine/Memory/.

How to read these pages

Every page follows the outlines AGENTS.md fixes for API reference documents. A module page opens with the module's own four sections, then repeats the class outline once per class.

LevelSections, in order
ModuleModule description, Module classes, Module variables, Module functions
ClassClass description, Template parameters, Class properties, Class methods, Non-member helper functions
FunctionFunction description, Parameters, Return value, Examples

Code shown on these pages is a declaration summary, not a definition. The header named under each heading is the authority: the engine is exception-free and self-documented, so the paired .h carries the contract — preconditions, ownership, lifetime, thread-safety — and docs/ carries the design reasoning.

Modules

Header and source counts are counted from the module's directory on the day this site was built. A documented entry is one named entity a module page carries a section for — a class, an enumeration, an alias family or a group of free functions — which is why the number is smaller than the header count: a header holding implementation detail is listed, not documented.

The site is being rebuilt to three levels: a module page, a page per entry, and a page per method. Two modules say "split into pages", which means their entries have their own folders and every method has a page. The rest still carry their entries as sections on the module page, so a card for those counts sections, not files. The wording changes as each module is converted.

Documenting policy

The engine is self-documented: names, types and structure carry the intent, so the codebase avoids comments and only brief comments are allowed in header files. Prose goes where a reader forms intent instead.

ProseDestination
What a caller of the engine depends on — contract, preconditions, ownership, lifetime, thread-safety, complexityThe paired .h declaration
What implementation or system design needs — invariants, algorithms, allocation strategy, locking protocol, platform quirksAn HTML design document under docs/
What exists and how to call itThe module pages of this site

Rules in full: AGENTS.md, docs/CodingStandards.md, and README.md § Documentation Policy. Identifier conventions — PascalCase for types and functions, T-prefixed type aliases and template parameters — belong to docs/CodingStandards.md and are not restated here, because a second copy of a standard is a second thing to keep correct.
