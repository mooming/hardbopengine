ListFilesInDirectory

member of hbe::OSAbstractLayer Engine/OSAL/OSAbstractLayer.h child names, one level deep, dot entries filtered — differently per platform

Signature

hbe::HVector<hbe::HString> ListFilesInDirectory(const char* path)

Function description

The child names of one directory, one level deep, as an hbe::HVector<hbe::HString> — names only, no paths, no types, no recursion. For a tree walk, Directory builds on this; for a recursive walk, its constructor is the recursion. Both POSIX units read the directory with opendir / readdir; the Windows unit uses FindFirstFileA over path + "/*". Every unit shrinks the vector to fit before returning.

The dot-entry filter differs by platform, and this is the one place the two POSIX units and the Windows unit disagree on results. Linux and macOS skip every name whose first character is '.' — hidden files included — plus . and .. and the empty name. The Windows unit skips only . and .., and returns hidden files like any other. A caller that must not see hidden files cannot rely on this function on Windows. 
	if (DIR* dir = opendir(path))
	{
		while (struct dirent* element = readdir(dir))
		{
			continueIf(strcmp(element->d_name, ".") == 0);
			continueIf(strcmp(element->d_name, "..") == 0);
			continueIf(element->d_name[0] == '.' || element->d_name[0] == '\0');

			fileList.push_back(HString(element->d_name));
		}

		closedir(dir);
	}

A path that cannot be opened — missing, or a file — yields an empty vector with no error signal: the failure and the empty directory are indistinguishable in the answer. Directory's constructor inherits that silence.

Parameters

ParameterTypeRequirement
pathconst char*The directory to list, NUL-terminated; a path that cannot be opened yields an empty result.

Return value

The child names, filtered as above, order unspecified — readdir and FindFirstFileA promise no order. Empty for an unreadable or empty directory alike.
