GetFullPath

member of hbe::OSAbstractLayer Engine/OSAL/OSAbstractLayer.h the absolute form of a path — realpath on POSIX, lexical on Windows

Signature

hbe::HString GetFullPath(const hbe::HString& path)

Function description

The absolute form of the path, with the platform's own resolution. On Linux and macOS the work is realpath into a PATH_MAX stack buffer, which has two consequences a caller must know: the path has to exist — realpath resolves symlinks and fails on a missing file — and the answer is the fully dereferenced spelling, not a lexical cleanup. On Windows the work is GetFullPathNameA, which resolves lexically against the current directory and does not require existence. Both then hand the result to StringUtil::TrimPath, which normalises backslashes to slashes and removes one trailing slash. 

	char fullPath[PATH_MAX];
	void* ptr = realpath(path.c_str(), fullPath);
	if (ptr != fullPath)
	{
		std::cerr << "[OS::GetFullPath] Failed to get the full path of " << path << std::endl;

		return TrimPath(path);
	}

	return TrimPath(fullPath);

From Engine/OSAL/LinuxAbstractLayer.cpp, OS::GetFullPath(const hbe::HString&)

Failure is quiet and lossy on POSIX. When realpath fails — a path that does not exist, most commonly — the function writes one line to std::cerr and returns the input, trimmed. The caller cannot distinguish "absolute path" from "the relative string I gave you" except by already knowing. The Windows unit checks nothing at all: it returns whatever GetFullPathNameA left in the buffer.

Parameters

ParameterTypeRequirement
pathconst hbe::HString&The path to resolve; on POSIX it must exist for the answer to be more than the input echoed back.

Return value

The resolved absolute path, trimmed. On POSIX failure: the trimmed input, after a line on std::cerr.

Examples

No call site for this function exists in the repository — no engine code, test or application resolves a path through it today. It is declared, defined on all three platforms, and waiting for a caller; the only in-tree callers of this header's functions are Directory's, and they use the other two.
