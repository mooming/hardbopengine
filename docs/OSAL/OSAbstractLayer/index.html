OSAbstractLayer

Engine/OSAL/OSAbstractLayer.h namespace OS macro set PATH_MAX and the WINDOWS/POSIX split, plus the path-and-listing primitives Directory is built on

Class description

OSAbstractLayer is a header, not a class: its surface is two preprocessor decisions and three free functions at OS:: scope — GetFullPath, IsDirectory and ListFilesInDirectory — the path and listing primitives that Directory is built on. The functions are declared once in Engine/OSAL/OSAbstractLayer.h and defined once per platform: Engine/OSAL/LinuxAbstractLayer.cpp, Engine/OSAL/OSXAbstractLayer.cpp and Engine/OSAL/WindowsAbstractLayer.cpp — the OSAL pattern in its cleanest form, and one of the few entries implemented on all three platforms.

The preprocessor half is the header's own preamble: it defines WINDOWS or POSIX from the compiler's WIN32, and uses that choice to include <windows.h> or <dirent.h> and to spell PATH_MAX. The generic unit Engine/OSAL/OSAbstractLayer.cpp defines nothing — it includes the header and stops, which is how the per-platform units avoid colliding with it.

The two POSIX units are line-for-line identical, and the Windows unit is not. Linux and macOS both answer through realpath, opendir and readdir; the Windows unit uses GetFullPathNameA, GetFileAttributesA and FindFirstFileA, and its listing filters a different set of names — see that function's page for the divergence.

Template parameters

None — the entry declares no types at all.

Class properties

The macros, with who reads them — a define nobody reads is a define that can rot:

NameRead byWhat it controls
WINDOWS Engine/OSAL/OSAbstractLayer.h itself Defined when the compiler predefines WIN32; selects the <windows.h> include and the PATH_MAX spelling

PATH_MAX Engine/OSAL/LinuxAbstractLayer.cpp, Engine/OSAL/OSXAbstractLayer.cpp — the realpath buffer; Engine/String/StringUtil.cpp defines its own independent fallback MAX_PATH from the Windows SDK on Windows, the system value elsewhere; the size of GetFullPath's stack buffer

Class methods

None — the entry is macros and free functions. The functions carry real contracts, so each owns a page:

NameSignatureWhat a caller depends on
GetFullPath hbe::HString GetFullPath(const hbe::HString& path) Absolute form of the path — resolved by realpath on POSIX, which requires the path to exist; backslashes normalised to slashes on the way out
IsDirectory bool IsDirectory(const char* path) true exactly when the path can be opened as a directory — a symlink to a directory answers true, a file and a missing path answer false
ListFilesInDirectory hbe::HVector<hbe::HString> ListFilesInDirectory(const char* path) Child names only, one level deep; dot entries are filtered — all of them on POSIX, only . and .. on Windows

Non-member helpers

None — the three functions above are the entire functional surface, and they are the entry.
