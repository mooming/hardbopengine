Window

Engine/OSAL/Window.h namespace OS a window on X11, Cocoa or Win32 — same interface, and the close button is detected on macOS only

Class description

A window on whichever toolkit the platform chose: created with a size and a title, polled for events, and closed explicitly. The public interface is identical on every operating system; the implementation units — Engine/OSAL/LinuxWindow.cpp (X11), Engine/OSAL/OSXWindow.mm (Cocoa), Engine/OSAL/Win32Window.cpp (Win32) — differ in what they actually do, and the differences reach a caller: initial visibility, resize handling, and whether the close button is detected at all.

GetNativeHandle is the deliberate leak: the intptr_t — an X11 Window id, an NSWindow*, or an HWND — is what the renderer passes to the graphics API to attach a surface. Every other method is portable; anything using the handle is not, which is why the renderer is where that call happens.

The close button is detected on macOS only. The macOS unit installs a delegate whose windowShouldClose: writes the shared closedFlag directly. The Linux unit's PollEvents has an unimplemented stub where the close message would be handled, and the Windows unit records the close in a shouldCloseFlag that nothing reads — IsClosed reports closedFlag, which only Close sets. A user clicking the window's X flips IsClosed() on macOS and on no other platform.
Two smaller divergences a caller meets. The default-constructed visibleFlag is true on Linux and Windows but false on macOS; and the macOS window is created without NSWindowStyleMaskResizable, so it is not user-resizable there — while SetSize works and the Linux and Windows units track user resizes through their event pumps.

Template parameters

None — the class is not a template.

void* osDelegate; private none in the header macOS only — the NSWindowDelegate observing the close button; NSWindow holds its delegate unretained, so the Window owns the reference and releases it in Close.
