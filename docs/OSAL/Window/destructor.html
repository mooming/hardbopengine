~Window

member of hbe::Window Engine/OSAL/Window.h calls Close — the window does not outlive its object

Signature

~Window()

Function description

Calls Close — every platform unit's destructor is exactly that call — so a Window object never outlives its platform window. The macOS unit additionally releases the delegate it owns (see Close for why the ownership exists at all). 

Window::~Window()
{
	Close();
}

From Engine/OSAL/LinuxWindow.cpp, OS::Window::~Window()

The identical definition exists in Engine/OSAL/OSXWindow.mm and Engine/OSAL/Win32Window.cpp. There is no way to detach a window from its object — the teardown always goes through Close, whether the object dies or the caller closes it first.

Parameters

None.

Return value

Not applicable — destructors return nothing.

Examples

The OSAL's own test releases the window through its unique_ptr, which is this destructor's moment: 

			window.reset();
			windowPromise.set_value(nullptr);
