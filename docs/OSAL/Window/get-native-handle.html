GetNativeHandle

member of hbe::Window Engine/OSAL/Window.h the deliberate leak: the platform window id as an integer

Signature

[[nodiscard]] intptr_t GetNativeHandle() const

Function description

The platform window as an integer: reinterpret_cast<intptr_t> of the X11 Window id on Linux, of the NSWindow* on macOS, of the HWND on Windows. This is the deliberate leak in the facade — the one method whose answer is not portable — and it exists because the renderer must hand the platform window to the graphics API to attach a surface to. Everything else on the class stays portable; this call is where portability ends, which is why it happens in the renderer and nowhere else. 

intptr_t Window::GetNativeHandle() const
{
	return reinterpret_cast<intptr_t>(window);
}

From Engine/OSAL/LinuxWindow.cpp, OS::Window::GetNativeHandle()

The value is meaningless after Close — the Linux and Windows units clear their handles, and the macOS window is closed — and it is 0 before CreateWindow. The renderer takes it once, at Initialize, while the window is alive.

Parameters

None.

Return value

The native window id cast to intptr_t; 0 before creation, and a dead value after close.

Examples

The renderer's surface creation is the consumer — it casts the handle to the platform type the graphics API wants: 

	if (!renderer.Initialize(window.get()))
