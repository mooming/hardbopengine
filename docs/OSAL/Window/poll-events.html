PollEvents

member of hbe::Window Engine/OSAL/Window.h drain the platform queue once — size updates, close detection on macOS

Signature

void PollEvents()

Function description

Drains the platform's event queue once — everything pending, not one event. Windows pumps with PeekMessage / TranslateMessage / DispatchMessage, which routes messages through the file-local WindowProc: WM_SIZE updates width / height, WM_DESTROY sets shouldCloseFlag (Engine/OSAL/Win32Window.cpp). Linux pumps XPending events, where ConfigureEvent updates the size and the close message is an unimplemented stub (Engine/OSAL/LinuxWindow.cpp). macOS polls differently: no queue drain at all — the unit checks whether the NSWindow is still visible and marks closedFlag when it is not, the close button having been handled by the delegate (Engine/OSAL/OSXWindow.mm). 

	if (osHandle != nullptr)
	{
		auto window = static_cast<NSWindow*>(osHandle);
		if (![window isVisible])
		{
			closedFlag = true;
		}
	}

From Engine/OSAL/OSXWindow.mm, OS::Window::PollEvents()

The two pumps must alternate. The macOS close detection depends on the OS application's event pump having run — the delegate fires from Application::PollEvents — and the OSAL's own tests call both pumps every iteration. A caller that pumps only the window starves the very events this method is supposed to reflect.

Parameters

None.

Return value

Not applicable — returns void, and cannot fail.

Examples

The alternating-pump shape from the OSAL's own test: 

			for (int i = 0; i < 100; ++i)
			{
				app->PollEvents();
				window->PollEvents();
				std::this_thread::sleep_for(std::chrono::milliseconds(10));
			}
