SetForbidden

member of hbe::ProtectionMode Engine/OSAL/OSProtectionMode.h ORs PROT_NONE into value — any access to the mapping faults

Signature

void SetForbidden() noexcept

Function description

ORs PROT_NONE into value, making any access to the mapping fault. The body is one OR of the <sys/mman.h> constant, and the identical definition exists in Engine/OSAL/LinuxProtectionMode.cpp (OS::ProtectionMode::SetForbidden()) and Engine/OSAL/OSXProtectionMode.cpp (OS::ProtectionMode::SetForbidden()), each behind its platform guard. No Windows definition exists — see the class page.

PROT_NONE excludes the other three bits by POSIX semantics — a mapping is either inaccessible or has some access — and the class does not enforce it; the in-tree callers never combine it with anything. Nothing is cleared first — on a fresh ProtectionMode it is the first call made.

Parameters

None.

Return value

Not applicable — the method mutates value and returns void.

Examples

No call site for this method exists in the repository. Note that an empty ProtectionMode — one that never had a setter called — already maps as PROT_NONE on POSIX, because mmap reads the protection argument verbatim and 0 is PROT_NONE; so a caller who wants a forbidden mapping does not need this setter at all.
