ProtectionMode

Engine/OSAL/OSProtectionMode.h namespace OS final the protection word OS::MapMemory passes to mmap — readable, writable, executable, forbidden; setters OR, nothing clears

Class description

OS::ProtectionMode is the argument builder for OS::MapMemory: a public int value, zero by default, that the Set… methods accumulate the POSIX mmap protection bits into — PROT_NONE, PROT_READ, PROT_WRITE, PROT_EXEC from <sys/mman.h>. The implementations of OS::MapMemory hand value to mmap verbatim: Engine/OSAL/LinuxInputOutput.cpp passes it as the protection argument.

The setters are defined on Linux and macOS only. The identical bodies live in Engine/OSAL/LinuxProtectionMode.cpp and Engine/OSAL/OSXProtectionMode.cpp, each behind its PLATFORM_* guard, and no Windows unit exists anywhere in the repository — Engine/OSAL/CMakeLists.txt lists none, and Engine/OSAL/WindowsInputOutput.cpp, the only Windows file of the IO surface, is a copyright notice with no code. A Windows build that calls any setter does not link.
Accumulation is the whole model: setters only OR, nothing clears. A fresh ProtectionMode is the only reset. PROT_NONE excludes the other three by POSIX semantics — a mapping is either inaccessible or has some access — and the class does not enforce it. The in-tree callers combine only SetReadable and SetWritable, in Engine/Resource/BufferUtil.cpp and the OSAL's own IO test.
