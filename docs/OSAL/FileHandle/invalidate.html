Invalidate

member of hbe::FileHandle Engine/OSAL/OSFileHandle.h writes -1 into the descriptor without closing anything

Signature

void Invalidate() noexcept

Function description

Writes -1 into the descriptor — and nothing else. This is not a close: a handle that held a real descriptor and is invalidated keeps that descriptor open in the operating system, with no handle left to close it. The method exists for the states where no descriptor is held — the default constructor calls it, the move constructor calls it on its emptied source, and OS::Close's implementations call it on the handle they just closed.

It is also the raw-storage escape hatch's reset: Engine/Resource/BufferUtil.cpp copies the union storage out of a live handle, invalidates the handle so its destructor will not close the file, and hands the raw bytes to the buffer's releaser. 

	auto handleData = fh.data;
	fh.Invalidate();

From Engine/Resource/BufferUtil.cpp, hbe::BufferUtil::GenerateFileBuffer(StaticString path, OS::FileOpenMode openMode, OS::ProtectionMode protection, size_t size)

The platform units write the same -1 through different spellings — Engine/OSAL/LinuxFileHandle.cpp assigns fd directly, Engine/OSAL/OSXFileHandle.cpp through its SetHandle helper.

Parameters

None.

Return value

Not applicable — the method mutates the handle and returns void.

Examples

The pair to keep straight: Invalidate on a live handle leaks the descriptor, while OS::Close closes it and then invalidates. The quote above is the intended use — invalidate only a handle whose storage has already been moved somewhere else.
