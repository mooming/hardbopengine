Module Index / OSAL / FileHandle / ~FileHandle

~FileHandle

member of hbe::FileHandle Engine/OSAL/OSFileHandle.h closes the file when the handle is valid; an invalid handle destructs silently

Signature

~FileHandle()

Function description

The destructor closes the file — but only when the handle is valid. An invalid handle (descriptor -1, which is what the default constructor leaves and what a move leaves behind) destructs without touching the operating system. A valid handle calls OS::Close on itself, by rvalue reference, which closes the descriptor and invalidates the handle before the storage dies. 

FileHandle::~FileHandle()
{
	returnIf(fd < 0);

	Close(std::move(*this));
}

From Engine/OSAL/LinuxFileHandle.cpp, OS::FileHandle::~FileHandle()

The OSX unit defines the same destructor through its GetHandle helper, reading the descriptor out of the void* data view (Engine/OSAL/OSXFileHandle.cpp); the guard is the same fd < 0 test under a different spelling.

The destructor discards the close result. OS::Close logs a warning and returns false when the platform close fails, and nothing retries — a descriptor that refused to close is gone from the handle's point of view, because the handle is already invalid by then. This is the normal destructor trade-off and the reason the class pairs so naturally with OS::Open: acquire in a scope, release by leaving it.

Parameters

None.

Return value

Not applicable — destructors return nothing.

Examples

Scope-based release is the intended use: on every early-exit path of the buffer generator, the local FileHandle goes out of scope and the destructor closes whatever OS::Open left in it. The long-distance version is the buffer releaser, which rebuilds a handle from raw storage so the close happens when the mapping is released: 

		FileHandle fh;
		fh.data = handleData;

		Assert(size > 0);
		auto ptr = static_cast<void*>(data);

		MapSyncMode syncMode;
		syncMode.SetSync();

		MapSync(ptr, size, syncMode);
		UnmapMemory((void*) data, size);

		OS::Close(std::move(fh));
