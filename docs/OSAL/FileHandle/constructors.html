FileHandle

member of hbe::FileHandle Engine/OSAL/OSFileHandle.h default-constructs to invalid; the move steals the descriptor and empties the source

Signature

FileHandle()

FileHandle(const FileHandle&) = delete

FileHandle(FileHandle&& rhs)

Function description

Two constructors, and the pair is the handle's ownership story. The default constructor calls Invalidate, so a fresh handle holds descriptor -1 — valid to destruct, valid to pass to OS::Open's out-parameter, never a dangling descriptor. The move constructor copies the raw union storage and then invalidates the source, so ownership of the descriptor ends with exactly one handle; the copy constructor is deleted, so there is no second owner by accident.

The two platform units define the pair identically in effect and differently in spelling: Engine/OSAL/LinuxFileHandle.cpp touches fd directly, Engine/OSAL/OSXFileHandle.cpp goes through its reinterpret_cast GetHandle / SetHandle helpers. Both alias the same union storage.

The default constructor is one call: Invalidate(), leaving descriptor -1. The move constructor is the ownership transfer — copy the raw union storage, then invalidate the source: 

FileHandle::FileHandle(FileHandle&& rhs)
	: data(rhs.data)
{
	rhs.Invalidate();
}
