IsValidAllocation

member of hbe::OSMemory Engine/OSAL/OSMemory.h namespace OS recognises the allocation sentinels VirtualAlloc returns

Signature

[[nodiscard]] bool IsValidAllocation(void* ptr) noexcept

Function description

Whether the pointer counts as a live allocation answer. The POSIX units (Engine/OSAL/LinuxMemory.cpp, Engine/OSAL/OSXMemory.cpp) accept a pointer only when it is neither nullptr nor reinterpret_cast<void*>(-1) — the second test is what recognises MAP_FAILED, the sentinel VirtualAlloc returns on failure there. The Windows unit (Engine/OSAL/WindowsMemory.cpp) tests only ptr != nullptr, which is Windows' own allocation sentinel. 

bool OS::IsValidAllocation(void* ptr) noexcept
{
	return ptr != nullptr && ptr != reinterpret_cast<void*>(-1);
}

From Engine/OSAL/LinuxMemory.cpp, OS::IsValidAllocation(void*)

The function does not ask the operating system anything: it recognises the sentinels the allocation functions of this same header return. It is the companion of VirtualAlloc, and only of it.

Parameters

ParameterTypeRequirement
ptrvoid*The pointer to test — typically straight out of VirtualAlloc.

Return value

true when the pointer is neither nullptr nor the platform's allocation-failure sentinel; false when it is either.

Examples

The OSAL's own test is the only in-tree caller — the round-trip test checks the allocation before writing to it: 

		void* ptr = OS::VirtualAlloc(allocSize);

		if (!OS::IsValidAllocation(ptr))
		{
			ls << "VirtualAlloc failed" << lferr;

			return;
		}
