VirtualFree

member of hbe::OSMemory Engine/OSAL/OSMemory.h namespace OS release a reservation — silent munmap on POSIX, asserting VirtualFree on Windows

Signature

void VirtualFree(void* address, std::size_t n) noexcept

Function description

Releases a reservation made by VirtualAlloc. On Linux and macOS the work is munmap(address, size) (Engine/OSAL/LinuxMemory.cpp, Engine/OSAL/OSXMemory.cpp) — and the return value is ignored, so a failed unmap is silent. On Windows it is ::VirtualFree(address, n, MEM_RELEASE), and a failure is neither silent nor survivable: the unit logs nothing and calls hbe::Assert(false) (Engine/OSAL/WindowsMemory.cpp). 

void OS::VirtualFree(void* address, std::size_t size) noexcept
{
	munmap(address, size);
}

From Engine/OSAL/LinuxMemory.cpp, OS::VirtualFree(void*, std::size_t)

The size must match what was mapped, and the address must be the mapping's base. munmap unmaps the given range; ::VirtualFree with MEM_RELEASE requires the base address returned by the allocation and treats the size as the whole reservation. A caller that frees a sub-range or a shifted pointer corrupts or fails — on POSIX silently, on Windows with an assert.

Parameters

ParameterTypeRequirement
addressvoid*The base address VirtualAlloc returned.
nstd::size_tThe size of the reservation; on Windows the whole reservation is released regardless.

Return value

Not applicable — returns void. POSIX failure is silent; Windows failure asserts.

Examples

The guard-page allocator releases its reservation when the memory-investigation build frees a buffer: 

		OS::VirtualFree(rawPtr, allocated);
