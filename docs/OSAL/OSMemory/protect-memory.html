ProtectMemory

member of hbe::OSMemory Engine/OSAL/OSMemory.h namespace OS make a range untouchable — the guard-page mechanism

Signature

void ProtectMemory(void* address, std::size_t n) noexcept

Function description

Makes the range untouchable: mprotect with PROT_NONE on Linux and macOS (Engine/OSAL/LinuxMemory.cpp, Engine/OSAL/OSXMemory.cpp), VirtualProtect with PAGE_NOACCESS on Windows (Engine/OSAL/WindowsMemory.cpp). Any read or write through the range afterwards faults. There is no mode parameter and no way back through this header — the one protection this function applies is none, which is what makes it the guard-page mechanism: the engine's dangling-pointer check (MEMORY_DANGLING_POINTER_CHECK_ENABLED) protects a freed buffer with it, so a stale pointer dies loudly instead of reading stale data. 

void OS::ProtectMemory(void* address, size_t n) noexcept
{
	auto result = mprotect(address, n, PROT_NONE);

	if (unlikely(result != 0))
	{
		using namespace std;
		cerr << "[OS::ProtectMemory] address = " << address << ", n = " << n << " : " << strerror(errno) << endl;

		hbe::Assert(false);
	}
}

Failure is loud on every platform. The POSIX units log to std::cerr and assert; the Windows unit logs through the engine and asserts. A failed protection is treated as a broken invariant, not a condition to continue from — which is the right posture for a debugging mechanism, and the reason this function is only compiled into investigation builds.

Parameters

ParameterTypeRequirement
addressvoid*Page-aligned base of the range; mprotect and VirtualProtect both require page alignment.
nstd::size_tLength in bytes; spans whole pages from the base.

Return value

Not applicable — returns void. Failure asserts rather than returning a code.

Examples

The dangling-pointer check protecting a freed buffer, in the guard-page allocator's release path: 

#if MEMORY_DANGLING_POINTER_CHECK_ENABLED
		OS::ProtectMemory(rawPtr, allocated);
#else // MEMORY_DANGLING_POINTER_CHECK_ENABLED
		OS::VirtualFree(rawPtr, allocated);
#endif // MEMORY_DANGLING_POINTER_CHECK_ENABLED
