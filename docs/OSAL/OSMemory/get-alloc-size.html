GetAllocSize

member of hbe::OSMemory Engine/OSAL/OSMemory.h namespace OS the usable size the platform allocator gave the pointer

Signature

[[nodiscard]] size_t GetAllocSize(void* ptr) noexcept

Function description

The size the platform's own allocator gave the pointer — asked back from the allocator, not stored by the engine. Linux answers malloc_usable_size (Engine/OSAL/LinuxMemory.cpp), macOS malloc_size (Engine/OSAL/OSXMemory.cpp), Windows _msize (Engine/OSAL/WindowsMemory.cpp). The three agree on the contract and differ on the exact figure: the platform may hand back more than was requested, so this is the usable size, which is at least the requested one.

The engine's global allocation tracking uses it exactly that way — when the caller did not record a size, the allocator's own figure is taken: 

		RecordDeallocation(size != 0 ? size : OS::GetAllocSize(ptr), caller);

From Engine/Memory/GlobalAllocation.cpp, hbe::Deallocate(void* ptr, size_t size, void* caller)

The pointer must be one the platform allocator owns. malloc_usable_size and friends are undefined for a pointer that did not come from malloc/new — notably, a pointer from VirtualAlloc is mmap memory, not heap memory, and this function has nothing to say about it. The engine's guard-page allocator knows its sizes and never asks.

Parameters

ParameterTypeRequirement
ptrvoid*A pointer the platform heap allocator gave out; anything else is undefined behaviour.

Return value

The usable size in bytes — at least what was requested, possibly more.

Examples

The second in-tree use — the guard-page allocator reading back what it got, so its page math matches the allocation it actually holds: 

		const auto allocated = OS::GetAllocSize(ptr);

From Engine/Memory/SystemAllocator.h, SystemAllocator::AllocateBytes(std::size_t nBytes)
