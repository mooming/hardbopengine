Application

member of hbe::Application Engine/OSAL/Application.h constructs to a null handle on every platform

Signature

Application() noexcept

Function description

The only constructor, and it does one thing on every platform: sets platformHandle to nullptr. No operating system object is taken at construction — the macOS application object is acquired by Initialize, and the Linux and Windows units never acquire one at all. The declaration is in Engine/OSAL/Application.h; the identical definitions live in Engine/OSAL/LinuxApplication.cpp, Engine/OSAL/OSXApplication.mm and Engine/OSAL/Win32Application.cpp. 

Application::Application() noexcept
	: platformHandle(nullptr)
{
}

From Engine/OSAL/LinuxApplication.cpp, OS::Application::Application()

noexcept in the declaration is honest: nothing here allocates or calls the operating system. Together with CreateApplication's [[nodiscard]] std::unique_ptr, the class's lifetime story is simple — one heap allocation, owned by whoever asked for it.

Parameters

None.

Return value

Not applicable — constructors return nothing.

Examples

The engine constructs it through the factory, then asserts it arrived: 

		application = OS::CreateApplication();
		FatalAssert(application != nullptr, "Application level requested, no OS application created");
		application->Initialize();
