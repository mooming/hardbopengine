Application

Engine/OSAL/Application.h namespace OS the OS application facade — an NSApplication story on macOS, empty bodies elsewhere

Class description

The platform-independent application facade: it creates the OS application object and pumps its events, and the public interface is identical on every operating system. What differs is the implementation unit behind it — Engine/OSAL/LinuxApplication.cpp, Engine/OSAL/OSXApplication.mm, Engine/OSAL/Win32Application.cpp, selected at build time by the PLATFORM_* macros — and here the difference is extreme: only the macOS unit does anything. The Linux and Windows definitions are empty bodies; the whole OS-application story of this engine is a macOS story, because NSApplication is the one platform where the window server requires an application object to exist.

On macOS, Initialize takes the process-wide NSApplication singleton, sets a regular activation policy, installs a delegate that refuses to terminate on last-window-closed, and finishes launching; PollEvents drains every queued event and dispatches it; the destructor stops the run loop — deliberately not [app terminate:], which would end in exit() and discard main()'s return value. The private platformHandle holds the NSApplication* there, and nullptr everywhere else.

The Engine creates and owns the application when EInitLevel::Application is requested, checks it with a FatalAssert, and hands the pointer out through GetApplication().

None — the class is not a template.
