Initialize

member of hbe::Application Engine/OSAL/Application.h takes the NSApplication singleton on macOS; no-op elsewhere

Signature

void Initialize()

Function description

Takes the OS application object. On macOS that is the process-wide NSApplication singleton: the unit asks for it, sets a regular activation policy (a normal app, dock icon and all), installs its own delegate if the application has none, and calls finishLaunching — after which platformHandle holds the application and every other method has something to act on (Engine/OSAL/OSXApplication.mm). The delegate — an AppDelegate defined in the same file — answers applicationShouldTerminateAfterLastWindowClosed: with NO, so closing the last window does not tear the process down behind the engine's back. 

	NSApplication *app = [NSApplication sharedApplication];
	[app setActivationPolicy:NSApplicationActivationPolicyRegular];

	auto delegate = [app delegate];
	if (delegate == nil)
	{
		AppDelegate *appDelegate = [[AppDelegate alloc] init];
		[app setDelegate:appDelegate];
	}

	[app finishLaunching];
	platformHandle = app;

From Engine/OSAL/OSXApplication.mm, OS::Application::Initialize()

On macOS the method is idempotent: a second call with a non-null handle returns immediately. On Linux and Windows the definition is an empty body — there is no OS application object to take, and the method's existence is what keeps the facade's interface identical across platforms.

Parameters

None.

Return value

Not applicable — returns void, and cannot fail.

Examples

The engine calls it exactly once, right after creating the application: 

		application = OS::CreateApplication();
		FatalAssert(application != nullptr, "Application level requested, no OS application created");
		application->Initialize();
