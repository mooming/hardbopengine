~Application

member of hbe::Application Engine/OSAL/Application.h stops the macOS run loop — deliberately not terminate:

Signature

~Application()

Function description

Empty on Linux and Windows — their units define bodies that do nothing, consistently with everything else those units define. On macOS the destructor stops the NSApplication run loop, and what it deliberately does not call is the interesting part: [app terminate:] ends in exit(), which would tear the process down from inside a destructor — main()'s return value discarded so no application could ever report a status, and static destructors never run. NSApplication is a process-wide singleton that outlives this wrapper, and the engine owns its own shutdown sequence, so stopping the run loop is all that belongs here. 

Application::~Application()
{
	returnIf(platformHandle == nullptr);

	auto app = static_cast<NSApplication*>(platformHandle);
	[app stop:nil];

	platformHandle = nullptr;
}

Quitting through the window's close button is unaffected by this choice: that path goes through the window's close handling and the application loop exits on its own — the run loop is already stopped or about to be.

Parameters

None.

Return value

Not applicable — destructors return nothing.

Examples

The engine releases the application at the end of its run loop, and this destructor is what runs:

	{
		application.reset();
	}
