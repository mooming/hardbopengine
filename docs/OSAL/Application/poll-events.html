PollEvents

member of hbe::Application Engine/OSAL/Application.h drains and dispatches all queued events on macOS; no-op elsewhere

Signature

void PollEvents()

Function description

Drains and dispatches all queued events — not one per call. The macOS unit loops nextEventMatchingMask:NSEventMaskAny untilDate:[NSDate distantPast] with dequeue, sending each event and updating the windows, until the queue is empty (Engine/OSAL/OSXApplication.mm). A caller that wants to coalesce work polls once per frame and gets everything that accumulated; the window's own PollEvents is the window-side pump the renderer drives. 

	while (NSEvent *event = [app nextEventMatchingMask:NSEventMaskAny
										 untilDate:[NSDate distantPast]
											inMode:NSDefaultRunLoopMode
										 dequeue:YES])
	{
		[app sendEvent:event];
		[app updateWindows];
	}

From Engine/OSAL/OSXApplication.mm, OS::Application::PollEvents()

An uninitialised application answers without touching the operating system — the unit returns when platformHandle is null. On Linux and Windows the definition is an empty body.

The engine's own loop never calls this. Engine::Run() pumps the task system and exits; the only caller in the repository is Applications/VulkanExample/Main.cpp, which polls once per rendered frame. An engine-driven window that needs OS events pumped relies on that example's shape, not on the engine loop.

Parameters

None.

Return value

Not applicable — returns void, and cannot fail.

Examples

The one in-tree call site, once per frame of the Vulkan example's render loop: 

	while (running && !window->IsClosed())
	{
		app->PollEvents();
