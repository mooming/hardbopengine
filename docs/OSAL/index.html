Module Index / OSAL

OSAL

namespace OS Engine/OSAL 18 headers, 35 sources — the operating-system boundary: application, window, files, threads, memory, backtrace

Module description

The OS abstraction layer is where platform difference is allowed to exist. The public interface of an entry here is identical on every operating system; what differs is the implementation unit behind it, chosen at build time by PLATFORM_LINUX / PLATFORM_OSX / PLATFORM_WINDOWS. The OS namespace, not hbe, marks this as the boundary — with one exception: SourceLocation lives at hbe:: scope because it is consumed by the Core and Memory modules directly.

The pattern in its cleanest form: a neutral header declares, a per-platform unit defines, and Engine/OSAL/CMakeLists.txt compiles every unit into the library on every platform — the PLATFORM_* guards inside each unit decide what actually gets defined. The consequence a reader must internalise is that "no definition exists" is a per-platform fact, not a global one: several surfaces of this module are implemented on Linux and macOS only, and one function on macOS only. The platform table names the units, and each class page names its own gaps.

Module variables

None exposed. Two constants are leaned on instead: Config::DefaultAlign, the default for every alignment argument in OSMemory, and PATH_MAX, which OSAbstractLayer.h defines per platform — MAX_PATH from the Windows SDK, the system value elsewhere.

Intrinsic macros (Engine/OSAL/Intrinsic.h)

Compiler-facing primitives. They are macros because the operations are not callable: branch prediction hints and a breakpoint are instructions, and caller information only exists at the expansion site.

MacroPurpose
likely(x)Tell the compiler the condition is usually true — the error path goes the other way
unlikely(x)The reverse, and the one worth putting on a failure branch in a hot loop
debugBreak()Halt for the debugger
CallerFile(), CallerFunc(), CallerLine(), CallerColumn()Expansion-site identity; the four defaults of SourceLocation::current

The names are lower-case, unlike the SCREAMING_SNAKE_CASE that docs/CodingStandards.md asks macros for — these are used as function-call shapes and read as such. The per-platform spellings live in LinuxIntrinsic.h, OSXIntrinsic.h and WindowsIntrinsic.h; on GCC, CallerColumn() is the literal 0.

Platform-specific units

One implementation unit per platform, per concern — compiled together. The library builds every unit listed above on every platform; the PLATFORM_* guard inside each unit decides whether it defines anything. The risk recorded in the repository's own review notes as an ODR hazard is real: if a generic unit and a platform unit ever define the same function unguarded, the linker sees two definitions. If you add a platform unit, check how the guards partition the surface before the linker or the reader of the code finds out.
