Module Index / OSAL / OSThread / GetCPUIndex

GetCPUIndex

member of hbe::OSThread Engine/OSAL/OSThread.h namespace OS which core this thread is on right now

Signature

[[nodiscard]] int GetCPUIndex() noexcept

Function description

Which core this thread is running on right now — a value that can change between the call and the next instruction, because the scheduler may migrate the thread at any time. Linux answers sched_getcpu() (Engine/OSAL/LinuxThread.cpp); Windows answers GetCurrentProcessorNumber() (Engine/OSAL/WindowsThread.cpp); macOS answers pthread_cpu_number_np and returns -1 after logging if that call fails (Engine/OSAL/OSXThread.cpp).

The negative answer is macOS-only: the Linux and Windows units have no failure path in their definitions, so a caller checking index < 0 is really checking "did the macOS query fail".

Parameters

None.

Return value

The current core index, zero-based; -1 only from the macOS unit's failure path.

Examples

The OSAL's own test treats a negative index as the one failure there is: 

		auto cpuIndex = OS::GetCPUIndex();
		ls << "CPU Index: " << cpuIndex << lf;

		if (cpuIndex < 0)
		{
			ls << "Invalid CPU index" << lferr;

			return;
		}
