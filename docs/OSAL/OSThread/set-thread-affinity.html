SetThreadAffinity

member of hbe::OSThread Engine/OSAL/OSThread.h namespace OS pin a thread to cores — ignored entirely on macOS

Signature

void SetThreadAffinity(std::thread& thread, uint64_t mask) noexcept

Function description

Pins a thread to a set of cores, one bit per core in mask. The Linux unit builds a cpu_set_t from the low 64 bits and applies it with sched_setaffinity on the thread's native handle (Engine/OSAL/LinuxThread.cpp); the Windows unit hands the mask straight to SetThreadAffinityMask (Engine/OSAL/WindowsThread.cpp). The macOS unit's definition is an empty body — affinity is simply not applied on macOS (Engine/OSAL/OSXThread.cpp). 

	cpu_set_t set;
	CPU_ZERO(&set);
	for (size_t i = 0; i < sizeof(uint64_t); ++i)
	{
		if (((mask >> i) & 1) == 0)
			continue;

		CPU_SET(i, &set);
	}

From Engine/OSAL/LinuxThread.cpp, OS::SetThreadAffinity(std::thread&, uint64_t) — mask decoding; the sched_setaffinity call follows

The failure story differs as much as the mechanism: the Linux unit logs an error through the logger when sched_setaffinity fails; the Windows unit ignores SetThreadAffinityMask's return entirely; macOS cannot fail because it does nothing.

Parameters

ParameterTypeRequirement
threadstd::thread&The thread to pin; its native handle is used.
maskuint64_tOne bit per core, bit i meaning core i; a mask of zero is meaningless on every unit.

Return value

Not applicable — returns void. Failures log or vanish; nothing throws or asserts.

Examples

No production call site exists in the repository — no engine code pins a thread today. The task system spreads work by scheduling, not by affinity, so this is the boundary's spelling of an operation nothing uses yet.
