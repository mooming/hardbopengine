GetThreadPriority

member of hbe::OSThread Engine/OSAL/OSThread.h namespace OS the thread's OS priority — defined on macOS only

Signature

[[nodiscard]] int GetThreadPriority(std::thread& thread) noexcept

Function description

The thread's priority, as an OS number — sched_priority from pthread_getschedparam, read out of the thread's native handle (Engine/OSAL/OSXThread.cpp). Failure returns -1 after logging: the unit distinguishes a dead thread (ESRCH) from anything unexpected, and reports both through the logger.

Defined on macOS only. No Linux or Windows unit defines this function — Engine/OSAL/LinuxThread.cpp defines the setter and not the getter, Engine/OSAL/WindowsThread.cpp likewise — so a call from a Linux or Windows build does not link. The OSAL's own test is the only in-tree caller, which is why the gap has never surfaced. Until a definition exists on those platforms, the priority a thread actually has can only be learned on macOS.

The number is not portable across platforms even where the function exists: it is whatever pthread_getschedparam returns for the thread's current policy, and the header's int carries no unit, scale or policy. See the class page's coverage for what the scales are.

Parameters

ParameterTypeRequirement
threadstd::thread&The thread to ask; its native handle is read. A finished thread answers -1.

Return value

The thread's priority as the platform spells it — sched_priority on macOS; -1 when the query fails, and no answer at all on Linux and Windows, where the function has no definition.

Examples

The OSAL's own test reads, sets and reads back — the only caller the repository has: 

		auto originalPriority = OS::GetThreadPriority(testThread);
		ls << "Original thread priority: " << originalPriority << lf;
