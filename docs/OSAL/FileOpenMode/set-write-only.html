SetWriteOnly

member of hbe::FileOpenMode Engine/OSAL/OSFileOpenMode.h ORs O_WRONLY into value

Signature

void SetWriteOnly() noexcept

Function description

ORs O_WRONLY into value, marking the open as write-only: writes succeed, reads fail at the platform call. The body is one OR of the <fcntl.h> constant, and the identical definition exists in Engine/OSAL/LinuxFileOpenMode.cpp (OS::FileOpenMode::SetWriteOnly()) and Engine/OSAL/OSXFileOpenMode.cpp (OS::FileOpenMode::SetWriteOnly()), each behind its platform guard. No Windows definition exists — see the class page.

Nothing is cleared first: calling it on a mode that already carries O_RDWR produces a flag word with both bits, which POSIX open semantics do not define.

Parameters

None.

Return value

Not applicable — the method mutates value and returns void.

Examples

The only call site in the repository is the test suite of Engine/Resource/Buffer.cpp, which opens a file for writing only, truncated and created: 

			FileOpenMode openMode;

			openMode.SetWriteOnly();
			openMode.SetTruncate();
			openMode.SetCreate();
