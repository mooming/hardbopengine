SetReadWrite

member of hbe::FileOpenMode Engine/OSAL/OSFileOpenMode.h ORs O_RDWR into value — the access mode every in-tree caller uses

Signature

void SetReadWrite() noexcept

Function description

ORs O_RDWR into value, marking the open as read-and-write. The body is one OR of the <fcntl.h> constant, and the identical definition exists in Engine/OSAL/LinuxFileOpenMode.cpp (OS::FileOpenMode::SetReadWrite()) and Engine/OSAL/OSXFileOpenMode.cpp (OS::FileOpenMode::SetReadWrite()), each behind its platform guard. No Windows definition exists — see the class page.

This is the access mode of every file the engine opens: the file-buffer helpers in Engine/Resource/BufferUtil.cpp use it for all three of their flavours, including the read-only one, and restrict what the mapping may do at the ProtectionMode level instead. Nothing is cleared first — on a fresh FileOpenMode it is the first call made.

Parameters

None.

Return value

Not applicable — the method mutates value and returns void.

Examples

The shape every in-tree caller shares — one access mode, then existence-dependent extras: 

	FileOpenMode openMode;
	openMode.SetReadWrite();

	if (Exist(path))
	{
		openMode.SetTruncate();
	}
	else
	{
		openMode.SetCreate();
	}
