SetReadOnly

member of hbe::FileOpenMode Engine/OSAL/OSFileOpenMode.h ORs O_RDONLY into value

Signature

void SetReadOnly() noexcept

Function description

ORs O_RDONLY into value, marking the open as read-only: reads succeed, writes fail at the platform call. The body is one OR of the <fcntl.h> constant, and the identical definition exists in Engine/OSAL/LinuxFileOpenMode.cpp (OS::FileOpenMode::SetReadOnly()) and Engine/OSAL/OSXFileOpenMode.cpp (OS::FileOpenMode::SetReadOnly()), each behind its platform guard. No Windows definition exists — see the class page.

Nothing is cleared first: calling it on a mode that already carries O_RDWR produces a flag word with both bits, which POSIX open semantics do not define. The in-tree callers always set the access mode on a fresh FileOpenMode.

Parameters

None.

Return value

Not applicable — the method mutates value and returns void.

Examples

Both call sites in the repository are test code. The OSAL's own IO test opens a file a second time purely to read back what the mapped-write phase put there:

			FileHandle fh;
			FileOpenMode openMode;
			openMode.SetReadOnly();
