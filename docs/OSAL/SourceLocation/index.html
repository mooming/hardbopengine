SourceLocation

Engine/OSAL/SourceLocation.h namespace hbe final a constexpr record of the call site — file, function, line and column, captured by default arguments

Class description

hbe::SourceLocation is a small constexpr value that records where in the source a call happened: a file name, a function name, a line and a column. It exists so that a function which wants to report its caller does not make the caller write anything — the parameters of current default to the CallerFile() / CallerFunc() / CallerLine() / CallerColumn() macros of Engine/OSAL/Intrinsic.h, and a default argument is evaluated at the caller's site, so a parameter written SourceLocation location = SourceLocation::current() captures the function that omitted the argument. That is the pattern Engine/Memory/PoolAllocator.h uses for its profiling constructor.

The consumers are the lock and allocator layers: Engine/Core/ScopedLock.h logs all four fields when a lock times out, and the profiling allocators (PoolAllocator, StackAllocator) store the location they were constructed with and hand it to MemoryManager::DeregisterAllocator(TId id, const SourceLocation& srcLocation) when they die. The assertion family in Engine/Core/Debug.h does not use this class — it captures with the standard library's std::source_location, which answers the same four questions through the same accessor shapes. Every field here is const, so a location is fixed at construction — there is no "update the line later" call to misuse.

The whole class lives in the header, and no per-platform unit touches it. OSAL's usual shape — a neutral header whose functions the Linux*.cpp / OSX*.mm / Win32*.cpp units define — does not apply here: capture is done entirely by compiler builtins expanded at the call site, so there is nothing for an operating system to answer.
