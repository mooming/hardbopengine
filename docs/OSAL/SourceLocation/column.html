Module Index / OSAL / SourceLocation / column

column

member of hbe::SourceLocation Engine/OSAL/SourceLocation.h the captured column; always zero on GCC

Signature

[[nodiscard]] constexpr std::uint_least32_t column() const noexcept

Function description

The captured column offset. The value is whatever CallerColumn() answered at the capture site, and it is the one field with a real platform split, because the macro itself has one: Engine/OSAL/Intrinsic.h defines CallerColumn() as __builtin_COLUMN() on Clang and MSVC, but as the literal 0 on GCC — __builtin_COLUMN does not exist there. A location captured on a GCC build therefore always reports column 0, and nothing is wrong when it does.

Because of that split, a consumer should treat the column as best-effort detail and never as a coordinate it depends on. The lock-timeout log in Engine/Core/ScopedLock.h prints it between the line and the function name, where a zero reads as a missing detail rather than a wrong one.

Parameters

None.

Return value

The column of the capture site on Clang and MSVC; 0 on every GCC build, and for a default-constructed location on any platform.

Examples

The only in-tree consumer prints it as the third coordinate of the location: 

			ls << "[file: " << srcLoc.file_name() << '(' << srcLoc.line() << ':' << srcLoc.column() << ") "
