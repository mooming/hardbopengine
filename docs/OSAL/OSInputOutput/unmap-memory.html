UnmapMemory

member of hbe::OSInputOutput Engine/OSAL/OSInputOutput.h namespace OS release a mapping — but true even when the unmap failed

Signature

bool UnmapMemory(void* ptr, size_t size) noexcept

Function description

Releases a mapping made by MapMemory: munmap(ptr, size) on the POSIX units (Engine/OSAL/LinuxInputOutput.cpp, Engine/OSAL/OSXInputOutput.cpp). After the call the address range is no longer valid to read or write — the pages the mapping held are gone from the address space, and any pointer into them is dangling.

Like MapSync, the bool overstates success. A null pointer answers false with a warning, but a failed munmap is only logged at error level, and the function still answers true. The range size must match what was mapped.

Parameters

ParameterTypeRequirement
ptrvoid*Base of the mapping, as MapMemory returned it; null answers false with a warning.
sizesize_tThe length that was mapped; it must match for the whole mapping to be released.

Return value

false only for a null pointer; true otherwise — including when the munmap call itself failed and logged.

Examples

The buffer releaser unmaps after syncing — the pair is the whole teardown of a file-backed Buffer: 

		MapSync(ptr, size, syncMode);
		UnmapMemory((void*) data, size);

		OS::Close(std::move(fh));
