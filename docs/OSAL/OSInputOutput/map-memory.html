MapMemory

member of hbe::OSInputOutput Engine/OSAL/OSInputOutput.h namespace OS map a file range into the address space

Signature

void* MapMemory(FileHandle& fileHandle, size_t size, ProtectionMode protection, size_t offset) noexcept

Function description

Maps size bytes of the file, starting at byte offset, into the address space: mmap(nullptr, size, protection.value, MAP_SHARED, fd, offset) on the POSIX units (Engine/OSAL/LinuxInputOutput.cpp, Engine/OSAL/OSXInputOutput.cpp). The protection word from ProtectionMode is passed verbatim; MAP_SHARED is fixed, which is what lets writes through the mapping reach the file — and what makes MapSync meaningful.

Two guard paths answer nullptr with a warning: an invalid handle and a zero size. A failed mmap answers nullptr after an error-level log that prints the handle, size, protection word and offset. This is how a large resource is read without a staging buffer — the engine's file-backed Buffer machinery lives on it.

Parameters

ParameterTypeRequirement
fileHandleFileHandle&An open handle to the file; taken by non-const reference though the implementations only read the descriptor.
sizesize_tBytes to map; zero answers nullptr with a warning. The file must be at least offset + size bytes for the mapping to be readable.
protectionProtectionModeThe protection word for the mapping; see ProtectionMode.
offsetsize_tByte offset into the file; POSIX requires it to be a multiple of the page size.

Return value

The base address of the mapping; nullptr for the guard paths and after a failed mmap (logged at error level). Release it with UnmapMemory.

Examples

The map-modify-sync cycle from the OSAL's own IO test: 

			ProtectionMode protection;
			protection.SetReadable();
			protection.SetWritable();

			auto ptr = MapMemory(fh, TestSize, protection, 0);
			if (ptr == nullptr)
			{
				Close(std::move(fh));
				Delete(path);
				...
				return;
			}
