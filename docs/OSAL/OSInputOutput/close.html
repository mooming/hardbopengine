Close

member of hbe::OSInputOutput Engine/OSAL/OSInputOutput.h namespace OS close by rvalue reference — the handle is invalid afterwards

Signature

bool Close(FileHandle&& handle) noexcept

Function description

Closes a file and takes the handle by rvalue reference — the signature is the safety argument. A caller must write Close(std::move(fh)), and after the call the handle is invalid: the implementations move it in, read the descriptor out, and invalidate the handle before touching the descriptor, so a handle cannot be closed twice and a closed handle cannot be passed to Read or Write by accident. 

	auto handle = std::move(inHandle);

	int fd = handle.fd;
	handle.Invalidate();

	if (unlikely(fd < 0))
	{
		log.OutWarning([fd](auto& ls) { ls << "File Close (fd:" << fd << ") failed."; });

		return false;
	}

	auto result = close(fd);
	if (unlikely(result < 0))
	{
		...
		return false;
	}

	return true;

From Engine/OSAL/LinuxInputOutput.cpp, OS::Close(FileHandle&&) — the failure log elided

Two failure paths, both a logged warning and false: closing an already-invalid handle, and a platform close that failed. In the second case the handle is already invalid — the descriptor, if it is still open, is no longer reachable through any handle. The macOS unit does the same work through its FileHandleHelper reinterpret helpers (Engine/OSAL/OSXInputOutput.cpp).

Parameters

ParameterTypeRequirement
handleFileHandle&&The handle to close — moved from, and invalid after the call whether the close succeeded or not.

Return value

true when the descriptor was closed; false — after a logged warning — for an invalid handle or a failed platform close.
