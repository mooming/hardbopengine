PerfBenchmark

Engine/Test/PerfHarness.h namespace hbe::Test final one benchmark cell: arms, rounds, a claim, a colour

Class description

A benchmark cell: one shape of queue traffic, every implementation of it, measured alternately so that machine drift cannot favour one implementation. A cell is not a test. Its numbers and its colour are information for a reader, and the suite’s pass count does not move whatever they say — see EPerfGrade for what each colour claims and the design document for why a performance suite that fails is worse than one that reports.

The one exception is a broken invariant. A measure function returns the count of items it lost, duplicated or read corrupted, and a winner with any such item grades REJECTED: a ratio measured on a queue that dropped work is not a slow design, it is a measurement of nothing.

The unit of a measurement is a round. In one round every arm is measured exactly once, in an order that rotates, and each measure function builds its queue from scratch and destroys it afterwards. Rotation is the whole defence against drift: with arms in a fixed order the arm measured first each round wins a thermal and cache headwind that has nothing to do with its design.

Coverage

Every member of PerfBenchmark is documented on this page or its own. Two things live in the source rather than here and are named so that the omission is not silent: the tenths-of-a-nanosecond conversion Tenths, which is a file-local arithmetic step rather than an API, and the arm table’s column widths, which are formatting constants rather than behaviour. The hb-standards:ignore marker on PerfArm is the member-layout waiver recorded in the design document: the struct declares tenths[MaxRounds], so it cannot be declared before the constant it sizes.
