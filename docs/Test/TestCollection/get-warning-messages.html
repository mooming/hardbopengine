GetWarningMessages

member of hbe::TestCollection Engine/Test/TestCollection.h const noexcept the lines this collection's last run ended with lfwarn — none of which failed anything

Signature

[[nodiscard]] const std::vector<std::string>& GetWarningMessages() const noexcept;

Function description

Returns warningMessages by reference. That vector is appended to from inside the log callback of the streaming operator, once for each message that ended in lfwarn, while the case that produced it is still running. An empty vector means the run emitted no warning — it never means the collection was skipped, so this is not a "did anything happen" probe.

Each entry is the message as the case wrote it, with the framework's case attribution in front: [TC<index>.<test name>] <text>. It is not the logger's line — there is no timestamp, no category and no severity word in it, because those are added later when the logger drains the entry. That makes these vectors the readable record of a run without console decoration, which is exactly why TestEnv re-prefixes them with the collection name and prints them as a block after all collections finish.

Start clears this vector before Prepare runs, so what comes back always belongs to the last run of this collection and not to all of them.

Warnings are collected on a passing run too. The severity affects only which buffer the line lands in; IsSuccess is computed from the error buffer alone. So the engine's summary can print a warnings block under a suite that passed, and TestEnv::ExecuteTest folds these lines in whichever branch the collection took.

Parameters

None.

Return value

TypeWhat you get
const std::vector<std::string>& One string per lfwarn message, in emission order, referencing the collection's own buffer — valid until the next Start clears it or the collection is destroyed. Copy it if you intend to hold it across a re-run

Examples

The only consumer in the engine is the environment, which prefixes each line with the collection's name and keeps it for the final report:

From Engine/Test/TestEnv.cpp

        auto& warnMessages = testCollection.GetWarningMessages();
        for (auto& msg : warnMessages)
        {
                ss << '[' << testCollection.GetName() << "] " << msg;
                warningMessages.push_back(ss.str());
                ss.str("");
        }

On the producing side, a warning is an observation worth surfacing without a verdict attached. In the engine that is almost always a measurement that came in worse than expected: the usual shape is a rate compared against system allocator, warned rather than failed because the result is still correct.

From Engine/Memory/InlinePoolAllocator.cpp

        AddTest("Perf. & Stress, Size(1)", [&, this](auto& ls)
        {
                constexpr int inlineSize = 64;
                InlinePoolAllocator<int, inlineSize, NumBlocks> inlineAlloc;

                auto rate = AllocDeallocTestFunc(inlineAlloc, ls, lf, 1);
                if (rate > 1.0f)
                {
                        ls << "Performance is worse than system malloc. rate = " << rate << lfwarn;
                }
        });

Two things are visible in those eight lines. The capture list is [&, this] — this is what makes lfwarn nameable, and & what makes NumBlocks from the enclosing Prepare visible. And a guard is an ordinary object, so it can be passed into a helper as AllocDeallocTestFunc(inlineAlloc, ls, lf, 1) does with lf: a helper that takes the stream and a guard can report at the severity its caller chose.
