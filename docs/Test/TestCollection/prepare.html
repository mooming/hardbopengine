Module Index / Test / TestCollection / Prepare

Prepare

member of hbe::TestCollection Engine/Test/TestCollection.h protected pure virtual the one member a subclass has to write: register this collection's cases

Signature

protected:
        virtual void Prepare() = 0;

Function description

Prepare is the entire subclass contract. It is called exactly once per Start, after the previous run's state has been cleared and before any case executes, and its only job is to call AddTest once per case with a display name and a body. It is never called by a subclass and never by a caller — a collection with no override does not compile, which is what = 0 buys.

Because it is protected, the only thing outside the class hierarchy that can reach it is the base class itself. That protection is the design talking: registering cases from outside would let a caller add a case to a collection it does not own, and would separate the case list from the code under test.

It runs on the same thread as Start, and any allocation it makes itself — as opposed to the allocations the cases make, which get a per-case AllocatorScope — falls into whichever scope is open at that point. In the engine's suite that is the scope RunTests opens for the whole run.

Registration order is execution order, and it is also the numbering. Case i is the i-th AddTest call, and the number in the TC<i>.<name> prefix of every message is that index. Reordering the calls in Prepare therefore renumbers the output; a case that depends on another case having run first is depending on the order of two adjacent lines of code, with nothing in the framework enforcing it.

Parameters

None.

Return value

void. A subclass cannot decline to run — there is no status to return and no exception to throw. To skip a collection's cases, the convention is a Prepare that registers none, which leaves the collection succeeding over zero cases.

Examples

The smallest complete override in the engine declares itself in the header beside the class it tests:

From Engine/Container/Array.h

#ifdef __UNIT_TEST__
class ArrayTest : public TestCollection
{
public:
        ArrayTest()
                : TestCollection("ArrayTest")
        {
        }

protected:
        void Prepare() override;
};
#endif // __UNIT_TEST__

and is defined in the paired source, where each case is one AddTest call:

From Engine/Container/Array.cpp

        void ArrayTest::Prepare()
        {
                AddTest("Default Constructor", [this](auto& ls)
                {
                        const Array<int> array;
                        if (array.Size() != 0)
                        {
                                ls << "Null Array Size is not zero. Size = " << array.Size() << lferr;
                        }
                });

                AddTest("Initializer List", [this](auto& ls)
                {
                        // …
                });
        }

Two details in those nine lines are load-bearing. The lambda captures this — without the capture it cannot name lferr, and so cannot fail. And the case is registered in Prepare, not in the constructor above it, for the reason given on the Start page.
