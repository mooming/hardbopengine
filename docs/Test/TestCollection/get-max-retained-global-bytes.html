GetMaxRetainedGlobalBytes

member of hbe::TestCollection Engine/Test/TestCollection.h const noexcept the largest amount of global heap any one of this collection's testlets still held at the end of its body

Signature

[[nodiscard]] std::size_t GetMaxRetainedGlobalBytes() const noexcept;

Function description

Retention for one testlet is the bytes it requested through the global allocation entry points minus the bytes it released during the same window; this getter reports the maximum over the testlets this collection ran. It is the quantity MaxRetainedGlobalBytes is compared against, so a reader who wants to know how close a collection is to its ceiling can ask for this without reading a log.

It is a maximum, not a total: two testlets each holding 4 KiB report 4 KiB, because the guard is per testlet. That is deliberate and matches what a breach means - one test being heavy, not the collection being sum-of-parts heavy.

Which way it is wrong

Over-retention, never under: a release that arrives through the unsized operator delete reports the block size the system heap chose, which can exceed the size originally asked for, so the released total can slightly outrun the requested total. The difference is clamped at zero rather than allowed to go negative, which is why the arithmetic reads as a ternary instead of a subtraction. A testlet whose releases are all unsized - most of them, in practice - will therefore look as if it retained a little more than it really did, and that direction is the safe one for a ceiling.

Return value

Zero before any testlet has run, or for a collection whose testlets free everything they take. Measured over the whole suite, the largest figure any collection reports is 33,200 bytes.
