Lifecycle changed on 2026-09-28. The one-call run this page describes is gone. A test is now a Testlet and the unit the harness schedules, so TestCollection::Start became PrepareTests / RunTestAt / Complete, TestEnv::Start became PrepareTestlets / RunTestlet / Finalize, and hbe::Test::RunTests became RegisterSuite and ScheduleSuiteOnBaseStream. The statements below that name the old lifecycle are history, not reference; the replacements are documented: PrepareTests / RunTestAt / Complete on TestCollection and PrepareTestlets / RunTestlet / Finalize on TestEnv.

Complete

member of hbe::TestCollection Engine/Test/TestCollection.h closes the collection decides the verdict from what its testlets accumulated and reports it

Signature

void Complete();

Function description

The third phase. It sets isSuccess to whether the error buffer is empty, marks the collection done, and calls Report, which writes the verdict under the collection's own log category. It reads nothing new - every fact it uses was left behind by RunTestAt - so the order of the three phases is the whole protocol: prepare, run each testlet once, complete.

Who calls it, and when

TestEnv::RunTestlet calls it when the testlet it just ran was the last of this collection. Collections therefore finalise in registration order, not in whichever order their testlets happened to execute, because a collection's verdict needs all of its testlets and its testlets are contiguous in the flattened schedule.

What the verdict is used for

ResultEffect at the environment
Done and successful Counts toward the pass total; its warnings are carried into the suite's warning list.
Done and failed Named in the failure list with [FAIL], and both its warning and error buffers are copied into the suite's, prefixed with the collection name.
Not done The collection never completed - it lands in the invalid list. This is the branch that catches a suite shortened by a broken schedule: a collection whose testlets never all ran is not a passing collection.
