constructors

member of hbe::TestCollection Engine/Test/TestCollection.h 1 overload explicit name the collection — the name is also the log category every message is filed under

Signature

explicit TestCollection(const char* title);

Function description

One constructor, and it does two things with its single argument. The title is copied into the member title, which is what GetName returns and what the run's banner and verdict lines are labelled with. It is also handed to all three guards as their log category, so every message the collection's cases emit is filed under this name and can be filtered as one group.

Beyond that, the constructor only establishes initial state: isDone and isSuccess false, the guard buffers empty, each guard's testIndex at 0 and its testName at "None" until Start starts rewriting them per case. No test is registered and nothing runs, which is why a subclass's constructor body is empty in every example in the engine.

There is no default constructor, so a collection cannot exist unnamed, and no constructor takes the case list — cases arrive through Prepare and AddTest instead.

Two of the guards keep the pointer you pass, not a copy. The member title is a std::string built from title, but each LogFlush stores the argument itself as a const char* and the streaming operator uses it on every message. So the string has to outlive the collection, not merely outlive the constructor call — a name in a local buffer, or a .c_str() from a temporary std::string, leaves the guards reading freed memory while GetName goes on answering correctly. Both titling idioms in the engine happen to satisfy this: most subclasses pass their own name as a string literal, and four — BufferTest, BufferInputStreamTest, HUnorderedMapTest and OSInputOutputTest — pass StringUtil::ToCompactClassName(__PRETTY_FUNCTION__), whose StaticString converts to a pointer into the interning string table rather than into the temporary it was called on.
A null title is undefined behaviour before the body runs. The member initialiser constructs std::string from the argument, and that is undefined for a null pointer — there is no null check on this path, unlike the ones in AddTest. Unlike AddTest's null-name case, nothing here quietly substitutes "None".

Parameters

ParameterTypeRequirement
title const char* Non-null, null-terminated, and alive for the collection's whole lifetime. In the engine this is always the subclass's own name — ArrayTest passes "ArrayTest", BufferTest derives its own from __PRETTY_FUNCTION__ — because it doubles as the logger category, and a test whose category differs from the code it tests cannot be filtered with the rest of them

Return value

No return value, and no failure to report: this constructor cannot decline. It allocates nothing beyond the std::string copy, and that copy uses the default allocator in whichever AllocatorScope is open — the collection's own memory is therefore not attributed to the per-case scope that Start opens for the cases.

Examples

Every subclass in the engine calls this from its own initialiser list, with its own name:

From Engine/Container/Array.h

class ArrayTest : public TestCollection
{
public:
        ArrayTest()
                : TestCollection("ArrayTest")
        {
        }

protected:
        void Prepare() override;
};

The empty body is the correct shape: registering cases there would be undone by the next Start, and constructing anything else there would be attributed to no case. See Prepare for where the cases belong.
