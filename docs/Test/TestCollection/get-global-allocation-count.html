GetGlobalAllocationCount

member of hbe::TestCollection Engine/Test/TestCollection.h const noexcept what this collection's testlet bodies took through the global allocation entry points

Signature

[[nodiscard]] std::uint64_t GetGlobalAllocationCount() const noexcept;
[[nodiscard]] std::size_t   GetGlobalAllocationBytes() const noexcept;
[[nodiscard]] std::size_t   GetTestletCountWithGlobalAllocations() const noexcept;

The three are one read-out and are documented together, because each on its own is a field return and the interesting fact is how they differ. Splitting a page per line of code would produce three pages that say nothing and hide the one thing worth reading, which is the difference between requests, bytes and how many testlets were involved.

What each one counts

GetterCountsWhat a reader should take from it
GetGlobalAllocationCount Requests this collection's testlet bodies sent to operator new. Churn. A testlet doing this thousands of times is doing something a test usually should not, whatever it holds at the end.
GetGlobalAllocationBytes Bytes those requests asked for, cumulative. Not memory used. Freeing does not reduce it, so a stress loop reaches hundreds of megabytes while retaining almost nothing. For the held figure see GetMaxRetainedGlobalBytes.
GetTestletCountWithGlobalAllocations How many of this collection's testlets reached the global heap at all. The honest scale of the problem. Measured across the suite this is 320 of 372 testlets in Debug and 282 in Release, which is why a refusal rule needed a decided ceiling rather than an exception list.

When the figures mean anything

All three read zero before the testlets have run, and they are cumulative over the testlets of this collection only - the fixture that prepares a testlet and everything the process allocated earlier are outside them. The measurement window is the testlet body: snapshots are taken after the collection's MultiPoolAllocator and AllocatorScope have been constructed and immediately around the call into the testlet itself.

Return value

The counters described above. No allocation, no formatting, no side effect; safe to call from a report path while another testlet is mid-run, though the numbers are then a snapshot of a moving total.
