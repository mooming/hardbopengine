AddTest

member of hbe::TestCollection Engine/Test/TestCollection.h public register one test case: a display name and a body that takes the log stream

Signature

template <size_t TNameBytes, typename TClosure>
void AddTest(const char (&testName)[TNameBytes],
                  TClosure&& testCase)

A second form declares the testlet's memory allowance beside it instead of taking the suite default. Everything else about the call is unchanged: 

template <size_t TNameLength, typename TClosure>
void AddTest(const char (&testName)[TNameLength], std::size_t maxRetainedGlobalBytes,
              TClosure&& testCase)

Function description

Registers one test. The name and the body are copied into a Testlet, which owns both inline, and the suite runs them in registration order.

Two constraints follow from that ownership, and both bite at compile time rather than at runtime. The name is a char-array parameter, so only a literal compiles: that gives the testlet storage it may own outright, gives the per-test allocator the null terminator it needs as a property of the type rather than as a hope, and refuses a computed name here instead of dangling later. And the closure is a template parameter, so it arrives with its real type — which is what lets Testlet size-check the capture and keep allocation off the registration path entirely.

Every real body in the engine is a lambda capturing this — measured, 0 of 379 are non-capturing — because lf, lfwarn and lferr are members, and a non-capturing lambda cannot name lferr and therefore cannot fail.

A null body is rejected rather than stored: it is reported at error severity through the collection's logger, which is only reachable in the if constexpr branch where the argument really is a pointer — a closure has no null state to test.

The overload that takes an allowance exists for reviewability rather than convenience. Retention is measured per testlet against MaxRetainedGlobalBytes, and a breach fails the run naming the testlet - so the way a heavy test gets past the ceiling should be visible in the diff that grants it. An argument at the registration site is; an edit to the shared constant is not, and it relaxes every other testlet at the same time. Nothing passes the argument today, so the first call site that does will be the only precedent there is.

Parameters

ParameterTypeRequirement
testName const char (&)[TNameLength] A string literal - the type admits nothing else, which is the point: the array has static storage so the Testlet may hold a view of it, and it is null terminated, which the log line and the per-testlet allocator both need. A computed name fails to compile here instead of dangling later. Longer than Testlet::MaxNameBytes (128) is refused at the site that registered it, never truncated.
maxRetainedGlobalBytes std::size_t Only in the second form: how much global heap this testlet may still be holding when its body ends. The single-argument form passes MaxRetainedGlobalBytes, so the exception to the ceiling is an argument beside the test that needs it rather than an edit to a shared constant that quietly relaxes all 372 testlets. Pass it when the test genuinely retains - a cache it warms, a buffer it intentionally keeps - and state the reason at the site, because the number alone is not an argument.
testCase TClosure&& — deduced, not type-erased Must not be null. Must not throw: the engine is exception-free, and this call sits on the path out of TaskSystem. Capture this if the body needs the guards — a non-capturing lambda cannot name lferr, and therefore cannot fail

Return value

void. Whether the case was stored is not reported to the caller; a rejected null body is visible only in the log. If a caller needs to know how many cases a collection registered, there is no accessor for tests — see GetName for the only public read of the collection's identity.

Examples

A case that both reports what it measured and fails if the measurement moved. Note that a single case may emit several messages, each one terminated by the guard whose severity it deserves:

From Engine/Core/ResultPacket.cpp

        AddTest("One packet prices a task and a record at the figures that were decided", [this](auto& ls)
        {
                constexpr std::size_t decidedPacketBytes = 128;

                const auto tableBytes = TaskRegistry::DefaultInitialCapacityRecords * TaskRegistry::RecordSizeBytes;

                ls << "Packet " << sizeof(ResultPacket) << " bytes, task " << sizeof(Task) << " bytes … and the default table is "
                   << tableBytes / 1024 << " KiB." << lf;

                if (sizeof(ResultPacket) != decidedPacketBytes)
                {
                        ls << "A result packet is " << sizeof(ResultPacket) << " bytes, not " << decidedPacketBytes
                           << ". The task is not a handle to a buffer any more, so this width is the cost of the design "
                           << "rather than an implementation detail." << lferr;
                }
        });

The same collection's guard objects are also what make a failing precondition usable: write the guard and return, so one broken setup produces one clear message instead of a cascade of derived ones.

        auto* firstTask = registry.Find(firstID);

Example: a testlet that keeps memory on purpose

        // Warms a lookup table the whole collection reads afterwards, so the retention is
        // the point of the test rather than a leak. Declared here, next to the reason.
        AddTest("The cache keeps its warmed table between testlets",
                256 * 1024,
                [this](auto& ls) {
                        Cache& cache = BuildCache(ls);
                        Assert(cache.GetEntryCount() == ExpectedEntries);
                });

The log then says so on every line that testlet produces - …, retained 98304 bytes, freed 4120 bytes outside the allocator scope, against a declared ceiling of 262144 # - which is what keeps an exception legible in a log excerpt when nobody is looking at the source that registered it.
