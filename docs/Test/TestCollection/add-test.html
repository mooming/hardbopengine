AddTest

member of hbe::TestCollection Engine/Test/TestCollection.h public register one test case: a display name and a body that takes the log stream

Signature

void AddTest(const char* testName, const TTestFunc& testCase);

Function description

Appends the pair (testName, testCase) to tests, which Start then runs in that order. The body is stored as a TTestFunc — a std::function — so any callable with the right signature works, and in the engine they are all lambdas capturing this so the body can reach lf, lfwarn and lferr.

A null body is rejected rather than stored: it is reported at error severity through the collection's logger category and the call returns without registering anything. A null testName is tolerated and stored as "None".

A rejected null body does not fail the collection. That rejection is written straight to the logger, not through the error guard, so errorMessages does not grow and IsSuccess is unaffected by it. It also happens during Prepare, before the first case runs, so nothing afterwards re-examines it. A collection whose cases were all rejected by a bad function pointer reports [SUCCESS] with zero cases run.
Public, though it belongs in Prepare. Nothing stops a caller from calling AddTest on a collection from outside — except that the next Start clears tests before it calls Prepare, so cases registered from outside are erased before they can run. Register in Prepare or not at all.

Parameters

ParameterTypeRequirement
testName const char* A short description of the case — the engine's convention is a sentence stating the invariant, not the function under test. Copied into a std::string, so it need not outlive the call. nullptr is accepted and becomes "None"
testCase const TTestFunc& (std::function<void(TLogOut&)>) Must not be null. Must not throw: the engine is exception-free, and this call sits on the path out of TaskSystem. Capture this if the body needs the guards — a non-capturing lambda cannot name lferr, and therefore cannot fail

Return value

void. Whether the case was stored is not reported to the caller; a rejected null body is visible only in the log. If a caller needs to know how many cases a collection registered, there is no accessor for tests — see GetName for the only public read of the collection's identity.

Examples

A case that both reports what it measured and fails if the measurement moved. Note that a single case may emit several messages, each one terminated by the guard whose severity it deserves:

From Engine/Core/ResultPacket.cpp

        AddTest("One packet prices a task and a record at the figures that were decided", [this](auto& ls)
        {
                constexpr std::size_t decidedPacketBytes = 128;

                const auto tableBytes = TaskRegistry::DefaultInitialCapacityRecords * TaskRegistry::RecordSizeBytes;

                ls << "Packet " << sizeof(ResultPacket) << " bytes, task " << sizeof(Task) << " bytes … and the default table is "
                   << tableBytes / 1024 << " KiB." << lf;

                if (sizeof(ResultPacket) != decidedPacketBytes)
                {
                        ls << "A result packet is " << sizeof(ResultPacket) << " bytes, not " << decidedPacketBytes
                           << ". The task is not a handle to a buffer any more, so this width is the cost of the design "
                           << "rather than an implementation detail." << lferr;
                }
        });

The same collection's guard objects are also what make a failing precondition usable: write the guard and return, so one broken setup produces one clear message instead of a cascade of derived ones.
