Lifecycle changed on 2026-09-28. The one-call run this page describes is gone. A test is now a Testlet and the unit the harness schedules, so TestCollection::Start became PrepareTests / RunTestAt / Complete, TestEnv::Start became PrepareTestlets / RunTestlet / Finalize, and hbe::Test::RunTests became RegisterSuite and ScheduleSuiteOnBaseStream. The statements below that name the old lifecycle are history, not reference; the replacements are documented: PrepareTests / RunTestAt / Complete on TestCollection and PrepareTestlets / RunTestlet / Finalize on TestEnv.

PrepareTests

member of hbe::TestCollection Engine/Test/TestCollection.h replaces Start (2026-09-28) registers this collection's testlets without running any of them

Signature

void PrepareTests();

Function description

Resets the collection, then calls the subclass's Prepare - the one overridden function in the class - which registers the testlets with AddTest. Nothing runs. It clears tests, the warning buffer and the error buffer first, so a collection prepared twice holds exactly what its Prepare put there the second time and no verdict carried over from an earlier pass.

This replaced Start(), which registered and ran in one call. The split exists because the suite is now scheduled as tasks: the harness needs the total number of testlets before the first one executes, so registration had to stop being a side effect of execution. See suite entry points for the posting side.

Contract

PropertyGuarantee
Ordering Called for every collection before anything is posted to a stream. A collection prepared after posting would change the total the harness is holding against, which is why TestEnv::PrepareTestlets does the whole set in one pass.
What Prepare may assume Nothing about state produced by a testlet - none has run. It registers lambdas, and that is what makes running it ahead of execution safe. Any cost it does pay is attributed to the harness, not to a testlet, because the measurement windows around a body have not started yet.
Repeat calls Safe and idempotent in effect: buffers are cleared on entry. It is not free - each call re-registers every closure - so the harness calls it once per run.
Thread Runs on whichever thread called PrepareTestlets. It touches only this collection's own state.

What it prints

One line under the collection's own log category: = START ========================================. That is the only output preparation produces; the per-testlet lines belong to RunTestAt.

Example: the override that owns it

class MyTest final : public TestCollection
{
public:
        MyTest() : TestCollection("MyTest") {}

        // Called by PrepareTests, not by the testlets. Registering here is what lets the
        // harness know the suite's size before its first task is posted.
        void Prepare() override
        {
                AddTest("A packet prices its own result", [this](auto& ls) {
                        Assert(PricePacket() == Expected);
                });
        }
};
