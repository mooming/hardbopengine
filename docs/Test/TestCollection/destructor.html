~TestCollection

member of hbe::TestCollection Engine/Test/TestCollection.h virtual = default discard the run: the results live on the collection and die with it

Signature

virtual ~TestCollection() = default;

Function description

Defaulted, and virtual only because ownership is polymorphic: TestEnv::AddTestCollection stores each collection as std::unique_ptr<TestCollection>, so the destructor that must run is found through the base class. Without virtual, deleting a subclass through that pointer is undefined and the subclass's own members leak.

What it releases is exactly what the members hold: the registered case list with its type-erased callables, the collected warning and error lines, and the title. The three guards need nothing — their messageBuffer pointers point into this same object and are never dereferenced on the way out.

What it does not do is the useful half of the description. It does not flush anything to the log, does not report the run if nobody asked, and does not complain that the collection was destroyed before Start was called on it. A collection constructed and destroyed without being run leaves no trace at all — the tally counts only what TestEnv::Start walked.

A log line is formatted synchronously, so nothing writes into these vectors after the object is gone — provided nothing else is logging at the moment it dies. Logger::AddLog invokes the message callback before it returns, which is why an lferr is counted against the case that emitted it rather than against whatever stream the logger happened to drain later. A background task still running when its collection is destroyed is the exception: it holds a reference into freed memory, not a queued message.

Parameters

None.

Return value

void — destructors have none. The results are unreadable afterwards, which is the only "return value" that matters here: IsSuccess and GetErrorMessages have to be read before the collection goes, which is precisely what TestEnv::ExecuteTest does between calling Start and printing the tally.

Examples

No engine code destroys a collection explicitly. The registered suite owns them through the environment, and they are destroyed when the TestEnv singleton is — that is, at static destruction, after main has already read the tallies:

From Engine/Test/TestEnv.cpp

TestEnv& TestEnv::GetEnv()
{
        static TestEnv instance;
        return instance;
}

From Engine/Test/TestEnv.h

        using TCPtr = std::unique_ptr<TestCollection>;

        std::vector<TCPtr> tests;

Because this destructor is virtual, the sixty-odd subclasses registered by RunTests are each destroyed through their own type by that one std::vector<TCPtr>.
