Start

member of hbe::TestCollection Engine/Test/TestCollection.h test build only run the whole collection — prepare, execute every case in order, decide pass or fail

Signature

void Start();

Function description

One call performs a complete run of the collection, in this order:

  1. isDone and isSuccess are set false and tests, warningMessages and errorMessages are emptied — so a previous run leaves nothing behind, and the state mid-run is indistinguishable from the state before a first run.
  2. A line = START ======================================== is written to the logger category named by the collection's title.
  3. Prepare() is called — the virtual dispatch into the subclass, which is where the cases get registered.
  4. The cases run in registration order. Each one gets the current index and name written into all three guards, is wrapped in a AllocatorScope over a fresh MultiPoolAllocator named after the case, and is then invoked with the collection's shared log stream. Whether it passed is decided by whether errorMessages gained an entry during it.
  5. isSuccess is assigned errorMessages.empty() and isDone true.
  6. The collection's verdict line is printed — [SUCCESS] at info severity, [FAIL] at error severity.

Nothing about that sequence is configurable, and nothing in it throws: the engine is exception-free, so the only control flow a test case has is return. A case that returns early without writing an error passes.

Register cases in Prepare, never in the constructor. Step 1 clears tests, and Prepare is called after that. A subclass that calls AddTest from its constructor registers cases that are thrown away before the first case runs, and the collection then reports success over zero cases — errorMessages is empty, so IsSuccess is true.
Public, and reentrant in the ordinary sense. A caller may call Start directly on a stack object without TestEnv at all; the run happens and the verdict sits on the object, but no tally counts it. Calling it a second time re-runs cleanly, because step 1 clears everything. What it is not is safe to call concurrently with itself: the shared log stream, the mutable guards and the three result vectors are plain unsynchronised members.

Parameters

None.

Return value

void. The outcome is on the object afterwards: IsDone, IsSuccess, GetErrorMessages and GetWarningMessages. Start only returns once every case has completed — there is nothing to wait on and no status to poll.

Examples

The framework's only call site — the environment runs each registered collection through this one call:

From Engine/Test/TestEnv.cpp

bool TestEnv::ExecuteTest(TestCollection& testCollection)
{
        testCollection.Start();

        if (!testCollection.IsDone())
        {
                invalidTests.push_back(testCollection.GetName());
        }
        // … else fold its messages into the environment's totals …
}

Note what the IsDone test can and cannot catch. Start sets isDone = true on the path out of a completed run, so the only way to land in invalidTests is for the call never to return — which in this engine means an assert firing, not an exception being thrown.

The other side of the same call — a collection run on its own, with its verdict read straight off it:

Illustrative — no call site for this exists in the repository; every engine run goes through TestEnv::Start.

MyTests tests("MyTests");
tests.Start();

if (!tests.IsSuccess())
{
        for (auto& message : tests.GetErrorMessages())
        {
                std::cerr << message << '\n';
        }
}
