GetName

member of hbe::TestCollection Engine/Test/TestCollection.h const noexcept the collection's title — which is also the log category its cases report under

Signature

[[nodiscard]] const char* GetName() const noexcept;

Function description

Returns title.c_str(), the copy of the name given to the constructor. A field read: no allocation, no formatting, nothing that can fail.

Nothing in the class writes title after construction, so the pointer is stable for the object's lifetime and may be kept. It is never null for a collection that finished constructing — an empty title yields an empty string, not a null pointer, and a null argument never reaches this state.

Inside the class this is how the framework labels its own output: Start opens its log with Logger::Get(GetName()), Report prints the verdict through the same category, and TestEnv::ExecuteTest uses it for the failed-list and invalid-list entries and for the [CollectionName] prefix on every collected message. It is the join key between one collection's output and the environment's summary, not merely a display string.

Parameters

None.

Return value

TypeWhat you get
const char* The title, valid until the collection is destroyed — and since nothing mutates it, that is a stable pointer rather than a borrowed one. [[nodiscard]], so calling it for effect is a compile error; there is no effect to call it for

Examples

The framework's own uses — collecting a failed collection's name, and prefixing its warnings:

From Engine/Test/TestEnv.cpp

        if (!testCollection.IsDone())
        {
                invalidTests.push_back(testCollection.GetName());
        }

        // … and later, for a collection that ran and failed:
        ss << testCollection.GetName() << " : [FAIL]";
        failedTests.push_back(ss.str());

Outside the framework, the name is also the way to address one collection's log output while it runs: it is the logger category the guards were built from, so filtering on "ArrayTest" filters exactly that collection's lines and nothing else. Subclasses rarely call it — they already know their own name — and no test body in the engine does.
