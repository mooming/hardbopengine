GetErrorMessages

member of hbe::TestCollection Engine/Test/TestCollection.h const noexcept the failure text — and the thing the pass-or-fail verdict is literally computed from

Signature

[[nodiscard]] const std::vector<std::string>& GetErrorMessages() const noexcept;

Function description

Returns errorMessages by reference. Every entry is one message that a test case ended with lferr, stored as [TC<index>.<test name>] <text> while the case was still running. This vector is not a report about the run; it is the run's evidence, and IsSuccess is exactly errorMessages.empty() evaluated after the last case.

Per-case attribution works by cursor: Start's loop records the size of this vector before a case, runs it, and compares again. Growth means that case failed. That is why one case cannot cancel another's failure, and why a case that emits three lferr messages contributes three entries and one failure.

Empty does not prove the cases passed; it proves no error message was recorded. Entries are appended from inside the logger's message callback, and Logger::AddLog returns without invoking a callback when logging is disabled, when the configured level is above the message's severity, or when a filter rejects the category. Under any of those, a genuinely failing case appends nothing and the collection reports success. Treat a suite that has never printed a single line for a collection as unverified rather than clean.
The text is the framework's, not the logger's. No timestamp, category or severity word is in these strings; the logger adds its own decoration when it drains the line, and TestEnv adds [CollectionName] in front of each one. So these vectors are the cleanest machine-readable record a run produces — and the only place the per-case TC<index> attribution survives after the console output scrolls past.

Parameters

None.

Return value

TypeWhat you get
const std::vector<std::string>& One entry per lferr message of the last run, in emission order, referencing the collection's own buffer. Cleared by the next Start, destroyed with the collection. It is the same vector lferr writes into, so a subclass holding a reference from here sees later cases append to it live

Examples

The environment keeps a failed collection's error text for the final report:

From Engine/Test/TestEnv.cpp

        auto& errMessages = testCollection.GetErrorMessages();
        for (auto& msg : errMessages)
        {
                ss << '[' << testCollection.GetName() << "]" << msg;
                errorMessages.push_back(ss.str());
                ss.str("");
        }

Only reached on the failing branch — a passing collection has its warnings folded in and its errors, if any, never queried. Reading the errors directly off a collection is the way to see one collection's failures without the environment's summary at all:

Illustrative — no engine code reads a collection's errors outside TestEnv::ExecuteTest; every registered suite goes through the environment.

tests.Start();

for (const auto& failure : tests.GetErrorMessages())
{
        // each line already says which case said it: [TC3.Resize] …
        std::cerr << failure << '\n';
}
