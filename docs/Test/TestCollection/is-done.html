IsDone

member of hbe::TestCollection Engine/Test/TestCollection.h const noexcept did a run reach its end — the framework's only check that a collection actually finished

Signature

[[nodiscard]] bool IsDone() const noexcept;

Function description

Returns isDone. It is set false on entry to Start and true after the last case, immediately before the collection's verdict is printed. So there are three states and only one flag: a collection that has never run, one that is mid-run, and one whose Start never returned all read as false.

TestEnv::ExecuteTest is what reads it, and what it does with the answer defines the module's idea of an "invalid" test: a collection that is not done lands in invalidTests and is counted by GetFailureCount without contributing any message text.

In an engine that does not throw, false after Start means the process did not get that far. Nothing unwinds out of a test case — the engine is exception-free — so the practical routes to a collection that never completes are a fatal assert firing, a crash, or a case blocking forever on work that never arrives. All three end the run of the whole suite, not just that collection, so invalidTests is empty in every run that reaches the summary. It is a safety net for a case the framework cannot otherwise explain, not a state a green suite has quietly passed through.
IsDone() == false is not a failure and never was: it is an absence. Reading IsSuccess on a collection that has not been run answers false as well, but so does one that ran, registered no cases and passed all zero of them. The two are indistinguishable from outside the object — there is no accessor for the case count — so a collection that silently registered nothing looks exactly like a collection that passed.

Parameters

None.

Return value

TypeWhat you get
bool true only after a Start call returned normally; false before the first one, during a run, and after a run that did not complete. [[nodiscard]]

Examples

One consumer in the engine, and it is the framework's own:

From Engine/Test/TestEnv.cpp

bool TestEnv::ExecuteTest(TestCollection& testCollection)
{
        testCollection.Start();

        if (!testCollection.IsDone())
        {
                invalidTests.push_back(testCollection.GetName());
        }
        // …
        return testCollection.IsSuccess();
}

Note the shape: Start is synchronous, so this is not a poll — by the time IsDone is called the answer is already final, and the value of the check is diagnostic rather than scheduling. No test body in the engine calls IsDone; a case is by definition running, so it has nothing to ask.
