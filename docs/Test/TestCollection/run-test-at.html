Lifecycle changed on 2026-09-28. The one-call run this page describes is gone. A test is now a Testlet and the unit the harness schedules, so TestCollection::Start became PrepareTests / RunTestAt / Complete, TestEnv::Start became PrepareTestlets / RunTestlet / Finalize, and hbe::Test::RunTests became RegisterSuite and ScheduleSuiteOnBaseStream. The statements below that name the old lifecycle are history, not reference; the replacements are documented: PrepareTests / RunTestAt / Complete on TestCollection and PrepareTestlets / RunTestlet / Finalize on TestEnv.

RunTestAt

member of hbe::TestCollection Engine/Test/TestCollection.h replaces ExecuteTests (2026-09-28) runs exactly one testlet, with its log line, its allocator scope and its memory ceiling

Signature

bool RunTestAt(std::size_t testIndex);

Function description

One call, one testlet - and only one, because this is the unit the harness schedules as a task. It sets the test index and name on the log flush objects so messages raised inside the body are attributed to the right case, opens the case's log line, constructs a fresh MultiPoolAllocator named after the test under an AllocatorScope, runs the testlet, then reads what happened.

What it measures around the body

QuantityHowReported where
Pass or fail Whether the error buffer grew. That is the only verdict rule: no exception is expected anywhere, because the engine is exception-free. The case's Result [PASS] / [FAIL] line, and the collection's IsSuccess later.
Allocator usage The per-testlet pool prints its own usage after the body. The log. Measured across the current suite it reports nothing at all, because test bodies use std containers and those bypass the scope entirely.
Global heap traffic Deltas of the engine's global allocation counters across the body - requested, released, and the retained difference. A global heap … line, but only when the testlet actually reached the heap. See the read-out.
Memory ceiling Retention compared against the testlet's own allowance. An error naming the testlet, the retained bytes and the ceiling - see MaxRetainedGlobalBytes.

Parameters

ParameterTypeRequirement
testIndex std::size_t Index into this collection's testlets, zero based. The harness passes the flattened index minus the collection's offset - see TestEnv::RunTestlet, which does that conversion.

Return value

True when the testlet added no error message. Returns false without running anything when testIndex is past the registered count - a caller that ignores the return value treats "index past the end" as a passing testlet, which is why the harness checks the index itself and reports the shortfall by name.

Thread and re-entry

Runs on whatever worker took the testlet task. It mutates this collection's error and warning buffers, so two testlets of the same collection must not run concurrently - the schedule is a chain in which each testlet posts its successor, which holds that property without a lock.
