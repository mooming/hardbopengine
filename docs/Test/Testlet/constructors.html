Function description

Two constructors, and every other special member is deleted. The registering constructor is the only way a testlet comes into existence: it copies the name into the inline buffer, records the retention ceiling, and constructs the closure in place in the inline storage — which is why registering a test cannot allocate. The name parameter is a char array reference rather than a pointer or a view so that a literal is the only thing that can arrive: it has static storage, so the testlet may hold a view of it, and it is null terminated, which the logger and the per-testlet allocator both need. A computed name fails to compile here rather than dangling later.

Four static_asserts refuse what cannot be honoured: a name longer than MaxNameBytes, an empty name, a closure whose captured state does not fit TClosureBytes, and a closure over-aligned for the inline buffer. Each message says what to do instead — shrink the capture, or instantiate Testlet with more bytes where the testlets are held and say why. The closure constructor's noexcept is deliberately absent: constructing an arbitrary closure is the case the coding standard points at when it says not to promise exception freedom for something whose implementation this type cannot see.

The move constructor steals the dispatch pointer and the ceiling, copies the name, and relocates the closure through TestletDispatch::relocate — then nulls the source's dispatch, which is how a moved-from testlet knows to refuse Run. Copy and both assignments are deleted: the inline storage makes a copy a closure-copying problem the type chooses not to solve.
