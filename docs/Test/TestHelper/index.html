TestHelper

Engine/Test/TestHelper.h namespace hbe::TestHelper 2 functions test-build API the wait an engine test uses for work the base stream has not run yet, and the line it writes when that wait gives up

Class description

A namespace of free functions, not a class. It holds the wait a testlet uses for work the engine has not run yet, DriveUntil, and the failure line that wait writes, ReportDriveTimeout.

Both were cut out of TaskSystem, where they had been members. The reason is a count: the wait had fourteen callers, six in Engine/OSAL/Window.cpp and eight in Engine/Core/TaskSystem.cpp, and every one of them was a test body inside an __TEST__ region. Nothing in the engine called it. A member whose only callers are tests is an interface that misreports what the engine does, so the pair now names the system in its argument list instead of through this.

Nothing inside the loop was rewritten on the way out. The two branches, the guard that withdraws the nested-pump permission, the decision to pump TaskSystem::Update rather than TaskStream::Update, the 30 000 ms default, the counter decremented instead of a deadline re-read, and the wording of the failure line all crossed unchanged — the last one proved by comparing the concatenated string literal against the text deleted from Engine/Core/TaskSystem.cpp, because a re-wrap that moved a word boundary would alter a sentence a reader only ever meets after a test has already failed. What did change is the order of the two declarations; ReportDriveTimeout says why.
The nested-pump permission was never this namespace's to withhold. TaskStream::SetNestedPumpAllowed is a public member of the stream (Engine/Core/TaskStream.h:382), so the older claim that the wait was the only place a pump is re-entered described there being one caller, not one reachable entry point. What enforces the rule is still the stream: TaskStream::Update asserts "Stream <name> was pumped while it was already pumping; only a designated wait point may nest a pump" at Engine/Core/TaskStream.cpp:333, and the guard this namespace holds is what satisfies it. The move costs a reader one name worth grepping for, which is why the TaskSystem page keeps a row pointing here rather than dropping the entry.

The header carries no #ifdef __TEST__ around its body, unlike UnitTestCollection.h, which is wrapped whole. The Test library defines __TEST__ for itself — add_compile_definitions in Engine/Test/CMakeLists.txt — and each caller includes this header from inside a test region of its own, so a third guard would remove no condition while adding one failure mode: an inclusion from somewhere unguarded would resolve to nothing and report an undeclared identifier far from its cause. It follows TestCollection.h, which is test-build API and unguarded for the same reason.

Template parameters

None — TestHelper is a namespace. The one template parameter belongs to a single function and is documented on its own page.

Class properties

None. The namespace declares no data, no alias and no constant. The default bound on the wait is a default argument on DriveUntil's patience parameter, so the number lives in a signature; promoting it to a namespace-scope constant would add an entry this reference then has to own, to name a value that appears exactly once. It was written std::chrono::milliseconds(30000) as a member too, and the move deliberately did not improve it.

Coverage

This page documents both functions Engine/Test/TestHelper.h declares, which is that header's whole surface. It does not document every wait an engine test can call, and the two it leaves out are deliberate:

Left outWhere it livesWhy it stayed
hbe::WaitUntil Engine/Test/TestCollection.h:32 A deadline sleep-poll with no driving, five callers, all of them in Engine/Core/TaskSystem.cpp. It belongs beside this namespace and owns no page; moving it was declined on 2026-10-02 so that this change stayed a one-function move. Engine/Core/Task.h refers to it in prose as the honest way for a test to wait
AdvanceWindowsUntil Engine/Core/TaskSystem.cpp:855, internal linkage Three callers. It advances budget windows rather than pumping the stream, which is a different mechanism with a destructive side effect — an advance zeroes the stream's accumulated CPU — so it is not a variant of the wait documented here. It has no page anywhere

One behaviour on the method page is read off the code rather than measured: the sleep-poll branch taken by a caller that is not the base stream's thread has no caller in this tree, because every testlet runs on the base stream. Nothing in the suite exercises it, and the claim that such a caller times out silently is therefore a reading of Engine/Test/TestHelper.h:25-34, not a test result.
