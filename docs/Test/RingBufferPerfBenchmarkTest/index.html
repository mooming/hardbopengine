RingBufferPerfBenchmarkTest

Engine/Test/RingBufferPerf.h hbe final the full ring-buffer sweep, registered only by the benchmark binary

Class description

The full ring-buffer sweep: twenty-two cells covering both queue families, saturated and sparse, sixteen producers deep, with the spin-cap comparison and the fetch_add experiment attached. It is an ordinary collection with an ordinary Prepare, and it is registered by exactly one binary — Examples/RingBufferBenchmark, through hbe::Test::RegisterPerfBenchmarkSuite.

That split, and not a command-line switch, is how the full sweep and the regression run stay honest. Both binaries execute the same measure functions through the same PerfBenchmark; the only difference is which collection was registered before the run was scheduled. A sweep that computed its numbers differently from the compact cells would be a sweep whose numbers could not be compared with the ones a regression run prints.

Twenty-two cells at 0.20 s to 2.37 s each, about 16 s in total, Release. No cell reaches the five-second limit any testlet is held to; each prints its own wall time so the claim can be checked rather than trusted. The budget is what decided the item counts, and the budget section records which knob was turned and why.

Class properties

None, for the same reason as the compact collection: the shapes live as file-local constexpr objects and every measurement lives in the PerfBenchmark built inside the testlet that runs it.
