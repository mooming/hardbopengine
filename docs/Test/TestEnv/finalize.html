Lifecycle changed on 2026-09-28. The one-call run this page describes is gone. A test is now a Testlet and the unit the harness schedules, so TestCollection::Start became PrepareTests / RunTestAt / Complete, TestEnv::Start became PrepareTestlets / RunTestlet / Finalize, and hbe::Test::RunTests became RegisterSuite and ScheduleSuiteOnBaseStream. The statements below that name the old lifecycle are history, not reference; the replacements are documented: PrepareTests / RunTestAt / Complete on TestCollection and PrepareTestlets / RunTestlet / Finalize on TestEnv.

Finalize

member of hbe::TestEnv Engine/Test/TestEnv.h call once, after the last testlet prints the suite report the gate reads its verdict from

Signature

void Finalize();

Function description

Prints the report block: total collections, how many completed, how many were invalid, pass and fail counts, and the suite's global heap figures - cumulative requests, cumulative bytes, and how many testlets were involved. It then lists the invalid collections and the failed ones with their collected messages.

Collections themselves are closed by RunTestlet as each one's last testlet finishes; this is the suite-level closing, and it does not decide anything - every verdict already exists by the time it is called.

Who calls it

The task that the last testlet posts, immediately before it asks the engine to shut down. That ordering is the point of the chain: the report is produced by the same scheduled sequence it is reporting on, so a suite that never reached the end also never produced a report claiming it did.

Where the verdict actually lives

ConsumerWhat it reads
The gate script The entry point's last line, EngineTest: all 59 collections passed (372 testlets), and the process exit status. Zero-collection runs are refused outright, so an empty suite cannot read as a pass.
GetFailureCount What the entry point turns into a non-zero exit. It includes failures the report itself would not mention - the shutdown-pump provenance guard and the duplicate-testlet guard both fold in here rather than into a buffer the next run clears.
