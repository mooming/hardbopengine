constructors

member of hbe::TestEnv Engine/Test/TestEnv.h 1 overload public, inline, noexcept an empty registry and two zeroed counters

Signature

TestEnv() noexcept : testedCount(0), passCount(0) {}

Function description

One default constructor, written out in the class body rather than defaulted. It initialises the two counters and leaves the five vectors to their own default constructors, so what you get is an environment with nothing registered, nothing collected and nothing counted. It does not register any collection, does not subscribe to anything and cannot fail — hence noexcept.

It is public. In the engine this runs exactly twice as a matter of fact: once for the GetEnv singleton, and once more if any code writes TestEnv as a local. That is a supported thing to want — running one collection alone — but the tallies that decide the process exit status are read from the singleton, so a private environment's results are reported by nobody. See the box on the class page.

There is no way back to zero. No constructor is called again on a live environment, no Reset exists, and Start clears only the two name lists — not passCount, not testedCount, not the merged message vectors. So a single environment cannot be re-used for a fresh measurement: a second Start yields a per-run failure count and a cumulative pass count at the same time. If you need two independent runs, use two environments and remember that only one of them is the one the executable reads.
The registry is append-only for the process's whole life. Collections built through AddTestCollection are owned by this environment as std::unique_ptr and destroyed with it. Since the engine's environment is the function-local static inside GetEnv, the collections — and each one's full text of warnings and errors — are still allocated after main returns.

Parameters

None.

Return value

Constructors have no return value. The observable state afterwards is an empty tests vector, so Start on a freshly built environment prints a completed report with a total of zero and both counters at zero — a run that is entirely green because there was nothing in it.

Examples

No engine code constructs a TestEnv. Both call sites go through the singleton, one to fill it and one to read it:

From Engine/Test/UnitTestCollection.cpp

        auto& testEnv = TestEnv::GetEnv();

        testEnv.AddTestCollection<SystemAllocatorTest>();
        // … fifty-nine more …
        testEnv.Start();

From Applications/EngineTest/TestMain.cpp

// The suite runs as a task that shuts the engine down when it finishes, so the tallies
// are only complete once Run() returns.
const hbe::TestEnv& testEnv = hbe::TestEnv::GetEnv();
const unsigned int failures = testEnv.GetFailureCount();

The second of those binds a reference to a const environment, which is the whole public read surface: the two counters. Everything else on the object is private.
