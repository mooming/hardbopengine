Global allocation totals

members of hbe::TestEnv Engine/Test/TestEnv.h const noexcept the suite-wide view of what the testlets took through operator new

Signature

[[nodiscard]] std::size_t   GetGlobalAllocationBytes() const noexcept;

[[nodiscard]] std::size_t   GetTestletCountWithGlobalAllocations() const noexcept;

What they add up

Each getter sums the matching figure over every collection the environment owns, so the suite reports one number instead of fifty-nine. They are the figures behind the report line # Global heap over testlet bodies = …, and behind the line the EngineTest entry point prints with the whole-process totals taken straight from MemoryManager.

Suite totals against process totals

FigureWindow it coversWhy both are printed
These getters Testlet bodies only, summed over collections. The fixture that prepares a testlet, engine boot and standard library start-up are all outside. This is the number a test author is responsible for.
MemoryManager::GetGlobalAllocation* Everything since process start, engine and standard library included. The gap between the two is what the harness and the engine consume on a run's behalf - the place to look when a suite gets slower and no testlet will admit to it.

Return value

Zero before any testlet has run. The byte figure is cumulative bytes requested, not memory held - freeing does not reduce it, so the suite total is dominated by allocator stress tests and means nothing alone. The held figure per collection is TestCollection::GetMaxRetainedGlobalBytes.
