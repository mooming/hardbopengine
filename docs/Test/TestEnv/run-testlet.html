Lifecycle changed on 2026-09-28. The one-call run this page describes is gone. A test is now a Testlet and the unit the harness schedules, so TestCollection::Start became PrepareTests / RunTestAt / Complete, TestEnv::Start became PrepareTestlets / RunTestlet / Finalize, and hbe::Test::RunTests became RegisterSuite and ScheduleSuiteOnBaseStream. The statements below that name the old lifecycle are history, not reference; the replacements are documented: PrepareTests / RunTestAt / Complete on TestCollection and PrepareTestlets / RunTestlet / Finalize on TestEnv.

RunTestlet

member of hbe::TestEnv Engine/Test/TestEnv.h replaces ExecuteTest (2026-09-28) runs one testlet of the flattened schedule and closes its collection when that was its last

Signature

void RunTestlet(std::size_t testletIndex);

Function description

The body of the task the suite is made of. It maps a flattened index to (collection, index within it) using the offsets PrepareTestlets built, hands the call to TestCollection::RunTestAt, counts the execution, and finalises the collection when the testlet was its last.

The two guards it owns

GuardBehaviourWhy it is in this shape
Index past the schedule Reports to std::cerr, naming the index and the registered total, and returns without running. The Test module deliberately writes its own diagnostics to std::cerr rather than the logger, so the message survives even when the failure is in logging or allocation itself.
A testlet asked for twice Recorded as a failure and the testlet still runs. Refusing to execute what it was handed would hide the scheduling defect that produced the duplicate - the schedule is a chain, so a node that posted its successor twice is the bug, and the run needs to say so while still showing the work.

What this call makes checkable

Each call increments GetExecutedTestletCount. The entry point compares that against the registered total, and a gap fails the run naming the loop that drives the suite: 

EngineTest: only 13 of 372 registered testlets ran, so the engine never drove the suite it was given

That message is the reason the suite is shaped this way at all: a testlet is a task, each one posts its successor, and if the engine's loop stops pumping the base stream the suite stops - and says which of those happened.

Parameters

ParameterTypeRequirement
testletIndex std::size_t Index into the flattened sequence, not into a collection. The conversion to a per-collection index happens here, which is the only place that knows both spaces.
