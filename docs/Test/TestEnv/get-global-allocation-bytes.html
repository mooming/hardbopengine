GetGlobalAllocationBytes

member of hbe::TestEnv Engine/Test/TestEnv.h bytes every testlet body asked the global allocation door for, suite-wide

Signature

[[nodiscard]] std::size_t GetGlobalAllocationBytes() const noexcept

Function description

Bytes every testlet body asked the global allocation entry points for, summed over every collection the environment owns — so the suite reports one number instead of fifty-nine. This is the figure behind the report line # Global heap over testlet bodies = ….

The window matters, and it is worth stating against the process-wide figure the entry point prints from MemoryManager: these getters cover testlet bodies only — the fixture that prepares a testlet, engine boot and standard library start-up are all outside — and that is the number a test author is responsible for. The gap between the two totals is what the harness and the engine consume on a run's behalf, which is the place to look when a suite gets slower and no testlet will admit to it.

Parameters

None.

Return value

Cumulative bytes requested, not memory held — freeing does not reduce it, so the suite total is dominated by allocator stress tests and means nothing alone. Zero before any testlet has run. The held figure per collection is TestCollection::GetMaxRetainedGlobalBytes.

Examples

The paired figures are GetGlobalAllocationCount (requests) and GetTestletCountWithGlobalAllocations (how many testlets touched the heap at all); the ceiling they are judged against is TestCollection's retention ceiling.
