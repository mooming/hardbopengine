GetPassCount

member of hbe::TestEnv Engine/Test/TestEnv.h const noexcept inline how many collections completed without an error message — never reset, never a case count

Signature

/// @brief Collections that completed successfully.
[[nodiscard]] unsigned int GetPassCount() const noexcept { return passCount; }

Function description

Returns passCount, incremented once for each collection that completed and reported no error message. The unit is the collection, and the header's own doc comment says so: "Collections that completed successfully." A collection with ten failures contributes one to GetFailureCount and nothing here.

This is the number the executable prints on success — Applications/EngineTest/TestMain.cpp writes "all N collections passed" from it.

It is a lifetime total, not a run total. Start clears the two name lists and leaves passCount alone, so calling Start twice reports a pass count summed over both runs beside a failure count from the second one alone. Nothing resets it — no accessor writes it, no Reset exists — so a harness that runs the suite more than once inside one process has to subtract the value it read before.
Nothing here tells you whether anything ran. A pass count of zero is also what a suite registers nothing into: the counters start at zero, so "no work" and "everything failed" are distinguishable only by comparing against the registration count — which has no accessor at all. Read together with GetFailureCount, a green run over zero collections is two zeros, and the report line "Total Count = 0" is the only other clue.

Parameters

None.

Return value

TypeWhat you get
unsigned int Collections completed without error, since the environment was constructed. Never negative, never reset; [[nodiscard]]

Examples

One consumer, and it is the line that decides whether a human being is told the suite is green — note that this is the success message only; the failure path uses GetFailureCount instead:

From Applications/EngineTest/TestMain.cpp

const hbe::TestEnv& testEnv = hbe::TestEnv::GetEnv();
const unsigned int failures = testEnv.GetFailureCount();

if (failures > 0)
{
        std::cerr << "EngineTest: " << failures << " test collection(s) FAILED" << std::endl;
        return 1;
}

std::cout << "EngineTest: all " << testEnv.GetPassCount() << " collections passed" << std::endl;

The read happens after hengine.Run() returns, because the suite is a task rather than a call: the tallies are incomplete while Run() is in progress. That ordering is the reason the same GetEnv instance can be read from main at all.

The header's /// @brief comment on this method is the only place in the module where the per-collection unit is written down; everything else in the source says "Test" where it means "collection".
