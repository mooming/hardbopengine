NoteTestletRepeated

member of hbe::TestEnv Engine/Test/TestEnv.h records a testlet that ran more than once — no scheduling may do that

Signature

void NoteTestletRepeated(std::size_t testletIndex)

Function description

Records that one testlet ran more than once — which no scheduling of this suite is allowed to do. The suite's own totals cannot see this defect: a chain whose every step is told it is step zero runs one testlet N times and still reports N of N executed, which is exactly how a real bug in this harness once looked green right up to the registry ceiling. Counting runs per testlet is what turns that into a named failure.

The record is a failure entry naming the first offender — later repeats append, so a report names the repeat rather than a count. The testlet still runs when asked; refusing to execute what the schedule handed over would hide the defect that produced the repeat.
