RingBufferPerfTest

Engine/Test/RingBufferPerf.h hbe final the three performance cells that run inside every EngineTest run

Class description

The three performance cells that belong in a regression run. They are registered by hbe::Test::RegisterSuite, which every EngineTest binary calls, so the direction of the two queue designs is visible in a ten-second run rather than only in a benchmark run somebody has to remember to make. Three cells cost about 0.75 s of a roughly ten-second suite, which is what makes them affordable to keep.

They are ordinary TestCollection subclasses and follow the module’s conventions: a testlet is a closure that streams text, and the text is flushed by ending with log << lf. Nothing here reports an error or a warning, whatever the numbers say — the grade is carried in EPerfGrade and the pass count does not move. A cell can still fail in the ordinary way: it would take a container that throws or leaks past its retention ceiling to get there, and neither is a performance complaint.

Coverage

The constructor and Prepare are both documented; the constructor only names the collection, so it has no page of its own and its one line is this sentence. The shapes, margins and arms the cells use are file-local to Engine/Test/RingBufferPerf.cpp and are listed in what the harness claims, because a shape is a measurement decision rather than an API a caller can call.
