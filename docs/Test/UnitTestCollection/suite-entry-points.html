Suite entry points

Engine/Test/UnitTestCollection.h  ·  namespace hbe::Test  ·  two free functions, both behind #ifdef __UNIT_TEST__

What this module is

The whole of UnitTestCollection is two free functions, and they are the only thing Applications/EngineTest calls. One registers the suite, the other starts it running on the engine's own base stream. There is no longer a single RunTests doing both from inside one task, and the reason that was split is recorded under Why the split.

void hbe::Test::RegisterSuite()

Registers every test collection by type into TestEnv and flattens them into the sequence of Testlets the harness schedules.

Preconditions. The engine is initialised — collection construction reaches the task system, the logger and the default allocator. Call it before Engine::Run is entered.

Postconditions. GetTestletCount() reports the total the run is expected to reach, and no work has been posted yet.

Thread-safety. Main thread only. It mutates the single TestEnv instance with no synchronisation, because nothing else exists yet to race with.

void hbe::Test::ScheduleSuiteOnBaseStream()

Posts the first testlet as a task on the base stream. Each testlet posts the next when it runs, and the last posts a task that prints the report and requests shutdown. Engine::Run is therefore the only thing that can carry the suite to its end, and it returns with the tallies already settled — which is why the harness reads them after the loop rather than before it.

Preconditions. RegisterSuite() has run.

Postconditions. One task is queued, and completing the suite is now the engine loop's job.

Why the split, and why before Run

Registering from inside the suite's own task would leave the suite to discover how many tests it has. A run that never started would then report an expected total of zero, agree with the zero that executed, and certify a dead engine as balanced — the exact shape a real defect passed through once. Registering before Run puts that expected total in the harness's hands instead, so a shortfall between registered and executed becomes a failure main can see; scheduling had to be separable for the total to be knowable without posting anything.

Coverage

Both functions run in every gate run in three configurations, and they fail loudly: measured against a build whose Engine::Run loop was reduced to a single pass, the run exited non-zero with only 13 of 372 registered testlets ran.
