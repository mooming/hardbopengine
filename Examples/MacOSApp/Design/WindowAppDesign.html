1. Project Overview

MacOSApp is a standalone C++23 example application that demonstrates how to build a complete window-based graphical application from scratch on macOS using the Cocoa framework. Unlike the HardBop Engine's existing OS::IWindow/OS::IApplication abstractions, this project implements its own window and application layer as a learning exercise to understand the underlying macOS APIs and eventually replace the engine's current OSAL implementation.

Core Principles

🖥️ Software Rendering
All UI is rendered pixel-by-pixel onto a software framebuffer, then presented to the screen via Cocoa's CGImage/NSImage APIs. No GPU or Metal required.
🍎 Objective-C++ Bridge
Platform-specific Cocoa code is isolated in .mm files, bridged to C++ via opaque void* handles. The C++ API remains platform-agnostic.
🎨 Custom UI Toolkit
A minimal immediate-mode-inspired UI toolkit with TextPanel, ScrollBar, and Button. All components draw onto the framebuffer using primitive operations.
🔧 Engine Conventions
Follows HardBop Engine coding standards: PascalCase, camelCase, tabs, noexcept, [[nodiscard]], final, exception-free.

Design Goals vs. Constraints

Goal Description Constraint
Full Screen / Windowed Toggle between native full-screen and standard window macOS only; uses NSWindow toggleFullScreen
Text Panel + Scrollbars Display scrollable multi-line text Must render on software framebuffer
Close Button UI button that terminates the app Self-contained; not the traffic light button
Custom Implementation No engine IWindow/IApplication usage Independent of Engine/OSAL headers
C++23 Compliance Modern C++ with standard library only No external GUI libraries (ImGui, etc.)

2. macOS AppKit Technology Reference

This section provides detailed reference for the macOS AppKit APIs that will be used in the Objective-C++ bridge files (.mm). Each class, function, variable, parameter, and constant is documented with its purpose and usage in this project.

Core Foundation & AppKit Classes

● NSApplication
Purpose: Manages the application lifecycle, event loop, and coordination between windows and menus.
Key Methods Used:
+ sharedApplication — Returns the singleton NSApplication instance (static method).
+ setActivationPolicy: — Sets how the app appears in the dock (Regular = shown, Prohibited = background-only).
+ finishLaunching — Completes app startup (creates menu bar, processes launch events).
+ nextEventMatchingMask:untilDate:inMode:dequeue: — Retrieves next event from queue. Parameters:
  • mask: Event type mask (NSEventMaskAny = all types)
  • untilDate: When to stop (distantPast = process all queued immediately)
  • inMode: Run loop mode (NSDefaultRunLoopMode)
  • dequeue: Whether to remove from queue (YES = remove)
+ sendEvent: — Dispatches an NSEvent to the appropriate target.
+ terminate: — Cleanly shuts down the application.
Variables: appHandle (void* storing NSApplication* pointer)
● NSWindow
Purpose: Manages a window's content, appearance, position, and event routing on screen.
Constructor / Initialization:
[[NSWindow alloc] initWithContentRect:frame styleMask:style backing:backingStore defer:isDeferred]
  • contentRect (NSRect): Initial position and size (origin + size)
  • styleMask (NSWindowStyleMask): Window decorations (titled, closable, miniaturizable, resizable)
  • backingStore (NSBackingStoreType): Backing store type (NSBackingStoreBuffered = buffered)
  • isDeferred (BOOL): Whether to defer drawing (NO = immediate)
Key Methods Used:
+ setReleasedWhenClosed: — Controls whether window is auto-released when closed.
+ setTitle: — Sets the window's title string.
+ setFrame:display:animate: — Sets window position/size with optional display and animation.
+ makeKeyAndOrderFront: — Makes window the key window and puts it in front.
+ center — Centers window on screen.
+ orderOut: — Hides the window (orderOut:nil).
+ toggleFullScreen: — Toggles full-screen mode. Argument is sender (can be nil).
+ setCollectionBehavior: — Sets window behavior flags (NSWindowCollectionBehaviorFullScreenPrimary enables full-screen).
+ close — Closes the window and performs cleanup.
+ release — Decrements reference count (manual memory management).
Properties Accessed:
frame (NSRect): Current position and size.
isVisible (BOOL): Whether window is currently visible.
title (NSString*): Current title.
Variables: nsWindowHandle (void* storing NSWindow* pointer), width, height, fullScreenFlag, closedFlag
Constants Used:
  • NSWindowStyleMaskTitled — Window has a title bar
  • NSWindowStyleMaskClosable — Has close button (red)
  • NSWindowStyleMaskMiniaturizable — Can minimize to dock
  • NSWindowStyleMaskResizable — Has resize handles
  • NSBackingStoreBuffered — Buffered backing store
  • NSWindowCollectionBehaviorFullScreenPrimary — Window can enter full-screen
● NSView (FramebufferView)
Purpose: Base class for custom drawing. A subclass will be created to draw the framebuffer to the screen.
Key Method to Override:
+ drawRect:(NSRect)dirtyRect — Called by the system when the view needs redrawing. In our subclass, this method will:
  • Create a CGImage from the framebuffer's raw pixel data
  • Obtain the current CGContext via UIGraphicsGetCurrentContext() or [NSGraphicsContext currentContext]
  • Draw the image into the context with CGContextDrawImage(context, rect, image)
Constructor/Properties:
  • initWithFrame: — Initialize view with a frame rectangle
  • setAutoresizingMask: — Set how the view resizes with its parent (NSViewWidthSizable | NSViewHeightSizable = stretch)
Variables: framebufferPtr (reference to our Framebuffer object for pixel data)
● NSEvent
Purpose: Represents a single input event (mouse, keyboard, etc.) from the OS.
Properties Accessed:
type (NSEventType): The event type.
  • NSLeftMouseDown / NSLeftMouseUp — Mouse button events
  • NSLeftMouseDragged — Mouse drag with left button
  • NSMouseMoved — Mouse movement (no button)
  • NSKeyDown / NSKeyUp — Keyboard events
  • NSScrollWheel — Mouse wheel events
locationInWindow (NSPoint): Mouse position as a point with x,y coordinates.
keyCode (unsigned short): Hardware scan code of the key pressed.
characters (NSString*): Unicode string of the key pressed.
modifierFlags (NSEventModifierFlags): Modifier keys (Command, Shift, etc.)
Variables: mouseX, mouseY, leftMousePressed, lastKeyDown, wheelDeltaY
● NSBitmapImageRep / CGImage / CGContext
Purpose: Core Graphics classes for creating and manipulating pixel data.
NSBitmapImageRep: Stores raw pixel data. Initialized with:
  • bitmapFormat: NSBitmapFormat (NSBitmapFormatAlphaFirst or NSBitmapFormatAlphaNonpremultiplied)
  • bytesPerRow: Stride (typically width * 4 bytes for RGBA)
  • bitsPerPixel: 32 (8 bits per channel)
  • representation: Pointer to pixel data
CGImage: Created via CGBitmapImageCreate(data, width, height, bitsPerComponent, bytesPerRow, colorSpace, bitmapInfo, provider, NULL, NO, kCGRenderingIntentDefault)
  • data: Raw RGBA pixel buffer
  • bitsPerComponent: 8
  • colorSpace: CGColorSpaceCreateDeviceRGB()
  • bitmapInfo: kCGImageAlphaPremultipliedLast | kCGBitmapByteOrder32Big
CGContext: Obtained via [NSGraphicsContext currentContext], then CGContextDrawImage(context, rect, image) to draw.
● AppDelegate (Custom)
Purpose: Custom NSObject implementing NSApplicationDelegate to handle app lifecycle events.
Key Methods Implemented:
+ applicationShouldTerminateAfterLastWindowClosed: — Returns NO to prevent app from quitting when last window closes (we manage shutdown manually).
Variables: None needed — serves as lifecycle handler only.

Coordinate Systems

Screen Coordinates vs. Framebuffer Coordinates
macOS uses a bottom-left origin for screen coordinates, while our framebuffer uses top-left origin. The Y coordinate must be flipped when converting mouse events from NSEvent to framebuffer coordinates:
// NSEvent gives locationInWindow (bottom-left origin)
// Our framebuffer uses (top-left origin)
NSPoint nsPoint = [event locationInWindow];
int framebufferX = (int)nsPoint.x;
int framebufferY = windowHeight - (int)nsPoint.y;  // Flip Y

Memory Management

Manual Reference Counting (MRC)
The engine's OSX code uses MRC (no ARC). Objects must be balanced with alloc/release calls. Each [[Class alloc] init] must be paired with [object release] when done. autorelease is used for temporary objects returned from functions.

Existing Engine Patterns (Learning Reference)

The existing engine's OSXWindow.mm provides the following patterns that we will adapt:

// Pattern 1: Store NSWindow as void* in C++ class
OSXWindow::OSXWindow() : nsWindow(nullptr), width(0), height(0) {}

// Pattern 2: Create NSWindow in C++ method (Objective-C++ file)
NSRect frame = NSMakeRect(100, 100, width, height);
NSUInteger styleMask = NSWindowStyleMaskTitled | NSWindowStyleMaskClosable | NSWindowStyleMaskMiniaturizable;
NSWindow *window = [[NSWindow alloc] initWithContentRect:frame
                                              styleMask:styleMask
                                                backing:NSBackingStoreBuffered
                                                  defer:NO];

// Pattern 3: Cast void* back to NSWindow* when needed
auto window = static_cast<NSWindow*>(nsWindow);
[window setTitle:[NSString stringWithUTF8String:title.c_str()]];

// Pattern 4: Clean up in Close()
[window close];
[window release];
nsWindow = nullptr;

Additional AppKit Concepts Used

NSMakeRect() and NSRect
Creates an NSRect (rectangle with origin x,y and size width,height). Used for window frame specification. Parameters:
  • x: X origin (left)
  • y: Y origin (bottom-left in macOS screen coords)
  • width: Rectangle width in pixels
  • height: Rectangle height in pixels
NSString stringWithUTF8String:
Creates an NSString from a C string (const char*). Used to bridge HString/c_str() to NSString for setTitle: calls. The created NSString is autoreleased.
NSRunLoop and NSDefaultRunLoopMode
The run loop mode for processing non-urgent events. Used in the event polling loop to prevent blocking.
NSView Autoresizing Mask
Bitmask constants controlling how a view resizes with its parent:
  • NSViewWidthSizable (1 << 2): Width stretches with parent
  • NSViewHeightSizable (1 << 3): Height stretches with parent
  • Combined: view fills its parent's bounds

Text Rendering Details

  • Font: Custom 8×12 bitmap font (each character is 8px wide, 12px tall), stored as a BitmapFont class with a lookup table of 96 ASCII characters (32-127).
  • Character spacing: 1px between characters, 2px left/right padding inside panel.
  • Line height: 14px (12px font + 2px gap).
  • Cursor: Text starts at (panelX + 4, panelY + 4) relative to the panel's top-left corner.
  • Clipping: Only characters within the panel bounds are rendered; scroll offset determines which lines are visible.

ScrollBar Layout

 ┌────────────────┐
 │  ScrollBar     │  ← Total height: panelHeight
 │  Track         │  ← Track height: panelHeight - 16px (padding)
 │  ┌───────┐     │  ← Thumb: proportional to pageSize / (max-min)
 │  │ Thumb │     │  ← Thumb position: proportional to currentValue
 │  └───────┘     │  ← Track width: 16px
 └────────────────┘

ScrollBar Behavior

  • Thumb dragging: When the user clicks and drags the thumb, the scroll position updates proportionally. The thumb's position maps linearly from minValue to maxValue.
  • Track click: Clicking above the thumb scrolls up by one page; clicking below scrolls down by one page. Page size = number of visible lines.
  • Mouse wheel: Scrolling the mouse wheel over the scrollbar (or the text panel) adjusts the value by one line per tick.
  • Callback: When the value changes, the onValueChanged callback notifies the linked TextPanel to update its scroll offset.

cmake_minimum_required(VERSION 3.12)
project(MacOSApp)

set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Build configurations
set(CMAKE_CONFIGURATION_TYPES "Debug;Dev;Release" CACHE STRING "" FORCE)
if (NOT CMAKE_BUILD_TYPE)
    set(CMAKE_BUILD_TYPE "Release" CACHE STRING "Build type" FORCE)
endif()

# Compiler flags
set(CMAKE_CXX_FLAGS_DEBUG "-g -O0")
set(CMAKE_CXX_FLAGS_DEV "-O1")
set(CMAKE_CXX_FLAGS_RELEASE "-O3")

# Treat warnings as errors
add_compile_options(-Wall -Werror)

# Find macOS frameworks
find_library(COCOA_LIBRARY Cocoa)
find_library(FOUNDATION_LIBRARY Foundation)

# Source files
add_executable(MacOSApp
    Source/Main.cpp
    Source/Framebuffer.cpp
    Source/BitmapFont.cpp
    Source/Window.mm
    Source/Application.mm
    Source/UI/TextPanel.cpp
    Source/UI/ScrollBar.cpp
    Source/UI/Button.cpp
)

target_link_libraries(MacOSApp
    ${COCOA_LIBRARY}
    ${FOUNDATION_LIBRARY}
)

# Include paths
target_include_directories(MacOSApp PRIVATE
    ${CMAKE_SOURCE_DIR}
    Include
    Engine
    Engine/OSAL
    Engine/Config
    Engine/HSTL
)

# Configure (from project root)
cmake --fresh -B build -G "Ninja Multi-Config" -S .

9. Test Plan

The test plan is organized into functional tests (verifying each feature) and code-quality tests (verifying standards compliance). All tests are designed to be verified manually during development.

Functional Test Cases

TC-01: Application Startup
Verify that the application launches and displays a window.
Steps: Run the binary from terminal. Observe window appearance.
Expected: Window titled "MacOSApp" appears at 1024×768, centered on screen. Background is dark (#0D1117). TextPanel, ScrollBar, Close button, and Full Screen button are visible.
Pass Criteria: Window appears within 2 seconds, no crash, no console errors.
TC-02: Full Screen via F11
Verify full-screen toggle using the F11 key.
Steps: Press F11. Press Esc (or F11 again) to exit.
Expected: Window transitions to full-screen (no title bar, covers entire display). UI elements reposition to fit new dimensions. Pressing Esc or F11 returns to windowed mode.
Pass Criteria: Transition takes < 1 second, UI re-renders without artifacts.
TC-03: Full Screen via UI Button
Verify full-screen toggle using the Full Screen button in the UI.
Steps: Click the "⛶ Full Screen" button in the bottom-left of the window.
Expected: Window enters full-screen mode. Button label changes to "⛶ Windowed". Clicking it again returns to windowed mode.
Pass Criteria: Same as TC-02, plus button state toggles correctly.
TC-04: Text Panel Rendering
Verify the text panel displays sample text correctly.
Steps: Observe the text panel area on launch.
Expected: Multi-line text from sample_text.txt is rendered in a monospace bitmap font. Text is left-aligned within the panel. Lines that don't fit vertically are clipped.
Pass Criteria: All characters render correctly, no garbled pixels, text is readable.
TC-05: Scrollbar - Drag Thumb
Verify scrollbar thumb dragging scrolls text.
Steps: Click and drag the scrollbar thumb. Observe text movement.
Expected: Text scrolls smoothly as the thumb is dragged. The thumb position visually corresponds to the scroll offset. When released, text stays at new position.
Pass Criteria: No jitter, text moves proportionally to thumb position.
TC-06: Scrollbar - Track Click
Verify clicking the scrollbar track scrolls a page.
Steps: Click above the thumb (scrolls up one page) and below the thumb (scrolls down one page).
Expected: Text jumps by one page (panel height in lines) per click. Thumb position updates.
Pass Criteria: Page scroll amount matches visible content height.
TC-07: Close Button Click
Verify clicking the Close button terminates the application.
Steps: Click the "✕ Close" button (bottom-right of window).
Expected: Application terminates cleanly with exit code 0. No crash, no error messages in console.
Pass Criteria: Process exits within 1 second, exit code is 0.
TC-08: Window Close (Traffic Light)
Verify closing via the macOS traffic light button.
Steps: Click the red traffic light button in the window's title bar.
Expected: Window closes, application terminates with exit code 0.
Pass Criteria: Same as TC-07.
TC-09: Full-Screen Exit via Escape
Verify Esc key exits full-screen mode.
Steps: Enter full-screen (via F11 or button), then press Esc.
Expected: Window returns to windowed mode.
Pass Criteria: Exit is immediate, UI re-layouts correctly.
TC-10: Coding Standards Compliance
Verify all code follows HardBop Engine coding standards.
Checks:
  • PascalCase for classes, functions, types
  • camelCase for variables (no m_ prefix)
  • Tab indentation (not spaces)
  • [[nodiscard]] on getters
  • noexcept on non-throwing methods
  • final on non-inheritable classes
  • Explicit access specifiers (public/protected/private)
  • 2 blank lines after includes in .cpp/.mm files
  • Exception-free (no try/catch, no throw)
  • Error logging via std::cerr before failure return
Pass Criteria: All checks pass. Compiles with -Wall -Werror with zero warnings.

Verification Methods

  • Manual: Run the application, interact with all UI elements, verify visual correctness.
  • Compiler: -Wall -Werror catches coding standards violations at build time.
  • Visual inspection: Pixel-level verification of text rendering, scrollbar position, button states.
  • Exit code: Verify clean exit (code 0) after close button and traffic light clicks.
