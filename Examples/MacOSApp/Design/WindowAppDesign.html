1. Project Overview

MacOSApp is a standalone C++23 example application demonstrating how to build a complete window-based graphical application from scratch on macOS using the Cocoa framework. It implements its own window and application layer without using the HardBop Engine's OS::IWindow/OS::IApplication abstractions.

Core Principles

🖥️ Software Rendering
All UI is rendered pixel-by-pixel onto a software framebuffer, then presented via CGImage/NSView. No GPU or Metal required.
🍎 Objective-C++ Bridge
Platform Cocoa code is isolated in .mm files, bridged to C++ via opaque void* handles.
🎨 Custom UI Toolkit
Immediate-mode-inspired UI with TextPanel, ScrollBar, Button — all rendering via framebuffer primitives.
🔧 Engine Conventions
Follows HardBop Engine standards: PascalCase, camelCase, tabs, noexcept, [[nodiscard]], final, exception-free.

Design Goals vs. Constraints

Goal Description Constraint
Full Screen / Windowed Toggle between native fullscreen and standard window macOS only; uses NSWindow toggleFullScreen
Text Panel + Scrollbars Display scrollable multi-line text Rendered on software framebuffer
Close Button UI button that terminates the app Self-contained; not the traffic light button
Custom Implementation No engine IWindow/IApplication usage Independent of Engine/OSAL headers
C++23 Compliance Modern C++ with standard library only No external GUI libraries (ImGui, etc.)

2. Architecture Overview

Layered Architecture

┌──────────────────────────────────────────────────────────────┐
│ Layer 5: Application Logic  (Main.cpp)                        │
│   - Entry point, main loop, UI layout, input routing           │
├──────────────────────────────────────────────────────────────┤
│ Layer 4: UI Toolkit           (TextPanel, ScrollBar, Button)  │
│   - Draw onto framebuffer, receive InputState for interaction  │
├──────────────────────────────────────────────────────────────┤
│ Layer 3: Software Framebuffer (Framebuffer.h/cpp)             │
│   - GetPixel, SetPixel, FillRect, DrawLine, DrawText, BitBlt   │
│   - 8x12 bitmap font (96 ASCII chars, embedded)                │
├──────────────────────────────────────────────────────────────┤
│ Layer 2: Window Abstraction  (Window.h/mm)                    │
│   - NSWindow wrapper, NSView framebuffer drawing             │
│   - Event polling (keyboard + mouse), Y-flip coordinate       │
├──────────────────────────────────────────────────────────────┤
│ Layer 1: OS Layer             (Application.h/mm)               │
│   - NSApplication singleton, event dispatch, app lifecycle    │
│   - AppDelegate for graceful shutdown behavior               │
└──────────────────────────────────────────────────────────────┘

Data Flow

[Cocoa Events] → Application::PollEvents() → Window::PollEvents()
    ↓
MouseState + KeyStates updated (Y-flipped for framebuffer coords)
    ↓
[Main Loop] → Build InputState from MouseState
    ↓
UIComponent::OnUpdate(input) ← TextPanel, ScrollBar, Button
    ↓
UIComponent::Draw(framebuffer) ← renders to Framebuffer
    ↓
Window::Present(framebuffer) → CGImage → NSView::drawRect() → Screen

Coordinate System

macOS uses bottom-left origin (0,0 at bottom-left). The software framebuffer uses top-left origin (0,0 at top-left). When mouse events are received from NSEvent, the Y coordinate is flipped: framebufferY = windowHeight - nsEventY.

Detailed reference for macOS AppKit APIs used in the Objective-C++ bridge files (.mm).

NSApplication

NSView (FramebufferView)

● NSView (FramebufferView subclass)
Purpose: Custom NSView subclass that draws framebuffer pixels to the screen via CGImage.
initWithFrame: — Initialize view with frame rect. Initializes fbPixelData to nullptr.
drawRect: — Called by system when view needs redrawing. Creates CGImage from framebuffer, flips Y-axis, draws to CGContext.

NSEvent

● NSEvent
Purpose: Represents a single input event (mouse, keyboard, scroll) from the OS.
Properties:

locationInWindow (NSPoint): Mouse position (bottom-left origin).
keyCode (unsigned short): Hardware scan code.
deltaY (CGFloat): Scroll wheel delta.
NSEventType values used: NSEventTypeKeyDown, NSEventTypeKeyUp, NSEventTypeLeftMouseDown, NSEventTypeLeftMouseUp, NSEventTypeLeftMouseDragged, NSEventTypeMouseMoved, NSEventTypeScrollWheel

CGImage / CGDataProvider / CGContext

CGImageCreate(width, height, bitsPerComponent, bitsPerPixel, bytesPerRow, colorSpace, bitmapInfo, dataProvider, decode, shouldInterpolate, renderingIntent)
Wraps raw pixel data into a CGImage for drawing. Used in FramebufferView::drawRect:.
  • bitmapInfo: kCGImageAlphaPremultipliedFirst | kCGBitmapByteOrder32Little
  • colorSpace: CGColorSpaceCreateDeviceRGB()
  • dataProvider: CGDataProviderCreateWithData(null, data, length, null)

Memory Management

Manual Reference Counting (MRC)
No ARC — objects balanced with alloc/release. Each [[Class alloc] init] paired with [object release] when done.

ScrollBar Drag Logic
Thumb position is calculated as: thumbY = trackStartY + progress * (trackHeight - thumbHeight) where progress = (currentValue - minValue) / (valueRange) and valueRange = (maxValue - minValue) - (range * pageSize). On drag, deltaValue = dragDelta / (trackHeight - thumbHeight) * valueRange.

6. Use Case Design

Use Case Table

ID Actor Use Case Precondition Main Flow Postcondition
UC-01 User Launch Application Binary exists 1. Application.Initialize() creates NSApplication → 2. Window.CreateWindow() creates NSWindow → 3. Framebuffer.Initialize() allocates pixels → 4. UI components created → 5. Main loop starts Window visible with TextPanel, ScrollBar, Close button. Background dark (#0D1117). Panel area slightly lighter (#161B22).
UC-02 User Toggle Full Screen (F11) App running, windowed mode 1. User presses F11 → 2. Window.PollEvents captures NSEventTypeKeyDown → 3. WasKeyPressed(KeyF11) edge-detected → 4. Window.ToggleFullScreen() calls [NSWindow toggleFullScreen:nil] Window in fullscreen, fullScreenFlag=true
UC-03 User Toggle Full Screen (Button) App running 1. User clicks "Full Screen" button → 2. Button.OnUpdate detects click → 3. onClicked callback → 4. window.ToggleFullScreen() Window in fullscreen, button label changes to "Windowed"
UC-04 User Scroll Text (Drag Thumb) TextPanel with overflow content 1. Mouse events captured (locationInWindow, Y-flipped) → 2. ScrollBar.OnUpdate detects thumb click+drag → 3. Thumb position mapped to scroll value → 4. onValueChanged callback fires → 5. TextPanel.SetScrollOffset() → 6. Draw() renders new lines Text scrolled smoothly, thumb position matches scroll offset
UC-05 User Scroll Text (Track Click) Scrollbar visible 1. Mouse click on track (above/below thumb) → 2. ScrollBar scrolls by pageSize * 0.2 → 3. Callback fires → 4. TextPanel updates Text scrolled by ~20% of visible page
UC-06 User Close Application (UI Button) App running 1. User clicks "Close" button → 2. Button.OnUpdate: hover detected → 3. leftMousePressed → pressedFlag=true → 4. leftMouseReleased → onClicked fires → 5. appShouldExit=true → 6. Main loop exits → 7. Window.Close(), App.ShutDown() Application exits with code 0
UC-07 User Close Application (Traffic Light) App running 1. User clicks red traffic light → 2. NSWindow closes → 3. PollEvents detects IsVisible == false → 4. closedFlag=true → 5. Main loop exits Application exits with code 0
UC-08 User Exit Full Screen (Escape) In fullscreen mode 1. User presses Escape → 2. WasKeyPressed(KeyEscape) → 3. ToggleFullScreen() Window returns to windowed mode
UC-09 User Mouse Wheel Scroll Hovering over TextPanel or ScrollBar 1. NSEventTypeScrollWheel captured → 2. mouseState.wheelDeltaY set → 3. InputState built → 4. TextPanel.OnUpdate or ScrollBar.OnUpdate processes wheel Text scrolls by wheel delta
UC-10 User Mouse Hover Interaction Mouse moving over UI 1. NSEventTypeMouseMoved captured → 2. MouseState.x/y updated (Y-flipped) → 3. UIComponent.OnUpdate: Contains() hit-test → 4. UIComponent.hoveredFlag updated → 5. Draw() uses different color for hover state UI components show hover state (buttons change color, scroll thumb lightens)

Sequence: Mouse Click on Close Button

User     NSEvent     Window     Main     Button

1. Mouse click on Close button
   MouseDown event → nextEventMatchingMask
   locationInWindow → Y-flipped via (height - y)

2. Window.PollEvents()
   NSEventTypeLeftMouseDown
   mouseState.leftButtonPressed = true
   mouseState.x/y updated (top-left origin)

3. Main.RunMainLoop()
   Build InputState from MouseState
   closeButton.OnUpdate(input)
     → hoveredFlag = Contains(mouseX, mouseY) → true
     → leftMousePressed && hoveredFlag → pressedFlag = true

4. Next frame: MouseUp event
   mouseState.leftMouseReleased = true
   mouseState.leftButtonPressed = false

5. Main.RunMainLoop()
   closeButton.OnUpdate(input)
     → pressedFlag && leftMouseReleased
     → hoveredFlag && !wasPressedOutside → onClicked()
     → appShouldExit = true

6. Main loop exits → Window.Close() → App.ShutDown()

8. Build System

CMakeLists.txt

cmake_minimum_required(VERSION 3.12)
project(MacOSApp)

set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Build configurations
set(CMAKE_CONFIGURATION_TYPES "Debug;Dev;Release" CACHE STRING "" FORCE)
if (NOT CMAKE_BUILD_TYPE)
    set(CMAKE_BUILD_TYPE "Release" CACHE STRING "Build type" FORCE)
endif()

# Compiler flags
set(CMAKE_CXX_FLAGS_DEBUG "-g -O0")
set(CMAKE_CXX_FLAGS_DEV "-O1")
set(CMAKE_CXX_FLAGS_RELEASE "-O3")

# Treat warnings as errors
add_compile_options(-Wall -Werror)

# Find macOS frameworks
find_library(COCOA_LIBRARY Cocoa)
find_library(FOUNDATION_LIBRARY Foundation)

# Source files
add_executable(MacOSApp
    Source/Main.cpp
    Source/Framebuffer.cpp
    Source/Window.mm
    Source/Application.mm
    Source/UI/TextPanel.cpp
    Source/UI/ScrollBar.cpp
    Source/UI/Button.cpp
    Source/UI/UIComponent.cpp
)

target_link_libraries(MacOSApp
    ${COCOA_LIBRARY}
    ${FOUNDATION_LIBRARY}
)

# Include paths
target_include_directories(MacOSApp PRIVATE
    ${CMAKE_SOURCE_DIR}
    Include
)

# Install
install(TARGETS MacOSApp RUNTIME DESTINATION bin)

Build Commands

# Configure (Ninja Multi-Config)
cmake --fresh -B build -G "Ninja Multi-Config" -S .

# Build
cmake --build build --config Debug
cmake --build build --config Release

# Run
./build/Debug/MacOSApp   # or ./build/Release/MacOSApp

10. Test Plan

TC-01: Application Startup
Verify that the application launches and displays a window.
Steps: Build and run the binary from terminal.
Expected: Window titled "MacOSApp" appears at 1024×768. Dark background (#0D1117). Panel area (#161B22) with TextPanel border, ScrollBar, and two buttons.
Pass Criteria: Window appears within 2 seconds, no crash, no console errors.
TC-02: Full Screen via F11
Verify full-screen toggle using the F11 key.
Steps: Press F11. Press Esc to exit.
Expected: Window transitions to full-screen. UI re-layouts for new dimensions.
Pass Criteria: Transition < 1 second, no visual artifacts.
TC-03: Full Screen via UI Button
Verify full-screen toggle using the Full Screen button.
Steps: Click the "Full Screen" button.
Expected: Window enters full-screen. Button label changes to "Windowed".
Pass Criteria: Button click fires callback, toggle works.
TC-04: Text Panel Rendering
Verify the text panel displays sample text correctly.
Steps: Observe the text panel on launch.
Expected: Light gray text (#C9D1D9) on dark background (#161B22). Text is readable, 8x12 bitmap font.
Pass Criteria: All characters render correctly, no garbled pixels.
TC-05: Scrollbar - Drag Thumb
Verify scrollbar thumb dragging scrolls text.
Steps: Click and drag the scrollbar thumb.
Expected: Text scrolls. Thumb position matches scroll offset. Thumb turns lighter blue on hover.
Pass Criteria: Smooth scrolling, proportional thumb movement.
TC-06: Scrollbar - Track Click
Verify clicking the scrollbar track scrolls a page.
Steps: Click above/below the thumb on the track.
Expected: Text scrolls by ~20% of visible content.
Pass Criteria: Page scroll works in both directions.
TC-07: Close Button Click
Verify clicking the Close button terminates the application.
Steps: Click the "Close" button (red, bottom-right).
Expected: Application terminates with exit code 0.
Pass Criteria: Process exits within 1 second, exit code 0.
TC-08: Window Close (Traffic Light)
Verify closing via the macOS traffic light button.
Steps: Click the red traffic light in title bar.
Expected: Window closes, application exits with code 0.
Pass Criteria: Clean exit.
TC-09: Escape to Exit Full-Screen
Verify Esc key exits full-screen mode.
Steps: Enter full-screen, press Esc.
Expected: Window returns to windowed mode.
Pass Criteria: Immediate exit from fullscreen.
TC-10: Button Hover States
Verify buttons show hover feedback.
Steps: Move mouse over Close button and Full Screen button.
Expected: Close button turns red on hover. Full Screen button turns blue on hover. Text becomes white.
Pass Criteria: Hover state updates immediately on mouse enter.
